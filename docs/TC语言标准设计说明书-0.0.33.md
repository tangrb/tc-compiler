## 第一部分：语言基础

### 1. 概述

#### 1.1 语言定位

TC 是为 **教学、AI 自动化编程与人类阅读** 而设计的指令式编程语言。执行模型采用 **伪汇编风格** 的逐条执行：每条语句至多包含 **一个** 运算或转换调用，**不支持** 表达式嵌套，从而将程序的每一步计算都显式化为独立的、可逐行推理的原子操作。

TC 的五项核心定位：

| 定位 | 说明 |
| ---- | ---- |
| **教学友好** | 伪汇编执行模型、显式类型系统与强制缩进使学习者能逐条跟踪程序状态；零隐式转换和零未定义行为让每一步语义均可唯一推断，降低概念过载 |
| **AI 自动化编程友好** | 命名实参、声明时强制初始化、单层表达式、禁止递归和完备的静态诊断体系，使 AI 生成代码的语义空间高度约束，排除了运算符优先级歧义、隐式转换误匹配、未初始化读取和嵌套陷阱等 AI 常犯错误类别 |
| **人类阅读友好** | 不考虑人类编码体验，以最大阅读清晰度为目标：显式类型标注、运算函数化、命名形参和关键字块结构使代码自文档化；阅读者无需推断隐式转换、运算符优先级、块边界或函数调用目标 |
| **安全计算** | 默认 strict 模式检测整数溢出与浮点异常；完整的 CFG 确定初始化分析杜绝未初始化读取；`cast`/`bitcast` 显式分类杜绝隐式位丢失；零未定义行为 |
| **可靠计算** | VM 与 AOT 共享同一抽象机语义，给定相同输入必得相同输出；浮点规则与 IEEE 754-2019 精准对齐；as-if 规则保证优化不改变可观察行为；所有合法程序的行为完全确定 |

0.0.33 的能力边界如下：

| 类别 | 当前定义 |
| ---- | -------- |
| 类型 | 8 种固定宽度整数（`int8`～`uint64`）、`float32`、`float64`、`bool`；`void` 仅表示函数无返回值 |
| 算术 | `add`、`sub`、`mul`、`div`、`mod`、`abs`、`neg`；整数与浮点均支持，浮点 `mod` 的商向零截断 |
| 位与逻辑 | 整数按位 `and`/`or`/`xor`/`not` 和 `shl`/`shr`；布尔逻辑 `and`/`or`/`xor`/`not`；由首个类型参数区分重载 |
| 比较 | `eq`、`ne`、`lt`、`le`、`gt`、`ge`，支持整数和浮点，结果为 `bool` |
| 转换 | 数值 `cast`、整数窄化 `cast(..., truncate, ...)`、等宽整数/浮点位重解释 `bitcast` |
| 模式 | 默认 strict；有符号整数算术及整数 `shl` 可按规则使用 `wrap`，浮点算术可按规则使用 `ieee`；浮点不支持 `wrap` |
| 控制流 | 缩进敏感且以 `end` 结束的 `if`/`while`；`break`/`continue`；仅函数内允许受限 `goto`/`label`，且 `while` 内禁止二者 |
| 函数 | 顶层 `func`、命名且有序的 `funcall`、显式 `return`；参数按值且只读，各函数作用域、调用帧和 CFG 独立，调用图无环 |
| 模块 | 一个 `.tc` 文件恰好定义一个全程序唯一的静态命名空间；模块不可实例化；首个有效行以 `#program` 或 `#lib` 声明模式；以 `import xxx` 导入 `xxx.tc` 库模块，以 `xxx.id` 访问其公开成员 |
| I/O | `write`、`writeln`、`read`；输出支持 13 种转换符及 C99 风格的标志、字段宽度和精度控制 |
| 入口 | `#program` 模块的顶层语句按源序执行；无特殊 `main`，顶层只允许结构化控制流 |

#### 1.2 设计原则

本节以 TC 的五项核心定位为纲组织设计原则。每条原则同时服务于多个定位，归入其贡献最突出的类别。

##### 1.2.1 教学友好：降低认知负荷，语义唯一可推断

| 原则 | 设计意图 | 详见 |
| ---- | -------- | ---- |
| 逐条执行 | 每条语句至多一个运算，无表达式嵌套，学习者可逐行暂停检查状态 | §4.5 |
| 显式类型标注 | 声明必须标注具体类型，类型信息始终可见 | §4.2 |
| 类型参数首位 | 运算类型作为第一个参数显式给出，无需猜测结果位宽或符号性 | §5 |
| 缩进强制 | 块结构由缩进界定、`end` 结束，控制流范围一目了然 | §9.1.2 |
| 常量与变量分离 | `let` 编译期求值，`var` 运行时可变 | §4.2–4.3 |

##### 1.2.2 AI 自动化编程友好：约束生成空间，消除易错模式

| 原则 | 设计意图 | 详见 |
| ---- | -------- | ---- |
| 声明时必须初始化 | `var` 统一带 `= <初始化器>`，杜绝声明后忘记初始化的错误模式 | §4.2 |
| 声明与再赋值分离 | 首次用 `var … = …`，其后省略 `var`；不存在模糊的首次写入路径 | §4.2, §4.4 |
| 运算函数化 | 所有运算以 `op(类型, 操作数…)` 调用，无优先级、结合性或隐式重载 | §5–8 |
| 同类型运算 | 操作数必须同类型，无混合精度算术 | §3.5, §5.1 |
| 单调用语句 | funcall 实参与 return 操作数限于 `operand`，禁止嵌套 | §10.2, §10.3 |
| 字面量类型显式 | 后缀唯一决定字面量类型，无推断歧义 | §2.3–2.5, §3.6 |
| 函数内跳转边界 | goto/label 限于函数体内，顶层禁止使用 | §9.3 |

##### 1.2.3 人类阅读友好：自文档化，无需推断

| 原则 | 设计意图 | 详见 |
| ---- | -------- | ---- |
| 显式类型转换 | 跨类型须通过 `cast` 完成，禁止隐式转换；阅读者不会漏掉类型改变 | §8 |
| 命名空间限定 | `module.id` 与 `Self.id` 是静态限定名，调用来源和状态归属完全透明 | §4.1 |
| 显式函数数据流 | 值仅通过参数/返回值进出函数，库状态访问须显式 `Self.id` | §10.4.1, §4.1.3 |
| I/O 格式化 | 单语句单操作数输出，格式说明符集中表达意图，无需拼接推断 | §12 |

##### 1.2.4 安全计算：默认检测，杜绝静默错误

| 原则 | 设计意图 | 详见 |
| ---- | -------- | ---- |
| 默认严格模式 | 有符号整数与浮点运算默认检测异常并报错；wrap/ieee 须显式声明 | §5.2 |
| 初始化安全 | 语法层声明时初始化 + 控制流层完整 CFG 确定初始化分析；可达的未初始化读取均为静态错误 | §4.2, §11.2 |

##### 1.2.5 可靠计算：行为完全确定，跨后端一致

| 原则 | 设计意图 | 详见 |
| ---- | -------- | ---- |
| 零未定义行为 | 规范未定义语义的程序形态即不合法；除实现资源失败及宿主 I/O 设备物理行为外无自由选择空间 | §1.4 |
| 实现一致性 | VM、AOT 与常量求值遵循相同的位宽、舍入、错误和控制流规则；同输入必同输出 | §1.4 |
| 调用图无环 | 禁止递归（直接与间接），栈深度编译期可确定上界 | §10.6.3 |

#### 1.3 设计哲学

TC 不优化人类编码效率，所有设计取舍优先服务于代码的阅读清晰性、AI 生成正确性以及计算的安全性与可靠性。

#### 1.4 规范约定与一致性判定

为避免资料性内容、示例和强制规则相互覆盖，本说明书使用以下规范层次：

1. **必须 / 禁止 / 仅可 / 不得** 表示一致性实现必须满足的规范性要求；**应当 / 建议** 表示不改变合法程序集合的实现或风格建议；**可以** 表示实现自由，但不得改变可观察语义。
2. 附录 A 只决定 Token 序列的**语法接受集**；正文决定通过语法后的静态语义、抽象执行语义和诊断映射。两者分工而非互相覆盖：正文不得放宽附录 A，附录 A 也不替代正文的类型、模式、作用域和运行时规则。
3. 第 14 章、附录 B、附录 C，以及标为“示例”或“设计说明”的段落均为**资料性内容**。资料性内容若与规范性正文或附录 A 冲突，不改变语言语义；应视为文档缺陷并以规范性条款为准。
4. TC 程序的可观察行为包括：是否通过静态检查、首个规范诊断及其错误码、按源序**成功提交到 TC 抽象标准输出**的字节、正常结束或首个运行时错误，以及运行时错误码。失败输出语句可能泄漏到宿主设备的物理前缀按 §12.2 明确排除在 TC 语言级可观察行为之外。槽位地址、调用帧物理布局、宿主字节序、宿主浮点环境和该类宿主设备泄漏不是可观察行为。
5. 除明确标为实现扩展的资源失败，以及 §12.2 明确隔离的宿主 I/O 设备物理行为外，不存在“实现自行选择”的未定义行为。规范未为某种源程序形态给出语法或静态语义时，该程序不合法；规范允许实现自由时，实现仍须保持相同的合法程序集合和可观察行为。给定相同的抽象输入 Token 序列和 I/O 成功/失败结果，VM 与 AOT 必须得到相同的 TC 抽象行为。
6. 浮点术语以 **IEEE 754-2019** 的 binary32、binary64、roundTiesToEven、NaN、无穷和非规格化数定义为准；与 C99 宿主规则不一致时，以本说明书定义的 TC 抽象机器为准。AOT 不得把宿主 C99 的未定义行为、实现定义行为、额外精度或当前舍入环境泄漏为 TC 行为。
7. VM、AOT 和优化器均遵循 **as-if** 规则：可以改变内部表示、布局与指令序列，但必须保留规范静态诊断、实际执行路径上的运行时错误顺序、标准 I/O 顺序和值结果。普通 RHS 中可在编译期算出的 strict 运算仍具有运行时错误语义；不得把它提升为 `let` 式静态错误，也不得因结果随后未使用而删除一个可能报错的指令。

“一致性实现”是指其前端与执行后端共同满足以上规则的实现。仅解析而不执行的工具可以只声明其所覆盖的阶段，但不得把实现限制描述为 TC 语言限制。

### 2. 词法结构

本章定义 TC 语言的基本词法单元。完整的 EBNF 定义见附录 A。

#### 2.1 字符集与 Token

TC 源文件的“编码字符集”与“可形成 Token 的字符集”分层规定：

1. **源编码**：文件必须是有效 UTF-8 字节序列。不接受 UTF-8 BOM；文件起始的 U+FEFF 按非法源字符处理。U+0000 在源文件任何位置均非法。
2. **Token 与结构字符**：除行注释内容外，只允许附录 A 终结符使用的 ASCII 字符：`A`–`Z`、`a`–`z`、`0`–`9`、`_`、`+`、`-`、`#`、`%`、`=`、`:`、`,`、`(`、`)`、`;`、`.`。字符是否能出现在具体位置仍由最长匹配规则与附录 A 决定；“属于本字符表”不代表在任意位置都是合法 Token。
3. **源空白、缩进与行结束**：Token 之间的水平空白可为 ASCII 空格 U+0020 或水平制表符 U+0009；但对非空、非纯注释逻辑行，第一个 Token 之前的**行首缩进只能由 ASCII 空格 U+0020 组成**，每连续 4 个空格表示一级，行首空格总数必须能被 4 整除，不得使用 U+0009 制表符缩进。逻辑行结束仅为 LF（U+000A）、CRLF（U+000D U+000A）或 CR（U+000D）。其他 Unicode 空白不是 TC 空白。
4. **注释内容**：分号 `;` 之后到当前逻辑行结束之前，允许任意已正确 UTF-8 解码的 Unicode 标量值（U+0000 除外）。注释内容不产生 Token，其中的非 ASCII 字符、关键字或类似数值的文本均不参与词法分析。

非法 UTF-8 在 UTF-8 解码阶段拒绝；BOM、U+0000，以及注释外的非 ASCII 字符、未列出的 ASCII 字符或非法空白在随后的词法/源字符检查中拒绝。两类均映射为 `TC_ERR_SYNTAX`。

#### 2.2 标识符

- 由字母、数字与 `_` 组成，**必须以字母或 `_` 开头**。
- **区分大小写**：`a` 与 `A` 为不同变量。
- 合法：`a`、`count`、`_tmp1`、`my_var`
- 非法：`1a`、`-x`（`-` 非标识符字符）

#### 2.3 整数字面量

##### 2.3.1 后缀与符号性

TC 字面量通过后缀区分符号性：

| 后缀      | 符号性 | 示例                   |
| --------- | ------ | ---------------------- |
| 无后缀    | 有符号 | `42`、`-128`、`0xFF`   |
| `u` / `U` | 无符号 | `42u`、`255u`、`0xFFu` |

**关键规则**：
- 无后缀字面量视为有符号整数，可用于有符号类型上下文；若用于无符号上下文，须满足范围约束
- `u` 后缀字面量视为无符号整数，**仅可用于无符号类型上下文**；用于有符号上下文触发 **字面量类型错误**
- 负号 `-` **仅可与无后缀字面量**组合；`-42u` 为非法
- 进制前缀只改变数值的书写方式，不改变其数学值，也不触发隐式补码重解释。例如 `0b1000_0000` 的数学值为 `128`，不能直接用于 `int8` 上下文；`int8` 的最小值应写作 `-128`

##### 2.3.2 进制

TC 支持四种进制字面量：

| 进制           | 前缀        | 数字字符集                | 示例                      |
| -------------- | ----------- | ------------------------- | ------------------------- |
| 十进制（默认） | —           | `0`–`9`                   | `0`、`255`、`-128`、`42u` |
| 十六进制       | `0x` / `0X` | `0`–`9`、`a`–`f`、`A`–`F` | `0xFF`、`0x1Au`、`-0x80`  |
| 二进制         | `0b` / `0B` | `0`、`1`                  | `0b1010`、`0b11111111u`   |
| 八进制         | `0o` / `0O` | `0`–`7`                   | `0o377`、`-0o100`         |

- 前缀中的 `0` 是必需的前导，**不区分大小写**
- 前缀与数字之间 **不可有空白**
- 后缀紧跟数字部分，前缀与后缀之间 **不可有空白**

##### 2.3.3 数字分隔符

为增强长数字的可读性，允许在下述位置插入单个下划线 `_`：

- 十进制：两个十进制数字之间（首数字之后、末数字之前）
- 十六进制：数字部分的两个十六进制数字之间
- 二进制：数字部分的两个二进制数字之间
- 八进制：数字部分的两个八进制数字之间

示例：

```text
1_000_000           → 1000000
0xFFFF_0000u        → 4294901760
0b1010_0011u        → 163
-0x7F_FF            → -32767
```

**约束**：不可连续两个 `_`，不可在字面量首尾放置 `_`，不可在前缀内部插入 `_`（如 `0x_FF` 非法）。

##### 2.3.4 前导零

- 十进制字面量 **不允许前导零**（`007` **非法**，应写作 `7`）；忽略分隔符后仍按数字序列判定，因此 `0_0`、`0_7` 也非法
- 单个 `0` 是合法的十进制零，不视为前导零特例
- 八进制须显式使用 `0o` 前缀

##### 2.3.5 字面量的词法上限

- 整数字面量的**数值**不得超过 `uint64` 范围：`0 ≤ N ≤ 18446744073709551615`
- 整数字面量超出此范围 → **字面量范围错误**

本节上限是只依赖 Token 自身的**第 2 阶段词法值检查**：在最长匹配形成候选整数字面量后、进入语法解析前执行，失败固定报告 `TC_ERR_LITERAL_OUT_OF_RANGE`。它不同于第 6/7/8 阶段依据变量、形参或返回类型进行的上下文字面量检查；两类检查的阶段分工见 §13.1。

##### 2.3.6 负号与减法运算符的关系

`-` 前缀仅出现在无后缀整数字面量中，**不作为独立的一元运算符**。若需变量间的减法，使用 `sub` 指令。

##### 2.3.7 词法分析器匹配策略

词法分析器采用 **最长匹配** 策略：
1. 扫描 `0` 时，检查后续字符是否为 `x`/`X`/`b`/`B`/`o`/`O`，转入对应进制（十六进制、二进制或八进制）
2. 数字部分扫描完成后，检查后续字符是否为 `u`/`U`，归约为带后缀字面量
3. 否则归约为无后缀字面量

#### 2.4 浮点字面量

##### 2.4.1 格式与后缀

TC 支持十进制浮点字面量和科学计数法：

| 形式                    | 示例                     | 类型                     |
| ----------------------- | ------------------------ | ------------------------ |
| 十进制浮点              | `3.14`、`-0.5`、`1.0`    | 无后缀 → `float64`       |
| 单精度后缀              | `3.14f`、`-0.5F`、`1.0f` | `f`/`F` 后缀 → `float32` |
| 科学计数法（小写 e）    | `1.2e5`、`-3.14e-2`      | 无后缀 → `float64`       |
| 科学计数法（大写 E）    | `1.2E5`、`-3.14E-2`      | 无后缀 → `float64`       |
| 科学计数法 + 单精度后缀 | `1.2e5f`、`-3.14E-2F`    | `f`/`F` 后缀 → `float32` |

**关键规则**：
- 浮点字面量必须包含小数点 `.` 或指数标记 `e`/`E`
- 无后缀浮点字面量为 `float64` 类型
- `f`/`F` 后缀浮点字面量为 `float32` 类型
- 浮点字面量 **不区分符号性**（浮点数无符号概念）
- 负号 `-` 可与浮点字面量组合
- 浮点字面量 **仅可用于能确定源浮点类型的上下文**（含 `float32`/`float64` 运算、`cast` 或 `bitcast`）
- 有限十进制字面量先解析为精确数学值，再直接按 roundTiesToEven 舍入到后缀决定的 binary32/binary64；不得通过另一浮点类型中转
- 非零有限值舍入为零，或有限值舍入为无穷 → **字面量范围错误**；可表示的非规格化数合法
- 数学值为零且字面量显式带 `-` 时生成负零；其余零字面量生成正零

有限浮点字面量的源类型完全由 `f`/`F` 后缀决定，因此上述“舍入为零或无穷”的检查同样是只依赖 Token 自身的**第 2 阶段词法值检查**，失败报告 `TC_ERR_LITERAL_OUT_OF_RANGE`。后续上下文只检查该已形成的 `float32` / `float64` 字面量是否与期望类型一致，不重复改变其源类型或舍入结果。

**特殊浮点值**：

| 字面量 | 含义             | IEEE 754 表示                |
| ------ | ---------------- | ---------------------------- |
| `inf`  | 正无穷           | 指数全 1，尾数全 0，符号位 0 |
| `-inf` | 负无穷           | 指数全 1，尾数全 0，符号位 1 |
| `nan`  | 非数（静默 NaN） | 指数全 1，尾数非 0           |

**约束**：
- `inf`、`-inf`、`nan` 为保留关键字，不可用作标识符
- 区分大小写：均为小写。`INF`/`NaN` 等其他大小写形式按普通标识符词法化，若未声明则报 `TC_ERR_UNDEFINED_VARIABLE`

```text
var pi: float64 = 3.141592653589793
var e: float32 = 2.71828f
var speed: float64 = 3.0e8
var tiny: float32 = 1.0e-38f
var inf_pos: float64 = inf
var nan_val: float64 = nan
```

##### 2.4.2 词法错误

```text
3.14u     ; 非法：浮点不支持 u 后缀
.5        ; 非法：须 0.5
1e5       ; 合法：科学计数法（整数指数形式）
```

#### 2.5 布尔字面量

| 字面量  | 值   | 类型   |
| ------- | ---- | ------ |
| `true`  | 真   | `bool` |
| `false` | 假   | `bool` |

**约束**：
- `true` 和 `false` 为保留关键字，不可用作标识符
- **区分大小写**，且仅小写形式是布尔字面量。`True` / `FALSE` 等按普通标识符词法化，若未声明则报 `TC_ERR_UNDEFINED_VARIABLE`
- 布尔字面量 **仅可用于** `bool` 类型上下文

```text
var flag: bool = true
var done: bool = false
var err: int32 = true      ; 字面量类型错误
```

#### 2.6 注释

- 行注释以 `;` 开始，延续至行尾
- 注释内容可以使用 Unicode；注释之外的 Token 仍仅使用 §2.1 规定的 ASCII 字符
- 示例：`var a: int32 = 10    ; 定义 32 位整数`

#### 2.7 关键字

以下 token 为保留关键字，不可用作标识符：

```text
var  let  bool  true  false
int8  uint8  int16  uint16  int32  uint32  int64  uint64
float32  float64
add  sub  mul  div  mod  abs  neg
eq  ne  lt  le  gt  ge
and  or  xor  not      ; 均支持 bool 逻辑与整数按位重载
shl  shr
cast  bitcast  wrap  truncate  ieee
write  writeln  read
if  then  else  end
while  break  continue   ; 结构化循环控制
goto  label            ; 仅函数体内可用的非结构化跳转
func  funcall  return  void  ; 函数定义、调用与返回
import                       ; 库模块导入
static  Self                  ; 库模块静态成员与当前模块限定符
public  private               ; 模块成员可见性修饰符
inf  nan
```

`#program` 和 `#lib` 是模式指令 Token，只能出现在 §4.1 规定的文件首个有效行。`call` 不是 0.0.33 的调用关键字；函数调用必须写作 `funcall`。`void` 只允许出现在函数返回类型位置。

#### 2.8 语句与行结构

- 每条语句独占一行
- **空行**、**仅含 ASCII 空格/制表符的行**、**仅含行注释**的行均合法，不产生语句；这些行的行首空白不构成缩进。非 ASCII 空白不能构成空白行
- 语句由 `NEWLINE` 结束。`;` 始终是行注释起始符；因注释可紧跟语句，外观上可写为“语句末尾的可选 `;`”，但语法 Token 序列中不存在分号终结符

### 3. 类型与值

#### 3.1 类型分类

TC 0.0.33 支持 **整数类型**、**浮点类型**、**布尔类型**，并以 `void` 表示函数不返回值：

| 类别         | 支持的类型               | 说明                   |
| ------------ | ---------------------- | ---------------------- |
| **整数类型** | `int8`～`uint64`       | 固定宽度二进制补码整数 |
| **浮点类型** | `float32`、`float64`   | IEEE 754 浮点数        |
| **布尔类型** | `bool`                 | 逻辑真/假              |
| **无值标记** | `void`                 | 不是值类型，仅用于函数返回类型 |

#### 3.2 整数类型

| 类型     | 位宽 | 符号   | 最小值                     | 最大值                     |
| -------- | ---- | ------ | -------------------------- | -------------------------- |
| `int8`   | 8    | 有符号 | −128                       | 127                        |
| `uint8`  | 8    | 无符号 | 0                          | 255                        |
| `int16`  | 16   | 有符号 | −32,768                    | 32,767                     |
| `uint16` | 16   | 无符号 | 0                          | 65,535                     |
| `int32`  | 32   | 有符号 | −2,147,483,648             | 2,147,483,647              |
| `uint32` | 32   | 无符号 | 0                          | 4,294,967,295              |
| `int64`  | 64   | 有符号 | −9,223,372,036,854,775,808 | 9,223,372,036,854,775,807  |
| `uint64` | 64   | 无符号 | 0                          | 18,446,744,073,709,551,615 |

类型命名规则：`<符号前缀><位宽>`，其中符号前缀为 `int`（有符号）或 `uint`（无符号），位宽为 `8`/`16`/`32`/`64`。

#### 3.3 浮点类型

| 类型      | 位宽 | IEEE 754 对应 | 最小正非零值（约） | 最大有限绝对值（约） | 精度（十进制） |
| --------- | ---- | ------------- | ------------ | ------------ | -------------- |
| `float32` | 32   | binary32      | 1.4e-45      | 3.4e38       | ~7 位          |
| `float64` | 64   | binary64      | 5e-324       | 1.8e308      | ~16 位         |

**内部表示**：
- 浮点数以 IEEE 754 二进制格式存储
- `float32`：符号字段 1 位 + 指数字段 8 位 + fraction 字段 23 位
- `float64`：符号字段 1 位 + 指数字段 11 位 + fraction 字段 52 位
- 浮点数的“位模式”只能通过等位宽 `bitcast` 与整数互转

#### 3.4 布尔类型

`bool` 类型表示逻辑真值，取值为 `true` 或 `false`。

**抽象表示**：
- `bool` 的抽象值域恰好为 `false` 与 `true`，所有产生 `bool` 的指令、`read` 和 `cast` 都必须把结果规范化为其中之一。
- `bool` 没有可由 TC 程序观察的位宽、对象布局或第三种“非零真值”位模式；其物理存储由后端自行决定。
- 若后端在 ABI 或内部载体上接收非规范布尔表示，必须先规范化再进入 TC 抽象机器；不得让该表示影响比较、逻辑、I/O 或函数传参结果。
- **不可** 将 `bool` 直接解释为整数；数值互转须通过 `cast`。`bitcast` 明确排除 `bool`，因此内部布局不会成为语言语义。

**类型性质**：
- 比较运算和逻辑运算的结果类型为 `bool`。
- `bool` 变量可被赋值、读取、输出。
- 与所有类型相同：`bool` 的 `var` 定义**声明时必须初始化**（§4.2）。

```text
var flag: bool = true      ; 声明并初始化
var done: bool = false     ; 声明并初始化
; var uninit: bool         ; ❌ 静态错误：变量定义必须初始化
```

#### 3.5 类型性质

**有符号类型（`int8`～`int64`）**

- 采用 **二进制补码** 表示
- `add`/`sub`/`mul`/`neg` 默认 **严格模式**：结果超出范围 → **整数溢出错误**
- `div` 的数学商不可表示时，以及 `abs(INT_MIN)` 时 → **整数溢出错误**
- 显式 `wrap` 模式：按模 `2^n` 回绕，不报错
- `shl` 默认严格模式：左移结果超出范围 → **整数溢出错误**；`wrap` 模式截断高位

**无符号类型（`uint8`～`uint64`）**

- 仅表示非负整数
- 算术结果超出最大值时 **模 `2^n` 回绕**，不报错
- `div`/`mod` 结果恒为非负
- `shl` 默认严格模式（仍可检测值溢出，例如 `shl(uint8, 255u, 1)` 的数学结果超过 255 时报错），`wrap` 模式截断高位

**浮点类型（`float32`、`float64`）**

- 符合 IEEE 754 标准
- 支持两种算术模式（详见 §5）：
  - **严格模式**（默认）：上溢/下溢/除零/无效操作均报错
  - **IEEE 754 模式**（`ieee`）：遵循 IEEE 754，返回 ±inf/nan，不报错
- 0.0.33 **不支持浮点 `wrap`**；位模式操作须通过等宽 `bitcast` 转为整数后完成
- 浮点数不支持位运算（`and`/`or`/`xor`/`not`/`shl`/`shr`）

**布尔类型**

- 仅表示逻辑真值
- 比较运算和逻辑运算返回 `bool`
- 不参与算术运算（须显式 `cast`）

**无值返回标记（`void`）**

- 只表示函数没有返回值，不是值类型
- 没有位宽、字面量、变量槽或运行时值
- 不能参与运算、转换、I/O、参数传递或变量/常量定义

**运行时值模型**

TC 中每个整数或浮点变量的值由 **n 位抽象位串**（`n` 为类型位宽）与 **类型解释** 共同构成：

- 整数内部以 n 位无符号位模式存储；有符号类型按 **二进制补码** 解释，无符号类型按非负整数解释
- 浮点数内部以 IEEE 754 位模式存储
- `bool` 只具有 `false` / `true` 两个抽象值，不参与本位串模型
- `wrap` 算术回绕、整数 `cast(..., truncate, ...)` 与等宽 `bitcast` 均在此位模式上操作
- 有符号 `wrap` 下的 `add`/`sub`/`mul`/`neg` 与同位宽无符号默认回绕 **位模式一致**

抽象位串按“最高有效位到最低有效位”的数值位权定义，与宿主内存的大小端字节序无关。`bitcast` 保持的是该抽象位串，不是对宿主对象表示执行类型别名访问；VM 与 AOT 在不同字节序主机上必须得到相同数值结果。

#### 3.6 字面量与类型的关系

字面量先由自身形式确定类别或源类型，再由所在位置提供的期望类型检查。不存在隐式跨类别转换。

##### 3.6.1 字面量检查规则

| 字面量 | 检查规则 |
| ------ | -------- |
| 无后缀整数 | 解析绝对值 `N`（`0 ≤ N ≤ 2^64−1`）；可带 `-`。有符号上下文要求数学值位于 §3.2 对应范围；无符号上下文要求值非负且在范围内 |
| `u`/`U` 整数 | 不得带 `-`，仅用于无符号整数上下文，且值须在对应范围内 |
| 普通浮点 | 无后缀源类型为 `float64`，`f`/`F` 后缀源类型为 `float32`；精确十进制值直接按 roundTiesToEven 舍入到该类型，不经另一浮点类型中转 |
| `inf`/`-inf`/`nan` | 仅用于浮点上下文；`nan` 为 §5.3 的 canonical quiet NaN |
| `true`/`false` | 仅用于 `bool` 上下文 |

非零有限浮点值舍入为零或有限值舍入为无穷时报字面量范围错误；可表示的非规格化数合法。类别、后缀或符号性与上下文不符时报字面量类型错误。`wrap`、`ieee`、`truncate` 和 `bitcast` 均不绕过这些检查。

```text
var a: int8 = 127       ; 合法
var b: uint8 = 255      ; 合法：无后缀非负整数可用于无符号上下文
var c: uint8 = 255u     ; 合法
var f: float32 = 1.5f   ; 合法
; var bad: int8 = 128   ; 字面量范围错误
; var bad: int32 = 1u   ; 字面量类型错误
```

#### 3.7 类型转换的通用框架

TC 0.0.33 将数值转换、整数截断与位重解释分开：

| 形式 | 用途 | 核心约束 |
| ---- | ---- | -------- |
| `cast(T, operand)` | 数值转换 | 按目标类型做范围检查与规定舍入 |
| `cast(T, truncate, operand)` | 整数缩窄 | 仅整数→更窄整数，保留低位 |
| `bitcast(T, operand)` | 位重解释 | 源、目标等宽；不改变任何位；`bool` 不参与 |

严格 `cast` 覆盖整数 ↔ 整数、整数 ↔ 浮点、浮点 ↔ 浮点，以及整数/浮点 ↔ `bool`。`truncate` 不再承担浮点位重解释；所有整数/浮点位模式互转统一使用 `bitcast`。

## 第二部分：程序结构与表达式

### 4. 程序结构、声明与表达式

#### 4.1 程序构成

一个 TC 编译单元恰好是一个 `.tc` 源文件，一个源文件恰好定义一个**模块**。除空行和纯注释行外，源文件的首行必须是模式指令 `#program` 或 `#lib`；指令不是语句，不得重复，也不得位于模块中部。未显式声明模式的文件是语法错误，实现不得猜测或默认其模式。

模块是全程序唯一的**静态命名空间**，不是值或运行时对象。模块不能实例化、复制、赋值、作为实参传递或作为返回值；TC 不定义模块实例身份、构造或多实例生命周期。`<模块名>.<成员名>` 与 `Self.<成员名>` 是静态名称限定形式，其中 `.` 不是通用的运行时成员访问运算符。

**模块语句分层排序规则**：除空行和纯注释行外，模块内顶层构造必须按以下固定层级顺序依次出现，跨层交错为静态错误：

1. **第一层**：模式指令 `#program` 或 `#lib`（文件首个有效行）；
2. **第二层**：`import` 声明区（所有 `import` 连续出现，可为空）；
3. **第三层**：声明定义区——`#lib` 中为 `static var` / `static let`（须带 `static` 关键字）；`#program` 中 `static var` / `static let` 为静态错误，仅允许顶层 `var` / `let`（不得使用 `static` 关键字）；
4. **第四层（最末等）**：`func` 函数定义（仅 `#lib` 允许；`#program` 不得定义函数）。

各层内部构造之间允许任意空行和纯注释行，但不得插入其他层的构造。前三层全部处理完毕后，才允许出现第四层的 `func` 或 `#program` 的顶层执行语句。模块中不得超过一个模式指令，且不得有跨层构造。

##### 4.1.1 程序模式（`#program`）

`#program` 模块不得定义函数；`static var` / `static let` 声明定义属于 `#lib` 模块专有构造，不得在 `#program` 中使用。`#program` 仅由三层构成：模式指令行（第一层）、可为空的 `import` 声明区（第二层）、可为空的顶层 `var` / `let` 声明定义区（第三层），之后为**顶层语句区**。顶层语句区由一系列可执行语句（赋值、I/O、控制流、`funcall` 等）按源序组成。`var` / `let` 声明不是可执行语句，必须全部位于第一条顶层可执行语句之前；一旦进入顶层可执行语句区，后续不得再声明 `var` / `let`。

程序模块可由宿主独立加载并运行。每次运行建立一个新的**程序运行环境**，完成可达库模块的静态存储初始化后，从顶层语句区的第一条可执行语句开始，按源序执行至文件末尾或首个运行时错误。新的程序运行重新初始化全部可达库模块的 `static var`，但不创建任何模块实例。TC 没有特殊 `main` 入口。`#program` 模块不得使用 `func` 或 `Self`，也不得出现 `static var` / `static let`；出现任何带 `static` 关键字的声明定义均为静态错误。

##### 4.1.2 库模式（`#lib`）

`#lib` 模块只允许以下顶层构造，每种构造必须以 `public` 或 `private` 关键字作为第一个修饰符，**必须显式书写，无默认值**：

- `public func` 或 `private func` 函数定义；
- `public static let` 或 `private static let <名>: <类型> = <const_rhs>` 模块常量；
- `public static var` 或 `private static var <名>: <类型> = <rhs>` 模块变量。
- 可见性修饰符只允许在 `#lib` 模块中使用；`#program` 模块不得出现 `public` 或 `private`。缺少可见性修饰符的库成员定义是静态错误。
- `public` 表示该成员可被导入者通过 `<模块名>.<成员名>` 访问；`private` 表示仅限本模块内部使用。

所有 `static let` 和 `static var` 声明定义必须出现在任何 `func` 函数定义之前；`static` 成员之间及函数定义之间的顺序不限。违反该排序（函数定义出现在 `static` 成员之前）为静态错误。

库模块不存在顶层语句区；未带 `static` 的顶层 `let` / `var`、赋值、调用、I/O 和控制流均为语法错误。`static let` 遵守 §4.3.1 的编译期常量规则。`static var` 初始化器不得包含 `funcall`，并且只得引用源序中更早已成功初始化的 `Self` 静态成员。

每个可达库模块的每个 `static var` 在一次程序运行中恰好对应一个**模块静态存储槽**，由宿主按源序初始化一次；完成初始化后不自动调用任何函数。同一模块无论被多少个模块直接或间接导入，所有调用均共享这唯一份静态存储；导入不复制状态。任一静态成员初始化失败时，整个程序准备失败，不得执行任何库函数或程序顶层语句。这些静态存储槽属于程序运行环境，不构成模块实例。

##### 4.1.3 `Self` 成员限定

`Self` 是仅在 `#lib` 模块内有效的保留字，表示“当前模块命名空间”。它仅可作为限定名的首部，不是值、类型、运行时对象或可绑定的标识符。函数体内访问本库的函数或静态成员必须使用限定名 `Self.<名>`：

```tc
#lib

static let step: int32 = 1
static var count: int32 = 0

func next() int32 then
	Self.count = add(int32, Self.count, Self.step)
	return Self.count
end

func twice() int32 then
	var first: int32 = funcall(Self.next)
	return add(int32, first, Self.step)
end
```

`Self.<名>` 必须恰好解析为当前库模块的一个顶层 `func`、`static let` 或 `static var`。当它解析为 `static let` 绑定时只读，解析为 `static var` 绑定时可读且可赋值；二者的确定初始化在程序准备成功后对所有函数成立。库函数内对本库函数或静态成员使用未限定的裸名是静态错误；局部绑定和形参仍使用裸名。这一规则避免局部名与模块成员之间的隐式捕获。`Self` 只表示当前模块命名空间，不能用于访问导入模块。

##### 4.1.4 库成员可见性

`#lib` 模块的顶层 `func`、`static let` 和 `static var` 均为模块成员。每个成员必须以 `public` 或 `private` 关键字作为第一个修饰符，**必须显式书写，没有默认可见性**：

- `public` 表示该成员可被导入者通过 `<模块名>.<成员名>` 访问。公开函数可调用，公开 `static let` 可读，公开 `static var` 可读且可赋值（包括作为 `read` 目标）。
- `private` 表示该成员仅限本模块内部使用。私有成员只能通过 `Self.<成员名>` 在模块内部访问。

可见性只由声明前的 `public` / `private` 修饰符决定，与成员名的字符形式无关。局部 `var` / `let`、函数形参和标签不是模块成员，不能带有 `public` / `private` 修饰符。

库内部使用 `Self.<成员名>` 可访问本模块的公开和私有成员。导入者使用 `<模块名>.<成员名>` 时只能解析公开成员。从导入者访问私有成员是静态可见性错误；实现不得将它降级为“成员不存在”，也不得因为 AOT 符号可被宿主链接器观察而绕过该检查。

##### 4.1.5 模块导入（`import`）

`#program` 和 `#lib` 都可以导入库模块。导入语法为 `import <模块名>`，其中模块名必须是一个 `identifier`：

```tc
#program

import counter

var value: int32 = funcall(counter.Next)
writeln(int32, "%d", value)
```

模式指令之后是可为空的**导入区**（第二层）。`import` 声明必须位于模式指令之后、所有 `static var` / `static let`（`#lib`）或顶层 `var` / `let`（`#program`）声明之前，不得出现在函数体或控制流块中。所有 `import` 必须连续出现，不得与 `static var` / `static let`、`var` / `let` 声明或函数定义交错。同一模块不得重复导入同名模块，导入名也不得与本模块的函数、静态成员或顶层值绑定同名。

`import xxx` 要求宿主的模块解析器唯一定位名为 `xxx.tc` 的源模块。导入目标必须声明为 `#lib`；导入 `#program`、找不到目标或同一逻辑名对应多个目标均是静态错误。源语言不接受路径、扩展名或字符串形式的导入；搜索目录的配置属于宿主接口，不属于 TC 源语法。

导入名在当前模块中引入对全程序唯一目标模块命名空间的静态引用；导入不构造、复制或实例化模块。导入成员必须使用 `<模块名>.<成员名>` 限定，不得省略模块名；该成员还必须具有 `public` 可见性（§4.1.4）。限定名中的模块名不是可求值的操作数，限定名整体在静态名称解析中确定其成员。0.0.33 不定义导入别名、选择性导入或通配导入。

**禁止循环导入**：以模块为顶点、`import` 为有向边建立完整模块依赖图。该图必须是有向无环图（DAG）；任一模块都不得经过一条或多条导入边回到自身。自导入、直接循环和任意长度的间接循环均是静态错误；即使环中的导入函数从未被调用，也不改变该结论。

```text
; a.tc: import b
; b.tc: import a             ; 非法：直接循环

; a.tc: import b
; b.tc: import c
; c.tc: import a             ; 非法：间接循环
```

实现必须在初始化任何 `static var` 或执行程序顶层语句之前，完成整张可达依赖图的环检查。不得以“部分初始化的模块”或懒加载规避循环诊断。

准备一次程序运行时，宿主按依赖顺序先处理其全部可达导入库；同一模块在完整可达依赖图中恰好对应一个全程序唯一的命名空间，其每个 `static var` 恰好分配一个模块静态存储槽，并被所有导入者共享。任一依赖解析、静态检查或初始化失败时，整次程序准备失败。

编译器必须在分析函数体和顶层语句前收集全部函数签名，因此 `#lib` 中函数可调用定义在其后的函数；调用图限制见 §10.6。每个函数构成独立控制流域，只有函数控制流域可以建立标签表和 `goto` 边。

**源构造种类**（其中 `func` 定义不是可执行语句，且仅允许在 `#lib` 模块中使用）：
- 模块导入（`import`，仅位于模式指令后的导入区，第二层）
- 变量定义（`var`）、常量定义（`let`）、赋值
- I/O（`write`/`writeln`/`read`）
- 结构化控制：条件分支（`if`-`then`-`else`-`end`）、循环（`while`-`then`-`end`）、循环控制（`break`/`continue`）
- 非结构化控制：函数体内的标签定义（`label`）与跳转（`goto`）
- 函数相关：`#lib` 模块函数定义（`func`）、函数调用（`funcall`）、函数返回（`return`）

**程序结构约束**：
- 模式指令必须是第一个非空、非注释逻辑行，且必须顶格书写
- 模块内顶层构造必须严格遵守 §4.1 的四层排序规则：模式指令（第一层）→ `import`（第二层）→ `static var` / `static let` 或顶层 `var` / `let`（第三层）→ `func` 函数定义或顶层可执行语句（第四层）。跨层交错为静态错误
- `import` 必须位于模式指令之后的连续导入区，且必须顶格书写
- 源文件由若干行组成；每行至多一条语句
- 空行、纯注释行均合法，不产生语句
- 语句由换行结束；`;` 仅引入行注释，词法层在产生 `NEWLINE` 前丢弃其后内容
- `#program` 模块不得定义函数；`#lib` 模块中函数定义只能出现在所有 `static var` / `static let` 之后；函数体、`if` / `else` 分支和 `while` 循环体内不得定义函数
- `func`/`if`/`while` 块内语句须满足 §9.1.2 的缩进规则
- **函数边界**：`goto` 与 `label` 必须具有 `func` 词法祖先；顶层直接使用，或在顶层 `if` / `else` / `while` 的任意嵌套层级使用，均为静态错误
- **范式隔离**：`while` 块内**严格禁止** `goto` 与 `label`（见 §9.2.4）

#### 4.2 变量定义（`var`）

##### 4.2.1 语法

`var` **声明时必须初始化**。统一外形为：

```text
var <identifier>: <type> = <initializer>
```

其中 `<initializer>` 是普通 `<rhs>`，或用于接收非 `void` 返回值的专用 `funcall`。

| 项目 | 规则 |
| ---- | ---- |
| 初始化器 | **强制**。`=` 与 `<initializer>` 不可省略 |
| 非法形态 | `var <identifier>: <type>`（无初始化器）→ 静态错误 `TC_ERR_VAR_MISSING_INIT` |
| RHS | 字面量、已定义标识符、单个运算、`cast` 或 `bitcast`（见 §4.5）；须与声明类型一致 |
| 函数返回初始化 | 非 `void` `funcall` 可通过专用形态 `var <名>: <类型> = funcall(...)` 初始化新变量（§10.2）；`funcall` 不属于普通 RHS |
| 再赋值 | 首次引入之后，修改写作 `<identifier> = <rhs>` 或 `<identifier> = funcall(...>`，**不再**写 `var`（§4.4） |

0.0.33 不允许“先声明、后首次赋值”。`read` 也不能代替初始化器：目标变量必须先以带初始化器的 `var` 定义，`read` 仅覆盖当前值（§12.3）。

##### 4.2.2 语义与检查

- 当且仅当该条 `var` 语句**执行成功**后，变量持有初始化器求得的有效值（顶层、函数和块内均在定义行写入预先建立的固定槽位）。
- 编译器对每条 `var` 做**语法/形态检查**：缺 `=` 或初始化器 → **`TC_ERR_VAR_MISSING_INIT`**（打印名 `VarMissingInitializer`，§13.1 / §13.5）。此检查与控制流无关，亦不依赖数据流分析；**不得**仅报笼统 `TC_ERR_SYNTAX`。
- 同一作用域内不可重复定义同名变量（作用域包括顶层、函数、`if`/`while` 块，以及 `then`/`else` 各自的互斥子块，见 §11.1、§9.1.5、§9.2.3）。跨类型值须先 `cast`；函数返回值则必须与接收类型严格相同。
- 声明带初始化器不等于该语句在所有路径上均已执行；完整 CFG 的确定初始化规则见 §11.2 与 §9.3.4。

```text
var a: int32 = 10                 ; ✅ 声明并初始化
var b: int32 = add(int32, a, 20)  ; ✅
var c: int8 = cast(int8, truncate, a)
var flag: bool = true
var pi: float64 = 3.14
var e: float32 = 2.71828f

var d: int32                      ; ❌ TC_ERR_VAR_MISSING_INIT
; d = 1                           ; 即便其后赋值，仍不能补救无初始化器的声明
```

块内 `var` 的可见性和生命周期按 §11.1 处理；离开该块后引用其绑定属于未定义标识符错误。

#### 4.3 常量定义（`let`）

使用 `let` 声明 **不可变常量**：

- RHS **必须** 提供
- RHS 须为 §4.3.1 定义的**单层编译期常量表达式**
- `let` 声明类型是整个 RHS 的唯一期望结果类型；RHS 结果必须与声明类型**完全一致**，不执行隐式转换，具体检查与诊断见 §4.3.1
- 常量在编译期求值；使用处**直接内联**编译期结果，**不生成运行时算术指令，亦不分配运行时变量槽**（与 §11.2、附录 B 一致）。源文件中 `let` 语句仍占一行，仅作为编译期声明
- `let` 的求值与可见性只由编译阶段和词法源序决定，不以运行时控制流是否经过该声明行为条件；合法 `goto` 绕过一条 `let` 不会使其在后续词法可见位置变为“未初始化”或不可用
- 为统一源级可达性诊断，每条 `let` 仍作为一个**无运行时效果的 CFG 身份节点**参与 §11.2.1 的可达性分析；该节点的数据流传递函数为恒等，不生成运行时指令
- 常量 **不可** 作为赋值语句的左值
- **在同一作用域内**，常量名不可与变量名或其他常量名冲突。

##### 4.3.1 编译期常量表达式

`let` 的 RHS 可包含以下任一形式：

**原子表达式**：
- 整数字面量（`42`、`-128`、`0xFFu`）
- 浮点字面量（`3.14`、`2.71828f`、`1.0e-5`）
- 特殊浮点值（`inf`、`-inf`、`nan`）
- 布尔字面量（`true`、`false`）
- 此前已定义的 `let` 常量引用（`PI`、`MASK`）

**单个调用表达式**（每个操作数只能是上述原子表达式）：
- 算术运算：`add`/`sub`/`mul`/`div`/`mod`/`abs`/`neg`，可使用 §5 允许的 `wrap` 或 `ieee` 模式；浮点 `mod` 同样支持 strict / `ieee`
- 位运算：`and`/`or`/`xor`/`not`（按位）、`shl`/`shr`（移位）
- 比较运算：`eq`/`ne`/`lt`/`le`/`gt`/`ge`（浮点比较允许但不推荐，因浮点精度）
- 逻辑运算：`and`/`or`/`xor`/`not`（布尔）
- 转换：严格 `cast`、整数 `cast(..., truncate, ...)` 与等宽 `bitcast`

**声明类型闭合与检查顺序**：

1. 先完成 `const_rhs` 内部的名称、运算支持类型、模式、操作数类型和字面量检查。单个调用表达式的操作数期望类型仅由该调用的显式类型参数决定；外层 `let` 声明类型不向调用内部传播，也不改变 §8.1.1 的 `cast` / `bitcast` 字面量源类型规则。
2. RHS 为直接字面量时，以 `let` 声明类型作为 §3.6 的期望类型：符号性、类别或浮点后缀不符时报 `TC_ERR_LITERAL_TYPE`，值不可表示时报 `TC_ERR_LITERAL_OUT_OF_RANGE`。
3. RHS 为标识符时，名称解析后以该绑定的声明类型为结果类型；RHS 为单个调用表达式时，按该调用的自身规则确定结果类型。若结果类型与外层 `let` 声明类型不完全一致，报 `TC_ERR_TYPE_MISMATCH`，定位到 RHS 的首个 Token。禁止因数值可表示而执行隐式窄化、加宽、符号性变换或整数/浮点转换。标识符若解析为 `var` 或函数参数，在本阶段完成类型闭合检查后，仍按本节约束于常量求值阶段报 `TC_ERR_CONSTANT_EXPRESSION`。
4. 只有上述名称和类型检查全部成功后才进入编译期求值。因此“RHS 结果类型不匹配”先于同一 RHS 的常量溢出、除零或无效浮点操作诊断。

**约束**：
- 常量表达式**不可** 引用任何 `var` 变量
- 常量表达式**不可** 包含 `funcall`；函数体内的 `let` 亦不得引用参数或局部 `var`
- 常量表达式**不可** 引用自身或尚未定义的 `let`
- 操作调用不可嵌套；复合计算须拆分为多条按源序定义的 `let`
- 由于只允许引用此前的 `let`，多常量循环依赖在语法可见性上不可形成，0.0.33 不定义常量循环依赖错误
- 有符号严格常量算术运算或 `shl` 的溢出，在编译期视为 **常量溢出错误** 并终止编译
- 常量 `shl` / `shr` 的移位计数按其整数类型直接取数学值；值为负时视为 **常量表达式错误 `TC_ERR_CONSTANT_EXPRESSION`** 并终止编译
- 严格浮点常量算术按 §5 的异常优先级求值：无效操作 → `TC_ERR_CONSTANT_EXPRESSION`，除零 → `TC_ERR_CONSTANT_DIV_ZERO`，上溢或下溢 → `TC_ERR_CONSTANT_OVERFLOW`；浮点 `mod` 不产生上溢或下溢
- 常量表达式中整数 `div`/`mod` 的除数为 0，或浮点严格 `div`/`mod` 的最高优先级异常为除零，视为 **常量除零错误** 并终止编译
- 常量移位、转换、NaN 与模式合法性完全复用 §5～§8 的运行时规则

常量表达式的“形态与依赖合法性”先于求值短路检查：`and(bool, false, x)` 或 `or(bool, true, x)` 中的 `x` 仍必须是合法、可见且已求值的更早 `let bool`。运行时逻辑短路和 §7.2.2 的确定初始化读边裁剪不得用于掩盖 `let` 中的非法依赖、名称或类型错误。

##### 4.3.2 静态布尔条件与三态判定

“静态布尔条件”是结果类型为 `bool`，且整体符合本节“编译期常量表达式”定义的单层 RHS。其原子操作数只能是字面量，或在当前词法作用域可见、定义语句位于使用点之前且已成功求值的 `let`；不得把 `var` 的当前值或跨语句运行时结果当作常量传播。

名称和类型检查完成后，编译器对 `if`/`while` 条件执行以下三态判定：

- **静态 `true`**：RHS 合法且按本节共享常量语义求值为 `true`；CFG 仅保留真边。
- **静态 `false`**：RHS 合法且求值为 `false`；CFG 仅保留假边。
- **`unknown`**：RHS 不是合法的单层常量表达式，或含 `var` 等不能静态解析的操作数；CFG 同时保留真、假边。

静态布尔判定只复用本节的表达式定义和 §5～§8 的共享语义，不建立第二套运算符白名单。布尔字面量、可见的更早 `let bool`、结果为 `bool` 的整数/浮点比较、布尔逻辑运算，以及目标为 `bool` 的合法严格 `cast` 均因此自然受支持；`bitcast` 不允许 `bool`，整数 `truncate` 也不能产生合法布尔条件。

三态判定与短路读边是两个独立分析结果。只要条件调用的任一操作数含 `var`，整个条件仍为 `unknown`，即使其左操作数足以由 `false and ...` 或 `true or ...` 决定运行时结果；§7.2.2 仍可单独删除右操作数的读取边。实现不得把该读边裁剪升级为本节未授权的 CFG 真/假边裁剪，否则会改变 `TC_ERR_UNREACHABLE_STATEMENT` 的合法程序集合。

前向 `let`、不可见 `let`、嵌套调用或其他非法形态在内部静态判定中不得被折叠；它们仍分别由更早的名称、语法或类型阶段报告错误，因此不会进入 CFG。若表达式形态合法但求值发生整数/浮点溢出、除零、无效浮点操作或严格转换失败，必须按本节既有映射报告 `TC_ERR_CONSTANT_OVERFLOW`、`TC_ERR_CONSTANT_DIV_ZERO`、`TC_ERR_CONSTANT_EXPRESSION` 或 `TC_ERR_CONSTANT_CAST_OVERFLOW` 并终止编译；不得降级为 `unknown`。

##### 4.3.3 浮点常量算术的精度规则

常量表达式中的浮点算术遵循以下规则：
1. 每条指令均按其显式类型参数执行：`float32` 使用 binary32，`float64` 使用 binary64。
2. 每条指令结束时立即按 roundTiesToEven 舍入；不得统一提升为 `float64` 中间精度。
3. strict / `ieee` 的结果与同一指令在运行时执行完全一致。
4. 常量求值器不得使用 FMA、扩展精度、FTZ 或 DAZ。

```text
let PI: float64 = 3.141592653589793
let PI_SQ: float64 = mul(float64, PI, PI)          ; binary64
let F32_A: float32 = add(float32, 16777216.0f, 1.0f) ; binary32，结果仍为 16777216
let INF_OK: float32 = div(float32, ieee, 1.0f, 0.0f)   ; inf
let REM_OK: float64 = mod(float64, 5.5, 2.0)           ; 1.5
; let ERR: float64 = div(float64, 1.0, 0.0)            ; 常量除零
```

##### 4.3.4 示例

```text
let PI: float64 = 3.141592653589793
let MASK: uint32 = 0xFFFF_0000u
let DEBUG: bool = true

let PI_SQUARED: float64 = mul(float64, PI, PI)
let FLOAT_REM: float64 = mod(float64, 5.5, 2.0)    ; 1.5
let IS_POSITIVE: bool = gt(float64, PI, 0.0)       ; true
let DIFFERS: bool = xor(bool, IS_POSITIVE, false)  ; true

if IS_POSITIVE then                              ; 静态 true，仅保留真边
	writeln(bool, %t, true)
end

let FLAG_INT: int32 = cast(int32, DEBUG)      ; 1
let PI_INT: int32 = cast(int32, PI)           ; 3
let PI_U32: uint32 = cast(uint32, PI_INT)      ; 复合转换拆为两条 let
let PI_BITS: uint64 = bitcast(uint64, PI)

; let ERR1: int32 = add(int32, a, 10)        ; 错误：a 是 var 变量
; let ERR2: int32 = add(int32, mul(int32, 2, 3), 4) ; 错误：调用嵌套
; let ERR3: float64 = div(float64, 1.0, 0.0)  ; 错误：常量除零
; let ERR4: int32 = add(int64, 1, 2)          ; TC_ERR_TYPE_MISMATCH：RHS 结果为 int64
; let ERR5: float32 = 1.0                     ; TC_ERR_LITERAL_TYPE：无后缀浮点为 float64
```

块内 `let` 仍受 §11.1 的词法作用域约束。

#### 4.4 赋值语句

对已定义变量重新赋值时 **省略** `var`。右侧可为普通 `<rhs>` 或 `<funcall>`，结果类型须与变量已声明类型 **完全一致**。首次引入该名必须已通过 §4.2 的 `var … = …` 完成，不存在「无初始化器的声明 + 本赋值作为首次写入」写法。

```text
var c: int32 = add(int32, a, b)
c = mul(int32, a, b)        ; 合法（普通 RHS 赋值）
c = cast(int32, d)          ; 跨类型须先 cast

var f: float64 = 3.14
f = mul(float64, f, 2.0)    ; 合法
f = cast(float64, 42)       ; 合法（整数 → 浮点）

var flag: bool = false
flag = true                 ; 合法
flag = lt(float64, f, 10.0) ; 合法
flag = and(bool, flag, true) ; 合法

var count: int32 = 0
count = funcall(get_next)   ; 合法（funcall 赋值）
```

**约束**：
- 赋值左侧按当前值作用域解析：函数内普通查找失败但命中 §10.4.1 的顶层值作用域直接声明索引时报告 `TC_ERR_FUNCTION_SCOPE_ACCESS`；除此之外未解析到值绑定时报告 `TC_ERR_UNDEFINED_VARIABLE`；解析为 `let` 时报告 `TC_ERR_CONSTANT_ASSIGNMENT`；解析为函数参数时报告 `TC_ERR_PARAMETER_ASSIGNMENT`；只有解析为 `var` 才继续类型与确定初始化检查。全局函数名不属于值绑定，不能成为赋值目标。
- 赋值目标必须在当前 CFG 点确定初始化；赋值不能补救被控制流绕过的声明初始化（§11.2）。
- 赋值 RHS 为普通 `<rhs>` 或 `<funcall>`。`funcall` 只能直接出现在 `=` 右侧，不得嵌套在其他 RHS 内部。非 `void` `funcall` 的返回类型须与赋值目标声明类型严格相同；`void` `funcall` 不得用于赋值（应使用独立 `funcall(...)` 语句）。若 `funcall` 发生运行时错误，目标变量保留原值，随后程序终止（§13.3）。

#### 4.5 右值表达式（RHS）

| 产生式               | 结果类型           | 说明                            |
| -------------------- | ------------------ | ------------------------------- |
| `identifier`         | 标识符已声明类型   | 须已定义；受源序可见性约束      |
| `integer_literal`    | 由左侧变量类型决定 | 须满足字面量符号性及范围约束    |
| `float_literal`      | 由 `f`/`F` 后缀决定 | 无后缀为 `float64`，有后缀为 `float32`；须与上下文一致 |
| `float_special`      | 由左侧变量类型决定 | `inf`/`-inf`/`nan`              |
| `bool_literal`       | `bool`             | `true` 或 `false`               |
| `binary_arith_expr`  | 第一参数类型       | 五种双目算术运算（含浮点）      |
| `unary_arith_expr`   | 第一参数类型       | 两种单目算术运算（含浮点）      |
| `bitwise_expr`       | 第一参数类型       | 按位 `and`/`or`/`xor`（仅整数） |
| `unary_bitwise_expr` | 第一参数类型       | 按位 `not`（仅整数）            |
| `shift_expr`         | 第一参数类型       | `shl`/`shr` 移位运算（仅整数）  |
| `compare_expr`       | `bool`             | 六种比较运算（整数+浮点）       |
| `binary_logic_expr`  | `bool`             | `and`/`or`/`xor` 逻辑运算（布尔） |
| `unary_logic_expr`   | `bool`             | `not` 逻辑运算（布尔）          |
| `cast_expr`          | 第一参数类型       | 类型转换                        |
| `bitcast_expr`       | 第一参数类型       | 等宽位重解释                    |

`funcall` **不属于**普通 `rhs`。它只在 `var <名>: <类型> = funcall(...)`、`<identifier> = funcall(...)` 或独立 `funcall(...)` 三种专用语法位置出现；其合法位置由被调函数返回类型决定（§10.2.3）。

#### 4.6 操作数（Operand）

| 形式              | 约束                                                         |
| ----------------- | ------------------------------------------------------------ |
| *identifier*      | 先按词法作用域解析绑定并检查类型：解析为运行时 `var` 或参数时，必须在当前 CFG 点确定初始化（参数在函数入口已初始化，§11.2）；解析为 `let` 时，必须在使用点可见且已成功完成编译期求值，随后直接内联，不进入确定初始化集合 |
| *integer_literal* | 须满足字面量约束                                             |
| *float_literal*   | 须满足字面量约束                                             |
| *float_special*   | `inf`/`-inf`/`nan`，仅用于浮点类型上下文                     |
| *bool_literal*    | 仅用于 `bool` 类型上下文                                     |

因此，凡规范引用 `operand` 的位置——包括运算、转换、`funcall` 命名实参、`return` 和输出——均可使用符合本行规则的 `let` 标识符。只有运行时绑定读取才执行 `TC_ERR_UNINITIALIZED_VARIABLE` 检查；编译期 `let` 永不因不属于 `IN` 集合而触发该错误。

**不支持** 嵌套：操作数不可为算术表达式、`cast`、`bitcast` 或 `funcall` 调用。复合计算须拆分为多条语句。

### 5. 算术运算

#### 5.1 运算模式总览

0.0.33 先以附录 A EBNF 判定表达式形态是否合法；仅对 EBNF 已接受的表达式，再以“操作 × 类型 × 模式”矩阵判定静态语义是否合法：

| 运算 | 类型 | 合法模式 |
| ---- | ---- | -------- |
| `add`/`sub`/`mul`/`neg` | 有符号整数 | strict（无关键字）、`wrap` |
| `add`/`sub`/`mul`/`neg` | 无符号整数 | 固定模 `2^n`；不接受模式关键字 |
| `shl` | 全部整数 | strict（无关键字）、`wrap` |
| `div`/`mod`/`abs`/`shr` | 全部整数 | 无模式关键字 |
| `add`/`sub`/`mul`/`div`/`mod` | 浮点 | strict（无关键字）、`ieee` |
| `abs`/`neg` | 浮点 | 无模式关键字；纯符号位操作 |
| 比较、逻辑、位运算 | 对应合法类型 | 无模式关键字 |

本表是**语法通过后的静态语义矩阵**，不得用于放宽附录 A：

- EBNF 已接受某个操作、类型参数与模式位置，但组合不在上表时，才报告 `TC_ERR_TYPE_MISMATCH` 或 `TC_ERR_MODE_MISMATCH`。例如 `mod(bool, true, false)` 符合通用算术产生式，随后报类型错误；`add(int32, ieee, a, b)` 符合带模式算术产生式，随后报模式错误。
- EBNF 已通过专用产生式排除的形态统一在语法阶段报 `TC_ERR_SYNTAX`，不得为了产生类型或模式专用诊断而放宽语法。例如运行时浮点位运算类型参数、移位使用 `bool` 类型参数、`shr(T, wrap, ...)`、比较/逻辑/位运算携带模式参数，均不符合运行时 RHS 产生式。
- `let` 常量表达式使用独立的 `const_*` 产生式。其 `const_shift_expr` 语法允许候选 `mode`，因此 `let` 中 `shr(int32, wrap, ...)` 或 `shl(int32, ieee, ...)` 会进入静态语义并报告 `TC_ERR_MODE_MISMATCH`；相同形态用于普通 `var`/赋值 RHS 时因不符合 `shift_expr` 而报告 `TC_ERR_SYNTAX`。

0.0.33 不支持浮点 `wrap`，也不接受冗余的无符号 `wrap`；具体错误类别必须先按上述 EBNF 边界确定。

#### 5.2 严格模式（默认）

**整数严格模式**（参见 §5.4～§5.6）：
- 有符号 `add`/`sub`/`mul`/`neg` 结果超范围 → **整数溢出错误**
- 有符号 `abs(INT_MIN)` → **整数溢出错误**
- `shl` 结果超范围 → **整数溢出错误**
- `div` 除数为 0 → **除零错误**；`div(INT_MIN, -1)` → **整数溢出错误**

**浮点严格模式**（IEEE 754 异常检测）：
- 上溢 → **浮点溢出错误**
- 下溢 → **浮点下溢错误**
- 除零 → **除零错误**
- 无效操作（0/0、∞−∞、0×∞） → **无效操作错误**
- `nan` 参与 `add`/`sub`/`mul`/`div`/`mod` → **无效操作错误**
- 浮点 `mod` 的被除数为无穷，或被除数和除数同时为零 → **无效操作错误**；有限非零数对零取模 → **除零错误**

浮点执行环境固定如下：

- `float32` 每条指令按 IEEE 754 binary32 执行并立即舍入；`float64` 按 binary64 执行并立即舍入。
- 固定舍入模式为 roundTiesToEven；不提供运行时舍入模式切换。
- 禁止保留超出目标类型的中间精度，禁止将独立 `mul`/`add` 融合为 FMA。
- 必须保留非规格化数；禁止 FTZ（flush-to-zero）与 DAZ（denormals-are-zero）。
- 下溢采用 **tininess-after-rounding**：结果舍入到目标类型后为微小结果且本次舍入不精确时才触发；精确的非规格化结果不触发下溢。有限结果舍入为无穷时定义为上溢。
- 同一指令同时满足多个异常条件时，只报告最高优先级：`FloatInvalidOperation` → `DivisionByZero` → `FloatOverflow` → `FloatUnderflow`。

为避免依赖宿主浮点异常标志，`add`/`sub`/`mul`/`div` 的特殊值分类必须按下表判定。表中“NaN”包含 quiet NaN 和由 `bitcast` 构造的 signaling-NaN 位模式；TC 不向程序暴露 signaling 状态。

| 运算 | 无效操作（最高优先级） | 除零 | 其他结果 |
| ---- | ---------------------- | ---- | -------- |
| `add` | 任一输入为 NaN；符号相反的两个无穷相加 | — | 遵循 IEEE 754 加法 |
| `sub` | 任一输入为 NaN；同号的两个无穷相减 | — | 遵循 IEEE 754 减法 |
| `mul` | 任一输入为 NaN；零与无穷相乘 | — | 遵循 IEEE 754 乘法 |
| `div` | 任一输入为 NaN；零除以零；无穷除以无穷 | 有限非零值除以正零或负零 | 遵循 IEEE 754 除法 |
| `mod` | 按 §5.7 的完整分类 | 按 §5.7 的完整分类 | 按 §5.7 的精确余数语义 |

strict 指令必须先完成上述分类，再以无限精度数学结果和目标格式正确舍入判定上溢/下溢；不得直接依赖 C99 表达式是否设置宿主 `fenv` 标志。发生运行时错误时，该指令没有结果提交，规则见 §13.3。

#### 5.3 IEEE 754 标准模式（`ieee`）

**仅用于浮点 `add`/`sub`/`mul`/`div`/`mod`**。执行精度、舍入方式、非规格化数与禁止 FMA 的规则同 §5.2，但异常不终止程序。

对浮点 `mod` 而言，`ieee` 只表示沿用本节的非终止异常处理与 canonical quiet NaN 结果；取模核心仍是 §5.7 定义的“商向零截断”语义，不采用将商舍入到最近整数（中点取偶数）的余数语义。

| 场景       | IEEE 754 行为                   | 返回值           |
| ---------- | ------------------------------- | ---------------- |
| 上溢       | 舍入到 ±∞                       | ±`inf`           |
| 下溢       | 返回 0 或非规格化数             | `0` 或非规格化值 |
| 除零       | 返回 ±∞                         | ±`inf`           |
| 无效操作   | 返回 canonical quiet NaN         | `nan`            |
| `nan` 传播 | 算术输入含 NaN 时返回 canonical quiet NaN | `nan`      |

上表的“除零返回 ±inf”仅适用于浮点 `div`。浮点 `mod` 的除数为零时没有可表示的余数：`ieee` 模式返回 canonical quiet NaN；strict 模式下，`0 mod 0` 按无效操作处理，有限非零数对零取模按除零处理。浮点 `mod` 的其余特殊值规则见 §5.7。

`ieee` 模式下，零、有限值和无穷结果的符号按 IEEE 754-2019 对相应运算的规则确定；特别地，除法无穷结果的符号为两操作数符号位的异或。无效操作和任何 NaN 输入统一返回本节规定的**正号** canonical quiet NaN，不传播输入的符号、payload 或 signaling 状态。

```text
var big: float32 = 1.0e30f
var result: float32 = mul(float32, ieee, big, big)  ; inf
var zero: float32 = 0.0f
var nan_result: float32 = div(float32, ieee, zero, zero)  ; nan
```

`nan` 字面量与 `ieee` 算术产生的 NaN 使用固定 canonical quiet NaN：binary32 为 `0x7FC00000`，binary64 为 `0x7FF8000000000000`。通过 `bitcast` 构造的其他 NaN 位模式可保留其 payload；其参与 `ieee` 算术后结果仍规范化为 canonical quiet NaN。

#### 5.4 整数回绕模式（`wrap`）

**整数 `wrap`**：
- 按模 `2^n` 回绕，不报错
- 仅用于有符号 `add`/`sub`/`mul`/`neg`，以及有符号或无符号 `shl`
- 无符号 `add`/`sub`/`mul`/`neg` 已固定采用模 `2^n` 语义，不接受冗余 `wrap`
- `div`/`mod`/`abs`/`shr` 不接受 `wrap`
- 浮点类型不接受 `wrap`；位模式混合须先 `bitcast` 为等宽整数

#### 5.5 整数有符号运算（`int8`～`int64`）

| 指令                  | 语义                                                         |
| --------------------- | ------------------------------------------------------------ |
| `add` / `sub` / `mul` | 和 / 差 / 积；严格模式超范围报错，wrap 回绕                  |
| `div`                 | 商，**向零截断**（同 C 有符号 `/`）；除数为 0 → **除零错误**；商不可表示 → **整数溢出错误** |
| `mod`                 | 余数符号与 **被除数** 相同；除数为 0 → **除零错误**；**注**：`mod` 本身不会因值不可表示而报错，因为余数绝对值小于除数，必在类型范围内（除数为 0 已单独处理）。 |
| `abs`                 | 返回绝对值；`INT_MIN` 时严格模式报错                         |
| `neg`                 | 返回相反数；`INT_MIN` 时严格模式报错，wrap 回绕              |

**严格模式溢出检测**（`div`，有符号类型）：

1. 将操作数按 `<T>` 解码为 int64 有符号值
2. 除数为 0 → **除零错误**
3. 计算向零截断商 \(q\)；若 \(q\) 不在 `<T>` 可表示范围内 → **整数溢出错误**

**特殊情形**（\(b \neq 0\)）：

| 表达式                   | 结果 | 说明                                                        |
| ------------------------ | ---- | ----------------------------------------------------------- |
| `div(T, INT_MIN(T), −1)` | —    | **整数溢出错误**（数学商 \(+2^{n-1}\) 不可在 `<T>` 中表示） |
| `mod(T, INT_MIN(T), −1)` | `0`  | 余数为 0，**不报错**                                        |
| `abs(T, INT_MIN(T))`     | —    | **整数溢出错误**                                            |
| `neg(T, INT_MIN(T))`     | —    | 严格模式时 **整数溢出错误**                                 |

```text
var g: int32 = 7
var h: int32 = -3
var i: int32 = div(int32, g, h)    ; i = -2

var j: int32 = -7
var k: int32 = 3
var m: int32 = mod(int32, j, k)    ; m = -1

var n: int32 = -42
var o: int32 = abs(int32, n)       ; o = 42
```

#### 5.6 整数无符号运算（`uint8`～`uint64`）

| 指令                  | 语义                                                |
| --------------------- | --------------------------------------------------- |
| `add` / `sub` / `mul` | 和 / 差 / 积；超范围 → 按模 2^n 回绕                |
| `div`                 | 数学整数商；除数为 0 → **除零错误**                 |
| `mod`                 | 余数满足 `0 ≤ 余数 < 除数`；除数为 0 → **除零错误** |
| `abs`                 | 恒等返回                                            |
| `neg`                 | 返回 `0 - 操作数`，按模 2^n 回绕                    |

无符号算术天然采用模 2^n 回绕，其位级结果与有符号 `wrap` 模式下的同宽算术一致。

```text
var a: uint8 = 200
var b: uint8 = 100
var c: uint8 = add(uint8, a, b)    ; c = 44
```

#### 5.7 浮点运算（`float32`、`float64`）

| 指令                  | 语义                                                         |
| --------------------- | ------------------------------------------------------------ |
| `add` / `sub` / `mul` | 和 / 差 / 积；strict 检测异常，`ieee` 返回 inf/nan           |
| `div`                 | 商；strict 检测除零/无效操作，`ieee` 返回 ±inf/nan           |
| `mod`                 | 商向零截断的余数；strict 检测除零/无效操作，`ieee` 对异常返回 nan |
| `abs`                 | 清除符号位；包括 NaN、无穷和零在内均不报错，不接受模式关键字 |
| `neg`                 | 翻转符号位；包括 NaN、无穷和零在内均不报错，不接受模式关键字 |

`abs`/`neg` 是纯位操作：仅修改符号位并保留其余位，包括通过 `bitcast` 构造的 NaN payload。它们不属于可能触发浮点异常的算术指令。

**浮点 `mod` 的精确语义**：

设操作数为同一浮点类型 `T` 的 `a` 与 `b`。当二者均为有限值且 `b != ±0` 时，先在数学实数域定义

```text
q = trunc(a / b)        ; 向零截断为数学整数
r = a - q * b
```

结果为 `r` 在 `T` 中的精确表示。实现不得先以 `T` 执行 `a / b` 再相乘相减，因为中间商可能溢出或舍入，从而改变余数。对于同一 binary32/binary64 类型的两个有限输入，上述余数可由该类型精确表示，因此浮点 `mod` 本身不产生上溢或下溢。

- 非零结果满足 `abs(r) < abs(b)`，且符号与 `a` 相同；`b` 的符号不影响结果符号。
- 结果为零时保留 `a` 的符号：`mod(T, -0.0, b)` 与负数恰好整除均返回 `-0.0`。
- `a` 有限且 `b` 为正或负无穷时，结果按位等于 `a`。
- 任一输入为 NaN，或 `a` 为正/负无穷时：strict 报 `TC_ERR_FLOAT_INVALID`；`ieee` 返回 canonical quiet NaN。
- `a` 与 `b` 同时为零时：strict 报 `TC_ERR_FLOAT_INVALID`；`ieee` 返回 canonical quiet NaN。
- `a` 为有限非零值且 `b` 为正或负零时：strict 报 `TC_ERR_DIVISION_BY_ZERO`；`ieee` 返回 canonical quiet NaN。
- 异常优先级继续遵循 §5.2：NaN 或无穷被除数导致的无效操作优先于零除数诊断。

```text
var a: float64 = 3.5
var b: float64 = 2.0

var sum: float64 = add(float64, a, b)      ; 5.5（严格模式）
var prod: float64 = mul(float64, a, b)     ; 7.0
var quot: float64 = div(float64, a, b)     ; 1.75
var rem: float64 = mod(float64, 5.5, 2.0)  ; 1.5
var neg_rem: float64 = mod(float64, -5.5, 2.0) ; -1.5

; abs/neg 无模式且永远安全
var neg_val: float64 = -3.14
var pos_val: float64 = abs(float64, neg_val)   ; 3.14（无异常）

; IEEE 模式
var big: float32 = 1.0e30f
var inf_res: float32 = mul(float32, ieee, big, big)  ; inf
var mod_nan: float64 = mod(float64, ieee, 1.0, 0.0)  ; nan
```

### 6. 位运算

本章定义整数位级操作，包括按位逻辑运算与移位运算。`and`、`or`、`xor`、`not` 均由**类型参数**重载：类型参数为整数时执行本章的按位运算，类型参数为 `bool` 时执行第 7 章的布尔逻辑运算。浮点类型不参与这组重载。

> **重要约束**：
> - 移位运算（`shl`/`shr`）中，**被移位数与移位计数必须为相同类型 `T`**。若需要不同位宽，必须先用 `cast` 统一类型。
> - 浮点类型 **不支持** 任何位运算，包括 `and`/`or`/`xor`/`not`/`shl`/`shr`。附录 A 的位运算与移位产生式仅接受 `int_type`，因此以浮点类型作为这些指令的类型参数 → **语法错误 `TC_ERR_SYNTAX`**；类型参数合法但操作数类型不匹配时，才进入静态语义并报告类型错误。

**设计说明：移位计数不掩码**

TC 对移位计数 `k` 的处理方式与主流语言不同，**不进行掩码**，直接取 `k` 的数学值。选择此语义主要基于以下原因：

- **教学清晰**：避免"计数被截断"这一隐含、非直观的行为
- **负数拒绝**：若 `T` 为有符号整数且 `k < 0`，立即触发 **负移位计数错误 `TC_ERR_NEGATIVE_SHIFT_COUNT`**；不将负数按无符号位模式重解释
- **确定性**：`k >= n` 时行为明确定义（`shl` 严格模式报溢出，`shr` 得 `0`）
- **可验证性**：便于形式化证明和静态分析
- **显式编程**：若需要取模移位，程序员可显式使用 `mod` 运算

#### 6.1 按位逻辑运算（`and`、`or`、`xor`、`not`）

##### 6.1.1 总览

| 运算  | 名称     | 操作数数量 | 适用类型                     | 语义                             |
| ----- | -------- | ---------- | ---------------------------- | -------------------------------- |
| `and` | 按位与   | 2          | 整数类型（`int8`～`uint64`） | 每位：两操作数均为 1 → 1，否则 0 |
| `or`  | 按位或   | 2          | 整数类型                     | 每位：任一操作数为 1 → 1，否则 0 |
| `xor` | 按位异或 | 2          | 整数类型                     | 每位：两操作数不同 → 1，相同 → 0 |
| `not` | 按位非   | 1          | 整数类型                     | 每位取反                         |

> **重载规则**：`and`/`or`/`xor`/`not` 均由类型参数 `T` 重载——`T` 为整数时执行本章的按位运算，`T` 为 `bool` 时执行第 7 章的逻辑运算。两类重载的操作数数量保持一致：`and`/`or`/`xor` 为双目，`not` 为单目。

##### 6.1.2 语法形式

```text
var a: int8 = -84              ; 二进制补码位模式为 0b1010_1100
var b: int8 = -16              ; 二进制补码位模式为 0b1111_0000

var and_res: int8 = and(int8, a, b)   ; 0b1010_0000 -> -96
var or_res:  int8 = or(int8, a, b)    ; 0b1111_1100 -> -4
var xor_res: int8 = xor(int8, a, b)   ; 0b0101_1100 -> 92
var not_res: int8 = not(int8, a)      ; 0b0101_0011 -> 83
```

##### 6.1.3 语义规则

1. 将操作数视为 **无符号位模式**（有符号数按二进制补码解释）。
2. 对每一位执行对应的逻辑操作。
3. 结果按目标类型 `T` 解释（有符号按补码回译，无符号直接取值）。

**溢出**：按位运算结果天然限制在 `T` 的位宽内，**不会溢出**，因此**不支持** `wrap` 或 `truncate` 模式。附录 A 未为运行时或常量按位运算提供模式参数位置，写入这些关键字不符合 EBNF，报告 `TC_ERR_SYNTAX`。

**操作数约束**：
- 两操作数必须与类型参数 `T` 一致（整数类型）。
- 若类型参数为 `bool`，则 `and`/`or`/`xor`/`not` 由逻辑运算产生式解析（参见第 7 章）。
- 若类型参数为浮点类型，按位与移位产生式均不接受该形态，触发 **`TC_ERR_SYNTAX`**。
- 当类型参数已经是 EBNF 要求的整数类型，但标识符或字面量操作数与该类型不一致时，才触发对应的类型或字面量错误。

#### 6.2 移位运算（`shl`、`shr`）

移位运算仅适用于整数类型。**被移位数与移位计数必须为相同类型 `T`**。移位计数按 `T` 的数值语义解码并直接取其数学值 `k`：有符号 `T` 按二进制补码解码，无符号 `T` 按非负整数解码。TC 不对 `k` 掩码，也不把负数按无符号位模式重解释。

`shl` 与 `shr` 共享以下前置检查：

1. 若 `k < 0`，立即触发 **`TC_ERR_NEGATIVE_SHIFT_COUNT`**；
2. 仅当 `k >= 0` 时，才继续判定 `k >= n`、严格溢出或回绕结果。

因此负移位计数错误的优先级高于 `shl` 的整数溢出检查，且不受 strict / `wrap` 模式影响。无符号移位计数在类型上恒为非负，不会触发本错误。

`k >= n` 是 TC 已定义的语言分支，不得先执行宿主 C99 的移位再修正结果：strict `shl` 报整数溢出，`wrap shl` 与 `shr` 返回 `0`。这一规则刻意不采用宿主硬件的计数掩码，也不采用 C99 的未定义行为。

##### 6.2.1 左移（`shl`）

- **适用类型**：整数类型（`int8`～`uint64`）。
- **调用形式**：
  - 严格模式（默认）：`shl(<T>, 被移位数, 移位计数)`
  - 回绕模式：`shl(<T>, wrap, 被移位数, 移位计数)`
- **语义**：
  - 按 §6.2 的共享规则取移位计数的数学值 `k`；`k < 0` 时触发 **`TC_ERR_NEGATIVE_SHIFT_COUNT`**。
  - 若 `k >= n`（`n` 为 `T` 的位宽）：
    - 严格模式：视为 **整数溢出错误**。
    - 回绕模式：所有位被移出，结果为 `0`。
  - **严格模式**（`k < n`）：
    - 计算数学结果：`result_math = 被移位数 * 2^k`
    - 若 `result_math` 超出 `T` 的可表示范围 → **整数溢出错误**。
    - 否则存储结果。
  - **回绕模式**（`k < n`）：
    - 取 `(被移位数 * 2^k)` 的低 `n` 位位模式，按 `T` 解释。**不报错**。

```text
var x: int8 = 0b0111_1111   ; 127
var r1: int8 = shl(int8, x, 2)        ; 127*4=508 -> 溢出错误
var r2: int8 = shl(int8, wrap, x, 2)  ; 508 mod 256 = 0b1111_1100 -> -4

var y: uint8 = 0b1111_1111u
var r3: uint8 = shl(uint8, wrap, y, 4)  ; 255*16 mod 256 = 0b1111_0000 -> 240u
var r4: uint8 = shl(uint8, wrap, y, 8)  ; k=8 >=8 -> 0

var negative_count: int8 = -1
var bad: int8 = shl(int8, x, negative_count) ; TC_ERR_NEGATIVE_SHIFT_COUNT
```

##### 6.2.2 右移（`shr`）

- **适用类型**：整数类型。
- **调用形式**：`shr(<T>, 被移位数, 移位计数)` —— **无模式关键字**（永不溢出）。
- **语义**：
  - 按 §6.2 的共享规则取移位计数的数学值 `k`；`k < 0` 时触发 **`TC_ERR_NEGATIVE_SHIFT_COUNT`**。
  - 若 `k >= n`，结果为 `0`。
  - **有符号类型**（`int*`）：执行 **算术右移**——高位补符号位。
  - **无符号类型**（`uint*`）：执行 **逻辑右移**——高位补 `0`。

当 `0 ≤ k < n` 时，右移还可等价地形式化为：无符号值取 `floor(x / 2^k)`；有符号非负值同样取 `floor(x / 2^k)`；有符号负值取 `floor(x / 2^k)`（向负无穷方向取整）。当 `k >= n` 时统一返回 `0` 是优先级更高的 TC 特例，因此不延续负数算术右移的符号填充结果。

```text
var neg: int8 = -128          ; 二进制补码位模式为 0b1000_0000
var r5: int8 = shr(int8, neg, 1)   ; -64 (算术右移)
var r6: int8 = shr(int8, neg, 8)   ; k=8 >=8 -> 0
var bad_count: int8 = -1
var r7: int8 = shr(int8, neg, bad_count) ; TC_ERR_NEGATIVE_SHIFT_COUNT
```

#### 6.3 位运算与常量表达式

`let` 常量表达式允许使用全部合法位运算。`shl` 可使用 strict 或 `wrap`；strict 溢出映射为常量溢出错误，`wrap` 与运行时一样保留低位。常量求值期间若移位计数的数学值为负，在编译期报 **`TC_ERR_CONSTANT_EXPRESSION`**；不延迟到运行时，也不映射为常量溢出。其余规则与 §4.3、§6.1、§6.2 完全一致。

### 7. 比较运算与逻辑运算

#### 7.1 比较运算

##### 7.1.1 比较运算总览

所有比较运算统一支持整数和浮点类型。显式类型参数 `T` 同时是两个操作数各自的期望类型：

- 接受 **两个类型均严格等于 `T` 的操作数**（整数或浮点）；“两个操作数彼此同类型”但二者都不等于 `T` 仍然非法
- 返回 `bool` 类型值
- **整数比较**不涉及 `wrap` / `truncate` 模式关键字
- **浮点比较**使用 IEEE 754 普通比较谓词（NaN 为 unordered），不使用 `totalOrder`；仅接受无模式形式。
- **不产生溢出**（比较本身无算术溢出风险）

附录 A 的 `compare_expr` 仅接受整数或浮点类型参数，且没有模式参数位置。因此 `eq(bool, ...)` 或 `eq(float64, ieee, ...)` 等形态在语法阶段报告 `TC_ERR_SYNTAX`。产生式已接受后，任一**标识符操作数**的声明类型不等于 `T`，统一报告 `TC_ERR_COMPARISON_TYPE_MISMATCH`，定位到源位置最早的不匹配操作数；即使两个操作数彼此具有相同的另一类型，也使用该错误码。字面量与 `T` 的类别、后缀或范围不兼容时，仍优先使用 `TC_ERR_LITERAL_TYPE` / `TC_ERR_LITERAL_OUT_OF_RANGE`。比较操作数类型错误不再与通用 `TC_ERR_TYPE_MISMATCH` 重叠。

| 运算 | 名称     | 语义     |
| ---- | -------- | -------- |
| `eq` | 等于     | `a == b` |
| `ne` | 不等于   | `a != b` |
| `lt` | 小于     | `a < b`  |
| `le` | 小于等于 | `a <= b` |
| `gt` | 大于     | `a > b`  |
| `ge` | 大于等于 | `a >= b` |

##### 7.1.2 语法形式

```text
; 整数比较
var eq_result: bool = eq(int32, a, b)   ; false
var lt_result: bool = lt(int32, a, b)   ; true

; 浮点比较
var f_gt: bool = gt(float64, 3.14, 2.71)  ; true
; 注意：不支持 gt(float64, ieee, 3.14, 2.71) 形式

; nan 比较（IEEE 754）
var nan_val: float64 = nan
var eq_nan: bool = eq(float64, nan_val, nan_val)  ; false
var ne_nan: bool = ne(float64, nan_val, nan_val)  ; true
```

##### 7.1.3 语义规则

**整数比较**：
- 有符号类型按二进制补码解释后的数学值比较
- 无符号类型按非负整数值比较
- 混合符号性比较须先 `cast` 统一类型

**浮点比较**：
- `eq(+0.0, -0.0)` 为 `true`，`ne(+0.0, -0.0)` 为 `false`
- `nan` 与任何值（包括自身）执行 `eq`/`lt`/`le`/`gt`/`ge` 均返回 `false`，执行 `ne` 返回 `true`
- 上一规则同样适用于由 `bitcast` 构造的任意 NaN 位模式；比较不触发 strict 运行时错误，也不修改操作数位模式
- 本组指令不区分 NaN payload，也不提供总序；若需比较位模式，先 `bitcast` 为等宽整数

由上述规则，检测 NaN 的惯用写法是 `ne(float64, x, x)`；`eq(float64, x, nan)` 始终为 `false`，不能用于检测。

#### 7.2 逻辑运算

##### 7.2.1 逻辑运算总览

所有逻辑运算：
- 接受 **`bool` 类型操作数**
- 返回 `bool` 类型值
- **不涉及** `wrap` / `truncate` 模式
- **不产生溢出**

附录 A 的逻辑产生式要求显式类型参数为 `bool`，且没有模式参数位置。不能由整数按位运算产生式或布尔逻辑产生式匹配的形态，以及逻辑调用中额外写入模式关键字的形态，均在语法阶段报告 `TC_ERR_SYNTAX`。产生式已接受后，操作数不是 `bool` 才报告类型或字面量错误。

| 运算  | 名称   | 操作数数量 | 语义                                            |
| ----- | ------ | ---------- | ----------------------------------------------- |
| `and` | 逻辑与 | 2          | 两操作数均为 `true` 时返回 `true`，否则 `false` |
| `or`  | 逻辑或 | 2          | 任一操作数为 `true` 时返回 `true`，否则 `false` |
| `xor` | 逻辑异或 | 2        | 两操作数不同时返回 `true`，相同时返回 `false`   |
| `not` | 逻辑非 | 1          | 操作数为 `true` 时返回 `false`，否则 `true`     |

##### 7.2.2 短路求值

**`and` 短路规则**：
- 左操作数为 `false` 时，**不计算** 右操作数，直接返回 `false`
- 左操作数为 `true` 时，计算右操作数并返回其值

**`or` 短路规则**：
- 左操作数为 `true` 时，**不计算** 右操作数，直接返回 `true`
- 左操作数为 `false` 时，计算右操作数并返回其值

**`xor` 求值规则**：
- `xor` **不短路**，始终先读取左操作数，再读取右操作数，然后判断二者是否不同。
- 确定初始化分析必须记录两个操作数的读取；即使左操作数是字面量或已求值的 `let bool`，也不得裁剪右操作数读取边。

确定初始化分析必须为短路求值建立操作数级的可达边。当左操作数是布尔字面量，或是在当前词法作用域可见、定义语句位于使用点之前且已求值的 `let bool` 时，使用其编译期值删除不可能的右操作数读取边：`false and RHS` 与 `true or RHS` 均不记录 RHS 的变量读取。左操作数为 `var` 时不做值推测，保守认为右操作数可达。

该裁剪只影响 CFG/DFA 的确定初始化读边，不跳过前序静态阶段。被短路排除的 RHS 不触发 `TC_ERR_UNINITIALIZED_VARIABLE`，但仍必须通过词法、语法、名称、类型、操作数数量与模式检查；前向或不可见 `let` 仍按名称解析规则报 `TC_ERR_UNDEFINED_VARIABLE`。

```text
func check_short_circuit() void then
	let FALSE: bool = false
	let TRUE: bool = true
	goto use
	var pending: bool = true
	label use:
	var a: bool = and(bool, FALSE, pending) ; 合法：pending 的读取边被裁剪
	var b: bool = or(bool, TRUE, pending)   ; 合法：pending 的读取边被裁剪

	var runtime_false: bool = false
	var c: bool = and(bool, runtime_false, pending)
	; 上一行仍报 TC_ERR_UNINITIALIZED_VARIABLE：var 的值不参与静态推测

	var d: bool = and(bool, FALSE, missing)
	; 上一行仍报 TC_ERR_UNDEFINED_VARIABLE：名称检查不被短路绕过
	return
end
```

### 8. 类型转换

#### 8.1 三种转换形式

| 形式 | 语义 | 类型约束 |
| ---- | ---- | -------- |
| `cast(T, operand)` | 数值转换 | 整数、浮点、`bool`；按本章做范围检查与舍入 |
| `cast(T, truncate, operand)` | 保留低位的整数缩窄 | 仅整数→更窄整数 |
| `bitcast(T, operand)` | 位模式不变的等宽重解释 | 等宽整数/浮点；`bool` 不参与 |

三种形式互不替代：数值 `cast` 不静默丢弃整数高位；`truncate` 不接受浮点；`bitcast` 不做数值转换。

##### 8.1.1 字面量操作数的源类型

标识符操作数的源类型是其声明类型。字面量作为转换操作数时按下列规则唯一确定源类型：

| 上下文 | 字面量 | 源类型规则 |
| ------ | ------ | ---------- |
| `cast` | 无后缀整数 | `int64`；数值必须先在 `int64` 范围内 |
| `cast` | `u`/`U` 整数 | `uint64` |
| `cast` | 浮点 | `f`/`F` 后缀为 `float32`，无后缀为 `float64`；`inf`/`-inf`/`nan` 默认为 `float64` |
| `cast` | 布尔 | `bool` |
| `bitcast` | 整数 | 源位宽取目标位宽，后缀决定有/无符号；字面量必须能由该同宽整数类型表示 |
| `bitcast` | 普通浮点 | `f`/`F` 后缀为 `float32`，无后缀为 `float64` |
| `bitcast` | `inf`/`-inf`/`nan` | 目标为 32 位时源为 `float32`，目标为 64 位时源为 `float64` |

因此 `cast(float32, 1.0)` 是从 `float64` 到 `float32` 的数值转换，而 `bitcast(float32, 0x40490FDBu)` 将后者按同宽 `uint32` 字面量解释。`bitcast(float32, 1.0)` 因源为 `float64` 而报 `TC_ERR_BITCAST_WIDTH`；需写成 `1.0f`。`bitcast` 仍不接受布尔字面量。非 `let` 语句中的严格 `cast` 即使操作数是字面量，也按运行时指令处理转换溢出；`let` 中的同一情形映射为 `TC_ERR_CONSTANT_CAST_OVERFLOW`。

#### 8.2 整数严格转换规则（strict）

严格整数转换统一依据数学值判定，与源/目标位宽关系无关：

1. 将源位模式按源类型解释为数学整数 `v`。
2. 若 `min(T) ≤ v ≤ max(T)`，结果为目标类型中表示同一数学值的位模式。
3. 否则报 `TC_ERR_CAST_OVERFLOW`。

因此无符号缩窄同样检查范围；例如已有 `var wide: uint16 = 256u` 时，`cast(uint8, wide)` 必须报错。需要显式保留低位时使用 §8.3 的 `truncate`。

#### 8.3 整数截断转换规则（`truncate`）

设源、目标位宽分别为 `n`、`m`：

- 源与目标必须均为整数类型，且必须满足 `m < n`。
- 将源视为 `n` 位位模式 `bits`，结果位模式为 `bits mod 2^m`，再按目标整数类型解释。
- 不执行范围检查，不报溢出。
- `m >= n` 时为静态错误 `TC_ERR_MODE_MISMATCH`；加宽应使用严格 `cast`，等宽位重解释应使用 `bitcast`。

```text
var big: int32 = 1000
var trunc: int8 = cast(int8, truncate, big) ; 低 8 位 0xE8 → -24
```

#### 8.4 浮点转换规则

| 转换方向              | 规则                                                         |
| --------------------- | ------------------------------------------------------------ |
| 整数 → 浮点           | 按 roundTiesToEven 转为目标浮点；允许精度舍入；有限整数若转换为无穷 → `TC_ERR_CAST_OVERFLOW` |
| 浮点 → 整数           | 向零舍入；结果超出目标整数范围，或源为 `nan`/`inf` → `TC_ERR_CAST_OVERFLOW` |
| `float64` → `float32` | 按 roundTiesToEven 舍入；有限源值若转换为无穷 → `TC_ERR_CAST_OVERFLOW`；舍入为非规格化数或零则合法 |
| `float32` → `float64` | 有限值无损精度提升（总是合法）                               |

浮点数值转换还须遵守：正负零保留符号，正负无穷保留符号；源为 NaN 且目标仍为浮点时，结果为目标类型的 canonical quiet NaN。同类型 `cast` 为恒等操作并保留完整位模式；若需在等宽不同类型间保留 NaN payload，必须使用 `bitcast`。

所有范围检查均在提交目标值之前、基于源值的精确数学值完成。尤其是浮点转整数时，必须先判定 NaN/无穷和截断后数学整数的范围，再执行后端转换；AOT 不得先执行可能在 C99 中产生未定义行为的越界浮点转整数强制转换。整数转浮点和浮点窄化必须直接正确舍入到目标格式，不得通过额外中间类型造成二次舍入。

```text
var i: int32 = 42
var f: float64 = cast(float64, i)        ; 42.0
var pi_f: float64 = 3.14159
var pi_int: int32 = cast(int32, pi_f)    ; 3（向零截断）
var huge: float64 = 1.0e100
; var err: int32 = cast(int32, huge)    ; 转换溢出错误
```

#### 8.5 `bool` ↔ 整数/浮点转换

| 方向               | 规则                                           |
| ------------------ | ---------------------------------------------- |
| `bool` → 整数/浮点 | `true` → `1`/`1.0`，`false` → `0`/`0.0`        |
| 整数/浮点 → `bool` | `0`/`0.0` → `false`，非零 → `true`（含 `nan`） |

```text
var flag: bool = true
var as_int: int32 = cast(int32, flag)      ; 1
var as_float: float64 = cast(float64, flag) ; 1.0
var back: bool = cast(bool, 3.14)          ; true
```

#### 8.6 等宽位重解释（`bitcast`）与速查

`bitcast(TargetType, operand)` 保持源位模式的全部位不变，仅改用目标类型解释：

- 源与目标必须为整数或浮点类型，且位宽完全相同。
- `bool` 不允许参与，否则报 `TC_ERR_TYPE_MISMATCH`。
- 源、目标类型相同时是保持位模式不变的合法恒等操作。
- 位宽不一致报 `TC_ERR_BITCAST_WIDTH`。
- `bitcast` 不触发数值溢出，也不规范化 NaN payload。
- 位模式按 §3.5 的抽象位串定义；源、目标的宿主对象地址、对齐和内存字节序不参与语义。C99 AOT 应使用无别名未定义行为的复制或整数位运算策略实现。

```text
var f: float32 = -1.0f
var bits: uint32 = bitcast(uint32, f)       ; 0xBF800000u
var f2: float32 = bitcast(float32, bits)    ; -1.0f
; var bad: float64 = bitcast(float64, bits) ; TC_ERR_BITCAST_WIDTH
```

| 源 ↓ / 目标 → | 整数 | 浮点 | `bool` |
| ------------- | ---- | ---- | ------ |
| **整数** | strict `cast` 检查数学范围；更窄目标可显式 `truncate` | strict `cast` 做数值转换；等宽 `bitcast` 做位重解释 | 零为 `false`，非零为 `true` |
| **浮点** | strict `cast` 向零舍入并检查；等宽 `bitcast` 做位重解释 | strict `cast` 做精度转换；不同位宽禁止 `bitcast` | `±0.0` 为 `false`，其他值（含 NaN）为 `true` |
| **`bool`** | `false`→0，`true`→1 | `false`→0.0，`true`→1.0 | 恒等 |

## 第三部分：控制流与执行模型

### 9. 控制流

**代码块与 CFG 基本块**

TC 将源语言的**代码块**与控制流图中的 **CFG 基本块**严格区分：

- **代码块**是由 `then` / `else` / `end` 词法结构界定的直接语句序列，用于名称作用域、局部变量生命周期、标签可见性、`goto` 的块关系和缩进检查。函数的 `then … end` 构成函数体代码块；`if` 的 `then` 分支和 `else` 分支分别构成两个互不包含、不可比的兄弟代码块，无 `else` 时只有 `then` 代码块；`while` 的 `then … end` 构成循环体代码块。嵌套 `if` / `while` 开启新的代码块。
- **CFG 基本块**是没有内部控制流分叉的最大连续 CFG 节点序列。函数入口、条件分支目标、循环入口/退出点与 `label` 均形成 CFG 基本块入口；`return`、`goto`、`break`、`continue` 及条件分支节点终结当前 CFG 基本块。
- `label` **不开启代码块**、不创建作用域、不改变缩进层级；但由于它是跳转目标，必须形成新的 CFG 基本块入口。

#### 9.1 条件分支语句（`if`）

TC 提供 **Pascal 风格** 的 `if-then-else` 条件分支语句，采用 **缩进敏感** 的块结构，并以 **`end`** 关键字作为块的强制结束标志。

##### 9.1.1 `if` 语句语法

**强制语法形式**（行结构敏感）：

```text
if <bool_rhs> then
	语句序列
[else
	语句序列]
end
```

- `<bool_rhs>` 必须产生 `bool`（§4.5）。`then` 位于 `if` 行末，之后只能有行末注释和换行。
- `else` 与 `end` 各自单独成行并与对应 `if` 对齐；`end` 不得省略。不支持单行 `else if`，多分支使用 §9.1.3 的嵌套形式。
- 语句序列可以为空；非空时按 §9.1.2 缩进。块内语句范围由附录 A 决定，不能嵌套 `func`；`goto`/`label` 还受 §9.3 的上下文限制。
- 缺少 `end` 或违反缩进规则均为静态错误。

##### 9.1.2 强制性缩进规则

| 规则编号 | 规则说明                                                     |
| -------- | ------------------------------------------------------------ |
| R1       | 非空、非纯注释逻辑行的行首缩进**只能使用 ASCII 空格 U+0020**。行首缩进中出现水平制表符 U+0009（Tab），无论是单独使用还是与空格混用，均为缩进错误。Token 之间的制表符不属于行首缩进，仍然合法。 |
| R2       | **每连续 4 个 ASCII 空格恰好表示 1 个缩进级别**。层级由行首连续空格的数量除以 4 决定。行首空格总数必须能被 4 整除，余数不为 0 时报缩进错误。 |
| R3       | `func`/`if`/`while`、`else` 和对应 `end` 行的缩进级别必须**完全一致**，称为**当前块级缩进**。 |
| R4       | `func` / `if` / `else` / `while` 的直接块内语句必须比当前块级缩进**恰好多一级**。过少、无对应嵌套语句却多于一级，或同一语句序列内行首空格组数量不一致，均为缩进错误。 |
| R5       | `end` 行缩进必须等于当前块级缩进；若缩进不足或过多，均为静态错误。 |
| R6       | 嵌套 `if`/`while` 时，内层块行缩进必须比外层块内语句的缩进再多一级（即外层缩进 + 2 个级别）。内层块的块内语句再比内层块多一级，其 `end` 与内层块对齐。 |
| R7       | 合法的函数内 `label` **不产生**新的缩进层级、不开启代码块。`label` 行缩进与同作用域其它普通语句一致；其后仍属同一作用域、且非新子块内的语句，缩进必须与该 `label` 行**完全一致**。仅当后续语句本身开启 `if`/`while` 子块时，子块内部才按 R3–R6 增加缩进（详见 §9.3.2）。 |

> **源码示例约定**：本文所有标记为 `text` 的 TC 源码块均使用 4 个 ASCII 空格表示一级缩进。

##### 9.1.3 多分支写法（链式 `if-else`）

由于 `else if` 不允许写在同一行，链式分支的标准写法为：

```text
if <cond1> then
	语句序列1
else
	if <cond2> then
		语句序列2
	else
		if <cond3> then
			语句序列3
		else
			语句序列4
		end
	end
end
```

每个 `if` 都必须有对应的 `end`，且缩进逐级递增。

##### 9.1.4 执行语义

1. 计算 `<bool_rhs>` 的值。
2. 若为 `true`，执行 `then` 块内的所有语句，执行完后跳过 `else` 部分，直接跳至对应的 `end` 之后继续执行外层后续语句。
3. 若为 `false`，若存在 `else` 分支，则进入 `else` 块执行其内部语句（若 `else` 块内包含 `if`，则按 `if` 规则递归执行）。执行完 `else` 块后，遇到 `end` 继续执行外层后续语句。
4. 若条件为 `false` 且无 `else`，则直接跳至 `end` 之后执行。

##### 9.1.5 作用域与变量定义

- `then` 与 `else` 的直接语句序列分别构成独立的**代码块与块级作用域**。两者是互斥、互不包含且不可比的兄弟块；同一 `if` 内，`then` 侧定义的局部标识符在 `else` 侧不可见，反之亦然。因执行路径互斥，允许两侧分别定义**同名**局部变量（静态分析视为不同绑定）。
- 无 `else` 时只建立 `then` 代码块。`if` 条件在包含该 `if` 语句的外层作用域中求值，不另行建立可容纳语句的“整个 `if`”作用域。
- 代码块内允许使用 `var` 和 `let` 定义新的变量/常量；执行离开该分支代码块后，无法访问其中定义的任何局部标识符。
- 嵌套 `if` 时，内层块可访问外层块已定义的变量，除非被内层同名局部变量屏蔽。

##### 9.1.6 与 `let` 常量的交互

`let` 常量可在 `if` 块内定义，作用域同样限于该块。若 `if` 条件中引用 `let` 常量，其值是编译期确定的。

##### 9.1.7 与函数控制流的交互

`if` 可出现在顶层或函数体内。函数体各分支可使用 `return`；非 `void` 函数是否覆盖全部正常退出路径按 §10.3.2 和 §10.4 的函数 CFG 判断。顶层 `return` 是静态错误。函数定义本身不得出现在任何 `if` / `else` 分支内。

#### 9.2 循环语句（`while`）

TC 提供 **Pascal 风格** 的 `while` 结构化循环语句，采用 **缩进敏感** 的块结构，并以 **`end`** 关键字作为块的强制结束标志。

##### 9.2.1 语法定义

**强制语法形式**（行结构敏感）：

```text
while <bool_rhs> then
	语句序列
end
```

- `<bool_rhs>` 必须产生 `bool`（§4.5）。`then` 位于 `while` 行末，之后只能有行末注释和换行。
- `end` 单独成行并与 `while` 对齐，不得省略；循环体可以为空，非空时按 §9.1.2 缩进。
- 循环体语句范围由附录 A 决定，不能嵌套 `func`；`goto`/`label` 的额外禁令见 §9.2.4。

##### 9.2.2 执行语义

1. 计算 `<bool_rhs>` 的值。
2. 若为 `true`，执行 `then` 块内的所有语句（顺序执行）。
   - 若执行过程中遇到 `break`，立即退出整个 `while` 循环，跳转到对应的 `end` 之后继续执行。
   - 若遇到 `continue`，立即跳过当前迭代的剩余语句，跳转到步骤 1（重新计算条件）。
   - 若正常执行完块内所有语句（未遇 `break`/`continue`），先离开本轮循环体块实例，再返回步骤 1，开始下一次迭代。
3. 若为 `false`，直接跳转到对应的 `end` 之后，循环终止。

每次条件为 `true` 都进入一个新的循环体块实例；规范上的局部生命周期逐轮结束并重建。实现可以复用固定物理槽，但必须在确定初始化状态和可观察值上等价于重新进入。`continue`、正常回边和条件失败均按 §11.2.1 的边规范化处理。

> **无限循环说明**：当 `<bool_rhs>` 恒为 `true`（如 `while true then`）时，循环仅能通过 `break` 终止（因 `while` 内禁止 `goto`），否则为无限循环。

##### 9.2.3 作用域与变量定义

- `while` 的 `then … end` 直接语句序列构成一个**代码块与块级作用域**；循环条件在包含该 `while` 语句的外层作用域中求值。
- 块内使用 `var` 和 `let` 定义的新变量/常量，在 `end` 之后不可访问。
- 嵌套循环时，内层循环可访问外层变量，除非被同名局部变量屏蔽。
- `break` 和 `continue` 作用于**最内层**包含它们的 `while` 循环。它们不能跨循环作用（即 `break` 不能跳出嵌套的外层循环，只能跳出直接包围它的循环）。
- 位于函数体内时，`break` / `continue` 的目标查找在当前函数边界停止，绝不作用于调用者中的循环。

##### 9.2.4 范式隔离原则（与 `goto` 的交互）

`while` 是结构化循环，只能用 `break`/`continue` 控制迭代；其词法后代中禁止 `goto` 和 `label`。非结构化循环须在函数内以不含 `while` 的 `if` + `goto` 构造（§9.3），顶层不能使用。

诊断先检查函数边界：函数外使用分别报告 `TC_ERR_GOTO_OUTSIDE_FUNCTION` / `TC_ERR_LABEL_OUTSIDE_FUNCTION`；仅当已确认位于函数内，具有 `while` 祖先的语句才分别报告 `TC_ERR_GOTO_INSIDE_LOOP` / `TC_ERR_LABEL_INSIDE_LOOP`。

##### 9.2.5 与初始化相关的静态分析

循环相关的静态分析必须覆盖：

- `break` / `continue` 是否处于合法的 `while` 上下文（§9.4）；
- 范式隔离：`while` 体内无 `goto` / `label`（§9.2.4）；
- 以条件失败、正常回边、`continue` 与 `break` 构造完整 CFG；
- 按 §11.2 在全部可达路径上计算确定初始化集合。

除 §11.2 能在编译期证明条件恒为 `true` 外，循环体均可能零次执行，因此仅在循环体中执行的 `var` 不会自动进入循环后的确定初始化集合。恒真 `while` 不产生条件失败出口，仅可达 `break` 边参与循环后的会合；恒假 `while` 的循环体不可达。所有符合 0.0.33 的实现必须得到相同的分析结果。

#### 9.3 受限 `goto` 语句

TC 提供**仅限函数体内**的受限 `goto` 跳转语句，在保留汇编级灵活性的同时维护函数、调用帧和结构化块的安全边界。`goto` 是函数内构建**非结构化循环**（`if` + `goto`）的基础工具；顶层语句区保持结构化，不建立标签表，也不允许出现 `goto` 或 `label`。

##### 9.3.1 设计原则

1. **函数内限定**：`goto` 与 `label` 都必须具有 `func` 词法祖先。顶层直接使用，或在顶层 `if` / `else` / `while` 的任意嵌套层级使用，分别触发 `TC_ERR_GOTO_OUTSIDE_FUNCTION` 或 `TC_ERR_LABEL_OUTSIDE_FUNCTION`。
2. **同函数限定**：每个函数独立建立标签表；`goto` 只能解析当前函数内的标签，绝不跳到顶层或另一函数。
3. **作用域约束（只出不进）**：函数内仅允许跳转到当前作用域的**祖先作用域**（向外）或**自身作用域**（平级）。
4. **位置自由**：在满足其他规则时支持向前跳转和向后跳转，无源序方向限制。
5. **禁止侵入**：严禁跳入任何子作用域或与源块不可比的不相交作用域（包括 `then` ↔ `else` 兄弟分支）。
6. **范式隔离**：函数内 `goto` **不得**出现在 `while` 循环体内，`label` 也不得定义在 `while` 循环体内（见 §9.2.4）。
7. **标签规则**：同一块级作用域内禁止定义同名标签；不同块可定义同名标签。`goto name` 从所在的最内层块开始，沿祖先链向函数体直接层级查找，第一个同名标签唯一胜出（最近词法绑定）。标签名与变量名、常量名属于不同命名空间。
8. **初始化约束完备统一**：合法 `goto` 边进入当前函数的完整 CFG；变量是否可用只由 §11.2 的确定初始化分析判定。

##### 9.3.2 语法定义

- 标签写作 `label <标识符>:`，跳转写作 `goto <标识符>`；二者各自单独占一行，行末可带注释。
- 二者只能位于函数体直接层级，或函数内且无 `while` 祖先的 `if`/`else` 块。
- 二者均按普通语句缩进。`label` 不开启代码块或作用域，也不增加缩进；同作用域的后续普通语句与其对齐（§9.1.2 R7）。
- 标签本身无运行时动作；跳转目标是 **`label` 节点本身**，执行该零动作节点后沿正常落入边继续。这样连续标签、块末尾标签和标签后无普通语句的情形都有唯一语义：连续标签依次落入，块末尾标签落入该块的正常退出续点。`label` 不改变代码块关系，但作为跳转目标必须形成新的 CFG 基本块入口。

```text
func count_to_ten() int32 then
	var i: int32 = 0
	label loop_start:            ; 函数体直接层级，不产生新缩进
	i = add(int32, i, 1)         ; 与 label 同缩进
	if lt(int32, i, 10) then
		goto loop_start          ; 函数内向外跳回 loop_start
	end
	return i
end

var result: int32 = funcall(count_to_ten)
```

顶层的 `var result` 与 `funcall` 合法；如果把函数内任一 `goto` 或 `label` 移到顶层，即使缩进为 0、目标也在顶层，仍属于函数外使用并必须拒绝。

##### 9.3.3 作用域跳转的形式化规则

设 `F` 为包含 `goto name` 的函数，`Src` 为该 `goto` 在 `F` 中所在的最内层代码块（函数体、`if` 的 `then` / `else` 分支或嵌套代码块）。将从 `Src` 到 `F` 函数体代码块的块序列记为可见祖先链，顺序为由内向外。

在应用块关系前，必须按以下顺序完成上下文检查：

1. `goto` 没有 `func` 词法祖先 → `TC_ERR_GOTO_OUTSIDE_FUNCTION`，不执行标签查找；
2. `goto` 的任一词法祖先是 `while` → `TC_ERR_GOTO_INSIDE_LOOP`；
3. 仅在当前函数 `F` 的标签表中查找 `name`：从 `Src` 开始沿可见祖先链由内向外逐块查找。遇到的第一个同名标签绑定为唯一目标 `Tgt`；更外层及其他块中的同名标签均不参与本次绑定。
4. 若可见祖先链上没有同名标签，再检查 `F` 中其他块的同名标签，但它们只用于产生确定的非法跳转诊断，不会成为跳转目标：
   1. 若至少一个同名标签位于 `Src` 的严格后代块，报 `TC_ERR_JUMP_INTO_BLOCK`；
   2. 否则，若 `F` 中仍有位于与 `Src` 不可比块（两者互非祖先）的同名标签，报 `TC_ERR_JUMP_TO_SIBLING_BLOCK`；本错误名中的“兄弟块”统称全部不可比块，不仅限于共享直接父块的两个块；
   3. 同一诊断类别有多个候选标签时，以源位置最早的候选作为关联位置。上述“后代优先于不可比块”的类别优先级高于候选标签的源位置。
5. 若 `F` 中不存在任何同名标签，但另一函数存在同名标签，报告跨控制流域跳转；所有函数均不存在时报告 `TC_ERR_LABEL_NOT_FOUND`。

同一最内层代码块重复定义标签时报 `TC_ERR_DUPLICATE_LABEL`；跨块同名合法，并按上述祖先链规则绑定。

##### 9.3.4 语义规则

1. **执行流转移**：`goto` 无条件将控制权转移至目标 `label` 节点；该节点无运行时动作，再沿其正常落入边继续。不得把“标签后没有普通语句”视为无目标或实现自由。
2. **变量生命周期**：若跳转跳出某作用域（如 `then` 块），该块内的局部变量按 §11.1 / §11.2 **立即销毁**（与 `end` / `break` 离开块等价）；后续任何对该块内变量的引用，静态分析会报"未定义标识符"。
3. **CFG 边**：每条合法 `goto` 都必须形成从跳转语句到目标 `label` 节点的显式 CFG 边；`label` 再通过普通落入边连接其续点。向前、向后、同层与向外跳转使用同一表示。
4. **确定初始化**：编译器按 §11.2 在包含该边的完整 CFG 上求固定点。任何变量读取、赋值目标或 `read` 目标若不在当前 `IN` 集合中，触发静态错误 `TC_ERR_UNINITIALIZED_VARIABLE`。
5. **精确拒绝**：仅仅在源序上越过 `var` 不自动构成错误；若被越过的绑定在离开其作用域前从未使用，程序仍可合法。反之，无论被越过的 `var` 位于同层还是祖先作用域，只要存在可达未初始化使用就必须拒绝。
6. **反向跳转**：再次执行同一 `var` 时重新初始化同一词法槽；不重复分配槽位。
7. **跳过 `end`**：允许 `goto` 跳出 `if` 块而无需经过 `end`，执行流正常继续。
8. **不修改值**：`goto` 本身不改变任何仍存活变量的值，仅转移控制流。
9. **不跨函数**：跨函数的非法跳转不得进入任何 CFG，VM 与 AOT 也不得为其生成运行时边。当前函数不存在同名标签、但另一函数存在时报告跨控制流域跳转；所有函数均不存在时报告标签未找到。

**示例**：
```text
func invalid_path() void then
	goto label_skip
	var x: int32 = 10
	label label_skip:
	writeln(int32, %d, x)   ; TC_ERR_UNINITIALIZED_VARIABLE
	return
end

func valid_path() void then
	goto after_unused
	var unused: int32 = 10
	label after_unused:
	writeln(int32, %d, 0)    ; 合法：被跳过的 var 从未使用
	return
end
```

#### 9.4 `break` 与 `continue` 语句

##### 9.4.1 语法定义

`break` 和 `continue` 各为一条独立语句，独占一行，无额外参数。

```text
break
continue
```

**缩进规则**：它们属于普通语句，必须遵循所在块（`while`、`if` 或嵌套块）的缩进规则，即缩进级别必须严格大于当前块级缩进。

##### 9.4.2 语义规则

| 语句       | 行为                                                         |
| ---------- | ------------------------------------------------------------ |
| `break`    | 立即终止**最内层**包含它的 `while` 循环，控制流跳转到该循环的 `end` 之后；离开该 `while` 块时，块内局部变量按 §11.1 / §11.2 销毁。 |
| `continue` | 立即结束当前迭代并离开本轮循环体块实例，控制流跳转到**最内层**包含它的 `while` 的条件求值处：重新计算 `<bool_rhs>`；若为 `true`，则建立新一轮块实例并从循环体**首条语句**起按源序重新执行（实现可复用同一局部槽，但其确定初始化状态已重置）；若为 `false`，则退出循环。`continue` **不会**跳过条件求值而直接落到循环体中部。 |

**约束**：
- `break` 和 `continue` **必须**直接或间接位于某个 `while` 循环体内（即其所在的词法作用域链中至少有一个 `while` 块）。
- 若编译器静态分析发现 `break` 或 `continue` 不在任何 `while` 循环内，触发静态错误：
  - `TC_ERR_BREAK_OUTSIDE_LOOP`（针对 `break`）
  - `TC_ERR_CONTINUE_OUTSIDE_LOOP`（针对 `continue`）
- `break`/`continue` 可以出现在 `if` 块或其他嵌套块内，只要这些块本身位于 `while` 循环体内即可。
- **禁止**使用 `break`/`continue` 跳出 `while` 直接到外层（例如想跳出两层循环，需改写结构化逻辑，或将该逻辑封装进函数后使用 `if` + `goto` 非结构化循环重构）。`break`/`continue` 的作用域目标是最内层 `while`，**而非**最内层 `if`。
- `break` 和 `continue` 的作用域目标仅为最内层包含它们的 `while` 循环，外围的 `if` 块不影响其合法性判定。
- 目标查找不得穿越函数边界；函数调用者中的 `while` 不会使被调函数内的 `break` / `continue` 合法。

##### 9.4.3 与 `if` 的典型组合

实际编程中，`break`/`continue` 常配合 `if` 条件使用：

```text
while lt(int32, i, 10) then
	if eq(int32, i, 5) then
		break
	end
	i = add(int32, i, 1)
end
```

##### 9.4.4 与 `let` 常量的交互

`while` 条件中可以引用 `let` 常量。强制 RHS 不因恒真/恒假循环而改变；`goto` 的限制见 §9.2.4 与 §9.3。

### 10. 函数与调用模型

#### 10.1 函数定义与签名（`func`）

函数是仅允许在 `#lib` 模块中定义的显式可调用结构。`#program` 模块不得定义函数，其顶层可执行语句是程序入口；`#lib` 没有顶层执行入口。函数定义只在编译期建立签名和函数体，不产生顶层执行效果。

##### 10.1.1 定义形式

```text
func <函数名>([<形参名>: <值类型> [, ...]]) <返回类型> then
	语句序列
end
```

- 形参类型只能是 `bool`、8 种整数类型或 2 种浮点类型。
- 返回类型可以是上述值类型或 `void`。
- 函数体直接语句必须比 `func` 行恰好多一个缩进级别；函数 `end` 必须与 `func` 行对齐。
- 函数体可以为空，但空函数体仍须满足返回路径规则；因此空的非 `void` 函数和空的 `void` 函数都会因可达函数末尾而报缺少返回。

##### 10.1.2 签名约束

- 函数名在源文件中唯一，不支持重载。
- 全局函数名不得与源文件中任何值绑定同名。该禁令覆盖顶层值作用域中直接定义的 `var` / `let`、顶层 `if` / `while` 任意嵌套块内的 `var` / `let`、全部函数形参，以及函数体任意层级的 `var` / `let`。
- 形参名在同一函数签名中唯一。
- 形参按值传递，是函数入口处已初始化的只读绑定；不得赋值，也不得作为 `read` 目标。
- `void` 不是值类型，不得用作形参、`var`、`let`、转换目标、运算类型参数或操作数类型。
- 形参与任何局部值绑定若与全局函数同名，统一报告 `TC_ERR_FUNCTION_NAME_CONFLICT`；顶层嵌套块的值绑定也按同一规则处理，不因 `funcall` 与普通 RHS 使用不同查找入口而获准同名。函数内任何层级都不得声明与形参同名的 `var` / `let`；这一参数保护冲突继续报告 `TC_ERR_DUPLICATE_DEFINITION`。两类冲突的定位与阶段见 §13.1.1 / §13.5。
- 编译器在分析任何函数体和顶层语句之前收集全部函数签名。函数可调用定义在其后的函数，但调用图必须无环（§10.6.3）。

##### 10.1.3 定义位置

- 函数仅允许在 `#lib` 模块中定义；`#program` 模块不得定义函数。
- `#lib` 中所有 `static var` 和 `static let` 声明定义必须先于任何 `func` 定义出现；函数定义之间的顺序不限。
- `func` 不是语句，因而不得出现在函数体、`if` / `else` 分支或 `while` 循环体内。
- 不支持脱离 `func`、`if` 或 `while` 的匿名代码块。
- `main` 不是特殊名称；程序不因存在 `main` 函数而自动调用它。

非法示例：

```text
var input: int32 = 10

func get_value() int32 then   ; 非法：顶层语句区开始后又定义函数
	return 10
end
```

##### 10.1.4 0.0.33 不支持的函数形态

0.0.33 不支持函数重载、默认参数、可变参数、函数值、函数指针、闭包、嵌套函数、匿名函数、直接或间接递归、隐式参数转换、隐式返回转换和函数调用嵌套。函数不能隐式访问顶层值绑定；标准 I/O 副作用仍被允许。

#### 10.2 函数调用（`funcall`）

##### 10.2.1 调用形式

```text
funcall(<函数名> | Self.<函数名> | <模块名>.<函数名>
        [, <形参名>: <operand> ...])
```

非 `void` 函数：

```text
var total: int32 = funcall(add_values, lhs: 10, rhs: 20)
```

`void` 函数：

```text
funcall(show_value, value: total)
```

`funcall` 的第一项必须是静态函数名，而不是普通 RHS 或函数值。程序模块调用本模块函数使用裸 `identifier`；库函数体调用本库函数必须使用 `Self.identifier`；两种模式调用已导入库函数都必须使用 `<模块名>.identifier`。名称分别在本模块函数签名表或对应导入模块的函数签名表中解析。

##### 10.2.2 命名且有序的实参

- 除函数名外，每一项必须使用 `<形参名>: <operand>` 形式。
- 每个形参恰好匹配一个实参；缺失、重复或未知名称均为静态错误。第 `i` 个实参必须命名为第 `i` 个形参，文本顺序不同也报错；编译器不得重排。
- 实参操作数严格按调用点从左到右读取并依次绑定。VM 与 AOT 不得改变该可观测顺序。
- 每个实参只能是 §4.6 的 `operand`：标识符、整数字面量、浮点字面量、浮点特殊值或布尔字面量。算术、位、比较、逻辑、转换和 `funcall` 均不得直接作为实参。
- 复杂值先写入临时 `var`；一条 `funcall` 只含一个运行时调用。
- 每个形参类型是对应实参的唯一期望类型，不做隐式转换。普通浮点字面量的源类型由后缀决定；整数字面量与浮点特殊值由形参提供上下文，并按 §3.6 检查。

合法：

```text
var total: int32 = funcall(add_values, lhs: 10, rhs: 20)
```

下列位置实参、乱序实参和复杂实参均非法：

```text
var a: int32 = funcall(add_values, 10, 20)
var b: int32 = funcall(add_values, rhs: 20, lhs: 10)
var c: int32 = funcall(add_values, lhs: add(int32, x, y), rhs: 20)
```

复杂实参必须拆分：

```text
var lhs_value: int32 = add(int32, x, y)
var total: int32 = funcall(add_values, lhs: lhs_value, rhs: 20)
```

##### 10.2.3 返回值使用位置

非 `void` 函数调用的返回值可由**新声明的 `var` 接收**或**覆盖已有变量**；`void` 函数调用只能作为独立语句。三种合法形态如下：

```text
var result: int32 = funcall(get_value)    ; 新声明 var，接收非 void 返回值
result = funcall(get_next)                ; 覆盖已有变量，返回值写入 result
funcall(show_value, value: result)        ; 独立调用 void 函数
```

调用位置矩阵如下：

| 调用位置 | 非 `void` | `void` |
| --- | ---: | ---: |
| `var x: T = funcall(...)` | 合法 | 静态错误 |
| `x = funcall(...)` | 合法 | 静态错误 |
| 独立 `funcall(...)` | 静态错误 | 合法 |
| `let x: T = funcall(...)` | 语法错误 | 语法错误 |
| `return` 操作数位置 | 语法错误 | 语法错误 |
| 嵌套实参或其他运算操作数 | 语法错误 | 语法错误 |

`var x: T = funcall(...)`、`x = funcall(...)` 与独立 `funcall(...)` 都由语法接受；被调函数的实际返回类型不适合该位置时，报函数调用位置错误。

- 非 `void` 调用用于 `var` 声明时，实参合法后检查接收 `var` 的声明类型；不匹配时报调用结果类型错误。
- 非 `void` 调用用于已有变量赋值时，实参合法后检查目标变量的声明类型；不匹配时报调用结果类型错误。赋值目标必须在当前 CFG 点确定初始化（§11.2）。
- `void` 调用仅可独立成句，不得用于 `var` 声明或已有变量赋值。

返回值转发可通过新 `var` 或已有变量：

```text
func forward() int32 then
	var result: int32 = funcall(get_value)
	return result
end

func accumulate(total: int32) int32 then
	total = funcall(add_next, value: total)  ; 读取 total，调用后再覆盖
	return total
end
```

#### 10.3 `return` 语句

##### 10.3.1 语法形式

```text
return [operand]
```

- 非 `void` 函数使用 `return operand`。
- `void` 函数使用裸 `return`。
- `return` 后最多一个 §4.6 定义的 `operand`；运算、转换或 `funcall` 不符合语法，必须先写入局部 `var`。

##### 10.3.2 静态语义

- `return` 只能出现在函数体内；顶层 `return` 是静态错误。
- 非 `void` 函数禁止裸 `return`；`void` 函数禁止 `return operand`。
- 返回标识符或普通字面量的类型必须与声明返回类型严格相同，不进行隐式转换。
- 整数字面量与浮点特殊值由返回类型提供期望类型上下文；浮点字面量仍由后缀决定类型。
- 每条从函数入口可达、会正常退出函数体的路径都必须经过匹配签名的显式 `return`。函数体 `end` 不产生隐式返回。
- 编译器为每个函数建立唯一函数末尾节点；若该节点从函数入口可达，报缺少返回。
- 不要求证明一般程序终止。永久停留在 `while` 或受限 `goto` 循环、且没有到函数末尾 CFG 边的可达路径合法。
- `return` 终结当前 CFG 路径，只连接当前函数的正常返回终止节点，不产生到源序后继语句的 CFG 边。`return` 后继节点是否不可达，与 `break` / `continue` / `goto` 的后继节点一样，统一由 §11.2.1 的完整 CFG 入口可达性分析判定；不再对“同一代码块内 `return` 之后到下一 `label` 之前”建立局部特例。

```text
func invalid_after_return() void then
	return
	var x: int32 = 0      ; TC_ERR_UNREACHABLE_STATEMENT
end

func valid_label_entry(flag: bool) void then
	if flag then
		goto resume
	end
	return                 ; flag == false 时可达
	label resume:          ; 可由可达的 goto resume 边到达
	return
end
```

直接返回运算结果非法，必须拆分：

```text
; 非法
return add(int32, lhs, rhs)

; 合法
var result: int32 = add(int32, lhs, rhs)
return result
```

全路径返回示例：

```text
func choose(flag: bool) int32 then
	if flag then
		return 1
	else
		return 2
	end
end
```

若删除 `else` 分支，`flag == false` 时会到达函数末尾，因而是缺少返回错误。

##### 10.3.3 运行时语义

`return` 按以下顺序执行：

1. 若存在返回操作数，在当前函数帧中读取其值。
2. 将结果复制到调用者拥有、且不随被调函数帧销毁的返回值位置。
3. 离开当前函数的所有活动块作用域。
4. 销毁当前函数帧。
5. 将控制权恢复到调用者的 `funcall` 之后。
6. 非 `void` 结果用于初始化调用点的新 `var`。

若读取返回值或执行被调函数期间发生运行时错误，整个程序立即终止；不执行正常返回流程，调用点的新 `var` 也不成为已初始化绑定。VM 与 AOT 可以采用不同清理机制，但不得恢复调用者继续执行。

#### 10.4 函数作用域与独立 CFG

##### 10.4.1 名称查找和局部绑定

函数体内普通裸标识符按以下顺序查找：当前块、逐层外部块、函数体直接局部绑定、当前函数参数；到函数边界即停止。函数仅存在于 `#lib` 模块中。函数体仅可按 §4.1.3 以 `Self.id` 访问本模块的 `static let` / `static var`；该限定查找不参与局部词法作用域的屏蔽。

为使越界名称诊断唯一，语法解析后必须建立一个只含**顶层值作用域直接声明**（不在任何顶层 `if` / `while` 块内）的 `var` / `let` 名称索引；该索引覆盖整个顶层语句区，但只用于错误分类，绝不赋予函数可见性。函数内普通查找失败后，若同名绑定存在于该索引，报告 `TC_ERR_FUNCTION_SCOPE_ACCESS`；否则报告 `TC_ERR_UNDEFINED_VARIABLE`。顶层嵌套块中的局部绑定不属于顶层值作用域直接声明，不能触发本专用错误。此分类统一适用于普通 RHS、赋值目标、`read` 目标、`let` 依赖、`funcall` 实参和 `return` 操作数，并在各构造所属的第 6/7/8 阶段执行。

- 函数体直接声明的 `var` / `let` 从声明完成后可见，到函数返回时失效。
- 同一作用域不得重复定义同名值绑定；内层块可按 §11.1 屏蔽普通外层局部绑定，但不得屏蔽参数或与任何全局函数同名。任意层级的 `var` / `let` 与当前函数形参同名均按参数保护冲突报告 `TC_ERR_DUPLICATE_DEFINITION`；与全局函数同名则报告 `TC_ERR_FUNCTION_NAME_CONFLICT`。两者都不解释为普通跨作用域屏蔽。
- 函数内 `let` 仍须在编译期求值，不得引用参数、局部 `var` 或 `funcall`。
- 参数在入口已初始化；函数内 `var` 仍须声明时提供初始化器。
- 函数返回时销毁所有局部运行时槽；`let` 继续编译期内联，不分配运行时槽。

##### 10.4.2 顶层 CFG

顶层 CFG：

1. 具有唯一入口和唯一程序正常结束节点，入口已初始化集合为空。
2. 顶层绑定只由顶层声明和顶层数据流产生。
3. 文件末尾连接程序正常结束节点，不执行缺少返回检查。
4. 顶层 `return` 在 CFG 构建前拒绝。
5. 顶层及其嵌套块中的 `goto` / `label` 在 CFG 构建前分别以 `TC_ERR_GOTO_OUTSIDE_FUNCTION` / `TC_ERR_LABEL_OUTSIDE_FUNCTION` 拒绝；顶层不建立标签表，也不生成 `goto` 边。
6. 顶层 `funcall` 是单个原子节点，不产生到被调函数 CFG 的边。

##### 10.4.3 函数 CFG

每个函数 CFG 至少包含唯一入口、函数体语句与控制节点、每条 `return` 的正常返回终止节点，以及表示未经 `return` 到达 `end` 的唯一函数末尾节点。

1. `IN[entry]` 恰好包含当前函数全部形参，不包含顶层绑定、调用者局部绑定或其他函数状态。
2. `if`、`while`、`break`、`continue`、`goto` 和标签沿用本章规则，但所有边必须留在当前函数 CFG 内。
3. `return` 只连接当前函数的正常返回终止节点，没有函数内后继边。
4. `funcall` 在调用者 CFG 中保持单节点；成功的非 `void` 调用若用于 `var` 初始化则把新绑定加入 `OUT`，若用于已有变量赋值则仅更新该绑定的值（不改变 `IN`/`OUT` 的成员关系）；`void` 调用不改变已初始化集合。
5. 按 §11.2.1 从函数唯一入口遍历 CFG；任何不在可达集合中的语句节点报 `TC_ERR_UNREACHABLE_STATEMENT`。只有入口可达节点参与确定初始化固定点和函数末尾检查；不可达代码的词法、语法、名称和类型检查仍执行。
6. 函数末尾节点可达时报缺少返回；无出口循环不产生到函数末尾的边。

顶层 CFG 与各函数 CFG 是完整、封闭、彼此独立的分析单元，不得拼接、内联或共享节点、边、可达性、已初始化集合、活动块路径或固定点状态。实现可复用算法，但不得合并各域的入口、出口和语义状态。

#### 10.5 函数控制流边界

顶层与每个函数是彼此封闭的控制流域；只有函数建立标签表。`return` 只退出当前函数，`break`/`continue` 只解析到当前函数内最内层 `while`。`goto`/`label` 的查找、块关系和诊断严格按 §9.3 执行并在函数边界停止：跨函数或跳向顶层的边不进入 CFG，不同函数中的同名标签互不相关。

#### 10.6 调用图与运行模型

##### 10.6.1 调用帧

每次 `funcall` 至少创建以下逻辑状态：

- 被调函数标识；
- 返回地址或等价继续点；
- 按形参绑定的实参值；
- 函数局部 `var` 槽；
- 活动块路径和函数内控制流状态；
- 非 `void` 函数的返回值位置。

规范不强制 VM 与 AOT 使用相同物理布局，但可观测语义必须一致。

##### 10.6.2 调用步骤

1. 按形参声明顺序，从左到右检查同一文本位置的实参名称和期望类型，并读取实参操作数。
2. 任一运行时错误立即终止整个程序。
3. 创建被调函数帧并写入参数值。
4. 从函数体第一条语句开始执行。
5. 执行 `return` 时销毁函数帧并恢复调用者。
6. 非 `void` 结果若用于 `var` 声明则初始化新变量，若用于已有变量赋值则覆盖目标变量的当前值。

##### 10.6.3 无环调用图

编译器必须为全部函数体内的 `funcall` 建立有向调用图；顶层调用可以作为无入边的外部根记录，但不参与函数间环判定。调用图边不是 CFG 边，不参与确定初始化、可达性或控制流传播。

若函数调用图存在环，无论相关调用点运行时是否可达，均报递归错误。自调用是长度为 1 的环；间接递归同样非法。

### 11. 名称、作用域、生命周期与确定初始化

#### 11.1 作用域

TC 采用 **全局函数签名表**、**顶层值作用域**、**函数作用域** 与 **块级作用域** 相结合的设计：

- **全局函数签名表**：编译器在分析函数体和顶层语句前收集全部函数签名。函数名全局可见，不受定义源序限制；普通 RHS 不把函数名解析为值，只有 `funcall` 的第一项在该表中解析。
- **顶层值作用域**：`#program` 模块中，所有 `import` 和顶层 `var` / `let` 声明之后、且不在任何 `if`/`while` 块内部定义的 `var` 和 `let` 属于顶层值作用域。它们在顶层语句区遵循源序可见性，生命周期贯穿程序运行始终。`#lib` 模块中函数为 `#lib` 私有，不存在独立的顶层值作用域。
- **函数作用域**：每个函数体形成独立函数作用域，包含只读参数、函数体直接声明的局部 `var` / `let`，以及嵌套块。普通值名称查找到函数边界即停止，不得继续查找顶层值。每次调用创建独立函数帧，不同调用之间不共享参数或局部 `var`。
- **代码块与块级作用域**：函数的 `then … end` 是函数体代码块。`if` 的 `then` 与 `else` 直接语句序列分别是两个互斥、互不包含且不可比的兄弟代码块；无 `else` 时只有 `then` 块。`while` 的 `then … end` 是循环体代码块。除函数体另按函数作用域管理外，每个分支/循环代码块同时构成独立块级作用域；嵌套 `if` / `while` 开启新代码块。两个兄弟分支中的局部标识符互不可见，但允许分别定义同名局部变量。代码块内定义的 `var` / `let` 在**离开该块之后**不可访问（见下「变量生命周期」）；嵌套块支持内层屏蔽普通外层同名值绑定（建议避免），但全局函数名与函数形参的保护规则优先，不得通过任何顶层或函数内嵌套块重新声明同名 `var` / `let`。
- **标签作用域**：标签只存在于函数内，遵循与函数局部变量（`var`）和常量（`let`）相同的块级可见性，并额外受函数边界与范式隔离约束：
  - `label` 必须具有 `func` 词法祖先，且 `while` 代码块内**禁止**定义 `label`（§9.2.4）。合法标签只能出现在函数体代码块或函数内 `if` 的 `then` / `else` 代码块中。`label` 不开启新代码块或作用域，但必须形成新的 CFG 基本块入口。
  - 标签在定义所在的**最内层代码块**及其后代块中可见，但后代块中更近的同名标签会屏蔽它。
  - `goto name` 从所在块开始沿祖先链由内向外查找，第一个同名标签是唯一绑定；查找到函数边界即停止。同一代码块内**禁止**定义同名标签。
  - 不同代码块（如 `then` 分支与 `else` 分支，或不同嵌套层级）允许定义**同名**标签，互不冲突（与 `var` 允许在互斥分支定义同名变量的规则一致）。
  - 每个函数拥有独立标签表，顶层没有标签表。不同函数中的同名标签是独立绑定；其他函数的标签只用于区分“跨控制流域跳转”和“标签未找到”诊断，绝不成为跳转目标。
- **源序可见性**：`var` / `let` 绑定从其声明结束后的词法位置开始可见；定义自身的初始化器或 RHS **不可**引用正在定义的绑定，亦不可引用尚未声明的值标识符。`var` 在某条运行时路径上是否已执行初始化由 §11.2 的确定初始化分析判定；`let` 在第 9 阶段统一求值并内联，不以运行时路径是否经过其声明行为条件，因此 `goto` 绕过 `let` 不影响后续词法可见位置对该常量的使用。函数签名是另一例外：全部函数签名在函数体分析前收集，因此函数可以调用定义在其后的函数，但调用图不得形成环。
- **变量生命周期**：
  - 顶层变量：程序启动时建立固定槽位，但不自动写入初值；执行到对应 `var` 后才成为已初始化。程序终止时销毁。
  - 参数：调用帧建立时按形参声明顺序写入并视为已初始化；函数返回时销毁。
  - 函数体直接局部变量：进入函数时建立固定槽位，执行到对应 `var` 时初始化；函数返回时销毁。
  - 局部变量（块内）：进入作用域时为该作用域的全部 `var` 绑定建立固定槽位；执行到对应 `var` 时计算 RHS、写入槽位并成为已初始化。反向跳转或下一次循环迭代重新执行同一 `var` 时，重新初始化同一词法槽，不重复分配。离开当前块实例时统一结束其局部生命周期——离开方式包括对应 `end` 的正常落入、循环体正常回边、`break`、`continue`、`return` 或向外 `goto`；实现可以复用物理槽，但必须清除该块实例的确定初始化状态。块内 `let` 随词法作用域结束而不再可见（本身无运行时槽，见 §11.2）。

#### 11.2 变量生命周期与确定初始化

| 阶段 | 行为 |
| ---- | ---- |
| 作用域进入 | 建立本作用域全部 `var` 的固定槽位，初始状态为“未初始化” |
| `var` 执行 | 先检查并计算普通 RHS 或执行非 `void` `funcall` 初始化器，再写入对应槽位；成功后状态变为“已初始化” |
| 赋值 / `read` | 目标变量必须已确定初始化；成功后更新同一槽位，不改变其生命周期 |
| 运行时绑定读取 | `var` 或参数绑定必须在当前 CFG 点上确定初始化，否则静态错误 `TC_ERR_UNINITIALIZED_VARIABLE`；`let` 已在编译期内联，不属于本行 |
| 反向跳转 / 下一迭代 | 再次执行 `var` 时重新初始化同一槽位，不创建新绑定或新槽位 |
| 作用域离开 | 因正常 `end` / 循环回边、`break`、`continue`、`return` 或向外 `goto` 离开当前块实例时，结束局部生命周期并清除其确定初始化状态；物理槽可复用 |
| `let` | 编译期求值并内联，不生成运行时槽；在 CFG 中保留无运行时效果的身份节点，仅参与源级可达性诊断，数据流传递函数为恒等 |
| 参数 | 函数入口时已初始化，只读；不得赋值或作为 `read` 目标 |
| `return` | 终止当前函数 CFG 路径，销毁当前函数帧及活动块局部槽 |

##### 11.2.1 CFG 可达性与确定初始化数据流

编译器必须分别为顶层语句区和每个函数建立封闭 CFG。顶层 CFG 处理结构化控制流，不含 `goto` / `label` / `return`；函数 CFG 在同一分析框架中额外处理函数内 `goto` / `label` 与 `return`。不同控制流域不得共享节点、边或数据流状态。

**CFG 边与可达性**：

1. 在 §4.3 常量求值和静态布尔三态判定完成后构建 CFG；静态 `true` / `false` 条件删除不可能边，`unknown` 条件保留真、假两边。
2. 附录 A `statement` 产生式接受的每条源语句均建立对应的源级 CFG 节点；其中 `let` 是无运行时效果的身份节点。普通顺序语句连接源序后继；`if` / `while` 按其结构化语义建立分支、会合、回边和退出边。函数定义、空行、纯注释行以及结构标记 `else` / `end` 不是语句节点。
3. `return` 只连接当前函数的正常返回终止节点；`break` 只连接最内层 `while` 的退出点；`continue` 只连接最内层 `while` 的条件节点；`goto` 只连接其已合法绑定的目标 `label`。这四类语句均不连接源序后继。
4. `label` 是 CFG 基本块入口，可同时接收源序落入边和合法 `goto` 边；但 `label` 不因自身是跳转目标而天然可达，只有来自已可达节点的入边才能使其可达。来自不可达 `goto` 的边不能使目标变为可达。
5. 从当前控制流域的唯一入口沿上述边遍历，所得节点集合是该域的唯一可达集合。每个函数的入口均作为本函数分析的可达根，不因该函数没有被 `funcall` 而把其函数体判为不可达。
6. 任何不在可达集合中的语句节点（包括 `label`）报 `TC_ERR_UNREACHABLE_STATEMENT`，并定位到源位置最早的不可达语句。不可达语句仍须通过词法、语法、名称和类型检查，但不参与确定初始化固定点、函数末尾可达性传播或其他运行时数据流。

**活动作用域与边规范化**：

- 每个 CFG 节点都附带其词法活动代码块链。绑定用“声明身份”而非名称表示，因此被屏蔽的同名变量是不同数据流元素。
- 对每条边 `p → n`，先从 `OUT[p]` 删除所有在 `n` 的活动块链中不存活的绑定，再作为 `n` 的前驱状态。该规则统一处理 `end`、`break`、`continue`、`return` 和向外 `goto` 的生命周期结束。
- 进入一个新的块实例时，该块内全部 `var` 绑定均以未初始化状态开始，即使实现复用同一物理槽。`while` 条件真边进入新一轮循环体时同样重置循环体局部绑定；`continue` 回到条件节点之前先离开当前循环体实例。
- 同一块内的反向 `goto` 不离开该块，因此不会仅因跳转而清除仍存活绑定；若再次执行某条 `var`，该语句按普通传递函数重新写入同一词法槽。初始化 RHS 仍不得引用正在定义的绑定，即使该槽在反向边上曾经初始化。

因此，静态条件边裁剪后不可能执行的非空分支或循环体，以及无可达 `break` 的恒真循环之后的语句，均按本规则报不可达语句错误。只含 `let` 的 suite 仍含源级语句节点；空 suite 不含语句节点，本身不产生不可达语句诊断。

完成可达性检查后，仅在可达子图上执行确定初始化分析。设 `IN[n]` 为可达语句 `n` 执行前确定已初始化的绑定集合，`OUT[n]` 为执行后的集合。再令 `U[n]` 为节点 `n` 的活动作用域链中全部运行时绑定的全集：它包含当前函数形参，以及当前块实例和全部活动祖先块实例中仍处于生命周期内的全部 `var` 绑定，无论相应 `var` 声明语句此时是否已经执行；不包含编译期 `let`、其他函数的绑定、尚未进入或已经退出的块实例绑定。各集合均以声明身份区分同名屏蔽绑定，并满足 `IN[n] ⊆ U[n]`、`OUT[n] ⊆ U[n]`：

```text
IN[top-level entry] = ∅
IN[function entry]  = 当前函数的全部参数
IN[n]     = ∩ EDGE_OUT[p → n]，其中 p 为 n 的全部可达前驱，
            EDGE_OUT 为按活动作用域规范化后的 OUT[p]
OUT[var x = rhs] = IN[n] ∪ {x}
OUT[var x = funcall(...)] = IN[n] ∪ {x}  ; 调用成功路径
OUT[x = funcall(...)] = IN[n]              ; x 须 ∈ IN[n]，结果覆盖同一槽位，不改变成员关系
OUT[let ...]       = IN[n]               ; 无运行时效果的身份节点
OUT[其他语句]    = IN[n]
```

- `var x = rhs` 的 RHS 在加入 `x` 之前检查，因此初始化自引用仍非法。
- 任何可达的运行时 `var` / 参数读取、赋值目标或 `read` 目标都要求对应运行时绑定属于当前 `IN`。`let` 只要求名称可见且已成功求值，不属于 `U` / `IN`；逻辑短路的右操作数是否可达按 §7.2.2 判定。
- 会合点取可达前驱集合的交集；只有所有可达路径均已初始化才成立。
- 上述方程在可达子图上采用**最大固定点（greatest fixed point）**语义，不得任选任一固定点。一个等价的强制求解策略是：保持两个入口边界值不变；对每个非入口可达节点，以 `U[n]` 初始化 `IN[n]` 与 `OUT[n]`，再按活动作用域边规范化和传递函数单调向下迭代，直至所有集合不再变化。工作队列、节点遍历和回边发现顺序不得改变最终结果。
- 最大固定点还等价于以下路径语义：绑定属于 `IN[n]`，当且仅当从当前控制流域唯一入口到 `n` 的**每一条有限可达路径**，在逐边应用作用域规范化和上述传递函数后，都已初始化该绑定。该路径定义用于判定任何求解实现是否一致。
- 对没有可达前驱的非入口节点不定义 `IN`；它们已由可达性阶段排除。每个节点参与固定点迭代的数据流格上界恰为 `U[n]`，绝不把其他函数、未进入或已退出块、或编译期 `let` 混入数据流域。
- CFG 可达性与静态条件边裁剪完全依据本小节前述规则；CFG 不另行维护运算符白名单，也不将优化器的值推测用于改变可达语句集合。
- `funcall` 在调用者 CFG 中是单个原子节点，不展开被调函数 CFG；被调函数发生运行时错误时程序终止，不形成返回调用者的 CFG 边。
- `return` 节点只连接当前函数的正常返回终止节点；函数末尾节点若从入口可达，触发缺少返回错误。顶层文件末尾是合法程序正常结束，不执行缺少返回检查。
- 分析结果是 0.0.33 的强制语义，不允许实现通过更弱或更强的默认规则改变合法程序集合。

声明时强制 RHS 与确定初始化分析是两个独立保证：前者约束源代码形态，后者证明每次可达使用之前相应初始化语句确已执行。

## 第四部分：I/O 与诊断

### 12. 标准 I/O

#### 12.1 `write` — 不换行输出

**形式一：无格式输出**

| 项目       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 语法       | `write(int32, x)`、`write(float64, pi)`、`write(bool, flag)` |
| 功能       | 将操作数的值按类型解释写入 stdout，**不换行**                |
| 操作数规则 | 一个 §4.6 `operand`：运行时 `var` / 参数须确定初始化，`let` 须可见且已成功求值，或使用合法字面量 |
| 类型约束   | 标识符绑定类型与 `type` 一致；字面量满足 §3.6 约束            |
| 输出格式   | 整数：十进制；浮点：与 `%g` 相同的 6 位有效数字；布尔：`true`/`false` |

无格式形式先解析操作数名称并按显式 `type` 检查字面量；标识符操作数的声明类型与 `type` 不一致时报 `TC_ERR_TYPE_MISMATCH`，主位置为操作数首 Token。字面量的类别、后缀或范围不符合 `type` 时，继续使用 `TC_ERR_LITERAL_TYPE` / `TC_ERR_LITERAL_OUT_OF_RANGE`，不降级为通用类型错误。

**形式二：格式化输出**

| 项目       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 语法       | `write(int32, %d, x)`、`write(float64, %0.3f, pi)`、`write(bool, %-8t, flag)` |
| 功能       | 按格式说明符输出操作数的值，**不换行**                       |
| 操作数规则 | 一个 §4.6 `operand`；**恰好一个**操作数                      |
| 类型约束   | 操作数类型与 `type` 一致，且与格式说明符的转换符兼容         |

格式化形式的类型检查顺序固定为：

1. 先按无格式形式的规则检查操作数是否与显式 `type` 一致；标识符不一致报 `TC_ERR_TYPE_MISMATCH`，字面量不一致使用字面量专用错误。
2. 只有第 1 步成功后，才以该已闭合的 `type` 检查转换符兼容性；不兼容报 `TC_ERR_FORMAT_TYPE_MISMATCH`，主位置为格式说明符中的转换符字符。

因此，同一条 `write` / `writeln` 中同时存在“操作数 ↔ `type`”和“`type` ↔ 转换符”两类不一致时，前者先报；不得跳过第 1 步直接报格式类型错误。

#### 12.2 `writeln` — 换行输出

与 `write` 相同，但在输出末尾追加一个 LF 字节（`\n`），不随主机平台改写为其他行结束序列。会把文本流 LF 转换为其他字节序列的宿主上，AOT 必须使用二进制流或等价机制。`write`/`writeln` 向 stdout 写入失败时报 `TC_ERR_IO`。

每条 `write` / `writeln` 必须先完整生成本语句的输出字节串，再按程序执行顺序尝试一次**抽象逻辑提交**；格式化值与 `writeln` 的末尾 LF 属于同一次提交。只有整个提交成功时，该字节串才追加到 TC 抽象标准输出；若底层写入在完整提交前失败，本语句对 TC 抽象标准输出贡献零字节，并报告 `TC_ERR_IO`。此前已经成功提交的输出不回滚，随后语句不再执行。

实现可以使用缓冲或多次宿主写调用完成一次抽象逻辑提交，但不得重排成功提交的语句。某些宿主设备无法回滚失败前已经物理写出的前缀；该物理前缀是抽象提交失败时的外部设备泄漏，明确不属于 §1.4 的 TC 可观察行为，也不得用于比较 VM 与 AOT 的语言一致性。TC 语言级可移植结果是：此前成功提交的完整字节序列，加上当前语句的 `TC_ERR_IO`，不包含当前失败语句的任何字节。

#### 12.3 `read` — 标准输入

| 项目     | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| 语法     | `read(int32, x)`、`read(float64, radius)`、`read(bool, flag)` |
| 功能     | 从 stdin 读取一个值，**覆盖**已定义变量的当前值              |
| 目标变量 | 必须是已通过带 RHS 的 `var` 声明、在当前 CFG 点确定初始化且类型与 `type` 一致的可写变量；函数参数只读，不得作为目标 |
| 与初始化 | **`read` 不是初始化器**，不能代替 `var … = …` 或补救被控制流绕过的初始化 |
| 输入格式 | 见下表；跳过前导 ASCII 空白，并读取一个以 ASCII 空白或 EOF 结束的完整 Token |
| 错误处理 | 非法输入/数值超范围/非预期 EOF → **I/O 错误**                |

`read` 目标名称使用与赋值左侧相同的分类顺序：函数内普通查找失败但命中 §10.4.1 的顶层值作用域直接声明索引 → `TC_ERR_FUNCTION_SCOPE_ACCESS`，其他未定义值名 → `TC_ERR_UNDEFINED_VARIABLE`，`let` → `TC_ERR_CONSTANT_ASSIGNMENT`，函数参数 → `TC_ERR_PARAMETER_ASSIGNMENT`，只有可写 `var` 才继续检查类型和 `TC_ERR_UNINITIALIZED_VARIABLE`。全局函数名不属于值绑定。上述静态错误在执行前完成，不消费 stdin。

目标名称已解析为可写 `var` 后，若其声明类型与 `read` 的显式 `type` 不一致，报 `TC_ERR_TYPE_MISMATCH`，主位置为目标标识符。该类型检查在 CFG 确定初始化检查之前完成；类型不一致时不再产生 `TC_ERR_UNINITIALIZED_VARIABLE`。

**输入规则**：

| 目标类型            | 输入格式                                      |
| ------------------- | --------------------------------------------- |
| `int*`              | 可选 `-` 前缀 + 连续十进制数字，至少一位      |
| `uint*`             | 连续十进制数字，至少一位；**不接受** `-` 前缀 |
| `float32`/`float64` | 必须完整匹配下述 `input_float_token` |
| `bool`              | `true` 或 `false`（大小写敏感，均为小写）     |

本节的 ASCII 空白仅指 U+0009～U+000D 与 U+0020，不受 locale 影响。输入必须完整匹配目标格式；例如 `12abc` 整体非法，不得只接受前缀 `12`。

**输入 Token 的权威 EBNF**：

```ebnf
signed_input_integer
           = [ "-" ] , input_digits ;

unsigned_input_integer
           = input_digits ;

bool_input_token
           = "true" | "false" ;

input_float_token
           = finite_input_float
           | "inf"
           | "-" , "inf"
           | "nan" ;

finite_input_float
           = [ "-" ] , input_digits , [
               "." , input_digits , [ input_exponent ]
             | input_exponent
           ] ;

input_exponent
           = ( "e" | "E" ) , [ "+" | "-" ] , input_digits ;

input_digits = input_digit , { input_digit } ;
input_digit  = "0" … "9" ;
```

`read(int*, ...)`、`read(uint*, ...)`、`read(bool, ...)` 分别完整匹配 `signed_input_integer`、`unsigned_input_integer`、`bool_input_token`，再按目标类型检查范围。整数输入固定为十进制，允许前导零和 `-0`，不接受前导 `+`、进制前缀、分隔符或源代码字面量后缀。

`input_float_token` 是 `read(float32, ...)` 与 `read(float64, ...)` 接受集的完整定义：

- 完整的十进制整数数字串是有限浮点输入的一种特殊书写形式；因此 `1`、`-42`、`0` 和 `0007` 均合法，分别表示 `1.0`、`-42.0`、`0.0` 和 `7.0` 的精确十进制数学值。
- 十进制小数必须在 `.` 前后都有至少一位数字；因此 `1.` 和 `.5` 均非法，应分别写作 `1.0` 和 `0.5`。
- 整数形式或含小数点的完整形式均可带完整指数；`1e5`、`1E+5`、`1e-5` 与 `1.25e-3` 均合法。
- 前导 `-` 仅适用于有限值和 `inf`；前导 `+`、`-nan`、不完整指数（`1e`、`1e+`）均非法。`+` / `-` 可作为完整指数内的号。
- 目标类型已由 `read` 的第一个参数确定，因此输入不接受 `f` / `F` 后缀、数字分隔符、十六进制浮点、NaN payload 或其他宿主浮点扩展形式。`inf` 和 `nan` 大小写敏感。
- 实现必须先完整匹配上述 EBNF，再做数值转换；不得因宿主转换函数能接受 `1.`、`.5`、`+1.0` 或十六进制浮点而扩大 TC 输入集。

有限浮点输入（包括整数书写形式）先解析为精确十进制数学值，再按 roundTiesToEven 直接舍入到目标 binary32/binary64；不得先解析为 TC 整数类型，也不得通过另一浮点类型中转。因此整数书写形式不受 `uint64` 字面量词法上限约束，其可表示性只按目标浮点类型判定。有限输入的精确数学值为零且 Token 显式带前导 `-` 时生成负零，其余零输入生成正零。非零有限值舍入为零、有限值舍入为无穷，或整数目标的输入超出目标整数类型范围，均报 `TC_ERR_IO`；可表示的非规格化数合法。`nan` 输入生成 §5.3 规定的 canonical quiet NaN。非法 Token 与意外 EOF 同样报 `TC_ERR_IO`。

`read` 先完整扫描并验证一个输入 Token，再转换并提交目标值；只有全部步骤成功后才覆盖目标变量。失败时目标槽保持原值，随后程序按 §13.3 终止。实现不得受当前 locale、宿主 `strto*` 接受的扩展拼写或宿主浮点中间精度影响。

#### 12.4 格式转换符定义

| 符号 | 含义                     | 适用类型            | 示例（值 42/3.14159265） |
| ---- | ------------------------ | ------------------- | ------------------ |
| `%d` | 有符号十进制             | `int8`～`int64`     | `42`               |
| `%i` | 有符号十进制（同 `%d`）  | `int8`～`int64`     | `42`               |
| `%u` | 无符号十进制             | `uint8`～`uint64`   | `42`               |
| `%x` | 十六进制（小写 a-f）     | 任一整数类型        | `2a`               |
| `%X` | 十六进制（大写 A-F）     | 任一整数类型        | `2A`               |
| `%o` | 八进制                   | 任一整数类型        | `52`               |
| `%b` | 二进制                   | 任一整数类型        | `101010`           |
| `%t` | 布尔值文本               | `bool`              | `true`             |
| `%f` | 浮点十进制（固定小数）   | `float32`/`float64` | `3.141593`         |
| `%e` | 科学计数法（小写 e）     | `float32`/`float64` | `3.141593e+00`     |
| `%E` | 科学计数法（大写 E）     | `float32`/`float64` | `3.141593E+00`     |
| `%g` | 紧凑格式（较短）         | `float32`/`float64` | `3.14159`          |
| `%G` | 紧凑格式（较短，大写 E） | `float32`/`float64` | `3.14159`          |

**确定性格式规则**：

- 格式化不受进程 locale 影响，小数点固定为 `.`。
- 未显式给出精度时，`%f`/`%e`/`%E` 输出小数点后 6 位，`%g`/`%G` 输出 6 位有效数字。
- 十进制输出以源 binary32/binary64 值的精确数学值为输入，按 roundTiesToEven 舍入到所需十进制位数；不得先经过宿主的更低精度类型。
- `%e`/`%E` 在小数点前保留恰好一位非零数字（零值为 `0`），指数始终含 `+` 或 `-`，且至少两位十进制数字。
- `%g`/`%G` 先以当前精度 `p` 位有效数字舍入。设舍入后值的十进制指数为 `e`（即科学计数法中小数点前恰好一位时的指数）：当 `e < -4` 或 `e >= p` 时使用 `%e`/`%E` 形式，否则使用定点形式。未使用 `#` 标志时，小数部分末尾的 `0` 全部删除；若小数部分为空，同时删除小数点。
- `%d`/`%i` 按有符号数学值输出，`%u` 按无符号数学值输出。
- `%x`/`%X`/`%o`/`%b` 对任意整数输出其固定宽度二进制补码位模式，默认不带进制前缀（`#` 备用形式见 §12.5）。零恰好输出 `0`；其他非负值省略前导零；负值保留足以表示完整类型位宽的全部数字。例如 `int8` 值 `-1` 分别输出 `ff`、`FF`、`377`、`11111111`。
- `%e` 使用小写指数标记，`%E` 使用大写指数标记；`%G` 的指数标记与特殊值使用大写。
- 有限负零保留符号，例如 `%f` 输出 `-0.000000`，`%g` 输出 `-0`。
- 不带格式控制时，特殊值固定输出 `inf`、`-inf`、`nan`；在 `%E`/`%G` 下输出 `INF`、`-INF`、`NAN`。`+` 与字段宽度按 §12.5 作用于这些文本；NaN payload 不通过文本 I/O 暴露。

上述 `%g` / `%G` 规则中，零（含负零）使用十进制指数 `e = 0`。NaN 的符号位和 payload 均不通过文本输出：NaN 默认输出 `nan` / `NAN`，即使其位模式符号位为 1 也不添加 `-`；仅 `+` 标志会添加 `+`。所有十进制格式化舍入均使用 roundTiesToEven。

#### 12.5 C99 风格格式控制

格式说明符采用以下形态，且整体必须是无空白的单个 Token：

```text
%[flags][width][.precision]conversion
```

TC 参考 C99 `printf` 的静态格式控制，但格式说明符不是运行时值：一条 `write`/`writeln` 仍只包含一个格式说明符和一个操作数。`flags` 中每个标志至多出现一次，顺序不限；`width` 与 `precision` 只能写十进制常量，不支持 `*` 动态取值。

**确定性拆分规则**：从 `%` 后开始依次读取标志；字符 `0` 在尚未开始字段宽度时一律作为 `0` 标志，首个 `1`～`9` 才开始 `width`，其后的所有十进制数字均属于宽度。`.` 开始精度，转换符结束说明符。因此 `%08.3f` 唯一拆分为标志 `0`、宽度 `8`、精度 `3`；`%0008d` 拆分为三个重复的 `0` 标志和宽度 `8`，随后报告 `TC_ERR_FORMAT_SPECIFIER`。解析不得凭 EBNF 的其他可选分组选择不同拆分。

| 控制项 | 语法 | 语义 |
| ------ | ---- | ---- |
| 左对齐 | `-` | 结果不足字段宽度时在右侧补 ASCII 空格；同时出现 `0` 时 `0` 被忽略 |
| 强制符号 | `+` | `%d`/`%i` 及浮点转换中未以 `-` 起始的结果添加 `+`；包括 `+inf` 和 `+nan` |
| 备用形式 | `#` | `%x`/`%X`/`%b` 的非零结果添加 `0x`/`0X`/`0b`；`%o` 保证首位为 `0`；有限浮点结果始终保留小数点，且 `%g`/`%G` 保留精度要求的末尾零 |
| 零填充 | `0` | 指定字段宽度且未左对齐时，在符号或进制前缀之后、数字之前补 `0`；整数转换显式指定精度时忽略该标志 |
| 最小字段宽度 | `width` | 取值 `1`～`65535`；结果较短时按对齐和填充规则补齐，结果较长时不得截断 |
| 精度 | `.precision` | 取值 `0`～`65535`；仅写 `.` 等价于 `.0`；各转换的含义见下表 |

| 转换符 | 显式精度的含义 |
| ------ | ---------------- |
| `%d`、`%i`、`%u`、`%x`、`%X`、`%o`、`%b` | 最少数字位数；不足时在数字左侧补 `0`。值为零且精度为零时不输出数字，但 `%#.0o` 仍输出 `0` |
| `%f` | 小数点后的数字位数 |
| `%e`、`%E` | 小数点后的数字位数，指数部分不计入精度 |
| `%g`、`%G` | 有效数字位数；精度为零按 1 位处理 |
| `%t` | 不允许指定精度 |

标志的适用范围如下；表中未列出的组合是静态格式错误：

| 转换符 | 允许的标志 |
| ------ | ---------- |
| `%d`、`%i` | `-`、`+`、`0` |
| `%u` | `-`、`0` |
| `%x`、`%X`、`%o`、`%b` | `-`、`#`、`0` |
| `%f`、`%e`、`%E`、`%g`、`%G` | `-`、`+`、`#`、`0` |
| `%t` | `-` |

字段宽度按最终 ASCII 输出字符数计算；符号和进制前缀计入宽度，精度不包含它们。处理顺序为：按转换符和精度生成数字文本，添加符号或进制前缀，再按字段宽度填充。对 `inf`/`nan`，精度不改变文本，`0` 按空格填充处理。无 `width` 时 `-`/`0` 不产生填充，因此 `%0.3f` 与 `%.3f` 输出相同；例如值 `3.14159265` 分别得到 `3.142`，而 `%08.3f` 得到 `0003.142`。

已匹配附录 A `format_specifier` 形态后，重复标志、宽度或精度超出上述范围，以及转换符不适用的标志/精度，均在 §13.1 的**第 6 阶段**报告 `TC_ERR_FORMAT_SPECIFIER`。不符合该 EBNF 的形式在第 3 阶段按语法规则报告 `TC_ERR_SYNTAX`。`%p`、C99 空格标志、长度修饰符（如 `hh`/`l`/`ll`/`L`）和 `*` 均不受支持；TC 的类型已由第一个参数显式给出。

### 13. 诊断与错误处理

遇到 **第一个** 错误即终止程序（fail-fast）。错误按发生阶段分为 **静态**（词法/语法/静态分析）与 **运行时** 两类。

#### 13.1 确定性诊断阶段与初始化错误分工

0.0.33 采用确定的静态处理顺序：

1. 源字节的 UTF-8 解码（文件打开失败属于实现/API 层）；
2. 词法与缩进扫描；在形成字面量 Token 时执行 §2.3.5 的整数绝对值上限，以及 §2.4.1 中由浮点后缀唯一确定源类型后的舍入为零/无穷检查，这两类只依赖 Token 自身的失败均报告 `TC_ERR_LITERAL_OUT_OF_RANGE`；
3. 语法解析；
4. 收集全部函数签名；
5. 检查函数重名、签名和名称空间；本阶段完成全局函数名与顶层值作用域直接 `var` / `let`、以及全部形参的冲突检查；
6. 检查 `goto` / `label` 的函数上下文，分别解析函数体和顶层的名称与词法作用域；对顶层嵌套块及函数体任意层级的 `var` / `let` 执行全局函数名冲突检查；仅为各函数建立标签表，并在本阶段完成 `goto` 的标签查找、跨控制流域判定与块关系检查；同时检查普通 RHS 与 `const_rhs` 的类型、模式及上下文字面量约束，其中 `let` 按 §4.3.1 检查 RHS 结果类型与声明类型是否闭合；检查 `write` / `writeln` / `read` 的显式类型、格式说明符静态控制项及转换符兼容性，已匹配 EBNF 但格式控制非法时在本阶段报告 `TC_ERR_FORMAT_SPECIFIER`；`funcall` 实参和 `return` 操作数的上下文字面量检查分别保留到第 7、8 阶段；固定元数内建调用外壳的操作数数量已在第 3 阶段按 §13.1.1 完成，本阶段不得再次分类或改写该诊断；
7. 检查符合 EBNF 的 `funcall` 之目标、使用位置、实参、实参上下文字面量约束和接收类型；
8. 检查符合 EBNF 的 `return [operand]` 之位置、形式、操作数名称、返回类型和返回上下文字面量约束；返回操作数的名称类诊断在本阶段产生，不回到第 6 阶段；
9. 求值 `let` 常量；
10. 按 §4.3 执行 `if`/`while` 静态布尔三态判定，并按 §7.2.2 判定逻辑 RHS 读边；
11. 构建唯一顶层 CFG，再分别构建各函数 CFG；按 §11.2.1 从每个域的唯一入口计算可达节点，报告不可达语句，然后仅在可达子图上执行确定初始化固定点；仅函数 CFG 执行函数末尾检查；
12. 检查函数调用图中的递归环；
13. 生成 VM / AOT 代码。

第 6 阶段建立后续检查所需的作用域和名称环境，但 `funcall` 内部名称与 `return` 操作数必须按第 7、8 阶段的专用优先级协调解析：未定义调用目标会抑制该调用的实参名称错误；调用位置错误会抑制实参错误；返回形式错误会先于返回操作数名称错误。下列专用规则覆盖通用阶段内的源位置顺序。

权威 EBNF 不接受的形式必须在第 3 阶段拒绝，不得为产生后续专用诊断而放宽语法。阶段按顺序完整执行，前一阶段有错时不进入后一阶段。

##### 13.1.1 首个诊断的通用规则

一个程序同时存在多个错误时，唯一首个诊断按以下顺序确定：

1. **阶段优先**：先报告编号较小阶段的错误。
2. **源位置优先**：一个 TC 编译单元恰好对应一个源文件；同一阶段按行、列选择起始位置最早者。批量编译多个文件属于驱动层行为，各文件分别产生语言诊断，文件间次序不属于 TC 语言语义。
3. **规则优先**：同一位置按本节专用优先级；未专门规定时依次为语法形态/数量、语句上下文、名称存在性、重复、名称空间/作用域/控制流域、使用位置、实参顺序、类型、模式/结构、字面量、CFG、调用图。
4. **关联位置**：重复定义、跨域跳转和递归环使用下文指定的主位置比较；其他位置只作附注。
5. **遍历无关**：函数表、哈希表、CFG、调用图和实参集合的内部遍历顺序不得改变结果。

`TC_ERR_LITERAL_OUT_OF_RANGE` 的阶段由失败所需的信息唯一决定：只依赖字面量 Token 自身的整数绝对值上限或浮点源类型舍入检查属于第 2 阶段；只有结合普通 RHS / `let` / I/O 的期望类型才能确定的范围错误属于第 6 阶段；结合 `funcall` 形参或函数返回类型才能确定的范围错误分别属于第 7、8 阶段。第 2 阶段已经失败的字面量不得延迟到上下文阶段，因此阶段优先规则对所有实现唯一。

源位置使用 1 基行号与 1 基列号。对有效 UTF-8，列号按解码后的 Unicode 标量值计数，每个 ASCII 空格计一个标量；换行序列不属于下一行的列。对非法 UTF-8，行列按首个非法字节之前的最长有效前缀计算，首个非法字节占据下一列，并以 0 基源字节偏移作为附加位置；主错误码仍为 `TC_ERR_SYNTAX`。语言诊断文本可以本地化，但错误码、主位置和本节规定的关联位置必须稳定；表中明确固定文本的实现资源错误除外。

用于诊断定位的虚拟 Token 位置固定如下：`NEWLINE` 位于该逻辑行行结束序列之前、最后一个源 Unicode 标量值之后一列；若行结束序列前不含任何源标量值，则位于第 1 列。空文件的 `EOF` 位于第 1 行第 1 列；非空文件以行结束序列结束时，`EOF` 位于下一逻辑行第 1 列；否则位于最后一行最后一个源标量值之后一列。词法层为文件末尾补入的 `NEWLINE` 不改变上述 `EOF` 源位置。

除 §13.1.2～§13.1.7 或其他规范性条款已经给出更专用的定位规则外，普通静态语义诊断的**主位置**按下列规则固定：

- 运算本身不支持显式类型参数所指类别时，定位到该类型参数 Token；若显式类型参数类别合法，而某个标识符或操作数与其期望类型不一致，则定位到源位置最早的不匹配操作数。`TC_ERR_COMPARISON_TYPE_MISMATCH` 使用同一操作数定位规则。
- RHS 自身合法、但其结果类型与接收变量、常量或赋值目标的声明类型不一致，且没有更专用的调用/返回诊断时，定位到 RHS 的第一个 Token。
- `TC_ERR_MODE_MISMATCH` 定位到候选模式关键字；`TC_ERR_BITCAST_WIDTH` 定位到源操作数的第一个 Token。
- `TC_ERR_LITERAL_TYPE` 与 `TC_ERR_LITERAL_OUT_OF_RANGE` 定位到完整字面量的第一个 Token；前导 `-` 属于该字面量时，定位到 `-`。
- `TC_ERR_CONDITION_TYPE` 定位到 `if` / `while` 条件 RHS 的第一个 Token。
- `TC_ERR_FORMAT_TYPE_MISMATCH` 定位到格式说明符中的转换符字符。格式说明符是单个 Token，但主列号仍精确指向该 Token 内对应的 Unicode 标量位置。
- `write` / `writeln` 的标识符操作数与显式 `type` 不一致，或 `read` 目标 `var` 的声明类型与显式 `type` 不一致时，使用 `TC_ERR_TYPE_MISMATCH` 并定位到操作数或目标标识符。格式化输出只在该检查成功后才检查转换符兼容性（§12.1）。

词法、缩进、语法及格式控制专用诊断的主位置按下表固定：

| 错误码 | 主位置 |
| -------- | ---------- |
| `TC_ERR_SYNTAX` | 非法源字符或非法 Token 定位到其首字节/首标量或首 Token；对无专用错误码的语法失配，定位到使当前 Token 前缀无法继续匹配任一可行产生式的首个 Token；缺少必需 Token 时定位到应插入位置的当前 `NEWLINE` / `EOF` 或后继 Token。`TC_ERR_MISSING_END` 优先使用下表的专用规则。 |
| `TC_ERR_KEYWORD` | 误占标识符位置的保留关键字 Token。 |
| `TC_ERR_VAR_MISSING_INIT` | 该 `var` 声明的标识符。 |
| `TC_ERR_OPERAND_COUNT` | 平衡固定元数调用外壳的内建关键字。 |
| `TC_ERR_INDENT_MIXED` | 行首缩进中首个 U+0020 空格。 |
| `TC_ERR_INDENT_INSUFFICIENT` | 缩进层级或缩进栈转移首次非法的逻辑行第一个 Token。 |
| `TC_ERR_INDENT_ELSE_END` | 未与对应块头对齐的 `else` 或 `end` 关键字。 |
| `TC_ERR_MISSING_END` | 先按 EBNF 的嵌套结构以现有 `end` 从内向外完成唯一配对，再把每个仍未配对块的 `func` / `if` / `while` 开启关键字作为候选主位置；有多个候选时按源位置最早者。 |
| `TC_ERR_ELSE_POSITION` | 无对应 `if` 的 `else` 关键字。 |
| `TC_ERR_FORMAT_SPECIFIER` | 重复标志定位到第二个及后续重复字符中的最早者；宽度/精度超范围定位到对应数字字段首字符；标志或精度不适用于转换符时，定位到源序最早的不适用控制项（标志字符或 `.`）。 |

对本节或其他规范性条款未另行给出主位置的语言诊断，统一使用以下兜底规则：绑定、名称解析、赋值/读取目标或操作数错误定位到对应标识符或操作数首 Token；重复定义定位到第二个及后续冲突定义中的最早名称，并把首个同名定义作为关联位置；整个语句或定义才能确定的错误定位到该构造的首 Token。常量求值的溢出、除零或无效操作定位到触发求值的运算/转换关键字；非法常量依赖、嵌套调用或负移位计数定位到最早违规操作数或内层调用关键字。运行时错误定位到当前实际执行指令的首 Token；`read` / 输出失败定位到对应 I/O 关键字。

函数参数名在整个函数内是受保护绑定。函数签名检查已成功后，任意层级的 `var` / `let` 声明若与当前函数形参同名，在第 6 阶段报告 `TC_ERR_DUPLICATE_DEFINITION`：主位置为该内层声明的标识符，关联位置为对应形参的声明标识符；存在多个此类冲突时按主位置源序选择最早者。该规则是参数保护的专用扩展，不禁止内层块按 §11.1 屏蔽普通外层局部绑定。

全局函数名在整个编译单元中受保护。与顶层值作用域直接 `var` / `let` 或任一形参同名的冲突在第 5 阶段报告 `TC_ERR_FUNCTION_NAME_CONFLICT`；与顶层嵌套块或函数体任意层级 `var` / `let` 同名的冲突在第 6 阶段报告同一错误。主位置恒为冲突的值绑定名，关联位置为对应全局函数定义名；多个冲突按阶段优先、再按主位置源序选择。该规则覆盖普通内外层值屏蔽规则。

附录 A 首先决定 Token 序列能否进入静态语义。若不符合产生式，第 3 阶段按已明确规定的语法专用诊断分类：缺少变量初始化器使用 `TC_ERR_VAR_MISSING_INIT`，符合下述固定元数外壳的操作数数量错误使用 `TC_ERR_OPERAND_COUNT`，保留关键字误占标识符位置使用 `TC_ERR_KEYWORD`，缩进/块形态使用对应专用码；没有专用语法诊断的其他形态使用 `TC_ERR_SYNTAX`。格式说明符按 §12.5 单独分流：无法完整匹配附录 A `format_specifier` 产生式时在第 3 阶段使用 `TC_ERR_SYNTAX`；完整匹配该产生式后，重复标志、宽度或精度超出范围，以及转换符不适用的标志/精度在第 6 阶段使用 `TC_ERR_FORMAT_SPECIFIER`。这些专用映射不得使不符合 EBNF 的程序进入类型或模式检查。

`TC_ERR_OPERAND_COUNT` 的适用范围是完整且权威的：仅当逻辑行中已识别出“内建关键字 `(` 顶层逗号分隔项 `)`”的平衡调用外壳，但其**值操作数**数量不符合下表时使用该错误码。类型参数、位于类型参数之后候选模式位置的 `wrap` / `ieee` / `truncate` 关键字，以及 `write` / `writeln` 的格式说明符均不计入值操作数。语法形态/数量的诊断优先级高于类型和模式组合：因此只要外壳平衡且顶层字段可分隔，先按上述方式计数值操作数；数量正确后，才由 EBNF 和 §5.1 判定类型参数或候选模式在当前操作中是否合法。

本识别是第 3 阶段在正常 EBNF 匹配失败后的**受限语法诊断恢复**：固定元数产生式本身已经规定合法数量；本规则只把其中“平衡外壳且仅值操作数数量不符”的非法 Token 序列映射为专用错误码。该序列仍未通过附录 A，不得进入第 6 阶段的名称、类型或模式分析，也不得在第 6 阶段重新分类为其他错误。

| 固定元数外壳 | 期望的值操作数 | 说明 |
| ---------------- | ------------------ | ---- |
| `add` / `sub` / `mul` / `div` / `mod` | 2 | 普通 RHS 与 `let` 常量 RHS 均适用 |
| `and` / `or` / `xor` | 2 | 整数按位与 `bool` 逻辑重载均适用 |
| `shl` / `shr` | 2 | 模式位置的合法性仍由 EBNF 与 §5.1 判定 |
| `eq` / `ne` / `lt` / `le` / `gt` / `ge` | 2 | 整数与浮点比较均适用 |
| `abs` / `neg` / `not` | 1 | `not` 的整数按位与 `bool` 逻辑重载均适用 |
| 严格 `cast` / `cast(..., truncate, ...)` / `bitcast` | 1 | 目标类型与 `truncate` 不计为值操作数 |
| `write` / `writeln` | 1 | 有格式和无格式形式均恰好输出一个值 |
| `read` | 1 | 唯一的目标标识符按一个操作数计 |

缺少右括号、顶层逗号结构破损或无法识别内建调用外壳时，使用 `TC_ERR_SYNTAX` 而非 `TC_ERR_OPERAND_COUNT`。嵌套调用也不属于操作数数量错误：`let` RHS 中的嵌套调用按本节后文报 `TC_ERR_CONSTANT_EXPRESSION`，其他不允许嵌套的位置报 `TC_ERR_SYNTAX`。`funcall` 的项是命名实参，不纳入本错误码；其缺失、重复、未知与顺序错误分别使用 §13.1.3 的专用诊断。`return`、`if` / `while`、变量/常量定义与其他语句形态也不属于内建固定元数调用外壳，沿用各自的语法或专用诊断。

只有完整 Token 序列符合附录 A 某一产生式时，才进入普通类型/模式诊断。语法已接受的同一位置同时违反多项静态语义时，固定按“运算支持的类型类别 → 模式合法性 → `bitcast` 位宽 → 字面量范围/类型 → 格式符与其他操作数类型”选择。`wrap` / `ieee` / `truncate` 仅在对应产生式明确提供的位置才是候选模式；若相关操作或上下文的产生式没有该参数位置，或类型参数已被专用非终结符排除，且没有上述语法专用诊断，统一在第 3 阶段报告 `TC_ERR_SYNTAX`。例如普通 RHS 的 `shr(int32, wrap, x, k)` 是语法错误，而 `const_shift_expr` 已接受的同形 `let` RHS 随后报告 `TC_ERR_MODE_MISMATCH`。

`let` 的类型闭合检查属于第 6 阶段，并在第 9 阶段常量求值之前完成。直接字面量以声明类型作为期望类型，按 §3.6 报 `TC_ERR_LITERAL_TYPE` 或 `TC_ERR_LITERAL_OUT_OF_RANGE`；标识符或合法单层调用的结果类型与声明类型不同时，报 `TC_ERR_TYPE_MISMATCH` 并定位到 RHS 首 Token。单层调用必须先完成其内部类型、模式、位宽、字面量和操作数检查，再比较调用结果与 `let` 声明类型；外层类型不向调用操作数传播。

非法 UTF-8、文件起始 BOM、U+0000，以及注释外违反 §2.1 的非法源字符均映射为 `TC_ERR_SYNTAX`；缩进和语法阶段有专用错误码时优先专用码。此处的专用语法码只改变错误分类，不改变附录 A 接受的程序集合。`let` RHS 嵌套调用在语法阶段映射为 `TC_ERR_CONSTANT_EXPRESSION`；自引用和前向引用在名称阶段映射为 `TC_ERR_UNDEFINED_VARIABLE`；解析为 `var` 或函数参数的引用在完成第 6 阶段类型闭合检查后，于常量求值阶段映射为 `TC_ERR_CONSTANT_EXPRESSION`。静态布尔判定仅在名称、类型及更早 `let` 求值成功后运行；合法常量形态的求值错误不得降级为 `unknown`。不可达代码仍完成词法、语法、名称和类型检查。

##### 13.1.2 函数签名错误优先级

第 5 阶段的候选错误包括函数重名、签名内名称冲突，以及全局函数名与顶层值作用域直接值绑定的冲突。多个候选先按本节规定的主位置选择源序最早者；同一主位置再按以下顺序：函数重复定义 → 函数名与顶层值作用域直接值绑定冲突 → 参数重名 → 参数名与全局函数名冲突。顶层嵌套块和函数体 `var` / `let` 的同名冲突在第 6 阶段按 §13.1.1 处理。

- 重复函数定位到第二次及后续定义的函数名。
- 函数名冲突定位到冲突的值绑定名，并把全局函数定义名作为关联位置。
- 参数重名定位到第二次及后续出现的参数名。
- 参数名冲突定位到冲突参数名。

参数和返回类型的语法接受集已由附录 A 的 `value_type` / `return_type` 穷尽规定；不符合该产生式的类型 Token 在第 3 阶段报告 `TC_ERR_SYNTAX`，不得进入第 5 阶段，也不存在“参数类型非法”或“返回类型非法”的第 5 阶段候选。

收集全部函数名是本阶段的前提，但诊断不得取决于函数表遍历顺序。

##### 13.1.3 `funcall` 错误优先级

多个调用有错时选择 `funcall` 位置最早的调用。选定调用后依次检查：

1. 目标函数是否存在；不存在时定位到函数名，不再检查实参。
2. 调用位置是否适合返回类型；非 `void` 独立调用、`void` 用于 `var` 初始化、`void` 用于已有变量赋值均定位到 `funcall`，不再检查实参。
3. 实参重复、未知、缺失、顺序、类型，按此顺序检查。
4. 非 `void` 调用接收变量的声明类型：`var` 声明为声明类型 Token，已有变量赋值为赋值目标标识符。在实参全部合法后检查，错误定位到声明类型 Token 或目标标识符。

实参重复定位到第二个重复名称；未知实参定位到最早未知名称；缺失实参定位到右括号并指出声明顺序最靠前的缺失形参；顺序错误定位到第一个名称已知、集合完整但与对应位置形参不同的名称；类型错误定位到最早不匹配操作数。

只有实参名称全部已知、唯一且集合完整时才检查顺序；只有顺序正确后才从左到右检查类型。单个实参先检查名称，再检查类型类别，最后按 §3.6 检查字面量符号性、后缀和范围。合法字面量不能用于形参类型时沿用字面量专用诊断，不降级为笼统实参类型错误。

##### 13.1.4 `return` 错误优先级

多个 `return` 有错时选择关键字位置最早者；同一条依次检查：是否在函数体内 → 有值/无值形式是否匹配 → 返回名称是否合法 → 返回类型是否匹配 → 返回字面量是否合法且可表示。

顶层返回和形式错误定位到 `return`；返回类型错误定位到操作数；未定义或越过函数边界的返回操作数分别使用名称类错误码，但统一在第 8 阶段按本小节顺序报告；字面量问题同样在第 8 阶段检查并沿用字面量专用诊断。

##### 13.1.5 `goto` / `label` 上下文错误优先级

`goto` 与 `label` 必须先检查是否具有 `func` 词法祖先。没有函数祖先时分别报告 `TC_ERR_GOTO_OUTSIDE_FUNCTION` 或 `TC_ERR_LABEL_OUTSIDE_FUNCTION`，定位到关键字；该语句不参与标签表、名称解析或 CFG 构建。

只有确认位于函数体内后，才检查是否具有 `while` 词法祖先；违反时分别报告 `TC_ERR_GOTO_INSIDE_LOOP` 或 `TC_ERR_LABEL_INSIDE_LOOP`。因此，位于顶层 `while` 内的 `goto` / `label` 固定报告“函数外使用”，而不是“循环内使用”。函数内合法上下文中的 `label` 才进入当前函数标签表，函数内合法上下文中的 `goto` 才继续执行标签查找、跨函数判定和块关系检查。

标签查找必须按 §9.3.3 从 `goto` 所在块沿祖先链由内向外进行，最近同名标签胜出。若可见链查找失败且当前函数存在多个不可见同名候选，诊断类别固定按“后代块 `TC_ERR_JUMP_INTO_BLOCK` 优先于不可比块 `TC_ERR_JUMP_TO_SIBLING_BLOCK`”选择；同类别内以源位置最早的标签作为关联位置。不得使用标签表或哈希表的自然遍历顺序选择目标或诊断。

编译器必须先收集全部函数中通过上述上下文检查的标签，再解析任何函数内 `goto`；跨函数诊断不得依赖函数定义顺序、标签表遍历顺序或当前正在分析的函数。

本小节中的全部 `goto` / `label` 上下文、名称、控制流域和块关系错误均属于 §13.1 第 6 阶段。只有完成标签绑定并通过全部上述检查的 `goto` 才能在第 11 阶段进入当前函数 CFG；CFG 阶段不再产生 `goto` / `label` 合法性诊断。

##### 13.1.6 CFG 错误优先级

顶层和全部函数 CFG 构建完成后，CFG 类错误按源位置统一选择，不依赖内部分析顺序。同一位置依次为：`break` / `continue` 位置 → 按 §11.2.1 从控制流域入口不可达的语句 → 确定初始化 → 缺少返回。存在多个不可达语句时，选择源位置最早者，不依赖 CFG 节点遍历顺序。所有 `goto` / `label` 合法性诊断已在第 6 阶段按 §13.1.5 完成；非法跳转不进入 CFG，也不参与本阶段的错误选择。

缺少返回定位到函数定义头的返回类型，但与其他 CFG 错误比较源位置时使用该函数体 `end` 的位置；函数内有明确位置的 CFG 错误因此优先。多个函数都缺少返回时选择定义最早者。

##### 13.1.7 递归错误的确定规则

调用图环检查只在更早阶段全部成功后执行。存在多个递归强连通分量时，选择包含源位置最早函数定义的分量，再选择该分量内源位置最早、且目标仍在该分量内的调用点；将其调用边固定为首边 `e0 = (u, v)`，并在该调用点的函数名处报告递归错误。

诊断必须给出一个有限、确定的简单环路径。若 `u == v`，环路径只含自递归首边 `e0`。否则，在所选强连通分量内，从 `v` 到 `u` 的全部**不重复函数顶点的简单路径**中，先选择调用边数量最少者；仍有并列时，将各路径上的调用点源位置序列按 `(行, 列)` 做字典序比较，选择最小者。最终环路径为首边 `e0` 加该返回路径，除闭合起点外不得重复函数顶点。有限调用图中该算法必定终止，且不得由哈希表、图节点或邻接表的自然遍历顺序改变结果。

初始化相关错误按下表严格分工：

| 层次 | 违规形态 | 错误码 | 检查性质 | 规范依据 |
| ---- | -------- | ------ | -------- | -------- |
| **语法层** | `var` 声明缺少 `= <rhs>` | `TC_ERR_VAR_MISSING_INIT` | 纯形态；与控制流无关 | §4.2 |
| **名称层** | 标识符从未声明、尚未源序可见或已超出词法作用域 | `TC_ERR_UNDEFINED_VARIABLE` | 名称解析 | §11.1 |
| **数据流层** | 声明存在，但在可达使用点不满足确定初始化 | `TC_ERR_UNINITIALIZED_VARIABLE` | 完整 CFG 固定点分析 | §11.2、§9.3.4 |

`TC_ERR_VAR_MISSING_INIT` 不得降级为通用语法错误；`TC_ERR_UNINITIALIZED_VARIABLE` 不得替代名称解析错误。0.0.33 不定义 `TC_ERR_GOTO_SKIPS_VAR_INIT`，因为未初始化是跨全部控制流种类的通用性质，不应绑定到单一语句。

#### 13.2 静态错误

静态错误覆盖词法/语法、名称与作用域、类型/字面量/模式、常量求值、缩进与控制流、函数调用与返回、CFG 确定初始化及调用图。具体触发条件、标准错误码、打印名和阶段以 §13.5 为准，多个错误的选择顺序以 §13.1 为准。

0.0.33 不定义 `TC_ERR_GOTO_SKIPS_VAR_INIT`、常量循环依赖专用错误、跨块引用专用错误或重复的 overflow-mode 错误：它们分别由确定初始化、源序可见性/名称解析，以及“EBNF 先行、模式语义随后”的统一规则处理。

#### 13.3 运行时错误

| 错误类型         | 触发条件                                                     |
| ---------------- | ------------------------------------------------------------ |
| 除零错误         | 整数 `div`/`mod` 除数为 0；严格浮点 `div` 的有限非零被除数除以零，或严格浮点 `mod` 的有限非零被除数对零取模 |
| 整数溢出错误     | 有符号 `add`/`sub`/`mul`/`neg` 结果超范围；有符号 `div` 的数学商不可表示（即 `INT_MIN / -1`）；有符号 `abs(INT_MIN)`；任一整数类型的 strict `shl` 结果超范围 |
| 负移位计数错误 | `shl`/`shr` 的有符号移位计数按其类型解码后的数学值小于 0 |
| 浮点溢出错误     | 严格模式浮点运算上溢                                         |
| 浮点下溢错误     | 严格模式浮点运算下溢                                         |
| 浮点无效操作错误 | 严格 `add/sub/mul/div/mod` 的输入含 NaN 或产生无效结果（如 0/0、∞−∞、0×∞、∞ mod x）；`abs/neg` 除外 |
| 转换溢出错误     | 严格 `cast` 的数学结果无法在目标类型中表示，或浮点源为 NaN/无穷且目标为整数 |
| I/O 错误         | `read` 输入非法/超范围/EOF，标准输入读取失败，或 `write`/`writeln` 写入失败 |

对 `shl` / `shr` 运行时指令，必须先按类型 `T` 解码移位计数的数学值并检查是否为负；只有该检查通过后，才检查 `k >= n` 或 `shl` 结果溢出。因此同一条指令不得以 `TC_ERR_INTEGER_OVERFLOW` 代替 `TC_ERR_NEGATIVE_SHIFT_COUNT`。

**运行时错误提交规则**：每条 TC 指令在抽象机器中先读取全部实际需要读取的操作数并完成检查，再提交目标值。算术、移位、转换或函数调用发生运行时错误时，不提交当前指令的目标槽、调用返回值或新 `var` 的已初始化状态；`read` / 输出失败的外部 I/O 边界按 §12 单独规定。首个运行时错误立即终止整个程序，不执行清理代码、后续语句或调用者续点，也不回滚此前已成功完成的赋值与 I/O。

#### 13.4 编译警告

TC 无编译警告，也不以警告方式放行初始化、溢出、类型或控制流违规。`and`/`or` 短路裁剪只免除不可达右操作数的确定初始化读取检查，不免除其词法、语法、名称和类型检查；`xor` 不短路。

#### 13.5 标准错误码对照表

下列两表是 0.0.33-rev17-converged.4 完整、权威的标准错误码对照，共 65 项：64 个语言错误码（56 个静态、8 个运行时）和实现资源失败码 `TC_ERR_OUT_OF_MEMORY`。语言错误码、打印名与诊断类别一一对应，不得合并、别名化或以其他错误码代替；布尔 `xor` 与浮点 `mod` 复用既有错误码。

#### 14.1 类型、运算模式与转换

let PI: float64 = 3.141592653589793

#### 14.2 单层表达式与静态条件

复合计算必须拆为多条语句；`let` 也只允许单层调用。

```text
let BASE: int32 = 20
let LIMIT: int32 = mul(int32, BASE, 5) ; 100
let READY: bool = ge(int32, LIMIT, 100)

var a: int32 = 3
var b: int32 = 4
var sum: int32 = add(int32, a, b)
var result: int32 = mul(int32, sum, 5) ; 35

if READY then                          ; 静态 true，仅保留真边
	writeln(int32, %d, result)
end
```

#### 14.3 结构化控制流

```text
var total: int32 = 0
var i: int32 = 0

while lt(int32, i, 10) then
	i = add(int32, i, 1)
	var even: int32 = mod(int32, i, 2)
	if eq(int32, even, 0) then
		continue                      ; 回到条件求值
	end
	total = add(int32, total, i)
	if gt(int32, total, 20) then
		break                         ; 退出最内层 while
	end
end

writeln(int32, %d, total)
```

#### 14.4 函数与非结构化控制流

`goto`/`label` 只允许位于函数内，且不得位于 `while` 内；标签不增加缩进。

```text
func sum_to(limit: int32) int32 then
	var total: int32 = 0
	var i: int32 = 1
	label loop:
	if gt(int32, i, limit) then
		goto done
	end
	total = add(int32, total, i)
	i = add(int32, i, 1)
	goto loop
	label done:
	return total
end

func show(value: int32) void then
	writeln(int32, %d, value)
	return
end

var total: int32 = funcall(sum_to, limit: 10)
funcall(show, value: total)
```

以下边界分别由专用诊断拒绝：

```text
; label top:                    ; TC_ERR_LABEL_OUTSIDE_FUNCTION
; goto top                      ; TC_ERR_GOTO_OUTSIDE_FUNCTION

; func invalid() void then
;     goto use
;     var x: int32 = 1
;     label use:
;     writeln(int32, %d, x)     ; TC_ERR_UNINITIALIZED_VARIABLE
;     return
; end
```

#### 14.5 浮点 I/O 与位模式

```text
var radius: float64 = 0.0
read(float64, radius)                   ; read 只覆盖已初始化变量

let PI: float64 = 3.141592653589793
var radius_sq: float64 = mul(float64, radius, radius)
var area: float64 = mul(float64, PI, radius_sq)
writeln(float64, %g, area)              ; 6 位有效数字

```

### 附录 A：形式化语法（EBNF）

本附录为 TC 语言的 **权威语法定义**。语义规则以正文为准。

#### A.1 符号约定

采用 **扩展巴科斯-瑙尔范式（EBNF）**：

| 元符号   | 含义              |
| -------- | ----------------- |
| `=`      | 产生式定义        |
| `\|`     | 择一              |
| `[ … ]`  | 可选（0 或 1 次） |
| `{ … }`  | 重复（0 或多次）  |
| `( … )`  | 分组              |
| `"…"`    | 终结符            |
| `"a" … "z"` | 包含两端的字符范围 |
| `? … ?`  | 用自然语言描述的词法特殊序列 |
| *斜体名* | 非终结符          |

#### A.2 词法与缩进 Token

词法分析的输入必须先通过 §2.1 的 UTF-8、BOM、U+0000 与源字符合法性检查。注释外的非 ASCII 字符不能被规范化、转写或当作空白，而必须报 `TC_ERR_SYNTAX`。

字符检查成功后，词法分析按最长匹配生成 Token，再将完整标识符与关键字表比较。`varx` 因而是一个 `IDENTIFIER`，绝不能拆成 `VAR` + `IDENTIFIER`。除行首缩进外，Token 间的 ASCII 空格和制表符由词法层丢弃；语法层不使用可匹配零字符的 `ws` 充当关键字边界。

**缩进 Token 化规则**：

1. 词法器维护“行首连续空格组数量”构成的缩进级别栈，初始仅含顶层级别 `0`。
2. 每个非空、非纯注释逻辑行开始时，先检查第一个 Token 之前的字符：它们只能是 U+0020；行首出现 U+0009 均报 `TC_ERR_INDENT_MIXED`。统计行首连续空格数量，必须能被 4 整除，否则为缩进错误。然后将空格组数量（空格数 / 4）与栈顶比较：增加时必须恰好增加 `1`，压栈并生成一个 `INDENT`；一次增加多组为缩进错误。减少时逐项出栈并为每次出栈生成一个 `DEDENT`。减少后的空格组数量必须等于某个既有栈值，否则为缩进错误。
3. 一级缩进恒为 4 个连续 ASCII 空格 U+0020。
4. 空行和纯注释行只生成 `NEWLINE`，不改变缩进栈；它们的行首 ASCII 空格/制表符不参与缩进字符或层级检查。非 ASCII 空白仍按 §2.1 拒绝。
5. LF（`\n`）、CRLF（`\r\n`）或 CR（`\r`）均表示一个逻辑行结束，并生成一个 `NEWLINE`；文件结尾先补最后一个 `NEWLINE`（若缺少），再生成剩余 `DEDENT`，最后生成 `EOF`。
6. `INDENT`/`DEDENT` 只反映 `func`/`if`/`else`/`while` 语句体的实际缩进；合法的函数内 `label` 是普通语句，不改变缩进栈。
7. 非空、非纯注释行的行首缩进使用水平制表符 U+0009（单独使用或与空格混用）报 `TC_ERR_INDENT_MIXED`；`else`/`end` 与对应 `func`/`if`/`while` 块头不对齐报 `TC_ERR_INDENT_ELSE_END`；其他违反上述空格缩进层级/栈规则的情形报 `TC_ERR_INDENT_INSUFFICIENT`。

#### A.3 语法

本节作用于 A.2 输出的 Token 序列。`NEWLINE`、`INDENT`、`DEDENT`、`EOF` 是虚拟终结符；`identifier`、`integer_literal` 等名称引用 A.2 的完整 Token 类别。EBNF 中以 `"…"` 标记的关键字或标点表示一个完整 Token，不按子序列匹配。非行首空白与行末注释已由词法层移除。

本 EBNF 同时规定全部语法诊断边界。位置实参、非 `operand` 实参、作为 `let` 或赋值 RHS 的 `funcall`、`return` 后的运算/转换/`funcall`，以及 `void` 出现在函数返回类型以外的位置，均必须在语法阶段拒绝。各专用产生式中的类型非终结符和模式参数位置同样具有约束力：例如位运算/移位只接受 `int_type`，逻辑运算只接受 `bool_type`，比较只接受整数或浮点类型；运行时 `wrap_shift_expr` 只接受 `shl`，比较、逻辑和按位运算没有模式参数位置。不满足这些形态时统一报告 `TC_ERR_SYNTAX`，不得为产生 `TC_ERR_TYPE_MISMATCH` 或 `TC_ERR_MODE_MISMATCH` 而放宽语法。常量表达式由独立 `const_*` 产生式决定边界；其中 `const_shift_expr` 接受候选 `mode`，非法组合在后续静态语义阶段报告 `TC_ERR_MODE_MISMATCH`。`var_funcall_def`、独立 `funcall` 和 `return [operand]` 的返回类型适配属于后续静态语义。`statement` 产生式复用 `label_def` / `goto_stmt` 只表示其行内语法；二者必须具有 `func` 词法祖先的上下文约束由 §9.3 和 §13.1.5 在静态语义阶段强制执行。

`constant_def` 只规定 `let` 声明的语法外形；`const_rhs` 结果类型与声明 `type` 的闭合由 §4.3.1 在后续静态语义阶段强制，不改变 EBNF 的语法接受集。

```ebnf
/* ── 程序 ── */

program    = blank_lines , (
               "#program" , NEWLINE , blank_lines , import_region , program_module
             | "#lib" , NEWLINE , blank_lines , import_region , library_module
           ) , EOF ;

import_region
           = { import_declaration , NEWLINE , blank_lines } ;

import_declaration
           = "import" , identifier ;

program_module
           = top_level_program ;

library_module
           = static_region , function_region ;

static_region
           = { ( static_constant_def | static_variable_def ) ,
               NEWLINE , blank_lines } ;

static_constant_def
           = ( "public" | "private" ) ,
             "static" , constant_def ;

static_variable_def
           = ( "public" | "private" ) ,
             "static" , variable_def ;

blank_lines = { NEWLINE } ;

function_region
           = { function_definition , NEWLINE , blank_lines } ;

top_level_program
           = { statement , NEWLINE , blank_lines } ;
/* #program 模块消费顶层语句区。
   #lib 模块先消费 static 成员区，再消费函数定义区。
   #program 不得包含函数定义或 static var / static let 声明定义，
   static var / static let 只在 #lib 模块中出现。
   该分层不改变任何 Token 序列的接受结果。 */

statement  = simple_statement
           | if_stmt
           | while_stmt ;

simple_statement
           = variable_def
           | constant_def
           | assignment
           | funcall_assign_stmt
           | write_stmt
           | writeln_stmt
           | read_stmt
           | break_stmt
           | continue_stmt
           | label_def
           | goto_stmt
           | var_funcall_def
           | void_funcall_stmt
           | return_stmt ;
/* label_def / goto_stmt 出现在 top_level_program 或其嵌套 suite 中时，
   分别报 TC_ERR_LABEL_OUTSIDE_FUNCTION / TC_ERR_GOTO_OUTSIDE_FUNCTION。 */

/* ── 函数定义 ── */

function_definition
           = ( "public" | "private" ) ,
             "func" , identifier , "(" , [ parameter_list ] , ")" ,
             return_type , "then" , NEWLINE , suite , "end" ;

parameter_list
           = parameter , { "," , parameter } ;

parameter  = identifier , ":" , value_type ;

return_stmt
           = "return" , [ operand ] ;

/* function_definition 不是 statement，因此不能嵌套在函数体、
   if / else 或 while 内；本语法没有匿名代码块产生式。 */

/* ── 函数调用 ── */

funcall    = "funcall" , "(" , callable_name ,
             { "," , named_argument } , ")" ;

callable_name = identifier | qualified_identifier | imported_member_name ;

qualified_identifier = "Self" , "." , identifier ;

imported_member_name = identifier , "." , identifier ;

named_argument
           = identifier , ":" , operand ;

var_funcall_def
           = "var" , identifier , ":" , value_type , "=" , funcall ;

void_funcall_stmt
           = funcall ;

funcall_assign_stmt
           = ( identifier | qualified_identifier | imported_member_name ) ,
             "=" , funcall ;

/* 命名实参必须与形参一一对应，文本顺序完全一致；第 i 个形参的
   value_type 是第 i 个实参 operand 的唯一期望类型。
   var_funcall_def / funcall_assign_stmt / void_funcall_stmt 的合法性由实际返回类型筛选。 */

/* ── 变量定义（声明时必须初始化；无可选 RHS） ── */

variable_def = "var" , identifier , ":" , type , "=" , rhs ;

/* ── 常量定义 ── */

constant_def = "let" , identifier , ":" , type , "=" , const_rhs ;
/* const_rhs 结果类型必须与声明 type 完全一致；这是 §4.3.1
   的静态语义约束，不改变本产生式的语法接受集。 */

/* ── 赋值语句 ── */

assignment = ( identifier | qualified_identifier | imported_member_name ) ,
             "=" , rhs ;

/* ── if 语句（缩进敏感，end 必须） ── */

if_stmt    = "if" , rhs , "then" , NEWLINE , suite ,
             [ "else" , NEWLINE , suite ] ,
             "end" ;

/* ── while 语句（缩进敏感，end 必须） ── */

while_stmt = "while" , rhs , "then" , NEWLINE , suite ,
             "end" ;

/* ── break / continue 语句 ── */

break_stmt = "break" ;
continue_stmt = "continue" ;

suite      = { NEWLINE } , [ INDENT , block , DEDENT ] ;
block      = statement , NEWLINE ,
             { NEWLINE | statement , NEWLINE } ;
/* 每个函数体 suite、if 的 then/else suite 和 while 体 suite
   分别对应一个代码块；suite 不含 INDENT 时表示零条语句的
   空代码块。label_def 不开启新代码块，但在 CFG 中形成
   新基本块入口；缩进约束见 §9.1.2。 */

/* ── label 与 goto 语句 ── */

label_def  = "label" , identifier , ":" ;
/* 仅函数内合法；label 不产生新缩进；同级后续语句与 label 缩进一致，
   见 §9.1.2 R7、§9.3.2。goto 的目标是该零动作 label 节点；连续标签
   与块末尾标签均沿正常落入边取得唯一续点。 */
goto_stmt  = "goto" , identifier ;
/* 仅函数内合法，且目标标签必须属于当前函数。 */

/* ── 右值表达式 ── */

rhs        = identifier
           | integer_literal
           | float_literal
           | float_special
           | bool_literal
           | binary_arith_expr
           | unary_arith_expr
           | bitwise_expr
           | unary_bitwise_expr
           | shift_expr
           | compare_expr
           | binary_logic_expr
           | unary_logic_expr
           | cast_expr
           | bitcast_expr ;

/* ── 常量右值表达式 ── */

const_rhs  = integer_literal
           | float_literal
           | float_special
           | bool_literal
           | identifier
           | const_binary_arith_expr
           | const_unary_arith_expr
           | const_bitwise_expr
           | const_unary_bitwise_expr
           | const_shift_expr
           | const_compare_expr
           | const_binary_logic_expr
           | const_unary_logic_expr
           | const_cast_expr
           | const_bitcast_expr ;

/* ── 常量表达式（只允许单层调用） ── */

const_binary_arith_expr
           = binary_arith_op , "(" , type , "," ,
             [ mode , "," ] , const_operand , "," , const_operand , ")" ;

const_unary_arith_expr
           = unary_arith_op , "(" , type , "," ,
             [ mode , "," ] , const_operand , ")" ;

/* ── 常量位运算表达式 ── */

const_bitwise_expr
           = bitwise_op , "(" , int_type , "," ,
             const_operand , "," , const_operand , ")" ;

const_unary_bitwise_expr
           = "not" , "(" , int_type , "," , const_operand , ")" ;

const_shift_expr
           = shift_op , "(" , int_type , "," ,
             [ mode , "," ] , const_operand , "," , const_operand , ")" ;

/* ── 常量比较表达式 ── */

const_compare_expr
           = compare_op , "(" , ( int_type | float_type ) , "," ,
             const_operand , "," , const_operand , ")" ;

/* ── 常量逻辑表达式 ── */

const_binary_logic_expr
           = binary_logic_op , "(" , bool_type , "," ,
             const_operand , "," , const_operand , ")" ;

const_unary_logic_expr
           = "not" , "(" , bool_type , "," , const_operand , ")" ;

/* ── 常量转换表达式 ── */

const_cast_expr
           = "cast" , "(" , type , "," , const_operand , ")"
           | "cast" , "(" , int_type , "," , "truncate" , "," ,
             const_operand , ")" ;

const_bitcast_expr
           = "bitcast" , "(" , type , "," , const_operand , ")" ;

/* ── 常量操作数 ── */

const_operand
           = integer_literal
           | float_literal
           | float_special
           | bool_literal
           | identifier
           | qualified_identifier
           | imported_member_name ;

/* ── 操作数 ── */

operand    = identifier | qualified_identifier | integer_literal | float_literal
           | float_special | bool_literal | imported_member_name ;

/* ── 双目算术表达式 ── */

binary_arith_expr
           = strict_binary_arith_expr
           | mode_binary_arith_expr ;

strict_binary_arith_expr
           = binary_arith_op , "(" , type , "," ,
             operand , "," , operand , ")" ;

mode_binary_arith_expr
           = binary_arith_op , "(" , type , "," , mode , "," ,
             operand , "," , operand , ")" ;

/* ── 单目算术表达式 ── */

unary_arith_expr
           = strict_unary_arith_expr
           | mode_unary_arith_expr ;

strict_unary_arith_expr
           = unary_arith_op , "(" , type , "," , operand , ")" ;

mode_unary_arith_expr
           = unary_arith_op , "(" , type , "," , mode , "," ,
             operand , ")" ;

/* ── 按位逻辑表达式（仅整数） ── */

bitwise_expr
           = bitwise_op , "(" , int_type , "," ,
             operand , "," , operand , ")" ;

unary_bitwise_expr
           = "not" , "(" , int_type , "," , operand , ")" ;

/* ── 移位表达式（仅整数） ── */

shift_expr
           = strict_shift_expr
           | wrap_shift_expr ;

strict_shift_expr
           = shift_op , "(" , int_type , "," ,
             operand , "," , operand , ")" ;

wrap_shift_expr
           = "shl" , "(" , int_type , "," , "wrap" , "," ,
             operand , "," , operand , ")" ;

/* ── 比较表达式（不支持 ieee 模式） ── */

compare_expr
           = compare_op , "(" , ( int_type | float_type ) , "," ,
             operand , "," , operand , ")" ;

/* ── 双目逻辑表达式（布尔） ── */

binary_logic_expr
           = binary_logic_op , "(" , bool_type , "," ,
             operand , "," , operand , ")" ;

binary_logic_op = "and" | "or" | "xor" ;

/* ── 单目逻辑表达式（布尔） ── */

unary_logic_expr
           = "not" , "(" , bool_type , "," , operand , ")" ;

/* ── 类型转换表达式 ── */

cast_expr  = strict_cast_expr | truncate_cast_expr ;

strict_cast_expr
           = "cast" , "(" , type , "," , operand , ")" ;

truncate_cast_expr
           = "cast" , "(" , int_type , "," , "truncate" , "," ,
             operand , ")" ;

bitcast_expr
           = "bitcast" , "(" , type , "," , operand , ")" ;

/* 所有运算类型/模式组合均受 §5.1 权威矩阵约束。
   truncate 仅允许整数窄化；bitcast 要求等位宽且两端非 bool（§8）。 */

/* ── I/O 语句 ── */

write_stmt = "write" , "(" , type , "," , operand , ")"
           | "write" , "(" , type , "," , format_specifier , "," ,
             operand , ")" ;

writeln_stmt = "writeln" , "(" , type , "," , operand , ")"
             | "writeln" , "(" , type , "," , format_specifier , "," ,
               operand , ")" ;

read_stmt  = "read" , "(" , type , "," ,
             ( identifier | qualified_identifier | imported_member_name ) , ")" ;
```

| 布尔        | `bool`    | `_Bool`                        |
| 无返回值    | `void`    | `void`（仅函数返回类型）       |

| ----------------- | ------------------------------------- | ---------------------------------------------- |
| 有符号字面量      | `42`                                  | `42`                                           |
| 无符号字面量      | `42u`                                 | `42u`                                          |
| 浮点字面量        | `3.14f` / `3.14`                      | `3.14f` / `3.14`                               |
| 加                | `add(int32, a, b)`                    | 先用无 UB 的范围预检或足够宽表示计算；成功后转为 `int32_t` |

| 整除 / 求余       | `div` / `mod`                         | 先检查零除数；`INT_MIN / -1` 对 `div` 报错、对 `mod` 直接返回 `0`，其余情形才可使用 `/` / `%` |
| 浮点取模          | `mod(float64, a, b)`                  | C99 无对应运算符；商向零截断的数学余数         |
| `div(INT_MIN,−1)` | `div` → **整数溢出错误**；`mod` → `0` | C99 为 **UB**                                  |
| 取绝对值          | `abs(int32, a)`                       | 先排除 `INT32_MIN`，再计算绝对值                |
| 按位与            | `and(int32, a, b)`                    | `a & b`                                        |
| 左移（严格）      | `shl(int32, a, b)`                    | 先检查负计数、`k >= n` 与数学结果范围；不得先执行 `a << b` |
| 左移（回绕）      | `shl(int32, wrap, a, b)`              | 先分支处理 `k >= n`，再对同宽无符号值移位并安全重解释 |
| 右移（有符号）    | `shr(int32, a, b)`                    | 先处理负计数和 `k >= n`，再以无符号位运算或 §6.2.2 数学式实现；不能依赖实现定义的 `a >> b` |
| 负移位计数         | `shl`/`shr` → `TC_ERR_NEGATIVE_SHIFT_COUNT` | C99 为 UB                                       |

| 逻辑与            | `and(bool, a, b)`                     | `a && b`                                       |
| 逻辑异或          | `xor(bool, a, b)`                     | `a != b`                                       |

| 转换                       | TC                              | C99                                         |
| -------------------------- | ------------------------------- | ------------------------------------------- |
| 严格数值转换（默认）   | `cast(int8, a)`                 | `(int8_t)a`（TC 在不可表示时报错）       |
| 整数窄化（`truncate`） | `cast(int8, truncate, a)`       | 取源整数低 8 位后按目标符号性解释        |
| 等宽位重解释（`bitcast`） | `bitcast(float32, bits)`        | 在宿主格式已验证兼容时以 `memcpy` 到等宽目标类型（避免别名 UB）；否则显式编解码抽象位串 |
| bool→int                   | `cast(int32, flag)`             | `flag ? 1 : 0`                              |
| int→bool                   | `cast(bool, x)`                 | `x != 0`                                    |

| I/O          | TC                              | C99 等价                  |
| ------------ | ------------------------------- | ------------------------- |
| 无格式输出   | `write(int32, x)`               | `printf("%d", x)`         |
| 有符号十进制 | `write(int32, %d, x)`           | `printf("%d", x)`         |
| 无符号十进制 | `write(uint32, %u, x)`          | `printf("%u", x)`         |
| 十六进制小写 | `write(uint32, %x, x)`          | `printf("%x", x)`         |
| 十六进制大写 | `write(uint32, %X, x)`          | `printf("%X", x)`         |
| 八进制       | `write(uint32, %o, x)`          | `printf("%o", x)`         |
| 浮点精度     | `write(float64, %.3f, x)`       | `printf("%.3f", x)`       |
| 宽度与零填充 | `write(float64, %08.3f, x)`     | `printf("%08.3f", x)`     |
| 左对齐       | `write(int32, %-8d, x)`         | `printf("%-8d", x)`       |
| 二进制       | `write(uint32, %#b, x)`         | 无标准等价（TC 扩展）     |
| 布尔输出     | `write(bool, %-8t, x)`          | 无标准等价（TC 扩展）     |

**主要差异**：
- TC 严格模式下有符号溢出报错（C99 为 UB）
- TC `div(INT_MIN, −1)` 报整数溢出错误（C99 为 UB）
- TC `cast` 对所有整数窄化和符号性变换做可表示性检查；C99 的对应转换可能为实现定义行为
- TC **声明时必须初始化**（`var … = …`；缺省 → `TC_ERR_VAR_MISSING_INIT`，§4.2）。此外，编译器必须在完整 CFG 上证明每次变量读取前都已执行其当前生命周期的初始化；否则报 `TC_ERR_UNINITIALIZED_VARIABLE`。`goto` 跳过但未读取某变量本身不构成错误。C99 读取未初始化对象可产生未定义行为
- TC 二进制 `%b` 和布尔 `%t` 为扩展格式；格式控制参考 C99，但不支持空格标志、动态 `*`、长度修饰符或多转换项格式文本
- TC 比较运算返回 `bool`（C99 中比较返回 `int`）
- TC 逻辑运算严格操作 `bool`（C99 中逻辑运算接受任意标量类型）
- TC 右移有符号固定算术右移，C99 为实现定义
- TC 的移位计数按其整数类型直接取数学值；负值报 `TC_ERR_NEGATIVE_SHIFT_COUNT`，不做掩码或无符号重解释

#### B.2 `let` 常量与 C99 `const` 语义对照

| 特性               | TC `let`     | C99 `const`  | 说明                    |
| ------------------ | ------------ | ------------ | ----------------------- |
| 编译期求值         | ✅ 必须       | ❌ 不要求     | TC `let` 保证编译期求值 |
| 运行时存储         | ❌ 不分配     | 通常分配     | TC 常量不生成运行时数据 |
| 地址可取值         | ❌ 不可取     | ✅ 可取       | TC 常量无运行时地址     |
| RHS 可为算术表达式 | ✅            | ✅            | TC 常量支持编译期算术   |
| 溢出检查           | ✅ 编译期报错 | ❌ UB         | TC 在编译期捕获常量溢出 |
| 优化器可推导       | ✅ 恒为常量   | ⚠️ 视实现而定 | TC 语义保证             |

#### B.3 0.0.33 函数与控制流边界

- 顶层语句区仍是程序入口，但只允许结构化控制流；顶层以及顶层嵌套块不得出现 `goto` 或 `label`。
- `goto` 与 `label` 只能出现在函数体内。每个函数独立建立标签表，跳转目标必须位于当前函数并满足 §9.3 的块关系规则。
- 顶层 CFG 不建立标签表或 `goto` 边；函数 CFG 独立处理其函数内标签、跳转、确定初始化和返回路径。
- 需要非结构化控制流的程序应把对应逻辑封装进函数，并由顶层通过 `funcall` 显式启动；TC 不引入特殊 `main` 或隐式函数调用。
- 函数内 `while` 继续禁止 `goto` / `label`，结构化循环与非结构化循环的范式隔离保持不变。

### 附录 C：各类型边界常量速查（C99 对照）

本附录严格以 ISO/IEC 9899:1999 及其 TC1～TC3 汇编文本的 C99 规则为准，主要对应 §7.18 `<stdint.h>`、§5.2.4.2.2 `<float.h>` 和 §7.16 `<stdbool.h>`。不使用 C11 及后续版本增加的宏、类型或语法。

#### C.1 精确宽度整数

C99 的 `intN_t` / `uintN_t` 是**可选**的精确宽度类型。仅当实现提供满足相应位宽、无填充位，且有符号类型采用二进制补码表示的整数类型时，才定义对应 typedef 及界限宏。下表中的直接对应关系因此均以“该 C99 实现实际定义相应名称”为前提：

| TC 类型 | C99 条件 typedef | C99 最小值宏 | C99 最大值宏 |
| ------- | --------------- | ------------ | ------------ |
| `int8` | `int8_t` | `INT8_MIN` | `INT8_MAX` |
| `uint8` | `uint8_t` | `0` | `UINT8_MAX` |
| `int16` | `int16_t` | `INT16_MIN` | `INT16_MAX` |
| `uint16` | `uint16_t` | `0` | `UINT16_MAX` |
| `int32` | `int32_t` | `INT32_MIN` | `INT32_MAX` |
| `uint32` | `uint32_t` | `0` | `UINT32_MAX` |
| `int64` | `int64_t` | `INT64_MIN` | `INT64_MAX` |
| `uint64` | `uint64_t` | `0` | `UINT64_MAX` |

- C99 源码应使用上述 `<stdint.h>` 界限宏表达边界，尤其不得用 `-9223372036854775808` 之类宿主整数字面量假定 `int64_t` 最小值的类型和求值过程。
- `int_leastN_t` / `uint_leastN_t` 只保证**至少** N 位，不能替代 TC 的精确位宽类型，否则回绕、移位、`bitcast` 和边界检查可能改变。
- 若宿主 C99 实现没有定义某个精确宽度 typedef，AOT 必须使用能保持 TC 规定值域和位模式的其他实现策略；不得把缺失的名称视为 TC 不支持对应类型。

#### C.2 浮点边界

C99 不要求 `float` 和 `double` 采用 IEEE 754 binary32 / binary64，也不保证存在非规格化数。`<float.h>` 中的 `FLT_MIN` / `DBL_MIN` 表示**最小正正规值**，不是最小正非零值；C99 没有 `FLT_TRUE_MIN`、`DBL_TRUE_MIN`、`FLT_HAS_SUBNORM` 或 `DBL_HAS_SUBNORM`。

| TC 类型 | TC 最大有限绝对值 | TC 最小正正规值 | TC 最小正非零值 | 匹配宿主格式时的 C99 宏 |
| ------- | ----------------- | -------------- | -------------- | ----------------------- |
| `float32` | `(2 − 2^-23) × 2^127` | `2^-126` | `2^-149` | `FLT_MAX`、`FLT_MIN`；C99 无最小正非零值宏 |
| `float64` | `(2 − 2^-52) × 2^1023` | `2^-1022` | `2^-1074` | `DBL_MAX`、`DBL_MIN`；C99 无最小正非零值宏 |

只有宿主 `<float.h>` 至少满足下列特征时，才能把 C99 `float` / `double` 分别作为 TC `float32` / `float64` 的候选存储类型：

| TC 类型 | 必要的 C99 `<float.h>` 特征 |
| ------- | --------------------------- |
| `float32` | `FLT_RADIX == 2`、`FLT_MANT_DIG == 24`、`FLT_MIN_EXP == -125`、`FLT_MAX_EXP == 128` |
| `float64` | `FLT_RADIX == 2`、`DBL_MANT_DIG == 53`、`DBL_MIN_EXP == -1021`、`DBL_MAX_EXP == 1024` |

这些特征只确认基本值域和精度，不能单独证明全部 TC 浮点语义。AOT 仍须确认非规格化数、NaN、无穷、roundTiesToEven 和位模式要求，并处理 C99 `FLT_EVAL_METHOD` 允许的额外中间精度；每条 TC 浮点指令结束时必须按目标 TC 类型舍入。

#### C.3 布尔值

C99 的对应类型为 `_Bool`；包含 `<stdbool.h>` 后，宏 `bool` 展开为 `_Bool`，`false` 和 `true` 分别展开为整数常量 `0` 和 `1`。该对应只保证逻辑值语义，不保证 C99 `_Bool` 与 TC `bool` 具有相同对象大小或可观察位模式。

| TC 值 | C99 表达 |
| ----- | -------- |
| `false` | `false`（或 `_Bool` 值 `0`） |
| `true` | `true`（或 `_Bool` 值 `1`） |
