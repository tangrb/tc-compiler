## 调研结论摘要

经过全面调研，代码库现状如下：

### 内存管理

**整体非常优秀。无明确内存泄漏。**

| 检查项 | 结果 |
|--------|------|
| `malloc`/`calloc`/`realloc` 分配次数 | 14 次，全部有配对 `free` |
| `strdup`/`strndup` 调用次数 | 11 次，全部在对应的 free 函数中释放 |
| `realloc` 安全模式 | 全用临时变量接收返回值，OOM 时不覆盖原指针 |
| `init`/`free` 配对的结构体 | TcTokenList, TcProgram, TcStmtBlock, TcWarningList, TcSymbolTable — 全部自洽 |
| OOM 回滚路径 | 19 个检查点，每条路径均释放之前已分配的资源 |
| ASan 支持 | 完整支持（`--asan` / `ASAN=1` / `build-asan`） |
| 连续分配链 | 已逐链验证 |

可改进方向：

- OOM 错误统一标记为 `TC_ERR_SYNTAX`，语义不当——应区分系统错误
- 缺少 Valgrind / UBSan 支持
- ASan CI 仅为手动，未集成到 GitHub Actions
- `tc_warning_list_add` 有 OOM 后数组槽位未初始化风险
- REPL OOM 路径 `last_init_stmt_index` 状态可能不一致
- `tc_rhs_free` / `tc_statement_free` 缺少防御性 NULL 检查

### 标准设计

**文档体系完整，合规审查 307/307 全通过。**

| 文档 | 行数 | 内容 |
|------|------|------|
| `docs/TC语言标准设计说明书.md` | 2595 | 语法/语义权威来源（v0.0.24） |
| `docs/TC-VM详细设计说明书.md` | 2270 | VM 架构、流水线、诊断、REPL |

| `docs/libtc设计说明书.md` | 550 | libtc 嵌入 API 设计、错误状态契约 |
| `docs/TC-VM命令行参考.md` | 412 | tc-vm / tc-aot CLI 选项 |
| `docs/设计实现合规审查报告.md` | 206 | 307 项逐节对照审查 |
| `docs/libtc-api.md` | 129 | libtc API 速查 |

可收敛方向：

- 无独立形式语法文件（EBNF/BNF 嵌在散文里）
- 无版本变更记录（changelog）
- 错误种类分散在多处，无单一注册表
- 缺少术语表（glossary）
- 部分章节引用 `tc-architecture/syntax.md` 等实际不存在的文件
- 中英文术语混杂，缺少统一格式

## Day 1 — Thu 7/9（~3.5h）内存安全加固：代码修复

> 代码修改集中一天完成，避免上下文切换。

### 1.1 修复 OOM 错误语义（0.5h）

- **现状**：所有 OOM 路径使用 `TC_ERR_SYNTAX`，但内存不足不是语法错误
- **任务**：
  1. 在 `tc_types.h` 的 `TcErrorKind` 枚举中新增 `TC_ERR_OUT_OF_MEMORY`
  2. 替换 `src/` 下全部 19 处 OOM 的 `TC_ERR_SYNTAX` → `TC_ERR_OUT_OF_MEMORY`
  3. 更新诊断消息从 `"out of memory"` → 统一消息
  4. 更新 `docs/TC语言标准设计说明书.md` 和 `docs/TC-VM详细设计说明书.md` 的错误表格
- **涉及文件**：`tc_types.h`、全线 `src/` .c 文件、2 份 docs
- **验证**：`rg "out of memory" src/` 归零，`make test` 通过

### 1.2 修复 `tc_warning_list_add` 的 OOM 后数组槽风险（0.5h）

- **现状**：`tc_warning.c:27-42` realloc 成功后 strdup 失败只 `return -1`，count 未增
- **任务**：调整为先 strdup 再 realloc，或 realloc 后 memset 清空新增槽位
- **涉及文件**：`tc_warning.c`

### 1.3 REPL OOM 路径加固（0.5h）

- **现状**：`tc_repl.c:125` realloc `last_init_stmt_index` 失败后 `old_cap` / `new_cap` 不一致
- **任务**：添加状态变量跟踪，统一临时变量模式
- **涉及文件**：`tc_repl.c`

### 1.4 `tc_rhs_free` / `tc_statement_free` 防御性检查（0.5h）

- **任务**：
  1. `tc_rhs_free` 中 `u.cast.source`、`u.const_ref.name` 加 `if (ptr)` 包装
  2. `tc_statement_free` 中所有 `name` 字段同样处理
  3. switch-default 分支加 `// unknown kind, skip` 注释
  4. `tc_operand_free` 同样防御
- **涉及文件**：`tc_parser.c`
