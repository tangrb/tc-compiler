# TC 语言标准设计说明书

> **版本**：0.0.42
> **作者**：唐荣兵（[yanhuang8923@qq.com](mailto:yanhuang8923@qq.com)）

本文档是 TC **语言**的规范性定义：词法与语法、静态语义、抽象机执行语义，以及由此决定的可观察行为。

---

## 1. 概述与设计原则

### 1.1 语言定位

TC 是面向教学、AI 自动化编程与人类阅读的指令式编程语言。执行模型为伪汇编风格的逐条执行：每条语句至多包含一个运算或转换调用，禁止表达式嵌套，从而使每一步计算均可独立、按源序推理。

| 定位 | 要点 |
| ---- | ---- |
| 教学友好 | 显式状态步进、强制缩进、零隐式转换与零未定义行为 |
| AI 友好 | 命名实参、声明时强制初始化、单层表达式、禁止递归、完备静态诊断 |
| 阅读友好 | 显式类型与运算函数化；不以人工编码效率为优先 |
| 安全计算 | 默认 strict；确定初始化；`cast` / `bitcast` 显式分类 |
| 可靠计算 | 实现无关的抽象机语义；浮点对齐 IEEE 754-2019；遵守 as-if |

#### 1.1.1 版本能力边界（0.0.42）

下表给出本版本的语言能力范围，细节以对应章节为准。语法接受集以附录 A 为准。

| 类别 | 范围 | 详见 |
| ---- | ---- | ---- |
| 类型 | 固定宽度整数 `int8`～`uint64`；平台字长整数 `isize` / `usize`；`float32` / `float64`；`bool`；`ptr<T>`（指针类型）；`memblock<T, N>`（带长度头部，`N` 为元素个数规划）；`struct`；`void` 仅作函数返回类型 | §3 |
| 运算 | 算术、按位、移位、布尔逻辑、比较；`cast` / `truncate` cast / `bitcast`；`memblock` 读写、区间拷贝与 `.count` 长度访问；`ptr_load` / `ptr_store` 指针读写；`ptr_address` 取地址；`ptr_add` / `ptr_sub` 指针算术；`ptr_size` 所指类型宽度查询；`ptr_lt` / `ptr_le` / `ptr_gt` / `ptr_ge` 指针序关系比较；`memcopy_unsafe` 原始内存块拷贝 | §6 |
| 模式 | 默认 strict；有符号整数算术与 `shl` 可按规则使用 `wrap`；浮点算术可按规则使用 `ieee` | §6.3 |
| 控制流 | 缩进敏感的 `if` / `while`（以 `end` 结束）；`break` / `continue`；函数内受限 `goto` / `label`（`while` 内禁止） | §7 |
| 函数 | `#lib` 中 `func`；命名且有序的 `funcall`；显式 `return`；按值只读形参；调用图无环 | §8 |
| 模块 | 每文件一模块；`#program` / `#lib`；`import` 与限定名访问公开成员 | §4 |
| I/O | `write` / `writeln` / `read`；仅标量类型；格式化输出 | §10 |
| 入口 | `#program` 顶层语句按源序执行；无特殊 `main` | §4.1 |

### 1.2 设计原则

设计取舍优先服务于阅读清晰性、AI 生成正确性，以及计算安全与可靠。原则与条款对应如下：

| 定位 | 原则 | 规范落点 |
| ---- | ---- | -------- |
| 教学友好 | 逐条执行；显式类型；类型参数首位；缩进强制；`let` / `var` 分离 | §5–§7 |
| AI 友好 | 声明时初始化；运算函数化；同类型运算；单层操作数；字面量后缀定型 | §3.6, §5–§6, §8 |
| 阅读友好 | 禁止隐式转换；`module.id` / `Self.id` 限定；显式跨边界数据流 | §4, §6.6, §8 |
| 安全计算 | 默认严格模式；确定初始化 | §6.3, §9.2 |
| 可靠计算 | 零未定义行为；实现间同规则；调用图无环 | §1.3, §8.6 |

### 1.3 规范约定与一致性判定

**规范性用语**：**必须 / 禁止 / 仅可 / 不得** 为一致性要求；**应当 / 建议** 为实现或风格建议；**可以** 为实现自由（不得改变可观察语义）。

**语法拒绝**：Token 序列不符合附录 A 语法产生式，在语法检查阶段报告专用诊断码（默认 `TC_CE_SYNTAX`；特定失配另有专用码）。本版本语法专用码白名单仅两项：缺块结构 `end` → `TC_CE_MISSING_END`；操作数个数与对应产生式不符 → `TC_CE_OPERAND_COUNT`。其余形态失配仍为 `TC_CE_SYNTAX`。语法拒绝的程序不得进入后续语义检查。

**静态语义拒绝**：附录 A 已接受但正文的静态规则不成立，在静态语义检查阶段报告对应错误码。附录 A 决定语法接受集，正文决定静态与执行语义；正文不重复给出产生式。

**资料性内容**：标为"设计说明"的段落不构成规范性条款。

**可观察行为**：包括是否通过静态检查、首个规范诊断及其错误码、按源序成功提交到 TC 抽象标准输出的字节、正常结束或首个运行时错误及错误码。槽位地址、帧布局、宿主字节序等宿主实现细节不是可观察行为。

**零未定义行为**：除实现资源失败和 §10.2 的 I/O 物理行为外，不存在实现自行选择的未定义行为。规范未给出的形态不合法。相同输入下所有符合一致性的实现必须得到相同抽象行为。

**实现定义行为**：以下场景的结果为实现定义（即同一实现的不同运行保持一致，但不同实现之间允许不同），不属于未定义行为：
- `ptr_add` / `ptr_sub` 产生越界指针后对其执行 `ptr_load` / `ptr_store` 的结果（§3.10.8、§6.8.5）。

实现定义行为不作为跨实现的一致性要求；符合一致性的多个实现可以给出不同结果，但单个实现必须在每次运行时保持确定。不存在程序可在 TC 抽象机器中观测的非确定性行为。

**浮点**：以 IEEE 754-2019 定义为准；与 C99 宿主不一致时以 TC 抽象机器为准。

**as-if 规则**：实现可改变内部表示与指令序列，但必须保留规范静态诊断、实际执行路径上的运行时错误顺序、标准 I/O 顺序和值结果。可编译期求值的 strict 运算仍具运行时错误语义，不得因结果未使用而删除。

**一致性实现**指其前端与执行后端共同满足以上规则的实现。仅解析不执行的工具可只声明所覆盖的阶段。

## 2. 词法结构

本章定义 TC 语言的基本词法单元。完整的 EBNF 定义见附录 A。

### 2.1 字符集与 Token

源文件必须是有效 UTF-8 字节序列。

1. 源编码：文件必须是有效 UTF-8 字节序列。不接受 UTF-8 BOM；文件起始的 U+FEFF 按非法源字符处理。U+0000 在源文件任何位置均非法。
2. Token 与结构字符：除注释内容外，只允许 ASCII 字符 `A`–`Z`、`a`–`z`、`0`–`9`、`_`、`+`、`-`、`#`、`%`、`=`、`:`、`,`、`(`、`)`、`<`、`>`、`;`、`.`、`@`。`<`/`>` 仅用于 `memblock<T, count>`，`@` 仅用于 `@padding(N)` 属性。字符是否能出现在具体位置仍由附录 A 决定。

3. 源空白与行结束：行首缩进只能由 ASCII 空格 U+0020 组成，每连续 4 个空格表示一级，空格总数须能被 4 整除。Token 间可用空格或水平制表符 U+0009。逻辑行结束仅为 LF、CRLF 或 CR。
4. 注释：分号 `;` 之后到当前行结束之前，允许任意已正确 UTF-8 解码的 Unicode 标量值（U+0000 除外）。注释内容不产生 Token。

非法 UTF-8 在 UTF-8 解码阶段拒绝；BOM、U+0000，以及注释外的非 ASCII 字符、未列出的 ASCII 字符或非法空白在随后的词法/源字符检查中拒绝。两类均映射为 `TC_CE_SYNTAX`。

### 2.2 标识符

- 由字母、数字与 `_` 组成，必须以字母或 `_` 开头（完整产生式见附录 A）。
- 区分大小写。

### 2.3 整数字面量

#### 2.3.1 后缀与符号性

TC 字面量通过后缀区分符号性：

| 后缀      | 符号性 | 示例                   |
| --------- | ------ | ---------------------- |
| 无后缀    | 有符号 | `42`、`-128`、`0xFF`   |
| `u` / `U` | 无符号 | `42u`、`255u`、`0xFFu` |

**关键规则**：
- 无后缀字面量视为有符号整数，可用于有符号类型上下文；若用于无符号上下文，须满足范围约束
- `u` 后缀字面量视为无符号整数，仅可用于无符号类型上下文；用于有符号上下文触发 字面量类型错误
- 负号 `-` 仅可与无后缀字面量组合；`-42u` 为非法
- 进制前缀只改变数值的书写方式，不改变其数学值，也不触发隐式补码重解释。例如 `0b1000_0000` 的数学值为 `128`，不能直接用于 `int8` 上下文；`int8` 的最小值应写作 `-128`

#### 2.3.2 进制

TC 支持四种进制字面量：

| 进制           | 前缀        | 数字字符集                | 示例                      |
| -------------- | ----------- | ------------------------- | ------------------------- |
| 十进制（默认） | —           | `0`–`9`                   | `0`、`255`、`-128`、`42u` |
| 十六进制       | `0x` / `0X` | `0`–`9`、`a`–`f`、`A`–`F` | `0xFF`、`0x1Au`、`-0x80`  |
| 二进制         | `0b` / `0B` | `0`、`1`                  | `0b1010`、`0b11111111u`   |
| 八进制         | `0o` / `0O` | `0`–`7`                   | `0o377`、`-0o100`         |

- 前缀中的 `0` 是必需的前导，不区分大小写
- 前缀与数字之间 不可有空白
- 后缀紧跟数字部分，前缀与后缀之间 不可有空白

#### 2.3.3 数字分隔符

为增强长数字的可读性，允许在下述位置插入单个下划线 `_`：

- 十进制：两个十进制数字之间（首数字之后、末数字之前）
- 十六进制：数字部分的两个十六进制数字之间
- 二进制：数字部分的两个二进制数字之间
- 八进制：数字部分的两个八进制数字之间

**约束**：不可连续两个 `_`，不可在字面量首尾放置 `_`，不可在前缀内部插入 `_`（如 `0x_FF` 非法）。

#### 2.3.4 前导零

- 十进制字面量 不允许前导零（`007` 非法，应写作 `7`）；忽略分隔符后仍按数字序列判定，因此 `0_0`、`0_7` 也非法
- 单个 `0` 是合法的十进制零，不视为前导零特例
- 八进制须显式使用 `0o` 前缀

#### 2.3.5 字面量的词法上限

- 整数字面量的数值不得超过 `2^64 − 1`，即 `0 ≤ N ≤ 18446744073709551615`
- 整数字面量超出此范围 → 字面量范围错误

本节上限是只依赖 Token 自身的词法值检查：在最长匹配形成候选整数字面量后、进入语法解析前执行，失败固定报告 `TC_CE_LITERAL_OUT_OF_RANGE`。它不同于随后依据变量、形参或返回类型进行的上下文字面量检查。

#### 2.3.6 负号与减法运算符的关系

`-` 前缀仅出现在无后缀整数字面量中，不作为独立的一元运算符。若需变量间的减法，使用 `sub` 指令。

#### 2.3.7 最长匹配

整数字面量 Token 按最长匹配形成：前缀 `0` 后接 `x`/`X`/`b`/`B`/`o`/`O` 转入对应进制；数字部分结束后若紧跟 `u`/`U` 则带后缀，否则为无后缀字面量。具体扫描步骤以实现确定性为准，但不得改变本节与附录 A 规定的 Token 集合。

### 2.4 浮点字面量

#### 2.4.1 格式与后缀

TC 支持十进制浮点字面量和科学计数法：

| 形式                    | 示例                     | 类型                     |
| ----------------------- | ------------------------ | ------------------------ |
| 十进制浮点              | `3.14`、`-0.5`、`1.0`    | 无后缀 → `float64`       |
| 单精度后缀              | `3.14f`、`-0.5F`、`1.0f` | `f`/`F` 后缀 → `float32` |
| 科学计数法（小写 e）    | `1.2e5`、`-3.14e-2`      | 无后缀 → `float64`       |
| 科学计数法（大写 E）    | `1.2E5`、`-3.14E-2`      | 无后缀 → `float64`       |
| 科学计数法 + 单精度后缀 | `1.2e5f`、`-3.14E-2F`    | `f`/`F` 后缀 → `float32` |

**关键规则**：
- 浮点字面量必须包含小数点 `.` 或指数标记 `e`/`E`
- 无后缀浮点字面量为 `float64` 类型
- `f`/`F` 后缀浮点字面量为 `float32` 类型
- 浮点字面量 不区分符号性（浮点数无符号概念）
- 负号 `-` 可与浮点字面量组合
- 浮点字面量 仅可用于能确定源浮点类型的上下文（含 `float32`/`float64` 运算、`cast` 或 `bitcast`）
- 有限十进制字面量先解析为精确数学值，再直接按 roundTiesToEven 舍入到后缀决定的 binary32/binary64；不得通过另一浮点类型中转
- 非零有限值舍入为零，或有限值舍入为无穷 → 字面量范围错误；可表示的非规格化数合法
- 数学值为零且字面量显式带 `-` 时生成负零；其余零字面量生成正零

有限浮点字面量的源类型完全由 `f`/`F` 后缀决定，因此上述"舍入为零或无穷"的检查同样是只依赖 Token 自身的词法值检查，失败报告 `TC_CE_LITERAL_OUT_OF_RANGE`。后续上下文只检查该已形成的 `float32` / `float64` 字面量是否与期望类型一致，不重复改变其源类型或舍入结果。

**特殊浮点值**：

| 字面量 | 含义             | IEEE 754 表示                |
| ------ | ---------------- | ---------------------------- |
| `inf`  | 正无穷           | 指数全 1，尾数全 0，符号位 0 |
| `-inf` | 负无穷           | 指数全 1，尾数全 0，符号位 1 |
| `nan`  | 非数（静默 NaN） | 指数全 1，尾数非 0           |

**特殊值的源类型**：

`inf`、`-inf`、`nan` 本身不区分 `float32` / `float64` 精度。词法层将它们归约为同一个特殊浮点 Token（`float_special`），不携带类型。源类型在所有上下文中统一由该位置的**期望类型**唯一决定：

| 上下文 | 期望类型的来源 |
| ------ | -------------- |
| 变量/常量声明 | 声明类型 |
| `cast(T, ...)` | 目标类型 `T` |
| `bitcast(T, ...)` | 目标位宽：32 位 → `float32`，64 位 → `float64` |
| 算术 / 比较 / I/O 的操作数位置 | 显式类型参数或 I/O 的类型参数 |

同一特殊值 Token 在不同期望类型下分别解释为对应精度的无穷或 canonical quiet NaN（`float32`：`0x7F800000` / `0x7FC00000`；`float64`：对应 64 位模式），不得经另一浮点类型中转。同一目标类型下所有路径产生相同位模式。

**约束**：
- `inf`、`-inf`、`nan` 为保留关键字，不可用作标识符
- 区分大小写：均为小写。`INF`/`NaN` 等其他大小写形式按普通标识符词法化，若未声明则报 `TC_CE_UNDEFINED_VARIABLE`

#### 2.4.2 词法错误

浮点字面量不得带整数 `u`/`U` 后缀。小数点左侧数字不可省略（例如不得以 `.` 开头）。不符合附录 A 浮点产生式的 Token 序列属语法拒绝（`TC_CE_SYNTAX`）；仅依赖 Token 自身即可判定的舍入为零/无穷失败报告 `TC_CE_LITERAL_OUT_OF_RANGE`（§2.4.1）。

### 2.5 布尔字面量

| 字面量  | 值   | 类型   |
| ------- | ---- | ------ |
| `true`  | 真   | `bool` |
| `false` | 假   | `bool` |

**约束**：
- `true` 和 `false` 为保留关键字，不可用作标识符
- 区分大小写，且仅小写形式是布尔字面量。`True` / `FALSE` 等按普通标识符词法化，若未声明则报 `TC_CE_UNDEFINED_VARIABLE`
- 布尔字面量 仅可用于 `bool` 类型上下文

### 2.6 注释

- 行注释以 `;` 开始，延续至行尾
- 注释内容可以使用 Unicode；注释之外的 Token 仍仅使用 §2.1 规定的 ASCII 字符

### 2.7 关键字

以下 token 为保留关键字（含模式指令 Token），不可用作标识符：

```text
#lib  #program
abs  add  and
bitcast  bool  break
cast  continue
div
else  end  eq
false  float32  float64  func  funcall
ge  goto  gt
ieee  if  import  inf  int16  int32  int64  int8  isize
label  le  let  lt
memblock  memblock_copy  memblock_load  memblock_store  memcopy_unsafe  mod  mul
nan  ne  neg  not  nullptr
or
private  ptr  ptr_add  ptr_address  ptr_eq  ptr_ge  ptr_gt  ptr_le  ptr_load  ptr_lt  ptr_ne  ptr_size  ptr_store  ptr_sub  public

Self  shl  shr  static  struct  sub
then  true  truncate

```

函数调用关键字为 `funcall`。`void` 只允许出现在函数返回类型位置。`padding` 不是保留关键字；它仅作为 `@padding(N)` 属性名出现在结构体字段声明中（§3.9）。`count` 和 `fill` 不是保留关键字；它们仅作为 `memblock` 构造器的命名实参标签，按普通标识符拼写匹配（§3.8.3）。

### 2.8 语句与行结构

- 每条语句独占一行
- 空行、仅含 ASCII 空格/制表符的行、仅含行注释的行均合法，不产生语句；这些行的行首空白不构成缩进。非 ASCII 空白不能构成空白行
- 语句由 `NEWLINE` 结束。`;` 始终是行注释起始符；因注释可紧跟语句，外观上可写为“语句末尾的可选 `;`”，但语法 Token 序列中不存在分号终结符

## 3. 类型系统

### 3.1 类型分类

TC 0.0.42 支持 **整数类型**、**浮点类型**、**布尔类型**、**指针类型**、**内存块类型**、**结构体类型**，并以 `void` 表示函数不返回值：

| 类别         | 支持的类型               | 说明                   |
| ------------ | ---------------------- | ---------------------- |
| **整数类型** | `int8`～`uint64`、`isize`、`usize` | 固定宽度二进制补码整数；`isize`/`usize` 宽度随目标平台指针宽度（§3.2.1） |
| **浮点类型** | `float32`、`float64`   | IEEE 754 浮点数        |
| **布尔类型** | `bool`                 | 逻辑真/假              |
| **指针类型** | `ptr<T>`               | 参数化指针类型，宽度等于目标平台指针宽度；`T` 一般为 `void` 以外的完整类型；结构体定义中允许 `ptr<正在定义的本结构体>`（§3.9.1、§3.10） |
| **内存块类型** | `memblock<T, N>` | 带长度头部的内存块值类型；`N` 为编译期 `usize` 常量，规划元素个数；`N` 不参与类型等价，`memblock<T>` 由 `T` 唯一决定（§3.8） |
| **结构体类型** | 用户定义的 `struct` 名 | 命名字段的值类型聚合；默认无内部填充，可选 `@padding(N)`（§3.9） |
| **无值标记** | `void`                 | 不是值类型，仅用于函数返回类型 |

**完整类型**：在 TC 中，"完整类型"指具有已知编译期宽度（`sizeof_bits`）且可以作为变量槽、`memblock` 元素类型或（除下款例外外）`ptr<T>` 的所指类型的类型，具体包括：
- 全部标量类型（`scalar_type`）：13 种固定宽度整数、`isize`/`usize`、`float32`/`float64`、`bool`；
- `memblock<T, N>`（`T` 为完整类型，`N` 为编译期常量）；
- 已成功定义完毕的结构体类型（字段均含编译期已知宽度）；
- `ptr<T>`（`T` 为 `void` 以外的完整类型；结构体字段中的指针自引用例外见 §3.9.1）。

`void` 不是完整类型。`ptr<void>` 不合法。正在定义、尚未成功结束（未见匹配的 `end` 且字段尚未全部接受）的结构体类型**不是**完整类型；它不得作为值类型字段、`memblock` 元素类型，也不得出现在本结构体定义以外的类型位置。唯一例外是：在**该结构体自身的字段类型表达式**中，它可作为某一层 `ptr<…>` 的所指类型（§3.9.1）。

### 3.2 整数类型

| 类型     | 位宽 | 符号   | 最小值                     | 最大值                     |
| -------- | ---- | ------ | -------------------------- | -------------------------- |
| `int8`   | 8    | 有符号 | −2^7                       | 2^7 − 1                    |
| `uint8`  | 8    | 无符号 | 0                          | 2^8 − 1                    |
| `int16`  | 16   | 有符号 | −2^15                     | 2^15 − 1                   |
| `uint16` | 16   | 无符号 | 0                          | 2^16 − 1                   |
| `int32`  | 32   | 有符号 | −2^31                     | 2^31 − 1                   |
| `uint32` | 32   | 无符号 | 0                          | 2^32 − 1                   |
| `int64`  | 64   | 有符号 | −2^63                     | 2^63 − 1                   |
| `uint64` | 64   | 无符号 | 0                          | 2^64 − 1                   |

类型命名规则：`<符号前缀><位宽>`，其中符号前缀为 `int`（有符号）或 `uint`（无符号），位宽为 `8`/`16`/`32`/`64`。

#### 3.2.1 平台字长类型（`isize`、`usize`）

`isize` 与 `usize` 的宽度等于目标平台的指针宽度（目标字长），是平台相关的整数类型：

| 类型    | 符号   | 32 位目标        | 64 位目标        |
| ------- | ------ | ---------------- | ---------------- |
| `isize` | 有符号 | 等价于 `int32`   | 等价于 `int64`   |
| `usize` | 无符号 | 等价于 `uint32`  | 等价于 `uint64`  |

**约束**：
- 目标平台字长仅可为 32 位或 64 位；同一 TC 实现的所有编译单元共享同一目标字长
- `isize` 的有符号算术默认 strict 模式，可选 `wrap` 模式，行为与同位宽 `int*` 一致
- `usize` 的算术固定模 `2^n` 回绕，与同位宽 `uint*` 一致
- `isize` / `usize` 与固定宽度整数之间的赋值、传参或运算须显式 `cast` 统一类型
- `isize` / `usize` 的字面量形式与同位宽 `int*` / `uint*` 相同，由目标字长唯一确定期望范围
- `usize` 是 `memblock<T, N>` 中 `N`（元素个数规划）的唯一合法类型，亦是 `memblock_load` / `memblock_store` 下标与 `memblock_copy` 区间操作数的推荐类型（§3.8、§6.7）

### 3.3 浮点类型

| 类型      | 位宽 | IEEE 754 对应 | 最大有限绝对值（精确） | 最小正正规值 | 最小正非零值 | 精度（十进制约） |
| --------- | ---- | ------------- | ---------------------- | ------------ | ------------ | ---------------- |
| `float32` | 32   | binary32      | (2 − 2^−23) × 2^127   | 2^−126       | 2^−149       | ~7 位            |
| `float64` | 64   | binary64      | (2 − 2^−52) × 2^1023  | 2^−1022      | 2^−1074      | ~16 位           |

**内部表示**：
- 浮点数以 IEEE 754 二进制格式存储
- `float32`：符号字段 1 位 + 指数字段 8 位 + fraction 字段 23 位
- `float64`：符号字段 1 位 + 指数字段 11 位 + fraction 字段 52 位
- 浮点数的“位模式”只能通过等位宽 `bitcast` 与整数互转

### 3.4 布尔类型

`bool` 类型表示逻辑真值，取值为 `true` 或 `false`。

**抽象表示与固定宽度**：
- `bool` 在 TC 抽象机器中占据**固定 1 字节（8 位）**，与 `int8` / `uint8` 等位宽。该宽度参与 `memblock` 布局、按值传参/返回与整体复制的大小计算。
- 规范位模式唯一：`false` = `0x00`，`true` = `0x01`。不存在第三种可由合法 TC 程序提交的“非零真值”字节。
- `bool` 的抽象值域恰好为 `false` 与 `true`；所有产生 `bool` 的指令、`read`、`cast` 与 `memblock_store`（元素类型为 `bool` 时）都必须把结果规范化为上述二者之一后再提交。
- 若后端在 ABI 或内部载体上接收非规范布尔字节，必须先规范化为 `0x00` / `0x01` 再进入 TC 抽象机器；不得让非规范字节影响比较、逻辑、I/O、函数传参或 `memblock` 元素内容。
- 不可将 `bool` 直接解释为整数；数值互转须通过 `cast`。尽管位宽与 `int8`/`uint8` 相同，`bitcast` 仍明确排除 `bool`（§6.6.6），以杜绝经位重解释写入非 `0x00`/`0x01` 字节。

**类型性质**：
- 比较运算和逻辑运算的结果类型为 `bool`。
- `bool` 变量可被赋值、读取、输出。
- 与所有类型相同：`bool` 的 `var` 定义**声明时必须初始化**（§5.1）。

由于 `bitcast` 明确排除 `bool` 类型（§6.6.6），TC 程序不存在通过位重解释将非规范位模式引入 `bool` 绑定的路径；所有产生 `bool` 值的指令和转换均保证结果已规范化为 `0x00` 或 `0x01`。

### 3.5 类型性质

**有符号类型（`int8`～`int64`、`isize`）**

- 采用 二进制补码 表示
- `add`/`sub`/`mul`/`neg` 默认 **严格模式**：结果超出范围 → 整数溢出错误
- `div` 的数学商不可表示时，以及 `abs(INT_MIN)` 时 → 整数溢出错误
- 显式 `wrap` 模式：按模 `2^n` 回绕，不报错
- `shl` 默认严格模式：左移结果超出范围 → 整数溢出错误；`wrap` 模式截断高位

**无符号类型（`uint8`～`uint64`、`usize`）**

- 仅表示非负整数
- 算术结果超出最大值时 模 `2^n` 回绕，不报错
- `div`/`mod` 结果恒为非负
- `shl` 默认严格模式（仍可检测值溢出，例如 `shl(uint8, 255u, 1)` 的数学结果超过 255 时报错），`wrap` 模式截断高位

**浮点类型（`float32`、`float64`）**

- 符合 IEEE 754 标准
- 支持两种算术模式（详见 §6.3）：
  - **严格模式**（默认）：上溢/下溢/除零/无效操作均报错
  - **IEEE 754 模式**（`ieee`）：遵循 IEEE 754，返回 ±inf/nan，不报错
- TC 不支持浮点 `wrap`；位模式操作须通过等宽 `bitcast` 转为整数后完成
- 浮点数不支持位运算（`and`/`or`/`xor`/`not`/`shl`/`shr`）

**布尔类型**

- 固定宽度 1 字节；规范位模式为 `false` = `0x00`、`true` = `0x01`（§3.4）
- 比较运算和逻辑运算返回 `bool`
- 不参与算术运算（须显式 `cast`）；不参与 `bitcast`

**无值返回标记（`void`）**

- 只表示函数没有返回值，不是值类型
- 没有位宽、字面量、变量槽或运行时值
- 不能参与运算、转换、I/O、参数传递或变量/常量定义

**内存块类型（`memblock<T, N>`）**

- 是值类型：整体赋值、按值传参与返回均按抽象布局整块复制（§3.8.4）
- 类型仅由元素类型 `T` 决定（`memblock<T>`）；`N` 是编译期元素个数规划，不参与类型等价，但赋值与传参时须匹配（§3.8.1、§3.8.4）
- `.count` 返回编译期常量 `N` 的数学值，可作为 `const_operand`
- 不参与算术、位运算、比较、`cast` / `bitcast` 或标量 I/O；整块 I/O 须按元素自行完成

**结构体类型（用户定义的 `struct`）**

- 是值类型：整体赋值、按值传参与返回均按抽象布局整块复制（§3.9.4）
- 默认字段紧密排列、无内部填充；仅当字段显式书写 `@padding(N)` 时在该字段之后插入恰好 `N` 字节填充
- 字段以 `let` / `var` 区分成员可变性；字段赋值规则同时受外层绑定种类约束（§3.9.5）
- 不参与算术、位运算、比较、逻辑、`cast` / `bitcast` 或标量 I/O；整块 I/O 须按字段自行完成

**指针类型（`ptr<T>`）**

- 是值类型：赋值、按值传参与返回均复制指针值（地址），而非所指对象（§3.10.6）
- 宽度恒为目标平台指针宽度（与 `isize`/`usize` 相同，32 或 64 位；§3.10.5）；宽度与 `T` 无关
- `ptr<T>` 的 `T` 不能是 `void`：`void` 不是值类型。`ptr<void>` 不合法。
- `nullptr` 表示空指针，与任意 `ptr<T>` 兼容
- 仅支持专用等值比较（`ptr_eq`/`ptr_ne`，同型 `ptr<T>`）以及专用序关系比较（`ptr_lt`/`ptr_le`/`ptr_gt`/`ptr_ge`，同型 `ptr<T>`，§3.10.7）；不参与通用整数/浮点比较运算
- 支持专用指针算术 `ptr_add(T, p, offset)` / `ptr_sub(T, p, offset)`（§3.10.8）；不参与通用算术、位运算、逻辑或标量 I/O
- 支持 `ptr_address(T, ident)` 从运行时绑定取地址（§3.10.3）；仅可用于 `var` / `static var` / 形参，不可用于 `let`
- 支持 `ptr_load`（按值读取所指对象）和 `ptr_store`（覆盖写入所指对象）；`ptr_load`/`ptr_store` 空指针时报告运行时错误
- 支持 `cast(T, ptr_val)` 进行同宽指针类型转换，以及 `bitcast(T, ptr_val)` 进行等宽位重解释（§3.7）

**运行时值模型**

TC 中每个整数、浮点、布尔或指针变量的值由 n 位抽象位串（`n` 为类型位宽）与类型解释共同构成：

- 整数内部以 n 位无符号位模式存储；有符号类型按 二进制补码 解释，无符号类型按非负整数解释
- 浮点数内部以 IEEE 754 位模式存储
- `bool` 的 `n = 8`；合法提交的位模式仅 `0x00`（`false`）与 `0x01`（`true`）
- `wrap` 算术回绕、整数 `cast(..., truncate, ...)` 与等宽 `bitcast` 均在整数/浮点位模式上操作；`bitcast` 不作用于 `bool`
- 有符号 `wrap` 下的 `add`/`sub`/`mul`/`neg` 与同位宽无符号默认回绕 位模式一致
- 结构体值由按 §3.9.3 规定的字段与填充字节序列构成；填充字节在构造与整块复制时均为 `0x00`
- memblock 值由 `usize` 长度头部（值为 `N` 的数学值）和随后紧密排列的 `N` 个元素位串构成；`N` 是编译期常量，不参与类型等价
- 指针值（`ptr<T>`）以目标平台指针宽度的抽象位串存储。未经 `bitcast` 时，该位模式对程序不可见，槽位地址也不是可观察行为。经等宽 `bitcast(ptr<T> ↔ usize)`（或与指针同宽的无符号整数，§3.10.9、§6.6.6）后，抽象槽编码可被观测；实现定义的是该抽象槽编码，而非宿主对象地址。`nullptr` 的位模式为实现定义，与用户值产生的位模式明确区分

抽象位串按“最高有效位到最低有效位”的数值位权定义，与宿主内存的大小端字节序无关。`bitcast` 保持的是该抽象位串，不是对宿主对象表示执行类型别名访问；所有实现在不同字节序主机上必须得到相同数值结果。

### 3.6 字面量与类型的关系

字面量先由自身形式确定类别或源类型，再由所在位置提供的期望类型检查。不存在隐式跨类别转换。

#### 3.6.1 字面量检查规则

| 字面量 | 检查规则 |
| ------ | -------- |
| 无后缀整数 | 解析绝对值 `N`（`0 ≤ N ≤ 2^64−1`）；可带 `-`。有符号上下文要求数学值位于 §3.2 对应范围；无符号上下文要求值非负且在范围内 |
| `u`/`U` 整数 | 不得带 `-`，仅用于无符号整数上下文，且值须在对应范围内 |
| 普通浮点 | 无后缀源类型为 `float64`，`f`/`F` 后缀源类型为 `float32`；精确十进制值直接按 roundTiesToEven 舍入到该类型，不经另一浮点类型中转 |
| `inf`/`-inf`/`nan` | 仅用于浮点上下文；`nan` 为 §6.3.3 的 canonical quiet NaN |
| `true`/`false` | 仅用于 `bool` 上下文 |

非零有限浮点值舍入为零或有限值舍入为无穷时报字面量范围错误；可表示的非规格化数合法。类别、后缀或符号性与上下文不符时报字面量类型错误。`wrap`、`ieee`、`truncate` 和 `bitcast` 均不绕过这些检查。

### 3.7 类型转换的通用框架

TC 0.0.42 将数值转换、整数截断、位重解释与指针转换分开：

| 形式 | 用途 | 核心约束 |
| ---- | ---- | -------- |
| `cast(T, operand)` | 数值转换 | 按目标类型做范围检查与规定舍入 |
| `cast(T, truncate, operand)` | 整数缩窄 | 仅整数→更窄整数，保留低位 |
| `bitcast(T, operand)` | 位重解释 | 源、目标等宽；不改变任何位；`bool` 不参与 |
| `cast(T, ptr_val)` | 指针类型转换 | `ptr<U>` → `ptr<T>`：仅当 `T`/`U` 均为完整类型且等宽时允许；`cast(ptr<T>, nullptr)` 合法（跳过等宽） |

严格 `cast` 覆盖整数 ↔ 整数、整数 ↔ 浮点、浮点 ↔ 浮点，以及整数/浮点 ↔ `bool`。`truncate` 仅做数值截断，不承担位重解释；所有整数/浮点位模式互转使用 `bitcast`。指针类型转换通过 `cast` 进行（同为等宽值类型的重标记），不经 `truncate`；指针与整数/浮点位模式互转使用 `bitcast`。

### 3.8 内存块类型（`memblock`）

`memblock<T, N>` 描述一段具有编译期已知长度的紧密排列元素连续内存块。它直接映射到伪汇编模型中的可寻址内存块，使内存读写显式化为原子操作，不引入指针、地址运算或隐式解引用。`T` 是元素类型，`N` 是元素个数（编译期 `usize` 常量）。`N` 不参与类型构造——`memblock<int32, 10>` 与 `memblock<int32, 20>` 是同一类型 `memblock<int32>`，仅元素个数不同。运行时布局为 `usize` 长度头部紧随其后排列的元素数据（§3.8.2）。

#### 3.8.1 类型语义

| 规则 | 说明 |
| ---- | ---- |
| **类型仅由 `T` 决定** | `memblock<T, N>` 的类型为 `memblock<T>`。`N` 是编译期规划（元素个数约束），不构建新类型。`memblock<int32, 10>` 与 `memblock<int32, 20>` 属于同一类型。 |
| **`T` 为完整类型** | `T` 为 `void` 以外的任意完整类型：标量类型（`scalar_type`，含 `isize`/`usize`）、`memblock<U, N>`（嵌套）、结构体类型、`ptr<U>`。`memblock<ptr<int32>, 4>`、`memblock<MyStruct, 8>`、`memblock<memblock<int32, 3>, 5>` 等嵌套形态均合法。`void` 不是值类型，不能作为 `T`。 |
| **`N` 为编译期 `usize` 常量** | `N` 必须是编译期可求值的 `usize` 表达式，取值为正整数（≥ 1）。合法的 `N` 来源：无后缀整数字面量（以 `usize` 为期望类型检查）、类型为 `usize` 的 `let` / `static let` 标识符、经 `Self.` / 导入限定解析到的只读 `usize` 绑定。运行时 `var`、形参或非常量表达式非法（静态语义拒绝 `TC_CE_CONSTANT_EXPRESSION`）。 |
| **`N` 不参与类型等价** | 两个 `memblock<T, N>` 类型等价当且仅当 `T` 相同。`N` 相同的约束只在赋值、传参等上下文以编译期常量检查强制执行（§3.8.4），不属于类型系统。`N` 是绑定级容量约束（与运行时长度头部一致），不是元素种类的一部分；故意不进入类型等价，以免与「同元素类型」身份判定纠缠。同型但 `N` 不同时，赋值/传参报告 `TC_CE_MEMBLOCK_SIZE_MISMATCH` 而非 `TC_CE_TYPE_MISMATCH`。 |

#### 3.8.2 运行时布局

元素类型 `T` 的抽象宽度 `sizeof_bits(T)` 按如下规则确定，与宿主 ABI 无关。实现查阅用常数表见 [编译器标准 §3.0.1]。

| `T` | 宽度（位） | 说明 |
| --- | ---------- | ---- |
| `int8` / `uint8` / `bool` | 8 | 标量固定宽度 |
| `int16` / `uint16` | 16 | |
| `int32` / `uint32` / `float32` | 32 | |
| `int64` / `uint64` / `float64` | 64 | |
| `isize` / `usize` | 平台指针宽度（32 或 64） | |
| `ptr<U>` | `sizeof_bits(usize)` | 所有指针等宽（§3.10.5） |
| `memblock<U, N>` | `sizeof_bits(usize) + N × sizeof_bits(U)` | 递归计算；`U` 为该嵌套 memblock 的元素类型（§3.8.2） |
| 结构体 `S` | `sizeof_bits(S)` | 按该结构体定义的布局递归计算（§3.9.3） |

其中 `bool` 按 §3.4 固定为 1 字节：`false` 存 `0x00`，`true` 存 `0x01`。`memblock_store` 写入 `bool` 元素前必须规范化；`memblock_load` 读出的 `bool` 必须已是规范字节。

每个 `memblock<T, count>` 值的运行时存储区布局为：

```text
[ usize: count值 (平台字长位) | elem0: sizeof_bits(T) | elem1: sizeof_bits(T) | … | elem_{count-1}: sizeof_bits(T) ]
```

即**长度头部在前，元素数据在后**，元素紧密排列、无填充。长度头部的位宽为 `sizeof_bits(usize)`（32 位或 64 位，取决于目标平台）。头部存储的 `usize` 值与类型参数 `count` 的数学值相同；构造时写入，之后不可改变（不可通过 `memblock_store` 或 `memblock_copy` 覆盖头部区域）。

示意图（`memblock<int32, 4>`，64 位平台）：

```text
[ count: 64bit = 4 | elem0: 32bit | elem1: 32bit | elem2: 32bit | elem3: 32bit ]
```

示意图（`memblock<uint8, 3>`，32 位平台）：

```text
[ count: 32bit = 3 | e0: 8bit | e1: 8bit | e2: 8bit ]
```

**类型级宽度**：`memblock<T, N>` 具有唯一的类型级宽度：

```text
sizeof_bits(memblock<T, count>) = sizeof_bits(usize) + count × sizeof_bits(T)
```

其中 `sizeof_bits(T)` 按上表取值，`sizeof_bits(usize)` 为目标平台指针宽度（32 或 64）。由于 `count` 是编译期常量，该宽度在编译期完全确定。宽度与宿主 ABI 对齐无关；所有实现对同一类型值必须使用同一布局。

#### 3.8.3 值构造器

`memblock` 同时作为类型标注（声明位置的 `memblock<T, N>`）和值构造器（`memblock(T, count: N, …)`），上下文区分：出现在类型位置的 `:` 之后为类型标注，出现在 `=` 右侧（或其它 RHS / 实参位置）为值构造器。

值构造器的 `count:` 作为命名实参（带 `count:` 标签），支持以下两种形式：

| 形态 | 产生式 | 语义 |
| ---- | ------ | ---- |
| 指定值填充 | `memblock_fill_ctor` | 分配 `sizeof_bits(usize) + count × sizeof_bits(T)` 存储区，头部写入 `count`，所有元素以 `v` 初始化；`v` 类型须与 `T` 严格一致 |
| 逐值初始化 | `memblock_elems_ctor` | 同上，以 `count` 个位置实参依次初始化各元素 |

`count:` 标签在词法上是普通标识符 Token，按拼写匹配，不是 §2.7 保留关键字。`fill:` 同理。

约束：

- `count:` 实参的取值必须是合法的编译期 `usize` 常量（同 §3.8.1 的 `N` 来源规则），数学值 ≥ 1。该值同时决定分配的元素数与头部写入值。
- 逐值初始化时，位置实参数量必须等于 `count` 的数学值，否则静态错误 `TC_CE_MEMBLOCK_ELEMENT_COUNT_MISMATCH`。
- 每个值的类型必须与 `T` 严格一致；每个值均为 `operand`（`let` 上下文中为 `const_operand`）。
- 构造成功时，头部 `usize` 值写入 `count` 的数学值。

#### 3.8.4 赋值语义

`memblock<T, N>` 是值类型，赋值整体深拷贝源操作数的全部存储区（含长度头部与元素数据）到目标绑定：

1. **类型**：左右必须同为 `memblock<T>`（即 `T` 相同）；否则 `TC_CE_TYPE_MISMATCH`。
2. **元素个数**：左右声明的 `N` 必须相等（编译期常量的数学值比较）。`N` 不同时报 `TC_CE_MEMBLOCK_SIZE_MISMATCH`。由于 `N` 在声明时唯一确定且为编译期常量，这一检查在静态语义阶段完成，不产生运行时分支。
3. 成功赋值后目标持有与源内容相同的独立存储区副本，含长度头部。

无别名语义，无指针，无浅/深拷贝歧义。

需要按偏移复制子区间、或只搬运部分元素时，使用独立语句 `memblock_copy`（§6.7.2.3）；`memblock_copy` 的 `length` 操作数是**本次拷贝的元素个数**。

#### 3.8.5 `.count` — 访问长度头部

`mb.count` 以字段访问的形式从 memblock 的长度头部读取 `usize` 值并返回。语法见附录 A。类别：RHS（结果类型为 `usize`）。

| 约束 | 规则 |
| ---- | ---- |
| 基址类型 | `mb` 必须是 `memblock<T, N>` 类型的绑定 |
| 返回类型 | `usize`，值为绑定声明中 `N` 的数学值 |
| 读操作 | 不改变 memblock 内容或已初始化状态 |
| 确定初始化 | `mb` 为运行时 `var` 时须已确定初始化 |
| 编译期常量 | 由于 `N` 在声明时唯一确定且为编译期常量，`.count` 是编译期常量，可作为 `const_operand` 在 `const_rhs` 中使用 |

### 3.9 结构体类型（`struct`）

`struct` 是 TC 的用户定义**值类型**：一组按声明顺序排列的命名字段。结构体不引入指针、引用、别名或隐式装箱；整体赋值与按值传参/返回均按抽象布局整块复制。字段级 `let`/`var` 与外层绑定种类共同约束可变性。

#### 3.9.1 定义语义

结构体定义的语法形态由附录 A 规定。结构体只能出现在模块顶层的**类型定义区**（§4），不得出现在函数体或控制流块内。`#lib` 中结构体定义必须带显式可见性；`#program` 不得使用可见性修饰符。字段声明每行恰好一个字段。

| 项目 | 规则 |
| ---- | ---- |
| 结构体名 | 模块内唯一的类型名；不得与标量/`memblock`/关键字/`void` 冲突，也不得与同模块的函数名、值绑定名或导入名冲突 |
| 字段数量 | 至少 1 个；空结构体不合法 |
| 字段名 | 同一结构体内唯一；区分大小写 |
| 字段种类 | `let` 字段：构造后不可通过字段赋值修改；`var` 字段：仅当外层绑定为可写 `var` / `static var` 时可通过字段赋值修改（§3.9.5） |
| 字段类型 | 见下款「字段类型位置规则」；禁止 `void` |
| 字段初始化器 | 定义处**不得**写 `=`；字段值只在值构造器中提供（§3.9.2） |
| 缩进 | 字段行比 `struct` 行恰好多一级；`end` 与 `struct` 行对齐（与 `func`/`if`/`while` 相同）；`end` 缺失 → `TC_CE_MISSING_END` |

**字段类型位置规则**（设当前正在定义的结构体名为 `S`）：

字段类型可为：全部标量类型（`scalar_type`）、`memblock<T, N>`（带长度，§3.8）、`ptr<T>`（§3.10），或结构体类型名。结构体名在字段类型表达式中按出现**位置**分流：

| 出现位置 | 合法所指 |
| -------- | -------- |
| **值位置**：字段类型本身为结构体名，或作为 `memblock<…>` 的元素类型 | 仅**本模块中源序更早**已成功定义完毕的结构体；禁止 `S` 自身；禁止尚未开始定义或尚未成功结束的其它结构体（前向引用） |
| **指针所指位置**：作为字段类型表达式中某一层 `ptr<…>` 的所指类型 | `void` 以外的完整类型，**或**当前正在定义的本结构体 `S`（同名）；仍禁止前向引用其它未定义结构体 |

因此：

- **指针自引用合法**（本版本最小放开）：`var next: ptr<S>`，以及嵌套形态如 `ptr<ptr<S>>`、`memblock<ptr<S>, N>`（此处 `memblock` 的元素是完整的 `ptr<S>`，不是不完整的 `S`）。
- **值自引用非法**：`var next: S`、`var block: memblock<S, N>` → `TC_CE_STRUCT_VALUE_SELF_REF`（`S` 在定义完成前不是完整类型，且值位置禁止自引用。结构体自身是已定义的（正在定义中），错误语义是「值位置引用正在定义的本结构体」，故使用专用错误码而非 `TC_CE_UNDEFINED_STRUCT`）。
- **不引入前向声明语法**；不支持两个结构体经指针互指（`A` 含 `ptr<B>` 且 `B` 定义在后）——后者仍属前向引用。

`ptr<S>` 字段的抽象宽度为指针宽度（§3.9.3），不依赖 `S` 的最终布局，故可在 `S` 定义完成前参与布局累加。`S` 的定义成功结束（字段全部接受且见到匹配 `end`）后，`S` 成为完整类型，可在后续定义与声明中按常规使用。

示例：

```text
struct Node
    var value: int32
    var next: ptr<Node>
end
```

上例中 `next` 的类型为 `ptr<Node>`：所指为正在定义的本结构体，合法。构造器中该字段可写 `nullptr` 或其它 `ptr<Node>` 操作数（§3.9.2、§3.10）。

`#lib` 中 `public struct` 可被导入者通过 `<模块名>.<结构体名>` 用作类型名与构造器名；`private struct` 仅本模块可用。缺少 `public`/`private` 报 `TC_CE_MISSING_VISIBILITY`。在 `#program` 中对 `struct` 使用可见性修饰符报 `TC_CE_PROGRAM_MODE_MISUSE`。

#### 3.9.2 值构造器

结构体名在类型位置表示类型，在 RHS / `const_rhs` / 实参位置表示**值构造器**（语法见附录 A）。导入的公开结构体以 `<模块名>.<结构体名>` 作为构造器名。

**静态约束**（全部为静态语义拒绝，附录 A 已接受命名实参外壳之后）：

1. **全字段必填**：必须为每个声明字段恰好提供一个命名实参；缺任一字段 → `TC_CE_STRUCT_MISSING_FIELD`；多写未知字段名 → `TC_CE_STRUCT_UNKNOWN_FIELD`；同一字段名重复 → `TC_CE_STRUCT_DUPLICATE_FIELD`。
2. **文本顺序**：命名实参的文本顺序必须与字段声明顺序完全一致，否则 → `TC_CE_STRUCT_FIELD_ORDER`（与 `funcall` 命名实参顺序规则同形）。
3. **类型一致**：每个实参操作数的类型必须与对应字段声明类型严格相同；字面量按 §3.6 以字段类型为期望类型检查。
4. **按值复制**：构造成功时，各字段值按字段类型的值语义**复制**进新结构体实例；不共享存储，无别名。
5. **常量上下文**：出现在 `let` / `static let` 的 `const_rhs` 中时，每个字段实参必须是合法的编译期常量操作数（§5.2.1）；运行时 `var`、参数或非常量表达式非法。

#### 3.9.3 运行时布局

字段按**声明源序**依次排列。默认**无内部填充**：每个字段的存储紧接前一字段（或前一字段的填充区）结束处。

**字段抽象宽度**（用于构造某一具体结构体**值**时的布局）：

| 字段类型 | 该字段在某一值中的抽象宽度 |
| -------- | ------------------------ |
| 标量 `T` | `sizeof_bits(T)`（与 §3.8.2 相同；`bool` 固定 8 位；`isize`/`usize` 为平台指针宽度）——类型级固定 |
| `memblock<U, N>` | `sizeof_bits(usize) + N × sizeof_bits(U)`——类型级固定（§3.8.2）；字段声明写 `memblock<U, N>` |
| `ptr<T>` | `sizeof_bits(usize)`（目标平台指针宽度：32 或 64，§3.10.5）——类型级固定 |
| 嵌套结构体 `S` | 该嵌套字段值的抽象宽度（按本款对嵌套值递归计算） |

可选属性 `@padding(N)`：

- `N` 必须是非负十进制整数字面量（无后缀；允许 `0`）。
- 语义：在**该字段存储之后**插入恰好 `N` 个填充字节（每位填充字节为 `0x00`）。
- 省略属性等价于 `@padding(0)`，即默认紧密布局。
- `@padding` 只改变布局字节数，不改变字段类型、可变性或构造器实参列表。

**类型级宽度**：

结构体类型 `S` 的字段均含编译期已知宽度的类型（标量、`memblock<T, N>`、`ptr<T>`、不含 `memblock` 的嵌套结构体），因此 `S` 具有唯一的类型级宽度：

```text
sizeof_bits(S) = Σ_i ( sizeof_bits(field_i) + 8 × padding_i )
```

其中 `sizeof_bits(field_i)` 按上表取值，均为类型级；`padding_i` 为字段 `i` 的 `N`（默认 0）。布局与宿主 ABI、自然对齐无关；所有实现对同一抽象值必须使用同一布局。构造与整块复制时，所有填充字节均为 `0x00`；程序不能单独寻址填充区。

#### 3.9.4 赋值与按值语义

结构体是值类型：

- **整块赋值** `dst = src`（`dst` 为可写结构体绑定，`src` 为同类型操作数或同类型构造器）复制全部字段与填充字节；左右类型必须同为某一结构体类型，否则 `TC_CE_TYPE_MISMATCH`。含 `memblock<T, N>` 字段时，对各带长度 memblock 字段做整块深拷贝（含长度头部，§3.8.4）。
- **按值传参 / 返回**：调用与 `return` 时整块复制（含各带长度 memblock 字段的完整存储区含头部）；形参是只读绑定，禁止对形参做整块赋值，也禁止对形参的任何字段赋值（与标量/`memblock` 形参一致，报 `TC_CE_PARAMETER_ASSIGNMENT`）。形参类型仍只写结构体名；`memblock<T, N>` 字段的规划元素个数 `N` 在声明时唯一确定（§3.8）。
- **无别名**：复制后源与目标独立；修改一方的 `var` 字段不影响另一方。

整块赋值替换的是整个值，因此可以更新目标中的 `let` 字段内容；字段赋值禁止的是部分更新。

#### 3.9.5 字段访问与可变性

**字段读取**（语法见附录 A）的结果类型为该字段的声明类型。结构体操作数可以是：

- 裸标识符（局部/`#program` 顶层 `var`/`let`）
- `Self.<名>` / `<模块名>.<名>`（解析为结构体类型的 `static` 绑定）
- 形参名（只读）

字段读取是 `operand` 的合法形式（§6.1.2），因此可出现在运算、`funcall` 实参、`return`、输出等需要操作数的位置。支持嵌套字段访问（如 `a.b.c`）：`a.b` 的结果类型必须是一个结构体类型，才能继续做 `.c` 字段读取。

**字段赋值**（语法见附录 A）的合法性由两层约束**同时**决定：

| 外层绑定 | 目标字段为 `let` | 目标字段为 `var` |
| -------- | ---------------- | ---------------- |
| `let` / `static let` | `TC_CE_CONSTANT_ASSIGNMENT` | `TC_CE_CONSTANT_ASSIGNMENT` |
| `var` / 可写 `static var` | `TC_CE_STRUCT_IMMUTABLE_FIELD` | 允许（RHS 类型须与字段类型一致） |
| 函数形参 | `TC_CE_PARAMETER_ASSIGNMENT` | `TC_CE_PARAMETER_ASSIGNMENT` |

说明：

1. 外层为不可变绑定（`let` / `static let`）时，**任何**字段赋值均非法——即使该字段在结构体定义中声明为 `var`。
2. 外层为可变绑定且字段为 `let` 时，禁止字段赋值；需要更新 `let` 字段只能通过整块赋值替换整个结构体值。
3. 外层绑定必须在当前程序点已确定初始化；字段赋值不改变该绑定的已初始化状态（与普通赋值覆盖相同）。
4. 未知字段名 → `TC_CE_STRUCT_UNKNOWN_FIELD`；左侧基址不是结构体类型 → `TC_CE_TYPE_MISMATCH`。

#### 3.9.6 与其他特性的边界

| 特性 | 规则 |
| ---- | ---- |
| I/O | `write`/`writeln`/`read` 仍仅接受 `scalar_type`；结构体须按字段自行标量 I/O |
| `cast` / `bitcast` | 不以结构体为源或目标 |
| 比较 / 算术 / 位 / 逻辑 | 不接受结构体类型参数或操作数 |
| `memblock` | 结构体字段类型可为 `memblock<T, N>`（带长度头部，§3.8）；`memblock` 元素类型 `T` 须为 `void` 以外的完整类型，故不得为正在定义的本结构体；`memblock<ptr<S>, N>`（`S` 为正在定义的本结构体）合法 |
| `ptr` | 字段类型可为 `ptr<T>`；`T` 可为完整类型，或正在定义的本结构体（§3.9.1）；含 `ptr` 字段的整块赋值复制指针值，产生所指对象别名（§3.10.6） |
| 模块 | 类型定义区位于 `import` 之后、值声明/`func` 之前（§4）；结构体名参与模块命名空间冲突检查 |

### 3.10 指针类型（`ptr<T>`）

`ptr<T>` 是 TC 的参数化值类型，表示一个可为空的指向类型 `T` 对象的指针。指针宽度等于目标平台指针宽度（与 `isize`/`usize` 相同）。指针使间接访问显式化为 `ptr_load`/`ptr_store` 操作，不引入隐式解引用、指针算术或原始地址操作。`ptr<T>` 是值类型：复制指针复制的是地址，而非所指对象。

#### 3.10.1 类型语义

`ptr<T>` 是参数化类型构造器，携带所指类型 `T`。除下款例外外，`T` 必须是 `void` 以外的完整类型：标量类型（`int8`～`uint64`、`isize`、`usize`、`float32`、`float64`、`bool`）、`memblock<T, N>`（带长度头部，§3.8）、**已成功定义完毕**的结构体类型（§3.9），或另一指针类型 `ptr<U>`。`ptr<void>` 不合法（`void` 不是值类型）。

**结构体字段中的指针自引用例外**：在定义结构体 `S` 的字段类型表达式中，某一层 `ptr<…>` 的所指类型可为正在定义的本结构体 `S`（§3.9.1）。该例外仅适用于 `S` 自身字段类型表达式内部；不得据此在其它结构体、其它声明或前向位置书写尚未定义完毕的结构体名。

| 规则 | 说明 |
| ---- | ---- |
| **类型含 `T`** | 类型构造器携带所指类型 `T`。`ptr<int32>` 与 `ptr<float64>` 是不同的类型。 |
| **`T` 参与类型等价** | 两个 `ptr<T>` 类型等价当且仅当 `T` 相同。对指针自引用字段，定义完成后 `T` 即为完整的 `S`，与其它位置的 `ptr<S>` 同型。 |
| **无隐式转换** | 不同所指类型的指针之间禁止隐式转换；赋值、传参两侧的 `ptr<T>` 必须严格同型，否则报 `TC_CE_TYPE_MISMATCH`。 |
| **无指针算术** | 不允许对 `ptr<T>` 值做加、减等通用算术运算或位运算；`ptr<T>` 不是整数类型。指针算术仅可通过专用的 `ptr_add` / `ptr_sub` 指令进行（§3.10.8），偏移量以所指类型 `T` 的元素大小为步长。 |
| **无宿主角度的地址保证** | `ptr<T>` 的抽象位模式对程序不可见；不保证任何指针值的位模式等于宿主内存地址。 |

#### 3.10.2 `nullptr` 空指针

`nullptr` 是空指针字面量，类别为 RHS（`operand`）。`nullptr` 本身不携带所指类型；它在所有上下文中统一由该位置的**期望类型**唯一决定：

| 上下文 | 期望类型的来源 |
| ------ | -------------- |
| 变量/常量声明 | 声明中的 `ptr<T>` 类型 |
| `ptr_load`/`ptr_store` 操作数位置 | 操作数的声明类型 |
| `funcall` 实参位置 | 对应形参的声明类型 |
| `return` 表达式 | 函数返回类型 |
| `cast` 目标 / `cast(ptr<T>, nullptr)` | `cast` 的 `T` 参数；`nullptr` 源无所指类型，不做等宽检查 |

**运行时语义**：

- `ptr_load(nullptr)` → 运行时错误 `TC_RE_NULL_POINTER_DEREFERENCE`。
- `ptr_store(nullptr, val)` → 运行时错误 `TC_RE_NULL_POINTER_DEREFERENCE`。
- 将 `nullptr` 赋值给 `ptr<T>` 绑定、作为实参传递或作为 `return` 返回值均合法，不触发运行时错误。

#### 3.10.3 指针读写与取地址（`ptr_load` / `ptr_store` / `ptr_address`）

`ptr_load` 和 `ptr_store` 是指针解引用的唯一方式。语法由附录 A 规定。

**`ptr_load`**

| 项目 | 规则 |
| ---- | ---- |
| 类别 | RHS（`operand`） |
| 类型参数 | `T` 须为完整类型（排除 `void`），即指针的所指类型 |
| 操作数 | `ptr` 须为 `ptr<T>` 类型 |
| 结果类型 | `T`（与类型参数一致，也与 `ptr` 的所指类型一致） |
| 执行语义 | 若 `ptr` 为 `nullptr`，报告 `TC_RE_NULL_POINTER_DEREFERENCE`；否则，将所指对象的值**按值复制**返回为 `T` 类型结果。读出不改变指针值，也不改变所指对象。 |
| 所指对象的可变性 | 所指绑定为 `let`/`static let` 时，`ptr_load` 合法（仅读）；所指绑定为 `var` 时，`ptr_load` 同样合法。 |

**`ptr_store`**

| 项目 | 规则 |
| ---- | ---- |
| 类别 | 语句 |
| 类型参数 | `T` 须为完整类型（排除 `void`），即指针的所指类型 |
| 操作数 | `ptr` 须为 `ptr<T>` 类型；`value` 须为 `T` 类型的操作数（类型须严格一致；字面量以 `T` 为期望类型检查） |
| 执行语义 | 若 `ptr` 为 `nullptr`，报告 `TC_RE_NULL_POINTER_DEREFERENCE`；否则，将 `value` 的位模式完整写入 `ptr` 所指对象（覆盖）。 |
| 可变性约束 | 仅当 `ptr` 所指的**外层绑定**为可写（`var` / 可写 `static var`）时允许 `ptr_store`；所指为 `let`/`static let`/形参时报告 `TC_CE_CONSTANT_ASSIGNMENT`。`ptr_store` 不能绕过 §5.1 的可变性规则。 |
| 类型级约束 | `value` 类型须与 `T` 严格一致；不支持通过指针做跨类型写入。 |

**`ptr_address`**

`ptr_address` 从变量的标识符取地址，产生指向该绑定的 `ptr<T>` 值。语法：`ptr_address(T, identifier)`，其中 `T` 是所指类型。类别：RHS（`operand`）。

| 项目 | 规则 |
| ---- | ---- |
| 类别 | RHS（`operand`） |
| 类型参数 | `T` 须为完整类型（排除 `void`）；`T` 必须与 `identifier` 的声明类型严格一致 |
| 操作数 | `identifier` 须为运行时绑定的裸名：局部 `var`、顶层 `var`、`static var`、函数形参，或（在 `#lib` 内）`Self.<名>`、已导入的 `<模块名>.<名>`（解析为 `static var`）。`let` / `static let` 绑定的标识符禁止 |
| 结果类型 | `ptr<T>` |
| 编译期上下文 | `const_rhs` 中非法（`ptr_address` 不是编译期常量） |
| 执行语义 | 计算该绑定的抽象存储位置并返回对应的 `ptr<T>`。取地址后，指针与绑定共享同一存储；通过 `ptr_store` 写入会同步反映到绑定的 `ptr_load` 与直接读取 |

**可变性交互**：`ptr_address` 本身是只读操作（只计算地址），不修改绑定值。但若取地址的目标是一个 `let` / `static let` 绑定，即使 `ptr_address` 调用本身成功，后续通过该指针做 `ptr_store` 仍会受 §6.8.3 的可变性约束——绑定的只读性质不因取地址而改变。因此 `ptr_address` 仅接受 `var` / `static var` / 形参绑定的标识符；将 `let` 标识符用于 `ptr_address` 报 `TC_CE_CONSTANT_ASSIGNMENT`。

**别名规则**：多个 `ptr<T>` 值可能指向同一对象（允许多个指针别名）。对同一对象的连续 `ptr_load` 与 `ptr_store` 按源序执行，次序由抽象机规定；实现不得重排序跨 `ptr_store` 的 `ptr_load`。

#### 3.10.4 指针值的来源

程序可通过以下方式获得 `ptr<T>` 类型的值：

| 来源 | 说明 |
| ---- | ---- |
| `nullptr` | 空指针字面量，与任意 `ptr<T>` 兼容（§3.10.2） |
| `ptr_address(T, ident)` | 从运行时绑定取地址，产生指向该绑定的 `ptr<T>`（§3.10.3）。仅可作用于 `var` / `static var` 绑定或函数形参；`let` 禁止 |
| 现有绑定（变量/常量/形参/`static`） | 将声明类型为 `ptr<T>` 的现有绑定用作操作数，即得到 `ptr<T>` 值（复制指针值本身，而非复制所指对象） |
| 函数返回值 | 函数返回类型为 `ptr<T>` 时，`funcall` 调用结果亦为 `ptr<T>` |
| 整块赋值 | 赋值 `dst = src`（双方同类型 `ptr<T>`）复制指针值 |

#### 3.10.5 指针宽度与布局

`ptr<T>` 的抽象宽度固定为：

```text
sizeof_bits(ptr<T>) = sizeof_bits(usize)  （目标平台指针宽度：32 或 64）
```

- `ptr<T>` 具有唯一类型级宽度，与 `T` 无关；所有指针类型等宽。
- 内部位模式对程序不可见；`bitcast` 允许 `ptr<T>` ↔ `usize` (或 `uint64` / `uint32`) 的等宽位重解释（见 §3.10.6）。
- 指针宽度与宿主 ABI 对齐无关；该宽度在抽象机器中固定，与具体实现无关。

#### 3.10.6 赋值与按值语义

`ptr<T>` 是值类型：

- **整块赋值** `dst = src`（`dst` 为可写 `ptr<T>` 绑定，`src` 为同类型 `ptr<T>` 操作数或 `nullptr`）复制指针值（所指地址），而非所指对象；左右类型必须同为某一 `ptr<T>`，否则 `TC_CE_TYPE_MISMATCH`。
- **按值传参 / 返回**：调用与 `return` 时复制指针值；形参是只读绑定，禁止对形参做整块赋值（报 `TC_CE_PARAMETER_ASSIGNMENT`）。
- **无别名于所指对象**：复制指针后，源与目标互为别名（指向同一对象）；通过任一指针做 `ptr_store` 会影响通过另一指针的 `ptr_load` 结果。这是有别于 `memblock` 和结构体的关键语义差异：指针复制产生的是**所指对象共享**，而非所指对象深拷贝。

#### 3.10.7 比较运算

`ptr<T>` 支持等值比较与序关系比较，**全部使用专用 `ptr_*` 指令**，不借用通用 `eq`/`ne` 等比较运算。

**等值比较（显式类型参数）**

| 运算 | 操作数类型 | 结果类型 | 语义 |
| ---- | ---------- | -------- | ---- |
| `ptr_eq(T, ptr1, ptr2)` | 同为 `ptr<T>` | `bool` | 指针值相等（指向同一对象或同为 `nullptr`）；`ptr_eq(T, nullptr, nullptr)` 为 `true`；非空指针与 `nullptr` 比较为 `false` |
| `ptr_ne(T, ptr1, ptr2)` | 同为 `ptr<T>` | `bool` | 指针值不等 |

等值比较的约束：

- 显式类型参数 `T` 须为 `void` 以外的完整类型，决定指针的所指类型；两个操作数必须同为 `ptr<T>` 类型。
- 通用 `eq`/`ne` 不接受 `ptr<T>` 类型操作数。

**序关系比较（显式类型参数）**

序关系比较需要显式类型参数 `T` 以指明指针所指类型，比较的是抽象地址关系：

| 运算 | 操作数类型 | 结果类型 | 语义 |
| ---- | ---------- | -------- | ---- |
| `ptr_lt(T, ptr1, ptr2)` | `ptr1`、`ptr2` 同为 `ptr<T>`，均为非 `nullptr` | `bool` | 指针值小于（`ptr1` 的抽象地址在 `ptr2` 之前） |
| `ptr_le(T, ptr1, ptr2)` | 同上 | `bool` | 指针值小于或等于 |
| `ptr_gt(T, ptr1, ptr2)` | 同上 | `bool` | 指针值大于 |
| `ptr_ge(T, ptr1, ptr2)` | 同上 | `bool` | 指针值大于或等于 |

序关系比较的约束：

- 两个操作数必须同为 `ptr<T>` 类型（`T` 由显式类型参数决定），且必须均为非 `nullptr` 的指针值；`nullptr` 参与序关系比较报告运行时错误 `TC_RE_NULL_POINTER_DEREFERENCE`。跨 `ptr<T>` 与 `ptr<U>`（`T ≠ U`）的比较报 `TC_CE_TYPE_MISMATCH`（静态语义拒绝）。
- 所有指针比较操作（等值与序关系）均使用专用 `ptr_eq`/`ptr_ne`/`ptr_lt`/`ptr_le`/`ptr_gt`/`ptr_ge` 指令，均带显式类型参数 `T`。通用 `eq`/`ne`/`lt`/`le`/`gt`/`ge` 不接受 `ptr<T>` 类型操作数。

#### 3.10.8 指针算术

指针算术通过专用指令进行，**禁止**通过 `add`/`sub` 等通用算术指令作用于 `ptr<T>` 值。所有指针算术指令以显式类型参数 `T`（所指类型）决定偏移的步长：偏移量 `n` 的单位是 `T` 类型的元素个数，实际地址移动量为 `n × sizeof_bits(T)` 位。

**`ptr_add`**

| 项目 | 规则 |
| ---- | ---- |
| 类别 | RHS（`operand`） |
| 类型参数 | `T` 须为 `void` 以外的完整类型，决定指针所指类型与偏移步长 |
| 操作数 | `ptr` 须为 `ptr<T>` 类型；`offset` 须为 `usize` 类型（非负偏移，向高位地址方向移动） |
| 结果类型 | `ptr<T>` |
| 执行语义 | 若 `ptr` 为 `nullptr`，报告 `TC_RE_NULL_POINTER_ARITHMETIC`；否则计算 `ptr + offset × sizeof_bits(T)` 位，返回新的 `ptr<T>` 值 |
| 边界 | `ptr_add` 不检查结果指针是否越界；越界指针的 `ptr_load`/`ptr_store` 行为为实现定义 |

**`ptr_sub`**

| 项目 | 规则 |
| ---- | ---- |
| 类别 | RHS（`operand`） |
| 类型参数 | `T` 须为 `void` 以外的完整类型，决定指针所指类型与偏移步长 |
| 操作数 | `ptr` 须为 `ptr<T>` 类型；`offset` 须为 `usize` 类型（非负偏移，向低位地址方向移动） |
| 结果类型 | `ptr<T>` |
| 执行语义 | 若 `ptr` 为 `nullptr`，报告 `TC_RE_NULL_POINTER_ARITHMETIC`；否则计算 `ptr - offset × sizeof_bits(T)` 位，返回新的 `ptr<T>` 值 |

#### 3.10.9 与其他特性的边界

| 特性 | 规则 |
| ---- | ---- |
| I/O | `write`/`writeln`/`read` 不接受 `ptr<T>` 类型 |
| `cast` | `cast(T, ptr_val)` 支持 `ptr<U>` → `ptr<T>` 的指针类型转换（仅当 `sizeof_bits(T) == sizeof_bits(U)` 且 `T` 与 `U` 均为 `void` 以外的完整类型时允许；非等宽转指针报 `TC_CE_TYPE_MISMATCH`）。`cast(ptr<T>, nullptr)` 合法：`nullptr` 无所指类型 `U`，由目标 `ptr<T>` 定型，不做等宽检查。`ptr<T>` 不可 `cast` 到整数/浮点类型 |
| `bitcast` | `bitcast(T, ptr_val)` 支持 `ptr<U>` ↔ `usize`/同宽整数的等宽位重解释，以及 `ptr<U>` ↔ `ptr<T>` 的等宽指针位重解释（等宽约束与 `bitcast` 通用规则一致，见 §6.6.6）；所得到的位模式再经目标类型解释后的行为见 §3.10.7（指针比较仅在同型 `ptr<T>` 上有定义） |
| 算术 / 移位 / 逻辑 / 按位 | 不接受 `ptr<T>` 类型操作数；指针算术仅可通过专用的 `ptr_add` / `ptr_sub` 进行（§3.10.8） |
| 指针算术 | `ptr_add(T, p, offset)` / `ptr_sub(T, p, offset)`（步长为 `sizeof_bits(T)` 位，偏移类型 `usize`）。不检查越界；越界指针解引用行为为实现定义 |
| 指针比较 | 等值比较 `ptr_eq(T, ptr1, ptr2)` / `ptr_ne(T, ptr1, ptr2)` 与序关系比较 `ptr_lt`/`ptr_le`/`ptr_gt`/`ptr_ge` 均带显式类型参数 `T`（§3.10.7）。序关系比较操作数必须为非 `nullptr`、同 `ptr<T>` |
| `memcopy_unsafe` | `memcopy_unsafe(T, dst, dst_idx, src, src_idx, length)` 按元素抽象位串从 `src` 区间拷贝到 `dst` 区间。两个指针操作数须同为 `ptr<T>` 类型；下标和 `length` 须为整数类型。不执行越界检查，越界拷贝行为为实现定义。空指针时报 `TC_RE_NULL_POINTER_DEREFERENCE`（§6.8.9） |
| `memblock` | `memblock<T, N>` 的元素类型 `T` 可为 `void` 以外的任意完整类型（§3.8.1） |
| 结构体字段 | 结构体字段类型可为 `ptr<T>`：`T` 为 `void` 以外的完整类型，或正在定义的本结构体（§3.9.1）；含 `ptr<T>` 字段的结构体整块赋值复制指针值，产生所指对象别名 |
| 模块 | `ptr<T>` 作为类型可直接使用，无需模块级定义；`ptr` 是关键字，不可用作标识符 |
| 函数参数 | 形参类型可为 `ptr<T>`（`T` 为 `void` 以外的任意完整类型）。函数体内对形参做 `ptr_load` 合法。对形参绑定本身赋值或作为 `read` 目标 → `TC_CE_PARAMETER_ASSIGNMENT`（§8.1.2）。经 `ptr_address` 取形参地址后再 `ptr_store` / `memcopy_unsafe` → `TC_CE_CONSTANT_ASSIGNMENT`（§6.8.3、§6.8.9）。`ptr<T>` 形参按值保存指针；对该指针值做 `ptr_store` 写入的是所指对象，合法性按所指外层绑定判定，不因指针本身是形参而改报 `PARAMETER_ASSIGNMENT` |
| `ptr_address` | 可用于 `var` / `static var` / 形参绑定的标识符；不可用于 `let` / `static let` 绑定或字面量。`ptr_address` 不是编译期常量，不可用于 `const_rhs` |

## 4. 程序结构与模块系统

一个 TC 编译单元恰好是一个 `.tc` 源文件，一个源文件恰好定义一个模块。未显式声明模式的文件为语法错误。`<模块名>.<成员名>` 与 `Self.<成员名>` 是静态名称限定形式，`.` 不是运行时成员访问运算符。

### 4.1 模块分层排序

模块内顶层构造必须按下表固定层级依次出现，跨层交错为语法阶段受限恢复错误 `TC_CE_MODULE_LAYER`（不得仅报笼统 `TC_CE_SYNTAX`）。各层内部允许空行和纯注释行，前四层全部完成后才可进入第五层。模块中不得超过一个模式指令。结构体类型名定义成功后即可被同模块后续构造引用。

| 层序 | 内容 | `#program` | `#lib` |
|------|------|-----------|--------|
| 1 | 模式指令 | `#program` | `#lib` |
| 2 | `import` 声明区（所有 import 连续出现，可为空） | | |
| 3 | `struct` 类型定义 | 不可带可见性修饰符 | 必须带 `public` / `private` |
| 4 | 值声明区 | `var` / `let`（禁止 `static`） | `static var` / `static let`（必须带 `static`） |
| 5 | 函数 / 语句区 | 顶层可执行语句，不可定义 `func` | `func` 函数定义（须带 `public` / `private`） |

### 4.2 模式对照

| 特性 | `#program` | `#lib` | 违反错误码 |
|------|-----------|--------|-----------|
| `func` 定义 | 禁止 | 允许（须带可见性） | `TC_CE_PROGRAM_MODE_MISUSE` |
| `static var` / `static let` | 禁止 | 允许（须带可见性） | `TC_CE_PROGRAM_MODE_MISUSE` |
| 顶层 `var` / `let` | 允许 | 禁止 | 语法拒绝 |
| `public` / `private` | 禁止 | 必须显式书写，无默认值 | `TC_CE_PROGRAM_MODE_MISUSE` / `TC_CE_MISSING_VISIBILITY` |
| `Self` | 禁止 | 允许 | `TC_CE_PROGRAM_MODE_MISUSE` |
| 顶层可执行语句 | 允许（入口） | 禁止 | 语法拒绝 |
| `goto` / `label` | 禁止 | 函数体内允许 | `TC_CE_LABEL_OUTSIDE_FUNCTION` / `TC_CE_GOTO_OUTSIDE_FUNCTION` |

**`#program` 语义**：从第一条语句按源序执行至文件末尾或首个运行时错误，无特殊 `main` 入口。声明必须位于第一条可执行语句之前，进入语句区后不得再声明。每次运行重新初始化全部可达库模块的 `static var`。

**`#lib` 语义**：只允许以下顶层构造（按上表层序排列）：

| 顶层构造 | 可见性 | 额外约束 |
|---------|--------|---------|
| `struct` | 必须 `public` / `private` | 位于 `static` 成员与 `func` 之前 |
| `static let` | 必须 `public` / `private` | 编译期常量（§5.2.1） |
| `static var` | 必须 `public` / `private` | 初始化器可为任意 §5.2.1 定义的单层编译期常量表达式（算术、按位、移位、比较、逻辑、`cast`/`bitcast`、`memblock` 构造器与结构体构造器），不得含 `funcall`；操作数仅可为字面量、当前源序中更早已成功初始化的 `Self` 成员（`static let` 与 `static var`），以及经导入限定解析到的公开 `static let` / `static var`；不得引用局部 `var`、函数形参或尚未完成初始化的成员 |
| `func` | 必须 `public` / `private` | 位于 `static` 成员之后；函数间顺序不限 |

每个 `static var` 在程序运行中对应一个模块静态存储槽，由宿主按源序初始化一次；所有导入者共享该槽，导入不复制状态。与 `static let` 在编译期求值内联不同，`static var` 的初始化器在程序准备阶段按运行时语义执行（指令级错误语义与 §6 一致），初始化成功后方可被本模块及导入者访问。任一静态成员初始化失败时整个程序准备失败。

### 4.3 `Self` 成员限定

`Self` 仅在 `#lib` 模块内有效，表示当前模块命名空间，不是值或运行时对象。函数体内访问本库成员须使用 `Self.<名>`。

| `Self.<名>` 解析目标 | 读写规则 |
|---------------------|---------|
| `static let` | 只读 |
| `static var` | 可读可赋值（含 `read` 目标） |
| `func` | 可调用 |

| 裸名使用场景 | 诊断 |
|-------------|------|
| 函数体内以裸名引用本库成员 | `TC_CE_FUNCTION_SCOPE_ACCESS` |
| 局部绑定 / 形参 | 使用裸名（合法） |

### 4.4 成员可见性

`#lib` 每个顶层成员必须显式标 `public` 或 `private`，无默认值。

| 修饰符 | 本模块 `Self.<名>` | 导入模块 `<模块>.<名>` |
|--------|-------------------|----------------------|
| `public` | ✅ 可访问 | ✅ 可访问 |
| `private` | ✅ 可访问 | ❌ `TC_CE_PRIVATE_MEMBER_ACCESS` |

| 公开成员类别 | 读写规则 |
|-------------|---------|
| `func` | 可调用 |
| `struct` | 可作为类型名与值构造器 |
| `static let` | 只读 |
| 标量 `static var` | 可读写，可作为 `read` 目标 |
| `memblock` / struct `static var` | 可读写，不可作为 `read`/`write`/`writeln` 整块目标 |

可见性仅由 `public` / `private` 修饰符决定，与成员名字符形式无关。局部 `var`/`let`、函数形参、标签、结构体字段声明（`let`/`var` 表示字段可变性，§3.9）均不是模块成员，不能带可见性修饰符。

### 4.5 模块导入（`import`）

`#program` 和 `#lib` 均可导入库模块。语法：`import <模块名>`（`identifier`）。

| 约束 | 规则 | 违反错误码 |
|------|------|-----------|
| 位置 | 模式指令之后、类型/值声明之前（第二层），连续出现 | `TC_CE_MODULE_LAYER` |
| 重复导入 | 禁止 | `TC_CE_DUPLICATE_IMPORT` |
| 名称冲突 | 导入名不得与本模块成员冲突 | `TC_CE_IMPORT_NAME_CONFLICT` |
| 目标存在 | 必须唯一定位 `xxx.tc` | `TC_CE_IMPORT_NOT_FOUND` |
| 目标模式 | 必须为 `#lib` | `TC_CE_IMPORT_NOT_LIB` |
| 路径歧义 | 不得多目标 | `TC_CE_IMPORT_AMBIGUOUS` |
| 循环导入 | 模块依赖图必须为 DAG | `TC_CE_CIRCULAR_IMPORT` |

导入名引入对目标模块命名空间的静态引用，不构造、复制或实例化模块。访问导入成员必须使用 `<模块名>.<成员名>` 限定，且该成员须为 `public`。TC 不支持导入别名、选择性导入或通配导入。

循环导入以模块依赖图判定：以模块为顶点、`import` 为边，必须为有向无环图。任一长度的循环（含自导入）均报 `TC_CE_CIRCULAR_IMPORT`，即使环中函数未被调用。在初始化 `static var` 或执行顶层语句之前须完成环检查。

准备程序时，宿主按依赖顺序处理全部可达导入库；同一模块对应全程序唯一的命名空间，所有导入者共享其 `static var` 槽。函数签名在分析函数体和顶层语句前完成收集，因此 `#lib` 中函数可调用后定义的函数；调用图限制见 §8.6。

## 5. 声明

### 5.1 变量定义（`var`）

#### 5.1.1 声明语义

`var` 声明的语法形态由附录 A 规定。**声明时必须初始化**：初始化器为普通 `rhs`，或用于接收非 `void` 返回值的专用 `funcall`。

| 项目 | 规则 |
| ---- | ---- |
| 初始化器 | 强制；`=` 与初始化器不可省略 |
| 缺初始化器 | 静态错误 `TC_CE_VAR_MISSING_INIT` |
| RHS | 字面量、已定义标识符、单个运算、`cast` 或 `bitcast`（见 §6.1.1）；须与声明类型一致 |
| 函数返回初始化 | 非 `void` `funcall` 可通过专用形态 `var <名>: <类型> = funcall(...)` 初始化新变量（§8.2）；`funcall` 不属于普通 RHS |
| 再赋值 | 首次引入之后，修改写作 `<identifier> = <rhs>` 或 `<identifier> = funcall(...)`，不写 `var`（§6.2） |

TC 不允许“先声明、后首次赋值”。`read` 也不能代替初始化器：目标变量必须先以带初始化器的 `var` 定义，`read` 仅覆盖当前值（§10.3）。

#### 5.1.2 语义与检查

- 当且仅当该条 `var` 语句执行成功后，变量持有初始化器求得的有效值（顶层、函数和块内均在定义行写入预先建立的固定槽位）。
- 每条 `var` 声明须经过语法/形态检查：缺 `=` 或初始化器 → `TC_CE_VAR_MISSING_INIT`（打印名 `VarMissingInitializer`）。此检查与控制流无关，亦不依赖数据流分析；不得仅报笼统 `TC_CE_SYNTAX`。
- 同一作用域内不可重复定义同名变量（作用域包括顶层、函数、`if`/`while` 块，以及 `then`/`else` 各自的互斥子块，见 §9.1、§7.1.4、§7.2.3）。跨类型值须先 `cast`；函数返回值则必须与接收类型严格相同。
- 声明带初始化器不等于该语句在所有路径上均已执行；完整的确定初始化规则见 §9.2 与 §7.3.4。

块内 `var` 的可见性和生命周期按 §9.1 处理；离开该块后引用其绑定属于未定义标识符错误。

### 5.2 常量定义（`let`）

使用 `let` 声明 不可变常量：

- RHS 必须 提供
- RHS 须为 §5.2.1 定义的单层编译期常量表达式
- `let` 声明类型是整个 RHS 的唯一期望结果类型；RHS 结果必须与声明类型完全一致，不执行隐式转换，具体检查与诊断见 §5.2.1
- 常量在编译期求值；使用处直接内联编译期结果，不生成运行时算术指令，亦不分配运行时变量槽（与 §9.2 一致）。源文件中 `let` 语句仍占一行，仅作为编译期声明
- `let` 的求值与可见性只由编译阶段和词法源序决定，不以运行时控制流是否经过该声明行为条件；合法 `goto` 绕过一条 `let` 不会使其在后续词法可见位置变为“未初始化”或不可用
- 每条 `let` 声明仍参与源级可达性分析（用于判定其后续语句是否可达），但不生成运行时指令
- 常量 不可 作为赋值语句的左值
- 在同一作用域内，常量名不可与变量名或其他常量名冲突。

#### 5.2.1 编译期常量表达式

`let` 的 RHS 可包含以下任一形式：

**原子表达式**：
- 整数字面量（`42`、`-128`、`0xFFu`）
- 浮点字面量（`3.14`、`2.71828f`、`1.0e-5`）
- 特殊浮点值（`inf`、`-inf`、`nan`）
- 布尔字面量（`true`、`false`）
- 空指针字面量（`nullptr`，§3.10.2）
- 此前已定义的 `let` 常量引用（`PI`、`MASK`）

**单个调用表达式**（每个操作数只能是上述原子表达式）：
- 算术运算：`add`/`sub`/`mul`/`div`/`mod`/`abs`/`neg`，可使用 §6.3 允许的 `wrap` 或 `ieee` 模式；浮点 `mod` 同样支持 strict / `ieee`
- 位运算：`and`/`or`/`xor`/`not`（按位）、`shl`/`shr`（移位）
- 比较运算：`eq`/`ne`/`lt`/`le`/`gt`/`ge`（浮点比较允许但不推荐，因浮点精度）
- 逻辑运算：`and`/`or`/`xor`/`not`（布尔）
- 转换：严格 `cast`、整数 `cast(..., truncate, ...)` 与等宽 `bitcast`
- memblock 构造器：`memblock(T, count: N, fill: v)` 和 `memblock(T, count: N, v0, …, vₙ)`（§3.8.3）；其中 `N` 须为合法的编译期 `usize` 常量（整数字面量或以 `usize` 为类型的 `let` / `static let` 标识符）；全部填充/逐值操作数必须也为编译期常量
- 结构体值构造器：`<结构体名>(字段: 常量操作数, …)`（或导入的 `<模块名>.<结构体名>(…)`），须满足 §3.9.2；每个字段实参必须是合法编译期常量操作数
- 指针宽度查询：`ptr_size(p)`（§3.10.5, §6.8.8）；`p` 须为 `ptr<T>` 类型的编译期常量（含 `nullptr` 或此前定义的 `let ptr<T>`）
- memblock `.count` 查询：`mb.count`，`mb` 须为声明了 `memblock<T, N>` 的绑定，返回值为 `N` 的编译期常量数学值（§3.8.5）

**声明类型闭合与检查顺序**：

1. 先完成 `const_rhs` 内部的名称、运算支持类型、模式、操作数类型和字面量检查。单个调用表达式的操作数期望类型仅由该调用的显式类型参数决定；外层 `let` 声明类型不向调用内部传播，也不改变 §6.6.1.1 的 `cast` / `bitcast` 字面量源类型规则。
2. RHS 为直接字面量时，以 `let` 声明类型作为 §3.6 的期望类型：符号性、类别或浮点后缀不符时报 `TC_CE_LITERAL_TYPE`，值不可表示时报 `TC_CE_LITERAL_OUT_OF_RANGE`。
3. RHS 为标识符时，名称解析后以该绑定的声明类型为结果类型。若绑定解析为 `var` 或函数参数，立即报 `TC_CE_CONSTANT_EXPRESSION`（"references runtime variable"），不比较结果类型，也不进入编译期求值。RHS 为单个调用表达式时，按该调用的自身规则确定结果类型。若结果类型与外层 `let` 声明类型不完全一致，报 `TC_CE_TYPE_MISMATCH`，定位到 RHS 的首个 Token。禁止因数值可表示而执行隐式窄化、加宽、符号性变换或整数/浮点转换。
4. 只有上述名称和类型检查全部成功后才进入编译期求值。因此“RHS 结果类型不匹配”先于同一 RHS 的常量溢出、除零或无效浮点操作诊断。

**约束**：
- 常量表达式不可 引用任何 `var` 变量
- 常量表达式不可 包含 `funcall`；函数体内的 `let` 亦不得引用参数或局部 `var`
- 常量表达式不可 引用自身或尚未定义的 `let`；此类引用在名称解析阶段被 `TC_CE_UNDEFINED_VARIABLE` 拦截
- 操作调用不可嵌套；复合计算须拆分为多条按源序定义的 `let`
- 由于只允许引用此前的 `let`，多常量循环依赖在语法可见性上不可形成，TC 不定义常量循环依赖错误；前向引用和自引用统一由 `TC_CE_UNDEFINED_VARIABLE` 处理
- 有符号严格常量算术运算或 `shl` 的溢出，在编译期视为 常量溢出错误 并终止编译
- 常量 `shl` / `shr` 的移位计数按其整数类型直接取数学值；值为负时视为 常量表达式错误 `TC_CE_CONSTANT_EXPRESSION` 并终止编译
- 严格浮点常量算术按 §6.3 的异常优先级求值：无效操作 → `TC_CE_CONSTANT_EXPRESSION`，除零 → `TC_CE_CONSTANT_DIV_ZERO`，上溢或下溢 → `TC_CE_CONSTANT_OVERFLOW`；浮点 `mod` 不产生上溢或下溢
- 常量表达式中整数 `div`/`mod` 的除数为 0，或浮点严格 `div`/`mod` 的最高优先级异常为除零，视为 常量除零错误 并终止编译
- 常量移位、转换、NaN 与模式合法性完全复用 §6.3～§6.6 的运行时规则

常量表达式的“形态与依赖合法性”先于求值短路检查：`and(bool, false, x)` 或 `or(bool, true, x)` 中的 `x` 仍必须是合法、可见且已求值的更早 `let bool`。运行时逻辑短路和 §6.5.2.2 的确定初始化读边裁剪不得用于掩盖 `let` 中的非法依赖、名称或类型错误。

块内 `let` 仍受 §9.1 的词法作用域约束。

#### 5.2.2 静态布尔条件与三态判定

“静态布尔条件”是结果类型为 `bool`，且整体符合本节“编译期常量表达式”定义的单层 RHS。其原子操作数只能是字面量，或在当前词法作用域可见、定义语句位于使用点之前且已成功求值的 `let`；不得把 `var` 的当前值或跨语句运行时结果当作常量传播。`if` / `while` 条件在类型检查通过后按本款做三态判定（交叉引用见 §7.1.1、§7.2.1）。

名称和类型检查完成后，对 `if`/`while` 条件执行以下三态判定：

  - 静态 `true`：RHS 合法且按本节共享常量语义求值为 `true`；仅 `then` 分支可达。
  - 静态 `false`：RHS 合法且求值为 `false`；仅 `else` 分支（如存在）可达。
  - `unknown`：RHS 不是合法的单层常量表达式，或含 `var` 等不能静态解析的操作数；`then` 与 `else` 分支均可达。

静态布尔判定只复用本节的表达式定义和 §6.3～§6.6 的共享语义，不建立第二套运算符白名单。形态归类如下（非穷尽列举运算符，仅固定判定出口）：

| 归类 | 典型形态 | 三态出口 |
| ---- | -------- | -------- |
| 可静态求值 | 布尔字面量；可见且更早的 `let bool`；结果为 `bool` 的整数/浮点比较；布尔逻辑运算；目标为 `bool` 的合法严格 `cast` | 求值为 `true` / `false` |
| 不可静态折叠 | 含 `var` / 形参等运行时操作数；其它非单层常量表达式形态 | `unknown`（两边均可达） |
| 非法或求值失败 | 前向 `let`、不可见 `let`、嵌套调用等（由更早阶段报错）；或形态合法但溢出/除零/无效浮点/`cast` 失败 | **不得**降级为 `unknown`；按既有映射终止编译 |
| 明确排除 | `bitcast`（不允许 `bool`）；整数 `truncate`（不能产生合法布尔条件） | 不构成合法静态布尔条件 |

三态判定与短路读边是两个独立分析：含 `var` 的条件始终为 `unknown`，即使短路语义可裁剪读取边。

前向 `let`、不可见 `let`、嵌套调用或其他非法形态在内部静态判定中不得被折叠；它们仍分别由更早的名称、语法或类型阶段报告错误，因此不参与可达性分析。若表达式形态合法但求值发生整数/浮点溢出、除零、无效浮点操作或严格转换失败，必须按本节既有映射报告 `TC_CE_CONSTANT_OVERFLOW`、`TC_CE_CONSTANT_DIV_ZERO`、`TC_CE_CONSTANT_EXPRESSION` 或 `TC_CE_CONSTANT_CAST_OVERFLOW` 并终止编译；不得降级为 `unknown`。

#### 5.2.3 浮点常量算术的精度规则

常量表达式中的浮点算术遵循以下规则：
1. 每条指令均按其显式类型参数执行：`float32` 使用 binary32，`float64` 使用 binary64。
2. 每条指令结束时立即按 roundTiesToEven 舍入；不得统一提升为 `float64` 中间精度。
3. strict / `ieee` 的结果与同一指令在运行时执行完全一致。
4. 常量求值器不得使用 FMA、扩展精度、FTZ 或 DAZ。

## 6. 表达式与运算

### 6.1 右值表达式与操作数

#### 6.1.1 右值表达式（RHS）

| 产生式               | 结果类型           | 说明                            |
| -------------------- | ------------------ | ------------------------------- |
| `identifier`         | 标识符已声明类型   | 须已定义；受源序可见性约束      |
| `integer_literal`    | 由左侧变量类型决定 | 须满足字面量符号性及范围约束    |
| `float_literal`      | 由 `f`/`F` 后缀决定 | 无后缀为 `float64`，有后缀为 `float32`；须与上下文一致 |
| `float_special`      | 由左侧变量类型决定 | `inf`/`-inf`/`nan`              |
| `bool_literal`       | `bool`             | `true` 或 `false`               |
| `binary_arith_expr`  | 第一参数类型       | 五种双目算术运算（含浮点）      |
| `unary_arith_expr`   | 第一参数类型       | 两种单目算术运算（含浮点）      |
| `bitwise_expr`       | 第一参数类型       | 按位 `and`/`or`/`xor`（仅整数） |
| `unary_bitwise_expr` | 第一参数类型       | 按位 `not`（仅整数）            |
| `shift_expr`         | 第一参数类型       | `shl`/`shr` 移位运算（仅整数）  |
| `compare_expr`       | `bool`             | 六种比较运算（整数+浮点，含显式类型参数）；不接受 `ptr<T>` 类型 |
| `ptr_eq_compare_expr` | `bool`         | `ptr_eq`/`ptr_ne` 指针等值比较，带显式类型参数 `T`：`ptr_eq(T, ptr1, ptr2)`（§3.10.7） |
| `binary_logic_expr`  | `bool`             | `and`/`or`/`xor` 逻辑运算（布尔） |
| `unary_logic_expr`   | `bool`             | `not` 逻辑运算（布尔）          |
| `cast_expr`          | 第一参数类型       | 类型转换                        |
| `bitcast_expr`       | 第一参数类型       | 等宽位重解释                    |
| *memblock_count_access* | `usize`            | 从 memblock 读取 `.count` 长度头部，返回编译期常量值（§3.8.5） |
| `memblock_constructor` | `memblock<T, N>` | 两种带长度构造器（§3.8.3）：`count:` `fill:` 填充 / 逐值列表 |
| `struct_constructor` | 对应结构体类型     | 命名字段值构造器（§3.9.2）       |
| `nullptr_literal`    | 由上下文期望类型决定 | `nullptr` 空指针字面量，与任意 `ptr<T>` 兼容（§3.10.2） |
| `ptr_load_expr`       | 类型参数 `T` | 从 `ptr<T>` 解引用读取：`ptr_load(T, ptr)`（§3.10.3, §6.8.2） |
| `ptr_address_expr`    | `ptr<T>`            | 从变量标识符取地址：`ptr_address(T, ident)`（§3.10.3, §6.8.4） |
| `ptr_add_expr`        | `ptr<T>`            | 指针加法：`ptr_add(T, ptr, offset)`，偏移单位为 `sizeof_bits(T)` 位，`offset` 为 `usize`（§3.10.8） |
| `ptr_sub_expr`        | `ptr<T>`            | 指针减法：`ptr_sub(T, ptr, offset)`，向低位地址方向偏移 `offset × sizeof_bits(T)` 位（§3.10.8） |
| `ptr_compare_expr`    | `bool`              | 指针序关系比较：`ptr_lt`/`ptr_le`/`ptr_gt`/`ptr_ge`，皆带显式类型参数 `T`（§3.10.7） |
| `ptr_size_expr`       | `usize`             | 返回 `ptr<T>` 的所指类型宽度 `sizeof_bits(T)`：`ptr_size(T, ptr)`，合法 `const_operand`（§6.8.8） |

`funcall` 不属于普通 `rhs`。它只在 `var <名>: <类型> = funcall(...)`、`<identifier> = funcall(...)` 或独立 `funcall(...)` 三种专用语法位置出现；其合法位置由被调函数返回类型决定（§8.2.3）。

字段读取 `<基址>.<字段名>` 属于 `operand`（§6.1.2），因此也可作为标识符类 RHS；它不是独立的运算产生式。

#### 6.1.2 操作数（Operand）

| 形式              | 约束                                                         |
| ----------------- | ------------------------------------------------------------ |
| *identifier*      | 先按词法作用域解析绑定并检查类型：解析为运行时 `var` 或参数时，必须在当前程序点已确定初始化（参数在函数入口已初始化，§9.2）；解析为 `let` 时，必须在使用点可见且已成功完成编译期求值，随后直接内联，不参与确定初始化检查 |
| *qualified_identifier* | `Self.<名>`（仅 `#lib`）：按 §4.3 / §8.4.1 解析为本库 `static let` / `static var`；只读或可写规则与绑定种类一致；`static var` 在程序准备成功后已确定初始化 |
| *imported_member_name* | `<模块名>.<名>`：按 §4.4 / §4.5 解析为已导入库的公开 `static let` / `static var`；可见性与读写规则同上 |
| *field_access*    | `<基址>.<字段名>`：基址为上述标识符形式之一，且其类型为结构体类型；字段名必须属于该结构体；结果类型为字段声明类型；对运行时 `var` 基址须确定初始化（§3.9.5） |
| *integer_literal* | 须满足字面量约束                                             |
| *float_literal*   | 须满足字面量约束                                             |
| *float_special*   | `inf`/`-inf`/`nan`，仅用于浮点类型上下文                     |
| *bool_literal*    | 仅用于 `bool` 类型上下文                                     |
| *nullptr*        | `nullptr` 空指针字面量，与任意 `ptr<T>` 兼容；不参与确定初始化检查（自身恒为已定义字面量） |

因此，凡规范引用 `operand` 的位置——包括运算、转换、`funcall` 命名实参、`return` 和输出——均可使用符合本行规则的 `let` 标识符（含经 `Self.` / 导入限定解析到的 `static let`），以及结构体字段读取。只有运行时绑定读取才执行 `TC_CE_UNINITIALIZED_VARIABLE` 检查；编译期 `let` / `static let` 永不因不属于 `IN` 集合而触发该错误。

不支持 嵌套：操作数不可为算术表达式、`cast`、`bitcast` 或 `funcall` 调用。复合计算须拆分为多条语句。结构体字段访问支持嵌套（如 `a.b.c`），前提是每层 `.<字段名>` 的左侧结果类型均为结构体类型。

### 6.2 赋值语句

对已定义变量重新赋值时 省略 `var`。右侧可为普通 `<rhs>` 或 `<funcall>`，结果类型须与变量已声明类型 完全一致。首次引入该名必须已通过 §5.1 的 `var … = …` 完成，不存在「无初始化器的声明 + 本赋值作为首次写入」写法。

赋值左侧可以是：

1. **整绑定目标**：裸标识符、`Self.<名>` 或 `<模块名>.<名>`（规则同前）；
2. **字段目标**：`<整绑定目标>.<字段名>`（§3.9.5）。

**约束**：
- 整绑定赋值左侧按当前值作用域解析：函数内普通查找失败但命中 §8.4.1 的本库顶层成员名索引时报告 `TC_CE_FUNCTION_SCOPE_ACCESS`；除此之外未解析到值绑定时报告 `TC_CE_UNDEFINED_VARIABLE`；解析为 `let` 或 `static let`（含经 `Self.` / 导入限定解析到的只读绑定）时报告 `TC_CE_CONSTANT_ASSIGNMENT`；解析为函数参数时报告 `TC_CE_PARAMETER_ASSIGNMENT`；只有解析为 `var` 或可写 `static var` 才继续类型与确定初始化检查。全局函数名不属于值绑定，不能成为赋值目标。
- 字段赋值额外遵守 §3.9.5：外层为 `let`/`static let` 时一律 `TC_CE_CONSTANT_ASSIGNMENT`；外层可写但字段为 `let` 时报告 `TC_CE_STRUCT_IMMUTABLE_FIELD`；外层为形参时报告 `TC_CE_PARAMETER_ASSIGNMENT`。字段赋值的 RHS 结果类型须与**字段**声明类型完全一致（不是整个结构体类型）。
- 赋值目标必须在当前程序点已确定初始化；赋值不能补救被控制流绕过的声明初始化（§9.2）。
- 赋值 RHS 为普通 `<rhs>` 或 `<funcall>`（字段赋值同样允许二者，只要结果类型与字段类型一致）。`funcall` 只能作为 `=` 右侧的初始化器/赋值值出现，或作为独立语句（`void` 返回时）；不得出现在任何运算的实参位置（含另一个 `funcall` 的命名实参、`write`/`writeln` 操作数、`return` 操作数等）。非 `void` `funcall` 的返回类型须与赋值目标声明类型严格相同；`void` `funcall` 不得用于赋值（应使用独立 `funcall(...)` 语句）。若 `funcall` 发生运行时错误，目标变量保留原值，随后程序终止。

### 6.3 算术运算

#### 6.3.1 运算模式总览

静态语义按操作 × 类型 × 模式矩阵判定：

| 运算 | 类型 | 合法模式 |
| ---- | ---- | -------- |
| `add`/`sub`/`mul`/`neg` | 有符号整数 | strict（无关键字）、`wrap` |
| `add`/`sub`/`mul`/`neg` | 无符号整数 | 固定模 `2^n`；不接受模式关键字 |
| `shl` | 全部整数 | strict（无关键字）、`wrap` |
| `div`/`mod`/`abs`/`shr` | 全部整数 | 无模式关键字 |
| `add`/`sub`/`mul`/`div`/`mod` | 浮点 | strict（无关键字）、`ieee` |
| `abs`/`neg` | 浮点 | 无模式关键字；纯符号位操作 |
| 比较、逻辑、位运算 | 对应合法类型 | 无模式关键字 |

组合不在上表时报告 `TC_CE_TYPE_MISMATCH` 或 `TC_CE_MODE_MISMATCH`。附录 A 已排除的形态属语法拒绝（`TC_CE_SYNTAX`）；`let` 的 `const_shift_expr` 接受候选 `mode`（不合法组合报 `TC_CE_MODE_MISMATCH`）；运行时 `wrap_shift_expr` 只接受 `shl`（`shr` 无 `wrap` 形态）。浮点 `wrap` 和无符号冗余 `wrap` 不支持。

**指针类型排除**：指针类型（`ptr<T>`）不参与任何通用标量算术运算（`add`/`sub`/`mul`/`div`/`mod`/`abs`/`neg`）、按位运算（`and`/`or`/`xor`/`not`）、移位运算（`shl`/`shr`）、通用比较运算（`eq`/`ne`/`lt`/`le`/`gt`/`ge`）或逻辑运算（`and`/`or`/`xor`/`not` 的重载布尔形式）。指针算术仅可通过专用的 `ptr_add` / `ptr_sub` 指令进行（§3.10.8）；指针比较仅可通过专用等值比较指令 `ptr_eq` / `ptr_ne` 和专用序关系比较指令 `ptr_lt`/`ptr_le`/`ptr_gt`/`ptr_ge` 进行（§3.10.7）。`ptr<T>` 值用于上述标量运算时报 `TC_CE_TYPE_MISMATCH`。

#### 6.3.2 严格模式（默认）

**整数严格模式**（参见 §6.3.4～§6.3.6）：
- 有符号 `add`/`sub`/`mul`/`neg` 结果超范围 → 整数溢出错误
- 有符号 `abs(INT_MIN)` → 整数溢出错误
- `shl` 结果超范围 → 整数溢出错误
- `div` 除数为 0 → 除零错误；`div(INT_MIN, -1)` → 整数溢出错误

**浮点严格模式**（IEEE 754 异常检测）：
- 上溢 → 浮点溢出错误
- 下溢 → 浮点下溢错误
- 除零 → 除零错误
- 无效操作（0/0、∞−∞、0×∞） → 无效操作错误
- `nan` 参与 `add`/`sub`/`mul`/`div`/`mod` → 无效操作错误
- 浮点 `mod` 的被除数为无穷，或被除数和除数同时为零 → 无效操作错误；有限非零数对零取模 → 除零错误

浮点执行环境固定如下：

- `float32` 每条指令按 IEEE 754 binary32 执行并立即舍入；`float64` 按 binary64 执行并立即舍入。
- 固定舍入模式为 roundTiesToEven；不提供运行时舍入模式切换。
- 禁止保留超出目标类型的中间精度，禁止将独立 `mul`/`add` 融合为 FMA。
- 必须保留非规格化数；禁止 FTZ（flush-to-zero）与 DAZ（denormals-are-zero）。
- 下溢采用 tininess-after-rounding：结果舍入到目标类型后为微小结果且本次舍入不精确时才触发；精确的非规格化结果不触发下溢。有限结果舍入为无穷时定义为上溢。
- 同一指令同时满足多个异常条件时，只报告最高优先级：`TC_RE_FLOAT_INVALID` → `TC_RE_DIVISION_BY_ZERO` → 浮点溢出错误 → 浮点下溢错误。

为避免依赖宿主浮点异常标志，`add`/`sub`/`mul`/`div` 的特殊值分类必须按下表判定。表中“NaN”包含 quiet NaN 和由 `bitcast` 构造的 signaling-NaN 位模式；TC 不向程序暴露 signaling 状态。

| 运算 | 无效操作（最高优先级） | 除零 | 其他结果 |
| ---- | ---------------------- | ---- | -------- |
| `add` | 任一输入为 NaN；符号相反的两个无穷相加 | — | 遵循 IEEE 754 加法 |
| `sub` | 任一输入为 NaN；同号的两个无穷相减 | — | 遵循 IEEE 754 减法 |
| `mul` | 任一输入为 NaN；零与无穷相乘 | — | 遵循 IEEE 754 乘法 |
| `div` | 任一输入为 NaN；零除以零；无穷除以无穷 | 有限非零值除以正零或负零 | 遵循 IEEE 754 除法 |
| `mod` | 按 §6.3.7 的完整分类 | 按 §6.3.7 的完整分类 | 按 §6.3.7 的精确余数语义 |

strict 指令必须先完成上述分类，再以无限精度数学结果和目标格式正确舍入判定上溢/下溢；不得直接依赖 C99 表达式是否设置宿主 `fenv` 标志。发生运行时错误时，该指令没有结果提交。

#### 6.3.3 IEEE 754 标准模式（`ieee`）

仅用于浮点 `add`/`sub`/`mul`/`div`/`mod`。执行精度、舍入方式、非规格化数与禁止 FMA 的规则同 §6.3.2，但异常不终止程序。

对浮点 `mod` 而言，`ieee` 只表示沿用本节的非终止异常处理与 canonical quiet NaN 结果；取模核心仍是 §6.3.7 定义的“商向零截断”语义，不采用将商舍入到最近整数（中点取偶数）的余数语义。

| 场景       | IEEE 754 行为                   | 返回值           |
| ---------- | ------------------------------- | ---------------- |
| 上溢       | 舍入到 ±∞                       | ±`inf`           |
| 下溢       | 返回 0 或非规格化数             | `0` 或非规格化值 |
| 除零       | 返回 ±∞                         | ±`inf`           |
| 无效操作   | 返回 canonical quiet NaN         | `nan`            |
| `nan` 传播 | 算术输入含 NaN 时返回 canonical quiet NaN | `nan`      |

上表的“除零返回 ±inf”仅适用于浮点 `div`。浮点 `mod` 的除数为零时没有可表示的余数：`ieee` 模式返回 canonical quiet NaN；strict 模式下，`0 mod 0` 按无效操作处理，有限非零数对零取模按除零处理。浮点 `mod` 的其余特殊值规则见 §6.3.7。

符号按 IEEE 754-2019 确定（除法的无穷结果符号为两操作数异或）。无效操作和 NaN 输入统一返回**正号** canonical quiet NaN（`float32`=`0x7FC00000`，`float64`=`0x7FF8000000000000`），不传播输入符号/payload。通过 `bitcast` 构造的其他 NaN payload 参与 `ieee` 算术后仍规范化为 canonical quiet NaN。

#### 6.3.4 整数回绕模式（`wrap`）

**整数 `wrap`**：
- 按模 `2^n` 回绕，不报错
- 仅用于有符号 `add`/`sub`/`mul`/`neg`，以及有符号或无符号 `shl`
- 无符号 `add`/`sub`/`mul`/`neg` 已固定采用模 `2^n` 语义，不接受冗余 `wrap`
- `div`/`mod`/`abs`/`shr` 不接受 `wrap`
- 浮点类型不接受 `wrap`；位模式混合须先 `bitcast` 为等宽整数

#### 6.3.5 整数有符号运算（`int8`～`int64`、`isize`）

| 指令                  | 语义                                                         |
| --------------------- | ------------------------------------------------------------ |
| `add` / `sub` / `mul` | 和 / 差 / 积；严格模式超范围报错，wrap 回绕                  |
| `div`                 | 商，向零截断（同 C 有符号 `/`）；除数为 0 → 除零错误；商不可表示 → 整数溢出错误 |
| `mod`                 | 余数符号与 被除数 相同；除数为 0 → 除零错误。 |
| `abs`                 | 返回绝对值；`INT_MIN` 时严格模式报错                         |
| `neg`                 | 返回相反数；`INT_MIN` 时严格模式报错，wrap 回绕              |

**特殊情形**（\(b \neq 0\)）：

| 表达式                   | 结果 | 说明                                                        |
| ------------------------ | ---- | ----------------------------------------------------------- |
| `div(T, INT_MIN(T), −1)` | —    | 整数溢出错误（数学商 \(+2^{n-1}\) 不可在 `<T>` 中表示） |
| `mod(T, INT_MIN(T), −1)` | `0`  | 余数为 0，不报错                                        |
| `abs(T, INT_MIN(T))`     | —    | 整数溢出错误                                            |
| `neg(T, INT_MIN(T))`     | —    | 严格模式时 整数溢出错误                                 |

#### 6.3.6 整数无符号运算（`uint8`～`uint64`、`usize`）

| 指令                  | 语义                                                |
| --------------------- | --------------------------------------------------- |
| `add` / `sub` / `mul` | 和 / 差 / 积；超范围 → 按模 2^n 回绕                |
| `div`                 | 数学整数商；除数为 0 → 除零错误                 |
| `mod`                 | 余数满足 `0 ≤ 余数 < 除数`；除数为 0 → 除零错误 |
| `abs`                 | 恒等返回                                            |
| `neg`                 | 返回 `0 - 操作数`，按模 2^n 回绕                    |

无符号算术天然采用模 2^n 回绕，其位级结果与有符号 `wrap` 模式下的同宽算术一致。

#### 6.3.7 浮点运算（`float32`、`float64`）

| 指令                  | 语义                                                         |
| --------------------- | ------------------------------------------------------------ |
| `add` / `sub` / `mul` | 和 / 差 / 积；strict 检测异常，`ieee` 返回 inf/nan           |
| `div`                 | 商；strict 检测除零/无效操作，`ieee` 返回 ±inf/nan           |
| `mod`                 | 商向零截断的余数；strict 检测除零/无效操作，`ieee` 对异常返回 nan |
| `abs`                 | 清除符号位；包括 NaN、无穷和零在内均不报错，不接受模式关键字 |
| `neg`                 | 翻转符号位；包括 NaN、无穷和零在内均不报错，不接受模式关键字 |

`abs`/`neg` 是纯位操作：仅修改符号位并保留其余位，包括通过 `bitcast` 构造的 NaN payload。它们不属于可能触发浮点异常的算术指令。

**浮点 `mod` 的精确语义**：

设操作数为同一浮点类型 `T` 的 `a` 与 `b`。当二者均为有限值且 `b != ±0` 时，先在数学实数域定义

```text
q = trunc(a / b)        ; 向零截断为数学整数
r = a - q * b
```

结果为 `r` 在 `T` 中的精确表示。实现不得先以 `T` 执行 `a / b` 再相乘相减，因为中间商可能溢出或舍入，从而改变余数。对于同一 binary32/binary64 类型的两个有限输入，上述余数可由该类型精确表示，因此浮点 `mod` 本身不产生上溢或下溢。

- 非零结果满足 `abs(r) < abs(b)`，且符号与 `a` 相同；`b` 的符号不影响结果符号。
- 结果为零时保留 `a` 的符号：`mod(T, -0.0, b)` 与负数恰好整除均返回 `-0.0`。
- `a` 有限且 `b` 为正或负无穷时，结果按位等于 `a`。
- 任一输入为 NaN，或 `a` 为正/负无穷时：strict 报 `TC_RE_FLOAT_INVALID`；`ieee` 返回 canonical quiet NaN。
- `a` 与 `b` 同时为零时：strict 报 `TC_RE_FLOAT_INVALID`；`ieee` 返回 canonical quiet NaN。
- `a` 为有限非零值且 `b` 为正或负零时：strict 报 `TC_RE_DIVISION_BY_ZERO`；`ieee` 返回 canonical quiet NaN。
- 异常优先级继续遵循 §6.3.2：NaN 或无穷被除数导致的无效操作优先于零除数诊断。

### 6.4 位运算

本章定义整数位级操作，包括按位逻辑运算与移位运算。`and`、`or`、`xor`、`not` 均由类型参数重载：类型参数为整数时执行本章的按位运算，类型参数为 `bool` 时执行 §6.5 的布尔逻辑运算。浮点类型与指针类型（`ptr<T>`）不参与这组重载。指针位模式操作须先经 `bitcast` 转为等宽整数。

> **约束**：移位计数必须与被移位数类型相同；不同位宽须先 `cast`。浮点不支持位运算。

移位计数不掩码，直接取其数学值：`k < 0` 报 `TC_RE_NEGATIVE_SHIFT_COUNT`；`k >= n` 时 strict `shl` 报溢出，`wrap shl` / `shr` 返 `0`。若需取模移位，程序员可显式使用 `mod` 运算。

#### 6.4.1 按位逻辑运算（`and`、`or`、`xor`、`not`）

#### 6.4.1.1 总览

| 运算  | 名称     | 操作数数量 | 适用类型                     | 语义                             |
| ----- | -------- | ---------- | ---------------------------- | -------------------------------- |
| `and` | 按位与   | 2          | 整数类型（`int8`～`uint64`） | 每位：两操作数均为 1 → 1，否则 0 |
| `or`  | 按位或   | 2          | 整数类型                     | 每位：任一操作数为 1 → 1，否则 0 |
| `xor` | 按位异或 | 2          | 整数类型                     | 每位：两操作数不同 → 1，相同 → 0 |
| `not` | 按位非   | 1          | 整数类型                     | 每位取反                         |

#### 6.4.1.2 语义规则

1. 将操作数视为 无符号位模式（有符号数按二进制补码解释）。
2. 对每一位执行对应的逻辑操作。
3. 结果按目标类型 `T` 解释（有符号按补码回译，无符号直接取值）。

**溢出**：按位运算结果天然限制在 `T` 的位宽内，不会溢出，因此不支持 `wrap` 或 `truncate` 模式。附录 A 未为运行时或常量按位运算提供模式参数位置，写入这些关键字不符合 EBNF，报告 `TC_CE_SYNTAX`。

**操作数约束**：两操作数必须与 `T` 一致（整数）。`T` 为 `bool` 时由逻辑运算产生式解析（§6.5）；`T` 为浮点时报 `TC_CE_SYNTAX`。

#### 6.4.2 移位运算（`shl`、`shr`）

移位运算仅适用于整数类型。**被移位数与移位计数必须为相同类型 `T`**。移位计数按 `T` 的数值语义解码并直接取其数学值 `k`：有符号 `T` 按二进制补码解码，无符号 `T` 按非负整数解码。TC 不对 `k` 掩码，也不把负数按无符号位模式重解释。

`shl` 与 `shr` 共享以下前置检查：

1. 若 `k < 0`，立即触发 `TC_RE_NEGATIVE_SHIFT_COUNT`；
2. 仅当 `k >= 0` 时，才继续判定 `k >= n`、严格溢出或回绕结果。

因此负移位计数错误的优先级高于 `shl` 的整数溢出检查，且不受 strict / `wrap` 模式影响。无符号移位计数在类型上恒为非负，不会触发本错误。

`k >= n` 是 TC 已定义的语言分支：strict `shl` 报整数溢出，`wrap shl` 与 `shr` 返回 `0`。实现不得先执行宿主 C99 移位再修正结果，不得采用宿主硬件的计数掩码，也不得泄漏 C99 对该情形的未定义行为。

#### 6.4.2.1 左移（`shl`）

- **适用类型**：整数类型（`int8`～`uint64`）。
- **模式**：默认 strict；可选 `wrap`（语法位置见附录 A）。
- **语义**：
  - 按 §6.4.2 的共享规则取移位计数的数学值 `k`；`k < 0` 时触发 `TC_RE_NEGATIVE_SHIFT_COUNT`。
  - 若 `k >= n`（`n` 为 `T` 的位宽）：
    - 严格模式：视为 整数溢出错误。
    - 回绕模式：所有位被移出，结果为 `0`。
  - **严格模式**（`k < n`）：
    - 计算数学结果：`result_math = 被移位数 * 2^k`
    - 若 `result_math` 超出 `T` 的可表示范围 → 整数溢出错误。
    - 否则存储结果。
  - **回绕模式**（`k < n`）：
    - 取 `(被移位数 * 2^k)` 的低 `n` 位位模式，按 `T` 解释。不报错。

#### 6.4.2.2 右移（`shr`）

- **适用类型**：整数类型。
- **模式**：无模式关键字（永不溢出）；语法见附录 A。
- **语义**：
  - 按 §6.4.2 的共享规则取移位计数的数学值 `k`；`k < 0` 时触发 `TC_RE_NEGATIVE_SHIFT_COUNT`。
  - 若 `k >= n`，结果为 `0`。
  - **有符号类型**（`int*`）：执行 算术右移——高位补符号位。
  - **无符号类型**（`uint*`）：执行 逻辑右移——高位补 `0`。

当 `0 ≤ k < n` 时，右移还可等价地形式化为：无符号值取 `floor(x / 2^k)`；有符号非负值同样取 `floor(x / 2^k)`；有符号负值取 `floor(x / 2^k)`（向负无穷方向取整）。当 `k >= n` 时统一返回 `0` 是优先级更高的 TC 特例，因此不延续负数算术右移的符号填充结果。

#### 6.4.3 位运算与常量表达式

`let` 常量表达式允许使用全部合法位运算。`shl` 可使用 strict 或 `wrap`；strict 溢出映射为常量溢出错误，`wrap` 与运行时一样保留低位。常量求值期间若移位计数的数学值为负，在编译期报 `TC_CE_CONSTANT_EXPRESSION`；不延迟到运行时，也不映射为常量溢出。其余规则与 §5.2、§6.4.1、§6.4.2 完全一致。

### 6.5 比较运算与逻辑运算

#### 6.5.1 比较运算

#### 6.5.1.1 比较运算总览

所有比较运算统一支持整数和浮点类型。显式类型参数 `T` 同时是两个操作数各自的期望类型：

- 接受 两个类型均严格等于 `T` 的操作数（整数或浮点）；“两个操作数彼此同类型”但二者都不等于 `T` 仍然非法
- 返回 `bool` 类型值
- **整数比较**不涉及 `wrap` / `truncate` 模式关键字
- **浮点比较**使用 IEEE 754 普通比较谓词（NaN 为 unordered），不使用 `totalOrder`；仅接受无模式形式。
- 不产生溢出（比较本身无算术溢出风险）

`compare_expr` 仅接受整数或浮点类型参数，无模式位置。`eq(bool, ...)` 或带 `ieee` 的形态属语法拒绝（`TC_CE_SYNTAX`）。标识符操作数类型不等于 `T` 时报 `TC_CE_COMPARISON_TYPE_MISMATCH`（即使两操作数同类型也不降级）。字面量不兼容时使用 `TC_CE_LITERAL_TYPE` / `TC_CE_LITERAL_OUT_OF_RANGE`。

此外，`ptr<T>` 类型支持专用等值比较：`ptr_eq(T, ptr1, ptr2)` 与 `ptr_ne(T, ptr1, ptr2)`，两个操作数同为 `ptr<T>`，比较指针值相等性（指向同一对象或同为 `nullptr`）。`nullptr` 之间的等值比较结果为 `true`；非空指针与 `nullptr` 比较为 `false`。通用 `eq`/`ne` 不接受 `ptr<T>` 类型操作数。

指针序关系比较（`<`/`>`/`<=`/`>=`）通过专用指令 `ptr_lt` / `ptr_le` / `ptr_gt` / `ptr_ge` 进行，需显式类型参数 `T`，且操作数必须为非 `nullptr` 的同型 `ptr<T>`（详见 §3.10.7、§6.8.7）。

| 运算 | 名称     | 语义     |
| ---- | -------- | -------- |
| `eq` | 等于     | `a == b` |
| `ne` | 不等于   | `a != b` |
| `lt` | 小于     | `a < b`  |
| `le` | 小于等于 | `a <= b` |
| `gt` | 大于     | `a > b`  |
| `ge` | 大于等于 | `a >= b` |

#### 6.5.1.2 语义规则

**整数比较**：
- 有符号类型按二进制补码解释后的数学值比较
- 无符号类型按非负整数值比较
- 混合符号性比较须先 `cast` 统一类型

**浮点比较**：
- `eq(+0.0, -0.0)` 为 `true`，`ne(+0.0, -0.0)` 为 `false`
- `nan` 与任何值（包括自身）执行 `eq`/`lt`/`le`/`gt`/`ge` 均返回 `false`，执行 `ne` 返回 `true`
- 上一规则同样适用于由 `bitcast` 构造的任意 NaN 位模式；比较不触发 strict 运行时错误，也不修改操作数位模式
- 本组指令不区分 NaN payload，也不提供总序；若需比较位模式，先 `bitcast` 为等宽整数

由上述规则，检测 NaN 的惯用写法是 `ne(float64, x, x)`；`eq(float64, x, nan)` 始终为 `false`，不能用于检测。

#### 6.5.2 逻辑运算

#### 6.5.2.1 逻辑运算总览

所有逻辑运算：
- 接受 `bool` 类型操作数
- 返回 `bool` 类型值
- 不涉及 `wrap` / `truncate` 模式
- 不产生溢出

逻辑产生式要求类型参数为 `bool`，无模式位置。带模式关键字或不符合产生式的形态属语法拒绝（`TC_CE_SYNTAX`）。操作数不是 `bool` 时报类型或字面量错误。

| 运算  | 名称   | 操作数数量 | 语义                                            |
| ----- | ------ | ---------- | ----------------------------------------------- |
| `and` | 逻辑与 | 2          | 两操作数均为 `true` 时返回 `true`，否则 `false` |
| `or`  | 逻辑或 | 2          | 任一操作数为 `true` 时返回 `true`，否则 `false` |
| `xor` | 逻辑异或 | 2        | 两操作数不同时返回 `true`，相同时返回 `false`   |
| `not` | 逻辑非 | 1          | 操作数为 `true` 时返回 `false`，否则 `true`     |

#### 6.5.2.2 短路求值

**`and` 短路规则**：
- 左操作数为 `false` 时，不计算 右操作数，直接返回 `false`
- 左操作数为 `true` 时，计算右操作数并返回其值

**`or` 短路规则**：
- 左操作数为 `true` 时，不计算 右操作数，直接返回 `true`
- 左操作数为 `false` 时，计算右操作数并返回其值

**`xor` 求值规则**：
- `xor` 不短路，始终先读取左操作数，再读取右操作数，然后判断二者是否不同。
- 确定初始化分析必须记录两个操作数的读取；即使左操作数是字面量或已求值的 `let bool`，也不得裁剪右操作数读取边。

确定初始化分析处理短路语义时：当左操作数是布尔字面量，或是在当前词法作用域可见、定义语句位于使用点之前且已求值的 `let bool` 时，使用其编译期值判定右操作数不可达：`false and RHS` 与 `true or RHS` 均豁免 RHS 的变量确定初始化检查。左操作数为 `var` 时不做值推测，保守认为右操作数可达。

被短路排除的 RHS 不触发 `TC_CE_UNINITIALIZED_VARIABLE`，但仍必须通过词法、语法、名称、类型、操作数数量与模式检查；前向或不可见 `let` 仍按名称解析规则报 `TC_CE_UNDEFINED_VARIABLE`。

### 6.6 类型转换

#### 6.6.1 三种转换形式

| 形式 | 语义 | 类型约束 |
| ---- | ---- | -------- |
| `cast(T, operand)` | 数值转换 | 整数、浮点、`bool`；按本章做范围检查与舍入 |
| `cast(T, truncate, operand)` | 保留低位的整数缩窄 | 仅整数→更窄整数 |
| `bitcast(T, operand)` | 位模式不变的等宽重解释 | 等宽整数/浮点；`bool` 不参与 |

三种形式互不替代。

#### 6.6.1.1 字面量操作数的源类型

标识符操作数的源类型是其声明类型。字面量作为转换操作数时按下列规则唯一确定源类型：

| 上下文 | 字面量 | 源类型规则 |
| ------ | ------ | ---------- |
| `cast` | 无后缀整数 | `int64`；数值必须先在 `int64` 范围内 |
| `cast` | `u`/`U` 整数 | `uint64` |
| `cast` | 浮点 | `f`/`F` 后缀为 `float32`，无后缀为 `float64`；`inf`/`-inf`/`nan` 以目标类型为源类型 |
| `cast` | 布尔 | `bool` |
| `bitcast` | 整数 | 源位宽取目标位宽，后缀决定有/无符号；字面量必须能由该同宽整数类型表示 |
| `bitcast` | 普通浮点 | `f`/`F` 后缀为 `float32`，无后缀为 `float64` |
| `bitcast` | `inf`/`-inf`/`nan` | 目标为 32 位时源为 `float32`，目标为 64 位时源为 `float64` |

因此 `cast(float32, 1.0)` 是从 `float64` 到 `float32` 的数值转换；`bitcast(float32, 1.0)` 因源类型 `float64` 而报 `TC_CE_BITCAST_WIDTH`（须写 `1.0f`）。非 `let` 中严格 `cast` 的字面量按运行时指令处理溢出；`let` 中映射为 `TC_CE_CONSTANT_CAST_OVERFLOW`。`inf`/`-inf`/`nan` 作为 `cast` 操作数时以目标类型为源类型，直接构造目标类型的 canonical NaN。

#### 6.6.2 整数严格转换规则（strict）

严格整数转换统一依据数学值判定，与源/目标位宽关系无关：

1. 将源位模式按源类型解释为数学整数 `v`。
2. 若 `min(T) ≤ v ≤ max(T)`，结果为目标类型中表示同一数学值的位模式。
3. 否则报 `TC_RE_CAST_OVERFLOW`。

因此无符号缩窄同样检查范围；例如已有 `var wide: uint16 = 256u` 时，`cast(uint8, wide)` 必须报错。需要显式保留低位时使用 §6.6.3 的 `truncate`。

#### 6.6.3 整数截断转换规则（`truncate`）

设源、目标位宽分别为 `n`、`m`：

- 源与目标必须均为整数类型，且必须满足 `m < n`。
- 将源视为 `n` 位位模式 `bits`，结果位模式为 `bits mod 2^m`，再按目标整数类型解释。
- 不执行范围检查，不报溢出。
- `m >= n` 时为静态错误 `TC_CE_MODE_MISMATCH`；加宽应使用严格 `cast`，等宽位重解释应使用 `bitcast`。

#### 6.6.4 浮点转换规则

| 转换方向              | 规则                                                         |
| --------------------- | ------------------------------------------------------------ |
| 整数 → 浮点           | 按 roundTiesToEven 转为目标浮点；允许精度舍入；有限整数若转换为无穷 → `TC_RE_CAST_OVERFLOW` |
| 浮点 → 整数           | 向零舍入；结果超出目标整数范围，或源为 `nan`/`inf` → `TC_RE_CAST_OVERFLOW` |
| `float64` → `float32` | 按 roundTiesToEven 舍入；有限源值若转换为无穷 → `TC_RE_CAST_OVERFLOW`；舍入为非规格化数或零则合法 |
| `float32` → `float64` | 有限值无损精度提升（总是合法）                               |

浮点数值转换还须遵守：正负零保留符号，正负无穷保留符号；源为 NaN 且目标仍为浮点时，结果为目标类型的 canonical quiet NaN。同类型 `cast` 为恒等操作并保留完整位模式；若需在等宽不同类型间保留 NaN payload，必须使用 `bitcast`。

所有范围检查均在提交目标值之前、基于源值的精确数学值完成。尤其是浮点转整数时，必须先判定 NaN/无穷和截断后数学整数的范围，再执行后端转换；实现不得采用可能在宿主语言中产生未定义行为的越界浮点转整数强制转换。整数转浮点和浮点窄化必须直接正确舍入到目标格式，不得通过额外中间类型造成二次舍入。

#### 6.6.5 `bool` ↔ 整数/浮点转换

| 方向               | 规则                                           |
| ------------------ | ---------------------------------------------- |
| `bool` → 整数/浮点 | `true`（字节 `0x01`）→ `1`/`1.0`，`false`（字节 `0x00`）→ `0`/`0.0` |
| 整数/浮点 → `bool` | `0`/`0.0` → `false`（`0x00`），非零 → `true`（`0x01`，含 `nan`） |

提交到 `bool` 目标槽或 `memblock<bool>` 元素时，结果字节必须已是 §3.4 的规范形式；不得保留“非零即真”的其它字节值。

#### 6.6.6 等宽位重解释（`bitcast`）与速查

`bitcast(TargetType, operand)` 保持源位模式的全部位不变，仅按目标类型解释：

- 源与目标必须为整数、浮点或指针类型，且位宽完全相同。
- `bool` 不允许参与，否则报 `TC_CE_TYPE_MISMATCH`。尽管 `bool` 抽象宽度为 8 位（与 `int8`/`uint8` 相同），仍禁止 `bitcast`，以免把非 `0x00`/`0x01` 字节写入 `bool` 绑定；`bool` ↔ 整数/浮点只能经 §6.6.5 的数值 `cast`。
- `memblock<T>` 与结构体类型不允许参与 `cast` / `bitcast`（§3.8、§3.9）；否则报 `TC_CE_TYPE_MISMATCH`。
- 源、目标类型相同时是保持位模式不变的合法恒等操作。
- 位宽不一致报 `TC_CE_BITCAST_WIDTH`。
- `bitcast` 不触发数值溢出，也不规范化 NaN payload。
- 位模式按 §3.5 的抽象位串定义；源、目标的宿主对象地址、对齐和内存字节序不参与语义。

| 源 ↓ / 目标 → | 整数 | 浮点 | `bool` |
| ------------- | ---- | ---- | ------ |
| **整数** | strict `cast` 检查数学范围；更窄目标可显式 `truncate` | strict `cast` 做数值转换；等宽 `bitcast` 做位重解释 | 零为 `false`，非零为 `true` |
| **浮点** | strict `cast` 向零舍入并检查；等宽 `bitcast` 做位重解释 | strict `cast` 做精度转换；不同位宽禁止 `bitcast` | `±0.0` 为 `false`，其他值（含 NaN）为 `true` |
| `bool` | `false`→0，`true`→1 | `false`→0.0，`true`→1.0 | 恒等 |

### 6.7 memblock 操作

#### 6.7.1 memblock 变量定义

memblock 变量遵循 TC 现有的 `var` / `let` 规则，声明时必须初始化。声明类型写完整的 `memblock<T, N>`，`N` 为编译期 `usize` 常量：

| 规则 | 说明 |
|------|------|
| 类型 | `memblock<T, N>`；`T` 为 `void` 以外的任意完整类型（标量、`memblock<U, M>`、结构体、`ptr<U>`），`N` 为编译期 `usize` 常量（≥ 1），规划元素个数。类型仅由 `T` 决定；`N` 不参与类型等价，但赋值与传参时须与声明一致（§3.8.1、§3.8.4） |
| 强制初始化 | 不可省略初始化器，`var mb: memblock<int32, 10>` 须带 `=` 或 `funcall` 初始化，触发 `TC_CE_VAR_MISSING_INIT` |
| `let` 只读 | `let` memblock 编译期求值，不可作为 `memblock_store` / `memblock_copy` 的目标块 |
| `let` 常量 | `N` 及全部填充/逐值操作数必须全是编译期常量；`count:` 标签必须提供 |
| `funcall` 初始化 | 非 `void` `funcall` 可通过专用形态 `var <名>: memblock<T, N> = funcall(...)` 初始化新变量（§8.2）；`T` 必须相同，且 `N` 的数学值必须与声明相等（编译期检查，不匹配时报 `TC_CE_MEMBLOCK_SIZE_MISMATCH`） |

同一作用域内不可重复定义同名 memblock 变量，也不可与标量变量或常量冲突。

#### 6.7.2 memblock 操作

所有 memblock 操作遵循 TC 的 `op(类型, 操作数…)` 约定。

#### 6.7.2.1 读取 — `memblock_load`

语法见附录 A。从 `mb` 中读取第 `index` 个元素，返回类型 `T`。`index` 为整数，0-based。类别：RHS。

#### 6.7.2.2 写入 — `memblock_store`

语法见附录 A。将 `value` 写入 `mb` 的第 `index` 个位置。`value` 类型必须与 `T` 严格一致。类别：独立语句（非 RHS）。

#### 6.7.2.3 区间拷贝 — `memblock_copy`

语法见附录 A。将 `src` 中从 `src_index` 起连续 `length` 个元素，按元素抽象位串复制到 `dst` 中从 `dst_index` 起的对应区间。类别：独立语句（非 RHS）。`length` 是**本次拷贝跨度**的操作数，不是 memblock 的长度属性；不改变两侧绑定的身份，不分配「新语言级长度」。

**操作数**：

| 位置 | 约束 |
| ---- | ---- |
| `T` | 显式元素标量类型；必须与 `dst`、`src` 的元素类型同时严格一致 |
| `dst` | `memblock_name`；必须是可写运行时绑定（局部/顶层 `var`、可写 `static var`，或函数形参 memblock——与 `memblock_store` 相同，只改副本元素）；`let` / `static let` 作目标 → `TC_CE_CONSTANT_ASSIGNMENT` |
| `dst_index` / `src_index` / `length` | §6.1.2 `operand`，且均为整数类型（彼此类型可不同，也不必等于 `T`） |
| `src` | `memblock_name`；可为 `var` / `let` / `static` / 形参 / 导入公开成员；运行时 `var` 须确定初始化 |

**区间合法性**（半开区间，以各 memblock 类型参数中的 `count` 值为上界）：

```text
n ≥ 0  ∧  0 ≤ d  ∧  0 ≤ s  ∧  d + n ≤ count_dst  ∧  s + n ≤ count_src
```

`n = 0` 合法（允许下标等于 `count`，不修改元素）。`n < 0` 或越界报告 `TC_CE_MEMBLOCK_INDEX_OUT_OF_RANGE`（编译期可确定时）或 `TC_RE_MEMBLOCK_INDEX_OUT_OF_RANGE`（运行时）。

**抽象执行语义**：

1. 先读取并检查 `dst_index`、`src_index`、`length`；再确认 `dst` 与 `src` 在当前程序点可读/可写要求已满足。
2. 区间非法则不修改 `dst` 的任何元素，并按 §11.1 终止（运行时）或在可静态判定的负 `length` 等情形拒绝编译。
3. 区间合法时，语义等价于：先把源区间 `[s, s+n)` 的 `n` 个元素按抽象位串拷入长度为 `n` 的临时缓冲，再按相同顺序写入目标区间 `[d, d+n)`。因此：
   - `dst` 与 `src` 为不同绑定时，结果与逐元素 `load`/`store` 一致；
   - **同一绑定上的重叠区间**行为完全确定，等价于 `memmove`，不得依赖宿主 `memcpy` 的重叠 UB；
   - 不重新规范化元素位模式：源元素已是合法 TC 值（含 `bool` 的 `0x00`/`0x01`），拷贝保持位串不变。
4. 成功后 `dst` 仍为同一词法槽上的已初始化绑定；其已初始化状态不变（与赋值覆盖相同）。

`memblock_copy` 不是 `let` 常量表达式的一部分；不得出现在 `const_rhs` 中。

#### 6.7.2.4 索引与拷贝区间检查

`load`/`store` 的 `index`，以及 `memblock_copy` 的 `dst_index`/`src_index`/`length`，都必须是整数类型的 `operand`。非整数类型报 `TC_CE_TYPE_MISMATCH` 或 `TC_CE_SYNTAX`（按产生式边界）。这些整数操作数的类型不必与 `T` 相同。

**单下标**（`load`/`store`）：索引解码为 `i` 后须满足 `0 ≤ i < N`（声明中的元素个数 `N`，不含头部）。

**拷贝区间**（`memblock_copy`）：按 §6.7.2.3 的半开区间检查；空拷贝（`n = 0`）允许下标等于 `count` 参数值。`count_dst` / `count_src` 分别为 `dst`、`src` 声明中的元素个数 `N`。

| 场景 | 诊断 |
|------|------|
| 编译期可确定的常量下标为负，或 `memblock_copy` 的常量 `length < 0` | 静态错误 `TC_CE_MEMBLOCK_INDEX_OUT_OF_RANGE` |
| 运行时下标/区间不满足相对 `count` 的规则 | 运行时错误 `TC_RE_MEMBLOCK_INDEX_OUT_OF_RANGE` |

负下标、负 `length` 或区间越界同属越界，不得静默回绕。由于 `count` 为编译期常量，其边界在编译期可完整判定。

#### 6.7.2.5 `.count` — 访问长度头部

`mb.count` 以字段访问的形式从带长度 memblock 的长度头部读取 `usize` 值并返回。语法见附录 A。类别：RHS，结果类型为 `usize`。

| 约束 | 规则 |
| ---- | ---- |
| 操作数 | `mb` 必须是 `memblock<T, N>` 类型的绑定（局部/顶层 `var`/`let`、`Self.<名>`、`<模块名>.<名>` 或函数形参） |
| 返回值 | `usize` 值，等于绑定声明中 `N` 的数学值 |
| 不修改 | 不改变 memblock 内容；不改变已初始化状态 |
| 确定初始化 | 运行时 `var` 须确定初始化；`let` 已在编译期内联，不检查 |
| 编译期常量 | `.count` 返回编译期常量 `N` 的数学值，是合法的 `const_operand`，可在 `const_rhs` 中使用（§3.8.5） |

`.count` 不是独立语句：只能出现在 RHS 或操作数位置。

#### 6.7.2.6 约束

- 不可取 `memblock` 或其元素的地址，无 `&` 语义
- 不提供子块视图或切片；需要搬运连续元素时使用 `memblock_copy`，需要整块复制时使用赋值（需 `T` 相同且 `N` 一致，§3.8.4）
- memblock 的 `N` 已由声明给出，且可通过 `.count` 读取该编译期常量值
- `memblock` 操作数可为局部/顶层 `var` 或 `let` 的裸名，或（在 `#lib` 内）`Self.<名>`，或已导入库的公开 `<模块名>.<名>`；名称解析与可见性规则与赋值目标一致（§4.3、§4.4、§8.4.1）
- `let` memblock 不可作为 `memblock_store` / `memblock_copy` 的目标（只读），与标量 `let` 相同，报 `TC_CE_CONSTANT_ASSIGNMENT`；`let` 可作为 `memblock_copy` 的 `src` 及 `.count` 的操作数
- 索引与拷贝跨度须先写入局部变量或使用字面量/`let`，`memblock_load(T, mb, add(int32, base, offset))` 与 `memblock_copy(..., add(...), ...)` 不合法
- `memblock_load` / `memblock_store` / `memblock_copy` 的显式类型参数必须是 memblock 的元素类型 `T`（`void` 以外的任意完整类型），且与所涉 memblock 操作数的元素类型 `T` 一致；不一致报 `TC_CE_TYPE_MISMATCH`
- `.count` 无显式类型参数；基址操作数须为 memblock 类型
- `write` / `writeln` / `read` 的显式类型参数仅接受 `scalar_type`，禁止 `memblock<T>`（§10、附录 A）；整块 I/O 须由程序自行按元素循环读写

### 6.8 指针操作

所有指针操作遵循 TC 的 `op(操作数…)` 约定。所有指针指令的第一个参数均为显式类型参数 `T`（所指类型，须为 `void` 以外的完整类型），该参数统一决定指令的所指类型、步长或返回类型，并从操作数自身的声明类型交叉验证一致性（与 `memblock_load`/`memblock_store` 不同，后者的显式类型参数是元素类型而非 memblock 类型）。

#### 6.8.1 空指针字面量 — `nullptr`

`nullptr` 是空指针字面量，类别为 RHS（`operand`）。语法见附录 A。

| 规则 | 说明 |
| ---- | ---- |
| 结果类型 | 由上下文期望的 `ptr<T>` 类型唯一决定（§3.10.2） |
| `let` 上下文 | `nullptr` 是合法的编译期常量（`const_operand`） |
| 运行时语义 | 本身不触发错误；`ptr_load(T, nullptr)` 和 `ptr_store(T, nullptr, ...)` 触发 `TC_RE_NULL_POINTER_DEREFERENCE` |

#### 6.8.2 读取 — `ptr_load`

语法：`ptr_load(T, ptr)`。从 `ptr` 中解引用读取所指对象，返回类型 `T`。类别：RHS。

| 规则 | 说明 |
| ---- | ---- |
| 类型参数 `T` | 须为 `void` 以外的完整类型；决定指针所指类型，且必须与 `ptr` 的声明类型一致 |
| 操作数 | `ptr` 须为 `ptr<T>` 类型 |
| 结果类型 | `T`（与类型参数一致） |
| `let` 上下文 | `ptr_load` 不可用于 `let` / `static let` 的 `const_rhs`（不是编译期常量） |
| 运行时语义 | `ptr` 为 `nullptr` 时 → `TC_RE_NULL_POINTER_DEREFERENCE`；否则返回所指对象的当前值（按值复制） |

#### 6.8.3 写入 — `ptr_store`

语法：`ptr_store(T, ptr, value)`。将 `value` 写入 `ptr` 所指对象。类别：独立语句（非 RHS）。

| 规则 | 说明 |
| ---- | ---- |
| 类型参数 `T` | 须为 `void` 以外的完整类型；决定指针所指类型，且必须与 `ptr` 的声明类型一致 |
| 操作数 | `ptr` 须为 `ptr<T>` 类型；`value` 须为 `T` 类型操作数（字面量以 `T` 为期望类型检查） |
| 可变性 | 仅当 `ptr` 所指外层绑定为可写（`var` / 可写 `static var`）时允许；所指为 `let`/`static let`/形参时报 `TC_CE_CONSTANT_ASSIGNMENT` |
| 运行时语义 | `ptr` 为 `nullptr` 时 → `TC_RE_NULL_POINTER_DEREFERENCE`；否则覆盖写入所指对象的存储 |

#### 6.8.4 取地址 — `ptr_address`

语法：`ptr_address(T, identifier)`。从变量标识符取地址，返回指向该绑定的 `ptr<T>`。类别：RHS（`operand`）。

| 规则 | 说明 |
| ---- | ---- |
| 类型参数 `T` | 须为 `void` 以外的完整类型；`T` 必须与 `identifier` 的声明类型严格一致（不一致报 `TC_CE_TYPE_MISMATCH`） |
| 操作数 | `identifier` 须为运行时 `var` / `static var` 绑定或函数形参的裸名；`let` / `static let` 绑定禁止（报 `TC_CE_CONSTANT_ASSIGNMENT`）；`Self.<名>` / `<模块名>.<名>` 仅当解析为可写 `static var` 时合法 |
| 结果类型 | `ptr<T>` |
| `let` 上下文 | `ptr_address` 不是编译期常量，不可用于 `const_rhs`（报 `TC_CE_CONSTANT_EXPRESSION`） |
| 运行时语义 | 计算绑定的抽象存储位置并返回对应的 `ptr<T>`。得到的指针与绑定共享存储 |
| 可变性 | `ptr_address` 本身为只读操作（只取地址）。但取地址后通过该指针做 `ptr_store` 须满足目标绑定的可写性约束（见 §6.8.3） |

#### 6.8.5 指针加法 — `ptr_add`

语法：`ptr_add(T, ptr, offset)`。指针按元素单位偏移。类别：RHS（`operand`）。

| 规则 | 说明 |
| ---- | ---- |
| 类型参数 `T` | 须为 `void` 以外的完整类型；决定所指类型与偏移步长 `sizeof_bits(T)` |
| 操作数 | `ptr` 须为 `ptr<T>` 类型；`offset` 须为 `usize` 类型操作数（非负偏移，向高位地址方向移动） |
| 结果类型 | `ptr<T>` |
| `let` 上下文 | `ptr_add` 不是编译期常量，不可用于 `const_rhs` |
| 运行时语义 | `ptr` 为 `nullptr` 时 → `TC_RE_NULL_POINTER_ARITHMETIC`；否则计算 `ptr + offset × sizeof_bits(T)` 位并返回新的 `ptr<T>` |
| 越界 | `ptr_add` 不检查结果指针是否越界；越界指针的 `ptr_load`/`ptr_store` 行为为实现定义 |

#### 6.8.6 指针减法 — `ptr_sub`

语法：`ptr_sub(T, ptr, offset)`。指针按元素单位向低位地址方向偏移。类别：RHS（`operand`）。

| 规则 | 说明 |
| ---- | ---- |
| 类型参数 `T` | 须为 `void` 以外的完整类型；决定所指类型与偏移步长 `sizeof_bits(T)` |
| 操作数 | `ptr` 须为 `ptr<T>` 类型；`offset` 须为 `usize` 类型操作数（非负偏移，向低位地址方向移动） |
| 结果类型 | `ptr<T>` |
| 运行时语义 | `ptr` 为 `nullptr` 时 → `TC_RE_NULL_POINTER_ARITHMETIC`；否则计算 `ptr - offset × sizeof_bits(T)` 位并返回新的 `ptr<T>` |
| 越界 | `ptr_sub` 不检查结果指针是否越界；越界指针的 `ptr_load`/`ptr_store` 行为为实现定义 |

#### 6.8.7 指针序关系比较 — `ptr_lt` / `ptr_le` / `ptr_gt` / `ptr_ge`

语法：`ptr_lt(T, ptr1, ptr2)` 等。比较 `ptr<T>` 指针的抽象地址序。类别：RHS（`operand`，结果类型为 `bool`）。

| 规则 | 说明 |
| ---- | ---- |
| 类型参数 `T` | 须为 `void` 以外的完整类型 |
| 操作数 | `ptr1`、`ptr2` 同为 `ptr<T>` 类型，均为非 `nullptr` |
| 结果类型 | `bool` |
| `let` 上下文 | 不可用于 `const_rhs`（须在运行时比较实际地址） |
| 运行时语义 | 若任一指针为 `nullptr`，报告 `TC_RE_NULL_POINTER_DEREFERENCE`。比较两指针抽象地址的序关系。两个操作数必须同为 `ptr<T>` 类型（`T` 由显式类型参数决定），跨类型比较报 `TC_CE_TYPE_MISMATCH` |

#### 6.8.8 指针宽度查询 — `ptr_size`

语法：`ptr_size(T, ptr)`。返回 `ptr<T>` 的所指类型 `T` 的抽象宽度（位）。类别：RHS（结果类型为 `usize`）。

| 规则 | 说明 |
| ---- | ---- |
| 类型参数 `T` | 须为 `void` 以外的完整类型；决定所指类型的宽度 |
| 操作数 | `ptr` 须为 `ptr<T>` 类型 |
| 返回类型 | `usize`，值为 `sizeof_bits(T)`（位） |
| 空指针语义 | `ptr_size(T, nullptr)` 合法：`nullptr` 的所指类型 `T` 由显式类型参数唯一决定，返回 `sizeof_bits(T)`。无需额外绑定 |
| 编译期常量 | 类型级信息，可在编译期完全确定，因此 `ptr_size` 是合法的 `const_operand` |

#### 6.8.9 `memcopy_unsafe` — 原始内存块拷贝

语法见附录 A。将 `src` 中从 `src_idx` 起连续 `length` 个元素，按元素抽象位串复制到 `dst` 中从 `dst_idx` 起的对应区间。类别：独立语句（非 RHS）。与 `memblock_copy` 不同，`memcopy_unsafe` 操作的是 `ptr<T>` 值而非 `memblock<T, count>` 值，**不执行越界检查**，因此适用于对原始内存块（如外部 FFI 传入的裸指针）进行区间拷贝。

**操作数**：

| 位置 | 约束 |
| ---- | ---- |
| `T` | 显式元素类型；须为 `void` 以外的完整类型；拷贝步长为 `sizeof_bits(T)` 位 |
| `dst` | `operand`，须为 `ptr<T>` 类型；所指的外层绑定为 `let`/`static let`/形参时报 `TC_CE_CONSTANT_ASSIGNMENT` |
| `dst_idx` | `operand`，须为整数类型（有符号/无符号均可，不必等于 `T` 或特定类型） |
| `src` | `operand`，须为 `ptr<T>` 类型；运行时 `var` 须确定初始化 |
| `src_idx` | `operand`，须为整数类型 |
| `length` | `operand`，须为整数类型且数学值 ≥ 0 |

**区间合法性**：

```text
length ≥ 0  ∧  dst_idx ≥ 0  ∧  src_idx ≥ 0
```

`length = 0` 合法（不修改任何元素）。`length < 0` 时，若编译期可确定则报 `TC_CE_MEMCOPY_UNSAFE_INVALID_RANGE`，运行时则报 `TC_RE_MEMCOPY_UNSAFE_INVALID_RANGE`。

**抽象执行语义**：

1. 先读取并检查所有操作数；`dst` 或 `src` 为 `nullptr` 时报告 `TC_RE_NULL_POINTER_DEREFERENCE`。
2. 若 `length` 的数学值 < 0，发生运行时错误，不修改 `dst` 所指内存的任何元素。
3. 正常执行时，语义等价于：先把源区间 `[src_idx, src_idx + length)` 的 `length` 个元素按抽象位串拷入临时缓冲，再按相同顺序写入目标区间 `[dst_idx, dst_idx + length)`。因此重叠区间（同一指针用作 `src` 和 `dst` 且区间有重叠）行为完全确定，等价于 `memmove`。
4. 不重新规范化元素位模式，保持位串不变。

**越界行为**：`memcopy_unsafe` 不检查 `dst_idx + length` 和 `src_idx + length` 所指内存的可用范围。若拷贝区间超出实际分配的内存边界，行为为实现定义（与 `ptr_add` 越界后 `ptr_load`/`ptr_store` 相同，§1.3）。对于通过 FFI 传入的指针，程序有责任保证区间合法；对于取自 TC 内 `var` 绑定的指针，越界拷贝是实现定义行为而非运行时错误。

`memcopy_unsafe` 不是 `let` 常量表达式的一部分；不得出现在 `const_rhs` 中。

#### 6.8.10 注意事项

- `ptr_load` / `ptr_store` / `ptr_address` / `ptr_add` / `ptr_sub` 及 `memcopy_unsafe` 的操作数除 `nullptr` 外，须是 `ptr<T>` 类型的局部/顶层 `var` 或 `let` 的裸名，或（在 `#lib` 内）`Self.<名>`，或已导入库的公开 `<模块名>.<名>`；名称解析与可见性规则与赋值目标一致（§4.3、§4.4、§8.4.1）
- 所有指针指令的第一个参数均为显式类型参数 `T`（所指类型），`T` 须为 `void` 以外的完整类型，且必须与指针操作数的声明类型一致。该参数统一决定指令的所指类型、步长或返回类型，不从操作数推断
- `let` 类型的 `ptr<T>` 指针不可作为 `ptr_store` 或 `memcopy_unsafe` 的目标（只读），与标量 `let` 相同，报 `TC_CE_CONSTANT_ASSIGNMENT`
- `ptr_address` 仅可用于 `var` / `static var` / 形参绑定；对 `let` 使用报 `TC_CE_CONSTANT_ASSIGNMENT`。`ptr_address` 的显式类型参数 `T` 不能是 `void`
- `ptr_add` / `ptr_sub` / `ptr_eq` / `ptr_ne` / `ptr_lt` / `ptr_le` / `ptr_gt` / `ptr_ge` / `ptr_load` / `ptr_store` / `ptr_size` / `memcopy_unsafe` 的显式类型参数 `T` 不能是 `void`
- `ptr_load` / `ptr_store` 不支持嵌套解引用（如 `ptr_load(int32, ptr_load(ptr_int32, ptr))` 不合法）；须分步：先 `ptr_load` 得到内层 `ptr<T>`，再对其做 `ptr_load`
- `write` / `writeln` / `read` 不接受 `ptr<T>` 类型（§10、附录 A）
- `ptr_size(T, nullptr)` 合法，所指类型 `T` 由显式类型参数唯一决定；`ptr_size` 是合法的编译期常量（`const_operand`），可在 `let` 中使用
- `memcopy_unsafe` 不检查越界（§6.8.9），`src` 或 `dst` 为 `nullptr` 时报告 `TC_RE_NULL_POINTER_DEREFERENCE`。`dst` 与 `src` 可以为同一指针（重叠拷贝）

## 7. 控制流

### 7.1 条件分支语句（`if`）

语法形态由附录 A 规定。采用缩进敏感块结构，以 `end` 结束。

#### 7.1.1 语义约束

| 约束 | 规则 |
|------|------|
| 条件 | 须为产生 `bool` 的 RHS（§6.1.1）；结果类型不是 `bool` → `TC_CE_CONDITION_TYPE`。名称与类型检查通过后按 §5.2.2 做静态布尔三态判定，以裁剪 CFG 可达边 |
| 语法形态 | `then` 位于 `if` 行末；`else` 与 `end` 独立成行、与对应 `if` 对齐；`end` 不得省略，缺失 → `TC_CE_MISSING_END` |
| 多分支 | 不支持单行 `else if`，须通过嵌套 `if`/`else`/`end` 实现 |
| 块内容 | 语句序列可为空；受附录 A 限制，不可嵌套 `func` |

#### 7.1.2 缩进规则

| 规则 | 说明 |
|------|------|
| 空格缩进 | 仅 ASCII 空格 U+0020，每 4 格一级，行首空格数须被 4 整除 |
| 对齐 | `func`/`if`/`while`、`else`、`end` 同级对齐 |
| 块内语句 | 比块关键字多一级；过多/过少为错误 |
| 嵌套 `end` | 与对应关键字对齐；内层块内语句再增一级 |
| `label` | 不增缩进、不开启代码块，与同作用域语句同级 |

#### 7.1.3 执行语义

1. 计算 `<bool_rhs>` 的值。
2. 若 `true`：执行 `then` 块，然后跳过 `else`，跳至 `end` 之后。
3. 若 `false` 且有 `else`：执行 `else` 块（含嵌套 `if` 递归），遇 `end` 继续外层。
4. 若 `false` 且无 `else`：直接跳至 `end` 之后。

#### 7.1.4 作用域

| 项目 | 规则 |
|------|------|
| `then`/`else` 关系 | 互斥兄弟块，互不可见，允许同名局部变量 |
| 无 `else` 时 | 仅建立 `then` 代码块；条件在外层作用域求值 |
| 块内声明 | 可用 `var`/`let`；离开块后不可访问 |
| 嵌套 `if` | 内层可访问外层变量（除非被同名屏蔽） |
| `let` 常量 | 可在块内定义，作用域限于该块 |
| 函数体交互 | 各分支可使用 `return`；`func` 定义不得出现在分支内 |

### 7.2 循环语句（`while`）

语法形态由附录 A 规定。采用缩进敏感块结构，以 `end` 结束。

#### 7.2.1 语义约束

| 约束 | 规则 |
|------|------|
| 条件 | 须为产生 `bool` 的 RHS（§6.1.1）；结果类型不是 `bool` → `TC_CE_CONDITION_TYPE`。名称与类型检查通过后按 §5.2.2 做静态布尔三态判定，以裁剪 CFG 可达边 |
| 语法形态 | `then` 位于 `while` 行末；`end` 独立成行、与 `while` 对齐，不得省略，缺失 → `TC_CE_MISSING_END` |
| 循环体 | 可为空；受附录 A 限制，不可嵌套 `func`；`goto`/`label` 禁止出现（§7.2.3） |

#### 7.2.2 执行语义

1. 计算 `<bool_rhs>`。
2. 若 `true`：顺序执行循环体语句。
   - 遇 `break` → 退出循环，跳至 `end` 之后。
   - 遇 `continue` → 跳过剩余语句，返回步骤 1 重新计算条件。
   - 正常执行完毕 → 返回步骤 1。
3. 若 `false`：退出循环，跳至 `end` 之后。

每次 `true` 进入新循环体块实例；实现可复用物理槽，但须与重新进入等价。恒真 `while` 仅能经 `break` 终止。

#### 7.2.3 作用域与范式隔离

| 项目 | 规则 |
|------|------|
| 循环体作用域 | `then … end` 构成块级作用域；条件在外层求值 |
| 块内声明 | `var`/`let` 在 `end` 后不可访问 |
| 嵌套循环 | 内层可访问外层变量 |
| `break`/`continue` 作用域 | 作用于最内层 `while`，不得穿越函数边界 |

**范式隔离**：`while` 是结构化循环，仅可用 `break`/`continue` 控制。`while` 体内禁止 `goto` 与 `label`。

| 诊断 | 条件 | 错误码 |
|------|------|--------|
| 函数外 `goto` | `goto` 无 `func` 祖先 | `TC_CE_GOTO_OUTSIDE_FUNCTION` |
| 函数外 `label` | `label` 无 `func` 祖先 | `TC_CE_LABEL_OUTSIDE_FUNCTION` |
| 循环内 `goto` | `goto` 有 `while` 祖先 | `TC_CE_GOTO_INSIDE_LOOP` |
| 循环内 `label` | `label` 有 `while` 祖先 | `TC_CE_LABEL_INSIDE_LOOP` |

### 7.3 受限 `goto` 语句

`goto` 与 `label` 仅限函数体内使用，是构建非结构化控制流的基础。顶层不建立标签表。

#### 7.3.1 设计原则

| 原则 | 说明 |
|------|------|
| 函数内限定 | `goto`/`label` 须有 `func` 祖先 |
| 同函数限定 | 每个函数独立标签表，不跨函数解析 |
| 只出不进 | 禁止跳入子作用域或兄弟分支（`then` ↔ `else`）；允许跳出 |
| 无方向限制 | 支持前后跳转 |
| 范式隔离 | `while` 体内禁止 `goto`/`label`（§7.2.3） |
| 标签唯一 | 同块禁止同名；`goto` 从最内层块沿祖先链查找，首个同名标签胜出 |
| 初始化约束 | 跳转进入可达性分析；变量可用性由 §9.2 判定 |

#### 7.3.2 作用域跳转诊断表

设 `src` 为 `goto name` 所在最内层代码块，按以下优先级检查：

| 步骤 | 条件 | 结果 |
|------|------|------|
| 1 | `goto` 无 `func` 祖先 | `TC_CE_GOTO_OUTSIDE_FUNCTION` |
| 2 | `goto` 有 `while` 祖先 | `TC_CE_GOTO_INSIDE_LOOP` |
| 3 | 沿 `src` 祖先链查找到 `name` | 首个同名标签胜出（合法） |
| 4 | 标签 `name` 在 `src` 的子作用域内 | `TC_CE_JUMP_INTO_BLOCK` |
| 5 | 标签 `name` 与 `src` 位于同一 `if`/`while` 的互斥分支（如 `then` 与 `else` 之间） | `TC_CE_JUMP_INCOMPATIBLE_BLOCK` |
| 6 | 当前函数内无匹配（含：标签仅存在于另一函数；或全程序均无该名标签） | `TC_CE_LABEL_NOT_FOUND` |

同块重复标签 → `TC_CE_DUPLICATE_LABEL`；跨块同名合法。每个函数独立标签表，不跨函数解析（§7.3.1）；因此「标签在另一函数」与「全程序无此标签」均落在步骤 6，**不得**另造跨函数跳转专用码。

步骤 4 与 5 均要求先完成全函数标签搜索，确认 `name` 存在于当前函数内。步骤 4 对应"跳入子作用域"（违反 §7.3.1 的"只出不进"），步骤 5 对应"兄弟分支互跳"（违反 §7.3.1 的"禁止兄弟分支间跳转"）。

#### 7.3.3 语义规则

| 规则 | 说明 |
|------|------|
| 跳转 | `goto` 无条件转移至目标 `label`；`label` 无运行时动作，沿落入边继续 |
| 作用域退出 | 跳出作用域时局部变量立即销毁 |
| 确定初始化 | 目标点未初始化的绑定上读取/赋值/`read` → `TC_CE_UNINITIALIZED_VARIABLE` |
| 越过 `var` | 不自动出错；反向跳转重新初始化同一槽 |
| 跳出 `if` | 允许不经 `end` 跳出；`goto` 不改变存活变量值 |

### 7.4 `break` 与 `continue` 语句

语法见附录 A：各为独立语句，无操作数。

| 语句 | 行为 |
|------|------|
| `break` | 立即终止最内层 `while`，跳至该循环 `end` 之后；块内局部变量按 §9.2 销毁 |
| `continue` | 立即结束当前迭代，跳至最内层 `while` 的条件求值处，重新计算条件 |

| 约束 | 说明 |
|------|------|
| 必须位于 `while` 内 | 否则 → `TC_CE_BREAK_OUTSIDE_LOOP` / `TC_CE_CONTINUE_OUTSIDE_LOOP` |
| 作用域目标 | 最内层 `while`，非最内层 `if` |
| 不穿越函数边界 | 调用者中的 `while` 不使被调函数内的 `break`/`continue` 合法 |
| 不跨层 | 禁止跳出嵌套外层循环；需用函数内 `if` + `goto` 或封装为函数 |

`while` 条件中可引用 `let` 常量；恒真/恒假不改变 RHS 要求。

## 8. 函数与调用模型

### 8.1 函数定义与签名（`func`）

函数仅在 `#lib` 模块中定义，在编译期建立签名和函数体，不产生顶层执行效果。`#program` 不得定义函数。

#### 8.1.1 定义形态

语法形态由附录 A 规定。

| 项目 | 规则 |
|------|------|
| 形参类型 | 标量（含 `isize`/`usize`）、`ptr<T>`（§3.10）、`memblock<T, N>`（带长度头部，§3.8）或已定义结构体（§3.9）。`ptr<T>` 形参按值传递（复制指针值，共享所指对象）。`memblock` 与结构体形参按值传递（深拷贝）。形参是只读**绑定**：不可对其做整体赋值或字段赋值 → `TC_CE_PARAMETER_ASSIGNMENT`；但可对 memblock 形参的**副本**做 `memblock_store` / `memblock_copy`（只改副本元素）。经 `ptr_address` 取形参地址后再 `ptr_store` / `memcopy_unsafe` → `TC_CE_CONSTANT_ASSIGNMENT`（§6.8.3），与直接赋值的 `PARAMETER_ASSIGNMENT` 分码 |
| 返回类型 | 值类型或 `void`；`memblock<T, N>` 与结构体返回时整块复制 |
| 缩进 | 函数体比 `func` 行恰好多一级；`end` 与 `func` 对齐；`end` 缺失 → `TC_CE_MISSING_END` |
| 空函数体 | 合法，但须满足返回路径规则，否则报 `TC_CE_MISSING_RETURN` |

#### 8.1.2 签名约束

| 约束 | 规则 | 违反错误码 |
|------|------|-----------|
| 函数名唯一 | 全局唯一，不支持重载；不得与任何值绑定同名 | `TC_CE_FUNCTION_NAME_CONFLICT` |
| 形参名唯一 | 同一签名内不重复 | `TC_CE_DUPLICATE_PARAMETER`（静态语义拒绝；EBNF 无法表达名不重复，故不在语法阶段拦截） |
| 形参只读 | 按值传递，入口已初始化；不得赋值或作为 `read` 目标 | `TC_CE_PARAMETER_ASSIGNMENT`（直接赋值/`read`）。经 `ptr_address` 取址后再 `ptr_store`/`memcopy_unsafe` → `TC_CE_CONSTANT_ASSIGNMENT`（§6.8.3） |
| `void` 限制 | 不得用作形参、`var`、`let`、转换目标、运算类型参数 | 语法拒绝 |
| 名称冲突保护 | 任意层级 `var`/`let` 与形参同名 → `TC_CE_DUPLICATE_DEFINITION`；与函数同名 → `TC_CE_FUNCTION_NAME_CONFLICT` | |
| 签名先收集 | 分析函数体前全部签名已收集，可调用后定义函数；调用图须无环（§8.6） | |

#### 8.1.3 定义位置

| 规则 | 说明 |
|------|------|
| 仅 `#lib` | `#program` 不得定义函数 → `TC_CE_PROGRAM_MODE_MISUSE` |
| 位于 `static` 成员之后 | 所有 `static let`/`static var` 须在 `func` 之前；函数间顺序不限 |
| 不可嵌套 | 不得出现在函数体、`if`/`else`、`while` 内 |
| 无匿名代码块 | 不支持脱离 `func`/`if`/`while` 的匿名块 |
| 无特殊 `main` | `main` 不是特殊名称，不自动调用 |

#### 8.1.4 不支持的函数形态

TC 不支持：函数重载、默认参数、可变参数、函数值、函数指针、闭包、嵌套函数、匿名函数、递归（直接或间接）、隐式参数转换、隐式返回转换、函数调用作为实参嵌套（`funcall` 的实参中不得出现另一个 `funcall`，§8.2.2）。函数不能隐式访问顶层值绑定。

### 8.2 函数调用（`funcall`）

#### 8.2.1 调用语法

`funcall` 第一项须为静态函数名，非普通 RHS 或函数值。

| 调用者位置 | 本库函数写法 | 导入库函数写法 | 裸 `identifier` |
|-----------|------------|-------------|----------------|
| `#program` 顶层 | 禁止（`TC_CE_PROGRAM_MODE_MISUSE`） | `<模块>.<函数名>` | `TC_CE_UNDEFINED_FUNCTION` |
| `#lib` 函数体 | `Self.<函数名>` | `<模块>.<函数名>` | 若命中本库函数 → `TC_CE_FUNCTION_SCOPE_ACCESS`；否则 `TC_CE_UNDEFINED_FUNCTION` |

#### 8.2.2 命名且有序的实参

除函数名外，每项必须使用 `<形参名>: <实参>` 形式。每个形参恰好匹配一个实参，文本顺序须与声明一致（`i` 对 `i`）。违反时按下列专用码报告，不得改报笼统 `TC_CE_SYNTAX` 或 `TC_CE_TYPE_MISMATCH`：

| 情形 | 错误码 |
|------|--------|
| 实参名未出现在签名中 | `TC_CE_UNKNOWN_ARGUMENT` |
| 同一形参名出现一次以上 | `TC_CE_DUPLICATE_ARGUMENT` |
| 某个形参没有对应实参 | `TC_CE_MISSING_ARGUMENT` |
| 实参个数多于形参（全部名称已知） | `TC_CE_EXTRA_ARGUMENT` |
| 实参文本顺序与声明顺序不一致（`i` 对 `i` 失败） | `TC_CE_ARGUMENT_ORDER` |

实参严格按照调用点从左到右读取并绑定。

| 形参类型 | 合法实参形式 |
|---------|------------|
| 标量 | 仅 `operand`（标识符/限定名/字段读取/字面量）；运算、转换、构造器、`funcall` 不可 |
| `memblock<T, count>` | 标识符（已声明带长度 memblock 绑定），或 `memblock_constructor`（填充/逐值） |
| 结构体 | 同类型标识符（含限定名、字段读取），或同类型 `struct_constructor` |

每个形参类型是实参的唯一期望类型，不做隐式转换。字面量按 §3.6 以形参类型为上下文检查。

#### 8.2.3 返回值使用位置

| 调用写入位置 | 非 `void` 函数 | `void` 函数 |
|------------|-------------|-----------|
| `var x: T = funcall(...)` | 合法 | `TC_CE_FUNCALL_RESULT_TYPE` |
| `x = funcall(...)` | 合法（目标须已确定初始化） | `TC_CE_FUNCALL_RESULT_TYPE` |
| 独立 `funcall(...)` | `TC_CE_FUNCALL_POSITION` | 合法 |
| `let` / `return` / 嵌套实参 | 语法拒绝（`TC_CE_SYNTAX`） | 语法拒绝（`TC_CE_SYNTAX`） |

非 `void` 返回值可经新 `var` 或已初始化局部变量继续传递；不得对形参赋值。

### 8.3 `return` 语句

#### 8.3.1 静态语义

| 约束 | 规则 |
|------|------|
| 出现位置 | 仅函数体内；顶层或函数外 `return` → `TC_CE_RETURN_OUTSIDE_FUNCTION` |
| 返回形态 | 非 `void` 函数须 `return <operand>`，`void` 函数须裸 `return`；形态不符 → `TC_CE_RETURN_FORM` |
| 返回类型匹配 | 非 `void` 的 `return` 操作数类型须与返回类型严格相同，否则 → `TC_CE_RETURN_TYPE` |
| 返回路径 | 每条可达路径须经过显式 `return`；存在到函数末尾的可达路径 → `TC_CE_MISSING_RETURN`。永久 `while`/`goto` 循环且无到末尾路径时合法 |
| 后续语句 | `return` 之后的源序语句不可达 → `TC_CE_UNREACHABLE_STATEMENT` |

#### 8.3.2 运行时语义

1. 若存在返回操作数，在当前函数帧读取其值。
2. 将结果复制到调用者的返回值位置。
3. 离开当前函数的所有活动块作用域，销毁当前函数帧。
4. 控制权恢复到调用者的 `funcall` 之后；非 `void` 结果用于初始化调用点新 `var`。

若读取返回值或执行被调函数期间发生运行时错误，整个程序立即终止，调用点新 `var` 不成为已初始化绑定。

### 8.4 函数作用域与控制流域

#### 8.4.1 名称查找

函数体内普通裸标识符按以下优先级查找：

| 优先级 | 查找对象 | 说明 |
|--------|---------|------|
| 1 | 当前块局部绑定 | 从声明完成后可见 |
| 2 | 逐层外部块 | 可屏蔽外层绑定（参数除外） |
| 3 | 函数体直接局部绑定 | |
| 4 | 当前函数参数 | 不得被任何层级 `var`/`let` 屏蔽 → `TC_CE_DUPLICATE_DEFINITION` |

到达函数边界后停止，不到模块顶层。访问本库顶层成员须用 `Self.<名>`（§4.3）。

| 冲突场景 | 诊断 |
|---------|------|
| `var`/`let` 与形参同名（任意层级） | `TC_CE_DUPLICATE_DEFINITION` |
| `var`/`let` 与全局函数同名 | `TC_CE_FUNCTION_NAME_CONFLICT` |
| 裸名引用本库顶层成员（RHS/赋值/`read`/`let`/`funcall`/`return`） | `TC_CE_FUNCTION_SCOPE_ACCESS` |

函数返回时销毁所有局部运行时槽；`let` 编译期内联，不分配运行时槽。

#### 8.4.2 顶层与函数的控制流域

顶层语句区与每个函数各自构成独立的控制流域：可达性、确定初始化与返回路径彼此封闭。只有函数域支持 `goto`/`label` 与 `return`。`return` 只退出当前函数，`break`/`continue` 只解析到当前函数内最内层 `while`。跨函数或跳向顶层的 `goto` 落在 §7.3.2 步骤 6，报 `TC_CE_LABEL_NOT_FOUND`。顶层 `return` 报 `TC_CE_RETURN_OUTSIDE_FUNCTION`。

### 8.5 调用模型

每次 `funcall` 在抽象机器上创建独立调用帧。物理布局不是可观察行为；所有符合一致性的实现必须保持相同可观察语义。

| 步骤 | 操作 |
|------|------|
| 1 | 按形参顺序从左到右读取实参；任一运行时错误立即终止程序 |
| 2 | 创建被调帧并写入参数，从函数体首条语句执行 |
| 3 | `return` 销毁帧并恢复调用者；非 `void` 结果用于初始化调用点新 `var` |

### 8.6 无环调用图

若函数调用关系包含直接或间接递归环（含自调用），则报告 `TC_CE_RECURSION`，无论调用点运行时是否可达。

## 9. 作用域、生命周期与确定初始化

### 9.1 作用域

TC 采用全局函数签名表 + 顶层值作用域 + 函数作用域 + 块级作用域 + 标签作用域：

| 作用域 | 范围 | 可见规则 | 名称冲突 |
|--------|------|---------|---------|
| 全局函数签名表 | 全程序 | 函数名全局可见，仅 `funcall` 解析；不受定义源序限制 | 函数名唯一（§8.1.2）；调用图不得有环（§8.6） |
| 顶层值作用域 | `#program` 顶层非块内 `var`/`let` | 源序可见，生命周期贯穿程序始终 | 同作用域不得重复；`#lib` 无此层 |
| 函数作用域 | 每个函数体（含参数、局部 `var`/`let`） | 名称查找到函数边界即止；每次调用独立帧 | 不得屏蔽参数或与全局函数同名 |
| 块级作用域 | `if` then/else 互斥兄弟块；`while` 体块 | 兄弟分支互不可见（可同名）；嵌套块可屏蔽外层绑定 | 禁止重声明全局函数名与函数形参 |
| 标签作用域 | 函数体内（§7.3） | `goto` 沿祖先链由内向外查找同函数同名标签 | 同块禁止同名标签；每个函数独立标签表 |

**补充规则**：

| 规则 | 说明 |
|------|------|
| 源序可见性 | 绑定从声明结束后可见；初始化器不可引用自身或尚未声明的标识符 |
| `var` 初始化状态 | 由 §9.2 确定初始化判定；`let` 统一编译期求值内联，不以路径是否经过声明行为条件 |
| 变量生命周期 | 见下表 |

| 变量类别 | 槽位建立 | 初始化时机 | 销毁时机 |
|---------|---------|-----------|---------|
| 顶层 `var`/`let` | 程序启动时 | `var` 执行后；`let` 编译期 | 程序终止时 |
| 函数参数 | 调用帧建立时 | 帧建立时写入（已初始化） | 函数返回时 |
| 函数体/块内局部 `var` | 进入作用域时 | 执行到对应 `var` | 离开块实例时（`end`/循环回边/`break`/`continue`/`return`/向外 `goto`） |
| 局部 `let` | 无运行时槽 | 编译期求值内联 | 无 |

反向跳转或下一迭代再次执行同一 `var` 时，重新初始化同一词法槽。

### 9.2 变量生命周期与确定初始化

声明时强制 RHS 与确定初始化是两个独立保证：前者约束源代码形态，后者要求在每条可达执行路径上，每次对绑定的运行时读取（及赋值/`read` 目标）之前，相应的初始化语句确已执行。

| 事件 | 行为 |
| ---- | ---- |
| 作用域进入 | 建立本作用域全部 `var` 的固定槽位，初始为未初始化 |
| `var` 执行 | 先求值 RHS 或执行非 `void` `funcall` 初始化器，再写入槽位；成功后变为已初始化 |
| 赋值 / `read` / `memblock_store` / `memblock_copy` | 目标必须已确定初始化；成功后更新槽内容，不改变生命周期 |
| 运行时绑定读取 | `var` 或参数须在当前程序点确定初始化 → `TC_CE_UNINITIALIZED_VARIABLE`；`let` 已在编译期内联，不适用 |
| 反向跳转 / 下一迭代 | 再次执行 `var` 时重新初始化同一槽，不创建新绑定 |
| 作用域离开 | 结束局部生命周期并清除确定初始化状态；物理槽可复用 |
| 参数 | 函数入口已初始化，只读；不得赋值或作为 `read` 目标 |
| `return` | 终止当前函数路径，销毁当前函数帧及活动块局部槽 |

**路径语义（规范性）**：在控制流域入口到程序点 *p* 的每条可达路径上，若绑定在 *p* 处仍处于生命周期内，且该路径上均已成功执行其初始化语句，则该绑定在 *p* 处确定初始化。会合点取各可达前驱的合取：仅当所有可达路径均已初始化时成立。静态恒真/恒假条件按 §5.2 裁剪不可能边。不可达语句报 `TC_CE_UNREACHABLE_STATEMENT`，不参与确定初始化判定但仍须通过词法、语法、名称与类型检查。

任何符合 0.0.42 的实现必须得到相同的合法程序集合与相同的首个相关诊断；具体求解算法不属于语言定义。

## 10. 标准 I/O

标准 I/O 仅操作标量类型（`int8`～`uint64`、`isize`、`usize`、`float32`、`float64`、`bool`）。`memblock`、结构体和指针类型（`ptr<T>`）参数属语法拒绝（`TC_CE_SYNTAX`），须由程序按元素/字段自行完成。

### 10.1 `write` — 不换行输出

**形式一：无格式输出**

| 项目       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 语法       | `write(int32, x)`、`write(float64, pi)`、`write(bool, flag)` |
| 功能       | 将操作数的值按类型解释写入 stdout，不换行                |
| 操作数规则 | 一个 §6.1.2 `operand`：运行时 `var` / 参数须确定初始化，`let` 须可见且已成功求值，或使用合法字面量 |
| 类型约束   | 显式类型参数必须是 `scalar_type`；标识符绑定类型与该标量类型一致；字面量满足 §3.6 约束 |
| 输出格式   | 整数：十进制（`isize`/`usize` 按平台宽度解释）；浮点：与 `%g` 相同的 6 位有效数字；布尔：`true`/`false` |

操作数声明类型须与显式类型一致（`TC_CE_TYPE_MISMATCH`），字面量不兼容时使用 `TC_CE_LITERAL_TYPE` / `TC_CE_LITERAL_OUT_OF_RANGE`。

**形式二：格式化输出**

| 项目       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 语法       | `write(int32, %d, x)`、`write(float64, %0.3f, pi)`、`write(bool, %-8t, flag)` |
| 功能       | 按格式说明符输出操作数的值，不换行                       |
| 操作数规则 | 一个 §6.1.2 `operand`；恰好一个操作数                      |
| 类型约束   | 显式类型参数为 `scalar_type`；操作数类型与其一致，且与格式说明符的转换符兼容 |

格式化类型检查顺序：先检查操作数与显式类型的一致性，成功后再检查转换符兼容性（`TC_CE_FORMAT_TYPE_MISMATCH`）。两类不一致同时存在时先报告前者。`write` / `writeln` / `read` 的操作数个数与对应产生式不符（多余或缺失）时报告 `TC_CE_OPERAND_COUNT`，不得改报笼统 `TC_CE_SYNTAX`。运算、转换等调用的操作数个数失配同样使用 `TC_CE_OPERAND_COUNT`。

### 10.2 `writeln` — 换行输出

与 `write` 相同，但在输出末尾追加一个 LF 字节（`\n`），不随主机平台改写为其他行结束序列。会把文本流 LF 转换为其他字节序列的宿主上，实现必须使用二进制流或等价机制。`write`/`writeln` 向 stdout 写入失败时报 `TC_RE_IO`。

每条 `write`/`writeln` 先生成本语句的完整输出字节串，再尝试一次抽象逻辑提交。只有全部提交成功时字节串才追加到 TC 抽象标准输出；失败时贡献零字节，此前已成功提交的输出不回滚。实现可缓冲或多次宿主导出完成一次提交，但不得重排成功语句。失败时物理写出的前缀属外部设备泄漏，不属于 TC 可观察行为。

### 10.3 `read` — 标准输入

| 项目     | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| 语法     | `read(int32, x)`、`read(float64, radius)`、`read(bool, flag)` |
| 功能     | 从 stdin 读取一个值，覆盖已定义变量的当前值              |
| 目标变量 | 必须是已通过带 RHS 的 `var` 声明、在当前程序点已确定初始化且类型与显式 `scalar_type` 一致的可写**标量**变量；函数参数只读，不得作为目标；`memblock` 目标不合法（语法拒绝） |
| 与初始化 | `read` 不是初始化器，不能代替 `var … = …` 或补救被控制流绕过的初始化 |
| 输入格式 | 见下表；跳过前导 ASCII 空白，并读取一个以 ASCII 空白或 EOF 结束的完整 Token |
| 错误处理 | 非法输入/数值超范围/非预期 EOF → I/O 错误                |

`read` 目标名称分类与 §6.2 赋值左侧相同（`TC_CE_FUNCTION_SCOPE_ACCESS` / `TC_CE_UNDEFINED_VARIABLE` / `TC_CE_CONSTANT_ASSIGNMENT` / `TC_CE_PARAMETER_ASSIGNMENT`），仅可写 `var`/`static var` 继续检查。`memblock` 目标在语法阶段被 `scalar_type` 拒绝。

目标名称已解析为可写标量 `var` 后，若其声明类型与 `read` 的显式标量类型不一致，报 `TC_CE_TYPE_MISMATCH`。该类型检查在确定初始化检查之前完成；类型不一致时不产生 `TC_CE_UNINITIALIZED_VARIABLE`。

**静态成员作为 `read` 目标**：可通过 `Self.<成员名>` 或 `<模块名>.<成员名>` 覆盖公开标量 `static var`。解析和可见性规则与赋值一致（§4.3/§4.4）。`static var` 在程序准备阶段已完成初始化。公开 `memblock` `static var` 不得作为 `read` 目标。

**输入规则**：

| 目标类型            | 输入格式                                      |
| ------------------- | --------------------------------------------- |
| `int*` / `isize`       | 可选 `-` 前缀 + 连续十进制数字，至少一位      |
| `uint*` / `usize`      | 连续十进制数字，至少一位；不接受 `-` 前缀 |
| `float32`/`float64` | 必须完整匹配下述 `input_float_token` |
| `bool`              | `true` 或 `false`（大小写敏感，均为小写）     |

本节的 ASCII 空白仅指 U+0009～U+000D 与 U+0020，不受 locale 影响。输入必须完整匹配目标格式；例如 `12abc` 整体非法，不得只接受前缀 `12`。

**输入 Token 的权威 EBNF**：

```ebnf
signed_input_integer
           = [ "-" ] , input_digits ;

unsigned_input_integer
           = input_digits ;

bool_input_token
           = "true" | "false" ;

input_float_token
           = finite_input_float
           | "inf"
           | "-" , "inf"
           | "nan" ;

finite_input_float
           = [ "-" ] , input_digits , [
               "." , input_digits , [ input_exponent ]
             | input_exponent
           ] ;

input_exponent
           = ( "e" | "E" ) , [ "+" | "-" ] , input_digits ;

input_digits = input_digit , { input_digit } ;
input_digit  = "0" … "9" ;
```

`read(int*, ...)`、`read(uint*, ...)`、`read(bool, ...)` 分别完整匹配 `signed_input_integer`、`unsigned_input_integer`、`bool_input_token`，再按目标类型检查范围。整数输入固定为十进制，允许前导零和 `-0`，不接受前导 `+`、进制前缀、分隔符或源代码字面量后缀。

`input_float_token`（`read` 浮点输入接受集）：
- 十进制整数串（`1`、`-42`、`0`、`0007`）为合法有限浮点输入。
- 小数须在 `.` 前后均有数字（`1.` 和 `.5` 非法）。
- 支持完整指数形式（`1e5`、`1E+5`、`1e-5`、`1.25e-3`）。
- 前导 `-` 仅可用于有限值和 `inf`；不接受 `+`、`-nan`、不完整指数、`f`/`F` 后缀、分隔符、十六进制浮点。`inf`/`nan` 大小写敏感。
- 须先完整匹配 EBNF 再做数值转换，宿主扩展形式不扩大 TC 输入集。

有限浮点输入（包括整数书写形式）先解析为精确十进制数学值，再按 roundTiesToEven 直接舍入到目标 binary32/binary64；不得先解析为 TC 整数类型，也不得通过另一浮点类型中转。因此整数书写形式不受 `uint64` 字面量词法上限约束，其可表示性只按目标浮点类型判定。有限输入的精确数学值为零且 Token 显式带前导 `-` 时生成负零，其余零输入生成正零。非零有限值舍入为零、有限值舍入为无穷，或整数目标的输入超出目标整数类型范围，均报 `TC_RE_IO`；可表示的非规格化数合法。`nan` 输入生成 §6.3.3 规定的 canonical quiet NaN。非法 Token 与意外 EOF 同样报 `TC_RE_IO`。

`read` 先完整扫描并验证一个输入 Token，再转换并提交目标值；只有全部步骤成功后才覆盖目标变量。失败时目标槽保持原值，随后程序终止。解析过程不受当前 locale、宿主 `strto*` 扩展拼写或宿主浮点中间精度影响。

### 10.4 格式转换符定义

| 符号 | 含义                     | 适用类型            | 示例（值 42/3.14159265） |
| ---- | ------------------------ | ------------------- | ------------------ |
| `%d` | 有符号十进制             | `int8`～`int64`、`isize` | `42`               |
| `%i` | 有符号十进制（同 `%d`）  | `int8`～`int64`、`isize` | `42`               |
| `%u` | 无符号十进制             | `uint8`～`uint64`、`usize` | `42`               |
| `%x` | 十六进制（小写 a-f）     | 任一整数类型        | `2a`               |
| `%X` | 十六进制（大写 A-F）     | 任一整数类型        | `2A`               |
| `%o` | 八进制                   | 任一整数类型        | `52`               |
| `%b` | 二进制                   | 任一整数类型        | `101010`           |
| `%t` | 布尔值文本               | `bool`              | `true`             |
| `%f` | 浮点十进制（固定小数）   | `float32`/`float64` | `3.141593`         |
| `%e` | 科学计数法（小写 e）     | `float32`/`float64` | `3.141593e+00`     |
| `%E` | 科学计数法（大写 E）     | `float32`/`float64` | `3.141593E+00`     |
| `%g` | 紧凑格式（较短）         | `float32`/`float64` | `3.14159`          |
| `%G` | 紧凑格式（较短，大写 E） | `float32`/`float64` | `3.14159`          |

**确定性格式规则**：

- 格式化不受进程 locale 影响，小数点固定为 `.`。
- 未显式给出精度时，`%f`/`%e`/`%E` 输出小数点后 6 位，`%g`/`%G` 输出 6 位有效数字。
- 十进制输出以源 binary32/binary64 值的精确数学值为输入，按 roundTiesToEven 舍入到所需十进制位数；不得先经过宿主的更低精度类型。
- `%e`/`%E` 在小数点前保留恰好一位非零数字（零值为 `0`），指数始终含 `+` 或 `-`，且至少两位十进制数字。
- `%g`/`%G` 先以当前精度 `p` 位有效数字舍入。设舍入后值的十进制指数为 `e`（即科学计数法中小数点前恰好一位时的指数）：当 `e < -4` 或 `e >= p` 时使用 `%e`/`%E` 形式，否则使用定点形式。未使用 `#` 标志时，小数部分末尾的 `0` 全部删除；若小数部分为空，同时删除小数点。
- `%d`/`%i` 按有符号数学值输出，`%u` 按无符号数学值输出。
- `%x`/`%X`/`%o`/`%b` 对任意整数输出其固定宽度二进制补码位模式，默认不带进制前缀（`#` 备用形式见 §10.5）。零恰好输出 `0`；其他非负值省略前导零；负值保留足以表示完整类型位宽的全部数字。例如 `int8` 值 `-1` 分别输出 `ff`、`FF`、`377`、`11111111`。
- `%e` 使用小写指数标记，`%E` 使用大写指数标记；`%G` 的指数标记与特殊值使用大写。
- 有限负零保留符号，例如 `%f` 输出 `-0.000000`，`%g` 输出 `-0`。
- 不带格式控制时，特殊值固定输出 `inf`、`-inf`、`nan`；在 `%E`/`%G` 下输出 `INF`、`-INF`、`NAN`。`+` 与字段宽度按 §10.5 作用于这些文本；NaN payload 不通过文本 I/O 暴露。

上述 `%g` / `%G` 规则中，零（含负零）使用十进制指数 `e = 0`。NaN 的符号位和 payload 均不通过文本输出：NaN 默认输出 `nan` / `NAN`，即使其位模式符号位为 1 也不添加 `-`；仅 `+` 标志会添加 `+`。所有十进制格式化舍入均使用 roundTiesToEven。

### 10.5 C99 风格格式控制

格式说明符采用以下形态，且整体必须是无空白的单个 Token：

语法形态见附录 A 的 `format_specifier`。

TC 参考 C99 `printf` 的静态格式控制，但格式说明符不是运行时值：一条 `write`/`writeln` 仍只包含一个格式说明符和一个操作数。`flags` 中每个标志至多出现一次，顺序不限；`width` 与 `precision` 只能写十进制常量，不支持 `*` 动态取值。

**确定性拆分规则**：从 `%` 后开始依次读取标志；连续的 `0` 字符在尚未开始字段宽度时合并为一个 `0` 标志，首个 `1`～`9` 才开始 `width`，其后的所有十进制数字均属于宽度。`.` 开始精度，转换符结束说明符。因此 `%08.3f` 唯一拆分为标志 `0`、宽度 `8`、精度 `3`；`%0008d` 等价于 `%08d`，同样拆分为标志 `0`、宽度 `8`。解析不得凭 EBNF 的其他可选分组选择不同拆分。此规则与 C99 `printf` 的行为一致：多写的前导零不产生重复标志错误。

| 控制项 | 语法 | 语义 |
| ------ | ---- | ---- |
| 左对齐 | `-` | 结果不足字段宽度时在右侧补 ASCII 空格；同时出现 `0` 时 `0` 被忽略 |
| 强制符号 | `+` | `%d`/`%i` 及浮点转换中未以 `-` 起始的结果添加 `+`；包括 `+inf` 和 `+nan` |
| 备用形式 | `#` | `%x`/`%X`/`%b` 的非零结果添加 `0x`/`0X`/`0b`；`%o` 保证首位为 `0`；有限浮点结果始终保留小数点，且 `%g`/`%G` 保留精度要求的末尾零 |
| 零填充 | `0` | 指定字段宽度且未左对齐时，在符号或进制前缀之后、数字之前补 `0`；整数转换显式指定精度时忽略该标志 |
| 最小字段宽度 | `width` | 取值 `1`～`65535`；结果较短时按对齐和填充规则补齐，结果较长时不得截断。本版本上界为教学与实现成本设定的硬上限；超出范围 → `TC_CE_FORMAT_SPECIFIER`。更长填充应通过循环或其它显式手段完成，不得依赖更大的格式宽度 |
| 精度 | `.precision` | 取值 `0`～`65535`；仅写 `.` 等价于 `.0`；各转换的含义见下表。上界意图与 `width` 相同；超出范围 → `TC_CE_FORMAT_SPECIFIER` |

| 转换符 | 显式精度的含义 |
| ------ | ---------------- |
| `%d`、`%i`、`%u`、`%x`、`%X`、`%o`、`%b` | 最少数字位数；不足时在数字左侧补 `0`。值为零且精度为零时不输出数字，但 `%#.0o` 仍输出 `0` |
| `%f` | 小数点后的数字位数 |
| `%e`、`%E` | 小数点后的数字位数，指数部分不计入精度 |
| `%g`、`%G` | 有效数字位数；精度为零按 1 位处理（继承 C99 语义：显式 `.0` 并非"不要有效数字"，而是"有效数字至少 1 位"） |
| `%t` | 不允许指定精度 |

标志的适用范围如下；表中未列出的组合是静态格式错误：

| 转换符 | 允许的标志 |
| ------ | ---------- |
| `%d`、`%i` | `-`、`+`、`0` |
| `%u` | `-`、`0` |
| `%x`、`%X`、`%o`、`%b` | `-`、`#`、`0` |
| `%f`、`%e`、`%E`、`%g`、`%G` | `-`、`+`、`#`、`0` |
| `%t` | `-` |

字段宽度按最终 ASCII 输出字符数计算；符号和进制前缀计入宽度，精度不包含它们。处理顺序为：按转换符和精度生成数字文本，添加符号或进制前缀，再按字段宽度填充。对 `inf`/`nan`，精度不改变文本，`0` 按空格填充处理。无 `width` 时 `-`/`0` 不产生填充，因此 `%0.3f` 与 `%.3f` 输出相同；例如值 `3.14159265` 分别得到 `3.142`，而 `%08.3f` 得到 `0003.142`。

已匹配附录 A `format_specifier` 形态后，重复标志、宽度或精度超出上述范围，以及转换符不适用的标志/精度，均报告 `TC_CE_FORMAT_SPECIFIER`。不符合该 EBNF 的形式按语法规则报告 `TC_CE_SYNTAX`。`%p`、C99 空格标志、长度修饰符（如 `hh`/`l`/`ll`/`L`）和 `*` 均不受支持；TC 的类型已由第一个参数显式给出。

## 11. 诊断与错误处理

静态错误与运行时错误均采用 fail-fast：报告**第一个**规范诊断后即停止。静态错误覆盖词法/语法、模块与导入、名称与作用域、类型/字面量/模式、常量求值、缩进与控制流、函数调用与返回、可达性与确定初始化、以及调用图无环等；正文与附录 A 在相关条款中给出触发条件与错误码。完整错误码速查见附录 B（86 码）。多错误并存时的阶段顺序、源位置比较与专用优先级由实现的确定性诊断规则规定，但不得改变本文已给出的错误码与合法程序集合。

### 11.1 运行时错误

遇到**第一个**运行时错误即终止程序（fail-fast）。运行时错误类型包括：

| 错误类型         | 错误码                                | 触发条件                                                     |
| ---------------- | ------------------------------------- | ------------------------------------------------------------ |
| 除零错误         | `TC_RE_DIVISION_BY_ZERO`             | 整数 `div`/`mod` 除数为 0；严格浮点 `div` 除数为零，或浮点 `mod` 中有限非零数对零取模  |
| 整数溢出错误     | `TC_RE_INTEGER_OVERFLOW`             | 有符号算术结果超范围、`div(INT_MIN, -1)`、`abs(INT_MIN)` 等 |
| 负移位计数错误   | `TC_RE_NEGATIVE_SHIFT_COUNT`         | `shl`/`shr` 的有符号移位计数数学值小于 0                     |
| 浮点溢出错误     | `TC_RE_FLOAT_OVERFLOW`               | 严格模式浮点运算的结果舍入为 ±∞                              |
| 浮点下溢错误     | `TC_RE_FLOAT_UNDERFLOW`              | 严格模式浮点运算的结果为微小非精确非规格化数                  |
| 浮点无效操作     | `TC_RE_FLOAT_INVALID`                | 严格浮点运算输入含 NaN 或产生 0/0、∞−∞、0×∞ 等               |
| 转换溢出错误     | `TC_RE_CAST_OVERFLOW`                | 严格 `cast` 的数学结果无法在目标类型中表示                     |
| 空指针解引用错误 | `TC_RE_NULL_POINTER_DEREFERENCE`    | `ptr_load`/`ptr_store`/`memcopy_unsafe` 或指针序关系比较的操作数为 `nullptr` |
| 空指针算术错误   | `TC_RE_NULL_POINTER_ARITHMETIC`    | `ptr_add`/`ptr_sub` 的操作数为 `nullptr` |
| I/O 错误         | `TC_RE_IO`                           | `read` 输入非法/超范围/EOF，或标准输入/输出读写失败            |
| memblock 越界    | `TC_RE_MEMBLOCK_INDEX_OUT_OF_RANGE`  | `memblock_load`/`store` 下标越界，或 `memblock_copy` 区间不合法 |
| memcopy_unsafe 区间非法 | `TC_RE_MEMCOPY_UNSAFE_INVALID_RANGE` | `memcopy_unsafe` 的 `length` 运行时为负                     |

**运行时错误提交规则**：每条 TC 指令在抽象机器中先读取全部实际需要读取的操作数并完成检查，再提交目标值。发生运行时错误时不提交当前指令的目标槽、调用返回值或新 `var` 的已初始化状态。首个运行时错误立即终止整个程序，不执行清理代码、后续语句或调用者续点，也不回滚此前已成功完成的赋值与 I/O。

### 11.2 编译警告

TC 无编译警告，也不以警告方式放行初始化、溢出、类型或控制流违规。

## 附录 A：形式化语法（EBNF）

本附录为 TC 语言的权威语法定义。语义规则以正文为准。**语法拒绝**与**静态语义拒绝**的判定口径以 §1.3 第 2 款为准：不符合本附录产生式的 Token 序列属语法拒绝；本附录已接受、但正文类型/模式/作用域等规则不成立时属静态语义拒绝。

### A.1 符号约定

采用 扩展巴科斯-瑙尔范式（EBNF）：

| 元符号   | 含义              |
| -------- | ----------------- |
| `=`      | 产生式定义        |
| `\|`     | 择一              |
| `[ … ]`  | 可选（0 或 1 次） |
| `{ … }`  | 重复（0 或多次）  |
| `( … )`  | 分组              |
| `"…"`    | 终结符            |
| `"a" … "z"` | 包含两端的字符范围 |
| `? … ?`  | 用自然语言描述的词法特殊序列 |
| *斜体名* | 非终结符          |

### A.2 词法与缩进 Token

词法分析的输入必须先通过 §2.1 的 UTF-8、BOM、U+0000 与源字符合法性检查。注释外的非 ASCII 字符不能被规范化、转写或当作空白，而必须报 `TC_CE_SYNTAX`。

字符检查成功后，词法分析按最长匹配生成 Token，再将完整标识符与关键字表比较。`varx` 因而是一个 `IDENTIFIER`，绝不能拆成 `VAR` + `IDENTIFIER`。除行首缩进外，Token 间的 ASCII 空格和制表符由词法层丢弃；语法层不使用可匹配零字符的 `ws` 充当关键字边界。

```ebnf

digit        = "0" … "9" ;

/* ── 标识符与字面量 ── */

identifier_continue = ascii_letter | digit | "_" ;
identifier = identifier_start , { identifier_continue } ;

           = ( "-" , (
               dec_literal
             | hex_literal
             | bin_literal
             | oct_literal
           ) )
           | (
               dec_literal [ "u" | "U" ]
             | hex_literal [ "u" | "U" ]
             | bin_literal [ "u" | "U" ]
             | oct_literal [ "u" | "U" ]
           ) ;
/* 负号仅可与无后缀字面量组合；禁止 -42u 等形式（§2.3.1） */

float_literal = [ "-" ] , (
    dec_float_literal [ ( "e" | "E" ) , [ "+" | "-" ] , digit , { digit } ]
  | sci_int_float_literal
) , [ "f" | "F" ] ;

           = digit , { digit } , ( "e" | "E" ) , [ "+" | "-" ] ,
             digit , { digit } ;
/* 允许 1e5 等无小数点的科学计数法（§2.4.2）；亦允许 1.2e5 */

float_special = "inf" | "-" , "inf" | "nan" ;
/* -inf 合法；-nan 非法 */

bool_literal = "true" | "false" ;

dec_literal = non_zero_digit , { [ "_" ] digit } | "0" ;
hex_literal = ( "0x" | "0X" ) , hex_digit , { [ "_" ] hex_digit } ;
bin_literal = ( "0b" | "0B" ) , ( "0" | "1" ) , { [ "_" ] ( "0" | "1" ) } ;
oct_literal = ( "0o" | "0O" ) , ( "0" … "7" ) , { [ "_" ] ( "0" … "7" ) } ;
non_zero_digit = "1" … "9" ;

/* ── 类型关键字 ── */

int_type   = "int8"   | "uint8"
           | "int16"  | "uint16"
           | "int32"  | "uint32"
           | "int64"  | "uint64"
           | "isize"  | "usize" ;
float_type = "float32" | "float64" ;
bool_type  = "bool" ;
scalar_type = int_type | float_type | bool_type ;
sized_memblock_type = "memblock" , "<" , memblock_element_type , "," , usize_operand , ">" ;
/* usize_operand 须为编译期 usize 常量：整数字面量或类型为 usize 的 let/static let 标识符（含 Self./导入限定名），≥ 1（§3.8.1）。
   该 N 是元素个数规划，不参与类型等价（类型仅由 memblock_element_type 决定）。 */
memblock_element_type = scalar_type | sized_memblock_type | struct_type | ptr_type ;
usize_operand = integer_literal    /* 以 usize 为期望类型检查 */
              | identifier          /* 须解析为类型是 usize 的 let / static let */
              | qualified_identifier
              | imported_member_name ;
struct_type = identifier | imported_member_name ;
/* struct_type 的 identifier 必须解析为本模块已定义的结构体名；
   imported_member_name 必须解析为已导入库的 public struct。 */
ptr_type   = "ptr" , "<" , pointee_type , ">" ;
pointee_type = scalar_type | sized_memblock_type | struct_type | ptr_type ;
/* ptr<void> 由 §3.10.1 静态语义拒绝。 */
type       = scalar_type | sized_memblock_type | struct_type | ptr_type ;
value_type = type ;
return_type = value_type | "void" ;
field_type = scalar_type | sized_memblock_type | struct_type | ptr_type ;
/* 字段类型中结构体名按位置分流（§3.9.1）：
   - 值位置（字段类型本身为 struct_type，或 memblock 的元素类型）
     不得为当前正在定义的结构体，且不得前向引用尚未完成定义的结构体；
   - 指针所指位置（某一层 ptr<…> 的 pointee）
     可为完整类型，或当前正在定义的本结构体（指针自引用）；
     仍不得前向引用其它尚未完成定义的结构体。
   ptr<void> 由 §3.10.1 静态语义拒绝。 */

/* ── 运算与模式关键字 ── */

binary_arith_op = "add" | "sub" | "mul" | "div" | "mod" ;
unary_arith_op  = "abs" | "neg" ;
bitwise_op      = "and" | "or" | "xor" ;
unary_bitwise_op = "not" ;

format_width = non_zero_digit , { digit } ;

           | "f" | "e" | "E" | "g" | "G" ;
/* 最长匹配形成一个无空白 Token；0 与 width 的唯一拆分算法、重复标志、
   数值范围和各转换符允许的控制项由 §10.5 静态检查。EBNF 的可选分组

if_kw      = "if" ;

break_kw   = "break" ;
continue_kw = "continue" ;

label_kw   = "label" ;

funcall_kw = "funcall" ;
return_kw  = "return" ;

static_kw  = "static" ;
self_kw    = "Self" ;
import_kw  = "import" ;
public_kw  = "public" ;
private_kw = "private" ;
program_directive = "#program" ;
lib_directive = "#lib" ;

/* ── 注释 ── */

line_comment = ";" , { ? any decoded Unicode scalar value except U+0000, U+000A and U+000D ? } ;

/* 注释内允许 Unicode；注释外的 Token 和结构字符仅允许 §2.1
   列出的 ASCII。LF、CRLF 与 CR 由词法层作为行结束处理。 */
```

**缩进规则**：

缩进由逻辑行开头的连续 ASCII 空格（U+0020）数量决定，每 4 个空格为一级。行首出现 U+0009 水平制表符时报 `TC_CE_INDENT_MIXED`。

缩进增加时必须恰好增加一级（增加多级为错误）。缩进减少时，减少后的级别必须是某个外层块的级别，且 `else` 和 `end` 必须与对应的 `func`/`if`/`while`/`struct` 对齐。

空行和纯注释行不改变缩进层级，其行首空白也不参与缩进检查。`label` 不改变缩进层级。

其他违反以上缩进规则的情形报 `TC_CE_INDENT_INSUFFICIENT`。`else`/`end` 与对应块头不对齐时报 `TC_CE_INDENT_ELSE_END`。

### A.3 语法

本节作用于 A.2 输出的 Token 序列。`NEWLINE`、`INDENT`、`DEDENT`、`EOF` 是虚拟终结符；`identifier`、`integer_literal` 等名称引用 A.2 的完整 Token 类别。EBNF 中以 `"…"` 标记的关键字或标点表示一个完整 Token，不按子序列匹配。非行首空白与行末注释已由词法层移除。

本 EBNF 同时规定全部语法诊断边界。位置实参、非 `operand` 实参、作为 `let` 或赋值 RHS 的 `funcall`、`return` 后的运算/转换/`funcall`，以及 `void` 出现在函数返回类型以外的位置，均必须在语法阶段拒绝。各专用产生式中的类型非终结符和模式参数位置同样具有约束力：例如位运算/移位只接受 `int_type`，逻辑运算只接受 `bool_type`，比较只接受整数或浮点类型；`write` / `writeln` / `read` 的显式类型参数只接受 `scalar_type`，因此 `write(memblock<int32>, …)` / `read(memblock<uint8>, …)` 为 `TC_CE_SYNTAX`；`memblock` 类型构造器与值构造器的元素类型、以及 `memblock_load` / `memblock_store` / `memblock_copy` 的显式类型参数接受 `void` 以外的任意完整类型（`memblock_element_type`），因此 `memblock<ptr<int32>, 4>`、`memblock<MyStruct, 8>`、`memblock<memblock<int32, 3>, 5>` 等嵌套形态均可通过语法阶段；`memcopy_unsafe` 的显式类型参数 `T` 接受 `void` 以外的完整类型；`memblock` 值构造器必须匹配 `memblock_fill_ctor` / `memblock_elems_ctor`（命名实参 `count:`、`usize_operand` 及可选 `fill:` 标签，§3.8.3）；运行时 `wrap_shift_expr` 只接受 `shl`，比较、逻辑和按位运算没有模式参数位置。不满足这些形态时，除下列白名单外统一报告 `TC_CE_SYNTAX`，不得为产生 `TC_CE_TYPE_MISMATCH` 或 `TC_CE_MODE_MISMATCH` 而放宽语法。白名单（专用语法码，不得改报笼统 `TC_CE_SYNTAX`）：① `if` / `while` / `func` / `struct` 产生式要求的 `end` 缺失 → `TC_CE_MISSING_END`；② `write` / `writeln` / `read` 以及运算、转换等调用的操作数个数与对应产生式不符 → `TC_CE_OPERAND_COUNT`。常量表达式由独立 `const_*` 产生式决定边界；其中 `const_shift_expr` 接受候选 `mode`，非法组合在后续静态语义阶段报告 `TC_CE_MODE_MISMATCH`。`var_funcall_def`、独立 `funcall` 和 `return [operand]` 的返回类型适配属于后续静态语义。`statement` 产生式复用 `label_def` / `goto_stmt` 只表示其行内语法；二者必须具有 `func` 词法祖先的上下文约束由 §7.3 在静态语义阶段强制执行。参数表中形参名是否重复由 §8.1.2 在静态语义阶段报告 `TC_CE_DUPLICATE_PARAMETER`，不在本 EBNF 拦截。

`#program` 的顶层分为类型定义区、声明区与可执行语句区（见 `program_type_region` / `program_decl_region` / `program_exec_region`）。块内 `suite` 仍使用完整 `statement`，因此 `if` / `while` 体内可以声明 `var` / `let`。若 Token 序列在顶层已进入可执行语句区后又出现顶层 `var` / `let` / `var_funcall_def`，则不符合 `program_module`；语法阶段对此类分区破坏报告 `TC_CE_MODULE_LAYER`（定位到该声明首 Token），不得仅报笼统 `TC_CE_SYNTAX`。

`#lib` 的 `library_struct_definition` / `static_constant_def` / `static_variable_def` / `function_definition` 均要求以 `public` 或 `private` 为第一个修饰符。若某一顶层成员在其余外形已可识别为 `struct` / `static let` / `static var` / `func` 定义，但缺少该可见性前缀，则不符合上述产生式；语法阶段受限恢复中报告 `TC_CE_MISSING_VISIBILITY`（定位到该成员的 `struct` / `static` / `func` 关键字），不得仅报笼统 `TC_CE_SYNTAX`。`#program` 类型定义区仅接受无可见性前缀的 `struct_definition`；若在 `#program` 中于 `struct` 之前写入 `public` / `private`，语法阶段受限恢复报告 `TC_CE_PROGRAM_MODE_MISUSE`（定位到该可见性关键字），同样不放宽接受集。

`constant_def` 只规定 `let` 声明的语法外形；`const_rhs` 结果类型与声明 `type` 的闭合由 §5.2.1 在后续语义检查中强制，不改变 EBNF 的语法接受集。

```ebnf
/* ── 程序 ── */

program    = blank_lines , (
               "#program" , NEWLINE , blank_lines , import_region , program_module
             | "#lib" , NEWLINE , blank_lines , import_region , library_module
           ) , EOF ;

import_region
           = { import_declaration , NEWLINE , blank_lines } ;

import_declaration
           = "import" , identifier ;

program_module
           = program_type_region , program_decl_region , program_exec_region ;
/* #program：第三层类型定义区、第四层声明区（均可为空）必须全部位于
   第五层可执行语句区之前。顶层声明区之后再出现 var / let /
   var_funcall_def → TC_CE_MODULE_LAYER（语法阶段拒绝）。 */

program_type_region
           = { struct_definition , NEWLINE , blank_lines } ;

program_decl_region
           = { program_declaration , NEWLINE , blank_lines } ;

program_declaration
           = variable_def
           | constant_def
           | var_funcall_def ;

program_exec_region
           = { program_exec_statement , NEWLINE , blank_lines } ;

program_exec_statement
           = assignment
           | field_assignment
           | funcall_assign_stmt
           | field_funcall_assign_stmt
           | write_stmt
           | writeln_stmt
           | read_stmt
           | break_stmt
           | continue_stmt
           | label_def
           | goto_stmt
           | void_funcall_stmt
           | return_stmt
           | memblock_store_stmt
           | memblock_copy_stmt
           | ptr_store_stmt
           | memcopy_unsafe_stmt
           | if_stmt
           | while_stmt ;
/* 顶层可执行区不含 variable_def / constant_def / var_funcall_def /
   struct_definition。
   label_def / goto_stmt / break / continue / return 出现在顶层时，
   由后续静态语义分别报告专用错误码（§7 / §8）。 */

library_module
           = type_region , static_region , function_region ;

type_region
           = { library_struct_definition , NEWLINE , blank_lines } ;

library_struct_definition
           = ( "public" | "private" ) , struct_definition ;

static_region
           = { ( static_constant_def | static_variable_def ) ,
               NEWLINE , blank_lines } ;

static_constant_def
           = ( "public" | "private" ) ,
             "static" , constant_def ;

static_variable_def
           = ( "public" | "private" ) ,
             "static" , variable_def ;

blank_lines = { NEWLINE } ;

function_region
           = { function_definition , NEWLINE , blank_lines } ;

statement  = simple_statement
           | if_stmt
           | while_stmt ;
/* statement 用于 func / if / while 的 suite；可含块内声明。 */

simple_statement
           = variable_def
           | constant_def
           | assignment
           | field_assignment
           | funcall_assign_stmt
           | field_funcall_assign_stmt
           | write_stmt
           | writeln_stmt
           | read_stmt
           | break_stmt
           | continue_stmt
           | label_def
           | goto_stmt
           | var_funcall_def
           | void_funcall_stmt
           | return_stmt
           | memblock_store_stmt
           | memblock_copy_stmt
           | ptr_store_stmt
           | memcopy_unsafe_stmt ;
/* label_def / goto_stmt 出现在 program_exec_region 或其嵌套 suite 中时，
   分别报 TC_CE_LABEL_OUTSIDE_FUNCTION / TC_CE_GOTO_OUTSIDE_FUNCTION。 */

/* ── 结构体定义 ── */

struct_definition
           = "struct" , identifier , "then" , NEWLINE ,
             INDENT , struct_field , { NEWLINE , struct_field } ,
             DEDENT , "end" ;
/* end 缺失 → TC_CE_MISSING_END。 */

struct_field
           = ( "let" | "var" ) , identifier , ":" , field_type ,
             [ padding_attr ] ;

padding_attr
           = "@" , "padding" , "(" , integer_literal , ")" ;
/* integer_literal 须为无后缀非负十进制字面量；带 u/U、进制前缀或负号
   的形态由静态语义拒绝（§3.9.3）。 */

/* ── 函数定义 ── */

function_definition
           = ( "public" | "private" ) ,
             "func" , identifier , "(" , [ parameter_list ] , ")" ,
             return_type , "then" , NEWLINE , suite , "end" ;
/* end 缺失 → TC_CE_MISSING_END。 */

parameter_list
           = parameter , { "," , parameter } ;
/* 形参名是否重复由 §8.1.2 报 TC_CE_DUPLICATE_PARAMETER（静态语义）。 */

parameter  = identifier , ":" , value_type ;

return_stmt
           = "return" , [ operand ] ;

/* function_definition 不是 statement，因此不能嵌套在函数体、
   if / else 或 while 内；本语法没有匿名代码块产生式。 */

/* ── 函数调用 ── */

funcall    = "funcall" , "(" , callable_name ,
             { "," , named_argument } , ")" ;

callable_name = identifier | qualified_identifier | imported_member_name ;

qualified_identifier = "Self" , "." , identifier ;

imported_member_name = identifier , "." , identifier ;

named_argument
           = identifier , ":" , ( operand | memblock_constructor | struct_constructor ) ;
/* memblock_constructor 仅在对应形参类型为 memblock<T, N> 时合法；
   struct_constructor 仅在对应形参类型为结构体时合法；
   其他情况由静态语义拒绝（§8.2.2）。 */

var_funcall_def
           = "var" , identifier , ":" , type , "=" , funcall ;

void_funcall_stmt
           = funcall ;

funcall_assign_stmt
           = ( identifier | qualified_identifier | imported_member_name ) ,
             "=" , funcall ;

field_funcall_assign_stmt
           = field_lvalue , "=" , funcall ;
/* 字段目标的可变性规则与 field_assignment 相同（§3.9.5）；
   返回类型须与字段声明类型严格相同。 */

/* 命名实参必须与形参一一对应，文本顺序完全一致；第 i 个形参的
   value_type 是第 i 个实参 operand 的唯一期望类型。
   var_funcall_def / funcall_assign_stmt / void_funcall_stmt 的合法性由实际返回类型筛选。 */

/* ── 变量定义（声明时必须初始化；无可选 RHS） ── */

variable_def = "var" , identifier , ":" , type , "=" , rhs ;

/* ── 常量定义 ── */

constant_def = "let" , identifier , ":" , type , "=" , const_rhs ;
/* const_rhs 结果类型必须与声明 type 完全一致；这是 §5.2.1
   的静态语义约束，不改变本产生式的语法接受集。 */

/* ── 赋值语句 ── */

assignment = ( identifier | qualified_identifier | imported_member_name ) ,
             "=" , rhs ;

field_assignment
           = field_lvalue , "=" , rhs ;

field_lvalue
           = ( identifier | qualified_identifier | imported_member_name ) ,
             { "." , identifier } ;
/* 支持嵌套字段赋值（如 a.b.c = rhs）；每层左侧须解析为结构体类型。
   字段赋值的可变性规则见 §3.9.5 / §6.2。 */

/* ── if 语句（缩进敏感，end 必须） ── */

if_stmt    = "if" , rhs , "then" , NEWLINE , suite ,
             [ "else" , NEWLINE , suite ] ,
             "end" ;
/* end 缺失 → TC_CE_MISSING_END（§1.3 白名单），不得改报笼统 TC_CE_SYNTAX。 */

/* ── while 语句（缩进敏感，end 必须） ── */

while_stmt = "while" , rhs , "then" , NEWLINE , suite ,
             "end" ;
/* end 缺失 → TC_CE_MISSING_END。 */

/* ── break / continue 语句 ── */

break_stmt = "break" ;
continue_stmt = "continue" ;

suite      = { NEWLINE } , [ INDENT , block , DEDENT ] ;
block      = statement , NEWLINE ,
             { NEWLINE | statement , NEWLINE } ;
/* 每个函数体 suite、if 的 then/else suite 和 while 体 suite
   分别对应一个代码块；suite 不含 INDENT 时表示零条语句的
   空代码块。label_def 不开启新代码块，但作为跳转目标，
   是可达性分析的入口点；缩进约束见 §7.1.2。 */

/* ── label 与 goto 语句 ── */

label_def  = "label" , identifier , ":" ;
/* 仅函数内合法；label 不产生新缩进；同级后续语句与 label 缩进一致，
   见 §7.1.2 R7、§7.3.2。goto 的目标是该零动作 label 节点；连续标签
   与块末尾标签均沿正常落入边取得唯一续点。 */
goto_stmt  = "goto" , identifier ;
/* 仅函数内合法，且目标标签必须属于当前函数。 */

/* ── 右值表达式 ── */

rhs        = identifier
           | qualified_identifier
           | imported_member_name
           | field_access
           | integer_literal
           | float_literal
           | float_special
           | bool_literal
           | nullptr_literal
           | binary_arith_expr
           | unary_arith_expr
           | bitwise_expr
           | unary_bitwise_expr
           | shift_expr
           | compare_expr
           | ptr_eq_compare_expr
           | ptr_compare_expr
           | binary_logic_expr
           | unary_logic_expr
           | cast_expr
           | bitcast_expr
           | memblock_load_expr
           | memblock_count_access
           | memblock_constructor
           | struct_constructor
           | ptr_load_expr
           | ptr_address_expr
           | ptr_add_expr
           | ptr_sub_expr
           | ptr_size_expr ;

/* ── rhs 与 const_rhs 的差异说明 ──
 *
 * const_rhs 是 rhs 的子集：所有需要求值运行时常量方可确定结果的产生式均在
 * const_rhs 中排除。差异按类别总结如下：
 *
 *   - 指针操作：ptr_load / ptr_address / ptr_add / ptr_sub / ptr_eq_compare /
 *     ptr_compare 都需要运行时指针值或运行时地址，因此不在 const_rhs 中。
 *     仅 ptr_size 是纯类型级查询，同时在 rhs 和 const_rhs 中。
 *
 *   - memblock 操作：memblock_load 读运行时内存，不在 const_rhs 中。
 *     memblock_count_access 返回编译期常量 N，同时在 rhs 和 const_rhs 中。
 *     memblock_constructor 有独立的 const_memblock_constructor 变体
 *     （全部元素操作数要求为 const_operand）。
 *
 *   - 结构体构造器：struct_constructor 有独立的 const_struct_constructor 变体
 *     （全部字段实参要求为 const_operand）。
 *
 *   - 运算/转换：所有算术、位、移位、比较、逻辑、cast / bitcast 在两层均有
 *     对应产生式（带 const_ 前缀的变体），差异仅在于操作数是 operand 还是
 *     const_operand，以及 const_shift_expr 接受候选 mode。
 *
 *   各产生式的独立注释同样记录其适用的 rhs 集合。正文 §5.2.1 权威定义
 *   const_rhs 的语义边界。 */

/* ── 常量右值表达式 ── */

const_rhs  = integer_literal
           | float_literal
           | float_special
           | bool_literal
           | nullptr_literal
           | identifier
           | qualified_identifier
           | imported_member_name
           | field_access
           | memblock_count_access
           | const_binary_arith_expr
           | const_unary_arith_expr
           | const_bitwise_expr
           | const_unary_bitwise_expr
           | const_shift_expr
           | const_compare_expr
           | const_binary_logic_expr
           | const_unary_logic_expr
           | const_cast_expr
           | const_bitcast_expr
           | const_memblock_constructor
           | const_struct_constructor
           | ptr_size_expr ;

/* ── 常量表达式（只允许单层调用） ── */

const_binary_arith_expr
           = binary_arith_op , "(" , type , "," ,
             [ mode , "," ] , const_operand , "," , const_operand , ")" ;

const_unary_arith_expr
           = unary_arith_op , "(" , type , "," ,
             [ mode , "," ] , const_operand , ")" ;

/* ── 常量位运算表达式 ── */

const_bitwise_expr
           = bitwise_op , "(" , int_type , "," ,
             const_operand , "," , const_operand , ")" ;

const_unary_bitwise_expr
           = "not" , "(" , int_type , "," , const_operand , ")" ;

const_shift_expr
           = shift_op , "(" , int_type , "," ,
             [ mode , "," ] , const_operand , "," , const_operand , ")" ;

/* ── 常量比较表达式 ── */

const_compare_expr
           = compare_op , "(" , ( int_type | float_type ) , "," ,
             const_operand , "," , const_operand , ")" ;

/* ── 常量逻辑表达式 ── */

const_binary_logic_expr
           = binary_logic_op , "(" , bool_type , "," ,
             const_operand , "," , const_operand , ")" ;

const_unary_logic_expr
           = "not" , "(" , bool_type , "," , const_operand , ")" ;

/* ── 常量转换表达式 ── */

const_cast_expr
           = "cast" , "(" , type , "," , const_operand , ")"
           | "cast" , "(" , int_type , "," , "truncate" , "," ,
             const_operand , ")" ;

const_bitcast_expr
           = "bitcast" , "(" , type , "," , const_operand , ")" ;
/* bitcast 语法上接受 type 的全部取值，但 bool、memblock 与结构体在语义检查中拒绝（TC_CE_TYPE_MISMATCH，§1.3/§6.6.6）；bitcast 也不接受 void。 */

/* ── 常量操作数 ── */

const_operand
           = integer_literal
           | float_literal
           | float_special
           | bool_literal
           | nullptr_literal
           | identifier
           | qualified_identifier
           | imported_member_name
           | field_access
           | memblock_count_access ;
/* field_access 的基址在常量上下文中必须解析为 let / static let 结构体绑定；
   嵌套访问链上的每一层中间结果也须为同类型只读结构体绑定。
   nullptr 是合法的编译期常量（§3.10.2）。 */

/* ── 操作数 ── */

operand    = identifier | qualified_identifier | integer_literal | float_literal
           | float_special | bool_literal | nullptr_literal
           | imported_member_name | field_access | memblock_count_access ;

field_access
           = ( identifier | qualified_identifier | imported_member_name ) ,
             { "." , identifier } ;
/* 支持嵌套字段访问（如 a.b.c）；每层左侧须解析为结构体类型，
   最终字段名的结果类型为该字段的声明类型。由静态语义检查链上各层的类型。 */

/* ── 双目算术表达式 ── */

binary_arith_expr
           = strict_binary_arith_expr
           | mode_binary_arith_expr ;

strict_binary_arith_expr
           = binary_arith_op , "(" , type , "," ,
             operand , "," , operand , ")" ;

mode_binary_arith_expr
           = binary_arith_op , "(" , type , "," , mode , "," ,
             operand , "," , operand , ")" ;

/* ── 单目算术表达式 ── */

unary_arith_expr
           = strict_unary_arith_expr
           | mode_unary_arith_expr ;

strict_unary_arith_expr
           = unary_arith_op , "(" , type , "," , operand , ")" ;

mode_unary_arith_expr
           = unary_arith_op , "(" , type , "," , mode , "," ,
             operand , ")" ;

/* ── 按位逻辑表达式（仅整数） ── */

bitwise_expr
           = bitwise_op , "(" , int_type , "," ,
             operand , "," , operand , ")" ;

unary_bitwise_expr
           = "not" , "(" , int_type , "," , operand , ")" ;

/* ── 移位表达式（仅整数） ── */

shift_expr
           = strict_shift_expr
           | wrap_shift_expr ;

strict_shift_expr
           = shift_op , "(" , int_type , "," ,
             operand , "," , operand , ")" ;

wrap_shift_expr
           = "shl" , "(" , int_type , "," , "wrap" , "," ,
             operand , "," , operand , ")" ;

/* ── 比较表达式（不支持 ieee 模式） ── */

compare_expr
           = compare_op , "(" , ( int_type | float_type ) , "," ,
             operand , "," , operand , ")" ;
/* 整数或浮点比较，接受 compare_op 的全部六种运算符（§6.5.1）。
   指针的等值比较和序关系比较由单独的 ptr_eq_compare_expr
   和 ptr_compare_expr 产生式处理（§3.10.7）。 */

ptr_eq_compare_expr
           = ( "ptr_eq" | "ptr_ne" ) , "(" , type , "," , operand , "," , operand , ")" ;
/* 指针等值比较，使用专用 ptr_eq / ptr_ne 指令，带显式类型参数 T（§3.10.7）。
   T 须为 void 以外的完整类型；两个 operand 须同为 ptr<T>。
   nullptr 等值比较结果为 true。
   通用 eq / ne 不接受 ptr<T> 类型操作数（TC_CE_TYPE_MISMATCH）。 */

/* ── 双目逻辑表达式（布尔） ── */

binary_logic_expr
           = binary_logic_op , "(" , bool_type , "," ,
             operand , "," , operand , ")" ;

binary_logic_op = "and" | "or" | "xor" ;

/* ── 单目逻辑表达式（布尔） ── */

unary_logic_expr
           = "not" , "(" , bool_type , "," , operand , ")" ;

/* ── 类型转换表达式 ── */

cast_expr  = strict_cast_expr | truncate_cast_expr ;

strict_cast_expr
           = "cast" , "(" , type , "," , operand , ")" ;

truncate_cast_expr
           = "cast" , "(" , int_type , "," , "truncate" , "," ,
             operand , ")" ;

bitcast_expr
           = "bitcast" , "(" , type , "," , operand , ")" ;
/* bitcast 语法上接受 type 的全部取值，但 bool、memblock 与结构体在语义检查中拒绝（TC_CE_TYPE_MISMATCH，§1.3/§6.6.6）；bitcast 也不接受 void。 */
/* 所有运算类型/模式组合均受 §6.3.1 权威矩阵约束。
   truncate 仅允许整数窄化；bitcast 要求等位宽且两端非 bool（§6.6）。 */

/* ── memblock 操作 ── */

memblock_name
           = identifier
           | qualified_identifier
           | imported_member_name ;
/* 名称解析与可见性：局部/顶层绑定用 identifier；本库 static 用 Self.id；
   导入公开成员用 module.id（§4.3、§4.4、§6.7.2.5）。 */

memblock_load_expr
           = "memblock_load" , "(" , memblock_element_type , "," , memblock_name , "," ,
             operand , ")" ;

memblock_store_stmt
           = "memblock_store" , "(" , memblock_element_type , "," , memblock_name , "," ,
             operand , "," , operand , ")" ;
/* memblock_store 是独立语句，非 RHS。索引操作数须为整数类型（§6.7.2.4）。 */

memblock_copy_stmt
           = "memblock_copy" , "(" , memblock_element_type , "," ,
             memblock_name , "," , operand , "," ,
             memblock_name , "," , operand , "," ,
             operand , ")" ;
/* memblock_copy 是独立语句，非 RHS。将 src[src_index, src_index+length)
   按元素抽象位串拷入 dst[dst_index, dst_index+length)；区间与重叠语义见 §6.7.2.3。
   三个整数操作数（dst_index / src_index / length）须为整数类型（§6.7.2.4）。
   length 为本次拷贝跨度。 */

memblock_constructor
           = memblock_fill_ctor
           | memblock_elems_ctor ;

/* count 为命名实参（带 count: 标签），取值是编译期 usize 常量（usize_operand，§3.8.1）。
   count: 和 fill: 标签按拼写匹配，在词法上是普通 identifier Token，不是 §2.7 保留关键字。 */

memblock_fill_ctor
           = "memblock" , "(" , memblock_element_type , "," ,
             "count" , ":" , usize_operand , "," ,
             "fill" , ":" , operand , ")" ;

memblock_elems_ctor
           = "memblock" , "(" , memblock_element_type , "," ,
             "count" , ":" , usize_operand , "," ,
             operand , { "," , operand } , ")" ;
/* 逐值初始化的实参个数必须等于 usize_operand 的数学值（TC_CE_MEMBLOCK_ELEMENT_COUNT_MISMATCH）。 */

/* ── .count 长度访问 ── */

memblock_count_access
           = memblock_name , "." , "count" ;
/* 从 memblock 访问长度头部（§3.8.5）。返回类型为 usize，值为绑定声明中 N 的数学值。
   N 是编译期常量，因此 .count 是合法的 const_operand，可在 const_rhs 中使用。 */

const_memblock_constructor
           = const_memblock_fill_ctor
           | const_memblock_elems_ctor ;

const_memblock_fill_ctor
           = "memblock" , "(" , memblock_element_type , "," ,
             "count" , ":" , usize_operand , "," ,
             "fill" , ":" , const_operand , ")" ;

const_memblock_elems_ctor
           = "memblock" , "(" , memblock_element_type , "," ,
             "count" , ":" , usize_operand , "," ,
             const_operand , { "," , const_operand } , ")" ;
/* usize_operand 须为编译期 usize 常量；全部元素操作数均为 const_operand。 */

/* ── 结构体值构造器 ── */

struct_constructor
           = struct_type , "(" ,
             [ identifier , ":" , operand ,
               { "," , identifier , ":" , operand } ] , ")" ;

const_struct_constructor
           = struct_type , "(" ,
             [ identifier , ":" , const_operand ,
               { "," , identifier , ":" , const_operand } ] , ")" ;
/* 全字段必填、顺序、类型与可见性由 §3.9.2 静态语义强制；
   空实参列表仅语法接受，语义上因缺少字段而拒绝。 */

/* ── 指针操作 ── */

nullptr_literal = "nullptr" ;
/* 空指针字面量；与任意 ptr<T> 兼容（§3.10.2）。
   本身不触发运行时错误；ptr_load / ptr_store 空指针时触发
   TC_RE_NULL_POINTER_DEREFERENCE。 */

ptr_load_expr
           = "ptr_load" , "(" , type , "," , operand , ")" ;
/* 从 ptr<T> 解引用读取（§6.8.2）。显式类型参数 T 须为
   非 void 的完整类型；操作数须为 ptr<T>。
   结果类型为 T。空指针时报运行时错误。 */

ptr_store_stmt
           = "ptr_store" , "(" , type , "," , operand , "," , operand , ")" ;
/* 写入 ptr<T> 所指对象（§6.8.3）。独立语句，非 RHS。
   显式类型参数 T 须为 void 以外的完整类型；
   第一个 operand 须为 ptr<T>，第二个须为 T 类型。
   可变性由 §6.8.3 约束。 */

ptr_address_expr
           = "ptr_address" , "(" , type , "," ,
             ( identifier | qualified_identifier | imported_member_name ) , ")" ;
/* 从变量标识符取地址，返回 ptr<T>（§6.8.4）。
   显式类型参数 T 须为 void 以外的完整类型，
   且必须与标识符的声明类型严格一致。
   仅可用于 var / static var / 形参；
   qualified_identifier / imported_member_name 须解析为可写 static var；
   let 绑定的标识符禁止。 */

ptr_add_expr
           = "ptr_add" , "(" , type , "," , operand , "," , operand , ")" ;
/* 指针加法（§6.8.5）。T 为所指类型（void 以外的完整类型）。
   第一个 operand 为 ptr<T>，第二个 operand 为 usize（非负偏移）。
   偏移单位为 sizeof_bits(T) 位。nullptr 时报运行时错误。 */

ptr_sub_expr
           = "ptr_sub" , "(" , type , "," , operand , "," , operand , ")" ;
/* 指针减法（§6.8.6）。T 为所指类型（void 以外的完整类型）。
   第一个 operand 为 ptr<T>，第二个 operand 为 usize（非负偏移），
   向低位地址方向移动 offset × sizeof_bits(T) 位。 */

ptr_compare_expr
           = ( "ptr_lt" | "ptr_le" | "ptr_gt" | "ptr_ge" ) ,
             "(" , type , "," , operand , "," , operand , ")" ;
/* 指针序关系比较（§6.8.7）。T 为所指类型（void 以外的完整类型）。
   两个 operand 同为 ptr<T> 且均为非 nullptr。
   结果类型为 bool。指针对比抽象地址序。 */

ptr_size_expr
           = "ptr_size" , "(" , type , "," , operand , ")" ;
/* 返回 ptr<T> 的所指类型宽度 sizeof_bits(T)（§6.8.8）。
   显式类型参数 T 须为 void 以外的完整类型，且必须与
   操作数的声明类型一致。结果类型为 usize。
   nullptr 合法（由显式类型参数决定 T）。
   编译期可求值，是合法的 const_operand。 */

/* ── memcopy_unsafe 语句 ── */

memcopy_unsafe_stmt
           = "memcopy_unsafe" , "(" , type , "," ,
             operand , "," , operand , "," ,
             operand , "," , operand , "," ,
             operand , ")" ;
/* 原始内存块拷贝（§6.8.9）。独立语句，非 RHS。
   操作数依次为：T（所指类型，void 以外的完整类型）、
   dst（ptr<T>）、dst_idx（整数）、src（ptr<T>）、src_idx（整数）、
   length（整数，≥0）。
   dst 或 src 为 nullptr 时报告 TC_RE_NULL_POINTER_DEREFERENCE。
   不执行越界检查；重叠区间行为等价于 memmove。
   length < 0 时报 TC_CE_MEMCOPY_UNSAFE_INVALID_RANGE（编译期可确定时）或 TC_RE_MEMCOPY_UNSAFE_INVALID_RANGE（运行时）。
   下标操作数须为整数类型（彼此类型可不同，也不必等于 T）；
   dst 和 src 可以是任意 operand（非仅裸名）。 */

/* ── I/O 语句（显式类型仅 scalar_type；禁止 memblock 和 ptr<T>，§10） ── */

write_stmt = "write" , "(" , scalar_type , "," , operand , ")"
           | "write" , "(" , scalar_type , "," , format_specifier , "," ,
             operand , ")" ;
/* 操作数个数与上列产生式不符 → TC_CE_OPERAND_COUNT（§1.3 白名单）。 */

writeln_stmt = "writeln" , "(" , scalar_type , "," , operand , ")"
             | "writeln" , "(" , scalar_type , "," , format_specifier , "," ,
               operand , ")" ;
/* 同上，操作数个数失配 → TC_CE_OPERAND_COUNT。 */

read_stmt  = "read" , "(" , scalar_type , "," ,
             ( identifier | qualified_identifier | imported_member_name ) , ")" ;
```
