### 1. 概述

#### 1.1 语言定位

TC 是一门伪汇编语言：语法接近高级语言的赋值表达式，执行模型保留汇编式的 **逐条语句** 顺序执行。每条语句至多包含 **一个** 运算或转换调用，**不支持** 表达式嵌套。

本文档定义：

- **8 种** 固定宽度整数类型（`int8`～`uint64`）
- **2 种** 浮点类型（`float32`、`float64`），符合 IEEE 754 标准
- **1 种** 布尔类型（`bool`，取值为 `true`/`false`）
- **7 类** 算术运算指令：
  - 双目运算（5 类）：`add`、`sub`、`mul`、`div`、`mod`
  - 单目运算（2 类）：`abs`（取绝对值）、`neg`（取负数）
  - 以上运算统一支持整数和浮点类型（除 `mod` 仅支持整数）
- **4 类** 位运算指令：`and`、`or`、`xor`（按位逻辑）、`not`（按位取反）
  - 仅支持整数类型，浮点类型不支持
- **2 类** 移位运算指令：`shl`（左移）、`shr`（右移）
  - 仅支持整数类型
- **6 类** 比较运算指令：`eq`、`ne`、`lt`、`le`、`gt`、`ge`
  - 统一支持整数和浮点类型
- **3 类** 逻辑运算指令：`and`、`or`、`not`（布尔逻辑，与整数位运算共享关键字，由类型参数区分）
- **2 类** 转换指令：`cast`、`bitcast`
  - `cast` 支持整数 ↔ 整数、整数 ↔ 浮点、浮点 ↔ 浮点、整数/浮点 ↔ `bool`；`truncate` 是其整数窄化形式
  - `bitcast` 在等位宽整数/浮点之间保持位模式重解释
- **3 条** 标准 I/O 语句：`write`、`writeln`、`read`
  - `write`/`writeln` 支持格式化输出（13 种格式化符号，含 `%t`、`%f`、`%e`、`%E`、`%g`、`%G`）
- **控制流语句**：
  - **结构化控制**：`if-then-else`（Pascal 风格，缩进敏感，以 `end` 结束）、`while-then-end`（结构化循环，含 `break`/`continue`）
  - **非结构化控制**：函数体内可使用 `goto` 与 `label`（受限跳转），用于 `if` + `goto` 构建底层汇编风格循环；顶层及其嵌套块一律禁止；所有可达路径统一纳入函数 CFG 的确定初始化分析（§11.2、§9.3.7）
  - **范式隔离原则**：`while` 循环体内**严格禁止**使用 `goto` 和 `label`；若需灵活的循环控制，应使用 `if` + `goto` 组合（见 §9.2.4、§9.3）
- **函数机制**：
  - 顶层 `func` 定义、`funcall` 命名有序实参调用和显式 `return`
  - 参数按值传递且只读；非 `void` 返回值只能初始化新 `var`，`void` 调用只能作为独立语句
  - 函数拥有独立作用域、调用帧和 CFG，不得访问顶层值绑定；调用图必须无环
- **程序入口保持顶层执行**：函数定义不执行，也没有特殊 `main`；函数定义区之后的顶层语句仍按源序运行，但顶层控制流仅允许结构化形式，不得出现 `goto` 或 `label`
- 算术模式关键字：
  - **整数**：`wrap`（回绕模式，用于 `add`/`sub`/`mul`/`neg`/`shl`）
  - **浮点**：`ieee`（IEEE 754 标准模式）；0.0.32 不支持浮点 `wrap`
  - 默认严格模式（整数检测溢出，浮点检测异常）
- 整数截断模式关键字 **`truncate`**（仅用于整数缩窄）

#### 1.2 设计原则

| 原则           | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| **声明时必须初始化** | **`var` 统一写作 `var <名>: <类型> = <初始化器>`**；初始化器为普通 RHS 或非 `void` `funcall`。禁止无 `=` 的声明，缺省 → `TC_ERR_VAR_MISSING_INIT`（§4.2） |
| 声明与再赋值分离 | 首次引入用 `var … = …`；其后修改省略 `var`，写作赋值语句。不存在「先声明、后首次赋值」的合法路径 |
| 常量与变量分离 | 不可变常量使用 `let` 定义，须在编译期初始化                  |
| 显式类型标注   | 变量/常量定义须声明具体类型                                  |
| 运算函数化     | 算术以 `op(<类型> [, 模式], 操作数...)` 形式调用；比较/逻辑以 `op(<类型> [, 模式], 操作数...)` 形式调用 |
| 类型参数首位   | 运算与转换的类型均作为 **第一个参数** 显式给出               |
| 默认严格模式   | 有符号整数运算默认检测溢出并报错；浮点运算默认检测异常并报错；允许的回绕或 IEEE 模式须显式传入对应关键字 |
| 同类型运算     | 同一运算的操作数须为相同类型                                 |
| 显式类型转换   | 跨类型须通过 `cast` 完成，禁止隐式转换                       |
| 逐条执行       | 每条语句独立执行，无隐式表达式嵌套求值                       |
| 显式函数数据流 | 普通值只能通过参数传入函数、通过返回值传出；函数不得隐式读取或修改顶层 `var` / `let` |
| 函数内跳转边界 | `goto` 与 `label` 只能位于函数体内；跳转目标必须属于同一函数，顶层及其嵌套块禁止使用 |
| 单调用语句     | `funcall` 的每个实参及 `return` 的返回值均限于 `operand`；复杂计算须拆为独立语句，禁止调用嵌套 |
| 字面量类型显式 | 无后缀整数字面量为有符号整数；`u`/`U` 后缀为无符号整数；无后缀浮点字面量为 `float64`；`f`/`F` 后缀为 `float32`；`true`/`false` 为布尔字面量 |
| I/O 格式化     | `write`/`writeln` 支持格式化符号，单符号单操作数             |
| 缩进强制       | 块结构由缩进界定，`if`/`else`/`end`/`while` 缩进必须一致，块内语句缩进必须多一级 |
| **内存安全**   | 语法层要求声明时初始化；控制流层对完整 CFG 做确定初始化分析，任何可达的未初始化读取均为静态错误（§11.2、§9.3.4） |
| **实现一致性** | VM、AOT 与常量求值必须遵循相同的位宽、舍入、错误和控制流规则；规范正文不提供可改变合法程序集合的可选加强项 |

#### 1.3 设计哲学

TC 的设计遵循以下核心理念：

| 理念             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| **显式优于隐式** | 类型转换、异常处理、符号性、块结束（`end`）、结构化/非结构化范式选择、参数名和函数返回均须显式标注，杜绝隐式歧义 |
| **安全优先**     | 默认检测溢出和转换错误；**声明时必须初始化**；完整确定初始化分析覆盖顶层与各函数的所有可达路径；函数间禁止递归环 |
| **教学友好**     | 伪汇编风格让底层概念（位宽、符号、溢出、截断、浮点异常、调用帧、内存分配、跳转底层实现）直观可见；缩进强制培养结构化编程习惯；范式隔离揭示高级循环与汇编跳转的本质差异；声明时初始化使「引入变量」与「给定初值」绑定为同一步 |
| **渐进扩展**     | 当前已覆盖整数、布尔、浮点与非递归函数；复合类型（数组/结构体/指针）、字符串和高阶函数等为后续扩展预留清晰的设计空间 |

### 2. 词法结构

本章定义 TC 语言的基本词法单元。完整的 EBNF 定义见附录 A。

#### 2.1 字符集与 Token

TC 源文件由以下字符构成：

- **字母**：`A`–`Z`、`a`–`z`、`_`
- **数字**：`0`–`9`
- **符号**：`+`、`-`、`*`、`/`、`%`、`=`、`:`、`,`、`(`、`)`、`;`、`_`、`.`、`e`、`E`
- **空白**：空格、制表符（`\t`）、换行符（`\n`、`\r\n`、`\r`）

源文件编码为 **UTF-8**，但语言关键字和标识符仅限于 ASCII 字符集。

#### 2.2 标识符

- 由字母、数字与 `_` 组成，**必须以字母或 `_` 开头**。
- **区分大小写**：`a` 与 `A` 为不同变量。
- 合法：`a`、`count`、`_tmp1`、`my_var`
- 非法：`1a`、`-x`（`-` 非标识符字符）

#### 2.3 整数字面量

##### 2.3.1 后缀与符号性

TC 字面量通过后缀区分符号性：

| 后缀      | 符号性 | 示例                   |
| --------- | ------ | ---------------------- |
| 无后缀    | 有符号 | `42`、`-128`、`0xFF`   |
| `u` / `U` | 无符号 | `42u`、`255u`、`0xFFu` |

**关键规则**：
- 无后缀字面量视为有符号整数，可用于有符号类型上下文；若用于无符号上下文，须满足范围约束
- `u` 后缀字面量视为无符号整数，**仅可用于无符号类型上下文**；用于有符号上下文触发 **字面量类型错误**
- 负号 `-` **仅可与无后缀字面量**组合；`-42u` 为非法

##### 2.3.2 进制

TC 支持四种进制字面量：

| 进制           | 前缀        | 数字字符集                | 示例                      |
| -------------- | ----------- | ------------------------- | ------------------------- |
| 十进制（默认） | —           | `0`–`9`                   | `0`、`255`、`-128`、`42u` |
| 十六进制       | `0x` / `0X` | `0`–`9`、`a`–`f`、`A`–`F` | `0xFF`、`0x1Au`、`-0x80`  |
| 二进制         | `0b` / `0B` | `0`、`1`                  | `0b1010`、`0b11111111u`   |
| 八进制         | `0o` / `0O` | `0`–`7`                   | `0o377`、`-0o100`         |

- 前缀中的 `0` 是必需的前导，**不区分大小写**
- 前缀与数字之间 **不可有空白**
- 后缀紧跟数字部分，前缀与后缀之间 **不可有空白**

##### 2.3.3 数字分隔符

为增强长数字的可读性，允许在下述位置插入单个下划线 `_`：

- 十进制：数字之间（首数字之后，末数字之前）
- 十六进制：`0x`/`0X` 与末数字之间
- 二进制：`0b`/`0B` 与末数字之间
- 八进制：`0o`/`0O` 与末数字之间

示例：

```text
1_000_000           → 1000000
0xFFFF_0000u        → 4294901760
0b1010_0011u        → 163
-0x7F_FF            → -32767
```

**约束**：不可连续两个 `_`，不可在字面量首尾放置 `_`，不可在前缀内部插入 `_`（如 `0x_FF` 非法）。

##### 2.3.4 前导零

- 十进制字面量 **不允许前导零**（`007` **非法**，应写作 `7`）
- 单个 `0` 是合法的十进制零，不视为前导零特例
- 八进制须显式使用 `0o` 前缀

##### 2.3.5 字面量的词法上限

- 整数字面量的**数值**不得超过 `uint64` 范围：`0 ≤ N ≤ 18446744073709551615`
- 整数字面量超出此范围 → **字面量范围错误**

##### 2.3.6 负号与减法运算符的关系

`-` 前缀仅出现在无后缀整数字面量中，**不作为独立的一元运算符**。若需变量间的减法，使用 `sub` 指令。

##### 2.3.7 词法分析器匹配策略

词法分析器采用 **最长匹配** 策略：
1. 扫描 `0` 时，检查后续字符是否为 `x`/`X`/`b`/`B`/`o`/`O`，转入对应进制（十六进制、二进制或八进制）
2. 数字部分扫描完成后，检查后续字符是否为 `u`/`U`，归约为带后缀字面量
3. 否则归约为无后缀字面量

#### 2.4 浮点字面量

##### 2.4.1 格式与后缀

TC 支持十进制浮点字面量和科学计数法：

| 形式                    | 示例                     | 类型                     |
| ----------------------- | ------------------------ | ------------------------ |
| 十进制浮点              | `3.14`、`-0.5`、`1.0`    | 无后缀 → `float64`       |
| 单精度后缀              | `3.14f`、`-0.5F`、`1.0f` | `f`/`F` 后缀 → `float32` |
| 科学计数法（小写 e）    | `1.2e5`、`-3.14e-2`      | 无后缀 → `float64`       |
| 科学计数法（大写 E）    | `1.2E5`、`-3.14E-2`      | 无后缀 → `float64`       |
| 科学计数法 + 单精度后缀 | `1.2e5f`、`-3.14E-2F`    | `f`/`F` 后缀 → `float32` |

**关键规则**：
- 浮点字面量必须包含小数点 `.` 或指数标记 `e`/`E`
- 无后缀浮点字面量为 `float64` 类型
- `f`/`F` 后缀浮点字面量为 `float32` 类型
- 浮点字面量 **不区分符号性**（浮点数无符号概念）
- 负号 `-` 可与浮点字面量组合
- 浮点字面量 **仅可用于能确定源浮点类型的上下文**（含 `float32`/`float64` 运算、`cast` 或 `bitcast`）
- 有限十进制字面量先解析为精确数学值，再直接按 roundTiesToEven 舍入到后缀决定的 binary32/binary64；不得通过另一浮点类型中转
- 非零有限值舍入为零，或有限值舍入为无穷 → **字面量范围错误**；可表示的非规格化数合法
- 数学值为零且字面量显式带 `-` 时生成负零；其余零字面量生成正零

**特殊浮点值**：

| 字面量 | 含义             | IEEE 754 表示                |
| ------ | ---------------- | ---------------------------- |
| `inf`  | 正无穷           | 指数全 1，尾数全 0，符号位 0 |
| `-inf` | 负无穷           | 指数全 1，尾数全 0，符号位 1 |
| `nan`  | 非数（静默 NaN） | 指数全 1，尾数非 0           |

**约束**：
- `inf`、`-inf`、`nan` 为保留关键字，不可用作标识符
- 区分大小写：均为小写。`INF`/`NaN` 等其他大小写形式按普通标识符词法化，若未声明则报 `TC_ERR_UNDEFINED_VARIABLE`

```text
var pi: float64 = 3.141592653589793
var e: float32 = 2.71828f
var speed: float64 = 3.0e8
var tiny: float32 = 1.0e-38f
var inf_pos: float64 = inf
var nan_val: float64 = nan
```

##### 2.4.2 词法错误

```text
3.14u     ; 非法：浮点不支持 u 后缀
.5        ; 非法：须 0.5
1e5       ; 合法：科学计数法（整数指数形式）
```

#### 2.5 布尔字面量

| 字面量  | 值   | 类型   |
| ------- | ---- | ------ |
| `true`  | 真   | `bool` |
| `false` | 假   | `bool` |

**约束**：
- `true` 和 `false` 为保留关键字，不可用作标识符
- **区分大小写**，且仅小写形式是布尔字面量。`True` / `FALSE` 等按普通标识符词法化，若未声明则报 `TC_ERR_UNDEFINED_VARIABLE`
- 布尔字面量 **仅可用于** `bool` 类型上下文

```text
var flag: bool = true
var done: bool = false
var err: int32 = true      ; 字面量类型错误
```

#### 2.6 字符与字符串字面量（预留）

> **扩展预留**：未来版本将支持：
> - 字符字面量：`'a'`、`'\n'`、`'\x41'`
> - 字符串字面量：`"hello"`、`"world\n"`
>
> 当前版本中，单引号或双引号包裹的内容为 **词法错误**。

#### 2.7 注释

- 行注释以 `;` 开始，延续至行尾
- 示例：`var a: int32 = 10    ; 定义 32 位整数`

#### 2.8 关键字

以下 token 为保留关键字，不可用作标识符：

```text
var  let  bool  true  false
int8  uint8  int16  uint16  int32  uint32  int64  uint64
float32  float64
add  sub  mul  div  mod  abs  neg
eq  ne  lt  le  gt  ge
and  or  not           ; and/or/not 支持 bool 逻辑与整数按位重载
xor                    ; 仅整数位运算，不支持 bool
shl  shr
cast  bitcast  wrap  truncate  ieee
write  writeln  read
if  then  else  end
while  break  continue   ; 结构化循环控制
goto  label            ; 仅函数体内可用的非结构化跳转
func  funcall  return  void  ; 函数定义、调用与返回
inf  nan
```

> **扩展预留**：以下关键字为未来功能保留：`string`、`array`、`struct`、`ptr`、`fmod`、`remainder`、`sqrt`、`sin`、`cos`。

`call` 不是 0.0.32 的调用关键字；函数调用必须写作 `funcall`。`void` 只允许出现在函数返回类型位置。

#### 2.9 语句与行结构

- 每条语句独占一行
- **空行**、**仅含空白符的行**、**仅含行注释**的行均合法，不产生语句
- 语句由 `NEWLINE` 结束。`;` 始终是行注释起始符；因注释可紧跟语句，外观上可写为“语句末尾的可选 `;`”，但语法 Token 序列中不存在分号终结符

### 3. 类型与值

#### 3.1 类型分类

TC 的类型系统设计为可扩展的分类体系。当前支持 **整数类型**、**浮点类型**、**布尔类型**，并以 `void` 表示函数不返回值；未来将逐步引入其他类别：

| 类别            | 当前支持               | 未来预留                 | 说明                   |
| --------------- | ---------------------- | ------------------------ | ---------------------- |
| **整数类型**    | ✅ `int8`～`uint64`     | `int128`、`uint128`      | 固定宽度二进制补码整数 |
| **浮点类型**    | ✅ `float32`、`float64` | `float128`               | IEEE 754 浮点数        |
| **布尔类型**    | ✅ `bool`               | —                        | 逻辑真/假              |
| **字符/字符串** | —                      | `char`、`string`         | Unicode 字符与字符串   |
| **复合类型**    | —                      | `array`、`struct`、`ptr` | 聚合与间接类型         |
| **单位类型**    | ✅ `void`               | —                        | 无值，仅用于函数返回类型 |

> **实现注记**：编译器内部 `TcType` 枚举将 `TC_BOOL`、整数类型及浮点类型统一管理，但类型分类函数（如 `tc_type_is_integer()`、`tc_type_is_float()`）分别返回对应真值。

#### 3.2 整数类型

| 类型     | 位宽 | 符号   | 最小值                     | 最大值                     |
| -------- | ---- | ------ | -------------------------- | -------------------------- |
| `int8`   | 8    | 有符号 | −128                       | 127                        |
| `uint8`  | 8    | 无符号 | 0                          | 255                        |
| `int16`  | 16   | 有符号 | −32,768                    | 32,767                     |
| `uint16` | 16   | 无符号 | 0                          | 65,535                     |
| `int32`  | 32   | 有符号 | −2,147,483,648             | 2,147,483,647              |
| `uint32` | 32   | 无符号 | 0                          | 4,294,967,295              |
| `int64`  | 64   | 有符号 | −9,223,372,036,854,775,808 | 9,223,372,036,854,775,807  |
| `uint64` | 64   | 无符号 | 0                          | 18,446,744,073,709,551,615 |

类型命名规则：`<符号前缀><位宽>`，其中符号前缀为 `int`（有符号）或 `uint`（无符号），位宽为 `8`/`16`/`32`/`64`。

#### 3.3 浮点类型

| 类型      | 位宽 | IEEE 754 对应 | 最小正非零值（约） | 最大有限绝对值（约） | 精度（十进制） |
| --------- | ---- | ------------- | ------------ | ------------ | -------------- |
| `float32` | 32   | binary32      | 1.4e-45      | 3.4e38       | ~7 位          |
| `float64` | 64   | binary64      | 5e-324       | 1.8e308      | ~16 位         |

**内部表示**：
- 浮点数以 IEEE 754 二进制格式存储
- `float32`：符号 1 位 + 指数 8 位 + 尾数 23 位
- `float64`：符号 1 位 + 指数 11 位 + 尾数 52 位
- 浮点数的“位模式”只能通过等位宽 `bitcast` 与整数互转

#### 3.4 布尔类型

`bool` 类型表示逻辑真值，取值为 `true` 或 `false`。

**内部表示**：
- 在运行时，`bool` 值以字节存储。
- `false` 的表示为其存储单元的所有位均为 `0`。
- `true` 的表示为任何非零的位模式（建议实现统一为 `1`）。
- 但 **不可** 将 `bool` 直接解释为整数（须通过 `cast` 显式转换）。

**类型性质**：
- 比较运算和逻辑运算的结果类型为 `bool`。
- `bool` 变量可被赋值、读取、输出。
- 与所有类型相同：`bool` 的 `var` 定义**声明时必须初始化**（§4.2）。

```text
var flag: bool = true      ; 声明并初始化
var done: bool = false     ; 声明并初始化
; var uninit: bool         ; ❌ 静态错误：变量定义必须初始化
```

#### 3.5 类型性质

**有符号类型（`int8`～`int64`）**

- 采用 **二进制补码** 表示
- `add`/`sub`/`mul`/`neg` 默认 **严格模式**：结果超出范围 → **整数溢出错误**
- 显式 `wrap` 模式：按模 `2^n` 回绕，不报错
- `shl` 默认严格模式：左移结果超出范围 → **整数溢出错误**；`wrap` 模式截断高位

**无符号类型（`uint8`～`uint64`）**

- 仅表示非负整数
- 算术结果超出最大值时 **模 `2^n` 回绕**，不报错
- `div`/`mod` 结果恒为非负
- `shl` 默认严格模式（仍可检测值溢出，例如 `shl(uint8, 255u, 1)` 的数学结果超过 255 时报错），`wrap` 模式截断高位

**浮点类型（`float32`、`float64`）**

- 符合 IEEE 754 标准
- 支持两种算术模式（详见 §5）：
  - **严格模式**（默认）：上溢/下溢/除零/无效操作均报错
  - **IEEE 754 模式**（`ieee`）：遵循 IEEE 754，返回 ±inf/nan，不报错
- 0.0.32 **不支持浮点 `wrap`**；位模式操作须通过等宽 `bitcast` 转为整数后完成
- 浮点数不支持位运算（`and`/`or`/`xor`/`not`/`shl`/`shr`）

**布尔类型**

- 仅表示逻辑真值
- 比较运算和逻辑运算返回 `bool`
- 不参与算术运算（须显式 `cast`）

**单位类型（`void`）**

- 只表示函数没有返回值，不是值类型
- 没有位宽、字面量、变量槽或运行时值
- 不能参与运算、转换、I/O、参数传递或变量/常量定义

**运行时值模型**

TC 中每个变量的值由 **n 位位模式**（`n` 为类型位宽）与 **类型解释** 共同构成：

- 整数内部以 n 位无符号位模式存储；有符号类型按 **二进制补码** 解释，无符号类型按非负整数解释
- 浮点数内部以 IEEE 754 位模式存储
- `bool` 内部以字节存储，语义上仅区分零和非零
- `wrap` 算术回绕、整数 `cast(..., truncate, ...)` 与等宽 `bitcast` 均在此位模式上操作
- 有符号 `wrap` 下的 `add`/`sub`/`mul`/`neg` 与同位宽无符号默认回绕 **位模式一致**

#### 3.6 字面量与类型的关系

整数字面量的符号性由后缀决定，数值须满足上下文类型的约束：

```text
; 有符号字面量（无后缀）——可用于有符号类型
var a: int8 = 127           ; 合法
var b: int8 = 128           ; 字面量范围错误
var c: int32 = -100         ; 合法

; 有符号字面量用于无符号类型——需满足范围
var e: uint8 = 255          ; 合法
var f: uint8 = 256          ; 字面量范围错误
var g: uint8 = -1           ; 字面量范围错误

; 无符号字面量（u 后缀）——仅可用于无符号类型
var h: uint8 = 255u         ; 合法
var j: int32 = 42u          ; 字面量类型错误

; 浮点字面量——仅可用于浮点类型上下文
var pi: float64 = 3.14      ; 合法
var e: float32 = 2.71828f   ; 合法
var err: int32 = 3.14       ; 字面量类型错误

; 布尔字面量——仅可用于 bool 类型
var flag: bool = true       ; 合法
var err: int32 = true       ; 字面量类型错误
```

##### 3.6.1 字面量检查规则

**整数字面量**：
1. 解析字面量数值 `N`（`0 ≤ N ≤ 18446744073709551615`）
2. 若带负号（仅无后缀字面量允许），取 `−N`（`N=0` 时 `−0 = 0`）
3. 根据后缀确定符号性：
   - 无后缀 → 有符号
   - `u`/`U` 后缀 → 无符号
4. 检查上下文类型：
   - 有符号类型：仅允许无后缀字面量，值在范围内
   - 无符号类型：允许无后缀（≥0）或 `u` 后缀字面量，值在范围内
5. 不满足则报错

| 上下文类型 | 允许的字面量形式        | 可接受数值范围                                          |
| ---------- | ----------------------- | ------------------------------------------------------- |
| `int8`     | 无后缀                  | −128 ～ 127                                             |
| `uint8`    | 无后缀（≥0）或 `u` 后缀 | 0 ～ 255                                                |
| `int16`    | 无后缀                  | −32,768 ～ 32,767                                       |
| `uint16`   | 无后缀（≥0）或 `u` 后缀 | 0 ～ 65,535                                             |
| `int32`    | 无后缀                  | −2,147,483,648 ～ 2,147,483,647                         |
| `uint32`   | 无后缀（≥0）或 `u` 后缀 | 0 ～ 4,294,967,295                                      |
| `int64`    | 无后缀                  | −9,223,372,036,854,775,808 ～ 9,223,372,036,854,775,807 |
| `uint64`   | 无后缀（≥0）或 `u` 后缀 | 0 ～ 18,446,744,073,709,551,615                         |

**浮点字面量**：
- 无后缀 → `float64`，精确十进制值按 roundTiesToEven 直接舍入为 binary64
- `f`/`F` 后缀 → `float32`，精确十进制值按 roundTiesToEven 直接舍入为 binary32
- 非零有限值舍入为零或有限值舍入为无穷 → **字面量范围错误**；可表示非规格化数合法
- 特殊值 `inf`/`-inf`/`nan` 可用于浮点类型上下文；`nan` 使用 §5.3 的 canonical quiet NaN
- 用于非浮点类型 → **字面量类型错误**

**布尔字面量**：
- `true` 仅可用于 `bool` 类型上下文
- `false` 仅可用于 `bool` 类型上下文
- 用于非 `bool` 类型 → **字面量类型错误**

**`wrap`/`ieee`/`truncate`/`bitcast` 不绕过字面量检查**：即使运算或转换使用特殊形式，字面量仍须先在其自身类型上下文中通过静态检查。

#### 3.7 类型转换的通用框架

TC 0.0.32 将数值转换、整数截断与位重解释分开：

| 形式 | 用途 | 核心约束 |
| ---- | ---- | -------- |
| `cast(T, operand)` | 数值转换 | 按目标类型做范围检查与规定舍入 |
| `cast(T, truncate, operand)` | 整数缩窄 | 仅整数→更窄整数，保留低位 |
| `bitcast(T, operand)` | 位重解释 | 源、目标等宽；不改变任何位；`bool` 不参与 |

严格 `cast` 覆盖整数 ↔ 整数、整数 ↔ 浮点、浮点 ↔ 浮点，以及整数/浮点 ↔ `bool`。`truncate` 不再承担浮点位重解释；所有整数/浮点位模式互转统一使用 `bitcast`。未来扩展复合类型时，不得复用这三种形式表达地址、所有权等不同性质的转换。

### 4. 程序结构、声明与表达式

#### 4.1 程序构成

TC 源文件由两个连续区域构成：可为空的**函数定义区**，以及**顶层语句区**。所有 `func` 定义必须位于第一条顶层语句（包括编译期 `let` 声明）之前；一旦进入顶层语句区，后续不得再定义函数。函数定义不是可执行语句，不产生顶层运行时效果；程序入口为顶层语句区的第一条非空、非注释语句，并按源序执行至文件末尾。TC 没有特殊 `main` 入口，名为 `main` 的函数与其他函数相同。

编译器必须在分析函数体和顶层语句前收集全部函数签名，因此函数可调用定义在其后的函数；调用图限制见 §10.6。顶层与每个函数分别构成独立控制流域，但只有函数控制流域可以建立标签表和 `goto` 边。

**语句种类**：
- 变量定义（`var`）、常量定义（`let`）、赋值
- I/O（`write`/`writeln`/`read`）
- 结构化控制：条件分支（`if`-`then`-`else`-`end`）、循环（`while`-`then`-`end`）、循环控制（`break`/`continue`）
- 非结构化控制：函数体内的标签定义（`label`）与跳转（`goto`）
- 函数相关：顶层函数定义（`func`）、函数调用（`funcall`）、函数返回（`return`）

**程序结构约束**：
- 源文件由若干行组成；每行至多一条语句
- 空行、纯注释行均合法，不产生语句
- 语句由换行结束；`;` 仅引入行注释，词法层在产生 `NEWLINE` 前丢弃其后内容
- 函数定义只能出现在函数定义区顶层；函数体、`if` / `else` 分支和 `while` 循环体内不得定义函数
- `func`/`if`/`while` 块内语句须满足 §9.1.2 的缩进规则
- **函数边界**：`goto` 与 `label` 必须具有 `func` 词法祖先；顶层直接使用，或在顶层 `if` / `else` / `while` 的任意嵌套层级使用，均为静态错误
- **范式隔离**：`while` 块内**严格禁止** `goto` 与 `label`（见 §9.2.4）

#### 4.2 变量定义（`var`）

##### 4.2.1 语法形态（已收敛）

`var` **声明时必须初始化**。统一外形为：

```text
var <identifier>: <type> = <initializer>
```

其中 `<initializer>` 是普通 `<rhs>`，或用于接收非 `void` 返回值的专用 `funcall`。

| 项目 | 规则 |
| ---- | ---- |
| 初始化器 | **强制**。`=` 与 `<initializer>` 不可省略 |
| 非法形态 | `var <identifier>: <type>`（无初始化器）→ 静态错误 `TC_ERR_VAR_MISSING_INIT` |
| RHS | 字面量、已定义标识符、单个运算、`cast` 或 `bitcast`（见 §4.5）；须与声明类型一致 |
| 函数返回初始化 | 非 `void` `funcall` 可通过专用形态 `var <名>: <类型> = funcall(...)` 初始化新变量（§10.2）；`funcall` 不属于普通 RHS |
| 再赋值 | 首次引入之后，修改写作 `<identifier> = <rhs>`，**不再**写 `var`（§4.4） |

> **设计收敛说明**：可选初始化（「先 `var x: T`，后某处首次赋值」）**已废止**。`read` **不能**代替声明处的初始化器——目标变量必须事先以带初始化器的 `var` 定义，`read` 仅覆盖其当前值（§12.3）。附录 A 的 `variable_def` / `var_funcall_def` 产生式均无可选初始化分支。

##### 4.2.2 语义与检查

- 当且仅当该条 `var` 语句**执行成功**后，变量持有初始化器求得的有效值（顶层、函数和块内均在定义行写入预先建立的固定槽位）。
- 编译器对每条 `var` 做**语法/形态检查**：缺 `=` 或初始化器 → **`TC_ERR_VAR_MISSING_INIT`**（打印名 `VarMissingInitializer`，§13.1 / §13.5）。此检查与控制流无关，亦不依赖数据流分析；**不得**仅报笼统 `TC_ERR_SYNTAX`。
- 同一作用域内不可重复定义同名变量（作用域包括顶层、函数、`if`/`while` 块，以及 `then`/`else` 各自的互斥子块，见 §11.1、§9.1.5、§9.2.3）。跨类型值须先 `cast`；函数返回值则必须与接收类型严格相同。
- 声明带初始化器不等于该语句在所有路径上均已执行；完整 CFG 的确定初始化规则见 §11.2 与 §9.3.4。

```text
var a: int32 = 10                 ; ✅ 声明并初始化
var b: int32 = add(int32, a, 20)  ; ✅
var c: int8 = cast(int8, truncate, a)
var flag: bool = true
var pi: float64 = 3.14
var e: float32 = 2.71828f

var d: int32                      ; ❌ TC_ERR_VAR_MISSING_INIT
; d = 1                           ; 即便其后赋值，仍不能补救无初始化器的声明
```

> **作用域补充**：若 `var` 出现在 `if` / `else` / `while` 缩进块内部，则该变量具有**块级局部作用域**，仅在本块（从定义处到对应的 `end`）内可见。块外任何对该变量的引用均为"未定义标识符错误"。

#### 4.3 常量定义（`let`）

使用 `let` 声明 **不可变常量**：

- RHS **必须** 提供
- RHS 须为 **单层编译期常量表达式**（见下文定义）
- 常量在编译期求值；使用处**直接内联**编译期结果，**不生成运行时算术指令，亦不分配运行时变量槽**（与 §11.2、附录 B 一致）。源文件中 `let` 语句仍占一行，仅作为编译期声明
- 常量 **不可** 作为赋值语句的左值
- **在同一作用域内**，常量名不可与变量名或其他常量名冲突。

##### 4.3.1 编译期常量表达式

`let` 的 RHS 可包含以下任一形式：

**原子表达式**：
- 整数字面量（`42`、`-128`、`0xFFu`）
- 浮点字面量（`3.14`、`2.71828f`、`1.0e-5`）
- 特殊浮点值（`inf`、`-inf`、`nan`）
- 布尔字面量（`true`、`false`）
- 此前已定义的 `let` 常量引用（`PI`、`MASK`）

**单个调用表达式**（每个操作数只能是上述原子表达式）：
- 算术运算：`add`/`sub`/`mul`/`div`/`mod`/`abs`/`neg`，可使用 §5 允许的 `wrap` 或 `ieee` 模式
- 位运算：`and`/`or`/`xor`/`not`（按位）、`shl`/`shr`（移位）
- 比较运算：`eq`/`ne`/`lt`/`le`/`gt`/`ge`（浮点比较允许但不推荐，因浮点精度）
- 逻辑运算：`and`/`or`/`not`（布尔）
- 转换：严格 `cast`、整数 `cast(..., truncate, ...)` 与等宽 `bitcast`

**约束**：
- 常量表达式**不可** 引用任何 `var` 变量
- 常量表达式**不可** 包含 `funcall`；函数体内的 `let` 亦不得引用参数或局部 `var`
- 常量表达式**不可** 引用自身或尚未定义的 `let`
- 操作调用不可嵌套；复合计算须拆分为多条按源序定义的 `let`
- 由于只允许引用此前的 `let`，多常量循环依赖在语法可见性上不可形成，0.0.32 不定义常量循环依赖错误
- 有符号严格常量算术运算或 `shl` 的溢出，在编译期视为 **常量溢出错误** 并终止编译
- 严格浮点常量算术按 §5 的异常优先级求值：无效操作 → `TC_ERR_CONSTANT_EXPRESSION`，除零 → `TC_ERR_CONSTANT_DIV_ZERO`，上溢或下溢 → `TC_ERR_CONSTANT_OVERFLOW`
- 常量表达式中整数 `div`/`mod` 的除数为 0，或浮点严格 `div` 的最高优先级异常为除零，视为 **常量除零错误** 并终止编译
- 常量移位、转换、NaN 与模式合法性完全复用 §5～§8 的运行时规则

##### 4.3.2 静态布尔条件与三态判定

“静态布尔条件”是结果类型为 `bool`，且整体符合本节“编译期常量表达式”定义的单层 RHS。其原子操作数只能是字面量，或在当前词法作用域可见、定义语句位于使用点之前且已成功求值的 `let`；不得把 `var` 的当前值或跨语句运行时结果当作常量传播。

名称和类型检查完成后，编译器对 `if`/`while` 条件执行以下三态判定：

- **静态 `true`**：RHS 合法且按本节共享常量语义求值为 `true`；CFG 仅保留真边。
- **静态 `false`**：RHS 合法且求值为 `false`；CFG 仅保留假边。
- **`unknown`**：RHS 不是合法的单层常量表达式，或含 `var` 等不能静态解析的操作数；CFG 同时保留真、假边。

静态布尔判定只复用本节的表达式定义和 §5～§8 的共享语义，不建立第二套运算符白名单。布尔字面量、可见的更早 `let bool`、结果为 `bool` 的整数/浮点比较、布尔逻辑运算，以及目标为 `bool` 的合法严格 `cast` 均因此自然受支持；`bitcast` 不允许 `bool`，整数 `truncate` 也不能产生合法布尔条件。

前向 `let`、不可见 `let`、嵌套调用或其他非法形态在内部静态判定中不得被折叠；它们仍分别由更早的名称、语法或类型阶段报告错误，因此不会进入 CFG。若表达式形态合法但求值发生整数/浮点溢出、除零、无效浮点操作或严格转换失败，必须按本节既有映射报告 `TC_ERR_CONSTANT_OVERFLOW`、`TC_ERR_CONSTANT_DIV_ZERO`、`TC_ERR_CONSTANT_EXPRESSION` 或 `TC_ERR_CONSTANT_CAST_OVERFLOW` 并终止编译；不得降级为 `unknown`。

##### 4.3.3 浮点常量算术的精度规则

常量表达式中的浮点算术遵循以下规则：
1. 每条指令均按其显式类型参数执行：`float32` 使用 binary32，`float64` 使用 binary64。
2. 每条指令结束时立即按 roundTiesToEven 舍入；不得统一提升为 `float64` 中间精度。
3. strict / `ieee` 的结果与同一指令在运行时执行完全一致。
4. 常量求值器不得使用 FMA、扩展精度、FTZ 或 DAZ。

```text
let PI: float64 = 3.141592653589793
let PI_SQ: float64 = mul(float64, PI, PI)          ; binary64
let F32_A: float32 = add(float32, 16777216.0f, 1.0f) ; binary32，结果仍为 16777216
let INF_OK: float32 = div(float32, ieee, 1.0f, 0.0f)   ; inf
; let ERR: float64 = div(float64, 1.0, 0.0)            ; 常量除零
```

##### 4.3.4 示例

```text
; 基础常量
let PI: float64 = 3.141592653589793
let E: float32 = 2.71828f
let MASK: uint32 = 0xFFFF_0000u
let DEBUG: bool = true

; 编译期整数算术
let ZERO: int32 = sub(int32, 10, 10)          ; 0
let OFFSET: int32 = add(int32, 1000, 100)     ; 1100

; 编译期浮点算术
let PI_SQUARED: float64 = mul(float64, PI, PI)   ; 9.869604401089358
let CIRCUMFERENCE: float64 = mul(float64, PI, 2.0)  ; 6.283185307179586

; 编译期比较与逻辑
let IS_POSITIVE: bool = gt(float64, PI, 0.0)  ; true
let RESULT: bool = and(bool, IS_POSITIVE, true)  ; true

; 静态布尔条件：完整合法单层 RHS 均参与 CFG 剪枝
let TEN: int32 = 10
let FIVE: int32 = 5
let FLAG_A: bool = true
let FLAG_B: bool = false
if gt(int32, TEN, FIVE) then                 ; 静态 true
    writeln(bool, %t, true)
end
while and(bool, FLAG_A, FLAG_B) then         ; 静态 false，循环体不可达
    writeln(bool, %t, true)
end

; var 不做值推测：即使运行时初值为 true，静态判定仍为 unknown
var runtime_flag: bool = true
if runtime_flag then
    writeln(bool, %t, runtime_flag)
end

; 编译期转换
let FLAG_INT: int32 = cast(int32, DEBUG)      ; 1
let PI_INT: int32 = cast(int32, PI)           ; 3
let PI_U32: uint32 = cast(uint32, PI_INT)      ; 3（嵌套调用拆为两条 let）
let PI_BITS: uint64 = bitcast(uint64, PI)      ; 等宽位重解释

; ========== 错误示例 ==========
; let ERR1: int32 = add(int32, a, 10)        ; 错误：a 是 var 变量
; let ERR2: int32 = add(int32, mul(int32, 2, 3), 4) ; 错误：调用嵌套
; let ERR3: float64 = div(float64, 1.0, 0.0)  ; 错误：常量除零
; let ERR4: int32 = bitcast(int32, PI)        ; 错误：位宽不匹配
```

> **作用域补充**：同 `var`，`let` 若定义在块内，其作用域限定于当前 `if`/`while` 块（到 `end` 为止）。常量在编译期求值，但可见性仍受块级作用域约束。

#### 4.4 赋值语句

对已定义变量重新赋值时 **省略** `var`。右侧结果类型须与变量已声明类型 **完全一致**。首次引入该名必须已通过 §4.2 的 `var … = …` 完成，不存在「无初始化器的声明 + 本赋值作为首次写入」写法。

```text
var c: int32 = add(int32, a, b)
c = mul(int32, a, b)        ; 合法
c = cast(int32, d)          ; 跨类型须先 cast

var f: float64 = 3.14
f = mul(float64, f, 2.0)    ; 合法
f = cast(float64, 42)       ; 合法（整数 → 浮点）

var flag: bool = false
flag = true                 ; 合法
flag = lt(float64, f, 10.0) ; 合法
flag = and(bool, flag, true) ; 合法
```

**约束**：
- 赋值左侧不可为 `let` 定义的常量。
- 赋值目标必须在当前 CFG 点确定初始化；赋值不能补救被控制流绕过的声明初始化（§11.2）。
- 赋值 RHS 不接受 `funcall`；函数返回值只能直接初始化一个新声明的 `var`（§10.2.3）。

#### 4.5 右值表达式（RHS）

| 产生式               | 结果类型           | 说明                            |
| -------------------- | ------------------ | ------------------------------- |
| `identifier`         | 标识符已声明类型   | 须已定义；受源序可见性约束      |
| `integer_literal`    | 由左侧变量类型决定 | 须满足字面量符号性及范围约束    |
| `float_literal`      | 由 `f`/`F` 后缀决定 | 无后缀为 `float64`，有后缀为 `float32`；须与上下文一致 |
| `float_special`      | 由左侧变量类型决定 | `inf`/`-inf`/`nan`              |
| `bool_literal`       | `bool`             | `true` 或 `false`               |
| `binary_arith_expr`  | 第一参数类型       | 五种双目算术运算（含浮点）      |
| `unary_arith_expr`   | 第一参数类型       | 两种单目算术运算（含浮点）      |
| `bitwise_expr`       | 第一参数类型       | 按位 `and`/`or`/`xor`（仅整数） |
| `unary_bitwise_expr` | 第一参数类型       | 按位 `not`（仅整数）            |
| `shift_expr`         | 第一参数类型       | `shl`/`shr` 移位运算（仅整数）  |
| `compare_expr`       | `bool`             | 六种比较运算（整数+浮点）       |
| `binary_logic_expr`  | `bool`             | `and`/`or` 逻辑运算（布尔）     |
| `unary_logic_expr`   | `bool`             | `not` 逻辑运算（布尔）          |
| `cast_expr`          | 第一参数类型       | 类型转换                        |
| `bitcast_expr`       | 第一参数类型       | 等宽位重解释                    |

`funcall` **不属于**普通 `rhs`。它只在 `var <名>: <类型> = funcall(...)` 或独立 `funcall(...)` 两种专用语法位置出现；其合法位置由被调函数返回类型决定（§10.2.3）。

#### 4.6 操作数（Operand）

| 形式              | 约束                                                         |
| ----------------- | ------------------------------------------------------------ |
| *identifier*      | 已定义，类型与运算类型一致，且在当前 CFG 点确定初始化（§11.2） |
| *integer_literal* | 须满足字面量约束                                             |
| *float_literal*   | 须满足字面量约束                                             |
| *float_special*   | `inf`/`-inf`/`nan`，仅用于浮点类型上下文                     |
| *bool_literal*    | 仅用于 `bool` 类型上下文                                     |

**不支持** 嵌套：操作数不可为算术表达式、`cast`、`bitcast` 或 `funcall` 调用。复合计算须拆分为多条语句。

### 5. 算术运算

#### 5.1 运算模式总览

0.0.32 以“操作 × 类型 × 模式”矩阵作为唯一权威来源：

| 运算 | 类型 | 合法模式 |
| ---- | ---- | -------- |
| `add`/`sub`/`mul`/`neg` | 有符号整数 | strict（无关键字）、`wrap` |
| `add`/`sub`/`mul`/`neg` | 无符号整数 | 固定模 `2^n`；不接受模式关键字 |
| `shl` | 全部整数 | strict（无关键字）、`wrap` |
| `div`/`mod`/`abs`/`shr` | 全部整数 | 无模式关键字 |
| `add`/`sub`/`mul`/`div` | 浮点 | strict（无关键字）、`ieee` |
| `abs`/`neg` | 浮点 | 无模式关键字；纯符号位操作 |
| 比较、逻辑、位运算 | 对应合法类型 | 无模式关键字 |

先在无模式的前提下检查运算是否支持所给类型；不支持时报 `TC_ERR_TYPE_MISMATCH`。类型本身受支持但模式不在上表时，报 `TC_ERR_MODE_MISMATCH`。0.0.32 不支持浮点 `wrap`，也不接受冗余的无符号 `wrap`。

#### 5.2 严格模式（默认）

**整数严格模式**（参见 §5.4～§5.6）：
- 有符号 `add`/`sub`/`mul`/`neg` 结果超范围 → **整数溢出错误**
- `shl` 结果超范围 → **整数溢出错误**
- `div` 除数为 0 → **除零错误**；`div(INT_MIN, -1)` → **整数溢出错误**

**浮点严格模式**（IEEE 754 异常检测）：
- 上溢 → **浮点溢出错误**
- 下溢 → **浮点下溢错误**
- 除零 → **除零错误**
- 无效操作（0/0、∞−∞、0×∞） → **无效操作错误**
- `nan` 参与 `add`/`sub`/`mul`/`div` → **无效操作错误**

浮点执行环境固定如下：

- `float32` 每条指令按 IEEE 754 binary32 执行并立即舍入；`float64` 按 binary64 执行并立即舍入。
- 固定舍入模式为 roundTiesToEven；不提供运行时舍入模式切换。
- 禁止保留超出目标类型的中间精度，禁止将独立 `mul`/`add` 融合为 FMA。
- 必须保留非规格化数；禁止 FTZ（flush-to-zero）与 DAZ（denormals-are-zero）。
- 下溢定义为结果在舍入后微小且不精确；有限结果舍入为无穷时定义为上溢。
- 同一指令同时满足多个异常条件时，只报告最高优先级：`FloatInvalidOperation` → `DivisionByZero` → `FloatOverflow` → `FloatUnderflow`。

#### 5.3 IEEE 754 标准模式（`ieee`）

**仅用于浮点 `add`/`sub`/`mul`/`div`**。执行精度、舍入方式、非规格化数与禁止 FMA 的规则同 §5.2，但异常不终止程序。

| 场景       | IEEE 754 行为                   | 返回值           |
| ---------- | ------------------------------- | ---------------- |
| 上溢       | 舍入到 ±∞                       | ±`inf`           |
| 下溢       | 返回 0 或非规格化数             | `0` 或非规格化值 |
| 除零       | 返回 ±∞                         | ±`inf`           |
| 无效操作   | 返回 canonical quiet NaN         | `nan`            |
| `nan` 传播 | 算术输入含 NaN 时返回 canonical quiet NaN | `nan`      |

```text
var big: float32 = 1.0e30f
var result: float32 = mul(float32, ieee, big, big)  ; inf
var zero: float32 = 0.0f
var nan_result: float32 = div(float32, ieee, zero, zero)  ; nan
```

`nan` 字面量与 `ieee` 算术产生的 NaN 使用固定 canonical quiet NaN：binary32 为 `0x7FC00000`，binary64 为 `0x7FF8000000000000`。通过 `bitcast` 构造的其他 NaN 位模式可保留其 payload；其参与 `ieee` 算术后结果仍规范化为 canonical quiet NaN。

#### 5.4 整数回绕模式（`wrap`）

**整数 `wrap`**：
- 按模 `2^n` 回绕，不报错
- 仅用于有符号 `add`/`sub`/`mul`/`neg`，以及有符号或无符号 `shl`
- 无符号 `add`/`sub`/`mul`/`neg` 已固定采用模 `2^n` 语义，不接受冗余 `wrap`
- `div`/`mod`/`abs`/`shr` 不接受 `wrap`
- 浮点类型不接受 `wrap`；位模式混合须先 `bitcast` 为等宽整数

#### 5.5 整数有符号运算（`int8`～`int64`）

| 指令                  | 语义                                                         |
| --------------------- | ------------------------------------------------------------ |
| `add` / `sub` / `mul` | 和 / 差 / 积；严格模式超范围报错，wrap 回绕                  |
| `div`                 | 商，**向零截断**（同 C 有符号 `/`）；除数为 0 → **除零错误**；商不可表示 → **整数溢出错误** |
| `mod`                 | 余数符号与 **被除数** 相同；除数为 0 → **除零错误**；**注**：`mod` 本身不会因值不可表示而报错，因为余数绝对值小于除数，必在类型范围内（除数为 0 已单独处理）。 |
| `abs`                 | 返回绝对值；`INT_MIN` 时严格模式报错                         |
| `neg`                 | 返回相反数；`INT_MIN` 时严格模式报错，wrap 回绕              |

**严格模式溢出检测**（`div`，有符号类型）：

1. 将操作数按 `<T>` 解码为 int64 有符号值
2. 除数为 0 → **除零错误**
3. 计算向零截断商 \(q\)；若 \(q\) 不在 `<T>` 可表示范围内 → **整数溢出错误**

**特殊情形**（\(b \neq 0\)）：

| 表达式                   | 结果 | 说明                                                        |
| ------------------------ | ---- | ----------------------------------------------------------- |
| `div(T, INT_MIN(T), −1)` | —    | **整数溢出错误**（数学商 \(+2^{n-1}\) 不可在 `<T>` 中表示） |
| `mod(T, INT_MIN(T), −1)` | `0`  | 余数为 0，**不报错**                                        |
| `abs(T, INT_MIN(T))`     | —    | **整数溢出错误**                                            |
| `neg(T, INT_MIN(T))`     | —    | 严格模式时 **整数溢出错误**                                 |

```text
var g: int32 = 7
var h: int32 = -3
var i: int32 = div(int32, g, h)    ; i = -2

var j: int32 = -7
var k: int32 = 3
var m: int32 = mod(int32, j, k)    ; m = -1

var n: int32 = -42
var o: int32 = abs(int32, n)       ; o = 42
```

#### 5.6 整数无符号运算（`uint8`～`uint64`）

| 指令                  | 语义                                                |
| --------------------- | --------------------------------------------------- |
| `add` / `sub` / `mul` | 和 / 差 / 积；超范围 → 按模 2^n 回绕                |
| `div`                 | 数学整数商；除数为 0 → **除零错误**                 |
| `mod`                 | 余数满足 `0 ≤ 余数 < 除数`；除数为 0 → **除零错误** |
| `abs`                 | 恒等返回                                            |
| `neg`                 | 返回 `0 - 操作数`，按模 2^n 回绕                    |

无符号算术天然采用模 2^n 回绕，其位级结果与有符号 `wrap` 模式下的同宽算术一致。

```text
var a: uint8 = 200
var b: uint8 = 100
var c: uint8 = add(uint8, a, b)    ; c = 44
```

#### 5.7 浮点运算（`float32`、`float64`）

| 指令                  | 语义                                                         |
| --------------------- | ------------------------------------------------------------ |
| `add` / `sub` / `mul` | 和 / 差 / 积；strict 检测异常，`ieee` 返回 inf/nan           |
| `div`                 | 商；strict 检测除零/无效操作，`ieee` 返回 ±inf/nan           |
| `abs`                 | 清除符号位；包括 NaN、无穷和零在内均不报错，不接受模式关键字 |
| `neg`                 | 翻转符号位；包括 NaN、无穷和零在内均不报错，不接受模式关键字 |

`abs`/`neg` 是纯位操作：仅修改符号位并保留其余位，包括通过 `bitcast` 构造的 NaN payload。它们不属于可能触发浮点异常的算术指令。

```text
var a: float64 = 3.5
var b: float64 = 2.0

var sum: float64 = add(float64, a, b)      ; 5.5（严格模式）
var prod: float64 = mul(float64, a, b)     ; 7.0
var quot: float64 = div(float64, a, b)     ; 1.75

; abs/neg 无模式且永远安全
var neg_val: float64 = -3.14
var pos_val: float64 = abs(float64, neg_val)   ; 3.14（无异常）

; IEEE 模式
var big: float32 = 1.0e30f
var inf_res: float32 = mul(float32, ieee, big, big)  ; inf
```

#### 5.8 算术运算的模式有效范围

| 指令 | 无模式形式 | `ieee` | `wrap` |
| ---- | ---------- | ------ | ------ |
| `add`/`sub`/`mul` | ✅ 全部整数 + 浮点 | ✅ 仅浮点 | ✅ 仅有符号整数 |
| `div` | ✅ 全部整数 + 浮点 | ✅ 仅浮点 | ❌ |
| `mod` | ✅ 仅整数 | ❌ | ❌ |
| `abs` | ✅ 全部整数 + 浮点 | ❌ | ❌ |
| `neg` | ✅ 全部整数 + 浮点 | ❌ | ✅ 仅有符号整数 |
| `shl` | ✅ 仅整数 | ❌ | ✅ 仅整数 |
| `shr` | ✅ 仅整数 | ❌ | ❌ |

无符号 `add`/`sub`/`mul`/`neg` 的无模式形式采用固定模 `2^n` 语义；表中的有符号整数无模式形式为 strict。

#### 5.9 算术运算的扩展框架

0.0.32 规范已包含 **整数算术**、**浮点算术**、**位运算** 和 **逻辑运算**。未来规范可逐步扩展：

| 运算类别     | 当前支持                                    | 未来扩展                                    |
| ------------ | ------------------------------------------- | ------------------------------------------- |
| **整数算术** | ✅ `add`/`sub`/`mul`/`div`/`mod`/`abs`/`neg` | 任意位宽整数                                |
| **浮点算术** | ✅ `add`/`sub`/`mul`/`div`/`abs`/`neg`       | `fmod`/`remainder`、`sqrt`、`sin`、`cos` 等 |
| **位运算**   | ✅ `and`/`or`/`xor`/`not`/`shl`/`shr`        | —                                           |
| **比较运算** | ✅ `eq`/`ne`/`lt`/`le`/`gt`/`ge`             | —                                           |
| **逻辑运算** | ✅ `and`/`or`/`not`（布尔）                  | —                                           |

### 6. 位运算

本章定义整数位级操作，包括按位逻辑运算与移位运算。位运算与布尔逻辑运算共享关键字 `and`、`or`、`not`，由**类型参数**区分：当类型参数为整数类型时执行按位操作；当类型参数为 `bool` 时执行逻辑运算（见第 7 章）。`xor` 仅用于整数按位运算，不支持布尔类型。

> **重要约束**：
> - 移位运算（`shl`/`shr`）中，**被移位数与移位计数必须为相同类型 `T`**。若需要不同位宽，必须先用 `cast` 统一类型。
> - 浮点类型 **不支持** 任何位运算，包括 `and`/`or`/`xor`/`not`/`shl`/`shr`。尝试对浮点类型使用位运算 → **类型错误**。

**设计说明：移位计数不掩码**

TC 对移位计数 `k` 的处理方式与主流语言不同，**不进行掩码**，直接取 `k` 的数学值。选择此语义主要基于以下原因：

- **教学清晰**：避免"计数被截断"这一隐含、非直观的行为
- **确定性**：`k >= n` 时行为明确定义（`shl` 严格模式报溢出，`shr` 得 `0`）
- **可验证性**：便于形式化证明和静态分析
- **显式编程**：若需要取模移位，程序员可显式使用 `mod` 运算

#### 6.1 按位逻辑运算（`and`、`or`、`xor`、`not`）

##### 6.1.1 总览

| 运算  | 名称     | 操作数数量 | 适用类型                     | 语义                             |
| ----- | -------- | ---------- | ---------------------------- | -------------------------------- |
| `and` | 按位与   | 2          | 整数类型（`int8`～`uint64`） | 每位：两操作数均为 1 → 1，否则 0 |
| `or`  | 按位或   | 2          | 整数类型                     | 每位：任一操作数为 1 → 1，否则 0 |
| `xor` | 按位异或 | 2          | 整数类型                     | 每位：两操作数不同 → 1，相同 → 0 |
| `not` | 按位非   | 1          | 整数类型                     | 每位取反                         |

> **`xor` 与 `and`/`or`/`not` 的区别**：`and`/`or`/`not` 由类型参数 `T` 重载——`T` 为整数时执行按位运算，`T` 为 `bool` 时执行逻辑运算。`xor` **无** bool 重载，仅接受整数类型参数。

##### 6.1.2 语法形式

```text
var a: int8 = 0b1010_1100      ; -84
var b: int8 = 0b1111_0000      ; -16

var and_res: int8 = and(int8, a, b)   ; 0b1010_0000 -> -96
var or_res:  int8 = or(int8, a, b)    ; 0b1111_1100 -> -4
var xor_res: int8 = xor(int8, a, b)   ; 0b0101_1100 -> 92
var not_res: int8 = not(int8, a)      ; 0b0101_0011 -> 83
```

##### 6.1.3 语义规则

1. 将操作数视为 **无符号位模式**（有符号数按二进制补码解释）。
2. 对每一位执行对应的逻辑操作。
3. 结果按目标类型 `T` 解释（有符号按补码回译，无符号直接取值）。

**溢出**：按位运算结果天然限制在 `T` 的位宽内，**不会溢出**，因此**不支持** `wrap` 或 `truncate` 模式。

**操作数约束**：
- 两操作数必须与类型参数 `T` 一致（整数类型）。
- 若类型参数为 `bool`，则 `and`/`or`/`not` 会视为逻辑运算（参见第 7 章），而 `xor` 不允许 `bool` 类型参数，将触发 **类型错误**。
- 若类型参数为浮点类型，所有位运算均触发 **类型错误**。

#### 6.2 移位运算（`shl`、`shr`）

移位运算仅适用于整数类型。**被移位数与移位计数必须为相同类型 `T`**。

##### 6.2.1 左移（`shl`）

- **适用类型**：整数类型（`int8`～`uint64`）。
- **调用形式**：
  - 严格模式（默认）：`shl(<T>, 被移位数, 移位计数)`
  - 回绕模式：`shl(<T>, wrap, 被移位数, 移位计数)`
- **语义**：
  - 将移位计数解释为无符号整数，取其数学值 `k`。**TC 不对 `k` 进行掩码操作**。
  - 若 `k >= n`（`n` 为 `T` 的位宽）：
    - 严格模式：视为 **整数溢出错误**。
    - 回绕模式：所有位被移出，结果为 `0`。
  - **严格模式**（`k < n`）：
    - 计算数学结果：`result_math = 被移位数 * 2^k`
    - 若 `result_math` 超出 `T` 的可表示范围 → **整数溢出错误**。
    - 否则存储结果。
  - **回绕模式**（`k < n`）：
    - 取 `(被移位数 * 2^k)` 的低 `n` 位位模式，按 `T` 解释。**不报错**。

```text
var x: int8 = 0b0111_1111   ; 127
var r1: int8 = shl(int8, x, 2)        ; 127*4=508 -> 溢出错误
var r2: int8 = shl(int8, wrap, x, 2)  ; 508 mod 256 = 0b1111_1100 -> -4

var y: uint8 = 0b1111_1111u
var r3: uint8 = shl(uint8, wrap, y, 4)  ; 255*16 mod 256 = 0b1111_0000 -> 240u
var r4: uint8 = shl(uint8, wrap, y, 8)  ; k=8 >=8 -> 0
```

##### 6.2.2 右移（`shr`）

- **适用类型**：整数类型。
- **调用形式**：`shr(<T>, 被移位数, 移位计数)` —— **无模式关键字**（永不溢出）。
- **语义**：
  - 若 `k >= n`，结果为 `0`。
  - **有符号类型**（`int*`）：执行 **算术右移**——高位补符号位。
  - **无符号类型**（`uint*`）：执行 **逻辑右移**——高位补 `0`。

```text
var neg: int8 = 0b1000_0000   ; -128
var r5: int8 = shr(int8, neg, 1)   ; -64 (算术右移)
var r6: int8 = shr(int8, neg, 8)   ; k=8 >=8 -> 0
```

#### 6.3 位运算与常量表达式

`let` 常量表达式允许使用全部合法位运算。`shl` 可使用 strict 或 `wrap`；strict 溢出映射为常量溢出错误，`wrap` 与运行时一样保留低位。其余规则与 §4.3、§6.1、§6.2 完全一致。

### 7. 比较运算与逻辑运算

#### 7.1 比较运算

##### 7.1.1 比较运算总览

所有比较运算统一支持整数和浮点类型：

- 接受 **两个同类型操作数**（整数或浮点）
- 返回 `bool` 类型值
- **整数比较**不涉及 `wrap` / `truncate` 模式关键字
- **浮点比较**使用 IEEE 754 普通比较谓词（NaN 为 unordered），不使用 `totalOrder`；仅接受无模式形式。
- **不产生溢出**（比较本身无算术溢出风险）

| 运算 | 名称     | 语义     |
| ---- | -------- | -------- |
| `eq` | 等于     | `a == b` |
| `ne` | 不等于   | `a != b` |
| `lt` | 小于     | `a < b`  |
| `le` | 小于等于 | `a <= b` |
| `gt` | 大于     | `a > b`  |
| `ge` | 大于等于 | `a >= b` |

##### 7.1.2 语法形式

```text
; 整数比较
var eq_result: bool = eq(int32, a, b)   ; false
var lt_result: bool = lt(int32, a, b)   ; true

; 浮点比较
var f_gt: bool = gt(float64, 3.14, 2.71)  ; true
; 注意：不支持 gt(float64, ieee, 3.14, 2.71) 形式

; nan 比较（IEEE 754）
var nan_val: float64 = nan
var eq_nan: bool = eq(float64, nan_val, nan_val)  ; false
var ne_nan: bool = ne(float64, nan_val, nan_val)  ; true
```

##### 7.1.3 语义规则

**整数比较**：
- 有符号类型按二进制补码解释后的数学值比较
- 无符号类型按非负整数值比较
- 混合符号性比较须先 `cast` 统一类型

**浮点比较**：
- `eq(+0.0, -0.0)` 为 `true`，`ne(+0.0, -0.0)` 为 `false`
- `nan` 与任何值（包括自身）执行 `eq`/`lt`/`le`/`gt`/`ge` 均返回 `false`，执行 `ne` 返回 `true`
- 本组指令不区分 NaN payload，也不提供总序；若需比较位模式，先 `bitcast` 为等宽整数

##### 7.1.4 NaN 检测的惯用写法

根据 IEEE 754 普通比较谓词，`nan` 与任何值（包括自身）比较均为 unordered。检测 `nan` 的推荐写法：

```text
var x: float64 = nan
var is_nan: bool = ne(float64, x, x)    ; true（仅 nan 满足 x != x）
var not_nan: bool = eq(float64, x, x)   ; false
```

**注意**：
- 由于 `nan != nan` 为 `true`，`ne(float64, x, x)` 可可靠检测 `nan`
- 不能使用 `eq(float64, x, nan)` 检测，因为 `nan` 字面量本身也是 `nan`，比较结果仍为 `false`
- 未来版本将提供 `isnan` 内置函数作为更直观的替代

#### 7.2 逻辑运算

##### 7.2.1 逻辑运算总览

所有逻辑运算：
- 接受 **`bool` 类型操作数**
- 返回 `bool` 类型值
- **不涉及** `wrap` / `truncate` 模式
- **不产生溢出**

| 运算  | 名称   | 操作数数量 | 语义                                            |
| ----- | ------ | ---------- | ----------------------------------------------- |
| `and` | 逻辑与 | 2          | 两操作数均为 `true` 时返回 `true`，否则 `false` |
| `or`  | 逻辑或 | 2          | 任一操作数为 `true` 时返回 `true`，否则 `false` |
| `not` | 逻辑非 | 1          | 操作数为 `true` 时返回 `false`，否则 `true`     |

##### 7.2.2 短路求值

**`and` 短路规则**：
- 左操作数为 `false` 时，**不计算** 右操作数，直接返回 `false`
- 左操作数为 `true` 时，计算右操作数并返回其值

**`or` 短路规则**：
- 左操作数为 `true` 时，**不计算** 右操作数，直接返回 `true`
- 左操作数为 `false` 时，计算右操作数并返回其值

确定初始化分析必须为短路求值建立操作数级的可达边。当左操作数是布尔字面量，或是在当前词法作用域可见、定义语句位于使用点之前且已求值的 `let bool` 时，使用其编译期值删除不可能的右操作数读取边：`false and RHS` 与 `true or RHS` 均不记录 RHS 的变量读取。左操作数为 `var` 时不做值推测，保守认为右操作数可达。

该裁剪只影响 CFG/DFA 的确定初始化读边，不跳过前序静态阶段。被短路排除的 RHS 不触发 `TC_ERR_UNINITIALIZED_VARIABLE`，但仍必须通过词法、语法、名称、类型、操作数数量与模式检查；前向或不可见 `let` 仍按名称解析规则报 `TC_ERR_UNDEFINED_VARIABLE`。

```text
func check_short_circuit() void then
    let FALSE: bool = false
    let TRUE: bool = true
    goto use
    var pending: bool = true
    label use:
    var a: bool = and(bool, FALSE, pending) ; 合法：pending 的读取边被裁剪
    var b: bool = or(bool, TRUE, pending)   ; 合法：pending 的读取边被裁剪

    var runtime_false: bool = false
    var c: bool = and(bool, runtime_false, pending)
    ; 上一行仍报 TC_ERR_UNINITIALIZED_VARIABLE：var 的值不参与静态推测

    var d: bool = and(bool, FALSE, missing)
    ; 上一行仍报 TC_ERR_UNDEFINED_VARIABLE：名称检查不被短路绕过
    return
end
```

##### 7.2.3 语法形式

```text
var and_result: bool = and(bool, a, b)   ; a && b
var or_result: bool = or(bool, a, b)     ; a || b
var not_result: bool = not(bool, a)      ; !a
```

### 8. 类型转换

#### 8.1 三种转换形式

| 形式 | 语义 | 类型约束 |
| ---- | ---- | -------- |
| `cast(T, operand)` | 数值转换 | 整数、浮点、`bool`；按本章做范围检查与舍入 |
| `cast(T, truncate, operand)` | 保留低位的整数缩窄 | 仅整数→更窄整数 |
| `bitcast(T, operand)` | 位模式不变的等宽重解释 | 等宽整数/浮点；`bool` 不参与 |

三种形式互不替代：数值 `cast` 不静默丢弃整数高位；`truncate` 不接受浮点；`bitcast` 不做数值转换。

##### 8.1.1 字面量操作数的源类型

标识符操作数的源类型是其声明类型。字面量作为转换操作数时按下列规则唯一确定源类型：

| 上下文 | 字面量 | 源类型规则 |
| ------ | ------ | ---------- |
| `cast` | 无后缀整数 | `int64`；数值必须先在 `int64` 范围内 |
| `cast` | `u`/`U` 整数 | `uint64` |
| `cast` | 浮点 | `f`/`F` 后缀为 `float32`，无后缀为 `float64`；`inf`/`-inf`/`nan` 默认为 `float64` |
| `cast` | 布尔 | `bool` |
| `bitcast` | 整数 | 源位宽取目标位宽，后缀决定有/无符号；字面量必须能由该同宽整数类型表示 |
| `bitcast` | 普通浮点 | `f`/`F` 后缀为 `float32`，无后缀为 `float64` |
| `bitcast` | `inf`/`-inf`/`nan` | 目标为 32 位时源为 `float32`，目标为 64 位时源为 `float64` |

因此 `cast(float32, 1.0)` 是从 `float64` 到 `float32` 的数值转换，而 `bitcast(float32, 0x40490FDBu)` 将后者按同宽 `uint32` 字面量解释。`bitcast(float32, 1.0)` 因源为 `float64` 而报 `TC_ERR_BITCAST_WIDTH`；需写成 `1.0f`。`bitcast` 仍不接受布尔字面量。非 `let` 语句中的严格 `cast` 即使操作数是字面量，也按运行时指令处理转换溢出；`let` 中的同一情形映射为 `TC_ERR_CONSTANT_CAST_OVERFLOW`。

#### 8.2 整数严格转换规则（strict）

严格整数转换统一依据数学值判定，与源/目标位宽关系无关：

1. 将源位模式按源类型解释为数学整数 `v`。
2. 若 `min(T) ≤ v ≤ max(T)`，结果为目标类型中表示同一数学值的位模式。
3. 否则报 `TC_ERR_CAST_OVERFLOW`。

因此无符号缩窄同样检查范围；例如已有 `var wide: uint16 = 256u` 时，`cast(uint8, wide)` 必须报错。需要显式保留低位时使用 §8.3 的 `truncate`。

#### 8.3 整数截断转换规则（`truncate`）

设源、目标位宽分别为 `n`、`m`：

- 源与目标必须均为整数类型，且必须满足 `m < n`。
- 将源视为 `n` 位位模式 `bits`，结果位模式为 `bits mod 2^m`，再按目标整数类型解释。
- 不执行范围检查，不报溢出。
- `m >= n` 时为静态错误 `TC_ERR_MODE_MISMATCH`；加宽应使用严格 `cast`，等宽位重解释应使用 `bitcast`。

```text
var big: int32 = 1000
var trunc: int8 = cast(int8, truncate, big) ; 低 8 位 0xE8 → -24
```

#### 8.4 浮点转换规则

| 转换方向              | 规则                                                         |
| --------------------- | ------------------------------------------------------------ |
| 整数 → 浮点           | 按 roundTiesToEven 转为目标浮点；允许精度舍入；有限整数若转换为无穷 → `TC_ERR_CAST_OVERFLOW` |
| 浮点 → 整数           | 向零舍入；结果超出目标整数范围，或源为 `nan`/`inf` → `TC_ERR_CAST_OVERFLOW` |
| `float64` → `float32` | 按 roundTiesToEven 舍入；有限源值若转换为无穷 → `TC_ERR_CAST_OVERFLOW`；舍入为非规格化数或零则合法 |
| `float32` → `float64` | 有限值无损精度提升（总是合法）                               |

浮点数值转换还须遵守：正负零保留符号，正负无穷保留符号；源为 NaN 且目标仍为浮点时，结果为目标类型的 canonical quiet NaN。同类型 `cast` 为恒等操作并保留完整位模式；若需在等宽不同类型间保留 NaN payload，必须使用 `bitcast`。

```text
var i: int32 = 42
var f: float64 = cast(float64, i)        ; 42.0
var pi_f: float64 = 3.14159
var pi_int: int32 = cast(int32, pi_f)    ; 3（向零截断）
var huge: float64 = 1.0e100
; var err: int32 = cast(int32, huge)    ; 转换溢出错误
```

#### 8.5 `bool` ↔ 整数/浮点转换

| 方向               | 规则                                           |
| ------------------ | ---------------------------------------------- |
| `bool` → 整数/浮点 | `true` → `1`/`1.0`，`false` → `0`/`0.0`        |
| 整数/浮点 → `bool` | `0`/`0.0` → `false`，非零 → `true`（含 `nan`） |

```text
var flag: bool = true
var as_int: int32 = cast(int32, flag)      ; 1
var as_float: float64 = cast(float64, flag) ; 1.0
var back: bool = cast(bool, 3.14)          ; true
```

#### 8.6 等宽位重解释（`bitcast`）与速查

`bitcast(TargetType, operand)` 保持源位模式的全部位不变，仅改用目标类型解释：

- 源与目标必须为整数或浮点类型，且位宽完全相同。
- `bool` 不允许参与，否则报 `TC_ERR_TYPE_MISMATCH`。
- 源、目标类型相同时是保持位模式不变的合法恒等操作。
- 位宽不一致报 `TC_ERR_BITCAST_WIDTH`。
- `bitcast` 不触发数值溢出，也不规范化 NaN payload。

```text
var f: float32 = -1.0f
var bits: uint32 = bitcast(uint32, f)       ; 0xBF800000u
var f2: float32 = bitcast(float32, bits)    ; -1.0f
; var bad: float64 = bitcast(float64, bits) ; TC_ERR_BITCAST_WIDTH
```

| 源 ↓ / 目标 → | 整数 | 浮点 | `bool` |
| ------------- | ---- | ---- | ------ |
| **整数** | strict `cast` 检查数学范围；更窄目标可显式 `truncate` | strict `cast` 做数值转换；等宽 `bitcast` 做位重解释 | 零为 `false`，非零为 `true` |
| **浮点** | strict `cast` 向零舍入并检查；等宽 `bitcast` 做位重解释 | strict `cast` 做精度转换；不同位宽禁止 `bitcast` | `±0.0` 为 `false`，其他值（含 NaN）为 `true` |
| **`bool`** | `false`→0，`true`→1 | `false`→0.0，`true`→1.0 | 恒等 |

## 第三部分：控制流与执行模型

### 9. 控制流

#### 9.1 条件分支语句（`if`）

TC 提供 **Pascal 风格** 的 `if-then-else` 条件分支语句，采用 **缩进敏感** 的块结构，并以 **`end`** 关键字作为块的强制结束标志。

##### 9.1.1 `if` 语句语法

**强制语法形式**（行结构敏感）：

```text
if <bool_rhs> then
    语句序列
[else
    语句序列]
end
```

- `if`、`then`、`else`、`end` 为保留关键字。
- `<bool_rhs>` 为任何可产生 `bool` 类型结果的右值表达式（参见 §4.5）。
- `then` 关键字必须位于 `if` 行的末尾（其后必须换行），不可在同一行写其他内容（行末注释 `;` 除外）。
- `else` 关键字**必须单独另起一行**，缩进级别必须与对应的 `if` 行**完全一致**。
- `end` 关键字**必须单独另起一行**，缩进级别必须与对应的 `if` 行**完全一致**。`end` 是 `if` 语句的强制结束标志，不可省略。
- **不支持 `else if` 组合关键字**。多分支通过在 `else` 块内嵌套 `if` 实现（见下文）。
- `语句序列` 由零条或多条语句组成，每条语句独占一行；直接块内语句**必须比所在的 `if` / `else` 行恰好多一个缩进级别**。块内允许包含 `var` / `let` 定义、赋值、I/O、`funcall`、函数体内的 `return`，以及嵌套 `if` / `while`；仅当当前 `if` 本身位于函数体内且不存在 `while` 词法祖先时，块内才允许 `label` / `goto`。不允许嵌套 `func` 定义。

**重要**：缩进是**强制性的语法规则**。块内所有语句的缩进必须严格大于当前块级缩进。`end` 行的缩进必须等于当前块级缩进。若缩进不符合规则，或缺少 `end`，均视为静态错误，程序不编译。

##### 9.1.2 强制性缩进规则

| 规则编号 | 规则说明                                                     |
| -------- | ------------------------------------------------------------ |
| R1       | 缩进使用**空格**或**制表符**，但同一文件中**必须保持一致**（不可混用）。 |
| R2       | 一个缩进级别必须恰好为 **4 个空格**或 **1 个制表符**。整个文件选定一种后必须统一，不得混用或改变每级宽度。 |
| R3       | `func`/`if`/`while`、`else` 和对应 `end` 行的缩进级别必须**完全一致**，称为**当前块级缩进**。 |
| R4       | `func` / `if` / `else` / `while` 的直接块内语句必须比当前块级缩进**恰好多一级**。过少、无对应嵌套语句却多于一级，或同一语句序列内宽度不一致，均为缩进错误。 |
| R5       | `end` 行缩进必须等于当前块级缩进；若缩进不足或过多，均为静态错误。 |
| R6       | 嵌套 `if`/`while` 时，内层块行缩进必须比外层块内语句的缩进再多一级（即外层缩进 + 2 个级别）。内层块的块内语句再比内层块多一级，其 `end` 与内层块对齐。 |
| R7       | 合法的函数内 `label` **不产生**新的缩进层级、不开启代码块。`label` 行缩进与同作用域其它普通语句一致；其后仍属同一作用域、且非新子块内的语句，缩进必须与该 `label` 行**完全一致**。仅当后续语句本身开启 `if`/`while` 子块时，子块内部才按 R3–R6 增加缩进（详见 §9.3.2）。 |

##### 9.1.3 多分支写法（链式 `if-else`）

由于 `else if` 不允许写在同一行，链式分支的标准写法为：

```text
if <cond1> then
    语句序列1
else
    if <cond2> then
        语句序列2
    else
        if <cond3> then
            语句序列3
        else
            语句序列4
        end
    end
end
```

每个 `if` 都必须有对应的 `end`，且缩进逐级递增。

##### 9.1.4 执行语义

1. 计算 `<bool_rhs>` 的值。
2. 若为 `true`，执行 `then` 块内的所有语句，执行完后跳过 `else` 部分，直接跳至对应的 `end` 之后继续执行外层后续语句。
3. 若为 `false`，若存在 `else` 分支，则进入 `else` 块执行其内部语句（若 `else` 块内包含 `if`，则按 `if` 规则递归执行）。执行完 `else` 块后，遇到 `end` 继续执行外层后续语句。
4. 若条件为 `false` 且无 `else`，则直接跳至 `end` 之后执行。

##### 9.1.5 作用域与变量定义

- 整个 `if` 语句（从 `if` 行到对应的 `end`）构成一个**块级作用域**。
- `then` 与 `else` 各自构成**互斥子作用域**：同一 `if` 内，`then` 侧定义的局部标识符在 `else` 侧不可见，反之亦然；因执行路径互斥，允许在 `then` 与 `else` 中分别定义**同名**局部变量（静态分析视为不同绑定）。
- 块内允许使用 `var` 和 `let` 定义新的变量/常量；`end` 之后无法访问该 `if` 块内定义的任何局部标识符。
- 嵌套 `if` 时，内层块可访问外层块已定义的变量，除非被内层同名局部变量屏蔽。

##### 9.1.6 与 `let` 常量的交互

`let` 常量可在 `if` 块内定义，作用域同样限于该块。若 `if` 条件中引用 `let` 常量，其值是编译期确定的。

##### 9.1.7 与函数控制流的交互

`if` 可出现在顶层或函数体内。函数体各分支可使用 `return`；非 `void` 函数是否覆盖全部正常退出路径按 §10.3.2 和 §10.4 的函数 CFG 判断。顶层 `return` 是静态错误。函数定义本身不得出现在任何 `if` / `else` 分支内。

#### 9.2 循环语句（`while`）

TC 提供 **Pascal 风格** 的 `while` 结构化循环语句，采用 **缩进敏感** 的块结构，并以 **`end`** 关键字作为块的强制结束标志。

##### 9.2.1 语法定义

**强制语法形式**（行结构敏感）：

```text
while <bool_rhs> then
    语句序列
end
```

- `while`、`then`、`end` 为保留关键字。
- `<bool_rhs>` 为任何可产生 `bool` 类型结果的右值表达式（参见 §4.5）。
- `then` 关键字必须位于 `while` 行的末尾（其后必须换行），不可在同一行写其他内容（行末注释 `;` 除外）。
- `end` 关键字**必须单独另起一行**，缩进级别必须与对应的 `while` 行**完全一致**。`end` 是 `while` 语句的强制结束标志，不可省略。
- `语句序列` 由零条或多条语句组成，每条语句独占一行；直接循环体语句**必须比 `while` 行恰好多一个缩进级别**。块内允许包含 `var` / `let` 定义、赋值、I/O、`funcall`、函数体内的 `return`、`break`、`continue` 以及嵌套 `if` / `while`；不允许嵌套 `func` 定义。

**缩进规则** 与 `if` 语句完全一致（参见 §9.1.2），即 `while`、`then`（隐式）、`end` 行缩进必须相等，块内语句缩进更大。

##### 9.2.2 执行语义

1. 计算 `<bool_rhs>` 的值。
2. 若为 `true`，执行 `then` 块内的所有语句（顺序执行）。
   - 若执行过程中遇到 `break`，立即退出整个 `while` 循环，跳转到对应的 `end` 之后继续执行。
   - 若遇到 `continue`，立即跳过当前迭代的剩余语句，跳转到步骤 1（重新计算条件）。
   - 若正常执行完块内所有语句（未遇 `break`/`continue`），则返回步骤 1，开始下一次迭代。
3. 若为 `false`，直接跳转到对应的 `end` 之后，循环终止。

> **无限循环说明**：当 `<bool_rhs>` 恒为 `true`（如 `while true then`）时，循环仅能通过 `break` 终止（因 `while` 内禁止 `goto`），否则为无限循环。

##### 9.2.3 作用域与变量定义

- 整个 `while` 语句（从 `while` 行到对应的 `end`）构成一个**块级作用域**。
- 块内使用 `var` 和 `let` 定义的新变量/常量，在 `end` 之后不可访问。
- 嵌套循环时，内层循环可访问外层变量，除非被同名局部变量屏蔽。
- `break` 和 `continue` 作用于**最内层**包含它们的 `while` 循环。它们不能跨循环作用（即 `break` 不能跳出嵌套的外层循环，只能跳出直接包围它的循环）。
- 位于函数体内时，`break` / `continue` 的目标查找在当前函数边界停止，绝不作用于调用者中的循环。

##### 9.2.4 范式隔离原则（与 `goto` 的交互）

TC 提供两种实现循环的手段，二者属于**互斥范式**，不得混合使用：

1. **结构化循环（`while`）**：适用于逻辑清晰、入口/出口明确的场景。`while` 循环体内部**严格禁止**出现 `goto` 和 `label` 定义（因其破坏结构化块的结构完整性）。循环控制仅通过 `break`（退出）和 `continue`（跳回条件）实现。
2. **非结构化循环（函数内 `if` + `goto`）**：适用于状态机、复杂退出条件或底层汇编模拟场景。程序员在函数体内使用 `if` 条件判断结合 `goto` 向前/向后跳转，自行构建循环入口和出口（详见 §9.3）。此模式下不涉及 `while` 关键字；顶层不能使用该范式。

**编译器约束**：
- 先按 §9.3.3 检查 `goto` / `label` 是否位于函数体内；函数外使用优先报告 `TC_ERR_GOTO_OUTSIDE_FUNCTION` / `TC_ERR_LABEL_OUTSIDE_FUNCTION`。
- 仅对已经确认位于函数体内的语句：若 `goto` 的词法祖先中包含 `while` 块 → 静态错误 `TC_ERR_GOTO_INSIDE_LOOP`。
- 仅对已经确认位于函数体内的语句：若 `label` 的词法祖先中包含 `while` 块 → 静态错误 `TC_ERR_LABEL_INSIDE_LOOP`。

> **设计原理**：`while` 是结构化编程的语法糖，强制程序员写出可预测、可验证的代码（受限的入口和出口）。`if` + `goto` 还原了汇编级的原始跳转灵活性。TC 不允许在同一段循环逻辑中混用两种范式，以保持代码意图清晰。

##### 9.2.5 与初始化相关的静态分析

循环相关的静态分析必须覆盖：

- `break` / `continue` 是否处于合法的 `while` 上下文（§9.4）；
- 范式隔离：`while` 体内无 `goto` / `label`（§9.2.4）；
- 以条件失败、正常回边、`continue` 与 `break` 构造完整 CFG；
- 按 §11.2 在全部可达路径上计算确定初始化集合。

除 §11.2 能在编译期证明条件恒为 `true` 外，循环体均可能零次执行，因此仅在循环体中执行的 `var` 不会自动进入循环后的确定初始化集合。恒真 `while` 不产生条件失败出口，仅可达 `break` 边参与循环后的会合；恒假 `while` 的循环体不可达。所有符合 0.0.32 的实现必须得到相同的分析结果。

#### 9.3 受限 `goto` 语句

TC 提供**仅限函数体内**的受限 `goto` 跳转语句，在保留汇编级灵活性的同时维护函数、调用帧和结构化块的安全边界。`goto` 是函数内构建**非结构化循环**（`if` + `goto`）的基础工具；顶层语句区保持结构化，不建立标签表，也不允许出现 `goto` 或 `label`。

##### 9.3.1 设计原则

1. **函数内限定**：`goto` 与 `label` 都必须具有 `func` 词法祖先。顶层直接使用，或在顶层 `if` / `else` / `while` 的任意嵌套层级使用，分别触发 `TC_ERR_GOTO_OUTSIDE_FUNCTION` 或 `TC_ERR_LABEL_OUTSIDE_FUNCTION`。
2. **同函数限定**：每个函数独立建立标签表；`goto` 只能解析当前函数内的标签，绝不跳到顶层或另一函数。
3. **作用域约束（只出不进）**：函数内仅允许跳转到当前作用域的**祖先作用域**（向外）或**自身作用域**（平级）。
4. **位置自由**：在满足其他规则时支持向前跳转和向后跳转，无源序方向限制。
5. **禁止侵入**：严禁跳入任何子作用域或兄弟作用域（如 `then` ↔ `else`）。
6. **范式隔离**：函数内 `goto` **不得**出现在 `while` 循环体内，`label` 也不得定义在 `while` 循环体内（见 §9.2.4）。
7. **标签规则**：同一块级作用域内禁止定义同名标签；不同块可定义同名标签。标签名与变量名、常量名属于不同命名空间。
8. **初始化约束完备统一**：合法 `goto` 边进入当前函数的完整 CFG；变量是否可用只由 §11.2 的确定初始化分析判定。

##### 9.3.2 语法定义

**标签定义**：
- 关键字 `label` + 标识符 + `:`，**必须单独占一行**（行末可带注释）。
- `label` 只能出现在函数体直接层级，或函数体内且不具有 `while` 祖先的 `if` / `else` 块中。
- **缩进规则**（与 §9.1.2 R7 一致）：
  1. `label` **不产生**新的缩进层级，也**不开启**代码块或作用域。
  2. `label` 行本身视为函数内的**普通语句**：在函数体直接层级时比 `func` 行恰好多一级；在 `if` / `else` 块内时比块头恰好多一级，并与同块赋值、`goto` 等对齐。
  3. 紧随 `label` 之后、仍属于同一作用域、且**不是**因 `if`/`while` 等开启的新子块内的语句，其缩进必须与该 `label` 行**完全一致**（不得因出现 `label` 而额外多缩进一级，也不得比 `label` 更少）。
  4. 仅当后续语句自身开启子块（如 `if` … `then` / `while` … `then`）时，子块内部语句才按 §9.1.2 R3–R6 增加缩进；该子块的 `if`/`while`/`else`/`end` 行缩进仍与其外围同级语句（含前述 `label`）对齐。
- **执行语义**：标签本身不产生任何执行动作（即零成本标记）。`goto` 跳转后，控制权转移到该标签后的**下一条语句**。

**跳转语句**：
- 关键字 `goto` + 标识符（标签名），单独占一行。
- `goto` 只能出现在函数体直接层级，或函数体内且不具有 `while` 祖先的 `if` / `else` 块中。
- `goto` 属于函数内普通语句，缩进规则与同作用域其他语句一致：函数体直接层级比 `func` 行恰好多一级；`if` 块内比块头恰好多一级并与块内赋值、`label` 对齐，不得与对应块头或 `end` 对齐。

```text
func count_to_ten() int32 then
    var i: int32 = 0
    label loop_start:            ; 函数体直接层级，不产生新缩进
    i = add(int32, i, 1)         ; 与 label 同缩进
    if lt(int32, i, 10) then
        goto loop_start          ; 函数内向外跳回 loop_start
    end
    return i
end

var result: int32 = funcall(count_to_ten)
```

顶层的 `var result` 与 `funcall` 合法；如果把函数内任一 `goto` 或 `label` 移到顶层，即使缩进为 0、目标也在顶层，仍属于函数外使用并必须拒绝。

##### 9.3.3 作用域跳转的形式化规则

设 `F` 为包含 `goto` 的函数，`Src` 为 `goto` 在 `F` 中所在的最内层代码块（`if` 块或函数体直接层级），`Tgt` 为目标标签在 `F` 中所在的最内层代码块。祖先链最多上溯到 `F` 的函数体直接层级。

在应用块关系前，必须按以下顺序完成上下文检查：

1. `goto` 没有 `func` 词法祖先 → `TC_ERR_GOTO_OUTSIDE_FUNCTION`，不执行标签查找；
2. `goto` 的任一词法祖先是 `while` → `TC_ERR_GOTO_INSIDE_LOOP`；
3. 仅在当前函数 `F` 的标签表中解析名称；当前函数无同名标签但另一函数存在时，报告跨控制流域跳转；所有函数均不存在时报告 `TC_ERR_LABEL_NOT_FOUND`；
4. 名称解析成功后，按下表检查 `Src` 与 `Tgt` 的块关系。

| 判定条件                                                     | 结果               | 错误码                         |
| :----------------------------------------------------------- | :----------------- | :----------------------------- |
| `Tgt` 与 `Src` 相同                                          | ✅ 合法（平级跳）   | —                              |
| `Tgt` 是 `Src` 的严格祖先（外层）                            | ✅ 合法（向外跳）   | —                              |
| `Tgt` 是 `Src` 的严格后代（内层）                            | ❌ 非法（跳入子块） | `TC_ERR_JUMP_INTO_BLOCK`       |
| `Tgt` 与 `Src` 为兄弟（同父不同子）                          | ❌ 非法（跨分支）   | `TC_ERR_JUMP_TO_SIBLING_BLOCK` |
| 当前函数无同名标签，但另一函数存在同名标签                   | ❌ 非法（跨函数）   | 函数诊断类别“跨控制流域跳转错误”（§13.2） |
| 在当前作用域及所有祖先作用域中均**未找到**目标标签           | ❌ 非法             | `TC_ERR_LABEL_NOT_FOUND`       |
| 在当前作用域内**重复定义**同名标签（即同一块内出现两个相同 `label` 名） | ❌ 非法             | `TC_ERR_DUPLICATE_LABEL`       |

> **注**：由于不同块级作用域允许定义同名标签，`TC_ERR_DUPLICATE_LABEL` 仅在**同一最内层代码块**内触发，跨块重名不视为错误。

> **实现注记**：判定算法为自 `Src` 向上遍历父级作用域链，若 `Tgt` 出现在链中（含自身），则合法；否则非法。

##### 9.3.4 语义规则

1. **执行流转移**：`goto` 无条件将控制权转移至目标标签后的第一条语句。
2. **变量生命周期**：若跳转跳出某作用域（如 `then` 块），该块内的局部变量按 §11.1 / §11.2 **立即销毁**（与 `end` / `break` 离开块等价）；后续任何对该块内变量的引用，静态分析会报"未定义标识符"。
3. **CFG 边**：每条合法 `goto` 都必须形成从跳转语句到目标标签后第一条语句的显式 CFG 边；向前、向后、同层与向外跳转使用同一表示。
4. **确定初始化**：编译器按 §11.2 在包含该边的完整 CFG 上求固定点。任何变量读取、赋值目标或 `read` 目标若不在当前 `IN` 集合中，触发静态错误 `TC_ERR_UNINITIALIZED_VARIABLE`。
5. **精确拒绝**：仅仅在源序上越过 `var` 不自动构成错误；若被越过的绑定在离开其作用域前从未使用，程序仍可合法。反之，无论被越过的 `var` 位于同层还是祖先作用域，只要存在可达未初始化使用就必须拒绝。
6. **反向跳转**：再次执行同一 `var` 时重新初始化同一词法槽；不重复分配槽位。
7. **跳过 `end`**：允许 `goto` 跳出 `if` 块而无需经过 `end`，执行流正常继续。
8. **不修改值**：`goto` 本身不改变任何仍存活变量的值，仅转移控制流。
9. **不跨函数**：跨函数的非法跳转不得进入任何 CFG，VM 与 AOT 也不得为其生成运行时边。当前函数不存在同名标签、但另一函数存在时报告跨控制流域跳转；所有函数均不存在时报告标签未找到。

**示例**：
```text
func invalid_path() void then
    goto label_skip
    var x: int32 = 10
    label label_skip:
    writeln(int32, %d, x)   ; TC_ERR_UNINITIALIZED_VARIABLE
    return
end

func valid_path() void then
    goto after_unused
    var unused: int32 = 10
    label after_unused:
    writeln(int32, %d, 0)    ; 合法：被跳过的 var 从未使用
    return
end
```

##### 9.3.5 合法示例

**示例 1：非结构化循环（`if` + `goto` 模拟 `while`）**
```text
func count_to_ten() int32 then
    var i: int32 = 0
    label loop_start:
    i = add(int32, i, 1)
    if lt(int32, i, 10) then
        goto loop_start   ; ✅ 当前函数内向外跳转
    end
    return i
end

var result: int32 = funcall(count_to_ten)
writeln(int32, %d, result) ; 10
```

**示例 2：向外跳转**
```text
func adjust(value: int32) int32 then
    var result: int32 = value
    if gt(int32, result, 0) then
        result = add(int32, result, 10)
        goto after_if      ; ✅ 跳出 if 块到函数体直接层级
    end
    label after_if:
    return result
end
```

**示例 3：跨多层向外跳转**
```text
func retry(a: int32, b: int32) void then
    label function_target:     ; 函数体直接层级标签
    if eq(int32, a, 0) then
        if eq(int32, b, 0) then
            goto function_target ; ✅ 从内层 if 跳到函数体直接层级
        end
    end
    return
end
```

**示例 4：跨块同名标签（合法，类比同名局部变量）**
```text
func show_branch(a: int32, b: int32) void then
    if gt(int32, a, 0) then
        label done:            ; 分支 A 中的标签
        writeln(int32, %d, a)
    else
        label done:            ; 分支 B 中的同名标签（合法，互斥作用域）
        writeln(int32, %d, b)
    end
    return
end
```

**示例 5：嵌套块引用外部标签（合法）**
```text
func count_again() int32 then
    var i: int32 = 0
    label outer:               ; 函数体直接层级标签
    if lt(int32, i, 10) then
        i = add(int32, i, 1)
        goto outer             ; ✅ 内部块引用函数内外层标签
    end
    return i
end
```

##### 9.3.6 非法示例

**示例 1：跳入子块**
```text
func invalid_into(a: int32) void then
    goto inner             ; ❌ TC_ERR_JUMP_INTO_BLOCK
    if gt(int32, a, 0) then
        label inner:
        writeln(int32, %d, a)
    end
    return
end
```

**示例 2：跳入兄弟分支**
```text
func invalid_sibling(a: int32) void then
    if gt(int32, a, 0) then
        goto else_branch   ; ❌ TC_ERR_JUMP_TO_SIBLING_BLOCK
    else
        label else_branch:
        writeln(int32, %d, a)
    end
    return
end
```

**示例 3：跨多层嵌套向里跳**
```text
func invalid_deep(a: int32, b: int32) void then
    if gt(int32, a, 0) then
        goto deep          ; ❌ TC_ERR_JUMP_INTO_BLOCK
        if gt(int32, b, 0) then
            label deep:
            writeln(int32, %d, b)
        end
    end
    return
end
```

**示例 4：`goto` 在 `while` 循环体内（范式隔离违规）**
```text
func invalid_loop() void then
    var i: int32 = 0
    while lt(int32, i, 10) then
        i = add(int32, i, 1)
        goto after_loop    ; ❌ TC_ERR_GOTO_INSIDE_LOOP
    end
    label after_loop:
    return
end
```

**示例 5：向前跳转导致未初始化读取（非法）**
```text
func invalid_init() void then
    goto skip_init
    var init: int32 = 42
    label skip_init:
    writeln(int32, %d, init) ; ❌ TC_ERR_UNINITIALIZED_VARIABLE
    return
end
```

**示例 6：函数外使用 `goto` / `label`**
```text
label top_target:          ; ❌ TC_ERR_LABEL_OUTSIDE_FUNCTION
goto top_target            ; ❌ TC_ERR_GOTO_OUTSIDE_FUNCTION

if true then
    goto nested_top        ; ❌ 仍在函数外，不因位于 if 内而合法
end
```

**示例 7：跨函数跳转**
```text
func first() void then
    label shared:
    return
end

func second() void then
    goto shared            ; ❌ 跨控制流域跳转错误
    return
end
```

##### 9.3.7 受限 `goto`：统一保证

受限 `goto` 同时受到函数边界、块作用域、标签解析、范式隔离和确定初始化五类强制规则：

| 类别 | 规则摘要 | 错误码 / 依据 |
| ---- | -------- | ------------- |
| 函数边界 | `goto` / `label` 必须位于函数体内；目标必须属于当前函数 | `TC_ERR_GOTO_OUTSIDE_FUNCTION` / `TC_ERR_LABEL_OUTSIDE_FUNCTION` / 跨控制流域跳转错误 |
| 作用域 | 禁止跳入子块、禁止跳入兄弟块；仅平级或向外 | `TC_ERR_JUMP_INTO_BLOCK` / `TC_ERR_JUMP_TO_SIBLING_BLOCK` |
| 标签 | 同块内标签唯一；祖先链上可解析；`while` 内禁止 `goto`/`label` | `TC_ERR_DUPLICATE_LABEL` / `TC_ERR_LABEL_NOT_FOUND` / `TC_ERR_GOTO_INSIDE_LOOP` / `TC_ERR_LABEL_INSIDE_LOOP` |
| 声明形态 | `var` 声明必须带 RHS | `TC_ERR_VAR_MISSING_INIT` |
| 路径安全 | 每次可达读取、赋值或 `read` 前，绑定均确定初始化 | `TC_ERR_UNINITIALIZED_VARIABLE` / §11.2 |

以上规则共同构成 0.0.32-rev2 的完整要求。实现可以采用不同的内部算法，但不得在顶层建立可跳转标签或 `goto` 边，不得接受跨函数跳转或存在可达未初始化使用的程序，也不得仅因源序上越过一个从未使用的 `var` 而拒绝程序。

#### 9.4 `break` 与 `continue` 语句

##### 9.4.1 语法定义

`break` 和 `continue` 各为一条独立语句，独占一行，无额外参数。

```text
break
continue
```

**缩进规则**：它们属于普通语句，必须遵循所在块（`while`、`if` 或嵌套块）的缩进规则，即缩进级别必须严格大于当前块级缩进。

##### 9.4.2 语义规则

| 语句       | 行为                                                         |
| ---------- | ------------------------------------------------------------ |
| `break`    | 立即终止**最内层**包含它的 `while` 循环，控制流跳转到该循环的 `end` 之后；离开该 `while` 块时，块内局部变量按 §11.1 / §11.2 销毁。 |
| `continue` | 立即结束当前迭代，控制流跳转到**最内层**包含它的 `while` 的条件求值处：重新计算 `<bool_rhs>`；若为 `true`，则从循环体**首条语句**起按源序重新执行（再次执行到的块内 `var` 会重新初始化同一局部槽）；若为 `false`，则退出循环（效果同条件失败，局部按离开块规则销毁）。`continue` **不会**跳过条件求值而直接落到循环体中部。 |

**约束**：
- `break` 和 `continue` **必须**直接或间接位于某个 `while` 循环体内（即其所在的词法作用域链中至少有一个 `while` 块）。
- 若编译器静态分析发现 `break` 或 `continue` 不在任何 `while` 循环内，触发静态错误：
  - `TC_ERR_BREAK_OUTSIDE_LOOP`（针对 `break`）
  - `TC_ERR_CONTINUE_OUTSIDE_LOOP`（针对 `continue`）
- `break`/`continue` 可以出现在 `if` 块或其他嵌套块内，只要这些块本身位于 `while` 循环体内即可。
- **禁止**使用 `break`/`continue` 跳出 `while` 直接到外层（例如想跳出两层循环，需改写结构化逻辑，或将该逻辑封装进函数后使用 `if` + `goto` 非结构化循环重构）。`break`/`continue` 的作用域目标是最内层 `while`，**而非**最内层 `if`。
- `break` 和 `continue` 的作用域目标仅为最内层包含它们的 `while` 循环，外围的 `if` 块不影响其合法性判定。
- 目标查找不得穿越函数边界；函数调用者中的 `while` 不会使被调函数内的 `break` / `continue` 合法。

##### 9.4.3 与 `if` 的典型组合

实际编程中，`break`/`continue` 常配合 `if` 条件使用：

```text
while lt(int32, i, 10) then
    if eq(int32, i, 5) then
        break
    end
    i = add(int32, i, 1)
end
```

##### 9.4.4 与 `let` 常量的交互

`while` 条件中可以引用 `let` 常量。强制 RHS 不因恒真/恒假循环而改变；涉及 `goto` 时见 §9.3.7。

### 10. 函数与调用模型

#### 10.1 函数定义与签名（`func`）

函数是显式可调用结构，不是 TC 程序的基本封装单元。顶层语句仍是程序入口，函数定义只在编译期建立签名和函数体，不产生顶层执行效果。

##### 10.1.1 定义形式

有返回值函数：

```text
func add_values(lhs: int32, rhs: int32) int32 then
    var result: int32 = add(int32, lhs, rhs)
    return result
end
```

`void` 函数：

```text
func show_value(value: int32) void then
    writeln(int32, value)
    return
end
```

无参函数：

```text
func get_value() int32 then
    return 10
end
```

函数头的形式为：

```text
func <函数名>([<形参名>: <值类型> [, ...]]) <返回类型> then
```

- 形参类型只能是 `bool`、8 种整数类型或 2 种浮点类型。
- 返回类型可以是上述值类型或 `void`。
- 函数体直接语句必须比 `func` 行恰好多一个缩进级别；函数 `end` 必须与 `func` 行对齐。
- 函数体可以为空，但空函数体仍须满足返回路径规则；因此空的非 `void` 函数和空的 `void` 函数都会因可达函数末尾而报缺少返回。

##### 10.1.2 签名约束

- 函数名在源文件中唯一，不支持重载。
- 函数名不得与顶层 `var` 或 `let` 同名。
- 形参名在同一函数签名中唯一。
- 形参按值传递，是函数入口处已初始化的只读绑定；不得赋值，也不得作为 `read` 目标。
- `void` 不是值类型，不得用作形参、`var`、`let`、转换目标、运算类型参数或操作数类型。
- 参数或函数局部值绑定不得与任何全局函数同名；函数内任何层级都不得声明与形参同名的 `var` / `let`。
- 编译器在分析任何函数体和顶层语句之前收集全部函数签名。函数可调用定义在其后的函数，但调用图必须无环（§10.6.3）。

##### 10.1.3 定义位置

- 函数定义区可以为空。
- 所有函数必须位于第一条顶层语句（包括编译期 `let` 声明）之前。
- `func` 不是语句，因而不得出现在函数体、`if` / `else` 分支或 `while` 循环体内。
- 不支持脱离 `func`、`if` 或 `while` 的匿名代码块。
- `main` 不是特殊名称；程序不因存在 `main` 函数而自动调用它。

非法示例：

```text
var input: int32 = 10

func get_value() int32 then   ; 非法：顶层语句区开始后又定义函数
    return 10
end
```

##### 10.1.4 0.0.32 不支持的函数形态

0.0.32 不支持函数重载、默认参数、可变参数、函数值、函数指针、闭包、嵌套函数、匿名函数、直接或间接递归、隐式参数转换、隐式返回转换和函数调用嵌套。函数不能隐式访问顶层值绑定；标准 I/O 副作用仍被允许。

#### 10.2 函数调用（`funcall`）

##### 10.2.1 调用形式

```text
funcall(<函数名> [, <形参名>: <operand> ...])
```

非 `void` 函数：

```text
var total: int32 = funcall(add_values, lhs: 10, rhs: 20)
```

`void` 函数：

```text
funcall(show_value, value: total)
```

`funcall` 的第一项必须是静态函数名，而不是普通 RHS 或函数值。该名称只在全局函数签名表中解析。

##### 10.2.2 命名且有序的实参

- 除函数名外，每一项必须使用 `<形参名>: <operand>` 形式。
- 每个形参必须恰好匹配一个实参；缺失、重复或未知实参名均为静态错误。
- 实参必须按形参在签名中的声明顺序书写。名称集合正确但文本顺序不同仍是静态错误。
- “命名且有序”是有意的双重约束：命名让调用点显式表达参数含义，声明顺序让数据流与接口结构一致，并为 VM 与 AOT 提供可直接检查的位置映射。
- 第 `i` 个实参必须命名为第 `i` 个形参，并以该形参声明类型作为唯一期望类型。编译器不得重排，也不得绕过文本位置按名称重新匹配。
- 实参操作数严格按调用点从左到右读取并依次绑定。VM 与 AOT 不得改变该可观测顺序。
- 每个实参只能是 §4.6 的 `operand`：标识符、整数字面量、浮点字面量、浮点特殊值或布尔字面量。算术、位、比较、逻辑、转换和 `funcall` 均不得直接作为实参。
- 复杂值必须先由独立语句初始化临时 `var`，再传入该变量。因此一条 `funcall` 语句只包含一个运行时调用。
- 标识符、普通浮点字面量和布尔字面量的类型必须与形参严格相同，不做隐式转换。无后缀浮点字面量为 `float64`，`f` / `F` 后缀为 `float32`。
- 整数字面量与浮点特殊值使用对应形参类型作为期望类型，并按 §3.6 检查符号性、后缀和范围。字面量自身的词法或范围错误先于实参类型错误。

合法：

```text
var total: int32 = funcall(add_values, lhs: 10, rhs: 20)
```

名称正确但顺序错误：

```text
var total: int32 = funcall(add_values, rhs: 20, lhs: 10)
```

位置实参和复杂实参都不符合附录 A：

```text
var a: int32 = funcall(add_values, 10, 20)
var b: int32 = funcall(add_values, lhs: add(int32, x, y), rhs: 20)
```

复杂实参必须拆分：

```text
var lhs_value: int32 = add(int32, x, y)
var total: int32 = funcall(add_values, lhs: lhs_value, rhs: 20)
```

##### 10.2.3 返回值使用位置

非 `void` 函数调用只能直接初始化一个**新声明**的 `var`，且该变量的声明类型必须与函数返回类型严格相同：

```text
var result: int32 = funcall(get_value)
```

`void` 函数调用只能作为独立语句。调用位置矩阵如下：

| 调用位置 | 非 `void` | `void` |
| --- | ---: | ---: |
| `var x: T = funcall(...)` | 合法 | 静态错误 |
| 独立 `funcall(...)` | 静态错误 | 合法 |
| `let x: T = funcall(...)` | 语法错误 | 语法错误 |
| 已有变量赋值 | 语法错误 | 语法错误 |
| `return` 操作数位置 | 语法错误 | 语法错误 |
| 嵌套实参或其他运算操作数 | 语法错误 | 语法错误 |

`var x: T = funcall(...)` 与独立 `funcall(...)` 都由语法接受；被调函数的实际返回类型不适合该位置时，报函数调用位置错误。非 `void` 调用的实参合法后，再检查接收 `var` 的声明类型；不匹配时报调用结果类型错误。

返回值转发必须经过新 `var`：

```text
func forward() int32 then
    var result: int32 = funcall(get_value)
    return result
end
```

#### 10.3 `return` 语句

##### 10.3.1 语法形式

```text
return [operand]
```

- 非 `void` 函数使用 `return operand`。
- `void` 函数使用裸 `return`。
- `return` 后最多一个 §4.6 定义的 `operand`；运算、转换或 `funcall` 不符合语法，必须先写入局部 `var`。

##### 10.3.2 静态语义

- `return` 只能出现在函数体内；顶层 `return` 是静态错误。
- 非 `void` 函数禁止裸 `return`；`void` 函数禁止 `return operand`。
- 返回标识符或普通字面量的类型必须与声明返回类型严格相同，不进行隐式转换。
- 整数字面量与浮点特殊值由返回类型提供期望类型上下文；浮点字面量仍由后缀决定类型。
- 每条从函数入口可达、会正常退出函数体的路径都必须经过匹配签名的显式 `return`。函数体 `end` 不产生隐式返回。
- 编译器为每个函数建立唯一函数末尾节点；若该节点从函数入口可达，报缺少返回。
- 不要求证明一般程序终止。永久停留在 `while` 或受限 `goto` 循环、且没有到函数末尾 CFG 边的可达路径合法。
- 同一基本块中，无条件 `return` 后的普通语句触发不可达语句错误。其他 CFG 不可达代码仍接受词法、语法、名称和类型检查，但不因不可达本身报错，也不参与确定初始化分析。

直接返回运算结果非法，必须拆分：

```text
; 非法
return add(int32, lhs, rhs)

; 合法
var result: int32 = add(int32, lhs, rhs)
return result
```

全路径返回示例：

```text
func choose(flag: bool) int32 then
    if flag then
        return 1
    else
        return 2
    end
end
```

若删除 `else` 分支，`flag == false` 时会到达函数末尾，因而是缺少返回错误。

##### 10.3.3 运行时语义

`return` 按以下顺序执行：

1. 若存在返回操作数，在当前函数帧中读取其值。
2. 将结果复制到调用者拥有、且不随被调函数帧销毁的返回值位置。
3. 离开当前函数的所有活动块作用域。
4. 销毁当前函数帧。
5. 将控制权恢复到调用者的 `funcall` 之后。
6. 非 `void` 结果用于初始化调用点的新 `var`。

若读取返回值或执行被调函数期间发生运行时错误，整个程序立即终止；不执行正常返回流程，调用点的新 `var` 也不成为已初始化绑定。VM 与 AOT 可以采用不同清理机制，但不得恢复调用者继续执行。

#### 10.4 函数作用域与独立 CFG

##### 10.4.1 名称查找和局部绑定

函数体内普通值标识符按以下顺序查找：当前块、逐层外部块、函数体直接局部绑定、当前函数参数；到函数边界即停止。函数体不得读取或修改顶层 `var` / `let`。

- 函数体直接声明的 `var` / `let` 从声明完成后可见，到函数返回时失效。
- 同一作用域不得重复定义同名值绑定；内层块可按 §11.1 屏蔽外层局部绑定，但不得屏蔽参数。
- 函数内 `let` 仍须在编译期求值，不得引用参数、局部 `var` 或 `funcall`。
- 参数在入口已初始化；函数内 `var` 仍须声明时提供初始化器。
- 函数返回时销毁所有局部运行时槽；`let` 继续编译期内联，不分配运行时槽。

##### 10.4.2 顶层 CFG

顶层 CFG：

1. 具有唯一入口和唯一程序正常结束节点，入口已初始化集合为空。
2. 顶层绑定只由顶层声明和顶层数据流产生。
3. 文件末尾连接程序正常结束节点，不执行缺少返回检查。
4. 顶层 `return` 在 CFG 构建前拒绝。
5. 顶层及其嵌套块中的 `goto` / `label` 在 CFG 构建前分别以 `TC_ERR_GOTO_OUTSIDE_FUNCTION` / `TC_ERR_LABEL_OUTSIDE_FUNCTION` 拒绝；顶层不建立标签表，也不生成 `goto` 边。
6. 顶层 `funcall` 是单个原子节点，不产生到被调函数 CFG 的边。

##### 10.4.3 函数 CFG

每个函数 CFG 至少包含唯一入口、函数体语句与控制节点、每条 `return` 的正常返回终止节点，以及表示未经 `return` 到达 `end` 的唯一函数末尾节点。

1. `IN[entry]` 恰好包含当前函数全部形参，不包含顶层绑定、调用者局部绑定或其他函数状态。
2. `if`、`while`、`break`、`continue`、`goto` 和标签沿用本章规则，但所有边必须留在当前函数 CFG 内。
3. `return` 只连接当前函数的正常返回终止节点，没有函数内后继边。
4. `funcall` 在调用者 CFG 中保持单节点；成功的非 `void` 调用把接收结果的新 `var` 加入 `OUT`，`void` 调用不改变已初始化集合。
5. 只有入口可达节点参与固定点和函数末尾检查。不可达代码的其他静态检查仍执行。
6. 函数末尾节点可达时报缺少返回；无出口循环不产生到函数末尾的边。

顶层 CFG 与各函数 CFG 是完整、封闭、彼此独立的分析单元，不得拼接、内联或共享节点、边、可达性、已初始化集合、活动块路径或固定点状态。实现可复用算法，但不得合并各域的入口、出口和语义状态。

#### 10.5 函数控制流边界

- `return` 立即离开当前函数，不影响调用者的词法作用域。
- 顶层与每个函数各自构成独立控制流域，但只有函数建立标签表。
- `goto` 与 `label` 必须具有 `func` 词法祖先；顶层直接出现或位于顶层嵌套块内时，在标签解析和 CFG 构建前拒绝。
- 函数内 `goto` 只能跳到当前函数内按 §9.3 可见的标签；标签查找到函数边界即停止。
- 函数不得跳到顶层或其他函数；非法跨域跳转不进入 CFG。
- 解析函数内 `goto name` 时，只把当前函数标签作为候选目标：若当前函数有同名标签，继续应用词法可见性和“只出不进”规则；若当前函数无同名标签而另一函数存在，报跨控制流域跳转；若所有函数都不存在，报标签未找到。
- 不同函数可以定义同名标签，它们是相互独立的绑定。
- 函数内标签继续遵循块级可见性以及 `while` 内禁用 `goto` / `label` 的规则。
- `break` / `continue` 只能作用于当前函数内词法上最内层 `while`，不得穿越函数边界。

#### 10.6 调用图与运行模型

##### 10.6.1 调用帧

每次 `funcall` 至少创建以下逻辑状态：

- 被调函数标识；
- 返回地址或等价继续点；
- 按形参绑定的实参值；
- 函数局部 `var` 槽；
- 活动块路径和函数内控制流状态；
- 非 `void` 函数的返回值位置。

规范不强制 VM 与 AOT 使用相同物理布局，但可观测语义必须一致。

##### 10.6.2 调用步骤

1. 按形参声明顺序，从左到右检查同一文本位置的实参名称和期望类型，并读取实参操作数。
2. 任一运行时错误立即终止整个程序。
3. 创建被调函数帧并写入参数值。
4. 从函数体第一条语句开始执行。
5. 执行 `return` 时销毁函数帧并恢复调用者。
6. 非 `void` 结果初始化调用点的新 `var`。

##### 10.6.3 无环调用图

编译器必须为全部函数体内的 `funcall` 建立有向调用图；顶层调用可以作为无入边的外部根记录，但不参与函数间环判定。调用图边不是 CFG 边，不参与确定初始化、可达性或控制流传播。

若函数调用图存在环，无论相关调用点运行时是否可达，均报递归错误。自调用是长度为 1 的环；间接递归同样非法。

#### 10.7 函数综合示例

```text
func add_values(lhs: int32, rhs: int32) int32 then
    var result: int32 = add(int32, lhs, rhs)
    return result
end

func forward_value(value: int32) int32 then
    var result: int32 = funcall(add_values, lhs: value, rhs: 1)
    return result
end

func show_value(value: int32) void then
    writeln(int32, value)
    return
end

var input: int32 = 10
var output: int32 = funcall(forward_value, value: input)
funcall(show_value, value: output)
```

函数签名先被收集而不执行；顶层初始化 `input` 后调用 `forward_value`，后者调用 `add_values` 并显式返回；顶层再用返回值初始化 `output`，最后独立调用 `void` 函数。

### 11. 名称、作用域、生命周期与确定初始化

#### 11.1 作用域

TC 采用 **全局函数签名表**、**顶层值作用域**、**函数作用域** 与 **块级作用域** 相结合的设计：

- **全局函数签名表**：编译器在分析函数体和顶层语句前收集全部函数签名。函数名全局可见，不受定义源序限制；普通 RHS 不把函数名解析为值，只有 `funcall` 的第一项在该表中解析。
- **顶层值作用域**：函数定义区之后、且不在任何 `if`/`while` 块内部定义的 `var` 和 `let` 属于顶层值作用域。它们在顶层语句区遵循源序可见性，生命周期贯穿程序运行始终；函数体不得读取或修改这些绑定。
- **函数作用域**：每个函数体形成独立函数作用域，包含只读参数、函数体直接声明的局部 `var` / `let`，以及嵌套块。普通值名称查找到函数边界即停止，不得继续查找顶层值。每次调用创建独立函数帧，不同调用之间不共享参数或局部 `var`。
- **块级作用域**：每个 `if` 语句（从 `if` 行到对应的 `end` 行）和每个 `while` 语句（从 `while` 行到对应的 `end` 行）各自构成一个独立的块级作用域。`then` 与 `else` 各自为互斥子作用域：两侧局部标识符互不可见，但允许分别定义同名局部变量。块内定义的 `var` / `let` 在**离开该块之后**不可访问（见下「变量生命周期」）。嵌套块支持内层屏蔽外层同名标识符（建议避免）。
- **标签作用域**：标签只存在于函数内，遵循与函数局部变量（`var`）和常量（`let`）相同的块级可见性，并额外受函数边界与范式隔离约束：
  - `label` 必须具有 `func` 词法祖先，且 `while` 块内**禁止**定义 `label`（§9.2.4）。合法标签只能出现在函数体直接层级或函数内的 `if` 块（含 `then` / `else` 子块）中。
  - 标签在定义所在的**最内层代码块**内可见。
  - 内部代码块可以引用当前函数外层代码块中的标签（对应“向外跳转”），但查找到函数边界即停止；同一代码块内**禁止**定义同名标签。
  - 不同代码块（如 `then` 分支与 `else` 分支，或不同嵌套层级）允许定义**同名**标签，互不冲突（与 `var` 允许在互斥分支定义同名变量的规则一致）。
  - 每个函数拥有独立标签表，顶层没有标签表。不同函数中的同名标签是独立绑定；其他函数的标签只用于区分“跨控制流域跳转”和“标签未找到”诊断，绝不成为跳转目标。
- **源序可见性**：变量/常量在**定义语句执行之后**才可供同一控制流域的后续语句引用。定义自身的 RHS **不可**引用自身，亦不可引用尚未定义的值标识符。函数签名是例外：全部函数签名在函数体分析前收集，因此函数可以调用定义在其后的函数，但调用图不得形成环。
- **变量生命周期**：
  - 顶层变量：程序启动时建立固定槽位，但不自动写入初值；执行到对应 `var` 后才成为已初始化。程序终止时销毁。
  - 参数：调用帧建立时按形参声明顺序写入并视为已初始化；函数返回时销毁。
  - 函数体直接局部变量：进入函数时建立固定槽位，执行到对应 `var` 时初始化；函数返回时销毁。
  - 局部变量（块内）：进入作用域时为该作用域的全部 `var` 绑定建立固定槽位；执行到对应 `var` 时计算 RHS、写入槽位并成为已初始化。反向跳转或下一次循环迭代重新执行同一 `var` 时，重新初始化同一词法槽，不重复分配。离开该块时统一销毁一次——离开方式包括对应的 `end`、`break` 或向外 `goto`。块内 `let` 随词法作用域结束而不再可见（本身无运行时槽，见 §11.2）。

#### 11.2 变量生命周期与确定初始化

| 阶段 | 行为 |
| ---- | ---- |
| 作用域进入 | 建立本作用域全部 `var` 的固定槽位，初始状态为“未初始化” |
| `var` 执行 | 先检查并计算普通 RHS 或执行非 `void` `funcall` 初始化器，再写入对应槽位；成功后状态变为“已初始化” |
| 赋值 / `read` | 目标变量必须已确定初始化；成功后更新同一槽位，不改变其生命周期 |
| 变量读取 | 该绑定必须在当前 CFG 点上确定初始化，否则静态错误 `TC_ERR_UNINITIALIZED_VARIABLE` |
| 反向跳转 / 下一迭代 | 再次执行 `var` 时重新初始化同一槽位，不创建新绑定或新槽位 |
| 作用域离开 | 因 `end`、`break` 或向外 `goto` 离开时，槽位统一销毁一次 |
| `let` | 编译期求值并内联，不生成运行时槽 |
| 参数 | 函数入口时已初始化，只读；不得赋值或作为 `read` 目标 |
| `return` | 终止当前函数 CFG 路径，销毁当前函数帧及活动块局部槽 |

##### 11.2.1 确定初始化数据流

编译器必须分别为顶层语句区和每个函数建立封闭 CFG。顶层 CFG 处理结构化控制流，不含 `goto` / `label` / `return`；函数 CFG 在同一分析框架中额外处理函数内 `goto` / `label` 与 `return`。不同控制流域不得共享节点、边或数据流状态。设 `IN[n]` 为语句 `n` 执行前确定已初始化的绑定集合，`OUT[n]` 为执行后的集合：

```text
IN[top-level entry] = ∅
IN[function entry]  = 当前函数的全部参数
IN[n]     = ∩ OUT[p]，其中 p 为 n 的全部可达前驱
OUT[var x = rhs] = IN[n] ∪ {x}
OUT[var x = funcall(...)] = IN[n] ∪ {x}  ; 调用成功路径
OUT[其他语句]    = IN[n]
```

- `var x = rhs` 的 RHS 在加入 `x` 之前检查，因此初始化自引用仍非法。
- 任何可达的变量读取、赋值目标或 `read` 目标都要求对应绑定属于当前 `IN`。逻辑短路的右操作数是否可达按 §7.2.2 判定。
- 会合点取可达前驱集合的交集；只有所有可达路径均已初始化才成立。
- 循环按上述传递函数迭代到固定点。
- 可达性在 §4.3 常量求值与静态布尔三态判定完成后确定。若 `if`/`while` 条件按 §4.3 判定为静态 `true` 或静态 `false`，删除不可能边；判定为 `unknown` 时同时保留 `true` 与 `false` 边。CFG 不另行维护运算符白名单。
- 不可达语句不参与可达前驱交集，但仍须通过词法、语法、名称与类型检查。
- `funcall` 在调用者 CFG 中是单个原子节点，不展开被调函数 CFG；被调函数发生运行时错误时程序终止，不形成返回调用者的 CFG 边。
- `return` 节点只连接当前函数的正常返回终止节点；函数末尾节点若从入口可达，触发缺少返回错误。顶层文件末尾是合法程序正常结束，不执行缺少返回检查。
- 分析结果是 0.0.32 的强制语义，不允许实现通过更弱或更强的默认规则改变合法程序集合。

声明时强制 RHS 与确定初始化分析是两个独立保证：前者约束源代码形态，后者证明每次可达使用之前相应初始化语句确已执行。

### 12. 标准 I/O

#### 12.1 `write` — 不换行输出

**形式一：无格式输出**

| 项目       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 语法       | `write(int32, x)`、`write(float64, pi)`、`write(bool, flag)` |
| 功能       | 将操作数的值按类型解释写入 stdout，**不换行**                |
| 操作数规则 | 在当前 CFG 点确定初始化的变量，或字面量                   |
| 类型约束   | 变量类型与 `type` 一致；字面量满足 §3.6 约束                 |
| 输出格式   | 整数：十进制；浮点：与 `%g` 相同的 6 位有效数字；布尔：`true`/`false` |

**形式二：格式化输出**

| 项目       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 语法       | `write(int32, %d, x)`、`write(float64, %f, pi)`、`write(bool, %t, flag)` |
| 功能       | 按格式化符号输出操作数的值，**不换行**                       |
| 操作数规则 | 变量或字面量；**恰好一个**操作数                             |
| 类型约束   | 操作数类型与 `type` 一致，且与格式化符号兼容                 |

#### 12.2 `writeln` — 换行输出

与 `write` 相同，但在输出末尾追加一个 LF 字节（`\n`），不随主机平台改写为其他行结束序列。`write`/`writeln` 向 stdout 写入失败时报 `TC_ERR_IO`。

#### 12.3 `read` — 标准输入

| 项目     | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| 语法     | `read(int32, x)`、`read(float64, radius)`、`read(bool, flag)` |
| 功能     | 从 stdin 读取一个值，**覆盖**已定义变量的当前值              |
| 目标变量 | 必须是已通过带 RHS 的 `var` 声明、在当前 CFG 点确定初始化且类型与 `type` 一致的可写变量；函数参数只读，不得作为目标 |
| 与初始化 | **`read` 不是初始化器**，不能代替 `var … = …` 或补救被控制流绕过的初始化 |
| 输入格式 | 见下表；跳过前导 ASCII 空白，并读取一个以 ASCII 空白或 EOF 结束的完整 Token |
| 错误处理 | 非法输入/数值超范围/非预期 EOF → **I/O 错误**                |

**输入规则**：

| 目标类型            | 输入格式                                      |
| ------------------- | --------------------------------------------- |
| `int*`              | 可选 `-` 前缀 + 连续十进制数字，至少一位      |
| `uint*`             | 连续十进制数字，至少一位；**不接受** `-` 前缀 |
| `float32`/`float64` | 可选 `-` 前缀 + 十进制浮点/科学计数法，或 `inf`/`-inf`/`nan` |
| `bool`              | `true` 或 `false`（大小写敏感，均为小写）     |

本节的 ASCII 空白仅指 U+0009～U+000D 与 U+0020，不受 locale 影响。输入必须完整匹配目标格式；例如 `12abc` 整体非法，不得只接受前缀 `12`。

有限浮点输入先解析为精确十进制数学值，再按 roundTiesToEven 舍入到目标 binary32/binary64；不得先通过另一浮点类型中转。显式 `-0.0` 保留负零符号。非零有限值舍入为零、有限值舍入为无穷，或整数超出目标范围，均报 `TC_ERR_IO`；可表示的非规格化数合法。`nan` 输入生成 §5.3 规定的 canonical quiet NaN。非法 Token 与意外 EOF 同样报 `TC_ERR_IO`。

#### 12.4 格式化符号定义

| 符号 | 含义                     | 适用类型            | 示例（值 42/3.14159265） |
| ---- | ------------------------ | ------------------- | ------------------ |
| `%d` | 有符号十进制             | `int8`～`int64`     | `42`               |
| `%i` | 有符号十进制（同 `%d`）  | `int8`～`int64`     | `42`               |
| `%u` | 无符号十进制             | `uint8`～`uint64`   | `42`               |
| `%x` | 十六进制（小写 a-f）     | 任一整数类型        | `2a`               |
| `%X` | 十六进制（大写 A-F）     | 任一整数类型        | `2A`               |
| `%o` | 八进制                   | 任一整数类型        | `52`               |
| `%b` | 二进制                   | 任一整数类型        | `101010`           |
| `%t` | 布尔值文本               | `bool`              | `true`             |
| `%f` | 浮点十进制（固定小数）   | `float32`/`float64` | `3.141593`         |
| `%e` | 科学计数法（小写 e）     | `float32`/`float64` | `3.141593e+00`     |
| `%E` | 科学计数法（大写 E）     | `float32`/`float64` | `3.141593E+00`     |
| `%g` | 紧凑格式（较短）         | `float32`/`float64` | `3.14159`          |
| `%G` | 紧凑格式（较短，大写 E） | `float32`/`float64` | `3.14159`          |

**确定性格式规则**：

- 格式化不受进程 locale 影响，小数点固定为 `.`。
- `%f`/`%e`/`%E` 固定输出小数点后 6 位；`%g`/`%G` 固定输出 6 位有效数字。
- 十进制输出以源 binary32/binary64 值的精确数学值为输入，按 roundTiesToEven 舍入到所需十进制位数；不得先经过宿主的更低精度类型。
- `%e`/`%E` 在小数点前保留恰好一位非零数字（零值为 `0`），指数始终含 `+` 或 `-`，且至少两位十进制数字。
- `%g`/`%G` 先以 6 位有效数字舍入。设舍入后值的十进制指数为 `e`（即科学计数法中小数点前恰好一位时的指数）：当 `e < -4` 或 `e >= 6` 时使用 `%e`/`%E` 形式，否则使用定点形式。小数部分末尾的 `0` 全部删除；若小数部分为空，同时删除小数点。
- `%d`/`%i` 按有符号数学值输出，`%u` 按无符号数学值输出。
- `%x`/`%X`/`%o`/`%b` 对任意整数输出其固定宽度二进制补码位模式，不带进制前缀。零恰好输出 `0`；其他非负值省略前导零；负值保留足以表示完整类型位宽的全部数字。例如 `int8` 值 `-1` 分别输出 `ff`、`FF`、`377`、`11111111`。
- `%e` 使用小写指数标记，`%E` 使用大写指数标记；`%G` 的指数标记与特殊值使用大写。
- 有限负零保留符号，例如 `%f` 输出 `-0.000000`，`%g` 输出 `-0`。
- 特殊值固定输出 `inf`、`-inf`、`nan`；在 `%E`/`%G` 下输出 `INF`、`-INF`、`NAN`。NaN payload 不通过文本 I/O 暴露。

#### 12.5 类型兼容性

| 符号                             | 可接受操作数类型     |
| -------------------------------- | -------------------- |
| `%d` / `%i`                      | `int8`～`int64`      |
| `%u`                             | `uint8`～`uint64`    |
| `%x` / `%X` / `%o` / `%b`        | 任一整数类型         |
| `%t`                             | `bool`               |
| `%f` / `%e` / `%E` / `%g` / `%G` | `float32`、`float64` |

#### 12.6 格式化输出扩展预留

0.0.32 规范包含 §12.4 所列 **13 种**格式化符号（含 `%f`/`%e`/`%E`/`%g`/`%G`）。以下为后续规范的扩展方向：

> **扩展预留**：
> - `%c`：字符
> - `%s`：字符串
> - `%p`：指针
> - 宽度、精度、左对齐等修饰符（如 `%10.2f`）
>
> 上述符号与修饰符尚未纳入当前语法；使用前须等待对应语言版本发布。

### 13. 诊断与错误处理

遇到 **第一个** 错误即终止程序（fail-fast）。错误按发生阶段分为 **静态**（词法/语法/静态分析）与 **运行时** 两类。

#### 13.1 确定性诊断阶段与初始化错误分工

0.0.32 采用确定的静态处理顺序：

1. 源字节的 UTF-8 解码（文件打开失败属于实现/API 层）；
2. 词法与缩进扫描；
3. 语法解析；
4. 收集全部函数签名；
5. 检查函数重名、签名和名称空间；
6. 检查 `goto` / `label` 的函数上下文，分别解析函数体和顶层的名称与词法作用域，仅为各函数建立标签表和解析 `goto`，并检查普通 RHS 的类型、操作数数量和模式；
7. 检查符合 EBNF 的 `funcall` 之目标、使用位置、实参和接收类型；
8. 检查符合 EBNF 的 `return [operand]` 之位置、形式和返回类型；
9. 求值 `let` 常量；
10. 按 §4.3 执行 `if`/`while` 静态布尔三态判定，并按 §7.2.2 判定逻辑 RHS 读边；
11. 构建和分析唯一顶层 CFG，再分别构建和分析各函数 CFG，执行不可达边裁剪与确定初始化固定点；仅函数 CFG 执行函数末尾检查；
12. 检查函数调用图中的递归环；
13. 生成 VM / AOT 代码。

第 6 阶段建立后续检查所需的作用域和名称环境，但 `funcall` 内部名称与 `return` 操作数必须按第 7、8 阶段的专用优先级协调解析：未定义调用目标会抑制该调用的实参名称错误；调用位置错误会抑制实参错误；返回形式错误会先于返回操作数名称错误。下列专用规则覆盖通用阶段内的源位置顺序。

权威 EBNF 不接受的形式必须在第 3 阶段拒绝，不得为产生后续专用诊断而放宽语法。阶段按顺序完整执行，前一阶段有错时不进入后一阶段。

##### 13.1.1 首个诊断的通用规则

一个程序同时存在多个错误时，唯一首个诊断按以下顺序确定：

1. **阶段优先**：先报告编号较小阶段的错误。
2. **源位置优先**：同一阶段按文件、行、列选择起始位置最早者。
3. **规则优先**：同一位置按本节专用优先级；未专门规定时依次为语法形态/数量、语句上下文、名称存在性、重复、名称空间/作用域/控制流域、使用位置、实参顺序、类型、模式/结构、字面量、CFG、调用图。
4. **关联位置**：重复定义、跨域跳转和递归环使用下文指定的主位置比较；其他位置只作附注。
5. **遍历无关**：函数表、哈希表、CFG、调用图和实参集合的内部遍历顺序不得改变结果。

同一 Token 同时违反普通类型/模式规则时，固定按“操作数数量 → 运算支持的类型类别 → 模式合法性 → `bitcast` 位宽 → 字面量范围/类型 → 格式符与其他操作数类型”选择。紧跟类型参数的 `wrap` / `ieee` / `truncate` 先识别为候选模式位，不算普通操作数；非模式指令写了数量正确的候选模式形式时映射为 `TC_ERR_MODE_MISMATCH`。

非法 UTF-8 映射为 `TC_ERR_SYNTAX`；缩进和语法阶段有专用错误码时优先专用码。`let` RHS 嵌套调用在语法阶段映射为 `TC_ERR_CONSTANT_EXPRESSION`；自引用和前向引用在名称阶段映射为 `TC_ERR_UNDEFINED_VARIABLE`；解析为 `var` 的引用在常量求值阶段映射为 `TC_ERR_CONSTANT_EXPRESSION`。静态布尔判定仅在名称、类型及更早 `let` 求值成功后运行；合法常量形态的求值错误不得降级为 `unknown`。不可达代码仍完成词法、语法、名称和类型检查。

##### 13.1.2 函数签名错误优先级

多个函数定义头有错时选择源位置最早者。同一函数头按以下顺序检查：函数重复定义 → 函数名与顶层值冲突 → 参数重名 → 参数名与全局函数名冲突 → 参数类型非法 → 返回类型非法。

- 重复函数定位到第二次及后续定义的函数名。
- 函数名冲突定位到源位置较后的冲突定义名。
- 参数重名定位到第二次及后续出现的参数名。
- 参数名冲突定位到冲突参数名。
- 类型非法定位到对应类型 Token。

收集全部函数名是本阶段的前提，但诊断不得取决于函数表遍历顺序。

##### 13.1.3 `funcall` 错误优先级

多个调用有错时选择 `funcall` 位置最早的调用。选定调用后依次检查：

1. 目标函数是否存在；不存在时定位到函数名，不再检查实参。
2. 调用位置是否适合返回类型；非 `void` 独立调用或 `void` 用于 `var` 初始化时，定位到 `funcall`，不再检查实参。
3. 实参重复、未知、缺失、顺序、类型，按此顺序检查。
4. 非 `void` 调用接收 `var` 的声明类型；在实参全部合法后检查，错误定位到声明类型 Token。

实参重复定位到第二个重复名称；未知实参定位到最早未知名称；缺失实参定位到右括号并指出声明顺序最靠前的缺失形参；顺序错误定位到第一个名称已知、集合完整但与对应位置形参不同的名称；类型错误定位到最早不匹配操作数。

只有实参名称全部已知、唯一且集合完整时才检查顺序；只有顺序正确后才从左到右检查类型。单个实参先检查名称，再检查类型类别，最后按 §3.6 检查字面量符号性、后缀和范围。合法字面量不能用于形参类型时沿用字面量专用诊断，不降级为笼统实参类型错误。

##### 13.1.4 `return` 错误优先级

多个 `return` 有错时选择关键字位置最早者；同一条依次检查：是否在函数体内 → 有值/无值形式是否匹配 → 返回名称是否合法 → 返回类型是否匹配 → 返回字面量是否合法且可表示。

顶层返回和形式错误定位到 `return`；返回类型错误定位到操作数；未定义或越过函数边界的名称在名称阶段报告；字面量问题沿用专用诊断。

##### 13.1.5 `goto` / `label` 上下文错误优先级

`goto` 与 `label` 必须先检查是否具有 `func` 词法祖先。没有函数祖先时分别报告 `TC_ERR_GOTO_OUTSIDE_FUNCTION` 或 `TC_ERR_LABEL_OUTSIDE_FUNCTION`，定位到关键字；该语句不参与标签表、名称解析或 CFG 构建。

只有确认位于函数体内后，才检查是否具有 `while` 词法祖先；违反时分别报告 `TC_ERR_GOTO_INSIDE_LOOP` 或 `TC_ERR_LABEL_INSIDE_LOOP`。因此，位于顶层 `while` 内的 `goto` / `label` 固定报告“函数外使用”，而不是“循环内使用”。函数内合法上下文中的 `label` 才进入当前函数标签表，函数内合法上下文中的 `goto` 才继续执行标签查找、跨函数判定和块关系检查。

编译器必须先收集全部函数中通过上述上下文检查的标签，再解析任何函数内 `goto`；跨函数诊断不得依赖函数定义顺序、标签表遍历顺序或当前正在分析的函数。

##### 13.1.6 CFG 错误优先级

顶层和全部函数 CFG 构建完成后，CFG 类错误按源位置统一选择，不依赖内部分析顺序。同一位置依次为：函数内非法 `goto` 边/跨控制流域跳转 → `break` / `continue` 位置 → 同一基本块内 `return` 后不可达语句 → 确定初始化 → 缺少返回。

缺少返回定位到函数定义头的返回类型，但与其他 CFG 错误比较源位置时使用该函数体 `end` 的位置；函数内有明确位置的 CFG 错误因此优先。多个函数都缺少返回时选择定义最早者。

##### 13.1.7 递归错误的确定规则

调用图环检查只在更早阶段全部成功后执行。存在多个递归强连通分量时，选择包含源位置最早函数定义的分量，再选择其中源位置最早、指向同分量函数的调用点，在该函数名处报告递归错误。

诊断给出一个确定环路径：从所选调用点的调用者开始，每一步选择源位置最早且仍能回到起点的调用边。自递归定位到自调用函数名。不得由哈希表或图节点自然遍历顺序决定所报告的环。

初始化相关错误按下表严格分工：

| 层次 | 违规形态 | 错误码 | 检查性质 | 规范依据 |
| ---- | -------- | ------ | -------- | -------- |
| **语法层** | `var` 声明缺少 `= <rhs>` | `TC_ERR_VAR_MISSING_INIT` | 纯形态；与控制流无关 | §4.2 |
| **名称层** | 标识符从未声明、尚未源序可见或已超出词法作用域 | `TC_ERR_UNDEFINED_VARIABLE` | 名称解析 | §11.1 |
| **数据流层** | 声明存在，但在可达使用点不满足确定初始化 | `TC_ERR_UNINITIALIZED_VARIABLE` | 完整 CFG 固定点分析 | §11.2、§9.3.4 |

`TC_ERR_VAR_MISSING_INIT` 不得降级为通用语法错误；`TC_ERR_UNINITIALIZED_VARIABLE` 不得替代名称解析错误。0.0.32 不定义 `TC_ERR_GOTO_SKIPS_VAR_INIT`，因为未初始化是跨全部控制流种类的通用性质，不应绑定到单一语句。

#### 13.4 编译警告

TC 语言**无编译警告**（无 `TcWarningKind` 承担初始化或控制流诊断）。

- 声明缺少初始化器 → **错误** `TC_ERR_VAR_MISSING_INIT`（§4.2 / §13.1），不得以警告放行。
- 任一可达路径上的未初始化使用 → **错误** `TC_ERR_UNINITIALIZED_VARIABLE`；不得以警告放行。
- 溢出、类型与其它控制流违规均以错误报告。
- 逻辑短路（§7.2.2）排除的右操作数不触发未初始化错误，但其名称、类型或语法违规仍是静态错误。

#### 13.5 错误码对照表（`TcErrorKind`）

§13.2、§13.3 以**可观测语义**命名错误类型；TC 实现通过 `TcErrorKind` 枚举编码诊断结果。`tc_error_kind_name()` 返回的打印名用于日志与 API 输出。

下表保留 **0.0.31 基线实现**的权威枚举，并加入 0.0.32-rev2 的两个函数边界控制流错误码，共 44 个条目：43 个语言错误码（36 个静态、7 个运行时）与 1 个实现扩展码 `TC_ERR_OUT_OF_MEMORY`。其余 0.0.32 函数诊断类别列于本节表后；其可观察阶段、优先级和合法程序集合属于规范要求，具体 `TcErrorKind` 枚举名在实现设计阶段按现有命名规则对齐。

下表只列出附录 A 已接受的程序形式所需的专用语义诊断；不符合 EBNF 的位置实参、复杂实参、`let`/赋值接收调用、直接返回运算或调用，以及 `void` 出现在非返回类型位置等，统一在语法阶段拒绝。表中类别的触发条件与阶段是权威的；具体枚举名不得通过合并类别而改变诊断优先级或合法程序集合。

| 诊断类别 | 阶段 | 触发条件 |
| --- | --- | --- |
| 函数重复定义 | 函数签名 | 同一文件存在同名函数 |
| 函数名冲突 | 函数签名/名称 | 函数名与顶层值同名，或参数/局部值与全局函数同名 |
| 未定义函数 | `funcall` | 调用目标不存在 |
| 参数重名 | 函数签名 | 同一签名含重复参数名 |
| 实参缺失 | `funcall` | 未为某形参提供实参 |
| 实参重复 | `funcall` | 同一实参名出现多次 |
| 未知实参 | `funcall` | 实参名不属于被调签名 |
| 实参顺序错误 | `funcall` | 文本顺序与形参声明顺序不同 |
| 实参类型错误 | `funcall` | 操作数类型与对应形参不同；字面量专用错误除外 |
| 函数调用位置错误 | `funcall` | 非 `void` 结果被丢弃，或 `void` 调用用于 `var` 初始化 |
| 调用结果类型错误 | `funcall` | 接收 `var` 类型与非 `void` 返回类型不同 |
| 顶层返回错误 | `return` | `return` 位于函数体外 |
| 返回形式错误 | `return` | 有值/无值形式与返回类型不匹配 |
| 返回类型错误 | `return` | 返回操作数类型与声明返回类型不同 |
| 缺少返回 | CFG | 函数末尾节点可达 |

#### 14.15 非结构化循环（`if` + `goto`）

> **设计说明**：非结构化循环只能在函数体内使用 `if` + `goto` 构建，不涉及 `while` 关键字。此范式适用于状态机、复杂退出条件或需要直接从任意深度跳出的场景；顶层只能调用承载该控制流的函数。

**示例 1：`if` + `goto` 模拟 `while` 循环**

> **缩进说明**（§9.3.2）：`label` 不产生新缩进；函数体直接层级的局部语句与 `label loop_start:` 同为函数缩进 1；仅 `if` 子块内的 `goto` 再多一级。

```text
func sum_with_goto() int32 then
    var sum: int32 = 0
    var j: int32 = 1
    label loop_start:
    sum = add(int32, sum, j)
    j = add(int32, j, 1)
    if le(int32, j, 10) then
        goto loop_start
    end
    return sum
end

var sum_goto: int32 = funcall(sum_with_goto)
writeln(int32, %d, sum_goto)          ; 55
```

**示例 2：`if` + `goto` 实现复杂状态机**

```text
func run_state_machine() int32 then
    var state: int32 = 0
    var result: int32 = 1
    label process:
    if eq(int32, state, 0) then
        result = mul(int32, result, 2)
        state = 1
        goto process
    end

    if eq(int32, state, 1) then
        result = add(int32, result, 5)
        state = 2
        goto process
    end

    if eq(int32, state, 2) then
        if lt(int32, result, 100) then
            state = 0
            goto process
        end
    end
    return result
end

var state_result: int32 = funcall(run_state_machine)
writeln(int32, %d, state_result) ; 最终结果 ≥ 100
```

#### 14.18 综合示例：浮点位模式哈希

浮点类型 **不支持** 位运算（§6）。位级混合须先将浮点按位重解释为整数，再使用整数 `xor`：

```text
; 浮点位模式哈希：bitcast 等宽重解释 → 整数 xor
var f1: float32 = 3.14f
var f2: float32 = 2.71f
var f3: float32 = 1.41f

var bits1: uint32 = bitcast(uint32, f1)
var bits2: uint32 = bitcast(uint32, f2)
var bits3: uint32 = bitcast(uint32, f3)

var hash: uint32 = xor(uint32, bits1, bits2)
hash = xor(uint32, hash, bits3)

writeln(uint32, %X, hash)
```

浮点类型不提供 `wrap`。所有位级混合都必须显式 `bitcast` 为等宽整数后完成；需要恢复浮点解释时再 `bitcast` 回原位宽浮点类型。

```text
; ============================================================

var bits: uint32 = bitcast(uint32, f_repr)  ; 0xBF800000
var pi_from_bits: float32 = bitcast(float32, 0x40490FDBu)  ; 3.1415927

; ============================================================
; 布尔与整数/浮点互转
; ============================================================
var flag_bool: bool = cast(bool, a)         ; true
var as_int: int32 = cast(int32, is_equal)   ; 0
var as_float: float64 = cast(float64, flag_bool)  ; 1.0

; ============================================================
; I/O
; ============================================================
write(int32, %d, sum)                      ; "30"
writeln(int32, %d, SCALED_BASE)            ; "3000\n"
writeln(bool, %t, is_less)                 ; "true\n"
writeln(float64, %f, PI)                   ; "3.141593\n"
writeln(float64, %e, PI)                   ; "3.141593e+00\n"

; ============================================================
; 函数调用
; ============================================================
var incremented: int32 = funcall(increment, value: sum)
funcall(show_value, value: incremented)
```

> **范式说明**：上述两种循环方式在 TC 中属于**互斥范式**。顶层使用结构化 `while`；非结构化循环封装在 `sum_with_goto` 函数中。`goto` / `label` 只能位于函数体内，且函数内的 `while` 块仍严禁出现二者。两种范式均纳入 §11.2 的完整确定初始化分析。

### 附录 A：形式化语法（EBNF）

本附录为 TC 语言的 **权威语法定义**。语义规则以正文为准。

#### A.1 符号约定

采用 **扩展巴科斯-瑙尔范式（EBNF）**：

| 元符号   | 含义              |
| -------- | ----------------- |
| `=`      | 产生式定义        |
| `\|`     | 择一              |
| `[ … ]`  | 可选（0 或 1 次） |
| `{ … }`  | 重复（0 或多次）  |
| `( … )`  | 分组              |
| `"…"`    | 终结符            |
| `"a" … "z"` | 包含两端的字符范围 |
| `? … ?`  | 用自然语言描述的词法特殊序列 |
| *斜体名* | 非终结符          |

#### A.2 词法与缩进 Token

词法分析先按最长匹配生成 Token，再将完整标识符与关键字表比较。`varx` 因而是一个 `IDENTIFIER`，绝不能拆成 `VAR` + `IDENTIFIER`。除行首缩进外，Token 间的空格和制表符由词法层丢弃；语法层不使用可匹配零字符的 `ws` 充当关键字边界。

```ebnf
/* ── 基本字符类 ── */

letter     = "A" … "Z" | "a" … "z" | "_" ;
digit      = "0" … "9" ;
hex_digit  = digit | "A" … "F" | "a" … "f" ;

/* ── 标识符与字面量 ── */

identifier = letter , { letter | digit | "_" } ;

integer_literal
           = ( "-" , (
               dec_literal
             | hex_literal
             | bin_literal
             | oct_literal
           ) )
           | (
               dec_literal [ "u" | "U" ]
             | hex_literal [ "u" | "U" ]
             | bin_literal [ "u" | "U" ]
             | oct_literal [ "u" | "U" ]
           ) ;
/* 负号仅可与无后缀字面量组合；禁止 -42u 等形式（§2.3.1） */

float_literal = [ "-" ] , (
    dec_float_literal [ ( "e" | "E" ) , [ "+" | "-" ] , digit , { digit } ]
  | sci_int_float_literal
) , [ "f" | "F" ] ;

dec_float_literal = digit , { digit } , "." , digit , { digit } ;
sci_int_float_literal
           = digit , { digit } , ( "e" | "E" ) , [ "+" | "-" ] ,
             digit , { digit } ;
/* 允许 1e5 等无小数点的科学计数法（§2.4.2）；亦允许 1.2e5 */

float_special = "inf" | "-" , "inf" | "nan" ;
/* -inf 合法；-nan 非法 */

bool_literal = "true" | "false" ;

dec_literal = non_zero_digit , { [ "_" ] digit } | "0" ;
hex_literal = ( "0x" | "0X" ) , hex_digit , { [ "_" ] hex_digit } ;
bin_literal = ( "0b" | "0B" ) , ( "0" | "1" ) , { [ "_" ] ( "0" | "1" ) } ;
oct_literal = ( "0o" | "0O" ) , ( "0" … "7" ) , { [ "_" ] ( "0" … "7" ) } ;
non_zero_digit = "1" … "9" ;

/* ── 类型关键字 ── */

int_type   = "int8"   | "uint8"
           | "int16"  | "uint16"
           | "int32"  | "uint32"
           | "int64"  | "uint64" ;
float_type = "float32" | "float64" ;
bool_type  = "bool" ;
type       = int_type | float_type | bool_type ;
value_type = type ;
return_type = value_type | "void" ;

/* ── 运算与模式关键字 ── */

binary_arith_op = "add" | "sub" | "mul" | "div" | "mod" ;
unary_arith_op  = "abs" | "neg" ;
bitwise_op      = "and" | "or" | "xor" ;
unary_bitwise_op = "not" ;
shift_op        = "shl" | "shr" ;
compare_op = "eq" | "ne" | "lt" | "le" | "gt" | "ge" ;
mode = "ieee" | "wrap" ;  /* 严格模式：无关键字（默认） */
truncate_kw = "truncate" ;
bitcast_kw  = "bitcast" ;

/* ── 格式化符号 ── */

format_specifier
           = "%d" | "%i" | "%u" | "%x" | "%X" | "%o" | "%b" | "%t"
           | "%f" | "%e" | "%E" | "%g" | "%G" ;

/* ── 控制流关键字 ── */
if_kw      = "if" ;
then_kw    = "then" ;
else_kw    = "else" ;
end_kw     = "end" ;
while_kw   = "while" ;
break_kw   = "break" ;
continue_kw = "continue" ;
goto_kw    = "goto" ;
label_kw   = "label" ;
func_kw    = "func" ;
funcall_kw = "funcall" ;
return_kw  = "return" ;
void_kw    = "void" ;

/* ── 注释 ── */

line_comment = ";" , { ? any character except newline ? } ;
```

**缩进 Token 化规则**：

1. 词法器维护缩进宽度栈，初始仅含顶层宽度 `0`。
2. 每个非空、非纯注释逻辑行开始时，将其缩进与栈顶比较：增加时必须恰好增加一级，压栈并生成一个 `INDENT`；一次增加多级为缩进错误。减少时逐项出栈并为每次出栈生成一个 `DEDENT`。减少后的宽度必须等于某个既有栈值，否则为缩进错误。
3. 一级缩进恒为 4 个空格或 1 个制表符；同一文件二者不可混用，每级宽度不可变化。
4. 空行和纯注释行只生成 `NEWLINE`，不改变缩进栈；它们的行首空白不参与缩进风格或宽度检查。
5. LF（`\n`）、CRLF（`\r\n`）或 CR（`\r`）均表示一个逻辑行结束，并生成一个 `NEWLINE`；文件结尾先补最后一个 `NEWLINE`（若缺少），再生成剩余 `DEDENT`，最后生成 `EOF`。
6. `INDENT`/`DEDENT` 只反映 `func`/`if`/`else`/`while` 语句体的实际缩进；合法的函数内 `label` 是普通语句，不改变缩进栈。
7. 空格/制表符混用报 `TC_ERR_INDENT_MIXED`；`else`/`end` 与对应 `func`/`if`/`while` 块头不对齐报 `TC_ERR_INDENT_ELSE_END`；其他违反上述缩进层级/栈规则的情形报 `TC_ERR_INDENT_INSUFFICIENT`。

#### A.3 语法

本节作用于 A.2 输出的 Token 序列。`NEWLINE`、`INDENT`、`DEDENT`、`EOF` 是虚拟终结符；`identifier`、`integer_literal` 等名称引用 A.2 的完整 Token 类别。引号中的关键字或标点表示一个完整 Token，不是字符子串匹配。非行首空白与行末注释已由词法层移除。

本 EBNF 同时规定函数语法诊断边界。位置实参、非 `operand` 实参、作为 `let` 或赋值 RHS 的 `funcall`、`return` 后的运算/转换/`funcall`，以及 `void` 出现在函数返回类型以外的位置，均必须在语法阶段拒绝。`var_funcall_def`、独立 `funcall` 和 `return [operand]` 的返回类型适配属于后续静态语义。`statement` 产生式复用 `label_def` / `goto_stmt` 只表示其行内语法；二者必须具有 `func` 词法祖先的上下文约束由 §9.3 和 §13.1.5 在静态语义阶段强制执行。

```ebnf
/* ── 程序 ── */

program    = { NEWLINE | function_definition , NEWLINE } ,
             top_level_program , EOF ;

top_level_program
           = { NEWLINE | statement , NEWLINE } ;
/* function_definition 一旦结束，顶层语句区不再允许再次定义函数。 */

statement  = simple_statement
           | if_stmt
           | while_stmt ;

simple_statement
           = variable_def
           | constant_def
           | assignment
           | write_stmt
           | writeln_stmt
           | read_stmt
           | break_stmt
           | continue_stmt
           | label_def
           | goto_stmt
           | var_funcall_def
           | void_funcall_stmt
           | return_stmt ;
/* label_def / goto_stmt 出现在 top_level_program 或其嵌套 suite 中时，
   分别报 TC_ERR_LABEL_OUTSIDE_FUNCTION / TC_ERR_GOTO_OUTSIDE_FUNCTION。 */

/* ── 函数定义 ── */

function_definition
           = "func" , identifier , "(" , [ parameter_list ] , ")" ,
             return_type , "then" , NEWLINE , suite , "end" ;

parameter_list
           = parameter , { "," , parameter } ;

parameter  = identifier , ":" , value_type ;

return_stmt
           = "return" , [ operand ] ;

/* function_definition 不是 statement，因此不能嵌套在函数体、
   if / else 或 while 内；本语法没有匿名代码块产生式。 */

/* ── 函数调用 ── */

funcall    = "funcall" , "(" , identifier ,
             { "," , named_argument } , ")" ;

named_argument
           = identifier , ":" , operand ;

var_funcall_def
           = "var" , identifier , ":" , value_type , "=" , funcall ;

void_funcall_stmt
           = funcall ;

/* 命名实参必须与形参一一对应，文本顺序完全一致；第 i 个形参的
   value_type 是第 i 个实参 operand 的唯一期望类型。
   var_funcall_def / void_funcall_stmt 的合法性由实际返回类型筛选。 */

/* ── 变量定义（声明时必须初始化；无可选 RHS） ── */

variable_def = "var" , identifier , ":" , type , "=" , rhs ;

/* ── 常量定义 ── */

constant_def = "let" , identifier , ":" , type , "=" , const_rhs ;

/* ── 赋值语句 ── */

assignment = identifier , "=" , rhs ;

/* ── if 语句（缩进敏感，end 必须） ── */

if_stmt    = "if" , rhs , "then" , NEWLINE , suite ,
             [ "else" , NEWLINE , suite ] ,
             "end" ;

/* ── while 语句（缩进敏感，end 必须） ── */

while_stmt = "while" , rhs , "then" , NEWLINE , suite ,
             "end" ;

/* ── break / continue 语句 ── */

break_stmt = "break" ;
continue_stmt = "continue" ;

suite      = { NEWLINE } , [ INDENT , block , DEDENT ] ;
block      = statement , NEWLINE ,
             { NEWLINE | statement , NEWLINE } ;
/* suite 不含 INDENT 时表示零条语句的空块；缩进约束见 §9.1.2 */

/* ── label 与 goto 语句 ── */

label_def  = "label" , identifier , ":" ;
/* 仅函数内合法；label 不产生新缩进；同级后续语句与 label 缩进一致，
   见 §9.1.2 R7、§9.3.2。 */
goto_stmt  = "goto" , identifier ;
/* 仅函数内合法，且目标标签必须属于当前函数。 */

/* ── 右值表达式 ── */

rhs        = identifier
           | integer_literal
           | float_literal
           | float_special
           | bool_literal
           | binary_arith_expr
           | unary_arith_expr
           | bitwise_expr
           | unary_bitwise_expr
           | shift_expr
           | compare_expr
           | binary_logic_expr
           | unary_logic_expr
           | cast_expr
           | bitcast_expr ;

/* ── 常量右值表达式 ── */

const_rhs  = integer_literal
           | float_literal
           | float_special
           | bool_literal
           | identifier
           | const_binary_arith_expr
           | const_unary_arith_expr
           | const_bitwise_expr
           | const_unary_bitwise_expr
           | const_shift_expr
           | const_compare_expr
           | const_binary_logic_expr
           | const_unary_logic_expr
           | const_cast_expr
           | const_bitcast_expr ;

/* ── 常量表达式（只允许单层调用） ── */

const_binary_arith_expr
           = binary_arith_op , "(" , type , "," ,
             [ mode , "," ] , const_operand , "," , const_operand , ")" ;

const_unary_arith_expr
           = unary_arith_op , "(" , type , "," ,
             [ mode , "," ] , const_operand , ")" ;

/* ── 常量位运算表达式 ── */

const_bitwise_expr
           = bitwise_op , "(" , int_type , "," ,
             const_operand , "," , const_operand , ")" ;

const_unary_bitwise_expr
           = "not" , "(" , int_type , "," , const_operand , ")" ;

const_shift_expr
           = shift_op , "(" , int_type , "," ,
             [ mode , "," ] , const_operand , "," , const_operand , ")" ;

/* ── 常量比较表达式 ── */

const_compare_expr
           = compare_op , "(" , ( int_type | float_type ) , "," ,
             const_operand , "," , const_operand , ")" ;

/* ── 常量逻辑表达式 ── */

const_binary_logic_expr
           = binary_logic_op , "(" , bool_type , "," ,
             const_operand , "," , const_operand , ")" ;

const_unary_logic_expr
           = "not" , "(" , bool_type , "," , const_operand , ")" ;

/* ── 常量转换表达式 ── */

const_cast_expr
           = "cast" , "(" , type , "," , const_operand , ")"
           | "cast" , "(" , int_type , "," , "truncate" , "," ,
             const_operand , ")" ;

const_bitcast_expr
           = "bitcast" , "(" , type , "," , const_operand , ")" ;

/* ── 常量操作数 ── */

const_operand
           = integer_literal
           | float_literal
           | float_special
           | bool_literal
           | identifier ;

/* ── 操作数 ── */

operand    = identifier | integer_literal | float_literal | float_special | bool_literal ;

/* ── 双目算术表达式 ── */

binary_arith_expr
           = strict_binary_arith_expr
           | mode_binary_arith_expr ;

strict_binary_arith_expr
           = binary_arith_op , "(" , type , "," ,
             operand , "," , operand , ")" ;

mode_binary_arith_expr
           = binary_arith_op , "(" , type , "," , mode , "," ,
             operand , "," , operand , ")" ;

/* ── 单目算术表达式 ── */

unary_arith_expr
           = strict_unary_arith_expr
           | mode_unary_arith_expr ;

strict_unary_arith_expr
           = unary_arith_op , "(" , type , "," , operand , ")" ;

mode_unary_arith_expr
           = unary_arith_op , "(" , type , "," , mode , "," ,
             operand , ")" ;

/* ── 按位逻辑表达式（仅整数） ── */

bitwise_expr
           = bitwise_op , "(" , int_type , "," ,
             operand , "," , operand , ")" ;

unary_bitwise_expr
           = "not" , "(" , int_type , "," , operand , ")" ;

/* ── 移位表达式（仅整数） ── */

shift_expr
           = strict_shift_expr
           | wrap_shift_expr ;

strict_shift_expr
           = shift_op , "(" , int_type , "," ,
             operand , "," , operand , ")" ;

wrap_shift_expr
           = "shl" , "(" , int_type , "," , "wrap" , "," ,
             operand , "," , operand , ")" ;

/* ── 比较表达式（不支持 ieee 模式） ── */

compare_expr
           = compare_op , "(" , ( int_type | float_type ) , "," ,
             operand , "," , operand , ")" ;

/* ── 双目逻辑表达式（布尔） ── */

binary_logic_expr
           = binary_logic_op , "(" , bool_type , "," ,
             operand , "," , operand , ")" ;

binary_logic_op = "and" | "or" ;

/* ── 单目逻辑表达式（布尔） ── */

unary_logic_expr
           = "not" , "(" , bool_type , "," , operand , ")" ;

/* ── 类型转换表达式 ── */

cast_expr  = strict_cast_expr | truncate_cast_expr ;

strict_cast_expr
           = "cast" , "(" , type , "," , operand , ")" ;

truncate_cast_expr
           = "cast" , "(" , int_type , "," , "truncate" , "," ,
             operand , ")" ;

bitcast_expr
           = "bitcast" , "(" , type , "," , operand , ")" ;

/* 所有运算类型/模式组合均受 §5.1 权威矩阵约束。
   truncate 仅允许整数窄化；bitcast 要求等位宽且两端非 bool（§8）。 */

/* ── I/O 语句 ── */

write_stmt = "write" , "(" , type , "," , operand , ")"
           | "write" , "(" , type , "," , format_specifier , "," ,
             operand , ")" ;

writeln_stmt = "writeln" , "(" , type , "," , operand , ")"
             | "writeln" , "(" , type , "," , format_specifier , "," ,
               operand , ")" ;

read_stmt  = "read" , "(" , type , "," , identifier , ")" ;
```

| 十六进制小写 | `write(uint32, %x, x)` | `printf("%x", x)`  |
| 十六进制大写 | `write(uint32, %X, x)` | `printf("%X", x)`  |
| 八进制       | `write(uint32, %o, x)` | `printf("%o", x)`  |
| 二进制       | `write(uint32, %b, x)` | 无标准等价（扩展） |
| 布尔输出     | `write(bool, %t, x)`   | 无标准等价（扩展） |

**主要差异**：
- TC 严格模式下有符号溢出报错（C 为 UB）
- TC `div(INT_MIN, −1)` 报整数溢出错误（C 为 UB；Java/C# 将 `div` 定义为 `INT_MIN`）
- TC `cast` 对所有整数窄化和符号性变换做可表示性检查；C 的对应转换可能为实现定义行为
- TC **声明时必须初始化**（`var … = …`；缺省 → `TC_ERR_VAR_MISSING_INIT`，§4.2）。此外，编译器必须在完整 CFG 上证明每次变量读取前都已执行其当前生命周期的初始化；否则报 `TC_ERR_UNINITIALIZED_VARIABLE`。`goto` 跳过但未读取某变量本身不构成错误。C 读取未初始化对象可产生未定义行为
- TC 二进制 `%b` 和布尔 `%t` 为扩展格式
- TC 比较运算返回 `bool`（C 中比较返回 `int`）
- TC 逻辑运算严格操作 `bool`（C 中逻辑运算接受任意标量类型）
- TC 右移有符号固定算术右移，C 为实现定义

#### B.2 `let` 常量与 C 语言 `const` 语义对照

| 特性               | TC `let`     | C `const`    | 说明                    |
| ------------------ | ------------ | ------------ | ----------------------- |
| 编译期求值         | ✅ 必须       | ❌ 不要求     | TC `let` 保证编译期求值 |
| 运行时存储         | ❌ 不分配     | 通常分配     | TC 常量不生成运行时数据 |
| 可用于数组大小     | 未来扩展     | ✅            | TC 预留，未来数组将支持 |
| 地址可取值         | ❌ 不可取     | ✅ 可取       | TC 常量无运行时地址     |
| RHS 可为算术表达式 | ✅            | ✅            | TC 常量支持编译期算术   |
| 溢出检查           | ✅ 编译期报错 | ❌ UB         | TC 在编译期捕获常量溢出 |
| 优化器可推导       | ✅ 恒为常量   | ⚠️ 视实现而定 | TC 语义保证             |

| 特性           | TC `let`                | C++ `constexpr` |
| -------------- | ----------------------- | --------------- |

#### B.4 0.0.32 函数与控制流边界

- 顶层语句区仍是程序入口，但只允许结构化控制流；顶层以及顶层嵌套块不得出现 `goto` 或 `label`。
- `goto` 与 `label` 只能出现在函数体内。每个函数独立建立标签表，跳转目标必须位于当前函数并满足 §9.3 的块关系规则。
- 顶层 CFG 不建立标签表或 `goto` 边；函数 CFG 独立处理其函数内标签、跳转、确定初始化和返回路径。
- 需要非结构化控制流的程序应把对应逻辑封装进函数，并由顶层通过 `funcall` 显式启动；TC 不引入特殊 `main` 或隐式函数调用。
- 函数内 `while` 继续禁止 `goto` / `label`，结构化循环与非结构化循环的范式隔离保持不变。

### 附录 E：函数一致性验收清单

本附录规定 0.0.32-rev2 函数实现的最低一致性覆盖。它不新增正文语义；若本清单与正文或附录 A 冲突，以正文和附录 A 为准。

#### E.1 应编译并正确执行

- 函数体直接语句比 `func` 行恰好多一级，嵌套 `if` / `else` / `while` 逐级恰好多一级；
- 零参数、单参数、多参数函数，以及全部现有值类型的参数和返回值；
- 命名实参按形参声明顺序传递；
- 各整数形参为对应整数字面量提供期望类型，覆盖有符号、无符号和范围边界；
- `float32` / `float64` 形参中普通浮点字面量的后缀检查，以及浮点特殊值的期望类型检查；
- 复杂实参先写入临时 `var`，`funcall` 实参只使用 `operand`；
- 非 `void` 返回值初始化顶层或函数局部新 `var`；
- 非 `void` 函数返回标识符或匹配返回类型的字面量；运算/转换结果先写入局部 `var` 再返回；
- `void` 函数作为独立语句调用；
- 多分支全路径显式返回，以及不存在可达函数末尾边的恒真 `while` 或受限 `goto` 循环；
- 参数作为每个函数 CFG 的唯一入口已初始化集合，顶层 CFG 入口集合为空；
- 顶层 `var` 与函数局部绑定的可达性和已初始化状态互不影响；
- 静态恒假分支、函数内无条件 `goto` 跨过的代码和无出口循环之后的代码，不因 CFG 不可达本身报错；
- `funcall` 在调用者 CFG 中保持单节点，被调函数 CFG 不内联；
- 顶层调用函数、函数调用另一函数时，调用图记录关系，但不同调用域的 CFG 间没有 CFG 边；
- 白盒检查证明顶层 CFG 与各函数 CFG 不共享节点、边、可达性、已初始化集合或固定点状态；
- 白盒检查证明顶层不建立标签表，也不存在 `goto` 边；
- 函数之间的无环调用链；
- 函数内符合 §9.3 的同作用域或向外 `goto`；
- 顶层通过 `funcall` 调用包含合法 `goto` / `label` 的函数；
- 不同函数存在同名标签时，各自 `goto` 只解析当前函数的标签；
- VM 与 AOT 的可观察结果一致。

#### E.2 应在语法阶段拒绝

- 函数体直接语句与 `func` 对齐或一次跨越两个及以上缩进级别；嵌套块同理；
- 嵌套函数、顶层语句之后的函数定义，以及脱离 `func` / `if` / `while` 的匿名代码块；
- 位置实参、嵌套 `funcall`，或以算术、位、比较、逻辑、转换 RHS 直接作为实参；
- `let` 或已有变量接收函数返回值，以及 `funcall` 出现在其他 RHS 位置；
- `return` 后直接使用算术、位、比较、逻辑、转换或 `funcall`；
- `void` 出现在函数返回类型之外的类型位置。

#### E.3 应在静态语义阶段拒绝

- 函数重名、形参重名和名称空间冲突；
- 未定义函数；
- 实参缺失、重复、未知、顺序错误或类型不同；
- 实参整数字面量符号性/范围不符，或普通浮点字面量后缀类型与形参不同；
- 非 `void` 返回值被独立调用丢弃，或 `void` 调用用于值位置；
- 顶层 `return`、错误返回形式、错误返回类型和可达函数末尾；
- 同一基本块内无条件 `return` 之后仍出现普通语句；
- 参数赋值、将参数作为 `read` 目标或屏蔽参数；
- 函数体访问顶层值绑定；
- 顶层直接或在任意嵌套块内使用 `goto` / `label`，分别映射为 `TC_ERR_GOTO_OUTSIDE_FUNCTION` / `TC_ERR_LABEL_OUTSIDE_FUNCTION`；顶层 `while` 内的使用也优先映射为这两个函数外错误；
- 函数内 `goto` 试图解析另一函数的标签；
- 当前函数无同名标签但另一函数存在时的跨域跳转，以及所有函数均无标签时的标签未找到；
- 直接或间接递归。
