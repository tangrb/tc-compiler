## 2. P1：诊断确定性仍需补齐

### TC46-DR-023：同一初始化器的多个依赖同时失败时，CT 首诊顺序仍不确定

**位置**：§3.10、§4.10、§12.1、§12.2。

**现行条款**：

- CT 以 `module_order` 和模块内源序为启动顺序；
- 引用 `Self.K`/`m.K` 时按需递归求值并缓存结果；
- 失败归属于目标声明，引用处不产生级联诊断；
- 按需求值过程中遇到的第一个失败即为首个 CT 诊断；
- 依赖求值可以把目标模块提前，启动顺序只在无依赖时决定先后。

**问题**：

规范没有规定**单个初始化器内多个常量引用的遍历顺序**。例如：

```tc
const K: int32 = add int32, m.A, n.B
```

若 `m.A` 与 `n.B` 的初始化器都含 CT 错误：

- 先求值 `m.A`，首个诊断位于模块 `m`；
- 先求值 `n.B`，首个诊断位于模块 `n`。

“遇到的第一个失败”只有在引用遍历顺序确定后才具有唯一含义。§12.2 的同模块源序规则处理的是诊断位置排序，不能替代不同模块依赖的求值顺序；§4.10 的“启动顺序只在无依赖时决定先后”也没有解决一个初始化器同时具有多个依赖的情况。

**影响**：

不同的合理实现可以按左到右、右到左或模块顺序遍历依赖，从而对同一程序报告不同首个诊断，仍不满足确定性首诊目标。

**建议**：

在 §4.10 增加规范性规则：

> 初始化器中的常量引用按源文法从左到右依次递归求值；首个失败后立即停止，其余引用不再求值。命名 `make` 字段也按其在初始化器中的书写顺序处理。

同时明确该顺序只决定依赖求值，不改变 §3.10 先完成名称/类型检查、再进入 CT 求值的阶段划分。

**验收用例**：

1. `add int32, m.A, n.B` 中两个依赖均失败，必须始终报告左侧依赖的首个错误；
2. 交换两个操作数后，首个诊断相应改变；
3. `make S, x: m.A, y: n.B` 中多个字段依赖均失败，按初始化器书写顺序选择；
4. 首个依赖失败后，不得继续求值后续依赖或产生级联诊断；
5. 钻石依赖中同一失败常量只缓存和报告一次。

## 3. P2：浮点转换表述仍需收紧

### TC46-DR-024：异类型 NaN 条款中的 `bitcast` 建议与等宽约束冲突

**位置**：§6.6.1、§6.6.2。

**现行条款**：

- 同类型 `cast` 保留全部位模式，包括 NaN payload；
- 异类型浮点 `cast` 将 NaN 规范化为 canonical quiet NaN；
- 异类型规则随后写道“需要保留 payload 用 `bitcast`”；
- `bitcast` 要求源类型与目标类型等宽。

**问题**：

本语言不同的浮点类型只有 `float32` 和 `float64`，二者宽度不同。因此，异类型浮点转换不能使用 `bitcast`：它必然违反 §6.6.2 的等宽要求，并应报 `TC_CE_BITCAST_WIDTH`。

异类型 NaN 的规范化结果本身已经明确，但“需要保留 payload 用 `bitcast`”指向了一条在该上下文中不合法的指令。

**建议**：

删除异类型规则后的 `bitcast` 建议，或改为：

> 异类型浮点 `cast` 不保留 NaN payload；同类型需要保留位模式时，使用 `copy`、同类型 `cast` 或等宽 `bitcast`。

不要暗示 `bitcast` 可以完成 `float32 ↔ float64` 的 payload 保留转换。

**验收用例**：

1. 同类型 `cast` 和 `bitcast` 均保留 NaN 位模式；
2. `float32 → float64` 与 `float64 → float32` 的 `cast` 均返回 canonical quiet NaN；
3. `float32 ↔ float64` 的 `bitcast` 继续报 `TC_CE_BITCAST_WIDTH`；
4. 修订后的正文不再为异类型转换推荐非法的 `bitcast`。

## 4. 建议处理顺序与关闭条件

### 第一步：关闭 CT 首诊确定性缺口

修订 TC46-DR-023，明确初始化器内引用从左到右的求值顺序，并使用多依赖同时失败的用例验证首个诊断。

### 第二步：删除不可能的转换建议

修订 TC46-DR-024，使异类型 NaN 规范化规则与 `bitcast` 等宽约束一致。

### 建议关闭条件

- 两项条款均完成正文修订，并重新核对 §3.10、§4.10、§6.6、§12.2 的交叉引用；
- CT 验收覆盖操作数交换、命名 `make`、失败缓存、钻石依赖和级联抑制；
- 浮点验收覆盖同类型 payload 保留、异类型规范化和异宽 `bitcast` 诊断；
- 文本关闭与实现/测试关闭分别记录，不以文档修订替代回归测试证据。
