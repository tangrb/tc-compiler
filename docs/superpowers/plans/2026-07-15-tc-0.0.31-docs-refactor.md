# TC 0.0.31 配套文档重构 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 `docs/` 中除两份语言标准外的六份文档重构为职责分层、版本边界明确、可指导 TC 0.0.31 实现且不误报当前能力的文档集。

**Architecture:** 三份设计说明书采用 0.0.31 目标架构视角，两份使用参考保留 v0.0.26 当前行为，合规报告同时维护 v0.0.26 证据与 0.0.31 差距。六份文档共享同一状态词汇、规范链接和验收口径，但不复制语言标准正文。

**Tech Stack:** Markdown、TC 0.0.31 语言标准、当前 C99/libtc/TC-VM/TC-AOT v0.0.26 源码与测试脚本、`rg`、Git。

## Global Constraints

- 唯一 0.0.31 规范来源是 `docs/TC语言标准设计说明书_0.0.31.md`。
- 不修改 `docs/TC语言标准设计说明书.md` 和 `docs/TC语言标准设计说明书_0.0.31.md`。
- 不修改源代码、测试、README、AGENTS 或 `.cursor` 文件。
- 设计文档描述 0.0.31 目标设计，并同时标明当前实现基线 v0.0.26。
- CLI 与 API 参考只把 v0.0.26 已存在行为写成当前能力；0.0.31 新能力只能标为规划或待实现。
- 合规报告保留 v0.0.26 历史证据，但不得使用这些数字证明 0.0.31 合规。
- 0.0.31 规范链接统一指向 `TC语言标准设计说明书_0.0.31.md`。
- 不存在的开发计划或已删除标准快照不得作为依赖链接。
- TC 0.0.31 的关键闭环包括：强制 `var` 初始化、`while`/`break`/`continue`、范式隔离、完整 CFG 确定初始化、严格 `cast`、整数窄化 `truncate`、等宽 `bitcast`、删除浮点 `wrap`、逐操作浮点精度、非嵌套 `let`、42 项错误码清单、REPL 非规范边界。
