# TC 语言标准设计说明书

> **版本**：0.0.35
> **作者**：唐荣兵（[yanhuang8923@qq.com](mailto:yanhuang8923@qq.com)）

本文档是 TC **语言**的规范性定义：词法与语法、静态语义、抽象机执行语义，以及由此决定的可观察行为。确定性编译管线、多错误时的首诊选择算法、CFG/调用图求解步骤与完整错误码阶段表不属于本文档。

---

## 1. 概述与设计原则

### 1.1 语言定位

TC 是为 教学、AI 自动化编程与人类阅读 而设计的指令式编程语言。执行模型采用 伪汇编风格 的逐条执行：每条语句至多包含 一个 运算或转换调用，不支持 表达式嵌套，从而将程序的每一步计算都显式化为独立的、可逐行推理的原子操作。

TC 的五项核心定位：

| 定位 | 说明 |
| ---- | ---- |
| **教学友好** | 伪汇编执行模型、显式类型系统与强制缩进使学习者能逐条跟踪程序状态；零隐式转换和零未定义行为让每一步语义均可唯一推断，降低概念过载 |
| **AI 自动化编程友好** | 命名实参、声明时强制初始化、单层表达式、禁止递归和完备的静态诊断体系，使 AI 生成代码的语义空间高度约束，排除了运算符优先级歧义、隐式转换误匹配、未初始化读取和嵌套陷阱等 AI 常犯错误类别 |
| **人类阅读友好** | 不考虑人类编码体验，以最大阅读清晰度为目标：显式类型标注、运算函数化、命名形参和关键字块结构使代码自文档化；阅读者无需推断隐式转换、运算符优先级、块边界或函数调用目标 |
| **安全计算** | 默认 strict 模式检测整数溢出与浮点异常；完整的确定初始化分析杜绝未初始化读取；`cast`/`bitcast` 显式分类杜绝隐式位丢失；零未定义行为 |
| **可靠计算** | VM 与 AOT 共享同一抽象机语义，给定相同输入必得相同输出；浮点规则与 IEEE 754-2019 精准对齐；as-if 规则保证优化不改变可观察行为；所有合法程序的行为完全确定 |

0.0.35 的能力边界如下：

| 类别 | 当前定义 |
| ---- | -------- |
| 类型 | 8 种固定宽度整数（`int8`～`uint64`）、`float32`、`float64`、`bool`（固定 1 字节，规范位 `0x00`/`0x01`）、`memblock<T>`（纯内存块；仅由元素类型 `T` 参数化，**无长度概念**，见 §3.8；`load`/`store`/`copy` 见 §6.7）、`struct` 用户结构体（值类型；默认紧密布局，可选 `@padding(N)`；字段 `let`/`var` 可变性见 §3.9）；`void` 仅表示函数无返回值 |
| 算术 | `add`、`sub`、`mul`、`div`、`mod`、`abs`、`neg`；整数与浮点均支持，浮点 `mod` 的商向零截断 |
| 位与逻辑 | 整数按位 `and`/`or`/`xor`/`not` 和 `shl`/`shr`；布尔逻辑 `and`/`or`/`xor`/`not`；由首个类型参数区分重载 |
| 比较 | `eq`、`ne`、`lt`、`le`、`gt`、`ge`，支持整数和浮点，结果为 `bool` |
| 转换 | 数值 `cast`、整数窄化 `cast(..., truncate, ...)`、等宽整数/浮点位重解释 `bitcast` |
| 模式 | 默认 strict；有符号整数算术及整数 `shl` 可按规则使用 `wrap`，浮点算术可按规则使用 `ieee`；浮点不支持 `wrap` |
| 控制流 | 缩进敏感且以 `end` 结束的 `if`/`while`；`break`/`continue`；仅函数内允许受限 `goto`/`label`，且 `while` 内禁止二者 |
| 函数 | 顶层 `func`、命名且有序的 `funcall`、显式 `return`；参数按值且只读，各函数作用域独立，调用图无环 |
| 模块 | 一个 `.tc` 文件恰好一个模块；`#program` / `#lib` 二分；`import` + `xxx.id` 访问公开成员（可复用逻辑须双文件，§4.1） |
| I/O | `write`、`writeln`、`read`，仅限 11 种标量类型（禁止 `memblock`）；输出支持 13 种转换符及 C99 风格的标志、字段宽度和精度控制 |
| 入口 | `#program` 模块的顶层语句按源序执行；无特殊 `main`，顶层只允许结构化控制流 |

### 1.2 设计原则

TC 不优化人类编码效率，所有设计取舍优先服务于阅读清晰性、AI 生成正确性及计算安全性与可靠性。以下原则以五项核心定位为纲：

| 定位 | 原则 | 设计意图 | 详见 |
| ---- | ---- | -------- | ---- |
| **教学友好** | 逐条执行 | 无表达式嵌套，可逐行暂停检查状态 | §6.1.1 |
| | 显式类型标注 | 类型信息始终可见 | §5.1 |
| | 类型参数首位 | 无需猜测结果位宽或符号性 | §6.3 |
| | 缩进强制 | 块结构由缩进界定、`end` 结束 | §7.1.2 |
| | 常量与变量分离 | `let` 编译期求值，`var` 运行时可变 | §5.1–5.2 |
| **AI 友好** | 声明时必须初始化 | `var` 统一带 `=`，杜绝遗漏初始化的错误模式 | §5.1 |
| | 运算函数化 | 以 `op(类型, 操作数…)` 调用，无优先级歧义 | §6.3–6.6 |
| | 同类型运算 | 无混合精度算术 | §6.3.1 |
| | 单调用语句 | funcall/return 操作数限于 `operand`，禁止嵌套 | §8.2, §8.3 |
| | 字面量类型显式 | 后缀唯一决定类型，无推断歧义 | §3.6 |
| **阅读友好** | 显式类型转换 | 跨类型须 `cast`，禁止隐式转换 | §6.6 |
| | 命名空间限定 | `module.id` / `Self.id` 静态限定，来源透明 | §4 |
| | 显式函数数据流 | 值默认只经参数/返回值流动；库成员须 `Self.id` / `module.id` | §8.4.1, §4.3 |
| **安全计算** | 默认严格模式 | 有符号整数/浮点默认检测异常；wrap/ieee 须显式声明 | §6.3.2 |
| | 初始化安全 | 语法层声明时初始化 + 确定初始化分析 | §5.1, §9.2 |
| **可靠计算** | 零未定义行为 | 规范未定义的形态即不合法 | §1.3 |
| | 实现一致性 | VM、AOT 与常量求值遵循相同规则；同输入必同输出 | §1.3 |
| | 调用图无环 | 禁止直接/间接递归，栈深度编译期可确定上界 | §8.6 |

### 1.3 规范约定与一致性判定

本说明书使用以下规范层次：

1. **规范性用语**：**必须 / 禁止 / 仅可 / 不得** 为一致性要求；**应当 / 建议** 为实现或风格建议；**可以** 为实现自由（但不得改变可观察语义）。

2. **语法拒绝**：Token 序列不符合附录 A 的产生式。在语法检查阶段报告专用诊断码（默认 `TC_ERR_SYNTAX`；对特定失配规定了专用码，如 `TC_ERR_VAR_MISSING_INIT`、`TC_ERR_OPERAND_COUNT`、`TC_ERR_MODULE_LAYER`、`TC_ERR_MISSING_VISIBILITY`、`TC_ERR_KEYWORD` 及缩进/块结构专用码）。专用码只改变错误分类，不放宽附录 A。语法拒绝的程序不得进入后续语义检查。

3. **静态语义拒绝**：附录 A 已接受但正文的类型、模式、作用域、可见性、确定初始化、返回路径或调用图等规则不成立。在静态语义检查阶段报告对应错误码。附录 A 决定语法接受集，正文决定静态与执行语义，二者分工、互不覆盖。

4. 同一形态在不同产生式中的分流属于语法接受集差异（如 `let` 的 `const_shift_expr` 接受 `mode` 而运行时 `shift_expr` 不接受）。正文仅写“静态错误”而未标明阶段时：可由附录 A 排除则按语法拒绝，否则按静态语义拒绝。示例中的“❌”注释不改变上述分类。

5. **资料性内容**：第 12 章、附录 B、附录 C 及标为“示例”或“设计说明”的段落不构成规范性条款；与正文或附录 A 冲突时以规范性条款为准。

6. **可观察行为**：包括是否通过静态检查、首个规范诊断及其错误码、按源序成功提交到 TC 抽象标准输出的字节、正常结束或首个运行时错误及错误码。失败输出语句泄漏的宿主物理前缀（§10.2）不算可观察行为。槽位地址、帧布局、宿主字节序等宿主泄漏均不是可观察行为。

7. **零未定义行为**：除实现资源失败和 §10.2 的 I/O 物理行为外，不存在实现自行选择的未定义行为。规范未给出的形态不合法。相同输入下 VM 与 AOT 必须得到相同抽象行为。

8. **浮点**：以 IEEE 754-2019 定义为准；与 C99 宿主不一致时以 TC 抽象机器为准。AOT 不得泄漏宿主 C99 的未定义/实现定义行为。

9. **as-if 规则**：VM、AOT 和优化器可改变内部表示与指令序列，但必须保留规范静态诊断、实际执行路径上的运行时错误顺序、标准 I/O 顺序和值结果。可在编译期算出的 strict 运算仍具运行时错误语义，不得提升为 `let` 式静态错误，也不得因结果未使用而删除可能报错的指令。

10. **不得借书写成本放宽语义**：实现不得以降低人手编码成本为由放宽附录 A 接受集、静默接受对 `private` 成员的外部访问，或以警告代替对公开 `static var` 跨模块写入的既有语义（§4.4）。

“一致性实现”指其前端与执行后端共同满足以上规则的实现。仅解析不执行的工具可以只声明所覆盖的阶段。

## 2. 词法结构

本章定义 TC 语言的基本词法单元。完整的 EBNF 定义见附录 A。

### 2.1 字符集与 Token

TC 源文件的“编码字符集”与“可形成 Token 的字符集”分层规定：

1. 源编码：文件必须是有效 UTF-8 字节序列。不接受 UTF-8 BOM；文件起始的 U+FEFF 按非法源字符处理。U+0000 在源文件任何位置均非法。
2. Token 与结构字符：除行注释内容外，只允许附录 A 终结符使用的 ASCII 字符：`A`–`Z`、`a`–`z`、`0`–`9`、`_`、`+`、`-`、`#`、`%`、`=`、`:`、`,`、`(`、`)`、`<`、`>`、`;`、`.`、`@`。其中 `<` / `>` 仅用于 `memblock<T>` 类型构造器的尖括号（§3.8、附录 A）；`@` 仅用于结构体字段的 `@padding(N)` 属性（§3.9、附录 A）；字符是否能出现在具体位置仍由最长匹配规则与附录 A 决定；“属于本字符表”不代表在任意位置都是合法 Token。
3. 源空白、缩进与行结束：Token 之间的水平空白可为 ASCII 空格 U+0020 或水平制表符 U+0009；但对非空、非纯注释逻辑行，第一个 Token 之前的行首缩进只能由 ASCII 空格 U+0020 组成，每连续 4 个空格表示一级，行首空格总数必须能被 4 整除，不得使用 U+0009 制表符缩进。逻辑行结束仅为 LF（U+000A）、CRLF（U+000D U+000A）或 CR（U+000D）。其他 Unicode 空白不是 TC 空白。
4. 注释内容：分号 `;` 之后到当前逻辑行结束之前，允许任意已正确 UTF-8 解码的 Unicode 标量值（U+0000 除外）。注释内容不产生 Token，其中的非 ASCII 字符、关键字或类似数值的文本均不参与词法分析。

非法 UTF-8 在 UTF-8 解码阶段拒绝；BOM、U+0000，以及注释外的非 ASCII 字符、未列出的 ASCII 字符或非法空白在随后的词法/源字符检查中拒绝。两类均映射为 `TC_ERR_SYNTAX`。

### 2.2 标识符

- 由字母、数字与 `_` 组成，必须以字母或 `_` 开头。
- 区分大小写：`a` 与 `A` 为不同变量。
- 合法：`a`、`count`、`_tmp1`、`my_var`
- 非法：`1a`、`-x`（`-` 非标识符字符）

### 2.3 整数字面量

#### 2.3.1 后缀与符号性

TC 字面量通过后缀区分符号性：

| 后缀      | 符号性 | 示例                   |
| --------- | ------ | ---------------------- |
| 无后缀    | 有符号 | `42`、`-128`、`0xFF`   |
| `u` / `U` | 无符号 | `42u`、`255u`、`0xFFu` |

**关键规则**：
- 无后缀字面量视为有符号整数，可用于有符号类型上下文；若用于无符号上下文，须满足范围约束
- `u` 后缀字面量视为无符号整数，仅可用于无符号类型上下文；用于有符号上下文触发 字面量类型错误
- 负号 `-` 仅可与无后缀字面量组合；`-42u` 为非法
- 进制前缀只改变数值的书写方式，不改变其数学值，也不触发隐式补码重解释。例如 `0b1000_0000` 的数学值为 `128`，不能直接用于 `int8` 上下文；`int8` 的最小值应写作 `-128`

#### 2.3.2 进制

TC 支持四种进制字面量：

| 进制           | 前缀        | 数字字符集                | 示例                      |
| -------------- | ----------- | ------------------------- | ------------------------- |
| 十进制（默认） | —           | `0`–`9`                   | `0`、`255`、`-128`、`42u` |
| 十六进制       | `0x` / `0X` | `0`–`9`、`a`–`f`、`A`–`F` | `0xFF`、`0x1Au`、`-0x80`  |
| 二进制         | `0b` / `0B` | `0`、`1`                  | `0b1010`、`0b11111111u`   |
| 八进制         | `0o` / `0O` | `0`–`7`                   | `0o377`、`-0o100`         |

- 前缀中的 `0` 是必需的前导，不区分大小写
- 前缀与数字之间 不可有空白
- 后缀紧跟数字部分，前缀与后缀之间 不可有空白

#### 2.3.3 数字分隔符

为增强长数字的可读性，允许在下述位置插入单个下划线 `_`：

- 十进制：两个十进制数字之间（首数字之后、末数字之前）
- 十六进制：数字部分的两个十六进制数字之间
- 二进制：数字部分的两个二进制数字之间
- 八进制：数字部分的两个八进制数字之间

示例：

```text
1_000_000           → 1000000
0xFFFF_0000u        → 4294901760
0b1010_0011u        → 163
-0x7F_FF            → -32767
```

**约束**：不可连续两个 `_`，不可在字面量首尾放置 `_`，不可在前缀内部插入 `_`（如 `0x_FF` 非法）。

#### 2.3.4 前导零

- 十进制字面量 不允许前导零（`007` 非法，应写作 `7`）；忽略分隔符后仍按数字序列判定，因此 `0_0`、`0_7` 也非法
- 单个 `0` 是合法的十进制零，不视为前导零特例
- 八进制须显式使用 `0o` 前缀

#### 2.3.5 字面量的词法上限

- 整数字面量的数值不得超过 `2^64 − 1`，即 `0 ≤ N ≤ 18446744073709551615`
- 整数字面量超出此范围 → 字面量范围错误

本节上限是只依赖 Token 自身的词法值检查：在最长匹配形成候选整数字面量后、进入语法解析前执行，失败固定报告 `TC_ERR_LITERAL_OUT_OF_RANGE`。它不同于随后依据变量、形参或返回类型进行的上下文字面量检查。

#### 2.3.6 负号与减法运算符的关系

`-` 前缀仅出现在无后缀整数字面量中，不作为独立的一元运算符。若需变量间的减法，使用 `sub` 指令。

#### 2.3.7 最长匹配

整数字面量 Token 按最长匹配形成：前缀 `0` 后接 `x`/`X`/`b`/`B`/`o`/`O` 转入对应进制；数字部分结束后若紧跟 `u`/`U` 则带后缀，否则为无后缀字面量。具体扫描步骤以实现确定性为准，但不得改变本节与附录 A 规定的 Token 集合。

### 2.4 浮点字面量

#### 2.4.1 格式与后缀

TC 支持十进制浮点字面量和科学计数法：

| 形式                    | 示例                     | 类型                     |
| ----------------------- | ------------------------ | ------------------------ |
| 十进制浮点              | `3.14`、`-0.5`、`1.0`    | 无后缀 → `float64`       |
| 单精度后缀              | `3.14f`、`-0.5F`、`1.0f` | `f`/`F` 后缀 → `float32` |
| 科学计数法（小写 e）    | `1.2e5`、`-3.14e-2`      | 无后缀 → `float64`       |
| 科学计数法（大写 E）    | `1.2E5`、`-3.14E-2`      | 无后缀 → `float64`       |
| 科学计数法 + 单精度后缀 | `1.2e5f`、`-3.14E-2F`    | `f`/`F` 后缀 → `float32` |

**关键规则**：
- 浮点字面量必须包含小数点 `.` 或指数标记 `e`/`E`
- 无后缀浮点字面量为 `float64` 类型
- `f`/`F` 后缀浮点字面量为 `float32` 类型
- 浮点字面量 不区分符号性（浮点数无符号概念）
- 负号 `-` 可与浮点字面量组合
- 浮点字面量 仅可用于能确定源浮点类型的上下文（含 `float32`/`float64` 运算、`cast` 或 `bitcast`）
- 有限十进制字面量先解析为精确数学值，再直接按 roundTiesToEven 舍入到后缀决定的 binary32/binary64；不得通过另一浮点类型中转
- 非零有限值舍入为零，或有限值舍入为无穷 → 字面量范围错误；可表示的非规格化数合法
- 数学值为零且字面量显式带 `-` 时生成负零；其余零字面量生成正零

有限浮点字面量的源类型完全由 `f`/`F` 后缀决定，因此上述"舍入为零或无穷"的检查同样是只依赖 Token 自身的词法值检查，失败报告 `TC_ERR_LITERAL_OUT_OF_RANGE`。后续上下文只检查该已形成的 `float32` / `float64` 字面量是否与期望类型一致，不重复改变其源类型或舍入结果。

**特殊浮点值**：

| 字面量 | 含义             | IEEE 754 表示                |
| ------ | ---------------- | ---------------------------- |
| `inf`  | 正无穷           | 指数全 1，尾数全 0，符号位 0 |
| `-inf` | 负无穷           | 指数全 1，尾数全 0，符号位 1 |
| `nan`  | 非数（静默 NaN） | 指数全 1，尾数非 0           |

**特殊值的源类型**：

`inf`、`-inf`、`nan` 本身不区分 `float32` / `float64` 精度。词法层将它们归约为同一个特殊浮点 Token（`float_special`），不携带类型。源类型在所有上下文中统一由该位置的**期望类型**唯一决定：

| 上下文 | 期望类型的来源 | 示例 |
| ------ | -------------- | ---- |
| 变量/常量声明 | 声明类型 | `var x: float32 = inf` → 源为 `float32` |
| `cast(T, ...)` | 目标类型 `T` | `cast(float32, inf)` → 源为 `float32` |
| `bitcast(T, ...)` | 目标位宽决定：32 位目标 → 源为 `float32`，64 位目标 → 源为 `float64` | `bitcast(uint32, nan)` → 源为 `float32` |
| 算术 / 比较 / I/O 的操作数位置 | 显式类型参数或 I/O 的 `type` 参数 | `add(float32, inf, ...)` → 源为 `float32` |

因此 `var x: float32 = inf` 将 `inf` 视为 `float32` 的正无穷，而 `var y: float64 = inf` 将其视为 `float64` 的正无穷。同样地，`cast(float32, inf)` 直接将 `inf` 视为 `float32` 的正无穷（`0x7F800000`），不再经过 `float64` 中转。`var z: float32 = nan` 产生 `float32` 的 canonical quiet NaN（`0x7FC00000`），`var w: float64 = nan` 产生 `float64` 的 canonical quiet NaN（`0x7FF8000000000000`）。所有路径对同一目标类型产生完全相同的位模式，不存在位级差异。

**约束**：
- `inf`、`-inf`、`nan` 为保留关键字，不可用作标识符
- 区分大小写：均为小写。`INF`/`NaN` 等其他大小写形式按普通标识符词法化，若未声明则报 `TC_ERR_UNDEFINED_VARIABLE`

```text
var pi: float64 = 3.141592653589793
var e: float32 = 2.71828f
var speed: float64 = 3.0e8
var tiny: float32 = 1.0e-38f
var inf_pos: float64 = inf
var nan_val: float64 = nan
```

#### 2.4.2 词法错误

```text
3.14u     ; 非法：浮点不支持 u 后缀
.5        ; 非法：须 0.5
1e5       ; 合法：科学计数法（整数指数形式）
```

### 2.5 布尔字面量

| 字面量  | 值   | 类型   |
| ------- | ---- | ------ |
| `true`  | 真   | `bool` |
| `false` | 假   | `bool` |

**约束**：
- `true` 和 `false` 为保留关键字，不可用作标识符
- 区分大小写，且仅小写形式是布尔字面量。`True` / `FALSE` 等按普通标识符词法化，若未声明则报 `TC_ERR_UNDEFINED_VARIABLE`
- 布尔字面量 仅可用于 `bool` 类型上下文

```text
var flag: bool = true
var done: bool = false
var err: int32 = true      ; 字面量类型错误
```

### 2.6 注释

- 行注释以 `;` 开始，延续至行尾
- 注释内容可以使用 Unicode；注释之外的 Token 仍仅使用 §2.1 规定的 ASCII 字符
- 示例：`var a: int32 = 10    ; 定义 32 位整数`

### 2.7 关键字

以下 token 为保留关键字，不可用作标识符：

```text
var  let  bool  true  false
int8  uint8  int16  uint16  int32  uint32  int64  uint64
float32  float64
add  sub  mul  div  mod  abs  neg
eq  ne  lt  le  gt  ge
and  or  xor  not      ; 均支持 bool 逻辑与整数按位重载
shl  shr
cast  bitcast  wrap  truncate  ieee
write  writeln  read
if  then  else  end
while  break  continue   ; 结构化循环控制
goto  label            ; 仅函数体内可用的非结构化跳转
func  funcall  return  void  ; 函数定义、调用与返回
import                       ; 库模块导入

```

`#program` 和 `#lib` 是模式指令 Token，只能出现在 §4 规定的文件首个有效行。`call` 不是 0.0.35 的调用关键字；函数调用必须写作 `funcall`。`void` 只允许出现在函数返回类型位置。`padding` 不是保留关键字；它仅作为 `@padding(N)` 属性名出现在结构体字段声明中（§3.9）。

### 2.8 语句与行结构

- 每条语句独占一行
- 空行、仅含 ASCII 空格/制表符的行、仅含行注释的行均合法，不产生语句；这些行的行首空白不构成缩进。非 ASCII 空白不能构成空白行
- 语句由 `NEWLINE` 结束。`;` 始终是行注释起始符；因注释可紧跟语句，外观上可写为“语句末尾的可选 `;`”，但语法 Token 序列中不存在分号终结符

## 3. 类型系统

### 3.1 类型分类

TC 0.0.35 支持 **整数类型**、**浮点类型**、**布尔类型**、**内存块类型**、**结构体类型**，并以 `void` 表示函数不返回值：

| 类别         | 支持的类型               | 说明                   |
| ------------ | ---------------------- | ---------------------- |
| **整数类型** | `int8`～`uint64`       | 固定宽度二进制补码整数 |
| **浮点类型** | `float32`、`float64`   | IEEE 754 浮点数        |
| **布尔类型** | `bool`                 | 逻辑真/假              |
| **内存块类型** | `memblock<T>`        | 仅由元素类型 `T` 区分的纯内存块值类型；无长度概念（§3.8） |
| **结构体类型** | 用户定义的 `struct` 名 | 命名字段的值类型聚合；默认无内部填充，可选 `@padding(N)`（§3.9） |
| **无值标记** | `void`                 | 不是值类型，仅用于函数返回类型 |

### 3.2 整数类型

| 类型     | 位宽 | 符号   | 最小值                     | 最大值                     |
| -------- | ---- | ------ | -------------------------- | -------------------------- |
| `int8`   | 8    | 有符号 | −128                       | 127                        |
| `uint8`  | 8    | 无符号 | 0                          | 255                        |
| `int16`  | 16   | 有符号 | −32,768                    | 32,767                     |
| `uint16` | 16   | 无符号 | 0                          | 65,535                     |
| `int32`  | 32   | 有符号 | −2,147,483,648             | 2,147,483,647              |
| `uint32` | 32   | 无符号 | 0                          | 4,294,967,295              |
| `int64`  | 64   | 有符号 | −9,223,372,036,854,775,808 | 9,223,372,036,854,775,807  |
| `uint64` | 64   | 无符号 | 0                          | 18,446,744,073,709,551,615 |

类型命名规则：`<符号前缀><位宽>`，其中符号前缀为 `int`（有符号）或 `uint`（无符号），位宽为 `8`/`16`/`32`/`64`。

### 3.3 浮点类型

| 类型      | 位宽 | IEEE 754 对应 | 最小正非零值（约） | 最大有限绝对值（约） | 精度（十进制） |
| --------- | ---- | ------------- | ------------ | ------------ | -------------- |
| `float32` | 32   | binary32      | 1.4e-45      | 3.4e38       | ~7 位          |
| `float64` | 64   | binary64      | 5e-324       | 1.8e308      | ~16 位         |

**内部表示**：
- 浮点数以 IEEE 754 二进制格式存储
- `float32`：符号字段 1 位 + 指数字段 8 位 + fraction 字段 23 位
- `float64`：符号字段 1 位 + 指数字段 11 位 + fraction 字段 52 位
- 浮点数的“位模式”只能通过等位宽 `bitcast` 与整数互转

### 3.4 布尔类型

`bool` 类型表示逻辑真值，取值为 `true` 或 `false`。

**抽象表示与固定宽度**：
- `bool` 在 TC 抽象机器中占据**固定 1 字节（8 位）**，与 `int8` / `uint8` 等位宽。该宽度参与 `memblock` 布局、按值传参/返回与整体复制的大小计算，VM 与 AOT 必须一致。
- 规范位模式唯一：`false` = `0x00`，`true` = `0x01`。不存在第三种可由合法 TC 程序提交的“非零真值”字节。
- `bool` 的抽象值域恰好为 `false` 与 `true`；所有产生 `bool` 的指令、`read`、`cast` 与 `memblock_store`（元素类型为 `bool` 时）都必须把结果规范化为上述二者之一后再提交。
- 若后端在 ABI 或内部载体上接收非规范布尔字节，必须先规范化为 `0x00` / `0x01` 再进入 TC 抽象机器；不得让非规范字节影响比较、逻辑、I/O、函数传参或 `memblock` 元素内容。
- 不可将 `bool` 直接解释为整数；数值互转须通过 `cast`。尽管位宽与 `int8`/`uint8` 相同，`bitcast` 仍明确排除 `bool`（§6.6.6），以杜绝经位重解释写入非 `0x00`/`0x01` 字节。

**类型性质**：
- 比较运算和逻辑运算的结果类型为 `bool`。
- `bool` 变量可被赋值、读取、输出。
- 与所有类型相同：`bool` 的 `var` 定义**声明时必须初始化**（§5.1）。

```text
var flag: bool = true      ; 声明并初始化；抽象字节 0x01
var done: bool = false     ; 声明并初始化；抽象字节 0x00
; var uninit: bool         ; ❌ 静态错误：变量定义必须初始化
```

由于 `bitcast` 明确排除 `bool` 类型（§6.6.6），TC 程序不存在通过位重解释将非规范位模式引入 `bool` 绑定的路径；所有产生 `bool` 值的指令和转换均保证结果已规范化为 `0x00` 或 `0x01`。

### 3.5 类型性质

**有符号类型（`int8`～`int64`）**

- 采用 二进制补码 表示
- `add`/`sub`/`mul`/`neg` 默认 **严格模式**：结果超出范围 → 整数溢出错误
- `div` 的数学商不可表示时，以及 `abs(INT_MIN)` 时 → 整数溢出错误
- 显式 `wrap` 模式：按模 `2^n` 回绕，不报错
- `shl` 默认严格模式：左移结果超出范围 → 整数溢出错误；`wrap` 模式截断高位

**无符号类型（`uint8`～`uint64`）**

- 仅表示非负整数
- 算术结果超出最大值时 模 `2^n` 回绕，不报错
- `div`/`mod` 结果恒为非负
- `shl` 默认严格模式（仍可检测值溢出，例如 `shl(uint8, 255u, 1)` 的数学结果超过 255 时报错），`wrap` 模式截断高位

**浮点类型（`float32`、`float64`）**

- 符合 IEEE 754 标准
- 支持两种算术模式（详见 §6.3）：
  - **严格模式**（默认）：上溢/下溢/除零/无效操作均报错
  - **IEEE 754 模式**（`ieee`）：遵循 IEEE 754，返回 ±inf/nan，不报错
- 0.0.35 不支持浮点 `wrap`；位模式操作须通过等宽 `bitcast` 转为整数后完成
- 浮点数不支持位运算（`and`/`or`/`xor`/`not`/`shl`/`shr`）

**布尔类型**

- 固定宽度 1 字节；规范位模式为 `false` = `0x00`、`true` = `0x01`（§3.4）
- 比较运算和逻辑运算返回 `bool`
- 不参与算术运算（须显式 `cast`）；不参与 `bitcast`

**无值返回标记（`void`）**

- 只表示函数没有返回值，不是值类型
- 没有位宽、字面量、变量槽或运行时值
- 不能参与运算、转换、I/O、参数传递或变量/常量定义

**结构体类型（用户定义的 `struct`）**

- 是值类型：整体赋值、按值传参与返回均按抽象布局整块复制（§3.9.4）；含 `memblock` 字段时，各字段存储区由实现持有，结构体无单一类型级宽度（§3.8.0、§3.9.3）
- 默认字段紧密排列、无内部填充；仅当字段显式书写 `@padding(N)` 时在该字段之后插入恰好 `N` 字节填充
- 字段以 `let` / `var` 区分成员可变性；字段赋值规则同时受外层绑定种类约束（§3.9.5）
- 不参与算术、位运算、比较、逻辑、`cast` / `bitcast` 或标量 I/O；整块 I/O 须按字段自行完成

**运行时值模型**

TC 中每个整数、浮点或布尔变量的值由 n 位抽象位串（`n` 为类型位宽）与类型解释共同构成：

- 整数内部以 n 位无符号位模式存储；有符号类型按 二进制补码 解释，无符号类型按非负整数解释
- 浮点数内部以 IEEE 754 位模式存储
- `bool` 的 `n = 8`；合法提交的位模式仅 `0x00`（`false`）与 `0x01`（`true`）
- `wrap` 算术回绕、整数 `cast(..., truncate, ...)` 与等宽 `bitcast` 均在整数/浮点位模式上操作；`bitcast` 不作用于 `bool`
- 有符号 `wrap` 下的 `add`/`sub`/`mul`/`neg` 与同位宽无符号默认回绕 位模式一致
- 结构体值由按 §3.9.3 规定的字段与填充字节序列构成；填充字节在构造与整块复制时均为 `0x00`

抽象位串按“最高有效位到最低有效位”的数值位权定义，与宿主内存的大小端字节序无关。`bitcast` 保持的是该抽象位串，不是对宿主对象表示执行类型别名访问；VM 与 AOT 在不同字节序主机上必须得到相同数值结果。

### 3.6 字面量与类型的关系

字面量先由自身形式确定类别或源类型，再由所在位置提供的期望类型检查。不存在隐式跨类别转换。

#### 3.6.1 字面量检查规则

| 字面量 | 检查规则 |
| ------ | -------- |
| 无后缀整数 | 解析绝对值 `N`（`0 ≤ N ≤ 2^64−1`）；可带 `-`。有符号上下文要求数学值位于 §3.2 对应范围；无符号上下文要求值非负且在范围内 |
| `u`/`U` 整数 | 不得带 `-`，仅用于无符号整数上下文，且值须在对应范围内 |
| 普通浮点 | 无后缀源类型为 `float64`，`f`/`F` 后缀源类型为 `float32`；精确十进制值直接按 roundTiesToEven 舍入到该类型，不经另一浮点类型中转 |
| `inf`/`-inf`/`nan` | 仅用于浮点上下文；`nan` 为 §6.3.3 的 canonical quiet NaN |
| `true`/`false` | 仅用于 `bool` 上下文 |

非零有限浮点值舍入为零或有限值舍入为无穷时报字面量范围错误；可表示的非规格化数合法。类别、后缀或符号性与上下文不符时报字面量类型错误。`wrap`、`ieee`、`truncate` 和 `bitcast` 均不绕过这些检查。

```text
var a: int8 = 127       ; 合法
var b: uint8 = 255      ; 合法：无后缀非负整数可用于无符号上下文
var c: uint8 = 255u     ; 合法
var f: float32 = 1.5f   ; 合法
; var bad: int8 = 128   ; 字面量范围错误
; var bad: int32 = 1u   ; 字面量类型错误
```

### 3.7 类型转换的通用框架

TC 0.0.35 将数值转换、整数截断与位重解释分开：

| 形式 | 用途 | 核心约束 |
| ---- | ---- | -------- |
| `cast(T, operand)` | 数值转换 | 按目标类型做范围检查与规定舍入 |
| `cast(T, truncate, operand)` | 整数缩窄 | 仅整数→更窄整数，保留低位 |
| `bitcast(T, operand)` | 位重解释 | 源、目标等宽；不改变任何位；`bool` 不参与 |

严格 `cast` 覆盖整数 ↔ 整数、整数 ↔ 浮点、浮点 ↔ 浮点，以及整数/浮点 ↔ `bool`。`truncate` 不再承担浮点位重解释；所有整数/浮点位模式互转统一使用 `bitcast`。

### 3.8 内存块类型（`memblock`）

`memblock<T>` 是 TC 的参数化值类型，表示一段紧密排列的标量元素连续内存块。它直接映射到伪汇编模型中的可寻址内存块，使内存读写显式化为原子操作，不引入指针、地址运算或隐式解引用。

#### 3.8.0 无长度模型

`memblock` 是**纯粹的内存块**概念。全文凡提及 memblock「类型」「布局」「赋值」「越界」均按本款理解：

| 规则 | 说明 |
| ---- | ---- |
| **无长度** | 语言模型中**不存在** memblock 的「长度」「元素个数」属性——不论类型、值还是绑定。不存在 `memblock<T, N>`，也不把个数写入类型、值模型或绑定元数据。 |
| **类型只含 `T`** | 类型构造器**只**携带元素类型 `T`。类型等价、声明标注、形参/返回类型、结构体字段类型均只比较 `T`。 |
| **无长度元数据** | memblock 不具有语言层面的存储容量属性；赋值、函数传参与类型检查均不比较元素个数。 |
| **`count:` 仅属构造器** | 值构造器中的 `count:` 是**本次构造的分配/初始化参数**（决定创建并填充多少个元素），不是 memblock 的持久语言属性；构造表达式求值结束后，该参数不进入绑定的编译期元数据。 |
| **程序自管范围** | 算法若需记住可用下标范围，须用独立的整数 `let`/`var` 自行跟踪；语言**不提供** `memblock_size`。 |

因此：`var a: memblock<int32> = memblock(int32, count: 256)` 与 `var b: memblock<int32> = memblock(int32, count: 128)` **类型相同**（均为 `memblock<int32>`）；`a = b` **仅**做类型检查，合法（整块深拷贝源存储区到目标，§3.8.4）。不得因构造时用过不同的 `count:` 而报告类型错误或任何「大小不匹配」诊断。

实现可为运行时越界检查与整块复制持有存储区容量（实现细节）；该容量**不是**语言层面的 memblock 长度，也不得升格为类型属性。

#### 3.8.1 类型语法

```
memblock<T>
```

`T` 为元素类型，仅限 11 种标量类型：

```
int8, uint8, int16, uint16, int32, uint32, int64, uint64
float32, float64, bool
```

`memblock<T>` 本身是值类型，不可嵌套：`memblock<memblock<T>>` 不支持。附录 A 以 `scalar_type` 限定类型构造器与值构造器的元素类型参数，因此嵌套形态不符合 EBNF，语法阶段报告 `TC_ERR_SYNTAX`。需要多维时，用一维 `memblock` 通过自行计算偏移来模拟，这符合 TC 伪汇编将地址计算显式化的哲学。

#### 3.8.2 运行时布局

元素类型 `T` 的抽象宽度 `sizeof_bits(T)` 固定如下，与宿主 ABI 无关：

| `T` | 宽度（位） |
| --- | ---------- |
| `int8` / `uint8` / `bool` | 8 |
| `int16` / `uint16` | 16 |
| `int32` / `uint32` / `float32` | 32 |
| `int64` / `uint64` / `float64` | 64 |

其中 `bool` 按 §3.4 固定为 1 字节：`false` 存 `0x00`，`true` 存 `0x01`。`memblock_store` 写入 `bool` 元素前必须规范化；`memblock_load` 读出的 `bool` 必须已是规范字节。

**类型 `memblock<T>` 没有类型级位宽**（§3.8.0：无长度概念）。每个 memblock 值对应一段元素按抽象位串**紧密排列、无填充**的连续存储区；存储区在构造时按构造器的分配参数创建，其后由实现持有，供整块复制与运行时越界检查使用。示意（构造参数为 4 个元素时）：

```text
某一由 memblock(int32, count: 4, …) 构造的存储区:
[ elem0:32bit | elem1:32bit | elem2:32bit | elem3:32bit ]

某一由 memblock(bool, count: 4, …) 构造的存储区:
[ e0:8bit | e1:8bit | e2:8bit | e3:8bit ]   ; 每元素仅 0x00 或 0x01
```

#### 3.8.3 构造器

`memblock` 同时作为类型构造器（`memblock<int32>`）和值构造器（`memblock(int32, count: 256)`），上下文区分：出现在类型位置的 `:` 之后为类型构造器，出现在 `=` 右侧（或其它 RHS / 实参位置）为值构造器。

值构造器一律使用**命名标签** `count:`（及可选的 `fill:`），三种形态在附录 A 中分属不同产生式，**语法即可区分**，不得再写旧式位置参数 `memblock(T, n)` / `memblock(T, n, v)` / `memblock(T, n, v0, …)`（该类 Token 序列不符合 EBNF，语法阶段报告 `TC_ERR_SYNTAX`）。

`count:` 之后的计数值必须是编译期常量（整数字面量，或求值结果为整数的 `let` / `static let` 标识符，含经 `Self.` / 导入限定解析到的只读绑定），数学值必须 ≥ 1。该计数值**只**决定本次构造创建并初始化多少个元素；**不**成为 memblock 的语言属性，也**不**写入绑定的编译期元数据（§3.8.0）。不提供就地伸缩存储区的语言操作。标签名 `count`、`fill` 仅在本构造器产生式中按固定拼写匹配，**不是** §2.7 保留关键字（词法上仍为普通标识符 Token，因此源程序仍可声明名为 `count` / `fill` 的绑定）。

**形态分流**：

| 形态 | 书写形式 | 产生式 | 语义 |
| ---- | -------- | ------ | ---- |
| 零值填充 | `memblock(T, count: c)` | `memblock_zero_ctor` | 分配并初始化 `c` 个元素，全部为零值 |
| 指定值填充 | `memblock(T, count: c, fill: v)` | `memblock_fill_ctor` | 分配并初始化 `c` 个元素，全部为 `v` |
| 逐值初始化 | `memblock(T, count: c, v0, v1, …, vₙ)` | `memblock_elems_ctor` | 分配并依次写入 `n+1` 个值；必须 `n+1 = c` |

在 `count: c` 之后若出现 `,`：若下一组 Token 为标识符 `fill` 紧跟 `:`，则只能进入指定值填充；否则进入逐值初始化（至少一个位置实参）。缺少 `fill:` 标签、仅写一个位置实参时**不得**解释为填充——若位置实参数量不等于 `c`，报告 `TC_ERR_MEMBLOCK_ELEMENT_COUNT_MISMATCH`（这是**构造器实参一致性**检查，不是 memblock「长度」属性检查）。

**零值填充** — `memblock(T, count: c)`：

分配并初始化 `c` 个元素，全部为零值：

| 元素类型 | 零值 |
|----------|------|
| 整数 | `0` / `0u` |
| 浮点 | `0.0` / `0.0f` |
| `bool` | `false` |

```tc
var buf: memblock<uint8> = memblock(uint8, count: 256)
; 构造时分配并零填充 256 个 uint8；若算法需要范围，自行保留整数绑定
```

**指定值填充** — `memblock(T, count: c, fill: v)`：

分配并初始化 `c` 个元素，全部以 `v` 初始化。`v` 的类型必须与 `T` 严格一致；`v` 为 §6.1.2 的 `operand`（`let` 上下文中为 `const_operand`）。

```tc
var ones: memblock<int32> = memblock(int32, count: 100, fill: 1)
var padded: memblock<uint8> = memblock(uint8, count: 64, fill: 0xFFu)
```

**逐值初始化** — `memblock(T, count: c, v0, v1, …, vₙ)`：

以 `n+1` 个位置实参依次初始化各元素。约束：

- 位置实参数量必须等于 `c`，否则静态错误 `TC_ERR_MEMBLOCK_ELEMENT_COUNT_MISMATCH`
- 每个值的类型必须与 `T` 严格一致
- 每个值均为 `operand`（`let` 上下文中为 `const_operand`）；不得嵌套调用

```tc
let PRIMES: memblock<int32> = memblock(int32, count: 5, 2, 3, 5, 7, 11)
var CRC: memblock<uint32> = memblock(uint32, count: 4,
    0x00000000u, 0x77073096u, 0xEE0E612Cu, 0x990951BAu)

; memblock(int32, count: 5, 1)          ; ❌ 逐值个数 1 ≠ 5 → TC_ERR_MEMBLOCK_ELEMENT_COUNT_MISMATCH
; memblock(int32, count: 5, fill: 1)    ; ✅ 指定值填充：五个元素均为 1
; memblock(int32, 5)                    ; ❌ 旧式位置参数 → TC_ERR_SYNTAX
```

#### 3.8.4 赋值语义

`memblock<T>` 是值类型，赋值整体深拷贝源操作数的当前存储区到目标绑定（替换目标原有存储区）。**只**检查类型：

1. **类型**：左右必须同为某一 `memblock<T>`（仅比较 `T`）；否则 `TC_ERR_TYPE_MISMATCH`。
2. **不做长度检查**：赋值不比较、不要求左右「元素个数」一致；不存在 `TC_ERR_MEMBLOCK_SIZE_MISMATCH`。

无别名语义，无指针，无浅/深拷贝歧义。成功赋值后目标持有与源内容相同的独立存储区副本。

需要按偏移复制子区间、或只搬运部分元素时，使用独立语句 `memblock_copy`（§6.7.2.3）；`memblock_copy` 的 `length` 操作数是**本次拷贝的元素个数**，不是 memblock 的长度属性。

```tc
var a: memblock<int32> = memblock(int32, count: 256, fill: 0)
var b: memblock<int32> = memblock(int32, count: 256, fill: 1)
; a 与 b 类型同为 memblock<int32>

memblock_store(int32, a, 0, 42)
b = a    ; 合法：类型相同；整块深拷贝，b 的存储区内容与 a 一致

var c: memblock<int32> = memblock(int32, count: 128)
a = c    ; 合法：类型相同；a 替换为 c 的整块副本（不因构造时 count: 不同而类型失败）

; 子区间拷贝：
; memblock_copy(int32, c, 0, a, 0, 128)
```

### 3.9 结构体类型（`struct`）

`struct` 是 TC 的用户定义**值类型**：一组按声明顺序排列的命名字段。结构体不引入指针、引用、别名或隐式装箱；整体赋值与按值传参/返回均按抽象布局整块复制。设计目标是在伪汇编模型下提供可读的聚合，同时用字段级 `let`/`var` 与外层绑定种类共同约束可变性，避免“常量绑定却可改字段”的歧义。

#### 3.9.1 定义语法

结构体只能出现在模块顶层的**类型定义区**（§4），不得出现在函数体或控制流块内。

`#program`：

```text
struct <结构体名> then
    <字段声明>
    …
end
```

`#lib`（必须带显式可见性）：

```text
public|private struct <结构体名> then
    <字段声明>
    …
end
```

字段声明每行恰好一个字段，外形为：

```text
let <字段名>: <字段类型> [ @padding(<N>) ]
var <字段名>: <字段类型> [ @padding(<N>) ]
```

| 项目 | 规则 |
| ---- | ---- |
| 结构体名 | 模块内唯一的类型名；不得与标量/`memblock`/关键字/`void` 冲突，也不得与同模块的函数名、值绑定名或导入名冲突 |
| 字段数量 | 至少 1 个；空结构体不合法 |
| 字段名 | 同一结构体内唯一；区分大小写 |
| 字段种类 | `let` 字段：构造后不可通过字段赋值修改；`var` 字段：仅当外层绑定为可写 `var` / `static var` 时可通过字段赋值修改（§3.9.5） |
| 字段类型 | 11 种标量、`memblock<T>`（仅元素类型，无长度，§3.8.0），或**本模块中源序更早**已成功定义的结构体类型；禁止自引用与前向引用；禁止 `void` |
| 字段初始化器 | 定义处**不得**写 `=`；字段值只在值构造器中提供（§3.9.2） |
| 缩进 | 字段行比 `struct` 行恰好多一级；`end` 与 `struct` 行对齐（与 `func`/`if`/`while` 相同） |

```tc
struct Demo then
    let lid: int32
    var vid: int32
end

struct Demo2 then
    let lid: int32 @padding(1)
    var vid: int16 @padding(2)
end
```

`#lib` 中 `public struct` 可被导入者通过 `<模块名>.<结构体名>` 用作类型名与构造器名；`private struct` 仅本模块可用。缺少 `public`/`private` 报 `TC_ERR_MISSING_VISIBILITY`。在 `#program` 中对 `struct` 使用可见性修饰符报 `TC_ERR_PROGRAM_MODE_MISUSE`。

#### 3.9.2 值构造器

结构体名在类型位置表示类型，在 RHS / `const_rhs` / 实参位置表示**值构造器**：

```text
<结构体名>(<字段名>: <操作数>, …)
```

导入的公开结构体写作 `<模块名>.<结构体名>(…)`。

**静态约束**（全部为静态语义拒绝，附录 A 已接受命名实参外壳之后）：

1. **全字段必填**：必须为每个声明字段恰好提供一个命名实参；缺任一字段 → `TC_ERR_STRUCT_MISSING_FIELD`；多写未知字段名 → `TC_ERR_STRUCT_UNKNOWN_FIELD`；同一字段名重复 → `TC_ERR_STRUCT_DUPLICATE_FIELD`。
2. **文本顺序**：命名实参的文本顺序必须与字段声明顺序完全一致，否则 → `TC_ERR_STRUCT_FIELD_ORDER`（与 `funcall` 命名实参顺序规则同形）。
3. **类型一致**：每个实参操作数的类型必须与对应字段声明类型严格相同；字面量按 §3.6 以字段类型为期望类型检查。
4. **按值复制**：构造成功时，各字段值按字段类型的值语义**复制**进新结构体实例；不共享存储，无别名。
5. **常量上下文**：出现在 `let` / `static let` 的 `const_rhs` 中时，每个字段实参必须是合法的编译期常量操作数（§5.2.1）；运行时 `var`、参数或非常量表达式非法。

```tc
let let_demo: Demo = Demo(lid: 1, vid: 2)
var var_demo: Demo = Demo(lid: 10, vid: 20)

; Demo(vid: 2, lid: 1)     ; ❌ TC_ERR_STRUCT_FIELD_ORDER
; Demo(lid: 1)             ; ❌ TC_ERR_STRUCT_MISSING_FIELD（缺 vid）
; Demo(lid: 1, vid: 2, x: 3) ; ❌ TC_ERR_STRUCT_UNKNOWN_FIELD
```

#### 3.9.3 运行时布局

字段按**声明源序**依次排列。默认**无内部填充**：每个字段的存储紧接前一字段（或前一字段的填充区）结束处。

**字段抽象宽度**（用于构造某一具体结构体**值**时的布局）：

| 字段类型 | 该字段在某一值中的抽象宽度 |
| -------- | ------------------------ |
| 标量 `T` | `sizeof_bits(T)`（与 §3.8.2 相同；`bool` 固定 8 位）——类型级固定 |
| `memblock<U>` | 该字段 memblock 当前存储区的抽象位宽（实现持有；§3.8.0）；**不是**类型或字段声明的属性，字段声明只写 `memblock<U>` |
| 嵌套结构体 `S` | 该嵌套字段值的抽象宽度（按本款对嵌套值递归计算） |

可选属性 `@padding(N)`：

- `N` 必须是非负十进制整数字面量（无后缀；允许 `0`）。
- 语义：在**该字段存储之后**插入恰好 `N` 个填充字节（每位填充字节为 `0x00`）。
- 省略属性等价于 `@padding(0)`，即默认紧密布局。
- `@padding` 只改变布局字节数，不改变字段类型、可变性或构造器实参列表。

**类型级与值级宽度**：

- 若结构体类型 `S` 的字段（含嵌套结构体字段，传递闭包）**均不含** `memblock`，则 `S` 具有唯一的类型级宽度：

```text
sizeof_bits(S) = Σ_i ( sizeof_bits(field_i) + 8 × padding_i )
```

  其中标量/无 memblock 嵌套结构体的 `sizeof_bits(field_i)` 为类型级；`padding_i` 为字段 `i` 的 `N`（默认 0）。
- 若 `S` **直接或间接**含有 `memblock` 字段，则**不存在**单一的类型级 `sizeof_bits(S)`；每个 `S` 值的抽象宽度按其各 memblock 字段当前存储区（及嵌套值）由实现确定：

```text
sizeof_bits(某一 S 值) = Σ_i ( 字段 i 在该值中的抽象宽度 + 8 × padding_i )
```

布局与宿主 ABI、自然对齐无关；VM 与 AOT 对同一抽象值必须使用同一布局。构造与整块复制时，所有填充字节均为 `0x00`；程序不能单独寻址填充区。memblock 字段的存储容量不是语言属性（§3.8.0）。

```text
struct Demo2 then
    let lid: int32 @padding(1)   ; 4 字节字段 + 1 字节填充
    var vid: int16 @padding(2)   ; 2 字节字段 + 2 字节填充
end
; Demo2 不含 memblock：类型级布局（字节）[ lid:4 | pad:1 | vid:2 | pad:2 ]  共 9 字节
```

含 `memblock` 字段的示例（字段类型仍只写 `memblock<T>`；构造器的 `count:` 只影响本次分配，不进入字段/类型的长度元数据）：

```text
struct Buf then
    var data: memblock<uint8>
    var flag: bool
end

var b1: Buf = Buf(data: memblock(uint8, count: 16, fill: 0u), flag: false)
var b2: Buf = Buf(data: memblock(uint8, count: 64, fill: 0u), flag: true)
; b1 与 b2 类型同为 Buf；b1 = b2 合法（只检查结构体类型；各 memblock 字段整块深拷贝，§3.9.4）
```

#### 3.9.4 赋值与按值语义

结构体是值类型：

- **整块赋值** `dst = src`（`dst` 为可写结构体绑定，`src` 为同类型操作数或同类型构造器）复制全部字段与填充字节；左右类型必须同为某一结构体类型，否则 `TC_ERR_TYPE_MISMATCH`。含 `memblock` 字段时，对各 memblock 字段做整块深拷贝（§3.8.4）；**不**比较字段「长度」，不报告 `TC_ERR_MEMBLOCK_SIZE_MISMATCH`。
- **按值传参 / 返回**：调用与 `return` 时整块复制（含各 memblock 字段的当前存储区深拷贝）；形参是只读绑定，禁止对形参做整块赋值，也禁止对形参的任何字段赋值（与标量/`memblock` 形参一致，报 `TC_ERR_PARAMETER_ASSIGNMENT`）。形参类型仍只写结构体名；memblock 字段无长度属性（§3.8.0）。
- **无别名**：复制后源与目标独立；修改一方的 `var` 字段不影响另一方。

整块赋值可以替换目标中的 `let` 字段内容（因为替换的是整个值），这与“禁止对 `let` 字段做字段赋值”不矛盾：后者禁止的是**部分更新**，前者是**整体替换**可写绑定。

#### 3.9.5 字段访问与可变性

**字段读取**写作 `<结构体操作数>.<字段名>`，结果类型为该字段的声明类型。结构体操作数可以是：

- 裸标识符（局部/`#program` 顶层 `var`/`let`）
- `Self.<名>` / `<模块名>.<名>`（解析为结构体类型的 `static` 绑定）
- 形参名（只读）

字段读取是 `operand` 的合法形式（§6.1.2），因此可出现在运算、`funcall` 实参、`return`、输出等需要操作数的位置。嵌套字段访问（如 `a.b.c`）在 0.0.35 **不支持**；若字段本身是结构体，须先把该字段复制到中间绑定再访问其子字段。

**字段赋值**写作：

```text
<结构体左值>.<字段名> = <rhs>
```

字段赋值的合法性由两层约束**同时**决定：

| 外层绑定 | 目标字段为 `let` | 目标字段为 `var` |
| -------- | ---------------- | ---------------- |
| `let` / `static let` | ❌ `TC_ERR_CONSTANT_ASSIGNMENT` | ❌ `TC_ERR_CONSTANT_ASSIGNMENT` |
| `var` / 可写 `static var` | ❌ `TC_ERR_STRUCT_IMMUTABLE_FIELD` | ✅ 合法（RHS 类型须与字段类型一致） |
| 函数形参 | ❌ `TC_ERR_PARAMETER_ASSIGNMENT` | ❌ `TC_ERR_PARAMETER_ASSIGNMENT` |

说明：

1. 外层为不可变绑定（`let` / `static let`）时，**任何**字段赋值均非法——即使该字段在结构体定义中声明为 `var`。
2. 外层为可变绑定且字段为 `let` 时，禁止字段赋值；需要更新 `let` 字段只能通过整块赋值替换整个结构体值。
3. 外层绑定必须在当前程序点已确定初始化；字段赋值不改变该绑定的已初始化状态（与普通赋值覆盖相同）。
4. 未知字段名 → `TC_ERR_STRUCT_UNKNOWN_FIELD`；左侧基址不是结构体类型 → `TC_ERR_TYPE_MISMATCH`。

```tc
let let_demo: Demo = Demo(lid: 1, vid: 2)
; let_demo.lid = 3      ; ❌ TC_ERR_CONSTANT_ASSIGNMENT（外层 let）
; let_demo.vid = 4      ; ❌ TC_ERR_CONSTANT_ASSIGNMENT（外层 let）

var var_demo: Demo = Demo(lid: 10, vid: 20)
; var_demo.lid = 11     ; ❌ TC_ERR_STRUCT_IMMUTABLE_FIELD（字段为 let）
var_demo.vid = 21       ; ✅ 合法（外层 var + 字段 var）

var_demo = Demo(lid: 100, vid: 200)   ; ✅ 整块替换（含 let 字段）
```

#### 3.9.6 与其他特性的边界

| 特性 | 规则 |
| ---- | ---- |
| I/O | `write`/`writeln`/`read` 仍仅接受 `scalar_type`；结构体须按字段自行标量 I/O |
| `cast` / `bitcast` | 不以结构体为源或目标 |
| 比较 / 算术 / 位 / 逻辑 | 不接受结构体类型参数或操作数 |
| `memblock` | 结构体字段类型可为 `memblock<T>`（只写 `T`）；无长度概念（§3.8.0、§3.9.3）；`memblock` 元素类型仍不得为结构体 |
| 模块 | 类型定义区位于 `import` 之后、值声明/`func` 之前（§4）；结构体名参与模块命名空间冲突检查 |

## 4. 程序结构与模块系统

一个 TC 编译单元恰好是一个 `.tc` 源文件，一个源文件恰好定义一个模块。除空行和纯注释行外，源文件的首行必须是模式指令 `#program` 或 `#lib`；指令不是语句，不得重复，也不得位于模块中部。未显式声明模式的文件为语法错误。

模块是全程序唯一的静态命名空间，不是值或运行时对象。模块不能实例化、复制、赋值、作为实参传递或作为返回值；TC 不定义模块实例身份、构造或多实例生命周期。`<模块名>.<成员名>` 与 `Self.<成员名>` 是静态名称限定形式，其中 `.` 不是通用的运行时成员访问运算符。

**模块语句分层排序规则**：除空行和纯注释行外，模块内顶层构造必须按以下固定层级顺序依次出现，跨层交错为静态错误 `TC_ERR_MODULE_LAYER`：

1. **第一层**：模式指令 `#program` 或 `#lib`（文件首个有效行）；
2. **第二层**：`import` 声明区（所有 `import` 连续出现，可为空）；
3. **第三层**：类型定义区——`struct` 定义（`#lib` 中须带 `public` / `private`；`#program` 中不得带可见性修饰符）。所有 `struct` 必须连续出现在本层，且位于任何值声明或 `func` 之前；跨层交错报 `TC_ERR_MODULE_LAYER`；
4. **第四层**：值声明定义区——`#lib` 中为 `static var` / `static let`（须带 `static` 关键字）；`#program` 中 `static var` / `static let` 为 `TC_ERR_PROGRAM_MODE_MISUSE`，仅允许顶层 `var` / `let`（不得使用 `static` 关键字）；
5. **第五层（最末等）**：
   - `#lib` 模块：`func` 函数定义。函数定义只允许在 `#lib` 模块中出现，且全部函数定义必须在所有 `static var` / `static let` 之后；违反该排序报 `TC_ERR_MODULE_LAYER`。
   - `#program` 模块：顶层可执行语句。`#program` 不得定义函数（出现 `func` 报 `TC_ERR_PROGRAM_MODE_MISUSE`），第四层之后直接进入顶层语句区；语句区可以为空，此时程序运行到文件末尾后正常终止。`#program` 一旦进入顶层可执行语句区后若再出现 `var` / `let` / `var_funcall_def`，报 `TC_ERR_MODULE_LAYER`（语法阶段拒绝）。

各层内部构造之间允许任意空行和纯注释行，但不得插入其他层的构造。前四层全部处理完毕后，才允许进入第五层的 `func` 定义区或顶层语句区。模块中不得超过一个模式指令，且不得有跨层构造。结构体类型名在定义成功后即可被同模块后续的值声明、函数签名与其他结构体字段类型引用；不得前向引用尚未定义的结构体名。

### 4.1 程序模式（`#program`）

`#program` 模块不得定义函数；`static var` / `static let` 声明定义属于 `#lib` 模块专有构造，不得在 `#program` 中使用。因此“带辅助函数的完整小程序”在 0.0.35 中至少需要 `#lib` + `#program` 两个源文件；单文件内“顶层语句 + 辅助函数”的写法非法。此限制为有意设计，不是过渡缺口：任意可复用或需 `goto`/`label` 的逻辑必须放在独立的 `#lib` 中，并由 `#program`（或其他库）通过 `import` 调用。`#program` 由五层构成：模式指令行、`import` 区、`struct` 类型定义区、`var` / `let` / `var … = funcall(...)` 声明定义区，之后为顶层可执行语句区。声明显式位于第一条可执行语句之前，一旦进入语句区后不得再声明。每次运行重新初始化全部可达库模块的 `static var`，从第一条语句按源序执行至文件末尾或首个运行时错误。TC 无特殊 `main` 入口。`#program` 不得使用 `func`、`Self`、`static var`/`static let`、`public`/`private`；上述误用报告 `TC_ERR_PROGRAM_MODE_MISUSE`。

### 4.2 库模式（`#lib`）

`#lib` 模块只允许以下顶层构造，每种构造必须以 `public` 或 `private` 关键字作为第一个修饰符，必须显式书写，无默认值：

- `public struct` 或 `private struct` 结构体类型定义（§3.9；必须位于全部 `static` 成员与 `func` 之前）；
- `public func` 或 `private func` 函数定义；
- `public static let` 或 `private static let <名>: <类型> = <const_rhs>` 模块常量；
- `public static var` 或 `private static var <名>: <类型> = <rhs>` 模块变量。
- 可见性修饰符只允许在 `#lib` 模块中使用；`#program` 模块出现 `public` 或 `private` 报 `TC_ERR_PROGRAM_MODE_MISUSE`。缺少可见性修饰符的库成员定义报 `TC_ERR_MISSING_VISIBILITY`。
- `public` 表示该成员可被导入者通过 `<模块名>.<成员名>` 访问；`private` 表示仅限本模块内部使用。对 `public struct`，导入者可将 `<模块名>.<结构体名>` 用作类型名与值构造器名。

`struct` 位于 `static` 成员与 `func` 之前；`static` 成员位于 `func` 之前。`static` 成员之间及函数定义的顺序不限，违反层序报 `TC_ERR_MODULE_LAYER`。

库模块不存在顶层语句区；未带 `static` 的顶层 `let` / `var`、赋值、调用、I/O 和控制流均为语法错误。`static let` 遵守 §5.2.1 的编译期常量规则。`static var` 初始化器不得包含 `funcall`，并且只得引用源序中更早已成功初始化的 `Self` 静态成员。

每个可达库模块的每个 `static var` 在一次程序运行中恰好对应一个模块静态存储槽，由宿主按源序初始化一次；完成初始化后不自动调用任何函数。同一模块无论被多少个模块直接或间接导入，所有调用均共享这唯一份静态存储；导入不复制状态。任一静态成员初始化失败时，整个程序准备失败，不得执行任何库函数或程序顶层语句。这些静态存储槽属于程序运行环境，不构成模块实例。

### 4.3 `Self` 成员限定

`Self` 是仅在 `#lib` 模块内有效的保留字，表示“当前模块命名空间”。它仅可作为限定名的首部，不是值、类型、运行时对象或可绑定的标识符。函数体内访问本库的函数或静态成员必须使用限定名 `Self.<名>`：

```tc
#lib

public static let step: int32 = 1
public static var count: int32 = 0

public func next() int32 then
    Self.count = add(int32, Self.count, Self.step)
    return Self.count
end

public func twice() int32 then
    var first: int32 = funcall(Self.next)
    return add(int32, first, Self.step)
end
```

`Self.<名>` 必须恰好解析为当前库模块的一个顶层 `func`、`static let` 或 `static var`。当它解析为 `static let` 绑定时只读，解析为 `static var` 绑定时可读且可赋值；二者的确定初始化在程序准备成功后对所有函数成立。库函数内对本库函数或静态成员使用未限定的裸名必须报告 `TC_ERR_FUNCTION_SCOPE_ACCESS`（须改为 `Self.<名>`），不得降级为笼统的 `TC_ERR_UNDEFINED_VARIABLE` / `TC_ERR_UNDEFINED_FUNCTION`；局部绑定和形参仍使用裸名。这一规则避免局部名与模块成员之间的隐式捕获。`Self` 只表示当前模块命名空间，不能用于访问导入模块；在 `#program` 中出现 `Self` 报 `TC_ERR_PROGRAM_MODE_MISUSE`。

### 4.4 库成员可见性

`#lib` 模块的顶层 `struct`、`func`、`static let` 和 `static var` 均为模块成员。每个成员必须以 `public` 或 `private` 关键字作为第一个修饰符，必须显式书写，没有默认可见性：

- `public` 表示该成员可被导入者通过 `<模块名>.<成员名>` 访问。公开函数可调用，公开 `struct` 可作为类型名与值构造器使用，公开 `static let` 可读，公开标量 `static var` 可读且可赋值（包括作为 `read` 目标）；公开 `memblock` / 结构体 `static var` 可读可赋值，但不得作为 `read`/`write`/`writeln` 的整块目标（§10）。公开 `static var` 构成显式的跨模块可变共享状态：共享须经限定名出现从而对阅读者可见，但一旦标为 `public`，即成为跨模块可变全局槽；规范不提供隐式隔离或写屏障，也不得将其跨模块写入降级为警告。
- `private` 表示该成员仅限本模块内部使用。私有成员只能通过 `Self.<成员名>` 在模块内部访问。

可见性只由声明前的 `public` / `private` 修饰符决定，与成员名的字符形式无关。局部 `var` / `let`、函数形参和标签不是模块成员，不能带有 `public` / `private` 修饰符。结构体字段声明中的 `let` / `var` 表示字段可变性（§3.9），不是模块可见性修饰符。

库内部使用 `Self.<成员名>` 可访问本模块的公开和私有成员。导入者使用 `<模块名>.<成员名>` 时只能解析公开成员。从导入者访问私有成员报告 `TC_ERR_PRIVATE_MEMBER_ACCESS`，不使用 `TC_ERR_UNDEFINED_VARIABLE` / `TC_ERR_UNDEFINED_FUNCTION`。

### 4.5 模块导入（`import`）

`#program` 和 `#lib` 都可以导入库模块。导入语法为 `import <模块名>`，其中模块名必须是一个 `identifier`：

```tc
#program

import counter

var value: int32 = funcall(counter.next)
writeln(int32, %d, value)
```

`import` 声明必须位于模式指令之后、所有类型与值声明之前（第二层），不得出现在函数体或控制流中。所有 `import` 须连续出现，不得与其他层交错（`TC_ERR_MODULE_LAYER`）。不得重复导入同名模块（`TC_ERR_DUPLICATE_IMPORT`），导入名不得与本模块成员冲突（`TC_ERR_IMPORT_NAME_CONFLICT`）。

`import xxx` 要求宿主的模块解析器唯一定位名为 `xxx.tc` 的源模块。导入目标必须声明为 `#lib`。找不到目标报 `TC_ERR_IMPORT_NOT_FOUND`；目标为 `#program` 报 `TC_ERR_IMPORT_NOT_LIB`；同一逻辑名对应多个目标报 `TC_ERR_IMPORT_AMBIGUOUS`。源语言不接受路径、扩展名或字符串形式的导入；搜索目录的配置属于宿主接口，不属于 TC 源语法。

导入名在当前模块中引入对全程序唯一目标模块命名空间的静态引用；导入不构造、复制或实例化模块。导入成员必须使用 `<模块名>.<成员名>` 限定，不得省略模块名；该成员还必须具有 `public` 可见性（§4.4），否则报 `TC_ERR_PRIVATE_MEMBER_ACCESS`。限定名中的模块名不是可求值的操作数，限定名整体在静态名称解析中确定其成员。0.0.35 不定义导入别名、选择性导入或通配导入。

**禁止循环导入**：以模块为顶点、`import` 为有向边建立完整模块依赖图。该图必须是有向无环图（DAG）；任一模块都不得经过一条或多条导入边回到自身。自导入、直接循环和任意长度的间接循环均报告 `TC_ERR_CIRCULAR_IMPORT`；即使环中的导入函数从未被调用，也不改变该结论。

```text
; a.tc: import b
; b.tc: import a             ; 非法：直接循环

; a.tc: import b
; b.tc: import c
; c.tc: import a             ; 非法：间接循环
```

在初始化任何 `static var` 或执行程序顶层语句之前，须完成整张可达依赖图的环检查。

准备一次程序运行时，宿主按依赖顺序先处理其全部可达导入库；同一模块在完整可达依赖图中恰好对应一个全程序唯一的命名空间，其每个 `static var` 恰好分配一个模块静态存储槽，并被所有导入者共享。任一依赖解析、静态检查或初始化失败时，整次程序准备失败。

函数签名在分析函数体和顶层语句前完成收集，因此 `#lib` 中函数可调用定义在其后的函数；调用图限制见 §8.6。每个函数构成独立控制流域，只有函数控制流域可以建立标签表和 `goto` 跳转。

**源构造种类**：模块导入（`import`）、变量/常量定义（`var`/`let`）、赋值、I/O（`write`/`writeln`/`read`）、结构化控制（`if`/`while`/`break`/`continue`）、函数体内 `goto`/`label`、函数定义/调用/返回（`func`/`funcall`/`return`）。

**程序结构约束**：模式指令必须为首个有效行且顶格；五层排序不得交错（`TC_ERR_MODULE_LAYER`）；每行至多一条语句，空行/注释行合法；`#program` 无 `func`；函数体、`if`/`while` 内不得定义函数；缩进见 §7.1.2；`goto`/`label` 仅可在函数体内，`while` 内禁止二者（§7.2.4）。

## 5. 声明

### 5.1 变量定义（`var`）

#### 5.1.1 语法

`var` **声明时必须初始化**。统一外形为：

```text
var <identifier>: <type> = <initializer>
```

其中 `<initializer>` 是普通 `<rhs>`，或用于接收非 `void` 返回值的专用 `funcall`。

| 项目 | 规则 |
| ---- | ---- |
| 初始化器 | 强制。`=` 与 `<initializer>` 不可省略 |
| 非法形态 | `var <identifier>: <type>`（无初始化器）→ 静态错误 `TC_ERR_VAR_MISSING_INIT` |
| RHS | 字面量、已定义标识符、单个运算、`cast` 或 `bitcast`（见 §6.1.1）；须与声明类型一致 |
| 函数返回初始化 | 非 `void` `funcall` 可通过专用形态 `var <名>: <类型> = funcall(...)` 初始化新变量（§8.2）；`funcall` 不属于普通 RHS |
| 再赋值 | 首次引入之后，修改写作 `<identifier> = <rhs>` 或 `<identifier> = funcall(...)`，不再写 `var`（§6.2） |

0.0.35 不允许“先声明、后首次赋值”。`read` 也不能代替初始化器：目标变量必须先以带初始化器的 `var` 定义，`read` 仅覆盖当前值（§10.3）。

#### 5.1.2 语义与检查

- 当且仅当该条 `var` 语句执行成功后，变量持有初始化器求得的有效值（顶层、函数和块内均在定义行写入预先建立的固定槽位）。
- 每条 `var` 声明须经过语法/形态检查：缺 `=` 或初始化器 → `TC_ERR_VAR_MISSING_INIT`（打印名 `VarMissingInitializer`）。此检查与控制流无关，亦不依赖数据流分析；不得仅报笼统 `TC_ERR_SYNTAX`。
- 同一作用域内不可重复定义同名变量（作用域包括顶层、函数、`if`/`while` 块，以及 `then`/`else` 各自的互斥子块，见 §9.1、§7.1.5、§7.2.3）。跨类型值须先 `cast`；函数返回值则必须与接收类型严格相同。
- 声明带初始化器不等于该语句在所有路径上均已执行；完整的确定初始化规则见 §9.2 与 §7.3.4。

```text
var a: int32 = 10                 ; ✅ 声明并初始化
var b: int32 = add(int32, a, 20)  ; ✅
var c: int8 = cast(int8, truncate, a)
var flag: bool = true
var pi: float64 = 3.14
var e: float32 = 2.71828f

var d: int32                      ; ❌ TC_ERR_VAR_MISSING_INIT
; d = 1                           ; 即便其后赋值，仍不能补救无初始化器的声明
```

块内 `var` 的可见性和生命周期按 §9.1 处理；离开该块后引用其绑定属于未定义标识符错误。

### 5.2 常量定义（`let`）

使用 `let` 声明 不可变常量：

- RHS 必须 提供
- RHS 须为 §5.2.1 定义的单层编译期常量表达式
- `let` 声明类型是整个 RHS 的唯一期望结果类型；RHS 结果必须与声明类型完全一致，不执行隐式转换，具体检查与诊断见 §5.2.1
- 常量在编译期求值；使用处直接内联编译期结果，不生成运行时算术指令，亦不分配运行时变量槽（与 §9.2、附录 B 一致）。源文件中 `let` 语句仍占一行，仅作为编译期声明
- `let` 的求值与可见性只由编译阶段和词法源序决定，不以运行时控制流是否经过该声明行为条件；合法 `goto` 绕过一条 `let` 不会使其在后续词法可见位置变为“未初始化”或不可用
- 每条 `let` 声明仍参与源级可达性分析（用于判定其后续语句是否可达），但不生成运行时指令
- 常量 不可 作为赋值语句的左值
- 在同一作用域内，常量名不可与变量名或其他常量名冲突。

#### 5.2.1 编译期常量表达式

`let` 的 RHS 可包含以下任一形式：

**原子表达式**：
- 整数字面量（`42`、`-128`、`0xFFu`）
- 浮点字面量（`3.14`、`2.71828f`、`1.0e-5`）
- 特殊浮点值（`inf`、`-inf`、`nan`）
- 布尔字面量（`true`、`false`）
- 此前已定义的 `let` 常量引用（`PI`、`MASK`）

**单个调用表达式**（每个操作数只能是上述原子表达式）：
- 算术运算：`add`/`sub`/`mul`/`div`/`mod`/`abs`/`neg`，可使用 §6.3 允许的 `wrap` 或 `ieee` 模式；浮点 `mod` 同样支持 strict / `ieee`
- 位运算：`and`/`or`/`xor`/`not`（按位）、`shl`/`shr`（移位）
- 比较运算：`eq`/`ne`/`lt`/`le`/`gt`/`ge`（浮点比较允许但不推荐，因浮点精度）
- 逻辑运算：`and`/`or`/`xor`/`not`（布尔）
- 转换：严格 `cast`、整数 `cast(..., truncate, ...)` 与等宽 `bitcast`
- memblock 构造器：`memblock(T, count: c)`、`memblock(T, count: c, fill: v)` 和 `memblock(T, count: c, v0, …, vₙ)`（§3.8.3）；其中 `count:` 计数值及全部填充/逐值操作数必须是编译期常量；`count:` 仅为构造分配参数，不引入 memblock 长度属性（§3.8.0）
- 结构体值构造器：`<结构体名>(字段: 常量操作数, …)`（或导入的 `<模块名>.<结构体名>(…)`），须满足 §3.9.2；每个字段实参必须是合法编译期常量操作数

**声明类型闭合与检查顺序**：

1. 先完成 `const_rhs` 内部的名称、运算支持类型、模式、操作数类型和字面量检查。单个调用表达式的操作数期望类型仅由该调用的显式类型参数决定；外层 `let` 声明类型不向调用内部传播，也不改变 §6.6.1.1 的 `cast` / `bitcast` 字面量源类型规则。
2. RHS 为直接字面量时，以 `let` 声明类型作为 §3.6 的期望类型：符号性、类别或浮点后缀不符时报 `TC_ERR_LITERAL_TYPE`，值不可表示时报 `TC_ERR_LITERAL_OUT_OF_RANGE`。
3. RHS 为标识符时，名称解析后以该绑定的声明类型为结果类型。若绑定解析为 `var` 或函数参数，立即报 `TC_ERR_CONSTANT_EXPRESSION`（"references runtime variable"），不再比较结果类型，也不进入编译期求值。RHS 为单个调用表达式时，按该调用的自身规则确定结果类型。若结果类型与外层 `let` 声明类型不完全一致，报 `TC_ERR_TYPE_MISMATCH`，定位到 RHS 的首个 Token。禁止因数值可表示而执行隐式窄化、加宽、符号性变换或整数/浮点转换。
4. 只有上述名称和类型检查全部成功后才进入编译期求值。因此“RHS 结果类型不匹配”先于同一 RHS 的常量溢出、除零或无效浮点操作诊断。

**约束**：
- 常量表达式不可 引用任何 `var` 变量
- 常量表达式不可 包含 `funcall`；函数体内的 `let` 亦不得引用参数或局部 `var`
- 常量表达式不可 引用自身或尚未定义的 `let`；此类引用在名称解析阶段被 `TC_ERR_UNDEFINED_VARIABLE` 拦截
- 操作调用不可嵌套；复合计算须拆分为多条按源序定义的 `let`
- 由于只允许引用此前的 `let`，多常量循环依赖在语法可见性上不可形成，0.0.35 不定义常量循环依赖错误；前向引用和自引用统一由 `TC_ERR_UNDEFINED_VARIABLE` 处理
- 有符号严格常量算术运算或 `shl` 的溢出，在编译期视为 常量溢出错误 并终止编译
- 常量 `shl` / `shr` 的移位计数按其整数类型直接取数学值；值为负时视为 常量表达式错误 `TC_ERR_CONSTANT_EXPRESSION` 并终止编译
- 严格浮点常量算术按 §6.3 的异常优先级求值：无效操作 → `TC_ERR_CONSTANT_EXPRESSION`，除零 → `TC_ERR_CONSTANT_DIV_ZERO`，上溢或下溢 → `TC_ERR_CONSTANT_OVERFLOW`；浮点 `mod` 不产生上溢或下溢
- 常量表达式中整数 `div`/`mod` 的除数为 0，或浮点严格 `div`/`mod` 的最高优先级异常为除零，视为 常量除零错误 并终止编译
- 常量移位、转换、NaN 与模式合法性完全复用 §6.3～§6.6 的运行时规则

常量表达式的“形态与依赖合法性”先于求值短路检查：`and(bool, false, x)` 或 `or(bool, true, x)` 中的 `x` 仍必须是合法、可见且已求值的更早 `let bool`。运行时逻辑短路和 §6.5.2.2 的确定初始化读边裁剪不得用于掩盖 `let` 中的非法依赖、名称或类型错误。

#### 5.2.2 静态布尔条件与三态判定

“静态布尔条件”是结果类型为 `bool`，且整体符合本节“编译期常量表达式”定义的单层 RHS。其原子操作数只能是字面量，或在当前词法作用域可见、定义语句位于使用点之前且已成功求值的 `let`；不得把 `var` 的当前值或跨语句运行时结果当作常量传播。

名称和类型检查完成后，对 `if`/`while` 条件执行以下三态判定：

  - 静态 `true`：RHS 合法且按本节共享常量语义求值为 `true`；仅 `then` 分支可达。
  - 静态 `false`：RHS 合法且求值为 `false`；仅 `else` 分支（如存在）可达。
  - `unknown`：RHS 不是合法的单层常量表达式，或含 `var` 等不能静态解析的操作数；`then` 与 `else` 分支均可达。

静态布尔判定只复用本节的表达式定义和 §6.3～§6.6 的共享语义，不建立第二套运算符白名单。布尔字面量、可见的更早 `let bool`、结果为 `bool` 的整数/浮点比较、布尔逻辑运算，以及目标为 `bool` 的合法严格 `cast` 均因此自然受支持；`bitcast` 不允许 `bool`，整数 `truncate` 也不能产生合法布尔条件。

三态判定与短路读边是两个独立分析结果。只要条件调用的任一操作数含 `var`，整个条件仍为 `unknown`，即使其左操作数足以由 `false and ...` 或 `true or ...` 决定运行时结果；§6.5.2.2 仍可单独删除右操作数的读取边。短路读边裁剪不改变三态判定的分支可达性结果，否则将改变 `TC_ERR_UNREACHABLE_STATEMENT` 的合法程序集合。

前向 `let`、不可见 `let`、嵌套调用或其他非法形态在内部静态判定中不得被折叠；它们仍分别由更早的名称、语法或类型阶段报告错误，因此不参与可达性分析。若表达式形态合法但求值发生整数/浮点溢出、除零、无效浮点操作或严格转换失败，必须按本节既有映射报告 `TC_ERR_CONSTANT_OVERFLOW`、`TC_ERR_CONSTANT_DIV_ZERO`、`TC_ERR_CONSTANT_EXPRESSION` 或 `TC_ERR_CONSTANT_CAST_OVERFLOW` 并终止编译；不得降级为 `unknown`。

#### 5.2.3 浮点常量算术的精度规则

常量表达式中的浮点算术遵循以下规则：
1. 每条指令均按其显式类型参数执行：`float32` 使用 binary32，`float64` 使用 binary64。
2. 每条指令结束时立即按 roundTiesToEven 舍入；不得统一提升为 `float64` 中间精度。
3. strict / `ieee` 的结果与同一指令在运行时执行完全一致。
4. 常量求值器不得使用 FMA、扩展精度、FTZ 或 DAZ。

```text
let PI: float64 = 3.141592653589793
let PI_SQ: float64 = mul(float64, PI, PI)          ; binary64
let F32_A: float32 = add(float32, 16777216.0f, 1.0f) ; binary32，结果仍为 16777216
let INF_OK: float32 = div(float32, ieee, 1.0f, 0.0f)   ; inf
let REM_OK: float64 = mod(float64, 5.5, 2.0)           ; 1.5
; let ERR: float64 = div(float64, 1.0, 0.0)            ; 常量除零
```

#### 5.2.4 示例

```text
let PI: float64 = 3.141592653589793
let MASK: uint32 = 0xFFFF_0000u
let DEBUG: bool = true

let PI_SQUARED: float64 = mul(float64, PI, PI)
let FLOAT_REM: float64 = mod(float64, 5.5, 2.0)    ; 1.5
let IS_POSITIVE: bool = gt(float64, PI, 0.0)       ; true
let DIFFERS: bool = xor(bool, IS_POSITIVE, false)  ; true

if IS_POSITIVE then                              ; 静态 true，仅保留真边
    writeln(bool, %t, true)
end

let FLAG_INT: int32 = cast(int32, DEBUG)      ; 1
let PI_INT: int32 = cast(int32, PI)           ; 3
let PI_U32: uint32 = cast(uint32, PI_INT)      ; 复合转换拆为两条 let
let PI_BITS: uint64 = bitcast(uint64, PI)

; let ERR1: int32 = add(int32, a, 10)        ; 错误：a 是 var 变量
; let ERR2: int32 = add(int32, mul(int32, 2, 3), 4) ; 错误：调用嵌套
; let ERR3: float64 = div(float64, 1.0, 0.0)  ; 错误：常量除零
; let ERR4: int32 = add(int64, 1, 2)          ; TC_ERR_TYPE_MISMATCH：RHS 结果为 int64
; let ERR5: float32 = 1.0                     ; TC_ERR_LITERAL_TYPE：无后缀浮点为 float64
```

块内 `let` 仍受 §9.1 的词法作用域约束。

## 6. 表达式与运算

### 6.1 右值表达式与操作数

#### 6.1.1 右值表达式（RHS）

| 产生式               | 结果类型           | 说明                            |
| -------------------- | ------------------ | ------------------------------- |
| `identifier`         | 标识符已声明类型   | 须已定义；受源序可见性约束      |
| `integer_literal`    | 由左侧变量类型决定 | 须满足字面量符号性及范围约束    |
| `float_literal`      | 由 `f`/`F` 后缀决定 | 无后缀为 `float64`，有后缀为 `float32`；须与上下文一致 |
| `float_special`      | 由左侧变量类型决定 | `inf`/`-inf`/`nan`              |
| `bool_literal`       | `bool`             | `true` 或 `false`               |
| `binary_arith_expr`  | 第一参数类型       | 五种双目算术运算（含浮点）      |
| `unary_arith_expr`   | 第一参数类型       | 两种单目算术运算（含浮点）      |
| `bitwise_expr`       | 第一参数类型       | 按位 `and`/`or`/`xor`（仅整数） |
| `unary_bitwise_expr` | 第一参数类型       | 按位 `not`（仅整数）            |
| `shift_expr`         | 第一参数类型       | `shl`/`shr` 移位运算（仅整数）  |
| `compare_expr`       | `bool`             | 六种比较运算（整数+浮点）       |
| `binary_logic_expr`  | `bool`             | `and`/`or`/`xor` 逻辑运算（布尔） |
| `unary_logic_expr`   | `bool`             | `not` 逻辑运算（布尔）          |
| `cast_expr`          | 第一参数类型       | 类型转换                        |
| `bitcast_expr`       | 第一参数类型       | 等宽位重解释                    |
| `memblock_load_expr` | 第一参数类型       | 从 memblock 读取一个元素         |
| `memblock_constructor` | `memblock<T>`    | 三种命名构造器（§3.8.3）：`count:` 零值 / `count:`+`fill:` 填充 / `count:`+逐值列表 |
| `struct_constructor` | 对应结构体类型     | 命名字段值构造器（§3.9.2）       |

`funcall` 不属于普通 `rhs`。它只在 `var <名>: <类型> = funcall(...)`、`<identifier> = funcall(...)` 或独立 `funcall(...)` 三种专用语法位置出现；其合法位置由被调函数返回类型决定（§8.2.3）。

字段读取 `<基址>.<字段名>` 属于 `operand`（§6.1.2），因此也可作为标识符类 RHS；它不是独立的运算产生式。

#### 6.1.2 操作数（Operand）

| 形式              | 约束                                                         |
| ----------------- | ------------------------------------------------------------ |
| *identifier*      | 先按词法作用域解析绑定并检查类型：解析为运行时 `var` 或参数时，必须在当前程序点已确定初始化（参数在函数入口已初始化，§9.2）；解析为 `let` 时，必须在使用点可见且已成功完成编译期求值，随后直接内联，不参与确定初始化检查 |
| *qualified_identifier* | `Self.<名>`（仅 `#lib`）：按 §4.3 / §8.4.1 解析为本库 `static let` / `static var`；只读或可写规则与绑定种类一致；`static var` 在程序准备成功后已确定初始化 |
| *imported_member_name* | `<模块名>.<名>`：按 §4.4 / §4.5 解析为已导入库的公开 `static let` / `static var`；可见性与读写规则同上 |
| *field_access*    | `<基址>.<字段名>`：基址为上述标识符形式之一，且其类型为结构体类型；字段名必须属于该结构体；结果类型为字段声明类型；对运行时 `var` 基址须确定初始化（§3.9.5） |
| *integer_literal* | 须满足字面量约束                                             |
| *float_literal*   | 须满足字面量约束                                             |
| *float_special*   | `inf`/`-inf`/`nan`，仅用于浮点类型上下文                     |
| *bool_literal*    | 仅用于 `bool` 类型上下文                                     |

因此，凡规范引用 `operand` 的位置——包括运算、转换、`funcall` 命名实参、`return` 和输出——均可使用符合本行规则的 `let` 标识符（含经 `Self.` / 导入限定解析到的 `static let`），以及结构体字段读取。只有运行时绑定读取才执行 `TC_ERR_UNINITIALIZED_VARIABLE` 检查；编译期 `let` / `static let` 永不因不属于 `IN` 集合而触发该错误。

不支持 嵌套：操作数不可为算术表达式、`cast`、`bitcast` 或 `funcall` 调用。复合计算须拆分为多条语句。结构体字段访问在 0.0.35 仅允许单层 `<基址>.<字段名>`，不支持 `a.b.c`。

### 6.2 赋值语句

对已定义变量重新赋值时 省略 `var`。右侧可为普通 `<rhs>` 或 `<funcall>`，结果类型须与变量已声明类型 完全一致。首次引入该名必须已通过 §5.1 的 `var … = …` 完成，不存在「无初始化器的声明 + 本赋值作为首次写入」写法。

赋值左侧可以是：

1. **整绑定目标**：裸标识符、`Self.<名>` 或 `<模块名>.<名>`（规则同前）；
2. **字段目标**：`<整绑定目标>.<字段名>`（§3.9.5）。

```text
var c: int32 = add(int32, a, b)
c = mul(int32, a, b)        ; 合法（普通 RHS 赋值）
c = cast(int32, d)          ; 跨类型须先 cast

var f: float64 = 3.14
f = mul(float64, f, 2.0)    ; 合法
f = cast(float64, 42)       ; 合法（整数 → 浮点）

var flag: bool = false
flag = true                 ; 合法
flag = lt(float64, f, 10.0) ; 合法
flag = and(bool, flag, true) ; 合法

var var_demo: Demo = Demo(lid: 1, vid: 2)
var_demo.vid = 3            ; 合法（外层 var + 字段 var）
; var_demo.lid = 4          ; ❌ 字段为 let（TC_ERR_STRUCT_IMMUTABLE_FIELD）

; #program 中（已 import nextlib）
var count: int32 = 0
count = funcall(nextlib.get_next)   ; 合法（funcall 赋值）
```

**约束**：
- 整绑定赋值左侧按当前值作用域解析：函数内普通查找失败但命中 §8.4.1 的本库顶层成员名索引时报告 `TC_ERR_FUNCTION_SCOPE_ACCESS`；除此之外未解析到值绑定时报告 `TC_ERR_UNDEFINED_VARIABLE`；解析为 `let` 或 `static let`（含经 `Self.` / 导入限定解析到的只读绑定）时报告 `TC_ERR_CONSTANT_ASSIGNMENT`；解析为函数参数时报告 `TC_ERR_PARAMETER_ASSIGNMENT`；只有解析为 `var` 或可写 `static var` 才继续类型与确定初始化检查。全局函数名不属于值绑定，不能成为赋值目标。
- 字段赋值额外遵守 §3.9.5：外层为 `let`/`static let` 时一律 `TC_ERR_CONSTANT_ASSIGNMENT`；外层可写但字段为 `let` 时报告 `TC_ERR_STRUCT_IMMUTABLE_FIELD`；外层为形参时报告 `TC_ERR_PARAMETER_ASSIGNMENT`。字段赋值的 RHS 结果类型须与**字段**声明类型完全一致（不是整个结构体类型）。
- 赋值目标必须在当前程序点已确定初始化；赋值不能补救被控制流绕过的声明初始化（§9.2）。
- 赋值 RHS 为普通 `<rhs>` 或 `<funcall>`（字段赋值同样允许二者，只要结果类型与字段类型一致）。`funcall` 只能直接出现在 `=` 右侧，不得嵌套在其他 RHS 内部。非 `void` `funcall` 的返回类型须与赋值目标声明类型严格相同；`void` `funcall` 不得用于赋值（应使用独立 `funcall(...)` 语句）。若 `funcall` 发生运行时错误，目标变量保留原值，随后程序终止。

### 6.3 算术运算

#### 6.3.1 运算模式总览

静态语义按操作 × 类型 × 模式矩阵判定：

| 运算 | 类型 | 合法模式 |
| ---- | ---- | -------- |
| `add`/`sub`/`mul`/`neg` | 有符号整数 | strict（无关键字）、`wrap` |
| `add`/`sub`/`mul`/`neg` | 无符号整数 | 固定模 `2^n`；不接受模式关键字 |
| `shl` | 全部整数 | strict（无关键字）、`wrap` |
| `div`/`mod`/`abs`/`shr` | 全部整数 | 无模式关键字 |
| `add`/`sub`/`mul`/`div`/`mod` | 浮点 | strict（无关键字）、`ieee` |
| `abs`/`neg` | 浮点 | 无模式关键字；纯符号位操作 |
| 比较、逻辑、位运算 | 对应合法类型 | 无模式关键字 |

组合不在上表时报告 `TC_ERR_TYPE_MISMATCH` 或 `TC_ERR_MODE_MISMATCH`。附录 A 已排除的形态属语法拒绝（`TC_ERR_SYNTAX`）；`let` 的 `const_shift_expr` 接受候选 `mode`（不合法组合报 `TC_ERR_MODE_MISMATCH`），运行时 `shift_expr` 不接受 `mode`。浮点 `wrap` 和无符号冗余 `wrap` 不支持。

#### 6.3.2 严格模式（默认）

**整数严格模式**（参见 §6.3.4～§6.3.6）：
- 有符号 `add`/`sub`/`mul`/`neg` 结果超范围 → 整数溢出错误
- 有符号 `abs(INT_MIN)` → 整数溢出错误
- `shl` 结果超范围 → 整数溢出错误
- `div` 除数为 0 → 除零错误；`div(INT_MIN, -1)` → 整数溢出错误

**浮点严格模式**（IEEE 754 异常检测）：
- 上溢 → 浮点溢出错误
- 下溢 → 浮点下溢错误
- 除零 → 除零错误
- 无效操作（0/0、∞−∞、0×∞） → 无效操作错误
- `nan` 参与 `add`/`sub`/`mul`/`div`/`mod` → 无效操作错误
- 浮点 `mod` 的被除数为无穷，或被除数和除数同时为零 → 无效操作错误；有限非零数对零取模 → 除零错误

浮点执行环境固定如下：

- `float32` 每条指令按 IEEE 754 binary32 执行并立即舍入；`float64` 按 binary64 执行并立即舍入。
- 固定舍入模式为 roundTiesToEven；不提供运行时舍入模式切换。
- 禁止保留超出目标类型的中间精度，禁止将独立 `mul`/`add` 融合为 FMA。
- 必须保留非规格化数；禁止 FTZ（flush-to-zero）与 DAZ（denormals-are-zero）。
- 下溢采用 tininess-after-rounding：结果舍入到目标类型后为微小结果且本次舍入不精确时才触发；精确的非规格化结果不触发下溢。有限结果舍入为无穷时定义为上溢。
- 同一指令同时满足多个异常条件时，只报告最高优先级：`FloatInvalidOperation` → `DivisionByZero` → `FloatOverflow` → `FloatUnderflow`。

为避免依赖宿主浮点异常标志，`add`/`sub`/`mul`/`div` 的特殊值分类必须按下表判定。表中“NaN”包含 quiet NaN 和由 `bitcast` 构造的 signaling-NaN 位模式；TC 不向程序暴露 signaling 状态。

| 运算 | 无效操作（最高优先级） | 除零 | 其他结果 |
| ---- | ---------------------- | ---- | -------- |
| `add` | 任一输入为 NaN；符号相反的两个无穷相加 | — | 遵循 IEEE 754 加法 |
| `sub` | 任一输入为 NaN；同号的两个无穷相减 | — | 遵循 IEEE 754 减法 |
| `mul` | 任一输入为 NaN；零与无穷相乘 | — | 遵循 IEEE 754 乘法 |
| `div` | 任一输入为 NaN；零除以零；无穷除以无穷 | 有限非零值除以正零或负零 | 遵循 IEEE 754 除法 |
| `mod` | 按 §6.3.7 的完整分类 | 按 §6.3.7 的完整分类 | 按 §6.3.7 的精确余数语义 |

strict 指令必须先完成上述分类，再以无限精度数学结果和目标格式正确舍入判定上溢/下溢；不得直接依赖 C99 表达式是否设置宿主 `fenv` 标志。发生运行时错误时，该指令没有结果提交。

#### 6.3.3 IEEE 754 标准模式（`ieee`）

仅用于浮点 `add`/`sub`/`mul`/`div`/`mod`。执行精度、舍入方式、非规格化数与禁止 FMA 的规则同 §6.3.2，但异常不终止程序。

对浮点 `mod` 而言，`ieee` 只表示沿用本节的非终止异常处理与 canonical quiet NaN 结果；取模核心仍是 §6.3.7 定义的“商向零截断”语义，不采用将商舍入到最近整数（中点取偶数）的余数语义。

| 场景       | IEEE 754 行为                   | 返回值           |
| ---------- | ------------------------------- | ---------------- |
| 上溢       | 舍入到 ±∞                       | ±`inf`           |
| 下溢       | 返回 0 或非规格化数             | `0` 或非规格化值 |
| 除零       | 返回 ±∞                         | ±`inf`           |
| 无效操作   | 返回 canonical quiet NaN         | `nan`            |
| `nan` 传播 | 算术输入含 NaN 时返回 canonical quiet NaN | `nan`      |

上表的“除零返回 ±inf”仅适用于浮点 `div`。浮点 `mod` 的除数为零时没有可表示的余数：`ieee` 模式返回 canonical quiet NaN；strict 模式下，`0 mod 0` 按无效操作处理，有限非零数对零取模按除零处理。浮点 `mod` 的其余特殊值规则见 §6.3.7。

符号按 IEEE 754-2019 确定（除法的无穷结果符号为两操作数异或）。无效操作和 NaN 输入统一返回**正号** canonical quiet NaN（`float32`=`0x7FC00000`，`float64`=`0x7FF8000000000000`），不传播输入符号/payload。通过 `bitcast` 构造的其他 NaN payload 参与 `ieee` 算术后仍规范化为 canonical quiet NaN。

```text
var big: float32 = 1.0e30f
var result: float32 = mul(float32, ieee, big, big)  ; inf
var nan_result: float32 = div(float32, ieee, zero, zero)  ; nan
```

#### 6.3.4 整数回绕模式（`wrap`）

**整数 `wrap`**：
- 按模 `2^n` 回绕，不报错
- 仅用于有符号 `add`/`sub`/`mul`/`neg`，以及有符号或无符号 `shl`
- 无符号 `add`/`sub`/`mul`/`neg` 已固定采用模 `2^n` 语义，不接受冗余 `wrap`
- `div`/`mod`/`abs`/`shr` 不接受 `wrap`
- 浮点类型不接受 `wrap`；位模式混合须先 `bitcast` 为等宽整数

#### 6.3.5 整数有符号运算（`int8`～`int64`）

| 指令                  | 语义                                                         |
| --------------------- | ------------------------------------------------------------ |
| `add` / `sub` / `mul` | 和 / 差 / 积；严格模式超范围报错，wrap 回绕                  |
| `div`                 | 商，向零截断（同 C 有符号 `/`）；除数为 0 → 除零错误；商不可表示 → 整数溢出错误 |
| `mod`                 | 余数符号与 被除数 相同；除数为 0 → 除零错误。 |
| `abs`                 | 返回绝对值；`INT_MIN` 时严格模式报错                         |
| `neg`                 | 返回相反数；`INT_MIN` 时严格模式报错，wrap 回绕              |

**特殊情形**（\(b \neq 0\)）：

| 表达式                   | 结果 | 说明                                                        |
| ------------------------ | ---- | ----------------------------------------------------------- |
| `div(T, INT_MIN(T), −1)` | —    | 整数溢出错误（数学商 \(+2^{n-1}\) 不可在 `<T>` 中表示） |
| `mod(T, INT_MIN(T), −1)` | `0`  | 余数为 0，不报错                                        |
| `abs(T, INT_MIN(T))`     | —    | 整数溢出错误                                            |
| `neg(T, INT_MIN(T))`     | —    | 严格模式时 整数溢出错误                                 |

```text
var g: int32 = 7
var h: int32 = -3
var i: int32 = div(int32, g, h)    ; i = -2

var j: int32 = -7
var k: int32 = 3
var m: int32 = mod(int32, j, k)    ; m = -1

var n: int32 = -42
var o: int32 = abs(int32, n)       ; o = 42
```

#### 6.3.6 整数无符号运算（`uint8`～`uint64`）

| 指令                  | 语义                                                |
| --------------------- | --------------------------------------------------- |
| `add` / `sub` / `mul` | 和 / 差 / 积；超范围 → 按模 2^n 回绕                |
| `div`                 | 数学整数商；除数为 0 → 除零错误                 |
| `mod`                 | 余数满足 `0 ≤ 余数 < 除数`；除数为 0 → 除零错误 |
| `abs`                 | 恒等返回                                            |
| `neg`                 | 返回 `0 - 操作数`，按模 2^n 回绕                    |

无符号算术天然采用模 2^n 回绕，其位级结果与有符号 `wrap` 模式下的同宽算术一致。

```text
var a: uint8 = 200
var b: uint8 = 100
var c: uint8 = add(uint8, a, b)    ; c = 44
```

#### 6.3.7 浮点运算（`float32`、`float64`）

| 指令                  | 语义                                                         |
| --------------------- | ------------------------------------------------------------ |
| `add` / `sub` / `mul` | 和 / 差 / 积；strict 检测异常，`ieee` 返回 inf/nan           |
| `div`                 | 商；strict 检测除零/无效操作，`ieee` 返回 ±inf/nan           |
| `mod`                 | 商向零截断的余数；strict 检测除零/无效操作，`ieee` 对异常返回 nan |
| `abs`                 | 清除符号位；包括 NaN、无穷和零在内均不报错，不接受模式关键字 |
| `neg`                 | 翻转符号位；包括 NaN、无穷和零在内均不报错，不接受模式关键字 |

`abs`/`neg` 是纯位操作：仅修改符号位并保留其余位，包括通过 `bitcast` 构造的 NaN payload。它们不属于可能触发浮点异常的算术指令。

**浮点 `mod` 的精确语义**：

设操作数为同一浮点类型 `T` 的 `a` 与 `b`。当二者均为有限值且 `b != ±0` 时，先在数学实数域定义

```text
q = trunc(a / b)        ; 向零截断为数学整数
r = a - q * b
```

结果为 `r` 在 `T` 中的精确表示。实现不得先以 `T` 执行 `a / b` 再相乘相减，因为中间商可能溢出或舍入，从而改变余数。对于同一 binary32/binary64 类型的两个有限输入，上述余数可由该类型精确表示，因此浮点 `mod` 本身不产生上溢或下溢。

- 非零结果满足 `abs(r) < abs(b)`，且符号与 `a` 相同；`b` 的符号不影响结果符号。
- 结果为零时保留 `a` 的符号：`mod(T, -0.0, b)` 与负数恰好整除均返回 `-0.0`。
- `a` 有限且 `b` 为正或负无穷时，结果按位等于 `a`。
- 任一输入为 NaN，或 `a` 为正/负无穷时：strict 报 `TC_ERR_FLOAT_INVALID`；`ieee` 返回 canonical quiet NaN。
- `a` 与 `b` 同时为零时：strict 报 `TC_ERR_FLOAT_INVALID`；`ieee` 返回 canonical quiet NaN。
- `a` 为有限非零值且 `b` 为正或负零时：strict 报 `TC_ERR_DIVISION_BY_ZERO`；`ieee` 返回 canonical quiet NaN。
- 异常优先级继续遵循 §6.3.2：NaN 或无穷被除数导致的无效操作优先于零除数诊断。

```text
var a: float64 = 3.5
var b: float64 = 2.0

var sum: float64 = add(float64, a, b)      ; 5.5（严格模式）
var prod: float64 = mul(float64, a, b)     ; 7.0
var quot: float64 = div(float64, a, b)     ; 1.75
var rem: float64 = mod(float64, 5.5, 2.0)  ; 1.5
var neg_rem: float64 = mod(float64, -5.5, 2.0) ; -1.5

; abs/neg 无模式且永远安全
var neg_val: float64 = -3.14
var pos_val: float64 = abs(float64, neg_val)   ; 3.14（无异常）

; IEEE 模式
var big: float32 = 1.0e30f
var inf_res: float32 = mul(float32, ieee, big, big)  ; inf
var mod_nan: float64 = mod(float64, ieee, 1.0, 0.0)  ; nan
```

### 6.4 位运算

本章定义整数位级操作，包括按位逻辑运算与移位运算。`and`、`or`、`xor`、`not` 均由类型参数重载：类型参数为整数时执行本章的按位运算，类型参数为 `bool` 时执行 §6.5 的布尔逻辑运算。浮点类型不参与这组重载。

> **重要约束**：移位计数必须与被移位数类型相同（`T`），不同位宽须先 `cast`。浮点不支持任何位运算（附录 A 仅接受 `int_type`，浮点类型参数属语法拒绝 `TC_ERR_SYNTAX`）。

移位计数不掩码，直接取其数学值：`k < 0` 报 `TC_ERR_NEGATIVE_SHIFT_COUNT`；`k >= n` 时 strict `shl` 报溢出，`wrap shl` / `shr` 返 `0`。若需取模移位，程序员可显式使用 `mod` 运算。

#### 6.4.1 按位逻辑运算（`and`、`or`、`xor`、`not`）

#### 6.4.1.1 总览

| 运算  | 名称     | 操作数数量 | 适用类型                     | 语义                             |
| ----- | -------- | ---------- | ---------------------------- | -------------------------------- |
| `and` | 按位与   | 2          | 整数类型（`int8`～`uint64`） | 每位：两操作数均为 1 → 1，否则 0 |
| `or`  | 按位或   | 2          | 整数类型                     | 每位：任一操作数为 1 → 1，否则 0 |
| `xor` | 按位异或 | 2          | 整数类型                     | 每位：两操作数不同 → 1，相同 → 0 |
| `not` | 按位非   | 1          | 整数类型                     | 每位取反                         |

> **重载规则**：`and`/`or`/`xor`/`not` 均由类型参数 `T` 重载——`T` 为整数时执行本章的按位运算，`T` 为 `bool` 时执行 §6.5 的逻辑运算。两类重载的操作数数量保持一致：`and`/`or`/`xor` 为双目，`not` 为单目。

#### 6.4.1.2 语法形式

```text
var a: int8 = -84              ; 二进制补码位模式为 0b1010_1100
var b: int8 = -16              ; 二进制补码位模式为 0b1111_0000

var and_res: int8 = and(int8, a, b)   ; 0b1010_0000 -> -96
var or_res:  int8 = or(int8, a, b)    ; 0b1111_1100 -> -4
var xor_res: int8 = xor(int8, a, b)   ; 0b0101_1100 -> 92
var not_res: int8 = not(int8, a)      ; 0b0101_0011 -> 83
```

#### 6.4.1.3 语义规则

1. 将操作数视为 无符号位模式（有符号数按二进制补码解释）。
2. 对每一位执行对应的逻辑操作。
3. 结果按目标类型 `T` 解释（有符号按补码回译，无符号直接取值）。

**溢出**：按位运算结果天然限制在 `T` 的位宽内，不会溢出，因此不支持 `wrap` 或 `truncate` 模式。附录 A 未为运行时或常量按位运算提供模式参数位置，写入这些关键字不符合 EBNF，报告 `TC_ERR_SYNTAX`。

**操作数约束**：两操作数必须与 `T` 一致（整数）。`T` 为 `bool` 时由逻辑运算产生式解析（§6.5）；`T` 为浮点时报 `TC_ERR_SYNTAX`。

#### 6.4.2 移位运算（`shl`、`shr`）

移位运算仅适用于整数类型。**被移位数与移位计数必须为相同类型 `T`**。移位计数按 `T` 的数值语义解码并直接取其数学值 `k`：有符号 `T` 按二进制补码解码，无符号 `T` 按非负整数解码。TC 不对 `k` 掩码，也不把负数按无符号位模式重解释。

`shl` 与 `shr` 共享以下前置检查：

1. 若 `k < 0`，立即触发 `TC_ERR_NEGATIVE_SHIFT_COUNT`；
2. 仅当 `k >= 0` 时，才继续判定 `k >= n`、严格溢出或回绕结果。

因此负移位计数错误的优先级高于 `shl` 的整数溢出检查，且不受 strict / `wrap` 模式影响。无符号移位计数在类型上恒为非负，不会触发本错误。

`k >= n` 是 TC 已定义的语言分支，不得先执行宿主 C99 的移位再修正结果：strict `shl` 报整数溢出，`wrap shl` 与 `shr` 返回 `0`。这一规则刻意不采用宿主硬件的计数掩码，也不采用 C99 的未定义行为。

#### 6.4.2.1 左移（`shl`）

- **适用类型**：整数类型（`int8`～`uint64`）。
- **调用形式**：
  - 严格模式（默认）：`shl(<T>, 被移位数, 移位计数)`
  - 回绕模式：`shl(<T>, wrap, 被移位数, 移位计数)`
- **语义**：
  - 按 §6.4.2 的共享规则取移位计数的数学值 `k`；`k < 0` 时触发 `TC_ERR_NEGATIVE_SHIFT_COUNT`。
  - 若 `k >= n`（`n` 为 `T` 的位宽）：
    - 严格模式：视为 整数溢出错误。
    - 回绕模式：所有位被移出，结果为 `0`。
  - **严格模式**（`k < n`）：
    - 计算数学结果：`result_math = 被移位数 * 2^k`
    - 若 `result_math` 超出 `T` 的可表示范围 → 整数溢出错误。
    - 否则存储结果。
  - **回绕模式**（`k < n`）：
    - 取 `(被移位数 * 2^k)` 的低 `n` 位位模式，按 `T` 解释。不报错。

```text
var x: int8 = 0b0111_1111   ; 127
var r1: int8 = shl(int8, x, 2)        ; 127*4=508 -> 溢出错误
var r2: int8 = shl(int8, wrap, x, 2)  ; 508 mod 256 = 0b1111_1100 -> -4

var y: uint8 = 0b1111_1111u
var r3: uint8 = shl(uint8, wrap, y, 4)  ; 255*16 mod 256 = 0b1111_0000 -> 240u
var r4: uint8 = shl(uint8, wrap, y, 8)  ; k=8 >=8 -> 0

var negative_count: int8 = -1
var bad: int8 = shl(int8, x, negative_count) ; TC_ERR_NEGATIVE_SHIFT_COUNT
```

#### 6.4.2.2 右移（`shr`）

- **适用类型**：整数类型。
- **调用形式**：`shr(<T>, 被移位数, 移位计数)` —— 无模式关键字（永不溢出）。
- **语义**：
  - 按 §6.4.2 的共享规则取移位计数的数学值 `k`；`k < 0` 时触发 `TC_ERR_NEGATIVE_SHIFT_COUNT`。
  - 若 `k >= n`，结果为 `0`。
  - **有符号类型**（`int*`）：执行 算术右移——高位补符号位。
  - **无符号类型**（`uint*`）：执行 逻辑右移——高位补 `0`。

当 `0 ≤ k < n` 时，右移还可等价地形式化为：无符号值取 `floor(x / 2^k)`；有符号非负值同样取 `floor(x / 2^k)`；有符号负值取 `floor(x / 2^k)`（向负无穷方向取整）。当 `k >= n` 时统一返回 `0` 是优先级更高的 TC 特例，因此不延续负数算术右移的符号填充结果。

```text
var neg: int8 = -128          ; 二进制补码位模式为 0b1000_0000
var r5: int8 = shr(int8, neg, 1)   ; -64 (算术右移)
var r6: int8 = shr(int8, neg, 8)   ; k=8 >=8 -> 0
var bad_count: int8 = -1
var r7: int8 = shr(int8, neg, bad_count) ; TC_ERR_NEGATIVE_SHIFT_COUNT
```

#### 6.4.3 位运算与常量表达式

`let` 常量表达式允许使用全部合法位运算。`shl` 可使用 strict 或 `wrap`；strict 溢出映射为常量溢出错误，`wrap` 与运行时一样保留低位。常量求值期间若移位计数的数学值为负，在编译期报 `TC_ERR_CONSTANT_EXPRESSION`；不延迟到运行时，也不映射为常量溢出。其余规则与 §5.2、§6.4.1、§6.4.2 完全一致。

### 6.5 比较运算与逻辑运算

#### 6.5.1 比较运算

#### 6.5.1.1 比较运算总览

所有比较运算统一支持整数和浮点类型。显式类型参数 `T` 同时是两个操作数各自的期望类型：

- 接受 两个类型均严格等于 `T` 的操作数（整数或浮点）；“两个操作数彼此同类型”但二者都不等于 `T` 仍然非法
- 返回 `bool` 类型值
- **整数比较**不涉及 `wrap` / `truncate` 模式关键字
- **浮点比较**使用 IEEE 754 普通比较谓词（NaN 为 unordered），不使用 `totalOrder`；仅接受无模式形式。
- 不产生溢出（比较本身无算术溢出风险）

`compare_expr` 仅接受整数或浮点类型参数，无模式位置。`eq(bool, ...)` 或带 `ieee` 的形态属语法拒绝（`TC_ERR_SYNTAX`）。标识符操作数类型不等于 `T` 时报 `TC_ERR_COMPARISON_TYPE_MISMATCH`（即使两操作数同类型也不降级）。字面量不兼容时使用 `TC_ERR_LITERAL_TYPE` / `TC_ERR_LITERAL_OUT_OF_RANGE`。

| 运算 | 名称     | 语义     |
| ---- | -------- | -------- |
| `eq` | 等于     | `a == b` |
| `ne` | 不等于   | `a != b` |
| `lt` | 小于     | `a < b`  |
| `le` | 小于等于 | `a <= b` |
| `gt` | 大于     | `a > b`  |
| `ge` | 大于等于 | `a >= b` |

#### 6.5.1.2 语法形式

```text
; 整数比较
var eq_result: bool = eq(int32, a, b)   ; false
var lt_result: bool = lt(int32, a, b)   ; true

; 浮点比较
var f_gt: bool = gt(float64, 3.14, 2.71)  ; true
; 注意：不支持 gt(float64, ieee, 3.14, 2.71) 形式

; nan 比较（IEEE 754）
var nan_val: float64 = nan
var eq_nan: bool = eq(float64, nan_val, nan_val)  ; false
var ne_nan: bool = ne(float64, nan_val, nan_val)  ; true
```

#### 6.5.1.3 语义规则

**整数比较**：
- 有符号类型按二进制补码解释后的数学值比较
- 无符号类型按非负整数值比较
- 混合符号性比较须先 `cast` 统一类型

**浮点比较**：
- `eq(+0.0, -0.0)` 为 `true`，`ne(+0.0, -0.0)` 为 `false`
- `nan` 与任何值（包括自身）执行 `eq`/`lt`/`le`/`gt`/`ge` 均返回 `false`，执行 `ne` 返回 `true`
- 上一规则同样适用于由 `bitcast` 构造的任意 NaN 位模式；比较不触发 strict 运行时错误，也不修改操作数位模式
- 本组指令不区分 NaN payload，也不提供总序；若需比较位模式，先 `bitcast` 为等宽整数

由上述规则，检测 NaN 的惯用写法是 `ne(float64, x, x)`；`eq(float64, x, nan)` 始终为 `false`，不能用于检测。

#### 6.5.2 逻辑运算

#### 6.5.2.1 逻辑运算总览

所有逻辑运算：
- 接受 `bool` 类型操作数
- 返回 `bool` 类型值
- 不涉及 `wrap` / `truncate` 模式
- 不产生溢出

逻辑产生式要求类型参数为 `bool`，无模式位置。带模式关键字或不符合产生式的形态属语法拒绝（`TC_ERR_SYNTAX`）。操作数不是 `bool` 时报类型或字面量错误。

| 运算  | 名称   | 操作数数量 | 语义                                            |
| ----- | ------ | ---------- | ----------------------------------------------- |
| `and` | 逻辑与 | 2          | 两操作数均为 `true` 时返回 `true`，否则 `false` |
| `or`  | 逻辑或 | 2          | 任一操作数为 `true` 时返回 `true`，否则 `false` |
| `xor` | 逻辑异或 | 2        | 两操作数不同时返回 `true`，相同时返回 `false`   |
| `not` | 逻辑非 | 1          | 操作数为 `true` 时返回 `false`，否则 `true`     |

#### 6.5.2.2 短路求值

**`and` 短路规则**：
- 左操作数为 `false` 时，不计算 右操作数，直接返回 `false`
- 左操作数为 `true` 时，计算右操作数并返回其值

**`or` 短路规则**：
- 左操作数为 `true` 时，不计算 右操作数，直接返回 `true`
- 左操作数为 `false` 时，计算右操作数并返回其值

**`xor` 求值规则**：
- `xor` 不短路，始终先读取左操作数，再读取右操作数，然后判断二者是否不同。
- 确定初始化分析必须记录两个操作数的读取；即使左操作数是字面量或已求值的 `let bool`，也不得裁剪右操作数读取边。

确定初始化分析处理短路语义时：当左操作数是布尔字面量，或是在当前词法作用域可见、定义语句位于使用点之前且已求值的 `let bool` 时，使用其编译期值判定右操作数不可达：`false and RHS` 与 `true or RHS` 均豁免 RHS 的变量确定初始化检查。左操作数为 `var` 时不做值推测，保守认为右操作数可达。

被短路排除的 RHS 不触发 `TC_ERR_UNINITIALIZED_VARIABLE`，但仍必须通过词法、语法、名称、类型、操作数数量与模式检查；前向或不可见 `let` 仍按名称解析规则报 `TC_ERR_UNDEFINED_VARIABLE`。

```text
#lib

public func check_short_circuit() void then
    let FALSE: bool = false
    let TRUE: bool = true
    goto use
    var pending: bool = true
    label use:
    var a: bool = and(bool, FALSE, pending) ; 合法：pending 的读取边被裁剪
    var b: bool = or(bool, TRUE, pending)   ; 合法：pending 的读取边被裁剪

    var runtime_false: bool = false
    var c: bool = and(bool, runtime_false, pending)
    ; 上一行仍报 TC_ERR_UNINITIALIZED_VARIABLE：var 的值不参与静态推测

    var d: bool = and(bool, FALSE, missing)
    ; 上一行仍报 TC_ERR_UNDEFINED_VARIABLE：名称检查不被短路绕过
    return
end
```

### 6.6 类型转换

#### 6.6.1 三种转换形式

| 形式 | 语义 | 类型约束 |
| ---- | ---- | -------- |
| `cast(T, operand)` | 数值转换 | 整数、浮点、`bool`；按本章做范围检查与舍入 |
| `cast(T, truncate, operand)` | 保留低位的整数缩窄 | 仅整数→更窄整数 |
| `bitcast(T, operand)` | 位模式不变的等宽重解释 | 等宽整数/浮点；`bool` 不参与 |

三种形式互不替代。

#### 6.6.1.1 字面量操作数的源类型

标识符操作数的源类型是其声明类型。字面量作为转换操作数时按下列规则唯一确定源类型：

| 上下文 | 字面量 | 源类型规则 |
| ------ | ------ | ---------- |
| `cast` | 无后缀整数 | `int64`；数值必须先在 `int64` 范围内 |
| `cast` | `u`/`U` 整数 | `uint64` |
| `cast` | 浮点 | `f`/`F` 后缀为 `float32`，无后缀为 `float64`；`inf`/`-inf`/`nan` 以目标类型为源类型 |
| `cast` | 布尔 | `bool` |
| `bitcast` | 整数 | 源位宽取目标位宽，后缀决定有/无符号；字面量必须能由该同宽整数类型表示 |
| `bitcast` | 普通浮点 | `f`/`F` 后缀为 `float32`，无后缀为 `float64` |
| `bitcast` | `inf`/`-inf`/`nan` | 目标为 32 位时源为 `float32`，目标为 64 位时源为 `float64` |

因此 `cast(float32, 1.0)` 是从 `float64` 到 `float32` 的数值转换；`bitcast(float32, 1.0)` 因源类型 `float64` 而报 `TC_ERR_BITCAST_WIDTH`（须写 `1.0f`）。非 `let` 中严格 `cast` 的字面量按运行时指令处理溢出；`let` 中映射为 `TC_ERR_CONSTANT_CAST_OVERFLOW`。`inf`/`-inf`/`nan` 作为 `cast` 操作数时以目标类型为源类型，直接构造目标类型的 canonical NaN。

#### 6.6.2 整数严格转换规则（strict）

严格整数转换统一依据数学值判定，与源/目标位宽关系无关：

1. 将源位模式按源类型解释为数学整数 `v`。
2. 若 `min(T) ≤ v ≤ max(T)`，结果为目标类型中表示同一数学值的位模式。
3. 否则报 `TC_ERR_CAST_OVERFLOW`。

因此无符号缩窄同样检查范围；例如已有 `var wide: uint16 = 256u` 时，`cast(uint8, wide)` 必须报错。需要显式保留低位时使用 §6.6.3 的 `truncate`。

#### 6.6.3 整数截断转换规则（`truncate`）

设源、目标位宽分别为 `n`、`m`：

- 源与目标必须均为整数类型，且必须满足 `m < n`。
- 将源视为 `n` 位位模式 `bits`，结果位模式为 `bits mod 2^m`，再按目标整数类型解释。
- 不执行范围检查，不报溢出。
- `m >= n` 时为静态错误 `TC_ERR_MODE_MISMATCH`；加宽应使用严格 `cast`，等宽位重解释应使用 `bitcast`。

```text
var big: int32 = 1000
var trunc: int8 = cast(int8, truncate, big) ; 低 8 位 0xE8 → -24
```

#### 6.6.4 浮点转换规则

| 转换方向              | 规则                                                         |
| --------------------- | ------------------------------------------------------------ |
| 整数 → 浮点           | 按 roundTiesToEven 转为目标浮点；允许精度舍入；有限整数若转换为无穷 → `TC_ERR_CAST_OVERFLOW` |
| 浮点 → 整数           | 向零舍入；结果超出目标整数范围，或源为 `nan`/`inf` → `TC_ERR_CAST_OVERFLOW` |
| `float64` → `float32` | 按 roundTiesToEven 舍入；有限源值若转换为无穷 → `TC_ERR_CAST_OVERFLOW`；舍入为非规格化数或零则合法 |
| `float32` → `float64` | 有限值无损精度提升（总是合法）                               |

浮点数值转换还须遵守：正负零保留符号，正负无穷保留符号；源为 NaN 且目标仍为浮点时，结果为目标类型的 canonical quiet NaN。同类型 `cast` 为恒等操作并保留完整位模式；若需在等宽不同类型间保留 NaN payload，必须使用 `bitcast`。

所有范围检查均在提交目标值之前、基于源值的精确数学值完成。尤其是浮点转整数时，必须先判定 NaN/无穷和截断后数学整数的范围，再执行后端转换；AOT 不得先执行可能在 C99 中产生未定义行为的越界浮点转整数强制转换。整数转浮点和浮点窄化必须直接正确舍入到目标格式，不得通过额外中间类型造成二次舍入。

```text
var i: int32 = 42
var f: float64 = cast(float64, i)        ; 42.0
var pi_f: float64 = 3.14159
var pi_int: int32 = cast(int32, pi_f)    ; 3（向零截断）
var huge: float64 = 1.0e100
; var err: int32 = cast(int32, huge)    ; 转换溢出错误
```

#### 6.6.5 `bool` ↔ 整数/浮点转换

| 方向               | 规则                                           |
| ------------------ | ---------------------------------------------- |
| `bool` → 整数/浮点 | `true`（字节 `0x01`）→ `1`/`1.0`，`false`（字节 `0x00`）→ `0`/`0.0` |
| 整数/浮点 → `bool` | `0`/`0.0` → `false`（`0x00`），非零 → `true`（`0x01`，含 `nan`） |

提交到 `bool` 目标槽或 `memblock<bool>` 元素时，结果字节必须已是 §3.4 的规范形式；不得保留“非零即真”的其它字节值。

```text
var flag: bool = true
var as_int: int32 = cast(int32, flag)      ; 1
var as_float: float64 = cast(float64, flag) ; 1.0
var back: bool = cast(bool, 3.14)          ; true（0x01）
```

#### 6.6.6 等宽位重解释（`bitcast`）与速查

`bitcast(TargetType, operand)` 保持源位模式的全部位不变，仅改用目标类型解释：

- 源与目标必须为整数或浮点类型，且位宽完全相同。
- `bool` 不允许参与，否则报 `TC_ERR_TYPE_MISMATCH`。尽管 `bool` 抽象宽度为 8 位（与 `int8`/`uint8` 相同），仍禁止 `bitcast`，以免把非 `0x00`/`0x01` 字节写入 `bool` 绑定；`bool` ↔ 整数/浮点只能经 §6.6.5 的数值 `cast`。
- `memblock<T>` 与结构体类型不允许参与 `cast` / `bitcast`（§3.8、§3.9）；否则报 `TC_ERR_TYPE_MISMATCH`。
- 源、目标类型相同时是保持位模式不变的合法恒等操作。
- 位宽不一致报 `TC_ERR_BITCAST_WIDTH`。
- `bitcast` 不触发数值溢出，也不规范化 NaN payload。
- 位模式按 §3.5 的抽象位串定义；源、目标的宿主对象地址、对齐和内存字节序不参与语义。C99 AOT 应使用无别名未定义行为的复制或整数位运算策略实现。

```text
var f: float32 = -1.0f
var bits: uint32 = bitcast(uint32, f)       ; 0xBF800000u
var f2: float32 = bitcast(float32, bits)    ; -1.0f
; var bad: float64 = bitcast(float64, bits) ; TC_ERR_BITCAST_WIDTH
```

| 源 ↓ / 目标 → | 整数 | 浮点 | `bool` |
| ------------- | ---- | ---- | ------ |
| **整数** | strict `cast` 检查数学范围；更窄目标可显式 `truncate` | strict `cast` 做数值转换；等宽 `bitcast` 做位重解释 | 零为 `false`，非零为 `true` |
| **浮点** | strict `cast` 向零舍入并检查；等宽 `bitcast` 做位重解释 | strict `cast` 做精度转换；不同位宽禁止 `bitcast` | `±0.0` 为 `false`，其他值（含 NaN）为 `true` |
| `bool` | `false`→0，`true`→1 | `false`→0.0，`true`→1.0 | 恒等 |

### 6.7 memblock 操作

#### 6.7.1 memblock 变量定义

memblock 变量遵循 TC 现有的 `var` / `let` 规则，声明时必须初始化。声明类型只写 `memblock<T>`；初始化器创建（或复制）一块存储区，但**不**把容量登记为绑定的编译期长度属性（§3.8.0）：

```tc
var  mb: memblock<int32> = memblock(int32, count: 256)
let  MB: memblock<int32> = memblock(int32, count: 4, 1, 2, 3, 4)
let  N: uint64 = 256   ; 若需要范围，用独立整数自行跟踪
```

| 规则 | 说明 |
|------|------|
| 类型 | 仅为 `memblock<T>`；无长度属性（§3.8.0） |
| 强制初始化 | 不可省略初始化器，`var mb: memblock<int32>` 非法，与标量变量一致，触发 `TC_ERR_VAR_MISSING_INIT` |
| `let` 只读 | `let` memblock 编译期求值，不可作为 `memblock_store` / `memblock_copy` 的目标块 |
| `let` 常量 | `count:` 分配参数、`fill:` 填充值与逐值列表必须全是编译期常量 |
| 多维禁止 | `memblock<memblock<T>>` 不支持；附录 A 仅接受 `scalar_type` 元素，嵌套为 `TC_ERR_SYNTAX` |
| `funcall` 初始化 | 非 `void` `funcall` 可通过专用形态 `var <名>: memblock<T> = funcall(...)` 初始化新变量（§8.2）；返回值整块深拷贝到新绑定；`funcall` 不属于普通 RHS |

同一作用域内不可重复定义同名 memblock 变量，也不可与标量变量或常量冲突。

#### 6.7.2 memblock 操作

所有 memblock 操作遵循 TC 的 `op(类型, 操作数…)` 约定。

#### 6.7.2.1 读取 — `memblock_load`

```text
memblock_load(T, mb, index)
```

从 `mb` 中读取第 `index` 个元素，返回类型 `T`。`index` 为整数，0-based。类别：RHS。

```tc
var val: int32 = memblock_load(int32, mb, 3)
```

#### 6.7.2.2 写入 — `memblock_store`

```text
memblock_store(T, mb, index, value)
```

将 `value` 写入 `mb` 的第 `index` 个位置。`value` 类型必须与 `T` 严格一致。类别：独立语句（非 RHS）。

```tc
memblock_store(int32, mb, 3, 42)
memblock_store(uint8, buf, idx, 0xFFu)
```

#### 6.7.2.3 区间拷贝 — `memblock_copy`

```text
memblock_copy(T, dst, dst_index, src, src_index, length)
```

将 `src` 中从 `src_index` 起连续 `length` 个元素，按元素抽象位串复制到 `dst` 中从 `dst_index` 起的对应区间。类别：独立语句（非 RHS）。`length` 是**本次拷贝跨度**的操作数，不是 memblock 的长度属性；不改变两侧绑定的身份，不分配「新语言级长度」。

**操作数**：

| 位置 | 约束 |
| ---- | ---- |
| `T` | 显式元素标量类型；必须与 `dst`、`src` 的元素类型同时严格一致 |
| `dst` | `memblock_name`；必须是可写运行时绑定（局部/顶层 `var`、可写 `static var`，或函数形参 memblock——与 `memblock_store` 相同，只改副本元素）；`let` / `static let` 作目标 → `TC_ERR_CONSTANT_ASSIGNMENT` |
| `dst_index` / `src_index` / `length` | §6.1.2 `operand`，且均为整数类型（彼此类型可不同，也不必等于 `T`） |
| `src` | `memblock_name`；可为 `var` / `let` / `static` / 形参 / 导入公开成员；运行时 `var` 须确定初始化 |

**区间合法性**（半开区间，`extent` 为运行时所持存储容量，非语言属性）：

```text
n ≥ 0  ∧  0 ≤ d  ∧  0 ≤ s  ∧  d + n ≤ extent_dst  ∧  s + n ≤ extent_src
```

`n = 0` 合法（允许下标等于存储容量，不修改元素）。`n < 0` 或越界报告 `TC_ERR_MEMBLOCK_INDEX_OUT_OF_RANGE`（memblock 无长度属性，因此仅常量负值和已求值 `let` 可参与编译期越界判定，不能由构造时的 `count:` 推断存储容量上界）。

**抽象执行语义**：

1. 先读取并检查 `dst_index`、`src_index`、`length`；再确认 `dst` 与 `src` 在当前程序点可读/可写要求已满足。
2. 区间非法则不修改 `dst` 的任何元素，并按 §11.1 终止（运行时）或在可静态判定的负 `length` 等情形拒绝编译。
3. 区间合法时，语义等价于：先把源区间 `[s, s+n)` 的 `n` 个元素按抽象位串拷入长度为 `n` 的临时缓冲，再按相同顺序写入目标区间 `[d, d+n)`。因此：
   - `dst` 与 `src` 为不同绑定时，结果与逐元素 `load`/`store` 一致；
   - **同一绑定上的重叠区间**行为完全确定，等价于 `memmove`，不得依赖宿主 `memcpy` 的重叠 UB；
   - 不重新规范化元素位模式：源元素已是合法 TC 值（含 `bool` 的 `0x00`/`0x01`），拷贝保持位串不变。
4. 成功后 `dst` 仍为同一词法槽上的已初始化绑定；其已初始化状态不变（与赋值覆盖相同）。

```tc
var dst: memblock<uint8> = memblock(uint8, count: 16, fill: 0u)
var src: memblock<uint8> = memblock(uint8, count: 8, fill: 0xAAu)

memblock_copy(uint8, dst, 4, src, 0, 8)   ; dst[4..12) ← src[0..8)

; 同一块内重叠：行为确定（先快照再写回）
memblock_copy(uint8, dst, 2, dst, 0, 6)

; memblock_copy(uint8, dst, 0, src, 0, -1) ; ❌ length < 0
```

`memblock_copy` 不是 `let` 常量表达式的一部分；不得出现在 `const_rhs` 中。

#### 6.7.2.4 索引与拷贝区间检查

`load`/`store` 的 `index`，以及 `memblock_copy` 的 `dst_index`/`src_index`/`length`，都必须是整数类型的 `operand`。非整数类型报 `TC_ERR_TYPE_MISMATCH` 或 `TC_ERR_SYNTAX`（按产生式边界）。这些整数操作数的类型不必与 `T` 相同。

**单下标**（`load`/`store`）：索引解码为 `i` 后须满足 `0 ≤ i < extent`（`extent` 为实现持有的当前存储容量，非语言长度属性）。

**拷贝区间**（`memblock_copy`）：按 §6.7.2.3 的半开区间检查；空拷贝（`n = 0`）允许下标等于存储容量。

| 场景 | 诊断 |
|------|------|
| 编译期可确定的常量下标为负，或 `memblock_copy` 的常量 `length < 0` | 静态错误 `TC_ERR_MEMBLOCK_INDEX_OUT_OF_RANGE` |
| 运行时下标/区间不满足相对存储区容量的规则 | 运行时错误 `TC_ERR_MEMBLOCK_INDEX_OUT_OF_RANGE` |

负下标、负 `length` 或区间越界同属越界，不得静默回绕。由于 memblock 不具有语言层面的长度属性，仅整数字面量和已求值 `let` 可参与编译期越界判定；`var` 不参与。

```tc
; memblock_load(int32, mb, -1)    ; ❌ 负索引 → TC_ERR_MEMBLOCK_INDEX_OUT_OF_RANGE（可静态）
; memblock_copy(int32, dst, 0, src, 0, -1) ; ❌ length < 0
```

#### 6.7.2.5 约束

- 不可取 `memblock` 或其元素的地址，无 `&` 语义
- 不提供子块视图或切片；需要搬运连续元素时使用 `memblock_copy`，需要整块复制时使用赋值（只检查类型，§3.8.4）
- 不提供 `memblock_size`；需要范围时用独立整数绑定自行跟踪（§3.8.0）
- `memblock` 操作数可为局部/顶层 `var` 或 `let` 的裸名，或（在 `#lib` 内）`Self.<名>`，或已导入库的公开 `<模块名>.<名>`；名称解析与可见性规则与赋值目标一致（§4.3、§4.4、§8.4.1）
- `let` memblock 不可作为 `memblock_store` / `memblock_copy` 的目标（只读），与标量 `let` 相同，报 `TC_ERR_CONSTANT_ASSIGNMENT`；`let` 可作为 `memblock_copy` 的 `src`
- 索引与拷贝跨度须先写入局部变量或使用字面量/`let`，`memblock_load(T, mb, add(int32, base, offset))` 与 `memblock_copy(..., add(...), ...)` 不合法
- `memblock_load` / `memblock_store` / `memblock_copy` 的显式类型参数必须是元素标量类型，且与所涉 memblock 操作数的元素类型 `T` 一致；不一致报 `TC_ERR_TYPE_MISMATCH`
- `write` / `writeln` / `read` 的显式类型参数仅接受 `scalar_type`，禁止 `memblock<T>`（§10、附录 A）；整块 I/O 须由程序自行按元素循环读写

## 7. 控制流
### 7.1 条件分支语句（`if`）

TC 提供 Pascal 风格 的 `if-then-else` 条件分支语句，采用 缩进敏感 的块结构，并以 `end` 关键字作为块的强制结束标志。

#### 7.1.1 `if` 语句语法

**强制语法形式**（行结构敏感）：

```text
if <bool_rhs> then
    语句序列
[else
    语句序列]
end
```

- `<bool_rhs>` 必须产生 `bool`（§6.1.1）。`then` 位于 `if` 行末，之后只能有行末注释和换行。
- `else` 与 `end` 各自单独成行并与对应 `if` 对齐；`end` 不得省略。不支持单行 `else if`，多分支使用 §7.1.3 的嵌套形式。
- 语句序列可以为空；非空时按 §7.1.2 缩进。块内语句范围由附录 A 决定，不能嵌套 `func`；`goto`/`label` 还受 §7.3 的上下文限制。
- 缺少 `end` 或违反缩进规则均为静态错误。

#### 7.1.2 强制性缩进规则

| 规则编号 | 规则说明                                                     |
| -------- | ------------------------------------------------------------ |
| R1       | 行首缩进只能用 ASCII 空格 U+0020，禁止 Tab。Token 之间的 Tab 仍合法。 |
| R2       | 每 4 个空格为 1 级缩进，行首空格总数须能被 4 整除。 |
| R3       | `func`/`if`/`while`、`else` 和 `end` 行同级对齐。 |
| R4       | 块内语句比块关键字多一级；过多/过少或多组不一致均为缩进错误。 |
| R5       | `end` 行须等于块级缩进。 |
| R6       | 嵌套块的 `end` 与对应关键字对齐；内层块内语句再增一级。 |
| R7       | 函数内 `label` 不增缩进、不开启代码块，与同作用域语句同级。 |

> **源码示例约定**：本文所有标记为 `text` 的 TC 源码块均使用 4 个 ASCII 空格表示一级缩进。

#### 7.1.3 多分支写法（链式 `if-else`）

由于 `else if` 不允许写在同一行，链式分支的标准写法为：

```text
if <cond1> then
    语句序列1
else
    if <cond2> then
        语句序列2
    else
        if <cond3> then
            语句序列3
        else
            语句序列4
        end
    end
end
```

每个 `if` 都必须有对应的 `end`，且缩进逐级递增。

#### 7.1.4 执行语义

1. 计算 `<bool_rhs>` 的值。
2. 若为 `true`，执行 `then` 块内的所有语句，执行完后跳过 `else` 部分，直接跳至对应的 `end` 之后继续执行外层后续语句。
3. 若为 `false`，若存在 `else` 分支，则进入 `else` 块执行其内部语句（若 `else` 块内包含 `if`，则按 `if` 规则递归执行）。执行完 `else` 块后，遇到 `end` 继续执行外层后续语句。
4. 若条件为 `false` 且无 `else`，则直接跳至 `end` 之后执行。

#### 7.1.5 作用域与变量定义

- `then` 与 `else` 的直接语句序列分别构成独立的代码块与块级作用域。两者是互斥、互不包含且不可比的兄弟块；同一 `if` 内，`then` 侧定义的局部标识符在 `else` 侧不可见，反之亦然。因执行路径互斥，允许两侧分别定义同名局部变量（静态分析视为不同绑定）。
- 无 `else` 时只建立 `then` 代码块。`if` 条件在包含该 `if` 语句的外层作用域中求值，不另行建立可容纳语句的“整个 `if`”作用域。
- 代码块内允许使用 `var` 和 `let` 定义新的变量/常量；执行离开该分支代码块后，无法访问其中定义的任何局部标识符。
- 嵌套 `if` 时，内层块可访问外层块已定义的变量，除非被内层同名局部变量屏蔽。

#### 7.1.6 与 `let` 常量的交互

`let` 常量可在 `if` 块内定义，作用域同样限于该块。若 `if` 条件中引用 `let` 常量，其值是编译期确定的。

#### 7.1.7 与函数控制流的交互

`if` 可出现在顶层或函数体内。函数体各分支可使用 `return`；非 `void` 函数是否覆盖全部正常退出路径按 §8.3.2 和 §8.4 的函数返回路径规则判断。顶层 `return` 是静态错误。函数定义本身不得出现在任何 `if` / `else` 分支内。

### 7.2 循环语句（`while`）

TC 提供 Pascal 风格 的 `while` 结构化循环语句，采用 缩进敏感 的块结构，并以 `end` 关键字作为块的强制结束标志。

#### 7.2.1 语法定义

**强制语法形式**（行结构敏感）：

```text
while <bool_rhs> then
    语句序列
end
```

- `<bool_rhs>` 必须产生 `bool`（§6.1.1）。`then` 位于 `while` 行末，之后只能有行末注释和换行。
- `end` 单独成行并与 `while` 对齐，不得省略；循环体可以为空，非空时按 §7.1.2 缩进。
- 循环体语句范围由附录 A 决定，不能嵌套 `func`；`goto`/`label` 的额外禁令见 §7.2.4。

#### 7.2.2 执行语义

1. 计算 `<bool_rhs>` 的值。
2. 若为 `true`，执行 `then` 块内的所有语句（顺序执行）。
   - 若执行过程中遇到 `break`，立即退出整个 `while` 循环，跳转到对应的 `end` 之后继续执行。
   - 若遇到 `continue`，立即跳过当前迭代的剩余语句，跳转到步骤 1（重新计算条件）。
   - 若正常执行完块内所有语句（未遇 `break`/`continue`），先离开本轮循环体块实例，再返回步骤 1，开始下一次迭代。
3. 若为 `false`，直接跳转到对应的 `end` 之后，循环终止。

每次条件为 `true` 都进入一个新的循环体块实例；规范上的局部生命周期逐轮结束并重建。实现可以复用固定物理槽，但必须在确定初始化状态和可观察值上等价于重新进入。`continue`、正常回边和条件失败均按活动作用域与边规范化处理。

> **无限循环说明**：当 `<bool_rhs>` 恒为 `true`（如 `while true then`）时，循环仅能通过 `break` 终止（因 `while` 内禁止 `goto`），否则为无限循环。

#### 7.2.3 作用域与变量定义

- `while` 的 `then … end` 直接语句序列构成一个代码块与块级作用域；循环条件在包含该 `while` 语句的外层作用域中求值。
- 块内使用 `var` 和 `let` 定义的新变量/常量，在 `end` 之后不可访问。
- 嵌套循环时，内层循环可访问外层变量，除非被同名局部变量屏蔽。
- `break` 和 `continue` 作用于最内层包含它们的 `while` 循环。它们不能跨循环作用（即 `break` 不能跳出嵌套的外层循环，只能跳出直接包围它的循环）。
- 位于函数体内时，`break` / `continue` 的目标查找在当前函数边界停止，绝不作用于调用者中的循环。

#### 7.2.4 范式隔离原则（与 `goto` 的交互）

`while` 是结构化循环，只能用 `break`/`continue` 控制迭代；其词法后代中禁止 `goto` 和 `label`。非结构化循环须在函数内以不含 `while` 的 `if` + `goto` 构造（§7.3），顶层不能使用。

诊断先检查函数边界：函数外使用分别报告 `TC_ERR_GOTO_OUTSIDE_FUNCTION` / `TC_ERR_LABEL_OUTSIDE_FUNCTION`；仅当已确认位于函数内，具有 `while` 祖先的语句才分别报告 `TC_ERR_GOTO_INSIDE_LOOP` / `TC_ERR_LABEL_INSIDE_LOOP`。

#### 7.2.5 与初始化相关的静态分析

循环相关的静态分析必须覆盖：

- `break` / `continue` 是否处于合法的 `while` 上下文（§7.4）；
- 范式隔离：`while` 体内无 `goto` / `label`（§7.2.4）；
- 以条件失败、正常回边、`continue` 与 `break` 建立完整的可达路径与数据流；
- 按 §9.2 在全部可达路径上计算确定初始化。

除 §9.2 能在编译期证明条件恒为 `true` 外，循环体均可能零次执行，因此仅在循环体中执行的 `var` 不会自动进入循环后的确定初始化集合。恒真 `while` 不产生条件失败出口，仅可达 `break` 边参与循环后的会合；恒假 `while` 的循环体不可达。所有符合 0.0.35 的实现必须得到相同的分析结果。

### 7.3 受限 `goto` 语句

TC 提供仅限函数体内的受限 `goto`，是构建非结构化循环（`if` + `goto`）的基础工具。顶层不建立标签表，禁止 `goto`/`label`。

#### 7.3.1 设计原则

1. **函数内限定**：`goto` 与 `label` 须有 `func` 词法祖先，否则分别报 `TC_ERR_GOTO_OUTSIDE_FUNCTION` / `TC_ERR_LABEL_OUTSIDE_FUNCTION`。
2. **同函数限定**：每个函数独立标签表，`goto` 只解析当前函数内标签。
3. **只出不进**：仅允许跳转到祖先作用域（向外）或平级，禁跳入子作用域或兄弟分支（`then` ↔ `else`）。
4. **无源序方向限制**：支持前后跳转。
5. **范式隔离**：`goto` 和 `label` 不得在 `while` 体内（§7.2.4）。
6. **标签规则**：同块禁止同名标签；`goto name` 从最内层块沿祖先链查找，首个同名标签胜出。标签名与变量名属不同命名空间。
7. **初始化约束**：合法 `goto` 跳转进入可达性分析，变量可用性由 §9.2 确定初始化分析判定。

#### 7.3.2 语法定义

- `label <标识符>:` / `goto <标识符>` 各占一行，行末可注释。
- 仅可位于函数体直接层级或函数内无 `while` 祖先的 `if`/`else` 块。
- 按普通语句缩进；`label` 不开启代码块（§7.1.2 R7），但作为跳转目标，是可达性分析的入口点。
- `label` 无运行时动作，落入边继续执行；连续标签依次落入，块末尾标签落入该块正常退出续点。

```text
; ---- countlib.tc ----
#lib

public func count_to_ten() int32 then
    var i: int32 = 0
    label loop_start:            ; 函数体直接层级，不产生新缩进
    i = add(int32, i, 1)         ; 与 label 同缩进
    if lt(int32, i, 10) then
        goto loop_start          ; 函数内向外跳回 loop_start
    end
    return i
end

; ---- main.tc ----
#program

import countlib

var result: int32 = funcall(countlib.count_to_ten)
```

`#program` 通过导入调用库函数合法；如果把函数内任一 `goto` 或 `label` 移到 `#program` 顶层（或其嵌套块），即使缩进为 0、目标也在顶层，仍属于函数外使用并必须拒绝。

#### 7.3.3 作用域跳转的规则

设 `Src` 为 `goto name` 所在最内层代码块，检查顺序：

1. `goto` 无 `func` 祖先 → `TC_ERR_GOTO_OUTSIDE_FUNCTION`；
2. `goto` 有 `while` 祖先 → `TC_ERR_GOTO_INSIDE_LOOP`；
3. 沿 `Src` 祖先链由内向外查找 `name`，首个同名标签胜出；
4. 链上无匹配：后代优先于不可比块，报告 `TC_ERR_JUMP_INTO_BLOCK` 或 `TC_ERR_JUMP_INCOMPATIBLE_BLOCK`；
5. 跨函数 → 跨控制流域跳转；全无 → `TC_ERR_LABEL_NOT_FOUND`。

同块重复标签 → `TC_ERR_DUPLICATE_LABEL`；跨块同名合法。

#### 7.3.4 语义规则

1. `goto` 无条件转移至目标 `label`，`label` 无运行时动作，沿落入边继续。
2. 跳出作用域时局部变量立即销毁（§9.1/§9.2），后续引用报“未定义标识符”。
3. 每条 `goto` 建立到目标 `label` 的控制转移；向前、向后、同层与向外跳转均统一处理。
4. 确定初始化：按 §9.2，在目标点尚未确定初始化的绑定上读取、赋值或作为 `read` 目标 → `TC_ERR_UNINITIALIZED_VARIABLE`。
5. 越过 `var` 不自动出错（仅当其被使用且未初始化时才拒绝）；反向跳转重新初始化同一槽。
6. 允许 `goto` 跳出 `if` 块不经 `end`；`goto` 不改变存活变量值。
7. 跨函数跳转非法，报告相应错误。

示例：
```text
#lib

public func invalid_path() void then
    goto label_skip
    var x: int32 = 10
    label label_skip:
    writeln(int32, %d, x)   ; TC_ERR_UNINITIALIZED_VARIABLE
    return
end

public func valid_path() void then
    goto after_unused
    var unused: int32 = 10
    label after_unused:
    writeln(int32, %d, 0)    ; 合法：被跳过的 var 从未使用
    return
end
```

### 7.4 `break` 与 `continue` 语句

#### 7.4.1 语法定义

`break` 和 `continue` 各为一条独立语句，独占一行，无额外参数。

```text
break
continue
```

**缩进规则**：它们属于普通语句，必须遵循所在块（`while`、`if` 或嵌套块）的缩进规则，即缩进级别必须严格大于当前块级缩进。

#### 7.4.2 语义规则

| 语句       | 行为                                                         |
| ---------- | ------------------------------------------------------------ |
| `break`    | 立即终止最内层包含它的 `while` 循环，控制流跳转到该循环的 `end` 之后；离开该 `while` 块时，块内局部变量按 §9.1 / §9.2 销毁。 |
| `continue` | 立即结束当前迭代并离开本轮循环体块实例，控制流跳转到最内层包含它的 `while` 的条件求值处：重新计算 `<bool_rhs>`；若为 `true`，则建立新一轮块实例并从循环体首条语句起按源序重新执行（实现可复用同一局部槽，但其确定初始化状态已重置）；若为 `false`，则退出循环。`continue` 不会跳过条件求值而直接落到循环体中部。 |

**约束**：
- `break` 和 `continue` 必须直接或间接位于某个 `while` 循环体内（即其所在的词法作用域链中至少有一个 `while` 块）。
- 若 `break` 或 `continue` 不在任何 `while` 循环内，触发静态错误：
  - `TC_ERR_BREAK_OUTSIDE_LOOP`（针对 `break`）
  - `TC_ERR_CONTINUE_OUTSIDE_LOOP`（针对 `continue`）
- `break`/`continue` 可以出现在 `if` 块或其他嵌套块内，只要这些块本身位于 `while` 循环体内即可。
- 禁止使用 `break`/`continue` 跳出 `while` 直接到外层（例如想跳出两层循环，需改写结构化逻辑，或将该逻辑封装进函数后使用 `if` + `goto` 非结构化循环重构）。`break`/`continue` 的作用域目标是最内层 `while`，而非最内层 `if`。
- `break` 和 `continue` 的作用域目标仅为最内层包含它们的 `while` 循环，外围的 `if` 块不影响其合法性判定。
- 目标查找不得穿越函数边界；函数调用者中的 `while` 不会使被调函数内的 `break` / `continue` 合法。

#### 7.4.3 与 `if` 的典型组合

实际编程中，`break`/`continue` 常配合 `if` 条件使用：

```text
while lt(int32, i, 10) then
    if eq(int32, i, 5) then
        break
    end
    i = add(int32, i, 1)
end
```

#### 7.4.4 与 `let` 常量的交互

`while` 条件中可以引用 `let` 常量。强制 RHS 不因恒真/恒假循环而改变；`goto` 的限制见 §7.2.4 与 §7.3。

## 8. 函数与调用模型

### 8.1 函数定义与签名（`func`）

函数是仅允许在 `#lib` 模块中定义的显式可调用结构。`#program` 模块不得定义函数，其顶层可执行语句是程序入口；`#lib` 没有顶层执行入口。函数定义只在编译期建立签名和函数体，不产生顶层执行效果。

#### 8.1.1 定义形式

```text
public|private func <函数名>([<形参名>: <值类型> [, ...]]) <返回类型> then
    语句序列
end
```

- 形参类型可以是现有值类型（`bool`、8 种整数类型、2 种浮点类型）、`memblock<T>`（`T` 仅限 11 种标量类型；形参类型**只写** `memblock<T>`，无长度，§3.8.0）或已定义的结构体类型（§3.9）。`memblock<T>` 与结构体形参均严格按值传递：调用时按抽象布局整块深拷贝到被调函数的调用帧；memblock 形参类型无容量属性。二者与标量形参一样是只读绑定——对 `memblock` 形参，`memblock_store` / `memblock_copy` 以该形参为**目标块**时合法（修改副本内容），但 `param = <另一个值>` 以及对形参的任何字段赋值均不合法（禁止对形参整体或字段赋值，报 `TC_ERR_PARAMETER_ASSIGNMENT`）。
- 返回类型可以是上述值类型或 `void`。返回类型同样允许 `memblock<T>` 与结构体类型，返回时整块复制。
- 函数体直接语句必须比 `func` 行恰好多一个缩进级别；函数 `end` 必须与 `func` 行对齐。
- 函数体可以为空，但空函数体仍须满足返回路径规则；因此空的非 `void` 函数和空的 `void` 函数都会因可达函数末尾而报缺少返回。

#### 8.1.2 签名约束

- 函数名在源文件中唯一，不支持重载；不得与任何值绑定同名（覆盖顶层、任意嵌套块、参数及局部绑定）。全局函数名不受普通 RHS 解析，只有 `funcall` 的首项在函数签名表中解析。
- 形参名在同一函数签名中唯一。
- 形参按值传递，是函数入口处已初始化的只读绑定；不得赋值，也不得作为 `read` 目标。
- `void` 不是值类型，不得用作形参、`var`、`let`、转换目标、运算类型参数或操作数类型。
- 形参与任何局部值绑定若与全局函数同名，统一报告 `TC_ERR_FUNCTION_NAME_CONFLICT`；顶层嵌套块的值绑定也按同一规则处理，不因 `funcall` 与普通 RHS 使用不同查找入口而获准同名。函数内任何层级都不得声明与形参同名的 `var` / `let`；这一参数保护冲突继续报告 `TC_ERR_DUPLICATE_DEFINITION`。
- 函数签名在分析任何函数体和顶层语句之前完成收集，因此 `#lib` 中函数可调用定义在其后的函数；但调用图必须无环（§8.6）。

#### 8.1.3 定义位置

- 函数仅允许在 `#lib` 模块中定义；`#program` 模块不得定义函数。
- `#lib` 中所有 `static var` 和 `static let` 声明定义必须先于任何 `func` 定义出现；函数定义之间的顺序不限。
- `func` 不是语句，因而不得出现在函数体、`if` / `else` 分支或 `while` 循环体内。
- 不支持脱离 `func`、`if` 或 `while` 的匿名代码块。
- `main` 不是特殊名称；程序不因存在 `main` 函数而自动调用它。

非法示例：

```text
#program

var input: int32 = 10
writeln(int32, %d, input)

func get_value() int32 then   ; 非法：#program 不得定义函数（TC_ERR_PROGRAM_MODE_MISUSE）
    return 10
end
```

#### 8.1.4 不支持的函数形态

0.0.35 不支持函数重载、默认参数、可变参数、函数值、函数指针、闭包、嵌套函数、匿名函数、直接或间接递归、隐式参数转换、隐式返回转换和函数调用嵌套。函数不能隐式访问顶层值绑定；标准 I/O 副作用仍被允许。

### 8.2 函数调用（`funcall`）

#### 8.2.1 调用形式

```text
funcall(Self.<函数名> | <模块名>.<函数名>
        [, <形参名>: <operand> ...])
```

（附录 A 语法上亦接受裸 `identifier` 作为第一项，但按下方规则在静态语义中拒绝：`#program` 不得使用裸名或 `Self.`；`#lib` 对本库函数须写 `Self.`。）

非 `void` 函数（`#program`，已 `import mathlib`）：

```text
var total: int32 = funcall(mathlib.add_values, lhs: 10, rhs: 20)
```

`void` 函数：

```text
funcall(mathlib.show_value, value: total)
```

`funcall` 的第一项必须是静态函数名，而不是普通 RHS 或函数值。由于函数定义仅允许出现在 `#lib`（§4.1 / §8.1），调用目标的书写形式固定为：

- `#program` 顶层只能通过 `<模块名>.<函数名>` 调用已导入库的公开函数；不得使用裸 `identifier`，也不得使用 `Self.`（后者属 `TC_ERR_PROGRAM_MODE_MISUSE`）。
- `#lib` 函数体调用本库函数必须使用 `Self.<函数名>`；对已导入库函数必须使用 `<模块名>.<函数名>`。
- 在 `#lib` 中以裸 `identifier` 作为 `funcall` 第一项，且该名恰好是本库某个顶层 `func` 时，报告 `TC_ERR_FUNCTION_SCOPE_ACCESS`；该名不是本库函数时报告 `TC_ERR_UNDEFINED_FUNCTION`。

名称分别在对应导入模块的函数签名表，或（仅当使用 `Self.` 时）当前库模块的函数签名表中解析。

#### 8.2.2 命名且有序的实参

- 除函数名外，每一项必须使用 `<形参名>: <实参>` 形式。
- 每个形参恰好匹配一个实参；缺失、重复或未知名称均为静态错误。第 `i` 个实参必须命名为第 `i` 个形参，文本顺序不同也报错；实参不得被重排。
- 实参操作数严格按调用点从左到右读取并依次绑定。VM 与 AOT 不得改变该可观测顺序。
- **标量形参**的实参只能是附录 A / §6.1.2 的 `operand`：裸标识符、`Self.<名>`、`<模块名>.<名>`、字段读取、整数字面量、浮点字面量、浮点特殊值或布尔字面量。算术、位、比较、逻辑、转换、`memblock`/`struct` 构造器和 `funcall` 均不得直接作为标量实参。
- **`memblock<T>` 形参**的实参可为 `operand` 中的 memblock 标识符（含限定名），或附录 A 允许的 `memblock_constructor`（见下表）；不得使用算术、位运算或其他运算表达式。
- **结构体形参**的实参可为 `operand` 中的同类型结构体标识符（含限定名与单层字段读取——仅当该字段类型恰为该结构体时），或附录 A 允许的 `struct_constructor`；不得使用算术或其他运算表达式。
- 复杂值先写入临时 `var`；一条 `funcall` 只含一个运行时调用。
- 每个形参类型是对应实参的唯一期望类型，不做隐式转换。普通浮点字面量的源类型由后缀决定；整数字面量与浮点特殊值由形参提供上下文，并按 §3.6 检查。
- 当形参类型为 `memblock<T>` 时，实参可为以下形式之一：

| 实参形式 | 示例 | 说明 |
|---------|------|------|
| 标识符 | `buf: my_buf` | 已声明的 `var` / `let` memblock 变量 |
| 零值构造器 | `buf: memblock(uint8, count: 256)` | 编译期常量 |
| 填充构造器 | `data: memblock(int32, count: 100, fill: 1)` | 编译期常量；必须写 `fill:` |
| 逐值构造器 | `table: memblock(int32, count: 3, 1, 2, 3)` | 或已有 `let` memblock 标识符；位置实参数量须等于 `count` |

- 当形参类型为结构体 `S` 时，实参可为以下形式之一：

| 实参形式 | 示例 | 说明 |
|---------|------|------|
| 标识符 | `point: p` | 已声明的同类型 `var` / `let` |
| 值构造器 | `point: Point(x: 1, y: 2)` | 满足 §3.9.2 的命名字段构造 |

合法：

```text
; #program（已 import mathlib）
var total: int32 = funcall(mathlib.add_values, lhs: 10, rhs: 20)
```

下列位置实参、乱序实参和复杂实参均非法：

```text
var a: int32 = funcall(mathlib.add_values, 10, 20)
var b: int32 = funcall(mathlib.add_values, rhs: 20, lhs: 10)
var c: int32 = funcall(mathlib.add_values, lhs: add(int32, x, y), rhs: 20)
```

复杂实参必须拆分：

```text
var lhs_value: int32 = add(int32, x, y)
var total: int32 = funcall(mathlib.add_values, lhs: lhs_value, rhs: 20)
```

#### 8.2.3 返回值使用位置

非 `void` 函数调用的返回值可由**新声明的 `var` 接收**或**覆盖已有变量**；`void` 函数调用只能作为独立语句。三种合法形态如下：

```text
; #program（已 import nextlib）
var result: int32 = funcall(nextlib.get_value)    ; 新声明 var，接收非 void 返回值
result = funcall(nextlib.get_next)                ; 覆盖已有变量，返回值写入 result
funcall(nextlib.show_value, value: result)        ; 独立调用 void 函数
```

调用位置矩阵如下：

| 调用位置 | 非 `void` | `void` |
| --- | --- | --- |
| `var x: T = funcall(...)` | 合法 | 静态错误 |
| `x = funcall(...)` | 合法 | 静态错误 |
| 独立 `funcall(...)` | 静态错误 | 合法 |
| `let x: T = funcall(...)` | 语法错误 | 语法错误 |
| `return` 操作数位置 | 语法错误 | 语法错误 |
| 嵌套实参或其他运算操作数 | 语法错误 | 语法错误 |

`var x: T = funcall(...)`、`x = funcall(...)` 与独立 `funcall(...)` 都由语法接受；被调函数的实际返回类型不适合该位置时，报函数调用位置错误。

- 非 `void` 调用用于 `var` 声明时，实参合法后检查接收 `var` 的声明类型；不匹配时报调用结果类型错误。
- 非 `void` 调用用于已有变量赋值时，实参合法后检查目标变量的声明类型；不匹配时报调用结果类型错误。赋值目标必须在当前程序点已确定初始化（§9.2）。
- `void` 调用仅可独立成句，不得用于 `var` 声明或已有变量赋值。

返回值转发可通过新 `var` 或已有局部变量（不可对形参赋值）：

```text
#lib

public func get_value() int32 then
    return 1
end

public func add_next(value: int32) int32 then
    return add(int32, value, 1)
end

public func forward() int32 then
    var result: int32 = funcall(Self.get_value)
    return result
end

public func accumulate(start: int32) int32 then
    var total: int32 = start
    total = funcall(Self.add_next, value: total)  ; 读取后再覆盖局部 total
    return total
end
```

### 8.3 `return` 语句

#### 8.3.1 语法形式

```text
return [operand]
```

- 非 `void` 函数使用 `return operand`。
- `void` 函数使用裸 `return`。
- `return` 后最多一个 §6.1.2 定义的 `operand`；运算、转换或 `funcall` 不符合语法，必须先写入局部 `var`。

#### 8.3.2 静态语义

- `return` 只能出现在函数体内；顶层 `return` 是静态错误。
- 非 `void` 函数禁止裸 `return`；`void` 函数禁止 `return operand`。
- 返回标识符或普通字面量的类型必须与声明返回类型严格相同，不进行隐式转换。
- 整数字面量与浮点特殊值由返回类型提供期望类型上下文；浮点字面量仍由后缀决定类型。
- 每条从函数入口可达、会正常退出函数体的路径都必须经过匹配签名的显式 `return`。函数体 `end` 不产生隐式返回。
- 若存在从函数入口到函数体末尾的可达路径（即未经历 `return`），报缺少返回。
- 不要求证明一般程序终止。永久停留在 `while` 或受限 `goto` 循环、且没有到函数体末尾的可达路径时合法。
- `return` 终止当前执行路径，不执行其后的源序语句（`return` 之后的语句不可达，报 `TC_ERR_UNREACHABLE_STATEMENT`）。不再对“同一代码块内 `return` 之后到下一 `label` 之前”建立局部特例——`label` 需有来自可达语句的跳转才能作为可达入口。

```text
#lib

public func invalid_after_return() void then
    return
    var x: int32 = 0      ; TC_ERR_UNREACHABLE_STATEMENT
end

public func valid_label_entry(flag: bool) void then
    if flag then
        goto resume
    end
    return                 ; flag == false 时可达
    label resume:          ; 可由可达的 goto resume 边到达
    return
end
```

直接返回运算结果非法，必须拆分：

```text
; 非法
return add(int32, lhs, rhs)

; 合法
var result: int32 = add(int32, lhs, rhs)
return result
```

全路径返回示例：

```text
#lib

public func choose(flag: bool) int32 then
    if flag then
        return 1
    else
        return 2
    end
end
```

若删除 `else` 分支，`flag == false` 时会到达函数末尾，因而是缺少返回错误。

#### 8.3.3 运行时语义

`return` 按以下顺序执行：

1. 若存在返回操作数，在当前函数帧中读取其值。
2. 将结果复制到调用者拥有、且不随被调函数帧销毁的返回值位置。
3. 离开当前函数的所有活动块作用域。
4. 销毁当前函数帧。
5. 将控制权恢复到调用者的 `funcall` 之后。
6. 非 `void` 结果用于初始化调用点的新 `var`。

若读取返回值或执行被调函数期间发生运行时错误，整个程序立即终止；不执行正常返回流程，调用点的新 `var` 也不成为已初始化绑定。VM 与 AOT 可以采用不同清理机制，但不得恢复调用者继续执行。

### 8.4 函数作用域与控制流域

#### 8.4.1 名称查找和局部绑定

函数体内普通裸标识符按以下顺序查找：当前块、逐层外部块、函数体直接局部绑定、当前函数参数；到函数边界即停止。函数仅存在于 `#lib` 模块中。函数体仅可按 §4.3 以 `Self.id` 访问本模块的 `static let` / `static var` / `func`；该限定查找不参与局部词法作用域的屏蔽。

0.0.35 中 `#program` 不得定义函数，`#lib` 也没有非 `static` 的顶层值作用域，因此函数体内的普通裸名查找在到达函数边界后即停止，不会继续到模块顶层。`#lib` 函数体如需访问本模块的顶层成员（`func`、`static let`、`static var`），必须使用 `Self.<名>` 限定形式。

若函数体内使用裸名引用本库顶层成员（即忘记书写 `Self.` 限定），必须报告 `TC_ERR_FUNCTION_SCOPE_ACCESS`（提示应改为 `Self.<名>`），而不是报告 `TC_ERR_UNDEFINED_VARIABLE` 或 `TC_ERR_UNDEFINED_FUNCTION` 等笼统错误。此诊断规则统一适用于普通 RHS、赋值目标、`read` 目标、`let` 依赖、`funcall` 第一项与实参、以及 `return` 操作数。

- 函数体直接声明的 `var` / `let` 从声明完成后可见，到函数返回时失效。
- 同一作用域不得重复定义同名值绑定；内层块可按 §9.1 屏蔽普通外层局部绑定，但不得屏蔽参数或与任何全局函数同名。任意层级的 `var` / `let` 与当前函数形参同名均按参数保护冲突报告 `TC_ERR_DUPLICATE_DEFINITION`；与全局函数同名则报告 `TC_ERR_FUNCTION_NAME_CONFLICT`。两者都不解释为普通跨作用域屏蔽。
- 函数内 `let` 仍须在编译期求值，不得引用参数、局部 `var` 或 `funcall`。
- 参数在入口已初始化；函数内 `var` 仍须声明时提供初始化器。
- 函数返回时销毁所有局部运行时槽；`let` 继续编译期内联，不分配运行时槽。

#### 8.4.2 顶层与函数的控制流域

顶层语句区与每个函数各自构成独立的控制流域：可达性、确定初始化与返回路径彼此封闭。只有函数域支持 `goto`/`label` 与 `return`。`return` 只退出当前函数，`break`/`continue` 只解析到当前函数内最内层 `while`。`goto`/`label` 的查找、块关系和诊断严格按 §7.3 执行并在函数边界停止：跨函数或跳向顶层的跳转非法，不同函数中的同名标签互不相关。

### 8.5 调用模型

每次 `funcall` 在抽象机器上创建独立调用帧：绑定实参、容纳局部 `var`、记录返回续点，非 `void` 时另有返回值位置。物理布局不是可观察行为；VM 与 AOT 可以不同，但必须保持相同可观察语义。

调用步骤：

1. 按形参声明顺序，从左到右检查并读取实参操作数；任一运行时错误立即终止整个程序。
2. 创建被调帧并写入参数，从函数体首条语句执行。
3. `return` 销毁帧并恢复调用者；非 `void` 结果用于初始化调用点新 `var`，或覆盖已有目标变量。

若读取返回值或执行被调函数期间发生运行时错误，整个程序立即终止；不执行正常返回流程，调用点的新 `var` 也不成为已初始化绑定。

### 8.6 无环调用图

若程序中的函数调用关系包含直接或间接递归环，则为静态错误，无论相关调用点运行时是否可达。自调用是长度为 1 的环。

## 9. 作用域、生命周期与确定初始化

### 9.1 作用域

TC 采用全局函数签名表 + 顶层值作用域 + 函数作用域 + 块级作用域：

- **全局函数签名表**：函数名全局可见，不受定义源序限制；普通 RHS 不把函数名解析为值，只有 `funcall` 的第一项在该表中解析。全部函数签名在分析函数体与顶层语句前视为已收集，因此可调用后定义的函数，但调用图不得有环（§8.6）。
- **顶层值作用域**：`#program` 中不在 `if`/`while` 块内的 `var`/`let` 属顶层，遵循源序可见性，生命周期贯穿程序始终。`#lib` 无非 `static` 顶层值作用域，模块状态只能是 `static let`/`static var`（函数内通过 `Self.` 访问，§4.3）。
- **函数作用域**：每个函数体是独立作用域（含只读参数、局部 `var`/`let` 及嵌套块）。名称查找到函数边界即止。每次调用创建独立帧，不共享参数或局部变量。
- **块级作用域**：`if` 的 `then`/`else` 为互斥兄弟块；`while` 的 `then … end` 为循环体块。兄弟分支中标识符互不可见（允许同名）。嵌套块可屏蔽外层同名绑定，但禁止重新声明全局函数名与函数形参。块内 `var`/`let` 离开块后不可访问。
- **标签作用域**：标签限于函数体内，受函数边界与 `while` 隔离约束（§7.2.4）。`goto` 沿祖先链由内向外查找，首个同名标签胜出；同块禁止同名标签。每个函数有独立标签表，顶层无标签表。
- **源序可见性**：绑定从声明结束后的词法位置开始可见；初始化器不可引用当前绑定或尚未声明的标识符。`var` 在某条路径上是否已执行初始化由 §9.2 判定；`let` 统一在编译期求值内联，不以运行时路径是否经过其声明行为条件。
- **变量生命周期**：
  - 顶层变量：程序启动时建立固定槽位，执行到对应 `var` 后才成为已初始化；程序终止时销毁。
  - 参数：调用帧建立时写入并视为已初始化；函数返回时销毁。
  - 函数体/块内局部变量：进入作用域时建立固定槽位，执行到对应 `var` 时初始化；离开块实例（正常 `end`、循环回边、`break`/`continue`/`return` 或向外 `goto`）时结束生命周期。反向跳转或下一迭代再次执行同一 `var` 时，重新初始化同一词法槽。`let` 无运行时槽。

### 9.2 变量生命周期与确定初始化

声明时强制 RHS（强制初始化器）与确定初始化是两个独立保证：前者约束源代码形态，后者要求在每条可达执行路径上，每次对绑定的运行时读取（及赋值/`read` 目标）之前，相应的初始化语句确已执行。

| 事件 | 行为 |
| ---- | ---- |
| 作用域进入 | 建立本作用域全部 `var` 的固定槽位，初始为未初始化 |
| `var` 执行 | 先求值 RHS 或执行非 `void` `funcall` 初始化器，再写入槽位；成功后变为已初始化 |
| 赋值 / `read` / `memblock_store` / `memblock_copy` | 目标（及 `copy`/`store` 的目标块）必须已确定初始化；成功后更新槽内容，不改变生命周期 |
| 运行时绑定读取 | `var` 或参数必须在当前程序点确定初始化，否则静态错误 `TC_ERR_UNINITIALIZED_VARIABLE`；`let` 已在编译期内联，不适用本行 |
| 反向跳转 / 下一迭代 | 再次执行 `var` 时重新初始化同一槽，不创建新绑定 |
| 作用域离开 | 结束局部生命周期并清除其确定初始化状态；物理槽可复用 |
| 参数 | 函数入口已初始化，只读；不得赋值或作为 `read` 目标 |
| `return` | 终止当前函数路径，销毁当前函数帧及活动块局部槽 |

**路径语义（规范性）**：在某一控制流域入口到程序点 *p* 的每一条有限可达路径上，若绑定在 *p* 处仍处于生命周期内，且该路径上均已成功执行过其初始化语句，则该绑定在 *p* 处确定初始化。会合点取各可达前驱的合取：仅当所有可达路径均已初始化时成立。静态可证明恒真/恒假的条件按 §5.2 裁剪不可能边后，再判定可达性与确定初始化；不可达语句仍须通过词法、语法、名称与类型检查，但不参与确定初始化判定。不可达语句报 `TC_ERR_UNREACHABLE_STATEMENT`；函数末尾在入口可达且未经 `return` 则报缺少返回（顶层文件末尾为正常结束，不检查缺少返回）。

任何符合 0.0.35 的实现必须得到相同的合法程序集合与相同的首个相关诊断；具体求解算法不属于语言定义。

## 10. 标准 I/O

标准 I/O 仅操作标量类型（`int8`～`uint64`、`float32`、`float64`、`bool`）。`memblock` 和结构体类型参数属语法拒绝（`TC_ERR_SYNTAX`），须由程序按元素/字段自行完成。

### 10.1 `write` — 不换行输出

**形式一：无格式输出**

| 项目       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 语法       | `write(int32, x)`、`write(float64, pi)`、`write(bool, flag)` |
| 功能       | 将操作数的值按类型解释写入 stdout，不换行                |
| 操作数规则 | 一个 §6.1.2 `operand`：运行时 `var` / 参数须确定初始化，`let` 须可见且已成功求值，或使用合法字面量 |
| 类型约束   | 显式类型参数必须是 `scalar_type`；标识符绑定类型与该标量类型一致；字面量满足 §3.6 约束 |
| 输出格式   | 整数：十进制；浮点：与 `%g` 相同的 6 位有效数字；布尔：`true`/`false` |

操作数声明类型须与显式类型一致（`TC_ERR_TYPE_MISMATCH`），字面量不兼容时使用 `TC_ERR_LITERAL_TYPE` / `TC_ERR_LITERAL_OUT_OF_RANGE`。

**形式二：格式化输出**

| 项目       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 语法       | `write(int32, %d, x)`、`write(float64, %0.3f, pi)`、`write(bool, %-8t, flag)` |
| 功能       | 按格式说明符输出操作数的值，不换行                       |
| 操作数规则 | 一个 §6.1.2 `operand`；恰好一个操作数                      |
| 类型约束   | 显式类型参数为 `scalar_type`；操作数类型与其一致，且与格式说明符的转换符兼容 |

格式化类型检查顺序：先检查操作数与显式类型的一致性，成功后再检查转换符兼容性（`TC_ERR_FORMAT_TYPE_MISMATCH`）。两类不一致同时存在时先报告前者。

### 10.2 `writeln` — 换行输出

与 `write` 相同，但在输出末尾追加一个 LF 字节（`\n`），不随主机平台改写为其他行结束序列。会把文本流 LF 转换为其他字节序列的宿主上，AOT 必须使用二进制流或等价机制。`write`/`writeln` 向 stdout 写入失败时报 `TC_ERR_IO`。

每条 `write`/`writeln` 先生成本语句的完整输出字节串，再尝试一次抽象逻辑提交。只有全部提交成功时字节串才追加到 TC 抽象标准输出；失败时贡献零字节，此前已成功提交的输出不回滚。实现可缓冲或多次宿主导出完成一次提交，但不得重排成功语句。失败时物理写出的前缀属外部设备泄漏，不属于 TC 可观察行为。

### 10.3 `read` — 标准输入

| 项目     | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| 语法     | `read(int32, x)`、`read(float64, radius)`、`read(bool, flag)` |
| 功能     | 从 stdin 读取一个值，覆盖已定义变量的当前值              |
| 目标变量 | 必须是已通过带 RHS 的 `var` 声明、在当前程序点已确定初始化且类型与显式 `scalar_type` 一致的可写**标量**变量；函数参数只读，不得作为目标；`memblock` 目标不合法（语法拒绝） |
| 与初始化 | `read` 不是初始化器，不能代替 `var … = …` 或补救被控制流绕过的初始化 |
| 输入格式 | 见下表；跳过前导 ASCII 空白，并读取一个以 ASCII 空白或 EOF 结束的完整 Token |
| 错误处理 | 非法输入/数值超范围/非预期 EOF → I/O 错误                |

`read` 目标名称分类与 §6.2 赋值左侧相同（`TC_ERR_FUNCTION_SCOPE_ACCESS` / `TC_ERR_UNDEFINED_VARIABLE` / `TC_ERR_CONSTANT_ASSIGNMENT` / `TC_ERR_PARAMETER_ASSIGNMENT`），仅可写 `var`/`static var` 继续检查。`memblock` 目标在语法阶段被 `scalar_type` 拒绝。

目标名称已解析为可写标量 `var` 后，若其声明类型与 `read` 的显式标量类型不一致，报 `TC_ERR_TYPE_MISMATCH`。该类型检查在确定初始化检查之前完成；类型不一致时不再产生 `TC_ERR_UNINITIALIZED_VARIABLE`。

**静态成员作为 `read` 目标**：可通过 `Self.<成员名>` 或 `<模块名>.<成员名>` 覆盖公开标量 `static var`。解析和可见性规则与赋值一致（§4.3/§4.4）。`static var` 在程序准备阶段已完成初始化。公开 `memblock` `static var` 不得作为 `read` 目标。

**输入规则**：

| 目标类型            | 输入格式                                      |
| ------------------- | --------------------------------------------- |
| `int*`              | 可选 `-` 前缀 + 连续十进制数字，至少一位      |
| `uint*`             | 连续十进制数字，至少一位；不接受 `-` 前缀 |
| `float32`/`float64` | 必须完整匹配下述 `input_float_token` |
| `bool`              | `true` 或 `false`（大小写敏感，均为小写）     |

本节的 ASCII 空白仅指 U+0009～U+000D 与 U+0020，不受 locale 影响。输入必须完整匹配目标格式；例如 `12abc` 整体非法，不得只接受前缀 `12`。

**输入 Token 的权威 EBNF**：

```ebnf
signed_input_integer
           = [ "-" ] , input_digits ;

unsigned_input_integer
           = input_digits ;

bool_input_token
           = "true" | "false" ;

input_float_token
           = finite_input_float
           | "inf"
           | "-" , "inf"
           | "nan" ;

finite_input_float
           = [ "-" ] , input_digits , [
               "." , input_digits , [ input_exponent ]
             | input_exponent
           ] ;

input_exponent
           = ( "e" | "E" ) , [ "+" | "-" ] , input_digits ;

input_digits = input_digit , { input_digit } ;
input_digit  = "0" … "9" ;
```

`read(int*, ...)`、`read(uint*, ...)`、`read(bool, ...)` 分别完整匹配 `signed_input_integer`、`unsigned_input_integer`、`bool_input_token`，再按目标类型检查范围。整数输入固定为十进制，允许前导零和 `-0`，不接受前导 `+`、进制前缀、分隔符或源代码字面量后缀。

`input_float_token`（`read` 浮点输入接受集）：
- 十进制整数串（`1`、`-42`、`0`、`0007`）为合法有限浮点输入。
- 小数须在 `.` 前后均有数字（`1.` 和 `.5` 非法）。
- 支持完整指数形式（`1e5`、`1E+5`、`1e-5`、`1.25e-3`）。
- 前导 `-` 仅可用于有限值和 `inf`；不接受 `+`、`-nan`、不完整指数、`f`/`F` 后缀、分隔符、十六进制浮点。`inf`/`nan` 大小写敏感。
- 须先完整匹配 EBNF 再做数值转换，宿主扩展形式不扩大 TC 输入集。

有限浮点输入（包括整数书写形式）先解析为精确十进制数学值，再按 roundTiesToEven 直接舍入到目标 binary32/binary64；不得先解析为 TC 整数类型，也不得通过另一浮点类型中转。因此整数书写形式不受 `uint64` 字面量词法上限约束，其可表示性只按目标浮点类型判定。有限输入的精确数学值为零且 Token 显式带前导 `-` 时生成负零，其余零输入生成正零。非零有限值舍入为零、有限值舍入为无穷，或整数目标的输入超出目标整数类型范围，均报 `TC_ERR_IO`；可表示的非规格化数合法。`nan` 输入生成 §6.3.3 规定的 canonical quiet NaN。非法 Token 与意外 EOF 同样报 `TC_ERR_IO`。

`read` 先完整扫描并验证一个输入 Token，再转换并提交目标值；只有全部步骤成功后才覆盖目标变量。失败时目标槽保持原值，随后程序终止。解析过程不受当前 locale、宿主 `strto*` 扩展拼写或宿主浮点中间精度影响。

### 10.4 格式转换符定义

| 符号 | 含义                     | 适用类型            | 示例（值 42/3.14159265） |
| ---- | ------------------------ | ------------------- | ------------------ |
| `%d` | 有符号十进制             | `int8`～`int64`     | `42`               |
| `%i` | 有符号十进制（同 `%d`）  | `int8`～`int64`     | `42`               |
| `%u` | 无符号十进制             | `uint8`～`uint64`   | `42`               |
| `%x` | 十六进制（小写 a-f）     | 任一整数类型        | `2a`               |
| `%X` | 十六进制（大写 A-F）     | 任一整数类型        | `2A`               |
| `%o` | 八进制                   | 任一整数类型        | `52`               |
| `%b` | 二进制                   | 任一整数类型        | `101010`           |
| `%t` | 布尔值文本               | `bool`              | `true`             |
| `%f` | 浮点十进制（固定小数）   | `float32`/`float64` | `3.141593`         |
| `%e` | 科学计数法（小写 e）     | `float32`/`float64` | `3.141593e+00`     |
| `%E` | 科学计数法（大写 E）     | `float32`/`float64` | `3.141593E+00`     |
| `%g` | 紧凑格式（较短）         | `float32`/`float64` | `3.14159`          |
| `%G` | 紧凑格式（较短，大写 E） | `float32`/`float64` | `3.14159`          |

**确定性格式规则**：

- 格式化不受进程 locale 影响，小数点固定为 `.`。
- 未显式给出精度时，`%f`/`%e`/`%E` 输出小数点后 6 位，`%g`/`%G` 输出 6 位有效数字。
- 十进制输出以源 binary32/binary64 值的精确数学值为输入，按 roundTiesToEven 舍入到所需十进制位数；不得先经过宿主的更低精度类型。
- `%e`/`%E` 在小数点前保留恰好一位非零数字（零值为 `0`），指数始终含 `+` 或 `-`，且至少两位十进制数字。
- `%g`/`%G` 先以当前精度 `p` 位有效数字舍入。设舍入后值的十进制指数为 `e`（即科学计数法中小数点前恰好一位时的指数）：当 `e < -4` 或 `e >= p` 时使用 `%e`/`%E` 形式，否则使用定点形式。未使用 `#` 标志时，小数部分末尾的 `0` 全部删除；若小数部分为空，同时删除小数点。
- `%d`/`%i` 按有符号数学值输出，`%u` 按无符号数学值输出。
- `%x`/`%X`/`%o`/`%b` 对任意整数输出其固定宽度二进制补码位模式，默认不带进制前缀（`#` 备用形式见 §10.5）。零恰好输出 `0`；其他非负值省略前导零；负值保留足以表示完整类型位宽的全部数字。例如 `int8` 值 `-1` 分别输出 `ff`、`FF`、`377`、`11111111`。
- `%e` 使用小写指数标记，`%E` 使用大写指数标记；`%G` 的指数标记与特殊值使用大写。
- 有限负零保留符号，例如 `%f` 输出 `-0.000000`，`%g` 输出 `-0`。
- 不带格式控制时，特殊值固定输出 `inf`、`-inf`、`nan`；在 `%E`/`%G` 下输出 `INF`、`-INF`、`NAN`。`+` 与字段宽度按 §10.5 作用于这些文本；NaN payload 不通过文本 I/O 暴露。

上述 `%g` / `%G` 规则中，零（含负零）使用十进制指数 `e = 0`。NaN 的符号位和 payload 均不通过文本输出：NaN 默认输出 `nan` / `NAN`，即使其位模式符号位为 1 也不添加 `-`；仅 `+` 标志会添加 `+`。所有十进制格式化舍入均使用 roundTiesToEven。

### 10.5 C99 风格格式控制

格式说明符采用以下形态，且整体必须是无空白的单个 Token：

```text
%[flags][width][.precision]conversion
```

TC 参考 C99 `printf` 的静态格式控制，但格式说明符不是运行时值：一条 `write`/`writeln` 仍只包含一个格式说明符和一个操作数。`flags` 中每个标志至多出现一次，顺序不限；`width` 与 `precision` 只能写十进制常量，不支持 `*` 动态取值。

**确定性拆分规则**：从 `%` 后开始依次读取标志；连续的 `0` 字符在尚未开始字段宽度时合并为一个 `0` 标志，首个 `1`～`9` 才开始 `width`，其后的所有十进制数字均属于宽度。`.` 开始精度，转换符结束说明符。因此 `%08.3f` 唯一拆分为标志 `0`、宽度 `8`、精度 `3`；`%0008d` 等价于 `%08d`，同样拆分为标志 `0`、宽度 `8`。解析不得凭 EBNF 的其他可选分组选择不同拆分。此规则与 C99 `printf` 的行为一致：多写的前导零不产生重复标志错误。

| 控制项 | 语法 | 语义 |
| ------ | ---- | ---- |
| 左对齐 | `-` | 结果不足字段宽度时在右侧补 ASCII 空格；同时出现 `0` 时 `0` 被忽略 |
| 强制符号 | `+` | `%d`/`%i` 及浮点转换中未以 `-` 起始的结果添加 `+`；包括 `+inf` 和 `+nan` |
| 备用形式 | `#` | `%x`/`%X`/`%b` 的非零结果添加 `0x`/`0X`/`0b`；`%o` 保证首位为 `0`；有限浮点结果始终保留小数点，且 `%g`/`%G` 保留精度要求的末尾零 |
| 零填充 | `0` | 指定字段宽度且未左对齐时，在符号或进制前缀之后、数字之前补 `0`；整数转换显式指定精度时忽略该标志 |
| 最小字段宽度 | `width` | 取值 `1`～`65535`；结果较短时按对齐和填充规则补齐，结果较长时不得截断 |
| 精度 | `.precision` | 取值 `0`～`65535`；仅写 `.` 等价于 `.0`；各转换的含义见下表 |

| 转换符 | 显式精度的含义 |
| ------ | ---------------- |
| `%d`、`%i`、`%u`、`%x`、`%X`、`%o`、`%b` | 最少数字位数；不足时在数字左侧补 `0`。值为零且精度为零时不输出数字，但 `%#.0o` 仍输出 `0` |
| `%f` | 小数点后的数字位数 |
| `%e`、`%E` | 小数点后的数字位数，指数部分不计入精度 |
| `%g`、`%G` | 有效数字位数；精度为零按 1 位处理（继承 C99 语义：显式 `.0` 并非"不要有效数字"，而是"有效数字至少 1 位"） |
| `%t` | 不允许指定精度 |

标志的适用范围如下；表中未列出的组合是静态格式错误：

| 转换符 | 允许的标志 |
| ------ | ---------- |
| `%d`、`%i` | `-`、`+`、`0` |
| `%u` | `-`、`0` |
| `%x`、`%X`、`%o`、`%b` | `-`、`#`、`0` |
| `%f`、`%e`、`%E`、`%g`、`%G` | `-`、`+`、`#`、`0` |
| `%t` | `-` |

字段宽度按最终 ASCII 输出字符数计算；符号和进制前缀计入宽度，精度不包含它们。处理顺序为：按转换符和精度生成数字文本，添加符号或进制前缀，再按字段宽度填充。对 `inf`/`nan`，精度不改变文本，`0` 按空格填充处理。无 `width` 时 `-`/`0` 不产生填充，因此 `%0.3f` 与 `%.3f` 输出相同；例如值 `3.14159265` 分别得到 `3.142`，而 `%08.3f` 得到 `0003.142`。

已匹配附录 A `format_specifier` 形态后，重复标志、宽度或精度超出上述范围，以及转换符不适用的标志/精度，均报告 `TC_ERR_FORMAT_SPECIFIER`。不符合该 EBNF 的形式按语法规则报告 `TC_ERR_SYNTAX`。`%p`、C99 空格标志、长度修饰符（如 `hh`/`l`/`ll`/`L`）和 `*` 均不受支持；TC 的类型已由第一个参数显式给出。

## 11. 诊断与错误处理

静态错误与运行时错误均采用 fail-fast：报告**第一个**规范诊断后即停止。静态错误覆盖词法/语法、模块与导入、名称与作用域、类型/字面量/模式、常量求值、缩进与控制流、函数调用与返回、可达性与确定初始化、以及调用图无环等；正文与附录 A 在相关条款中给出触发条件与错误码。多错误并存时的阶段顺序、源位置比较与专用优先级，以及完整错误码对照表，由实现的确定性诊断规则规定，但不得改变本文已给出的错误码与合法程序集合。

### 11.1 运行时错误

遇到**第一个**运行时错误即终止程序（fail-fast）。运行时错误类型包括：

| 错误类型         | 触发条件                                                     |
| ---------------- | ------------------------------------------------------------ |
| 除零错误         | 整数 `div`/`mod` 除数为 0；严格浮点 `div`/`mod` 的除数为零  |
| 整数溢出错误     | 有符号算术结果超范围、`div(INT_MIN, -1)` 等                  |
| 负移位计数错误   | `shl`/`shr` 的有符号移位计数数学值小于 0                     |
| 浮点溢出/下溢    | 严格模式浮点运算上溢或下溢                                    |
| 浮点无效操作     | 严格浮点运算输入含 NaN 或产生 0/0、∞−∞、0×∞ 等               |
| 转换溢出错误     | 严格 `cast` 的数学结果无法在目标类型中表示                     |
| I/O 错误         | `read` 输入非法/超范围/EOF，或标准输入/输出读写失败            |
| memblock 越界    | `memblock_load`/`store` 下标越界，或 `memblock_copy` 区间不合法 |

**运行时错误提交规则**：每条 TC 指令在抽象机器中先读取全部实际需要读取的操作数并完成检查，再提交目标值。发生运行时错误时不提交当前指令的目标槽、调用返回值或新 `var` 的已初始化状态。首个运行时错误立即终止整个程序，不执行清理代码、后续语句或调用者续点，也不回滚此前已成功完成的赋值与 I/O。

### 11.2 编译警告

TC 无编译警告，也不以警告方式放行初始化、溢出、类型或控制流违规。

## 12. 资料性示例

本章仅演示规则组合，不新增语义；若示例与正文或附录 A 冲突，以正文和附录 A 为准。完整可运行示例均显式写出 `#program` / `#lib` 与可见性修饰符。

### 12.1 类型、运算模式与转换

```text
#program

let PI: float64 = 3.141592653589793
let ENABLED: bool = true

var max_i8: int8 = 127
var one_i8: int8 = 1
var wrapped: int8 = add(int8, wrap, max_i8, one_i8) ; -128

var x: float64 = 5.5
var y: float64 = 2.0
var rem: float64 = mod(float64, x, y)               ; 1.5
var ieee_nan: float64 = mod(float64, ieee, x, 0.0)  ; nan

var differs: bool = xor(bool, ENABLED, false)        ; true
var bits: uint64 = bitcast(uint64, PI)
var wide: int32 = 1000
var low: int8 = cast(int8, truncate, wide)           ; -24
```


### 12.2 结构化控制流

```text
#program

var total: int32 = 0
var i: int32 = 0

while lt(int32, i, 10) then
    i = add(int32, i, 1)
    var even: int32 = mod(int32, i, 2)
    if eq(int32, even, 0) then
        continue                      ; 回到条件求值
    end
    total = add(int32, total, i)
    if gt(int32, total, 20) then
        break                         ; 退出最内层 while
    end
end

writeln(int32, %d, total)
```

### 12.3 函数与非结构化控制流

`goto`/`label` 只允许位于 `#lib` 函数内，且不得位于 `while` 内；标签不增加缩进。`#program` 通过导入调用库函数。

```text
; ---- sumlib.tc ----
#lib

public func sum_to(limit: int32) int32 then
    var total: int32 = 0
    var i: int32 = 1
    label loop:
    if gt(int32, i, limit) then
        goto done
    end
    total = add(int32, total, i)
    i = add(int32, i, 1)
    goto loop
    label done:
    return total
end

public func show(value: int32) void then
    writeln(int32, %d, value)
    return
end

; ---- main.tc ----
#program

import sumlib

var total: int32 = funcall(sumlib.sum_to, limit: 10)
funcall(sumlib.show, value: total)
```


### 12.4 浮点 I/O 与位模式

```text
#program

let PI: float64 = 3.141592653589793
var radius: float64 = 0.0
var radius_sq: float64 = 0.0
var area: float64 = 0.0
var f: float32 = -1.0f
var raw: uint32 = bitcast(uint32, f)    ; 0xBF800000u

read(float64, radius)                   ; read 只覆盖已初始化变量
radius_sq = mul(float64, radius, radius)
area = mul(float64, PI, radius_sq)
writeln(float64, %g, area)              ; 6 位有效数字
writeln(float64, %0.3f, area)           ; 3 位小数；无字段宽度，0 标志不填充
writeln(float64, %08.3f, 3.14159265)    ; 0003.142

writeln(uint32, %X, raw)                ; BF800000
```

### 12.5 memblock 区间拷贝

整块复制用赋值（只检查类型，§3.8.4）；子区间或只搬运部分元素时用 `memblock_copy`。

```text
#program

var dst: memblock<int32> = memblock(int32, count: 8, fill: 0)
var src: memblock<int32> = memblock(int32, count: 4, 10, 20, 30, 40)

memblock_copy(int32, dst, 2, src, 0, 4)  ; dst[2..6) ← 10,20,30,40

; 同一块重叠区间：规范保证先快照再写回
memblock_copy(int32, dst, 0, dst, 2, 4)

var first: int32 = memblock_load(int32, dst, 0)
writeln(int32, %d, first)
```

## 附录 A：形式化语法（EBNF）

本附录为 TC 语言的权威语法定义。语义规则以正文为准。**语法拒绝**与**静态语义拒绝**的判定口径以 §1.3 第 2 款为准：不符合本附录产生式的 Token 序列属语法拒绝；本附录已接受、但正文类型/模式/作用域等规则不成立时属静态语义拒绝。

### A.1 符号约定

采用 扩展巴科斯-瑙尔范式（EBNF）：

| 元符号   | 含义              |
| -------- | ----------------- |
| `=`      | 产生式定义        |
| `\|`     | 择一              |
| `[ … ]`  | 可选（0 或 1 次） |
| `{ … }`  | 重复（0 或多次）  |
| `( … )`  | 分组              |
| `"…"`    | 终结符            |
| `"a" … "z"` | 包含两端的字符范围 |
| `? … ?`  | 用自然语言描述的词法特殊序列 |
| *斜体名* | 非终结符          |

### A.2 词法与缩进 Token

词法分析的输入必须先通过 §2.1 的 UTF-8、BOM、U+0000 与源字符合法性检查。注释外的非 ASCII 字符不能被规范化、转写或当作空白，而必须报 `TC_ERR_SYNTAX`。

字符检查成功后，词法分析按最长匹配生成 Token，再将完整标识符与关键字表比较。`varx` 因而是一个 `IDENTIFIER`，绝不能拆成 `VAR` + `IDENTIFIER`。除行首缩进外，Token 间的 ASCII 空格和制表符由词法层丢弃；语法层不使用可匹配零字符的 `ws` 充当关键字边界。

```ebnf
/* ── 基本字符类 ── */

ascii_letter = "A" … "Z" | "a" … "z" ;
digit        = "0" … "9" ;
hex_digit    = digit | "A" … "F" | "a" … "f" ;

/* ── 标识符与字面量 ── */

identifier_start = ascii_letter | "_" ;
identifier_continue = ascii_letter | digit | "_" ;
identifier = identifier_start , { identifier_continue } ;

integer_literal
           = ( "-" , (
               dec_literal
             | hex_literal
             | bin_literal
             | oct_literal
           ) )
           | (
               dec_literal [ "u" | "U" ]
             | hex_literal [ "u" | "U" ]
             | bin_literal [ "u" | "U" ]
             | oct_literal [ "u" | "U" ]
           ) ;
/* 负号仅可与无后缀字面量组合；禁止 -42u 等形式（§2.3.1） */

float_literal = [ "-" ] , (
    dec_float_literal [ ( "e" | "E" ) , [ "+" | "-" ] , digit , { digit } ]
  | sci_int_float_literal
) , [ "f" | "F" ] ;

dec_float_literal = digit , { digit } , "." , digit , { digit } ;
sci_int_float_literal
           = digit , { digit } , ( "e" | "E" ) , [ "+" | "-" ] ,
             digit , { digit } ;
/* 允许 1e5 等无小数点的科学计数法（§2.4.2）；亦允许 1.2e5 */

float_special = "inf" | "-" , "inf" | "nan" ;
/* -inf 合法；-nan 非法 */

bool_literal = "true" | "false" ;

dec_literal = non_zero_digit , { [ "_" ] digit } | "0" ;
hex_literal = ( "0x" | "0X" ) , hex_digit , { [ "_" ] hex_digit } ;
bin_literal = ( "0b" | "0B" ) , ( "0" | "1" ) , { [ "_" ] ( "0" | "1" ) } ;
oct_literal = ( "0o" | "0O" ) , ( "0" … "7" ) , { [ "_" ] ( "0" … "7" ) } ;
non_zero_digit = "1" … "9" ;

/* ── 类型关键字 ── */

int_type   = "int8"   | "uint8"
           | "int16"  | "uint16"
           | "int32"  | "uint32"
           | "int64"  | "uint64" ;
float_type = "float32" | "float64" ;
bool_type  = "bool" ;
scalar_type = int_type | float_type | bool_type ;
memblock_type = "memblock" , "<" , scalar_type , ">" ;
struct_type = identifier | imported_member_name ;
/* struct_type 的 identifier 必须解析为本模块已定义的结构体名；
   imported_member_name 必须解析为已导入库的 public struct。 */
type       = scalar_type | memblock_type | struct_type ;
value_type = type ;
return_type = value_type | "void" ;
field_type = scalar_type | memblock_type | struct_type ;
/* 字段类型的 struct_type 不得为当前正在定义的结构体（禁止自引用），
   且不得前向引用尚未完成定义的结构体（§3.9.1）。 */

/* ── 运算与模式关键字 ── */

binary_arith_op = "add" | "sub" | "mul" | "div" | "mod" ;
unary_arith_op  = "abs" | "neg" ;
bitwise_op      = "and" | "or" | "xor" ;
unary_bitwise_op = "not" ;
shift_op        = "shl" | "shr" ;
compare_op = "eq" | "ne" | "lt" | "le" | "gt" | "ge" ;
mode = "ieee" | "wrap" ;  /* 严格模式：无关键字（默认） */
truncate_kw = "truncate" ;
bitcast_kw  = "bitcast" ;

/* ── 格式说明符 ── */

format_specifier
           = "%" , { format_flag } , [ format_width ] ,
             [ "." , { digit } ] , format_conversion ;

format_flag = "-" | "+" | "#" | "0" ;
format_width = non_zero_digit , { digit } ;
format_conversion
           = "d" | "i" | "u" | "x" | "X" | "o" | "b" | "t"
           | "f" | "e" | "E" | "g" | "G" ;
/* 最长匹配形成一个无空白 Token；0 与 width 的唯一拆分算法、重复标志、
   数值范围和各转换符允许的控制项由 §10.5 静态检查。EBNF 的可选分组
   不授权解析器对同一 Token 选择不同拆分。 */

/* ── 控制流关键字 ── */
if_kw      = "if" ;
then_kw    = "then" ;
else_kw    = "else" ;
end_kw     = "end" ;
while_kw   = "while" ;
break_kw   = "break" ;
continue_kw = "continue" ;
goto_kw    = "goto" ;
label_kw   = "label" ;
func_kw    = "func" ;
funcall_kw = "funcall" ;
return_kw  = "return" ;
void_kw    = "void" ;
static_kw  = "static" ;
self_kw    = "Self" ;
import_kw  = "import" ;
public_kw  = "public" ;
private_kw = "private" ;
program_directive = "#program" ;
lib_directive = "#lib" ;

/* ── 注释 ── */

line_comment = ";" , { ? any decoded Unicode scalar value except U+0000, U+000A and U+000D ? } ;

/* 注释内允许 Unicode；注释外的 Token 和结构字符仅允许 §2.1
   列出的 ASCII。LF、CRLF 与 CR 由词法层作为行结束处理。 */
```

**缩进规则**：

缩进由逻辑行开头的连续 ASCII 空格（U+0020）数量决定，每 4 个空格为一级。行首出现 U+0009 水平制表符时报 `TC_ERR_INDENT_MIXED`。

缩进增加时必须恰好增加一级（增加多级为错误）。缩进减少时，减少后的级别必须是某个外层块的级别，且 `else` 和 `end` 必须与对应的 `func`/`if`/`while`/`struct` 对齐。

空行和纯注释行不改变缩进层级，其行首空白也不参与缩进检查。`label` 不改变缩进层级。

其他违反以上缩进规则的情形报 `TC_ERR_INDENT_INSUFFICIENT`。`else`/`end` 与对应块头不对齐时报 `TC_ERR_INDENT_ELSE_END`。

### A.3 语法

本节作用于 A.2 输出的 Token 序列。`NEWLINE`、`INDENT`、`DEDENT`、`EOF` 是虚拟终结符；`identifier`、`integer_literal` 等名称引用 A.2 的完整 Token 类别。EBNF 中以 `"…"` 标记的关键字或标点表示一个完整 Token，不按子序列匹配。非行首空白与行末注释已由词法层移除。

本 EBNF 同时规定全部语法诊断边界。位置实参、非 `operand` 实参、作为 `let` 或赋值 RHS 的 `funcall`、`return` 后的运算/转换/`funcall`，以及 `void` 出现在函数返回类型以外的位置，均必须在语法阶段拒绝。各专用产生式中的类型非终结符和模式参数位置同样具有约束力：例如位运算/移位只接受 `int_type`，逻辑运算只接受 `bool_type`，比较只接受整数或浮点类型；`write` / `writeln` / `read` 的显式类型参数只接受 `scalar_type`，因此 `write(memblock<int32>, …)` / `read(memblock<uint8>, …)` 为 `TC_ERR_SYNTAX`；`memblock` 类型构造器与值构造器的元素类型、以及 `memblock_load` / `memblock_store` / `memblock_copy` 的显式类型参数只接受 `scalar_type`，因此 `memblock<memblock<T>>` 与 `memblock(memblock<int32>, …)` 等嵌套形态为 `TC_ERR_SYNTAX`；`memblock` 值构造器必须匹配 `memblock_zero_ctor` / `memblock_fill_ctor` / `memblock_elems_ctor`（命名标签 `count:` / `fill:`，§3.8.3），旧式位置参数 `memblock(T, n[, …])` 为 `TC_ERR_SYNTAX`；运行时 `wrap_shift_expr` 只接受 `shl`，比较、逻辑和按位运算没有模式参数位置。不满足这些形态时统一报告 `TC_ERR_SYNTAX`，不得为产生 `TC_ERR_TYPE_MISMATCH` 或 `TC_ERR_MODE_MISMATCH` 而放宽语法。常量表达式由独立 `const_*` 产生式决定边界；其中 `const_shift_expr` 接受候选 `mode`，非法组合在后续静态语义阶段报告 `TC_ERR_MODE_MISMATCH`。`var_funcall_def`、独立 `funcall` 和 `return [operand]` 的返回类型适配属于后续静态语义。`statement` 产生式复用 `label_def` / `goto_stmt` 只表示其行内语法；二者必须具有 `func` 词法祖先的上下文约束由 §7.3 在静态语义阶段强制执行。

`#program` 的顶层分为类型定义区、声明区与可执行语句区（见 `program_type_region` / `program_decl_region` / `program_exec_region`）。块内 `suite` 仍使用完整 `statement`，因此 `if` / `while` 体内可以声明 `var` / `let`。若 Token 序列在顶层已进入可执行语句区后又出现顶层 `var` / `let` / `var_funcall_def`，则不符合 `program_module`；语法阶段对此类分区破坏报告 `TC_ERR_MODULE_LAYER`（定位到该声明首 Token），不得仅报笼统 `TC_ERR_SYNTAX`。

`#lib` 的 `library_struct_definition` / `static_constant_def` / `static_variable_def` / `function_definition` 均要求以 `public` 或 `private` 为第一个修饰符。若某一顶层成员在其余外形已可识别为 `struct` / `static let` / `static var` / `func` 定义，但缺少该可见性前缀，则不符合上述产生式；语法阶段受限恢复中报告 `TC_ERR_MISSING_VISIBILITY`（定位到该成员的 `struct` / `static` / `func` 关键字），不得仅报笼统 `TC_ERR_SYNTAX`。`#program` 类型定义区仅接受无可见性前缀的 `struct_definition`；若在 `#program` 中于 `struct` 之前写入 `public` / `private`，语法阶段受限恢复报告 `TC_ERR_PROGRAM_MODE_MISUSE`（定位到该可见性关键字），同样不放宽接受集。

`constant_def` 只规定 `let` 声明的语法外形；`const_rhs` 结果类型与声明 `type` 的闭合由 §5.2.1 在后续语义检查中强制，不改变 EBNF 的语法接受集。

```ebnf
/* ── 程序 ── */

program    = blank_lines , (
               "#program" , NEWLINE , blank_lines , import_region , program_module
             | "#lib" , NEWLINE , blank_lines , import_region , library_module
           ) , EOF ;

import_region
           = { import_declaration , NEWLINE , blank_lines } ;

import_declaration
           = "import" , identifier ;

program_module
           = program_type_region , program_decl_region , program_exec_region ;
/* #program：第三层类型定义区、第四层声明区（均可为空）必须全部位于
   第五层可执行语句区之前。顶层声明区之后再出现 var / let /
   var_funcall_def → TC_ERR_MODULE_LAYER（语法阶段拒绝）。 */

program_type_region
           = { struct_definition , NEWLINE , blank_lines } ;

program_decl_region
           = { program_declaration , NEWLINE , blank_lines } ;

program_declaration
           = variable_def
           | constant_def
           | var_funcall_def ;

program_exec_region
           = { program_exec_statement , NEWLINE , blank_lines } ;

program_exec_statement
           = assignment
           | field_assignment
           | funcall_assign_stmt
           | field_funcall_assign_stmt
           | write_stmt
           | writeln_stmt
           | read_stmt
           | break_stmt
           | continue_stmt
           | label_def
           | goto_stmt
           | void_funcall_stmt
           | return_stmt
           | memblock_store_stmt
           | memblock_copy_stmt
           | if_stmt
           | while_stmt ;
/* 顶层可执行区不含 variable_def / constant_def / var_funcall_def /
   struct_definition。
   label_def / goto_stmt / break / continue / return 出现在顶层时，
   由后续静态语义分别报告专用错误码（§7 / §8）。 */

library_module
           = type_region , static_region , function_region ;

type_region
           = { library_struct_definition , NEWLINE , blank_lines } ;

library_struct_definition
           = ( "public" | "private" ) , struct_definition ;

static_region
           = { ( static_constant_def | static_variable_def ) ,
               NEWLINE , blank_lines } ;

static_constant_def
           = ( "public" | "private" ) ,
             "static" , constant_def ;

static_variable_def
           = ( "public" | "private" ) ,
             "static" , variable_def ;

blank_lines = { NEWLINE } ;

function_region
           = { function_definition , NEWLINE , blank_lines } ;

statement  = simple_statement
           | if_stmt
           | while_stmt ;
/* statement 用于 func / if / while 的 suite；可含块内声明。 */

simple_statement
           = variable_def
           | constant_def
           | assignment
           | field_assignment
           | funcall_assign_stmt
           | field_funcall_assign_stmt
           | write_stmt
           | writeln_stmt
           | read_stmt
           | break_stmt
           | continue_stmt
           | label_def
           | goto_stmt
           | var_funcall_def
           | void_funcall_stmt
           | return_stmt
           | memblock_store_stmt
           | memblock_copy_stmt ;
/* label_def / goto_stmt 出现在 program_exec_region 或其嵌套 suite 中时，
   分别报 TC_ERR_LABEL_OUTSIDE_FUNCTION / TC_ERR_GOTO_OUTSIDE_FUNCTION。 */

/* ── 结构体定义 ── */

struct_definition
           = "struct" , identifier , "then" , NEWLINE ,
             INDENT , struct_field , { NEWLINE , struct_field } ,
             DEDENT , "end" ;

struct_field
           = ( "let" | "var" ) , identifier , ":" , field_type ,
             [ padding_attr ] ;

padding_attr
           = "@" , "padding" , "(" , integer_literal , ")" ;
/* integer_literal 须为无后缀非负十进制字面量；带 u/U、进制前缀或负号
   的形态由静态语义拒绝（§3.9.3）。 */

/* ── 函数定义 ── */

function_definition
           = ( "public" | "private" ) ,
             "func" , identifier , "(" , [ parameter_list ] , ")" ,
             return_type , "then" , NEWLINE , suite , "end" ;

parameter_list
           = parameter , { "," , parameter } ;

parameter  = identifier , ":" , value_type ;

return_stmt
           = "return" , [ operand ] ;

/* function_definition 不是 statement，因此不能嵌套在函数体、
   if / else 或 while 内；本语法没有匿名代码块产生式。 */

/* ── 函数调用 ── */

funcall    = "funcall" , "(" , callable_name ,
             { "," , named_argument } , ")" ;

callable_name = identifier | qualified_identifier | imported_member_name ;

qualified_identifier = "Self" , "." , identifier ;

imported_member_name = identifier , "." , identifier ;

named_argument
           = identifier , ":" , ( operand | memblock_constructor | struct_constructor ) ;
/* memblock_constructor 仅在对应形参类型为 memblock<T> 时合法；
   struct_constructor 仅在对应形参类型为结构体时合法；
   其他情况由静态语义拒绝（§8.2.2）。 */

var_funcall_def
           = "var" , identifier , ":" , value_type , "=" , funcall ;

void_funcall_stmt
           = funcall ;

funcall_assign_stmt
           = ( identifier | qualified_identifier | imported_member_name ) ,
             "=" , funcall ;

field_funcall_assign_stmt
           = field_lvalue , "=" , funcall ;
/* 字段目标的可变性规则与 field_assignment 相同（§3.9.5）；
   返回类型须与字段声明类型严格相同。 */

/* 命名实参必须与形参一一对应，文本顺序完全一致；第 i 个形参的
   value_type 是第 i 个实参 operand 的唯一期望类型。
   var_funcall_def / funcall_assign_stmt / void_funcall_stmt 的合法性由实际返回类型筛选。 */

/* ── 变量定义（声明时必须初始化；无可选 RHS） ── */

variable_def = "var" , identifier , ":" , type , "=" , rhs ;

/* ── 常量定义 ── */

constant_def = "let" , identifier , ":" , type , "=" , const_rhs ;
/* const_rhs 结果类型必须与声明 type 完全一致；这是 §5.2.1
   的静态语义约束，不改变本产生式的语法接受集。 */

/* ── 赋值语句 ── */

assignment = ( identifier | qualified_identifier | imported_member_name ) ,
             "=" , rhs ;

field_assignment
           = field_lvalue , "=" , rhs ;

field_lvalue
           = ( identifier | qualified_identifier | imported_member_name ) ,
             "." , identifier ;
/* 字段赋值的可变性规则见 §3.9.5 / §6.2。 */

/* ── if 语句（缩进敏感，end 必须） ── */

if_stmt    = "if" , rhs , "then" , NEWLINE , suite ,
             [ "else" , NEWLINE , suite ] ,
             "end" ;

/* ── while 语句（缩进敏感，end 必须） ── */

while_stmt = "while" , rhs , "then" , NEWLINE , suite ,
             "end" ;

/* ── break / continue 语句 ── */

break_stmt = "break" ;
continue_stmt = "continue" ;

suite      = { NEWLINE } , [ INDENT , block , DEDENT ] ;
block      = statement , NEWLINE ,
             { NEWLINE | statement , NEWLINE } ;
/* 每个函数体 suite、if 的 then/else suite 和 while 体 suite
   分别对应一个代码块；suite 不含 INDENT 时表示零条语句的
   空代码块。label_def 不开启新代码块，但作为跳转目标，
   是可达性分析的入口点；缩进约束见 §7.1.2。 */

/* ── label 与 goto 语句 ── */

label_def  = "label" , identifier , ":" ;
/* 仅函数内合法；label 不产生新缩进；同级后续语句与 label 缩进一致，
   见 §7.1.2 R7、§7.3.2。goto 的目标是该零动作 label 节点；连续标签
   与块末尾标签均沿正常落入边取得唯一续点。 */
goto_stmt  = "goto" , identifier ;
/* 仅函数内合法，且目标标签必须属于当前函数。 */

/* ── 右值表达式 ── */

rhs        = identifier
           | qualified_identifier
           | imported_member_name
           | field_access
           | integer_literal
           | float_literal
           | float_special
           | bool_literal
           | binary_arith_expr
           | unary_arith_expr
           | bitwise_expr
           | unary_bitwise_expr
           | shift_expr
           | compare_expr
           | binary_logic_expr
           | unary_logic_expr
           | cast_expr
           | bitcast_expr
           | memblock_load_expr
           | memblock_constructor
           | struct_constructor ;

/* ── 常量右值表达式 ── */

const_rhs  = integer_literal
           | float_literal
           | float_special
           | bool_literal
           | identifier
           | qualified_identifier
           | imported_member_name
           | field_access
           | const_binary_arith_expr
           | const_unary_arith_expr
           | const_bitwise_expr
           | const_unary_bitwise_expr
           | const_shift_expr
           | const_compare_expr
           | const_binary_logic_expr
           | const_unary_logic_expr
           | const_cast_expr
           | const_bitcast_expr
           | const_memblock_constructor
           | const_struct_constructor ;

/* ── 常量表达式（只允许单层调用） ── */

const_binary_arith_expr
           = binary_arith_op , "(" , type , "," ,
             [ mode , "," ] , const_operand , "," , const_operand , ")" ;

const_unary_arith_expr
           = unary_arith_op , "(" , type , "," ,
             [ mode , "," ] , const_operand , ")" ;

/* ── 常量位运算表达式 ── */

const_bitwise_expr
           = bitwise_op , "(" , int_type , "," ,
             const_operand , "," , const_operand , ")" ;

const_unary_bitwise_expr
           = "not" , "(" , int_type , "," , const_operand , ")" ;

const_shift_expr
           = shift_op , "(" , int_type , "," ,
             [ mode , "," ] , const_operand , "," , const_operand , ")" ;

/* ── 常量比较表达式 ── */

const_compare_expr
           = compare_op , "(" , ( int_type | float_type ) , "," ,
             const_operand , "," , const_operand , ")" ;

/* ── 常量逻辑表达式 ── */

const_binary_logic_expr
           = binary_logic_op , "(" , bool_type , "," ,
             const_operand , "," , const_operand , ")" ;

const_unary_logic_expr
           = "not" , "(" , bool_type , "," , const_operand , ")" ;

/* ── 常量转换表达式 ── */

const_cast_expr
           = "cast" , "(" , type , "," , const_operand , ")"
           | "cast" , "(" , int_type , "," , "truncate" , "," ,
             const_operand , ")" ;

const_bitcast_expr
           = "bitcast" , "(" , type , "," , const_operand , ")" ;
/* bitcast 语法上接受 type 的全部取值，但 bool、memblock 与结构体在语义检查中拒绝（TC_ERR_TYPE_MISMATCH，§1.3/§6.6.6）；bitcast 也不接受 void。 */

/* ── 常量操作数 ── */

const_operand
           = integer_literal
           | float_literal
           | float_special
           | bool_literal
           | identifier
           | qualified_identifier
           | imported_member_name
           | field_access ;
/* field_access 的基址在常量上下文中必须解析为 let / static let 结构体绑定。 */

/* ── 操作数 ── */

operand    = identifier | qualified_identifier | integer_literal | float_literal
           | float_special | bool_literal | imported_member_name | field_access ;

field_access
           = ( identifier | qualified_identifier | imported_member_name ) ,
             "." , identifier ;
/* 仅单层字段读取；a.b.c 不符合本产生式（§3.9.5）。 */

/* ── 双目算术表达式 ── */

binary_arith_expr
           = strict_binary_arith_expr
           | mode_binary_arith_expr ;

strict_binary_arith_expr
           = binary_arith_op , "(" , type , "," ,
             operand , "," , operand , ")" ;

mode_binary_arith_expr
           = binary_arith_op , "(" , type , "," , mode , "," ,
             operand , "," , operand , ")" ;

/* ── 单目算术表达式 ── */

unary_arith_expr
           = strict_unary_arith_expr
           | mode_unary_arith_expr ;

strict_unary_arith_expr
           = unary_arith_op , "(" , type , "," , operand , ")" ;

mode_unary_arith_expr
           = unary_arith_op , "(" , type , "," , mode , "," ,
             operand , ")" ;

/* ── 按位逻辑表达式（仅整数） ── */

bitwise_expr
           = bitwise_op , "(" , int_type , "," ,
             operand , "," , operand , ")" ;

unary_bitwise_expr
           = "not" , "(" , int_type , "," , operand , ")" ;

/* ── 移位表达式（仅整数） ── */

shift_expr
           = strict_shift_expr
           | wrap_shift_expr ;

strict_shift_expr
           = shift_op , "(" , int_type , "," ,
             operand , "," , operand , ")" ;

wrap_shift_expr
           = "shl" , "(" , int_type , "," , "wrap" , "," ,
             operand , "," , operand , ")" ;

/* ── 比较表达式（不支持 ieee 模式） ── */

compare_expr
           = compare_op , "(" , ( int_type | float_type ) , "," ,
             operand , "," , operand , ")" ;

/* ── 双目逻辑表达式（布尔） ── */

binary_logic_expr
           = binary_logic_op , "(" , bool_type , "," ,
             operand , "," , operand , ")" ;

binary_logic_op = "and" | "or" | "xor" ;

/* ── 单目逻辑表达式（布尔） ── */

unary_logic_expr
           = "not" , "(" , bool_type , "," , operand , ")" ;

/* ── 类型转换表达式 ── */

cast_expr  = strict_cast_expr | truncate_cast_expr ;

strict_cast_expr
           = "cast" , "(" , type , "," , operand , ")" ;

truncate_cast_expr
           = "cast" , "(" , int_type , "," , "truncate" , "," ,
             operand , ")" ;

bitcast_expr
           = "bitcast" , "(" , type , "," , operand , ")" ;
/* bitcast 语法上接受 type 的全部取值，但 bool、memblock 与结构体在语义检查中拒绝（TC_ERR_TYPE_MISMATCH，§1.3/§6.6.6）；bitcast 也不接受 void。 */

/* 所有运算类型/模式组合均受 §6.3.1 权威矩阵约束。
   truncate 仅允许整数窄化；bitcast 要求等位宽且两端非 bool（§6.6）。 */

/* ── memblock 操作 ── */

memblock_name
           = identifier
           | qualified_identifier
           | imported_member_name ;
/* 名称解析与可见性：局部/顶层绑定用 identifier；本库 static 用 Self.id；
   导入公开成员用 module.id（§4.3、§4.4、§6.7.2.5）。 */

memblock_load_expr
           = "memblock_load" , "(" , scalar_type , "," , memblock_name , "," ,
             operand , ")" ;

memblock_store_stmt
           = "memblock_store" , "(" , scalar_type , "," , memblock_name , "," ,
             operand , "," , operand , ")" ;
/* memblock_store 是独立语句，非 RHS。索引操作数须为整数类型（§6.7.2.4）。 */

memblock_copy_stmt
           = "memblock_copy" , "(" , scalar_type , "," ,
             memblock_name , "," , operand , "," ,
             memblock_name , "," , operand , "," ,
             operand , ")" ;
/* memblock_copy 是独立语句，非 RHS。将 src[src_index, src_index+length)
   按元素抽象位串拷入 dst[dst_index, dst_index+length)；区间与重叠语义见 §6.7.2.3。
   三个整数操作数（dst_index / src_index / length）须为整数类型（§6.7.2.4）。
   length 为本次拷贝跨度，不是 memblock 的长度属性（§3.8.0）。 */

memblock_constructor
           = memblock_zero_ctor
           | memblock_fill_ctor
           | memblock_elems_ctor ;

/* count: / fill: 标签在词法上是普通 identifier Token，本产生式按拼写
   "count" / "fill" 匹配；二者不是 §2.7 保留关键字（§3.8.3）。
   计数值 memblock_count_operand 的编译期常量与 ≥1 约束由静态语义强制。 */

memblock_count_operand
           = integer_literal
           | identifier
           | qualified_identifier
           | imported_member_name ;

memblock_zero_ctor
           = "memblock" , "(" , scalar_type , "," ,
             "count" , ":" , memblock_count_operand , ")" ;

memblock_fill_ctor
           = "memblock" , "(" , scalar_type , "," ,
             "count" , ":" , memblock_count_operand , "," ,
             "fill" , ":" , operand , ")" ;

memblock_elems_ctor
           = "memblock" , "(" , scalar_type , "," ,
             "count" , ":" , memblock_count_operand , "," ,
             operand , { "," , operand } , ")" ;
/* 元素类型仅为 scalar_type，故 memblock(memblock<…>, …) 为 TC_ERR_SYNTAX。
   三种形态由产生式语法区分（§3.8.3）：
     memblock(T, count: c)                    零值填充；
     memblock(T, count: c, fill: v)           指定值填充；
     memblock(T, count: c, v0, …, vₙ)         逐值初始化（至少一个位置实参；
                                               个数须等于 c，否则 TC_ERR_MEMBLOCK_ELEMENT_COUNT_MISMATCH）。
   旧式位置参数 memblock(T, n) / memblock(T, n, …) 不符合本产生式 → TC_ERR_SYNTAX。
   在 count 值之后的 "," 处分流：下一 Token 序列为拼写 fill 的 identifier 紧跟 ":"
   则只可进入 fill 形态；否则进入 elems 形态。 */

const_memblock_constructor
           = const_memblock_zero_ctor
           | const_memblock_fill_ctor
           | const_memblock_elems_ctor ;

const_memblock_zero_ctor
           = "memblock" , "(" , scalar_type , "," ,
             "count" , ":" , memblock_count_operand , ")" ;

const_memblock_fill_ctor
           = "memblock" , "(" , scalar_type , "," ,
             "count" , ":" , memblock_count_operand , "," ,
             "fill" , ":" , const_operand , ")" ;

const_memblock_elems_ctor
           = "memblock" , "(" , scalar_type , "," ,
             "count" , ":" , memblock_count_operand , "," ,
             const_operand , { "," , const_operand } , ")" ;

/* ── 结构体值构造器 ── */

struct_constructor
           = struct_type , "(" ,
             [ identifier , ":" , operand ,
               { "," , identifier , ":" , operand } ] , ")" ;

const_struct_constructor
           = struct_type , "(" ,
             [ identifier , ":" , const_operand ,
               { "," , identifier , ":" , const_operand } ] , ")" ;
/* 全字段必填、顺序、类型与可见性由 §3.9.2 静态语义强制；
   空实参列表仅语法接受，语义上因缺少字段而拒绝。 */

/* ── I/O 语句（显式类型仅 scalar_type；禁止 memblock，§10） ── */

write_stmt = "write" , "(" , scalar_type , "," , operand , ")"
           | "write" , "(" , scalar_type , "," , format_specifier , "," ,
             operand , ")" ;

writeln_stmt = "writeln" , "(" , scalar_type , "," , operand , ")"
             | "writeln" , "(" , scalar_type , "," , format_specifier , "," ,
               operand , ")" ;

read_stmt  = "read" , "(" , scalar_type , "," ,
             ( identifier | qualified_identifier | imported_member_name ) , ")" ;
```

| 8 位无符号  | `uint8`   | `uint8_t`                      |

| 16 位无符号 | `uint16`  | `uint16_t`                     |
| 32 位有符号 | `int32`   | `int32_t`                      |
| 32 位无符号 | `uint32`  | `uint32_t`                     |
| 64 位有符号 | `int64`   | `int64_t`                      |
| 64 位无符号 | `uint64`  | `uint64_t`                     |
| 单精度浮点  | `float32` | `float`                        |
| 双精度浮点  | `float64` | `double`                       |
| 布尔        | `bool`    | 固定 1 字节的 `_Bool` 语义载体（规范字节 `0x00`/`0x01`；不等于“宿主 `_Bool` 对象大小任意”） |
| 无返回值    | `void`    | `void`（仅函数返回类型）       |

| ----------------- | ------------------------------------- | ---------------------------------------------- |
| 有符号字面量      | `42`                                  | `42`                                           |
| 无符号字面量      | `42u`                                 | `42u`                                          |
| 浮点字面量        | `3.14f` / `3.14`                      | `3.14f` / `3.14`                               |
| 加                | `add(int32, a, b)`                    | 先用无 UB 的范围预检或足够宽表示计算；成功后转为 `int32_t` |
| 加（回绕）        | `add(int32, wrap, a, b)`              | 同宽无符号模运算后以 `memcpy` 或显式位规则重解释，不能依赖越界有符号运算 |
| 浮点加（严格）    | `add(float64, a, b)`（默认严格模式）  | C99 无直接等价；须固定格式/舍入并按 §6.3.2 自行分类异常 |
| 浮点加（IEEE）    | `add(float64, ieee, a, b)`            | 仅在已验证 binary64、roundTiesToEven、无额外精度/FTZ/融合时可用 `a + b` |
| 整除 / 求余       | `div` / `mod`                         | 先检查零除数；`INT_MIN / -1` 对 `div` 报错、对 `mod` 直接返回 `0`，其余情形才可使用 `/` / `%` |
| 浮点取模          | `mod(float64, a, b)`                  | C99 无对应运算符；商向零截断的数学余数         |
| `div(INT_MIN,−1)` | `div` → 整数溢出错误；`mod` → `0` | C99 为 UB                                  |
| 取绝对值          | `abs(int32, a)`                       | 先排除 `INT32_MIN`，再计算绝对值                |

| 右移（有符号）    | `shr(int32, a, b)`                    | 先处理负计数和 `k >= n`，再以无符号位运算或 §6.4.2.2 数学式实现；不能依赖实现定义的 `a >> b` |
| 负移位计数         | `shl`/`shr` → `TC_ERR_NEGATIVE_SHIFT_COUNT` | C99 为 UB                                       |

| 逻辑与            | `and(bool, a, b)`                     | `a && b`                                       |
| 逻辑异或          | `xor(bool, a, b)`                     | `a != b`                                       |

| 等宽位重解释（`bitcast`） | `bitcast(float32, bits)`        | 在宿主格式已验证兼容时以 `memcpy` 到等宽目标类型（避免别名 UB）；否则显式编解码抽象位串 |
| bool→int                   | `cast(int32, flag)`             | `flag ? 1 : 0`                              |
| int→bool                   | `cast(bool, x)`                 | `x != 0`                                    |

| I/O          | TC                              | C99 等价                  |
| ------------ | ------------------------------- | ------------------------- |
| 无格式输出   | `write(int32, x)`               | `printf("%d", x)`         |
| 有符号十进制 | `write(int32, %d, x)`           | `printf("%d", x)`         |
| 无符号十进制 | `write(uint32, %u, x)`          | `printf("%u", x)`         |
| 十六进制小写 | `write(uint32, %x, x)`          | `printf("%x", x)`         |
| 十六进制大写 | `write(uint32, %X, x)`          | `printf("%X", x)`         |
| 八进制       | `write(uint32, %o, x)`          | `printf("%o", x)`         |
| 浮点精度     | `write(float64, %.3f, x)`       | `printf("%.3f", x)`       |
| 宽度与零填充 | `write(float64, %08.3f, x)`     | `printf("%08.3f", x)`     |
| 左对齐       | `write(int32, %-8d, x)`         | `printf("%-8d", x)`       |
| 二进制       | `write(uint32, %#b, x)`         | 无标准等价（TC 扩展）     |
| 布尔输出     | `write(bool, %-8t, x)`          | 无标准等价（TC 扩展）     |

### B.2 `let` 常量与 C99 `const` 语义对照

| 特性               | TC `let`     | C99 `const`  | 说明                    |
| ------------------ | ------------ | ------------ | ----------------------- |
| 编译期求值         | ✅ 必须       | ❌ 不要求     | TC `let` 保证编译期求值 |
| 运行时存储         | ❌ 不分配     | 通常分配     | TC 常量不生成运行时数据 |
| 地址可取值         | ❌ 不可取     | ✅ 可取       | TC 常量无运行时地址     |
| RHS 可为算术表达式 | ✅            | ✅            | TC 常量支持编译期算术   |
| 溢出检查           | ✅ 编译期报错 | ❌ UB         | TC 在编译期捕获常量溢出 |
| 优化器可推导       | ✅ 恒为常量   | ⚠️ 视实现而定 | TC 语义保证             |

### B.3 0.0.35 函数与控制流边界

- 顶层语句区仍是程序入口，但只允许结构化控制流；顶层以及顶层嵌套块不得出现 `goto` 或 `label`。
- `goto` 与 `label` 只能出现在函数体内。每个函数独立建立标签表，跳转目标必须位于当前函数并满足 §7.3 的块关系规则。
- 顶层不建立标签表或 goto 跳转；函数控制流域独立处理其函数内标签、跳转、确定初始化和返回路径。
- 需要非结构化控制流的程序应把对应逻辑封装进函数，并由顶层通过 `funcall` 显式启动；TC 不引入特殊 `main` 或隐式函数调用。
- 函数内 `while` 继续禁止 `goto` / `label`，结构化循环与非结构化循环的范式隔离保持不变。

## 附录 C：各类型边界常量速查（C99 对照）

本附录严格以 ISO/IEC 9899:1999 及其 TC1～TC3 汇编文本的 C99 规则为准，主要对应 §7.18 `<stdint.h>`、§5.2.4.2.2 `<float.h>` 和 §7.16 `<stdbool.h>`。不使用 C11 及后续版本增加的宏、类型或语法。

### C.1 精确宽度整数

C99 的 `intN_t` / `uintN_t` 是可选的精确宽度类型。仅当实现提供满足相应位宽、无填充位，且有符号类型采用二进制补码表示的整数类型时，才定义对应 typedef 及界限宏。下表中的直接对应关系因此均以“该 C99 实现实际定义相应名称”为前提：

| TC 类型 | C99 条件 typedef | C99 最小值宏 | C99 最大值宏 |
| ------- | --------------- | ------------ | ------------ |
| `int8` | `int8_t` | `INT8_MIN` | `INT8_MAX` |
| `uint8` | `uint8_t` | `0` | `UINT8_MAX` |
| `int16` | `int16_t` | `INT16_MIN` | `INT16_MAX` |
| `uint16` | `uint16_t` | `0` | `UINT16_MAX` |
| `int32` | `int32_t` | `INT32_MIN` | `INT32_MAX` |
| `uint32` | `uint32_t` | `0` | `UINT32_MAX` |
| `int64` | `int64_t` | `INT64_MIN` | `INT64_MAX` |
| `uint64` | `uint64_t` | `0` | `UINT64_MAX` |

- C99 源码应使用上述 `<stdint.h>` 界限宏表达边界，尤其不得用 `-9223372036854775808` 之类宿主整数字面量假定 `int64_t` 最小值的类型和求值过程。
- `int_leastN_t` / `uint_leastN_t` 只保证至少 N 位，不能替代 TC 的精确位宽类型，否则回绕、移位、`bitcast` 和边界检查可能改变。
- 若宿主 C99 实现没有定义某个精确宽度 typedef，AOT 必须使用能保持 TC 规定值域和位模式的其他实现策略；不得把缺失的名称视为 TC 不支持对应类型。

### C.2 浮点边界

C99 不要求 `float` 和 `double` 采用 IEEE 754 binary32 / binary64，也不保证存在非规格化数。`<float.h>` 中的 `FLT_MIN` / `DBL_MIN` 表示最小正正规值，不是最小正非零值；C99 没有 `FLT_TRUE_MIN`、`DBL_TRUE_MIN`、`FLT_HAS_SUBNORM` 或 `DBL_HAS_SUBNORM`。

| TC 类型 | TC 最大有限绝对值 | TC 最小正正规值 | TC 最小正非零值 | 匹配宿主格式时的 C99 宏 |
| ------- | ----------------- | -------------- | -------------- | ----------------------- |
| `float32` | `(2 − 2^-23) × 2^127` | `2^-126` | `2^-149` | `FLT_MAX`、`FLT_MIN`；C99 无最小正非零值宏 |
| `float64` | `(2 − 2^-52) × 2^1023` | `2^-1022` | `2^-1074` | `DBL_MAX`、`DBL_MIN`；C99 无最小正非零值宏 |

只有宿主 `<float.h>` 至少满足下列特征时，才能把 C99 `float` / `double` 分别作为 TC `float32` / `float64` 的候选存储类型：

| TC 类型 | 必要的 C99 `<float.h>` 特征 |
| ------- | --------------------------- |
| `float32` | `FLT_RADIX == 2`、`FLT_MANT_DIG == 24`、`FLT_MIN_EXP == -125`、`FLT_MAX_EXP == 128` |
| `float64` | `FLT_RADIX == 2`、`DBL_MANT_DIG == 53`、`DBL_MIN_EXP == -1021`、`DBL_MAX_EXP == 1024` |

这些特征只确认基本值域和精度，不能单独证明全部 TC 浮点语义。AOT 仍须确认非规格化数、NaN、无穷、roundTiesToEven 和位模式要求，并处理 C99 `FLT_EVAL_METHOD` 允许的额外中间精度；每条 TC 浮点指令结束时必须按目标 TC 类型舍入。

### C.3 布尔值

TC `bool` 在抽象机器中**固定为 1 字节（8 位）**，规范位模式为 `false` = `0x00`、`true` = `0x01`（§3.4）。该宽度用于 `memblock<bool>` 布局与按值复制；与 C99 `_Bool` 的宿主对象大小无关——AOT 若用 `_Bool` 作载体，必须在进出 TC 抽象边界时保证可观察字节仅为 `0x00`/`0x01`，且 `memblock` 中按 1 字节元素紧密排列。

C99 包含 `<stdbool.h>` 后，宏 `bool` 展开为 `_Bool`，`false` / `true` 展开为整数常量 `0` / `1`。逻辑值对应如下；**对象大小与可观察布局以 TC 的 1 字节规则为准**，不得把宿主 `_Bool` 可能大于 1 字节或填充布局泄漏为 TC `memblock<bool>` 语义。

| TC 值 | TC 抽象字节 | C99 逻辑表达 |
| ----- | ----------- | ------------ |
| `false` | `0x00` | `false`（或 `_Bool` 值 `0`） |
| `true` | `0x01` | `true`（或 `_Bool` 值 `1`） |
