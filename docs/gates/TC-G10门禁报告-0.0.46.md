## 复现

需要 clang、llvm-ar、ld.lld、qemu-system-aarch64、qemu-system-arm 与
qemu-system-riscv32；缺失时 CMake 配置失败。

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
python3 tests/conformance/platform/s10_riscv32_cases.py --check
python3 tests/conformance/platform/s10_limits_cases.py --check
python3 tests/conformance/abi/s10_abi_fuzz.py --check --seeds 8
```

## 当前限制

- 可选优化管线（SSA/regalloc/内联）未启用，0.0.46 保持零 pass。
- 未新增 RISC-V 64/x86-64/Cortex-M 等其它目标；新增目标流程与 RISC-V 实例约定记录于
  `src/CONTRACTS.md`。
- `riscv32-baremetal` 使用 qemu-system-riscv32 virt；程序 stdout/stdin 为 UART0，
  退出记录使用 semihosting，终止使用 SiFive test finisher；栈 8 MiB、`D=64`，
  静态区 1 MiB、运行时 arena 128 KiB。
- VM 的帧由宿主内存承载，不受 AOT 目标 `frame_total*(D+1) <= stack_size` 预算约束；
  超出目标栈预算的大帧程序可在 VM 执行、但 AOT 以实现错误（退出 71）拒绝。这属于
  实现资源边界，不是语言行为；见 `src/CONTRACTS.md`。
- ARM32 代码窗口为 1 MiB；超过窗口的函数在链接阶段被拒绝，不发布产物。
- 单函数 30000 指令已有 far-branch 回归；更大规模受宿主内存与汇编/链接工具
  处理能力影响，不纳入门禁，也不宣称支持。
- qemu-user/Linux-user 不在门禁路径；门禁使用 qemu-system。
