## 证据

固定 Linux 手动签名作业使用仓库批准变量指定的 Ubuntu 26.04 container digest，
安装 `gdb-multiarch`，收集真实 GNU GDB 输出，并为 `result.json` 与 `transcript.log`
分别生成 attestation。作业随后按仓库、workflow、source ref、source digest、subject digest
与证书身份验证两份签名，拒绝 self-hosted runner，并执行强制发布审计。

证据矩阵：

| 入口 | 覆盖 |
| ---- | ---- |
| `toolchain.debug_elf` | 四档案独立 ELF/DWARF 语义解码 |
| `vm.gdb.e2e` | 四档案合成地址断点、TC IR PC、单步与程序语义 |
| `toolchain.aot_debug` | 四档案 DWARF 验证 |
| `toolchain.debug_smoke` | 三个裸机档案的 qemu gdbstub 源码断点 |

证据状态为 `PASS`，共 548 项断言；transcript SHA-256 与源提交由签名证据和发布审计
共同校验。签名 artifact 名为 `gdb-e2e-evidence`。

## 复现

```sh
cmake -S . -B .tmp/build
cmake --build .tmp/build
ctest --test-dir .tmp/build --output-on-failure
python3 tests/tools/g11_evidence.py --selftest
python3 tests/tools/s10_release_audit.py --selftest
python3 tests/tools/s10_release_audit.py --check \
  --require-g11-evidence=<signed-artifact-directory> \
  --g11-repo=tangrb/TC-Compiler
```

手动签名作业由 `.github/workflows/ci.yml` 的 `gdb-evidence` 提供；输入 digest 必须匹配
`TC_GDB_CONTAINER_DIGEST` 仓库变量。
