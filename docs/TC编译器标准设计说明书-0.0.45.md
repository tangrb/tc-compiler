本文档定义 TC 编译器为实现 [TC语言标准 0.0.45](./TC语言标准设计说明书-0.0.45.md) 所必须遵循的确定性编译阶段、分析算法、诊断优先级与错误码体系。
语言语义以语言标准为准；本说明书只规定**如何**确定性实现那些语义（管线顺序、CFG/调用图算法、首个诊断选择、内部索引与约束），并在类型系统、表达式、模块、I/O 与函数调用等关键领域补充编译器必须执行的静态验证细则。
诊断码前缀与语言标准一致：静态/编译期为 `TC_CE_*`，运行时为 `TC_RE_*`；实现资源失败保留 `TC_ERR_OUT_OF_MEMORY`。

## 1. 概述与编译管线

### 1.1 文档定位

本说明书是本文所定义的编译器行为的规范性条款：凡影响可观察诊断、错误码、静态接受集或与语言标准交叉引用的算法步骤，均必须按本文实现。各后端（VM / AOT / JIT / 汇编）共享同一前端分析语义；代码生成不属于本说明书内容，且不得改变本文规定的静态结果。

### 1.1.1 版本能力边界（0.0.45）

编译器必须涵盖以下语言能力范围，细节以对应章节为准。语法接受集以语言标准附录 A 为准。

| 类别 | 范围 | 详见 |
| ---- | ---- | ---- |
| 类型 | 固定宽度整数 `int8`～`uint64`；平台字长整数 `isize` / `usize`；`float32` / `float64`；`bool`；`ref<T>`（托管引用）；`addr<T>`（线性地址，含 `addr<void>`）；`memblock<T, N>`（带长度头部，`N` 为元素个数规划）；`struct`；`void` 仅作函数返回类型 | §3 |
| 运算 | 算术、按位、移位、布尔逻辑、比较；`cast` / `truncate` cast / `bitcast`；`memblock` 读写、区间拷贝与 `.count` 长度访问；**托管引用**：`ref_load` / `ref_store` / `ref_of` / `ref_eq` / `ref_ne`；**线性地址**：`addr` 构造、`addr_load` / `addr_store`、`addr_io_load` / `addr_io_store`（易失）、`addr_add` / `addr_sub`、`addr_eq` / `addr_ne`；`bits_of` 类型宽度查询 | §6 |
| 模式 | 默认 strict；有符号整数算术与 `shl` 可按规则使用 `wrap`；浮点算术可按规则使用 `ieee` | §6.0.1、§6.3 |
| 控制流 | 缩进敏感的 `if` / `while`（以 `end` 结束）；`break` / `continue`；函数内受限 `goto` / `label`（`while` 内禁止） | §7 |
| 函数 | `#lib` 中 `func`；命名且有序的 `funcall`；显式 `return`；按值只读形参；调用图无环 | §8 |
| 模块 | 每文件一模块；`#program` / `#lib`；`import` 与限定名访问公开成员 | §4 |
| I/O | `write` / `writeln` / `read`；仅标量类型；格式化输出 | §10 |
| 入口 | `#program` 顶层语句按源序执行；无特殊 `main` | §4.1 |

### 1.2 确定性处理顺序

本规范采用确定的静态处理顺序，共 13 个主阶段：

| 阶段 | 核心任务 | 语言标准锚点 |
| ---- | -------- | ----------- |
| 1 | UTF-8 解码（文件打开失败属于实现/API 层） | [语言标准 §2.1] |
| 2 | 词法与缩进扫描；字面量 Token 自身的绝对值上限 / 浮点舍入为零/无穷检查 → `TC_CE_LITERAL_OUT_OF_RANGE` | [语言标准 §2.3.5]、[语言标准 §2.3.7]、[语言标准 §2.4.1] |
| 3 | 语法解析；**结构类语法阶段诊断**（`TC_CE_MODULE_LAYER` / `TC_CE_MISSING_VISIBILITY` / `TC_CE_PROGRAM_MODE_MISUSE` / `TC_CE_VAR_MISSING_INIT`）；操作数数量语法恢复 | [语言标准 §1.3]、[语言标准 §5.1.2]、[语言标准 附录 A] |
| 4 | 模块结构、导入解析、结构体表注册与函数签名收集（子阶段 4a→4b→4c→4d；结构体表在 4c 与 4d 之间） | [语言标准 §4.1]–[语言标准 §4.5] |
| 5 | 函数重名、签名内名称冲突与全局函数名保护 | [语言标准 §8.1.2] |
| 6 | 名称、作用域与类型语义（子阶段 6a→6b→6c→6d→6e） | [语言标准 §5]、[语言标准 §6]、[语言标准 §7.3]、[语言标准 §8.4.1] |
| 7 | 函数调用（`funcall`）检查：目标、位置、实参与字面量约束 | [语言标准 §8.2] |
| 8 | 返回（`return`）检查：位置、形式、操作数名称与类型 | [语言标准 §8.3] |
| 9 | `let` / `static let` 编译期求值；`static var` 初始化器约束验证 | [语言标准 §5.2]–[语言标准 §5.2.3]、[语言标准 §4.2] |
| 10 | `if`/`while` 静态布尔三态判定；逻辑 RHS 读边判定 | [语言标准 §5.2.2]、[语言标准 §6.5.2.2] |
| 11 | CFG 构建、可达性、确定初始化固定点；函数末尾检查 | [语言标准 §9.2] |
| 12 | 函数调用图递归环检查 | [语言标准 §8.6] |
| 13 | 代码生成（不属于本说明书内容） | — |

1. 源字节的 UTF-8 解码（文件打开失败属于实现/API 层）；
2. 词法与缩进扫描；词法分析采用最长匹配策略（详见 §2.1），缩进处理基于缩进级别栈生成 INDENT/DEDENT Token（详见 §2.2）。在形成字面量 Token 时执行 [语言标准 §2.3.5] 的整数绝对值上限，以及 [语言标准 §2.4.1] 中由浮点后缀唯一确定源类型后的舍入为零/无穷检查，这两类只依赖 Token 自身的失败均报告 `TC_CE_LITERAL_OUT_OF_RANGE`；
3. 语法解析；附录 A 已分区的 `#program` 顶层若在可执行语句之后再出现声明，按结构类语法阶段诊断报告 `TC_CE_MODULE_LAYER`（附录 A.3）；`var` 声明缺 `=` 或初始化器报告 `TC_CE_VAR_MISSING_INIT`（[语言标准 §1.3]、[语言标准 §5.1.2]）。两者均不进入后续阶段；
4. **模块结构、导入解析与函数签名收集**。本阶段内部按以下子阶段顺序执行，前一子阶段有错时不进入后一子阶段；跨文件诊断的主位置与关联位置规则见 §4.1：

   4a. **单文件模块结构**：

   | 检查项 | 错误码 |
   | ---- | ---- |
   | 五层排序 | `TC_CE_MODULE_LAYER` |
   | `#lib` 成员是否带显式 `public` / `private`（覆盖 `struct` / `func` / `static let` / `static var`） | `TC_CE_MISSING_VISIBILITY`（缺可见性前缀亦可在第 3 阶段结构类语法阶段诊断中报告，见附录 A.3） |
   | `#program` 是否误用 `func` / `Self` / `static` / `public` / `private`（含带可见性前缀的 `struct`） | `TC_CE_PROGRAM_MODE_MISUSE` |

   4b. **导入解析**：对每个 `import` 唯一定位目标模块：

   - 找不到 → `TC_CE_IMPORT_NOT_FOUND`；
   - 目标非 `#lib` → `TC_CE_IMPORT_NOT_LIB`；
   - 逻辑名歧义 → `TC_CE_IMPORT_AMBIGUOUS`；
   - 同名重复导入 → `TC_CE_DUPLICATE_IMPORT`；
   - 导入名与本模块任何顶层名称冲突 → `TC_CE_IMPORT_NAME_CONFLICT`（完整范围见 §4.6）。

   4c. **依赖图环检查**：在完整可达依赖图上检查自环与任意长度间接环 → `TC_CE_CIRCULAR_IMPORT`（§4.1）。

   4c 成功后、进入 4d 之前，编译器注册结构体表（分析步骤）：

   | 项 | 规则 |
   | ---- | ---- |
   | 登记方式 | 按依赖拓扑登记全部可达模块的 `struct`，条目以 `(定义模块名, 结构体名)` 定界 |
   | 解析位置 | 类型位置与值构造器中的结构体名（裸标识符或 `imported_member_name`）在此解析，规则见 §3.3 |
   | 未解析为已定义且可见的结构体 | `TC_CE_UNDEFINED_STRUCT` |
   | 经导入限定解析到存在但为 `private` 的结构体 | `TC_CE_PRIVATE_MEMBER_ACCESS`（不得改报未定义） |
   | 同一模块重复定义 | `TC_CE_DUPLICATE_STRUCT` |

   4d. **收集函数签名**：在 4a–4c 成功后，收集全部可达 `#lib` 模块的函数签名，供后续阶段使用。

5. 检查函数重名、签名和名称空间；本阶段完成全局函数名与顶层值作用域直接 `var` / `let`、以及全部形参的冲突检查；
6. 名称、作用域与类型语义阶段。本阶段内部按以下子阶段顺序执行，每个子阶段内按同一源文件的行列序选择首个诊断；前一子阶段有错时不进入后一子阶段：

   6a. **控制流上下文检查**：检查 `goto` / `label` 是否具有 `func` 词法祖先；再检查是否具有 `while` 词法祖先（函数内 `while` 中的 `goto`/`label` 分别报 `TC_CE_GOTO_INSIDE_LOOP` / `TC_CE_LABEL_INSIDE_LOOP`）。

   6b. **名称作用域预建**：分别解析函数体和顶层的名称与词法作用域；为当前 `#lib` 建立 [语言标准 §8.4.1] 的本库顶层成员名索引；对顶层嵌套块及函数体任意层级的 `var` / `let` 执行全局函数名冲突检查（报告 `TC_CE_FUNCTION_NAME_CONFLICT`）；仅为各函数建立标签表。

   6c. **goto/label 名称解析**：完成 `goto` 的标签查找（沿祖先链找到最近同名标签）、跨控制流域判定与块关系检查（[语言标准 §7.3.2]）。本子阶段使用 6b 建立的标签表；固定元数内建调用外壳的操作数数量已在第 3 阶段完成，本阶段不得再次分类或改写。

   6d. **类型、模式与字面量语义检查**：检查普通 RHS 与 `const_rhs` 的类型、模式及上下文字面量约束。

   | 检查项 | 规则 |
   | ---- | ---- |
   | `let` 的名称绑定类别 | 按 [语言标准 §5.2.1] 先检查类别（`var` 或参数引用立即报 `TC_CE_CONSTANT_EXPRESSION`），再检查 RHS 结果类型与声明类型是否闭合 |
   | 标识符操作数 | 声明类型与显式类型不一致时报告对应错误 |
   | 字面量 | 类别、后缀或范围不符合上下文时使用字面量专用错误 |
   | 限定名解析 | 解析 `<模块名>.<成员名>` 时若成员存在但为 `private`，报告 `TC_CE_PRIVATE_MEMBER_ACCESS`，不得改报未定义 |
   | 函数内裸名 | 命中本库顶层成员名索引时报告 `TC_CE_FUNCTION_SCOPE_ACCESS` |
   | 结构体类型名与构造器名 | 已在 4c 与 4d 之间的结构体表注册中解析（§3.3）；本子阶段只做构造器字段验证（全字段必填、顺序、类型一致） |
   | 本子阶段亦完成 | `memblock` 赋值/传参的 `N` 规划个数比较（`TC_CE_MEMBLOCK_SIZE_MISMATCH`）、memblock 构造器验证（§3.4）、`.count` 常量性、`none` / `nil` 期望类型定型、字段赋值双层可变性检查（§3.3），以及 `ref_*` / `addr_*` 的类型与可变性静态约束（§3.1、§3.2、§3.8） |

   6e. **I/O 格式检查**：检查 `write` / `writeln` / `read` 的显式类型、格式说明符静态控制项及转换符兼容性。格式说明符按确定性拆分算法（§10.1）解析标志、字段宽度和精度。已匹配 EBNF 但格式控制非法时报告 `TC_CE_FORMAT_SPECIFIER`；操作数类型与转换符不兼容时报告 `TC_CE_FORMAT_TYPE_MISMATCH`。

   `funcall` 实参和 `return` 操作数的上下文字面量检查分别保留到第 7、8 阶段。

7. 检查符合 EBNF 的 `funcall` 之目标、使用位置、实参、实参上下文字面量约束和接收类型；调用目标若以裸名命中本库 `func`，报告 `TC_CE_FUNCTION_SCOPE_ACCESS`；经导入限定解析到 `private` 函数时报告 `TC_CE_PRIVATE_MEMBER_ACCESS`；
8. 检查符合 EBNF 的 `return [operand]` 之位置、形式、操作数名称、返回类型和返回上下文字面量约束；返回操作数的名称类诊断在本阶段产生，不回到第 6 阶段；
9. 求值 `let` 常量（名称类别、类型闭合和依赖合法性已在第 6 阶段完成检查，本阶段仅执行算术、位运算和转换的编译期计算）；

   | 项 | 规则 |
   | ---- | ---- |
   | `static let` 与 `static var` | 亦按源序求值各可达库的 `static let`，并检查 `static var` 初始化器的编译期约束（[语言标准 §4.2]） |
   | 移位计数 | 常量算术中 `shl`/`shr` 的移位计数取其整数类型的数学值（[语言标准 §5.2.1]） |
   | 浮点精度 | 浮点常量算术需按类型参数独立执行 binary32/binary64 精度、采用 roundTiesToEven 舍入，不得使用 FMA、扩展精度、FTZ 或 DAZ（[语言标准 §5.2.3]） |
10. 按 [语言标准 §5.2.2] 执行 `if`/`while` 静态布尔三态判定，并按 [语言标准 §6.5.2.2] 判定逻辑 RHS 读边；
11. 构建唯一顶层 CFG，再分别构建各函数 CFG；按 [语言标准 §9.2] 从每个域的唯一入口计算可达节点，报告不可达语句，然后仅在可达子图上执行确定初始化固定点；仅函数 CFG 执行函数末尾检查；
12. 检查函数调用图中的递归环；
13. 生成后端代码。

第 6 阶段（名称、作用域与类型语义）建立后续检查所需的作用域和名称环境。其内部子阶段 6a–6e 按序执行，前一子阶段有错时不进入后一子阶段。

`funcall` 内部名称与 `return` 操作数必须按第 7、8 阶段的专用优先级协调解析：

- 未定义调用目标会抑制该调用的实参名称错误；
- `TC_CE_FUNCTION_SCOPE_ACCESS` / `TC_CE_PRIVATE_MEMBER_ACCESS` 与未定义目标同级，均抑制实参错误；
- 调用位置错误会抑制实参错误；
- 返回形式错误会先于返回操作数名称错误。

下列专用规则覆盖通用阶段内的源位置顺序。

权威 EBNF 不接受的形式必须按 [语言标准 §1.3] 作**语法拒绝**（第 3 阶段），不得为产生后续专用语义诊断而放宽语法。亦须遵守 [语言标准 §1.3] 一致性要求与 [语言标准 §4.4]：不得放宽附录 A 接受集、静默接受对 `private` 成员的外部访问，或以警告代替对公开 `static var` 跨模块写入的既有语义。阶段按顺序完整执行，前一阶段有错时不进入后一阶段。

### 1.3 首个诊断的通用规则

一个程序同时存在多个错误时，唯一首个诊断按以下顺序确定（核心规则与 [语言标准 §1.3] 的一致性判定对齐）：

1. **阶段优先**：先报告**诊断类阶段**（LT → SYN → SEM → CT，对应表见下款）编号较小者的错误。
2. **同一诊断类阶段内按源位置优先**：一个 TC 编译单元恰好对应一个源文件；同一诊断类阶段内按行、列选择起始位置最早者，**不得按内部处理阶段编号抢先**——例如第 4–8、11、12 阶段同属 SEM，其间一律按源序选首个诊断。批量编译多个文件属于驱动层行为，各文件分别产生语言诊断，文件间次序不属于 TC 语言语义。
3. **规则优先**：同一位置按本节专用优先级；

   | 项 | 规则 |
   | ---- | ---- |
   | 未专门规定时的顺序 | 依次为语法形态/数量、语句上下文、名称存在性、重复、名称空间/作用域/控制流域、使用位置、实参顺序、类型、模式/结构、字面量、CFG、调用图 |
   | 专用码优先 | 同一位置存在多个候选码时**专用码优先于通用码** |
   | 例 | `TC_CE_LITERAL_TYPE` 优先于 `TC_CE_TYPE_MISMATCH`，且优先于 `TC_CE_CONDITION_TYPE`（条件位置的直接字面量）；`TC_CE_INDENT_ELSE_END` 优先于 `TC_CE_INDENT_INSUFFICIENT`（`else`/`end` 行） |
4. **关联位置**：重复定义、跨域跳转和递归环使用下文指定的主位置比较；其他位置只作附注。
5. **遍历无关**：函数表、哈希表、CFG、调用图和实参集合的内部遍历顺序不得改变结果。

**诊断类阶段与处理阶段的对应**：本节 13 个阶段是**实现步骤**编号，不等同于 [语言标准 §11] 四步规则中的诊断类阶段（LT / SYN / SEM / CT）：

| 处理阶段 | 诊断类阶段 |
| ---- | ---- |
| 第 1–2 阶段 | **LT** |
| 第 3 阶段 | **SYN** |
| 第 4–8、11、12 阶段 | **SEM** |
| 第 9–10 阶段（常量求值与三态判定） | **CT**（其形态与来源类子条件仍属 SEM，见 [语言标准 §5.2.1]） |
| 第 13 阶段（代码生成） | 不产生语言诊断，不属于任何诊断类阶段 |

- **CT 类诊断必须挂起**：[语言标准 §11] 的「阶段优先（LT → SYN → SEM → CT）」要求 CT 类诊断晚于全部 SEM 类诊断；实现必须在第 9、10 阶段挂起 `TC_CE_CONSTANT_OVERFLOW` / `TC_CE_CONSTANT_DIV_ZERO` / `TC_CE_CONSTANT_CAST_OVERFLOW`，以及求值类 `TC_CE_CONSTANT_EXPRESSION`。
- **挂起期间只使用数值结果**：供第 10 阶段三态判定与第 11 阶段可达性分析。
- **SEM 优先**：若第 11 阶段（可达性、确定初始化、函数末尾）或第 12 阶段（调用图环）产生 SEM 诊断，则报告该 SEM 诊断并终止，挂起的 CT 诊断不再报告；仅当全部 SEM 检查均无触发时，才按第 2 条源位置顺序报告挂起的 CT 诊断。
- **顺序的理由**：未按此顺序实现将违反 [语言标准 §11] 的规范性顺序，并使「首个规范诊断及其错误码」跨实现不一致。

`TC_CE_LITERAL_OUT_OF_RANGE` 的阶段由失败所需的信息唯一决定：

- 只依赖字面量 Token 自身的整数绝对值上限或浮点源类型舍入检查属于第 2 阶段；
- 只有结合普通 RHS / `let` / I/O 的期望类型才能确定的范围错误属于第 6 阶段；
- 结合 `funcall` 形参或函数返回类型才能确定的范围错误分别属于第 7、8 阶段。

第 2 阶段已经失败的字面量不得延迟到上下文阶段，因此阶段优先规则对所有实现唯一。

源位置使用 1 基行号与 1 基列号。对有效 UTF-8，列号按解码后的 Unicode 标量值计数，每个 ASCII 空格计一个标量；换行序列不属于下一行的列。

对非法 UTF-8，行列按首个非法字节之前的最长有效前缀计算，首个非法字节占据下一列，并以 0 基源字节偏移作为附加位置；主错误码仍为 `TC_CE_SYNTAX`。语言诊断文本可以本地化，但错误码、主位置和本节规定的关联位置必须稳定；表中明确固定文本的实现资源错误除外。

虚拟 Token 位置：`NEWLINE` 位于逻辑行最后一个源标量值之后一列（空行在第 1 列）。空文件 `EOF` 位于第 1 行第 1 列；非空文件在下一逻辑行第 1 列或最后标量值之后。

除 §4.1、§7.5～§7.6、§8.1～§8.3、§8.8 或其他规范性条款已经给出更专用的定位规则外，普通静态语义诊断的**主位置**按下列规则固定：

- **规则 1**：运算本身不支持显式类型参数所指类别时，定位到该类型参数 Token；若显式类型参数类别合法，而某个标识符或操作数与其期望类型不一致，则定位到源位置最早的不匹配操作数。`TC_CE_COMPARISON_TYPE_MISMATCH` 使用同一操作数定位规则。
- **规则 2**：RHS 自身合法、但其结果类型与接收变量、常量或赋值目标的声明类型不一致，且没有更专用的调用/返回诊断时，定位到 RHS 的第一个 Token。
- **规则 3**：`TC_CE_MODE_MISMATCH` 定位到候选模式关键字；`TC_CE_BITCAST_WIDTH` 定位到源操作数的第一个 Token。
- **规则 4**：`TC_CE_LITERAL_TYPE` 与 `TC_CE_LITERAL_OUT_OF_RANGE` 定位到完整字面量的第一个 Token；前导 `-` 属于该字面量时，定位到 `-`。
- **规则 5**：`TC_CE_CONDITION_TYPE` 定位到 `if` / `while` 条件 RHS 的第一个 Token。
- **规则 6**：`TC_CE_FORMAT_TYPE_MISMATCH` 定位到格式说明符中的转换符字符。格式说明符是单个 Token，但主列号仍精确指向该 Token 内对应的 Unicode 标量位置。
- **规则 7**：`write` / `writeln` 的标识符操作数与显式 `scalar_type` 不一致，或 `read` 目标 `var` 的声明类型与显式 `scalar_type` 不一致时，使用 `TC_CE_TYPE_MISMATCH` 并定位到操作数或目标标识符。格式化输出只在该检查成功后才检查转换符兼容性（[语言标准 §10.1]）。以 `memblock<…>`、结构体、`ref<…>` 或 `addr<…>` 作为 I/O 显式类型参数属语法拒绝（`TC_CE_SYNTAX`），不适用本条。

词法、缩进、语法及格式控制专用诊断的主位置按下表固定：

| 错误码 | 主位置 |
| -------- | ---------- |
| `TC_CE_SYNTAX` | 非法源字符或非法 Token 定位到其首字节/首标量或首 Token；对无专用错误码的语法失配，定位到使当前 Token 前缀无法继续匹配任一可行产生式的首个 Token；缺少必需 Token 时定位到应插入位置的当前 `NEWLINE` / `EOF` 或后继 Token。`TC_CE_MISSING_END` 优先使用下表的专用规则。无模式参数位置却写入 `wrap`/`ieee`/`truncate` 时，定位到该关键字 Token。 |
| `TC_CE_VAR_MISSING_INIT` | 该 `var` 声明的标识符。 |
| `TC_CE_OPERAND_COUNT` | 平衡固定元数调用外壳的内建关键字。 |
| `TC_CE_INDENT_MIXED` | 行首缩进中首个 U+0020 空格。 |
| `TC_CE_INDENT_INSUFFICIENT` | 缩进层级或缩进栈转移首次非法的逻辑行第一个 Token。 |
| `TC_CE_INDENT_ELSE_END` | 未与对应块头对齐的 `else` 或 `end` 关键字。 |
| `TC_CE_MISSING_END` | 先按 EBNF 的嵌套结构以现有 `end` 从内向外完成唯一配对，再把每个仍未配对块的 `func` / `if` / `while` 开启关键字作为候选主位置；有多个候选时按源位置最早者。 |
| `TC_CE_FORMAT_SPECIFIER` | 重复标志定位到第二个及后续重复字符中的最早者；宽度/精度超范围定位到对应数字字段首字符；标志或精度不适用于转换符时，定位到源序最早的不适用控制项（标志字符或 `.`）。 |

兜底规则：标识符/操作数错误 → 首 Token；重复定义 → 第二个及后续最早名称（关联首个）；构造级错误 → 构造首 Token；常量求值错误 → 触发运算关键字；运行时错误 → 当前指令首 Token；I/O 失败 → 对应 I/O 关键字。

函数参数名受保护：任意层级 `var`/`let` 与形参同名 → `TC_CE_DUPLICATE_DEFINITION`（第 6 阶段，主位置为内层标识符，关联形参位置）。

全局函数名受保护：同一文件同名函数，或与任何值绑定同名 → `TC_CE_FUNCTION_NAME_CONFLICT`（同名函数与顶层直接绑定在第 5 阶段，嵌套/函数体内在第 6 阶段；主位置为后声明的函数名或值绑定名，关联先前定义）。

附录 A 首先决定 Token 序列能否进入静态语义（[语言标准 §1.3]）。不符合产生式属**语法拒绝**（第 3 阶段）：

| 失配形态 | 第 3 阶段错误码 |
| ---- | ---- |
| 缺初始化器 | `TC_CE_VAR_MISSING_INIT` |
| 操作数数量错 | `TC_CE_OPERAND_COUNT` |
| 无模式位置的模式关键字 | `TC_CE_SYNTAX` |
| 缩进/块形态（`else`/`end` 不对齐） | `TC_CE_INDENT_ELSE_END` |
| 声明/语句分区破坏 | `TC_CE_MODULE_LAYER` |
| 其余 | `TC_CE_SYNTAX` |
| 格式说明符：无法匹配 EBNF | 第 3 阶段 `TC_CE_SYNTAX` |
| 格式说明符：已匹配但控制项非法 | 第 6 阶段 `TC_CE_FORMAT_SPECIFIER` |

| 项 | 规则 |
| ---- | ---- |
| 适用条件 | `TC_CE_OPERAND_COUNT` 的适用范围是完整且权威的：仅当逻辑行中已识别出「内建关键字 `(` 顶层逗号分隔项 `)`」的平衡调用外壳，但其值操作数数量不符合下表时使用该错误码 |
| 不计入值操作数的项 | 类型参数、位于类型参数之后候选模式位置的 `wrap` / `ieee` / `truncate` 关键字，以及 `write` / `writeln` 的格式说明符 |
| 优先级 | 语法形态/数量的诊断优先级高于类型和模式组合：只要外壳平衡且顶层字段可分隔，先按上述方式计数值操作数；数量正确后，才由 EBNF 和 [语言标准 §6.3.1] 判定类型参数或候选模式在当前操作中是否合法 |

本识别是第 3 阶段在正常 EBNF 匹配失败后的受限语法诊断恢复：固定元数产生式本身已经规定合法数量；本规则只把其中"平衡外壳且仅值操作数数量不符"的非法 Token 序列映射为专用错误码。该序列仍未通过附录 A，不得进入第 6 阶段的名称、类型或模式分析，也不得在第 6 阶段重新分类为其他错误。

| 固定元数外壳 | 期望的值操作数 | 说明 |
| ---------------- | ------------------ | ---- |
| `add` / `sub` / `mul` / `div` / `mod` | 2 | 普通 RHS 与 `let` 常量 RHS 均适用；不接受 `ref<T>` / `addr<T>`（地址算术须用 `addr_add` / `addr_sub`） |
| `and` / `or` / `xor` | 2 | 整数按位与 `bool` 逻辑重载均适用；不接受 `ref<T>` / `addr<T>` |
| `shl` / `shr` | 2 | 模式位置的合法性仍由 EBNF 与 [语言标准 §6.3.1] 判定 |
| `eq` / `ne` / `lt` / `le` / `gt` / `ge` | 2 | 整数与浮点比较均适用；托管引用比较须用 `ref_eq` / `ref_ne`，地址比较须用 `addr_*` |
| `abs` / `neg` / `not` | 1 | `not` 的整数按位与 `bool` 逻辑重载均适用 |
| 严格 `cast` / `cast(..., truncate, ...)` / `bitcast` | 1 | 目标类型与 `truncate` 不计为值操作数 |
| `memblock_load` | 2 | 块名与下标；显式元素类型不计 |
| `memblock_store` | 3 | 块名、下标与写入值；显式元素类型不计 |
| `memblock_copy` | 5 | `dst`、`dst_index`、`src`、`src_index`、`length`；显式元素类型不计 |
| `ref_load` | 1 | 引用操作数；显式所指类型 `T` 不计 |
| `ref_store` | 2 | 引用与写入值；显式所指类型 `T` 不计 |
| `ref_of` | 1 | 绑定标识符；显式所指类型 `T` 不计 |
| `addr_add` / `addr_sub` | 2 | 地址与 `usize` 偏移；显式所指类型 `T` 不计 |
| `ref_eq` / `ref_ne` / `addr_eq` / `addr_ne` | 2 | 两个同型操作数；显式所指类型 `T` 不计 |
| `addr` | 1 | 地址整数；显式所指类型 `T` 不计 |
| `addr_load` | 1 | 地址操作数；显式所指类型 `T` 不计 |
| `addr_store` | 2 | 地址与写入值；显式所指类型 `T` 不计 |
| `addr_io_load` | 1 | 同 `addr_load`（易失） |
| `addr_io_store` | 2 | 同 `addr_store`（易失） |
| `bits_of` | 0 | **无操作数**：`bits_of(T)` 的唯一参数是类型（§3.0.1、§6.7） |
| `write` / `writeln` | 1 | 有格式和无格式形式均恰好输出一个值；不接受 `ref<T>` / `memblock` |
| `read` | 1 | 唯一的目标标识符按一个操作数计 |

| 形态 | 诊断 |
| ---- | ---- |
| 缺少右括号、顶层逗号结构破损或无法识别内建调用外壳 | `TC_CE_SYNTAX`（而非 `TC_CE_OPERAND_COUNT`） |
| 嵌套调用（`let` RHS（`const_rhs`）中的嵌套调用与其它不允许嵌套的位置） | 第 3 阶段 `TC_CE_SYNTAX`（[语言标准 §5.2.1]） |
| `funcall` 的项（命名实参） | 不纳入本错误码；缺失、重复、未知与顺序错误分别使用 §8.2 的专用诊断 |
| `return`、`if` / `while`、变量/常量定义与其他语句形态 | 不属于内建固定元数调用外壳，沿用各自的语法或专用诊断 |

| 项 | 规则 |
| ---- | ---- |
| 进入普通诊断的前提 | 只有完整 Token 序列符合附录 A 某一产生式时，才进入普通类型/模式诊断 |
| 同一位置的静态语义优先级 | 语法已接受的同一位置同时违反多项静态语义时，固定按「运算支持的类型类别 → 模式合法性 → `bitcast` 位宽 → 字面量范围/类型 → 格式符与其他操作数类型」选择 |
| 模式参数的合法性 | `wrap` / `ieee` / `truncate` 仅在对应产生式明确提供的位置才是候选模式；若相关操作或上下文的产生式没有该参数位置，或类型参数已被专用非终结符排除，且没有上述语法专用诊断，统一在第 3 阶段报告 `TC_CE_SYNTAX` |
| 示例 | 普通 RHS 的 `shr(int32, wrap, x, k)` 是语法错误，而 `const_shift_expr` 已接受的同形 `let` RHS 随后报告 `TC_CE_MODE_MISMATCH` |

`let` 类型闭合检查在第 6 阶段完成：

- RHS 为标识符且解析为 `var` 或函数参数时，**先**报 `TC_CE_CONSTANT_EXPRESSION` 且**不比较结果类型**（[语言标准 §5.2.1] 第 3 步）；
- 否则字面量按 [语言标准 §3.6] 报专用错误，标识符/单层调用的结果类型不同时报 `TC_CE_TYPE_MISMATCH`（定位 RHS 首 Token）。

调用的内部类型检查先于与外层类型的比较。

| 形态 | 阶段与错误码 |
| ---- | ---- |
| 非法 UTF-8、文件起始 BOM、U+0000、注释外违反 [语言标准 §2.1] 的非法源字符 | `TC_CE_SYNTAX` |
| 缩进与语法阶段有专用错误码时 | 优先专用码（此处专用语法码只改变错误分类，不改变附录 A 接受的程序集合） |
| `let` RHS 中的嵌套调用（不符合 `const_rhs` 产生式） | 语法阶段 `TC_CE_SYNTAX`（与引用指令、`memblock_load` 等非 `const_rhs` 形态同口径，[语言标准 §5.2.1]） |
| 自引用和前向引用 | 名称阶段 `TC_CE_UNDEFINED_VARIABLE` |
| `let` 中引用 `var` 或函数参数 | 第 6 阶段子阶段 6d 立即 `TC_CE_CONSTANT_EXPRESSION`，不延迟到常量求值阶段 |
| 静态布尔判定 | 仅在名称、类型及更早 `let` 求值成功后运行；合法常量形态的求值错误不得降级为 `unknown` |
| 不可达代码 | 仍完成词法、语法、名称和类型检查 |

### 1.4 类型化中间形式与降级契约

本节承载**工具链契约**：语言标准只规定语义与可观察行为，本节规定 TC 文本与其**类型化中间形式**（`TcTypedProgram`）之间的关系。

#### 1.4.1 两层形态

| 形态 | 角色 | 产出者 | 消费者 |
| ---- | ---- | ------ | ------ |
| TC 文本 | 人类可读 IR；规范性唯一对象在语言标准 | 人类；前端（编译器前端、AI 生成器、翻译器） | 本说明书的静态阶段 |
| `TcTypedProgram` | 类型化中间形式（降级形态） | 本说明书的静态阶段 | VM、AOT 及 JIT / 汇编后端 |

`TcTypedProgram` 的字段与序列化形式不属于本说明书内容；其**语义不变量**如下。

#### 1.4.2 降级不变量（必须）

1. **语义保持**：降级必须保持语言标准规定的静态接受集、首个诊断及其错误码，以及执行语义。
2. **托管引用不透明**：`ref<T>` 在降级形态中**不得**编码为可被语言程序观测的数值（不暴露槽号、句柄值或其任何函数）。后端可以自由选择其表示。
3. **线性地址即地址**：`addr<T>` 在降级形态中必须保持「位模式 = 目标地址空间地址」，使后端可直接映射到机器地址；不得改写为托管句柄或槽索引。
4. **两个类型族可区分**：降级形态必须能区分 `ref<T>` 与 `addr<T>`，且二者互不转换。
5. **常量已求值**：`bits_of`、`none` / `nil`、常量 `addr` 与常量折叠的结果应在降级形态中保持编译期可确定。
6. **易失与顺序**：`addr_io_load` / `addr_io_store` 的发生次数与相对顺序不得在降级或优化中丢失。
7. **无未定义值**：降级形态不得引入语言标准未定义的形态——不存在 `undef` / `poison` 一类"未定义值"。

#### 1.4.3 后端中立

同一实现的各后端（VM、AOT 及 JIT / 汇编）**必须**对同一 `TcTypedProgram` 产生 [语言标准 §1.3] 定义的相同可观察行为（诊断与错误码、标准输出字节、`addr_io_*` 的发生次数与顺序）。实现定义清单内的差异只允许发生在**实现之间**，不允许发生在同一实现的不同后端之间。

#### 1.4.4 前端义务

前端（生成 TC 文本的工具）必须自行保证语言不接受的形态不出现：调用图无环、结构化控制流、声明时初始化、单层操作数、类型参数首位等。前端不得依赖托管引用的数值、槽位编号、降级形态的字段布局，或任何未列入 [语言标准 §1.3] 实现定义清单的实现细节。

### 1.5 局部可判定（工具链义务）

[语言标准 §1.3] 要求「接受集不依赖优化、中间形态或后端」。编译器侧义务：

1. **确定性判定顺序**：静态检查必须按 §1.3 的通用规则与各章专用优先级给出唯一首个诊断；不得因中间形态或优化改变接受/拒绝结果。
2. **无固定容量拒绝**：实现不得以固定上限（最大嵌套层数、最大语句数、最大标识符长度等）拒绝语言标准接受的程序；超出实际可用资源属**实现资源失败**，不产生 `TC_CE_*` 码（[语言标准 §1.3]「可核实性」）。
3. **可核实性**：只实现「附录 A 语法 + 局部类型规则 + CFG 数据流 + 调用图检查」的工具必须得到与完整实现相同的接受/拒绝结果；本文各章的检查不得依赖任何优化前提。

## 2. 词法结构

本章对应 [语言标准 §2]。下列条款规定词法扫描与缩进 Token 的确定性算法；字符集（[语言标准 §2.1]）、标识符（[语言标准 §2.2]）、字面量形态（[语言标准 §2.3]–[语言标准 §2.5]）、注释（[语言标准 §2.6]）与关键字（[语言标准 §2.7]）仍以语言标准为准。

### 2.1 词法分析器

词法分析器采用**最长匹配**策略，落实 [语言标准 §2.3.7]：

1. 扫描 `0` 时，检查后续字符是否为 `x`/`X`/`b`/`B`/`o`/`O`，转入对应进制（十六进制、二进制或八进制）。
2. 数字部分扫描完成后，检查后续字符是否为 `u`/`U`，归约为带后缀字面量。
3. 否则归约为无后缀字面量。

对于前导零判定：

- 十进制字面量以 `0` 开头且后接数字字符（包括通过下划线 `_` 分隔符连接的数字）时，视为非法前导零（[语言标准 §2.3.4]）；
- 该形态不符合附录 A 的 `dec_literal` 产生式，属**语法拒绝**（第 3 阶段 `TC_CE_SYNTAX`），不得改用 `TC_CE_LITERAL_OUT_OF_RANGE` 或 `TC_CE_LITERAL_TYPE`。

忽略分隔符后仍按数字序列判定。

特殊浮点值按最长匹配归约为 `float_special` Token：`inf`、`-inf`、`nan` 合法；负号仅可与有限浮点字面量或 `inf` 组合，**`-nan` 不符合附录 A 的浮点产生式**，属语法拒绝（第 3 阶段 `TC_CE_SYNTAX`，[语言标准 §2.4.2]）。

### 2.2 缩进处理

缩进由词法器维护的缩进级别栈处理（对应 [语言标准 §2.8] 的语句与行结构）：

1. 词法器维护由行首连续空格组数量构成的缩进级别栈，初始仅含顶层级别 `0`。
2. 每个非空、非纯注释逻辑行开始时，先检查第一个 Token 之前的字符：它们只能是 U+0020；行首出现 U+0009 均报 `TC_CE_INDENT_MIXED`。统计行首连续空格数量，必须能被 4 整除，否则为缩进错误。然后将空格组数量（空格数 / 4）与栈顶比较：增加时必须恰好增加 `1`，压栈并生成一个 `INDENT`；一次增加多组为缩进错误。减少时逐项出栈并为每次出栈生成一个 `DEDENT`。减少后的空格组数量必须等于某个既有栈值，否则为缩进错误。
3. 一级缩进恒为 4 个连续 ASCII 空格 U+0020。
4. 空行和纯注释行只生成 `NEWLINE`，不改变缩进栈；它们的行首 ASCII 空格/制表符不参与缩进字符或层级检查。
5. LF（`\n`）、CRLF（`\r\n`）或 CR（`\r`）均表示一个逻辑行结束，并生成一个 `NEWLINE`；文件结尾先补最后一个 `NEWLINE`（若缺少），再生成剩余 `DEDENT`，最后生成 `EOF`。
6. `INDENT`/`DEDENT` 只反映 `func`/`if`/`else`/`while`/`struct` 语句体的实际缩进；合法的函数内 `label` 是普通语句，不改变缩进栈。

## 3. 类型系统

本章对应 [语言标准 §3]。类型分类、转换与布局语义以语言标准为准；本节固定 `memblock<T, N>` 与 `ref<T>` 的编译器侧确定性约束，以及 `bool` 规范位模式验证。

### 3.0 内部类型事实源（禁止双轨）

编译器内部必须遵守单一事实源契约：

- **规则 1**：以「类型标签 + 类型参数」的单一表示贯穿符号、绑定、值与分析期期望类型；该表示在分析期构造完成后即固化，执行端与后端只读。
- **规则 2**：只用于类型判别、位宽与语义内核参数；禁止在绑定、值或符号上单独存裸标签充当完整类型。
- **规则 3**：声明类型在名称/类型语义阶段固化为完整类型后写入符号；`cast` / `bitcast` 的目标类型在同一阶段固化并写入该 RHS 的目标类型。复合类型不得经标量标签降级后写回绑定。
- **规则 4**：`memblock` 的规划个数 `N` 与结构体标识只存在于完整类型的类型参数中，不得在符号上冗余平行字段。
- **规则 5**：`cast` / `bitcast` 的目标类型解析必须接受完整类型语法（含 `ref<T>`）；`cast(ref<T>, none)` / `cast(addr<T>, nil)` 合法且跳过等宽检查，见 §3.7。
- **规则 6**：执行端与后端只读使用已解析的类型表示，不得在分析完成后重建或改写类型事实源。

### 3.0.1 类型宽度速查（`sizeof_bits`）

本节是实现查阅用的**索引表**。宽度语义与公式的权威定义在 [语言标准 §3.8.2]、[语言标准 §3.9.3]、[语言标准 §3.10.5]；本表不得另行引入与语言标准冲突的常数或例外。实现中的宽度计算、后端布局与 `bits_of` 内联必须与下表及所指条款一致。

**标量与引用（类型级固定）**：

| 类型 | `sizeof_bits`（位） | 权威条款 |
| ---- | ------------------- | -------- |
| `int8` / `uint8` / `bool` | 8 | [语言标准 §3.8.2]；`bool` 规范字节见 [语言标准 §3.4] |
| `int16` / `uint16` | 16 | [语言标准 §3.8.2] |
| `int32` / `uint32` / `float32` | 32 | [语言标准 §3.8.2] |
| `int64` / `uint64` / `float64` | 64 | [语言标准 §3.8.2] |
| `isize` / `usize` | 目标平台地址宽度（32 或 64） | [语言标准 §3.2.1]、[语言标准 §3.8.2] |
| `ref<T>`（`T` 为任意 `ref_pointee_type`：标量 / `memblock` / 结构体 / `ref<U>`） | `sizeof_bits(usize)` | [语言标准 §3.10.5] |
| `addr<T>`（任意合法 `T`，含 `void`） | `sizeof_bits(usize)` | [语言标准 §3.11.1] |

**复合类型（公式）**：

| 类型 | 公式 | 权威条款 |
| ---- | ---- | -------- |
| `memblock<T, N>` | `sizeof_bits(usize) + N × sizeof_bits(T)` | [语言标准 §3.8.2] |
| 结构体 `S` | `Σ_i ( sizeof_bits(field_i) + 8 × padding_i )` | [语言标准 §3.9.3] |

说明：

- **`void` 无宽度**：`void` 无 `sizeof_bits`；不得作为值槽、`memblock` 元素或（除结构体字段引用自引用例外外的）`ref` 所指；`addr<void>` 合法但宽度同 `addr<T>`。
- **`ref<T>` 的所指类型集比「`void` 以外的完整类型」更窄**：取 [语言标准 附录 A] 的 `ref_pointee_type`——标量 / `memblock` / 已定义结构体 / `ref<U>`；**不含 `void` 与 `addr<U>`**。`addr<U>` 虽是完整类型（可作值槽、`memblock` 元素与结构体字段），但 `ref<addr<U>>` 属**语法拒绝**（[语言标准 §3.10.1]）；同理，四条引用指令（`ref_load` / `ref_store` / `ref_of` / `ref_eq` / `ref_ne`）的显式类型参数也只接受该集合。
- **复合类型递归展开**：嵌套 `memblock` / 嵌套结构体按上表递归展开；布局与宿主 ABI 对齐无关。
- **`bits_of` 取值**：`bits_of(T)` 的编译期内联结果即为上表对类型 `T` 的取值（[语言标准 §6.8.5]）；该指令**无操作数**。
- **自引用结构体字段宽度**：结构体字段中的 `ref<S>`（`S` 为正在定义的本结构体）宽度仍为 `sizeof_bits(usize)`，不依赖 `S` 最终布局（[语言标准 §3.9.1]）。

### 3.1 memblock 编译器约束

`memblock<T, N>` 的类型仅由元素类型 `T` 决定；`N` 是编译期 `usize` 规划元素个数，不参与类型等价，但必须进入绑定的编译期元数据，供赋值、传参与下标检查使用（[语言标准 §3.8.1]、[语言标准 §3.8.4]）。运行时布局为 `usize` 长度头部紧随其后排列的元素数据（[语言标准 §3.8.2]）。

设计动机：`N` 是**绑定级容量约束**（声明时确定的元素个数规划，并与运行时长度头部一致），不是元素种类的一部分。将其留在类型等价之外，可使「同元素类型」的身份判定保持简单（类型等价只看 `T`），而在赋值/传参等需要整块兼容的上下文再用独立的 `N` 比较报 `TC_CE_MEMBLOCK_SIZE_MISMATCH`。实现不得把这两层合并成「不同 `N` 即不同类型」。

编译器必须：

- **记录规划个数 `N`**：绑定的完整类型必须持有声明 `N` 的数学值及元素类型 `T`。`N` 来源限于 [语言标准 §3.8.1] 的编译期 `usize` 常量：整数字面量（**含 `u`/`U` 后缀**——按 [语言标准 §2.3.1] 在无符号上下文合法；负号仅可与无后缀字面量组合）或类型为 `usize` 的 `let` / `static let` 标识符（含 `Self.` / 导入限定名）。来源不合法（运行时 `var`、形参、非常量表达式）**或数学值 `< 1`** → `TC_CE_CONSTANT_EXPRESSION`。
- **计算并记录类型级宽度**：`sizeof_bits(memblock<T, N>) = sizeof_bits(usize) + N × sizeof_bits(T)`（速查见 §3.0.1），其中 `sizeof_bits(T)` 按 [语言标准 §3.8.2] 的宽度表计算，`sizeof_bits(usize)` 为目标平台地址宽度。该宽度在编译期完全确定，供 memblock 整体赋值和按值传参使用。
- **比较规划个数**：赋值、`funcall` 初始化与按值传参在 `T` 相同之外，还须比较两侧声明的 `N` 数学值；不相等 → `TC_CE_MEMBLOCK_SIZE_MISMATCH`。不得把该检查推迟到运行时。
- **按 `N` 做边界**：`memblock_load` / `memblock_store` 使用 `0 ≤ i < N`；`memblock_copy` 的上界取自两侧声明的 `N`（[语言标准 §6.7.2.3]–[语言标准 §6.7.2.4]）。编译期可确定的负下标/负 `length`/越界 → `TC_CE_MEMBLOCK_INDEX_OUT_OF_RANGE`；否则运行时 → `TC_RE_MEMBLOCK_INDEX_OUT_OF_RANGE`。
- **`.count` 为编译期常量**：`mb.count` 结果等于声明 `N` 的数学值，可作为 `const_operand`；不得改写为运行时读头指令语义。
- **类型等价不含 `N`**：`memblock<int32, 10>` 与 `memblock<int32, 20>` 类型相同；仅在需要元素个数一致的上下文才比较 `N`。

禁止：

- **以优化替代 `N` 检查**：因优化而省略 `N` 不一致检查，或以宿主分配容量代替声明 `N` 作为语言级上界；
- **将 `N` 注入类型等价判定**：使不同 `N` 成为不同 `Tc` 类型。

### 3.2 托管引用类型编译器约束

`ref<T>` 语义以 [语言标准 §3.10] / [语言标准 §6.8] 为准；线性地址与区间见 §3.8。编译器侧必须：

- **类型携带所指 `T`**：`ref<int32>` 与 `ref<float64>` 不等价；赋值/传参两侧须严格同型，否则 `TC_CE_TYPE_MISMATCH`。`T` 取 [语言标准 附录 A] 的 `ref_pointee_type`——标量 / `memblock` / 已定义结构体 / `ref<U>`；**不含 `void` 与 `addr<U>`**（`ref<void>` 与 `ref<addr<U>>` 均属语法拒绝，不得静默接受）。
- **引用宽度**：`sizeof_bits(ref<T>) = sizeof_bits(usize)`，与 `T` 无关。该宽度是**抽象宽度**，不承诺引用值与整数位模式之间的任何关系。
- **`none` 由期望类型定型**：字面量本身无所指类型；在声明、`funcall` 实参、`return`、`cast` 等位置由唯一期望 `ref<T>` 定型。`none` 是编译期常量，可作为 `const_operand`。**空地址字面量是 `nil`（期望 `addr<T>`），见 §3.8**；把 `none` 用于地址位置（或 `nil` 用于引用位置）→ `TC_CE_TYPE_MISMATCH`。
- **禁止引用算术与序关系比较**：`ref<T>` 不得进入 `add`/`sub`/…、按位、移位、通用比较或逻辑运算；**托管引用不存在专用算术/序关系指令**（[语言标准 §3.10.8]）。`addr_add` / `addr_sub` 只接受 `addr<T>`（§6.8）。不合规 → `TC_CE_TYPE_MISMATCH`。
- **禁止位重解释与跨空间转换**：`bitcast` 不接受 `ref<T>` 操作数或目标；`ref<T>` 与 `addr<U>` 之间不存在 `cast` / `bitcast` / 隐式转换 → `TC_CE_TYPE_MISMATCH`。**编译器不得把引用值暴露为整数**，也不得让任何可观察行为依赖槽号或句柄数值。
- **`ref_of` 可变性**：仅接受 `var` / `static var` / 形参，且绑定声明类型须 ∈ `ref_pointee_type`——**`addr<T>` 类型的绑定不可取引用**（`ref<addr<T>>` 不是合法类型，[语言标准 §3.10.1]）；对 `let` / `static let` → `TC_CE_CONSTANT_ASSIGNMENT`。`ref_of` 非编译期常量，出现在 `const_rhs` 中属**语法拒绝**（`TC_CE_SYNTAX`）。
- **`ref_store` 可变性**：判据是**所指外层绑定**，与持有引用的绑定自身是否为 `let` 无关。`ref_of` 只接受可写目标，故实际可达的只读来源是形参取引用及由其复制的引用——命中 → `TC_CE_CONSTANT_ASSIGNMENT`（形参直接赋值/`read` 仍用 `TC_CE_PARAMETER_ASSIGNMENT`）。`let p: ref<T> = none` 一类常量空引用不报静态码，按空引用运行时分类处理。
- **空引用运行时分类**：`ref_load` / `ref_store` 遇 `none` → `TC_RE_NULL_REFERENCE_DEREFERENCE`；`ref_eq` / `ref_ne` 允许 `none` 比较，不触发运行时错误。引用没有算术指令，因此不存在「空引用算术」码；地址侧空值码见 §3.8。
- **`bits_of`**：`bits_of(T)`，**无操作数**，返回 `sizeof_bits(T)` 并在编译期内联。它是调用型 RHS：可整条充当 `const_rhs`，不属于 `const_operand`。
- **I/O 排除**：`write` / `writeln` / `read` 以 `ref<T>` / `addr<T>` 为显式类型属语法拒绝（`TC_CE_SYNTAX`）。
- **来源跟踪**：编译器应记录引用值来源（`ref_of`、`none`、现有绑定、函数返回值），供可变性交叉验证；这**不改变**静态接受集。
- **别名**：多个 `ref<T>` 可能指向同一对象；同一对象的连续 `ref_load` 与 `ref_store` 按源序执行，实现不得重排序跨 `ref_store` 的 `ref_load`。

### 3.3 结构体类型编译器约束

结构体类型语义以 [语言标准 §3.9] 为准。编译器侧必须：

- **类型定义唯一性**：结构体表按 `(定义模块名, 结构体名)` 定界；不同模块可同名。同一模块内结构体名不得与标量类型名、`memblock`/`ref` 类型名、关键字冲突（使用保留字属**语法拒绝** `TC_CE_SYNTAX`）。三类名称冲突分别定码（[语言标准 §3.9.1]）：同一模块重复定义同名结构体 → `TC_CE_DUPLICATE_STRUCT`；与同模块函数名或值绑定名冲突 → `TC_CE_FUNCTION_NAME_CONFLICT`；与导入名冲突 → `TC_CE_IMPORT_NAME_CONFLICT`。
- **结构体名解析**：类型语法为 `identifier \| imported_member_name`（[语言标准附录 A]）。解析阶段把未决名（裸名或 `Mod.Name`）记录为待解析名；分析阶段在注册结构体表时按**当前文件**的 `import` 列表解析。
- **裸名解析**：裸标识符仅解析为**当前模块**已定义的结构体；不得因依赖库中存在同名 `public struct` 而接受裸名（导入方写 `Player` → `TC_CE_UNDEFINED_STRUCT`）。
- **限定名解析**：`<模块名>.<结构体名>` 要求限定符为本文件已成功 `import` 的库（传递依赖不计入）；未 import 或目标库无该结构体 → `TC_CE_UNDEFINED_STRUCT`；存在但为 `private` → `TC_CE_PRIVATE_MEMBER_ACCESS`（不得改报 `TC_CE_UNDEFINED_STRUCT`）。
- **构造器名规范化**：值构造器名解析成功后规范化为定义模块的 `<模块名>.<结构体名>`，供后续查找使用。
- **字段类型检查**：字段类型仅可为标量（`scalar_type`）、`memblock<T, N>`（带 `N` 规划）、`ref<T>`、**`addr<T>`**（[语言标准 §3.9.1]、[语言标准 §3.11.6]），或结构体类型名。结构体名按 [语言标准 §3.9.1] 的位置规则分流：值位置（字段类型本身或 `memblock` 元素类型）允许本模块源序更早已成功定义完毕的结构体，以及经导入限定解析到的、目标库中已定义完毕的 `public struct`；禁止当前结构体自身与本模块前向引用。引用所指位置（某一层 `ref<…>` 的 pointee）只接受 [语言标准 附录 A] 的 `ref_pointee_type`（标量 / `memblock` / 结构体 / `ref<U>`；**不含 `void` 与 `addr<U>`**），或**正在定义的本结构体**（引用自引用）；仍禁止其它未完成定义的结构体名。值位置自引用 → `TC_CE_STRUCT_VALUE_SELF_REF`；前向引用或未定义结构体 → `TC_CE_UNDEFINED_STRUCT`。`void` 字段类型不合法。
- **字段声明约束**：每行恰好一个字段；至少 1 个字段（空结构体不合法）。字段定义处不得写 `=`（字段值只在值构造器中提供）。同一结构体内字段名唯一 → `TC_CE_STRUCT_DUPLICATE_FIELD`。
- **字段可变性记录**：符号表必须区分 `let` 字段（构造后不可通过字段赋值修改）与 `var` 字段（仅当外层绑定为可写 `var`/`static var` 时可修改，见 [语言标准 §3.9.5]）。

**值构造器静态验证**（在第 6 阶段子阶段 6d 执行）：

- **全字段必填**：必须为每个声明字段恰好提供一个命名实参；缺字段 → `TC_CE_STRUCT_MISSING_FIELD`；未知字段名 → `TC_CE_STRUCT_UNKNOWN_FIELD`；重复字段名 → `TC_CE_STRUCT_DUPLICATE_FIELD`；
- **文本顺序**：命名实参的文本顺序必须与字段声明顺序完全一致 → `TC_CE_STRUCT_FIELD_ORDER`；
- **类型一致**：每个实参类型必须与对应字段声明类型严格相同；字面量以字段类型为期望类型，按 [语言标准 §3.6] 检查；
- **常量上下文**：出现在 `let`/`static let` 的 `const_rhs` 中时，每个字段实参必须是合法编译期常量操作数 → `TC_CE_CONSTANT_EXPRESSION`。
- **字段赋值双层可变性检查**：同时检查外层绑定种类与目标字段种类（[语言标准 §3.9.5] 完整矩阵）。外层为不可变绑定时任何字段赋值均非法 → `TC_CE_CONSTANT_ASSIGNMENT`；外层可写但字段为 `let` → `TC_CE_STRUCT_IMMUTABLE_FIELD`；形参的字段赋值 → `TC_CE_PARAMETER_ASSIGNMENT`。
- **字段访问链**：`a.b.c` 整条是**一个** `operand`，不属于嵌套表达式；中间结果 `a.b` 须为结构体类型才能继续 `.c` 访问；任何层级类型为非结构体时报告 `TC_CE_TYPE_MISMATCH`。
- **`@padding(N)` 布局记录**：符号表为每个字段记录填充字节数 `N`（无后缀非负**十进制**整数字面量，允许 `0`）；省略时记录 `0`。`N` 带 `u`/`U` 后缀、进制前缀或负号（附录 A 的 `padding_attr` 经 `integer_literal` 在语法上接受）→ 静态语义阶段报告 `TC_CE_CONSTANT_EXPRESSION`（与 `N` / `count:` 来源不合法同码，[语言标准 §3.9.3]）。`@padding` 只改变布局字节数，不改变字段类型、可变性或构造器实参列表。编译器必须按 `sizeof_bits(S) = Σ_i ( sizeof_bits(field_i) + 8 × padding_i )` 计算结构体的类型级宽度并记录在符号表中，供整体赋值与按值传参使用。所有填充字节在构造与整块复制时均为 `0x00`。
- **禁止的操作**：结构体不得参与算术、位运算、比较（复用 `TC_CE_TYPE_MISMATCH`）、`bitcast`（`TC_CE_SYNTAX`）或标量 I/O（`TC_CE_SYNTAX`）。`cast` 不以结构体为源或目标。

### 3.4 memblock 构造器编译期验证

`memblock` 值构造器（[语言标准 §3.8.3]）在编译器侧的验证要点：

| 项 | 说明 |
| ---- | ---- |
| `count:` 合法性 | `count:` 实参必须是合法编译期 `usize` 常量（整数字面量以 `usize` 为期望类型——**含 `u`/`U` 后缀**，或类型为 `usize` 的 `let`/`static let` 标识符，含 `Self.` / 导入限定形式）。来源不合法或取值 `< 1` → `TC_CE_CONSTANT_EXPRESSION`（[语言标准 §3.8.3]）。 |
| 逐值初始化数量检查 | `memblock(T, count: N, v0, …, vₙ)` 的位置实参数量 `n+1` 必须等于 `N` 的数学值 → `TC_CE_MEMBLOCK_ELEMENT_COUNT_MISMATCH`。每个值类型必须与 `T` 严格一致。 |
| 填充形式 | `memblock(T, count: N, fill: v)` 中 `v` 类型须与 `T` 严格一致。 |
| 常量化 | 出现在 `let`/`static let` 的 `const_rhs` 中时，`count:` 和所有值操作数必须是编译期常量。 |
| `N` 记录 | 构造成功后，绑定的完整类型必须持有规划个数 `N` 与元素类型 `T`，供后续赋值/传参的 `N` 比较及 `.count` 常量访问使用。 |

### 3.5 整数类型编译器约束

编译器必须按 [语言标准 §3.2] / [语言标准 §3.5] 实现如下整数类型约束：

**有符号整数类型（`int8`～`int64`、`isize`）**：

- **表示**：二进制补码。编译器在类型系统内按位宽和符号性区分各整数类型；类型等价要求位宽与符号性均相同。
- **算术默认模式**：`add`/`sub`/`mul`/`neg` 默认 strict；`div` 的数学商不可表示（即 `INT_MIN / -1`）与 `abs(INT_MIN)` → `TC_RE_INTEGER_OVERFLOW`（运行时）或 `TC_CE_CONSTANT_OVERFLOW`（编译期）。
- **`wrap` 模式**：编译器必须在 `add`/`sub`/`mul`/`neg`/`shl` 上接受 `wrap` 关键字，此时按模 `2^n` 回绕，不报溢出。`div`/`mod`/`abs` 不接受 `wrap`（→ `TC_CE_MODE_MISMATCH`）；`shr` 在普通 RHS 中无模式参数位置，写了 `wrap` 属**语法拒绝** `TC_CE_SYNTAX`（附录 A `wrap_shift_expr` 只接受 `shl`），仅在 `let` RHS 的 `const_shift_expr` 形态下报 `TC_CE_MODE_MISMATCH`（§6.0.1）。
- **`shl` 默认 strict**：左移结果超出目标类型范围时报溢出；`wrap` 模式下截断高位。

**无符号整数类型（`uint8`～`uint64`、`usize`）**：

- **表示**：非负整数的 `n` 位二进制模式。
- **算术**：`add`/`sub`/`mul`/`neg` 固定模 `2^n` 回绕。无符号 `shl` 默认 strict（可检测值溢出），`wrap` 模式截断高位。
- **不接受模式关键字**：写了 `wrap` → `TC_CE_MODE_MISMATCH`（附录 A 的 `mode_binary_arith_expr` 对无符号类型同样提供模式槽，Token 序列被 EBNF 接受，故只能在静态语义阶段报告，不得改报 `TC_CE_SYNTAX`；[语言标准 §6.3.1]）。

**`isize` / `usize` 平台字长约束**：

- **目标字长**：宽度等于目标平台的地址宽度（32 或 64 位）。同一 TC 实现的所有编译单元共享同一目标字长。
- **本版固定 64 位目标字长**：`isize` / `usize` / 地址宽度与 memblock 长度头均为 64 位。
- **符号表位宽记录**：编译器必须在符号表中为 `isize`/`usize` 记录目标字长决定的具体位宽（运行时与 `int32`/`int64` 或 `uint32`/`uint64` 等价）。

- **`isize` 算术默认模式**：`isize` 的有符号算术默认 strict 模式，可选 `wrap` 模式，行为与同位宽 `int*` 一致。
- **`usize` 算术回绕**：`usize` 的算术固定模 `2^n` 回绕，与同位宽 `uint*` 一致。
- **与固定宽度整数的互操作**：`isize`/`usize` 与固定宽度整数之间的赋值、传参或运算须显式 `cast` 统一类型 → `TC_CE_TYPE_MISMATCH`。
- **`usize` 的使用位置**：`usize` 是 `memblock<T, N>` 中 `N` 的唯一合法类型，亦是 `memblock_load`/`memblock_store` 下标与 `memblock_copy` 区间操作数的推荐类型。
- **`isize`/`usize` 字面量范围**：`isize`/`usize` 的字面量形式与同位宽 `int*`/`uint*` 相同，由目标字长唯一确定期望范围。

### 3.6 字面量检查实现要点

编译器必须按 [语言标准 §3.6] 实现字面量与期望类型的统一检查。各类字面量的检查规则、错误码与阶段归属如下：

| 字面量类别 | 编译器检查规则 | 错误码 |
| ---------- | ------------ | ------ |
| 无后缀整数字面量 | 解析绝对值 `N`（`0 ≤ N ≤ 2^64−1`，词法阶段）；可带 `-`。有符号上下文要求数学值位于 [语言标准 §3.2] 对应范围；无符号上下文要求值非负且在范围内 | `TC_CE_LITERAL_OUT_OF_RANGE`（词法阶段上限）或在上下文中超范围时同样使用本错误码；`u` 后缀用于有符号上下文 → `TC_CE_LITERAL_TYPE` |
| `u`/`U` 整数字面量 | 不得带 `-`（语法拒绝，[语言标准 §2.3.1]）；仅用于无符号整数上下文；值须在对应范围内 | `TC_CE_LITERAL_TYPE`（仅「误用于有符号上下文」）；带 `-` 属语法拒绝 `TC_CE_SYNTAX`（第 3 阶段，附录 A `integer_literal` 不接受负号与 `u`/`U` 并用） |
| 普通浮点字面量 | 无后缀源类型为 `float64`，`f`/`F` 后缀源类型为 `float32`。有限十进制值直接按 roundTiesToEven 舍入到源类型（[语言标准 §2.4.1]）。词法阶段：非零有限值舍入为零或有限值舍入为无穷 → `TC_CE_LITERAL_OUT_OF_RANGE`。上下文阶段：源类型与期望类型不一致 → `TC_CE_LITERAL_TYPE` | `TC_CE_LITERAL_OUT_OF_RANGE` / `TC_CE_LITERAL_TYPE` |
| `inf`/`-inf`/`nan` | 词法层归约为 `float_special` Token，不携带类型。上下文阶段以期望类型定型（[语言标准 §2.4.1] 期望类型表）。仅用于浮点上下文；误用于非浮点上下文 → `TC_CE_LITERAL_TYPE` | `TC_CE_LITERAL_TYPE` |
| `true`/`false` | 结果类型为 `bool`，规范字节 `0x01`/`0x00`。仅用于 `bool` 上下文；误用于非 `bool` 上下文 → `TC_CE_LITERAL_TYPE` | `TC_CE_LITERAL_TYPE` |
| `none` / `nil` | 本身不携带类型。`none` 由期望 `ref<T>` 定型，`nil` 由期望 `addr<T>` 定型（[语言标准 §3.10.2] 期望类型表）。期望类型不匹配 → `TC_CE_TYPE_MISMATCH`。编译期常量，可作为 `const_operand` | `TC_CE_TYPE_MISMATCH` |

**统一检查顺序**：编译器在第 6d 子阶段对各上下文的字面量操作数按以下优先级执行检查：
1. 类别与符号性（整数有无 `u`、浮点有无 `f`/`F`、`none` 是否在引用上下文、`nil` 是否在地址上下文）；
2. 源类型与期望类型的一致性（浮点 `float32`/`float64`、`inf`/`-inf`/`nan` → 类型匹配）；
3. 值范围（整数范围、浮点舍入到期望类型的值可表示性）。

`wrap`、`ieee`、`truncate` 和 `bitcast` 均不绕过这些检查。

### 3.7 类型转换框架编译器约束

编译器必须对 [语言标准 §3.7] 的三种转换形式分别执行不同的静态验证与运行时检查策略：

| 转换形式 | 静态验证 | 运行时检查 | 说明 |
| -------- | -------- | ------------ | ---- |
| `cast(T, operand)` | 源、目标可为整数/浮点/`bool`/`ref<U>`→`ref<T>`/`addr<U>`→`addr<T>`。**引用与地址的类型转换均不附加等宽条件**：`ref<U>`→`ref<T>` 仅要求 `U`、`T` 均为合法的引用所指类型（[语言标准 附录 A] 的 `ref_pointee_type`：标量 / `memblock` / 结构体 / `ref`；不含 `void` 与 `addr`；引用值恒等宽，§3.2）；`addr<U>`→`addr<T>` 为**重标记**，`T`、`U` 为标量/`addr<V>`/`void`（含 `void`），不改地址位、不访存（§3.8、[语言标准 §3.11.3]）；不满足 → `TC_CE_TYPE_MISMATCH`。源为 `none`（→ `ref<T>`）或 `nil`（→ `addr<T>`）时无源所指类型，由目标类型定型。`ref<T>` 不可 `cast` 到整数/浮点/`addr<U>`；`addr<T>` 不可 `cast` 到整数/浮点/`ref<U>`（地址与等宽整数的互转须用 `bitcast`，§3.8） | 严格模式：范围检查触发 `TC_RE_CAST_OVERFLOW`；浮点到整数 NaN/无穷 → `TC_RE_CAST_OVERFLOW` | 数值转换含范围检查与规定舍入 |
| `cast(T, truncate, operand)` | 源与目标必须均为整数且目标更窄（`m < n`）；`m ≥ n` → `TC_CE_MODE_MISMATCH`；不接受非整数类型 | 无溢出检查；保留低 `m` 位 | 仅整数缩窄 |
| `bitcast(T, operand)` | 源与目标必须等宽 → `TC_CE_BITCAST_WIDTH`；`bool` 不可参与 → `TC_CE_TYPE_MISMATCH`；memblock/结构体不可参与 → `TC_CE_TYPE_MISMATCH`；**`ref<T>`、`none` 与 `nil` 完全不参与 `bitcast`**（与整数、浮点、其它 `ref<U>`、`addr<U>` 组合均 → `TC_CE_TYPE_MISMATCH`，§3.2；`bitcast(T, none)` 与 `bitcast(T, nil)` 同为非法，[语言标准 §6.6.1.1]、[语言标准 §6.6.6]）；`addr<T>` 与等宽整数/其它 `addr<U>` 可互转（地址往返语义，[语言标准 §6.9.1]）；整数与等宽浮点、等宽整数之间亦可互转 | 无运行时检查；位模式不变 | 等宽位重解释 |

| 项 | 规则 |
| ---- | ---- |
| 解析与固化 | `cast` / `bitcast` 的目标 `T` 必须在解析阶段按完整类型语法解析，并在分析阶段固化为稳定的完整类型表示后写入该 RHS 的目标类型，再以期望类型做类型等价校验 |
| 引用 `cast` | **不得再以「所指类型等宽」为条件**（引用值恒等宽，[语言标准 §3.7]） |
| `bitcast` | 仍须校验源目标位宽相等，并**完全排除 `ref<T>` / `none` / `nil` 参与**（[语言标准 §3.10.4]、[语言标准 §6.6.1.1]、[语言标准 §6.6.6]、[语言标准 §6.8.7]） |
| 只读使用 | 执行端与后端**只读**使用已解析的类型表示，不得在分析完成后改写类型事实源 |
| 不得拒绝 | 不得因内部使用类型标签投影而拒绝合法 `ref` 目标 |

**字面量操作数的源类型确定**：编译器在形成 `cast`/`bitcast` 调用节点时，必须按 [语言标准 §6.6.1.1] 的字面量源类型规则确定每个字面量操作数的内部表示类型，再执行上述检查。关键规则：

- **规则 1**：`cast` 中无后缀整数字面量的源类型为 `int64`，`u`/`U` 后缀为 `uint64`；
- **规则 2**：`cast` 中无后缀浮点字面量源类型为 `float64`，`f`/`F` 后缀为 `float32`；
- **规则 3**：`cast` 中 `inf`/`-inf`/`nan` 以目标类型为源类型，直接构造 canonical 位模式；
- **规则 4**：`cast` 中 `true`/`false` 的源类型为 `bool`，按 [语言标准 §6.6.5] 生成规范字节，不报 `TC_CE_LITERAL_TYPE`；
- **规则 5**：`bitcast` 中整数字面量的源位宽取目标类型的位宽，后缀决定有符号/无符号解释；
- **规则 6**：`bitcast` 中 `inf`/`-inf`/`nan` 的源类型由目标位宽决定（与目标同宽的浮点），直接构造 canonical 位模式，**不得**报 `TC_CE_BITCAST_WIDTH`；
- **规则 7**：`bitcast` 中浮点字面量的源精度由其 `f`/`F` 后缀唯一决定；与目标位宽失配 → `TC_CE_BITCAST_WIDTH`。

**`bool` ↔ 整数/浮点转换**（[语言标准 §6.6.5]）：编译器必须生成规范字节：`true`(0x01)→整数1/浮点1.0，`false`(0x00)→整数0/浮点0.0。

整数/浮点→`bool` 时，零(0/0.0)→`false`(0x00)，非零(含NaN)→`true`(0x01)。编译器必须验证写入 `bool` 目标的所有字节均已规范化为 `0x00`/`0x01`。

### 3.8 线性地址类型编译器约束

`addr<T>` 以 [语言标准 §3.11] / [语言标准 §6.9] 为准。编译器侧必须：

- **类型参数取值**：`addr<T>` 的 `T` ∈ 标量 \| `addr<U>` \| `void`；`addr<ref<U>>` / `addr<struct>` / `addr<memblock>` → `TC_CE_TYPE_MISMATCH`。
- **宽度**：`sizeof_bits(addr<T>) = sizeof_bits(usize)`（§3.0.1）。

- **跨空间互不转换**：`ref<T>` 与 `addr<U>` 之间禁止 `cast` / `bitcast` / 隐式转换。
- **算术步长**：`addr_add` / `addr_sub` 步长为 `sizeof_bytes(T) = sizeof_bits(T) / 8`，偏移类型 `usize`；**本版不提供** `addr_diff` / 地址序关系比较 / 区间拷贝（[语言标准 §1.4]）。
- **空值分类**：`addr_load` / `addr_store` 遇 `nil` → `TC_RE_NULL_ADDRESS_DEREFERENCE`；`addr_add` / `addr_sub` 遇 `nil` → `TC_RE_NULL_ADDRESS_ARITHMETIC`；`addr_io_load` / `addr_io_store` **不检查空地址**（地址 `0` 合法，不产生空值码）。空值与不可用码共四个，彼此不得混用。
- **易失档案**：`addr_io_*` 不得删除、合并、转发或重排；`addr_load` / `addr_store` 为普通内存访问，可按 §1.5 与 [语言标准 §1.3] 的变换合法性优化。
- **常量性**：只有常量 `addr(T, <常量 usize>)` 可整条充当 `const_rhs`（`const_addr_expr`）；`addr_load` / `addr_store` / `addr_io_*` / `addr_add` / `addr_sub` / `addr_eq` / `addr_ne` 不在 `const_rhs` 中（语法拒绝 `TC_CE_SYNTAX`）。
- **不可完成访问**：宿主映射类实现对不可用地址报 `TC_RE_ADDR_UNAVAILABLE`；裸机真地址实现按 [语言标准 §1.3] 第 3 项给出实现定义结果。不得降级为内部错误，也不得回退为槽访问。
- **字节序与对齐**：`addr_*` 访存的字节序是**目标地址空间**的属性，不是宿主属性（[语言标准 §3.11.4]）；实现应当把每次访问实现为逐字节访问序列，使访问对齐无关；**未对齐本身不是错误**，不产生任何 TC 诊断。依赖宿主语言的未对齐访存（其行为由宿主决定）不符合 [语言标准 §1.3] 的 as-if 规则；若实现不按字节访问，未对齐访问按 [语言标准 §1.3] 第 3 项归入地址不可用，宿主映射类实现须报 `TC_RE_ADDR_UNAVAILABLE`。
- **编译期可折叠**：常量 `addr`、常量 `addr_add`/`addr_sub` 可折叠；折叠结果必须与同一指令在抽象机中的运行时结果一致，并与 [语言标准 §6.9.5] 的算术语义、[语言标准 §3.11.3] 的往返语义、[语言标准 §1.3] 的 as-if 规则保持一致；**不得改变空值分类或运行时错误顺序**——`nil` 操作数的 `TC_RE_NULL_ADDRESS_ARITHMETIC` 不得因操作数为常量而被消除或提前为静态诊断。折叠**不改变** `const_rhs` 接受集：`addr_add` / `addr_sub` 仍不在 `const_rhs` 中（见上条「常量性」）。

## 4. 程序结构与模块系统

本章对应 [语言标准 §4]。模块模式、可见性与 `import` 语义以语言标准为准——含 [语言标准 §4.1] 的 `#program` 双文件约束（不得在 `#program` 内定义函数）与 [语言标准 §4.4] 的公开 `static var` 跨模块可变语义。本节规定第 4 阶段诊断的选择与定位；亦不得违反 [语言标准 §1.3] 一致性要求与 [语言标准 §4.4]。

### 4.1 模块结构与导入错误优先级

第 4 阶段的模块类错误按子阶段 4a → 4b → 4c 选择；同一子阶段内按主位置源序，主位置相同时按下表规则优先顺序。跨文件比较时，先按**导入方**源文件中触发该诊断的 `import` 或限定名主位置选择；环诊断的主位置规则见下。

**4a 单文件结构**（同一文件内）：`TC_CE_MODULE_LAYER` → `TC_CE_MISSING_VISIBILITY` → `TC_CE_PROGRAM_MODE_MISUSE`。

| 错误码 | 定位规则 |
| ------ | -------- |
| `TC_CE_MODULE_LAYER` | 定位到破坏层序的最早构造首 Token（例如插在导入区中的 `var`、`#program` 顶层可执行语句区之后的 `let` / `var` / `var_funcall_def`、`static` 区之前的 `func`）。其中「`#program` 声明出现在可执行语句之后」由附录 A 分区产生式拒绝，并在第 3 阶段按结构类语法阶段诊断映射为本错误码（见附录 A.3），主位置仍为该声明首 Token。 |
| `TC_CE_MISSING_VISIBILITY` | 定位到缺少修饰符的 `struct` / `static` / `func` 关键字（`#lib` 顶层成员未写 `public` / `private`；附录 A 产生式要求前缀，第 3 阶段结构类语法阶段诊断映射为本错误码，见附录 A.3）。 |
| `TC_CE_PROGRAM_MODE_MISUSE` | 定位到误用的 `func` / `Self` / `static` / `public` / `private` 关键字（含 `#program` 中带可见性前缀的 `struct`；[语言标准 §4.1]）。不得把「单文件顶层语句 + 辅助函数」接受为合法程序。 |

**4b 导入解析**：同一导入方文件内按 `import` 行源序；同一 `import` 上依次为：`TC_CE_IMPORT_NOT_FOUND` → `TC_CE_IMPORT_NOT_LIB` → `TC_CE_IMPORT_AMBIGUOUS` → `TC_CE_DUPLICATE_IMPORT` → `TC_CE_IMPORT_NAME_CONFLICT`。

- **规则 1**：找不到/非库/歧义均定位到该 `import` 的模块名标识符；歧义时把实现枚举到的最早候选路径作为关联附注（附注不参与主位置比较）。
- **规则 2**：重复导入定位到第二次及后续 `import` 的模块名，关联位置为首次同名 `import`。
- **规则 3**：导入名冲突定位到 `import` 的模块名，关联位置为冲突的本模块成员名。冲突名称的完整检查范围见 §4.6 "名称冲突检查范围"。

**4c 循环导入**：存在多个环时，选择包含源位置最早之 `import` 边的环；将该边固定为首边。环路径的确定算法与 §8.8 递归环相同（以模块为顶点、`import` 为边），主位置为该首边 `import` 的模块名标识符。不得由模块表或邻接表遍历顺序改变结果。

| 项 | 规则 |
| ---- | ---- |
| 归类 | `TC_CE_PRIVATE_MEMBER_ACCESS` 属于名称/可见性解析：函数与 `static` 成员在第 6/7 阶段；导入结构体类型名与值构造器在 4c 与 4d 之间的结构体表注册中 |
| 定位 | 限定名中的成员名标识符，关联位置为该私有成员的声明名 |
| 不得改报 | `TC_CE_UNDEFINED_VARIABLE`、`TC_CE_UNDEFINED_FUNCTION` 或 `TC_CE_UNDEFINED_STRUCT`（[语言标准 §4.4]） |
| 公开 `static var` | 跨模块读写（含作为 `read` 目标）按 [语言标准 §4.4] / [语言标准 §10.3] 保留完整语义，不得降级为警告 |

### 4.2 模块分层架构

编译器必须按 [语言标准 §4.1] 的五层模块结构实施分层检查。同一模块文件内顶层构造必须依次出现，跨层交错报告 `TC_CE_MODULE_LAYER`：

| 层序 | 内容 | `#program` 约束 | `#lib` 约束 |
|------|------|----------------|------------|
| 1 | 模式指令 | 必须 `#program` | 必须 `#lib` |
| 2 | `import` 声明区 | 所有 import 连续出现，可为空 | 同左 |
| 3 | `struct` 类型定义 | 不可带可见性修饰符；带修饰符 → `TC_CE_PROGRAM_MODE_MISUSE` | 必须带 `public` / `private`；缺修饰符 → `TC_CE_MISSING_VISIBILITY` |
| 4 | 值声明区 | `var` / `let`（禁止 `static`）；`static` → `TC_CE_PROGRAM_MODE_MISUSE` | `static var` / `static let`（必须带 `static`+可见性）；非 `static` → 语法拒绝 |
| 5 | 函数 / 语句区 | 顶层可执行语句，不可定义 `func`（→ `TC_CE_PROGRAM_MODE_MISUSE`） | `func` 函数定义（须带 `public` / `private`） |

- 各层内部允许空行和纯注释行。前四层全部完成后才可进入第五层。
- 结构体类型名定义成功后即可被同模块后续构造引用。
- 附录 A 的分区产生式在第 3 阶段执行结构类语法阶段诊断，将声明/语句分区破坏映射为 `TC_CE_MODULE_LAYER`（见附录 A.3）。
- `Self` 仅在 `#lib` 模块内有效，不得出现在 `#program` 中（→ `TC_CE_PROGRAM_MODE_MISUSE`）。
- `#lib` 中没有非 `static` 的顶层值作用域；模块状态只能是 `static let`/`static var`（函数内通过 `Self.` 访问）。

### 4.3 `static let` / `static var` 编译期约束

`#lib` 的 `static let` 和 `static var` 均须在声明时带初始化器。

**`static let`** 是编译期常量：其初始化器必须是 §5.2.1 描述的单层编译期常量表达式。**求值**属 CT，在第 9 阶段（见 §1.2）完成全部可达 `#lib` 的 `static let` 求值并内联到所有使用点；求值类诊断按 §1.3 挂起至全部 SEM 类诊断无触发后再报告。

**`static let`** 的来源与形态（[语言标准 §4.3]、[语言标准 §5.2.1]）

| 项 | 规则 |
| ---- | ---- |
| 检查阶段 | 第 6 阶段子阶段 6d（属 SEM） |
| 允许来源 | 仅限**字面量**与**源序更早且已成功求值的 `let` / `static let`**（含经 `Self.` / 导入限定解析到的 `static let`） |
| 禁止 | **不得引用 `static var`** |
| 违反时的码 | 在任一位置（整条 RHS、操作数、字段读基址、`.count` 基址、构造器字段值、`cast`/`bitcast` 源、`memblock` 的 `N` 与 `count:`）统一报 `TC_CE_CONSTANT_EXPRESSION` |

**`static var`**（[语言标准 §4.2]）

| 项 | 规则 |
| ---- | ---- |
| 存储 | 对应一个模块静态存储槽 |
| 初始化器形态 | 可为 §5.2.1 定义的单层编译期常量表达式，但不得含 `funcall` |
| 操作数来源 | 仅可为字面量、当前源序中更早已成功初始化的 `Self` 成员（`static let` 与 `static var`），以及经导入限定解析到的公开 `static let` / `static var`；不得引用局部 `var` 或函数形参 |
| 诊断归属 | 引用本模块中源序更晚（或自身）的静态成员时，该名称在源序可见性上尚未建立 → `TC_CE_UNDEFINED_VARIABLE`（与 [语言标准 §5.2.1] 的前向引用口径一致，故静态成员之间不形成初始化环）；操作数可见但不属于上述允许来源时 → `TC_CE_CONSTANT_EXPRESSION` |

编译器必须：

- 在完成模块依赖图检查后，按依赖拓扑序初始化所有可达模块的 `static var`。初始化器按**运行时指令语义**执行；形态检查通过后若求值失败（溢出、除零、无效浮点操作、严格转换失败等），报告对应的 `TC_RE_*` 码（[语言标准 §11.1]）并使整个程序准备失败；该阶段不引入新的错误码。
- 全程序共享同一 `static var` 槽：同一模块的所有导入者共享其 `static var`，导入不复制状态。
- 初始化表达式中的操作数引用执行以下验证：
  - 引用当前编译单元的 `Self.` 成员时，验证该成员已成功初始化（源序更早）；
  - 引用导入的公开 `static var` 时，验证该值在运行时已被初始化器成功提交；
  - 引用 `static let`（本库或导入的）时，直接使用编译期求值结果。

### 4.4 模式对照编译器约束

编译器必须按 [语言标准 §4.2] 的模式对照表，在第 4a 阶段对两种模式执行不同的接受集检查：

| 特性 | `#program` | `#lib` | 违反错误码 |
|------|-----------|--------|-----------|
| `func` 定义 | 禁止 | 允许（须带可见性） | `TC_CE_PROGRAM_MODE_MISUSE` |
| `static var` / `static let` | 禁止 | 允许（须带可见性） | `TC_CE_PROGRAM_MODE_MISUSE` |
| 顶层 `var` / `let` | 允许 | 禁止 | 语法拒绝 |
| `public` / `private` | 禁止 | 必须显式书写，无默认值 | `TC_CE_PROGRAM_MODE_MISUSE` / `TC_CE_MISSING_VISIBILITY` |
| `Self` | 禁止 | 允许 | `TC_CE_PROGRAM_MODE_MISUSE` |
| 顶层可执行语句 | 允许（入口） | 禁止 | 语法拒绝 |
| `goto` / `label` | 禁止 | 函数体内允许 | `TC_CE_LABEL_OUTSIDE_FUNCTION` / `TC_CE_GOTO_OUTSIDE_FUNCTION` |

编译器不得因目标模式而改变模块成员的类型系统行为或运行时语义。

### 4.5 `Self` 成员限定与可见性检查

编译器必须落实 [语言标准 §4.3] 的 `Self` 解析与 [语言标准 §4.4] 的可见性检查。函数与 `static` 成员在第 6/7 阶段检查；导入结构体类型名与值构造器在注册结构体表时检查（4c 之后、4d 之前）：

**`Self` 解析**：

- **规则 1**：`Self` 仅在 `#lib` 模块内有效，表示当前模块命名空间，不是值或运行时对象。
- **规则 2**：函数体内访问本库成员须使用 `Self.<名>`。
- **规则 3**：裸名引用本库成员 → `TC_CE_FUNCTION_SCOPE_ACCESS`（由 §8.4 的本库顶层成员名索引分类）。

**成员可见性检查**：

| 修饰符 | 本模块 `Self.<名>` | 导入模块 `<模块>.<名>` |
|--------|-------------------|----------------------|
| `public` | 可访问 | 可访问 |
| `private` | 可访问 | `TC_CE_PRIVATE_MEMBER_ACCESS` |

公开成员类别的读写规则：

| 公开成员类别 | 读写规则 |
|-------------|---------|
| `func` | 可调用 |
| `struct` | 可作为类型名与值构造器；导入方必须写 `<模块名>.<结构体名>`，裸名不解析为已导入结构体 |
| `static let` | 只读 |
| 标量 `static var` | 可读写，可作为 `read` 目标 |
| `memblock` / struct `static var` | 可读写，不可作为 `read`/`write`/`writeln` 整块目标 |

编译器不得将 `TC_CE_PRIVATE_MEMBER_ACCESS` 降级为 `TC_CE_UNDEFINED_VARIABLE`、`TC_CE_UNDEFINED_FUNCTION` 或 `TC_CE_UNDEFINED_STRUCT`，亦不得降级为警告（[语言标准 §4.4]、[语言标准 §1.3]）。

### 4.6 导入解析实现要点

编译器必须按 [语言标准 §4.5] 完成导入解析：

| 项 | 说明 |
| ---- | ---- |
| 位置约束 | `import` 必须在模式指令之后、类型/值声明之前（第二层），连续出现。安装在其他层 → `TC_CE_MODULE_LAYER`。 |
| 目标定位 | 对每个 `import <模块名>`，在编译器实现的模块搜索路径中唯一定位 `模块名.tc`。找不到 → `TC_CE_IMPORT_NOT_FOUND`；多候选 → `TC_CE_IMPORT_AMBIGUOUS`。 |

| 项 | 说明 |
| ---- | ---- |
| 模式验证 | 目标必须是 `#lib` 模块 → `TC_CE_IMPORT_NOT_LIB`。 |
| 重复检查 | 同一模块不可重复导入 → `TC_CE_DUPLICATE_IMPORT`。 |
| 名称冲突 | 导入名不得与本模块已在此前阶段收集的任何顶层名称同名。检查范围因模块模式而异，详见下文 "名称冲突检查范围"。 |
| 循环依赖 | 模块依赖图必须为有向无环图（DAG），以模块为顶点、`import` 为边。任一长度的循环（含自导入）→ `TC_CE_CIRCULAR_IMPORT`，即使环中函数未被调用。 |
| 命名空间语义 | 导入引入静态命名空间引用，不构造或复制模块。访问导入成员必须使用 `<模块名>.<成员名>` 限定。TC 不支持导入别名、选择性导入或通配导入。 |

**名称冲突检查范围**：

`TC_CE_IMPORT_NAME_CONFLICT` 在子阶段 4b 对每条 `import` 语句执行。此时子阶段 4a 已完整解析当前模块的全部顶层结构，所有模块成员名均已确定。因此检查覆盖当前模块的全部顶层名称，与它们相对于该 `import` 的文本位置（前或后）无关。

两种模式下受检查的名称集合如下：

| 模式 | 受检查的顶层名称 |
|------|----------------|
| `#program` | 顶层 `var` 名、顶层 `let` 名、`struct` 名。不含 `import` 引入的其他模块名（导入名之间的互斥由重复导入检查负责，见下）。不含关键字与保留标识符（它们在更早的语法阶段已被拒绝）。 |
| `#lib` | `func` 名、`struct` 名、`static let` 名、`static var` 名 |

因此，"导入名与本模块成员冲突"具体指：

| 项 | 说明 |
| ---- | ---- |
| 在 `#program` 中 | 若 `import foo` 且该模块顶层存在 `var foo: int32 = ...`、`let foo: int32 = ...` 或 `struct foo`，报告本错误； |
| 在 `#lib` 中 | 若 `import foo` 且该模块存在名为 `foo` 的 `func`、`struct`、`static let` 或 `static var`，报告本错误。 |

下列情形**不属于**本错误码：

- **规则 1**：`import` 后声明的同名 `var`/`let` 并不改变"源序较晚的名称被更早的 import 发现并报冲突"的规则：冲突判定以 4b 执行时已有的全部模块名称为基准，而非以各自定义语句的源序先后裁定。
- **规则 2**：用关键字或保留标识符（如 `import Self`、`import func`）作导入名 → 语法阶段 `TC_CE_SYNTAX`，不进入 4b。
- **规则 3**：同一模块被不同名称 `import` 两次（如 `import a` 后 `import b` 且 a.tc 与 b.tc 为同一文件）→ 4b 在冲突检查之前先由重复导入检查报告 `TC_CE_DUPLICATE_IMPORT`（见 §4.1 优先级）。两个 import 使用不同名称但目标不同模块时，各名称各自独立检查，不存在跨 import 的名称互斥。

准备程序时，编译器按依赖拓扑序处理全部可达导入库；同一模块对应全程序唯一的命名空间，所有导入者共享其 `static var` 槽。

### 5.2 常量定义（`let`）实现要点

`let` 声明必须在编译期完全求解；语义以 [语言标准 §5.2] 为准。编译器实现要点：

**5.2.1 编译期常量表达式形态验证**（第 6 阶段子阶段 6d）：

`const_rhs` 必须是 [语言标准 §5.2.1] 定义的原子表达式或单层调用表达式。编译器必须拒绝：

- **规则 1**：嵌套调用（如 `mul` 内嵌 `add`） → **语法拒绝** `TC_CE_SYNTAX`（调用形式不属于附录 A 的 `const_operand`，与引用指令、`memblock_load` 等非 `const_rhs` 形态同等对待，[语言标准 §5.2.1]、[语言标准 §1.3]）；
- **规则 2**：引用 `var` 变量或函数参数（含通过限定名间接引用 `static var`） → `TC_CE_CONSTANT_EXPRESSION`（"references runtime variable"）；
- **规则 3**：引用自身或尚未定义的 `let` → `TC_CE_UNDEFINED_VARIABLE`（在名称解析阶段拦截）；
- **规则 4**：非法常量形态 → `TC_CE_CONSTANT_EXPRESSION`（"invalid constant expression form"）。

- **允许的原子表达式**：各类字面量、`none` / `nil`、此前已定义 `let` 引用、只读结构体字段读取、`mb.count`
- **允许的单层运算调用**：算术 / 按位 / 移位 / 比较 / 逻辑 / `cast` / `bitcast`
- **允许的构造器**：memblock 构造器、结构体值构造器
- **只能整条充当 `const_rhs`**：`bits_of` 查询。详细清单见 [语言标准 §5.2.1]；`bits_of` 不得作为其它调用的操作数（[语言标准 §6.8.5]）
- **`none` / `nil` 的限制**：虽可作原子操作数（`let p: ref<int32> = none`、`let a: addr<int32> = nil`、`cast(ref<T>, none)`、`cast(addr<T>, nil)`），但**不参与 `bitcast`**——`bitcast(T, none)` 与 `bitcast(T, nil)` 均报 `TC_CE_TYPE_MISMATCH`（[语言标准 §6.6.1.1、§3.10.2]）

**5.2.2 声明类型闭合检查顺序**（第 6 阶段子阶段 6d）：

1. 先完成 `const_rhs` 内部的名称、运算支持类型、模式、操作数类型和字面量检查；
2. RHS 为直接字面量时，以 `let` 声明类型作为期望类型检查（[语言标准 §3.6]）；
3. RHS 为标识符时，以该绑定的声明类型为结果类型；结果类型与外层 `let` 声明类型不同 → `TC_CE_TYPE_MISMATCH`；
4. RHS 为单个调用表达式时，按调用自身规则确定结果类型；结果类型与声明类型不同 → `TC_CE_TYPE_MISMATCH`；
5. 只有以上检查全部成功后，才进入第 9 阶段的编译期算术求值。

**5.2.3 编译期求值**（第 9 阶段）：

- **求值**：按源序求值全部 `let` 常量；使用处直接内联编译期结果，不生成运行时算术指令或变量槽。
- **合法常量形态的求值错误**：
  - 常量溢出 → `TC_CE_CONSTANT_OVERFLOW`；
  - 常量除零 → `TC_CE_CONSTANT_DIV_ZERO`；
  - 常量转换溢出 → `TC_CE_CONSTANT_CAST_OVERFLOW`；
  - 浮点无效操作 / 负移位计数 → `TC_CE_CONSTANT_EXPRESSION`。

- **常量移位计数**：常量 `shl`/`shr` 的移位计数按整数类型直接取数学值。
- **逻辑短路不影响常量检查**：`and(bool, false, x)` 中的 `x` 仍必须是合法、可见且已求值的更早 `let bool`。

**5.2.3.1 浮点常量算术的精度规则**（编译器必须落实，对应 [语言标准 §5.2.3]）：

常量求值不得依赖宿主浮点环境（舍入模式、异常标志或宿主浮点库），必须按以下规则自行实现确定性求解：

1. 每条指令均按其显式类型参数独立执行：`float32` 使用 binary32，`float64` 使用 binary64。
2. 每条指令结束时立即按 roundTiesToEven 舍入到目标精度；不得统一提升为更高精度中间类型，也不得在连续 `mul`→`add` 上使用融合乘加（FMA）。
3. strict / `ieee` 模式的结果必须与同一指令在运行时执行完全一致。
4. 不得使用扩展精度、Flush-to-Zero（FTZ）或 Denormals-Are-Zero（DAZ）。
5. 必须保留非规格化数；非精确的非规格化结果触发下溢（`TC_CE_CONSTANT_OVERFLOW`），精确的非规格化结果合法。
6. 无效操作（含 NaN 参与 `add`/`sub`/`mul`/`div`/`mod`）→ `TC_CE_CONSTANT_EXPRESSION`；除零（含有限非零数对零取模）→ `TC_CE_CONSTANT_DIV_ZERO`；上溢或下溢 → `TC_CE_CONSTANT_OVERFLOW`。异常优先级按 [语言标准 §6.3.2] 顺序判定。
7. 浮点 `mod` 的编译期求值需按 [语言标准 §6.3.7] 的精确商向零截断语义实现：设有限操作数 `a`, `b`（`b != ±0`），先在数学实数域计算 `q = trunc(a/b)` 与 `r = a - q · b`，结果 `r` 在目标浮点类型中可精确表示，不产生上溢或下溢。

**5.2.4 静态布尔三态判定**（第 10 阶段）：

编译器在名称和类型检查完成后、CFG 构建前，对 `if`/`while` 条件执行三态判定（[语言标准 §5.2.2]，含形态归类表）：

- **静态 `true`**：RHS 合法且求值为 `true` → 仅 `then` 分支可达；
- **静态 `false`**：RHS 合法且求值为 `false` → 仅 `else` 分支（如存在）可达；
- **`unknown`**：RHS 不是合法单层常量表达式，或含 `var` → 真、假两边均可达。

合法常量形态的求值错误（溢出、除零等）必须报告并终止编译，不得降级为 `unknown`。形态白名单不在本说明书重开；以实现侧复用 [语言标准 §5.2] 常量表达式与 [语言标准 §5.2.2] 归类表为准。

### 6.0.1 算术模式验证矩阵

| 运算 | 类型 | 合法模式 | 非法模式 → 诊断 |
| ---- | ---- | -------- | --------------- |
| `add`/`sub`/`mul`/`neg` | 有符号整数 | strict（无关键字）、`wrap` | 其他关键字 → `TC_CE_MODE_MISMATCH` |
| `add`/`sub`/`mul`/`neg` | 无符号整数 | 固定模 `2ⁿ`；不接受模式关键字 | 写了 `wrap` → `TC_CE_MODE_MISMATCH`（附录 A 对无符号类型同样提供模式槽，不得改报 `TC_CE_SYNTAX`） |
| `shl` | 全部整数 | strict（无关键字）、`wrap` | |

| `shr` | 全部整数 | 无模式关键字 | 普通 RHS：无模式参数位置，写了 `wrap`/`ieee`/`truncate` 属**语法拒绝** `TC_CE_SYNTAX`（附录 A `wrap_shift_expr` 只接受 `shl`）；`const_shift_expr`（`let` RHS）：写了模式关键字 → `TC_CE_MODE_MISMATCH` |
| `add`/`sub`/`mul`/`div`/`mod` | 浮点 | strict（无关键字）、`ieee` | |
| `abs`/`neg` | 浮点 | 无模式关键字；纯符号位操作 | |
| 比较、逻辑、位运算 | 对应合法类型 | 无模式关键字 | |
| 所有运算 | `ref<T>` | 全程排除（[语言标准 §3.10.8]） | `TC_CE_TYPE_MISMATCH` |
| 所有运算 | `addr<T>` | 全程排除：地址算术仅 `addr_add` / `addr_sub`，地址等值比较仅 `addr_eq` / `addr_ne`（§6.8） | `TC_CE_TYPE_MISMATCH` |

### 6.0.2 浮点执行环境约束（编译器/后端必须遵循）

本文对应 [语言标准 §6.3.2] 的浮点执行环境。编译器生成代码时必须保证：

1. **固定舍入模式**：roundTiesToEven，不提供运行时舍入模式切换。
2. **禁止精度提升**：每条 `float32` 指令必须在 binary32 精度内执行并立即舍入，`float64` 同理。禁止保留超出目标类型的中间精度。
3. **禁止 FMA**：不得将独立的 `mul`/`add` 融合为融合乘加指令。
4. **保留非规格化数**：禁止 FTZ（flush-to-zero）与 DAZ（denormals-are-zero）。
5. **下溢判定**：采用 tininess-after-rounding；结果舍入到目标类型后为微小结果且本次舍入不精确时才触发。精确的非规格化结果不触发下溢。
6. **上溢/下溢定义**：有限结果舍入为无穷时定义为上溢（`TC_RE_FLOAT_OVERFLOW`）；微小非精确非规格化结果定义为下溢（`TC_RE_FLOAT_UNDERFLOW`）。
7. **异常优先级**：同一指令同时满足多个异常条件时，只报告最高优先级：`TC_RE_FLOAT_INVALID`（无效操作）→ `TC_RE_DIVISION_BY_ZERO`（除零）→ `TC_RE_FLOAT_OVERFLOW`（上溢）→ `TC_RE_FLOAT_UNDERFLOW`（下溢）。

### 6.0.3 浮点 `mod` 的商向零截断语义（编译器必须确保）

对应 [语言标准 §6.3.7]。编译器在生成 `mod(float32, a, b)` / `mod(float64, a, b)` 时，必须以本节算法**语义**为准（可自行实现，或在逐项验证宿主行为一致后委托宿主余数函数）：

1. 若任一输入为 NaN 或 `a` 为 ±inf：strict → `TC_RE_FLOAT_INVALID`；`ieee` → 返回 canonical quiet NaN。
2. 若 `a` 与 `b` 同时为 ±0：strict → `TC_RE_FLOAT_INVALID`；`ieee` → canonical quiet NaN。
3. 若 `a` 为有限非零、`b` 为 ±0：strict → `TC_RE_DIVISION_BY_ZERO`；`ieee` → canonical quiet NaN。
4. 若 `a` 有限、`b` 为 ±inf：结果按位等于 `a`。
5. 若二者均为有限且 `b != ±0`：设 `q = trunc(a / b)` `r = a - q · b`（均在数学实数域），结果 `r` 在目标类型中可精确表示。

TC 浮点 `mod` 的取模核心是「商向零截断」，**以 [语言标准 §6.3.7] 为准**；若实现选择委托宿主余数函数（如 C99 `fmod`），必须逐项验证其语义与本节一致（含符号、零结果符号、`a` 有限而 `b` 为无穷时按位等于 `a`、以及非规格化数不被冲刷），并**不得依赖宿主浮点环境**（舍入模式、异常标志、FTZ/DAZ，[语言标准 §6.3.2]）。

不得因为优化而采用向负无穷、向最近或向偶数截断。对 strict 模式，必须先判断 NaN/无穷/零除数的特殊情形，再进入实际求值。

### 6.1 右值表达式与操作数编译器验证

编译器必须按 [语言标准 §6.1] 的 RHS 分类实现以下验证：

#### 6.1.1 普通 RHS 类型检查

第 6d 子阶段对每个 RHS 调用执行类型检查。各类 RHS 的结果类型确定规则：

| RHS 形式 | 结果类型 | 编译器检查 |
| -------- | -------- | ---------- |
| 标识符 / 限定名 / 字段读取 | 绑定声明类型 | 名称解析成功且可见；`var`/参数须确定初始化 |
| 整数字面量 | 由期望类型决定 | 按 §3.6 检查符号性、类别与范围 |
| 浮点字面量 | 由 `f`/`F` 后缀决定 | 按 §3.6 检查源类型与期望类型一致性 |
| `float_special` | 由期望类型决定 | 仅浮点上下文；按 [语言标准 §2.4.1] 期望类型表定型 |
| 布尔字面量 | `bool` | 仅 `bool` 上下文 |
| `none` | 由期望 `ref<T>` 决定 | 按 §3.6；期望 `addr<T>` → `TC_CE_TYPE_MISMATCH` |
| `nil` | 由期望 `addr<T>` 决定 | 按 §3.6；期望 `ref<T>` → `TC_CE_TYPE_MISMATCH` |
| 运算调用 | 显式类型参数 `T` | 操作数类型须与 `T` 一致；模式合法性按 §6.0.1 矩阵 |
| `cast` / `bitcast` | 目标类型参数 | 按 §3.7 验证 |
| `memblock_load` | 显式元素类型 `T` | 按 §6.6 验证 |
| `memblock_constructor` | `memblock<T, N>` | 按 §3.4 验证 |
| `struct_constructor` | 结构体类型 | 按 §3.3 验证 |
| `ref_load` | 显式类型参数 `T` | 按 §3.2、§6.7 验证；`none` → `TC_RE_NULL_REFERENCE_DEREFERENCE` |
| `ref_of` | `ref<T>` | 按 §3.2、§6.7 验证；仅可作用于 `var`/`static var`/形参，且绑定声明类型 ∈ `ref_pointee_type`（`addr<T>` 绑定不可取引用） |
| `addr` | `addr<T>` | 按 §3.8、§6.8 验证；`u` 为 `usize`；常量时属 `const_rhs` |
| `addr_load` / `addr_io_load` | 显式类型参数 `T` | 按 §3.8、§6.8 验证；`addr_load` 的 `nil` → `TC_RE_NULL_ADDRESS_DEREFERENCE`；`addr_io_load` 不检查空地址 |
| `addr_add` / `addr_sub` | `addr<T>` | 按 §3.8、§6.8 验证；`nil` → `TC_RE_NULL_ADDRESS_ARITHMETIC` |
| `addr_eq` / `addr_ne` | `bool` | 同为 `addr<T>`（`T` 含 `void`）；`nil` = 地址 0，合法；跨类型 → `TC_CE_TYPE_MISMATCH` |
| `ref_eq` / `ref_ne` | `bool` | 同为 `ref<T>` 或含 `none`；跨 `ref<T>`/`ref<U>` → `TC_CE_TYPE_MISMATCH` |
| `bits_of` | `usize`（编译期常量） | 按 §3.2 验证；**无操作数**（`bits_of(T)`） |
| `.count` 访问 | `usize`（编译期常量） | 按 §3.1 验证 |

**`const_rhs` 额外约束**

| 项 | 规则 |
| ---- | ---- |
| 接受的形态 | `const_rhs` 仅接受 [语言标准 §5.2.1] 的原子表达式与单层调用 |
| 不在产生式内 | `ref_load`、`ref_of`、`ref_eq` / `ref_ne`、`addr_load`、`addr_add`、`addr_sub`、`addr_compare_expr`、`memblock_load`、`memblock_copy`、嵌套调用、`bits_of` 的嵌套 |
| 违反的后果 | **语法拒绝 `TC_CE_SYNTAX`**（[语言标准 §1.3]、[语言标准 §5.2.1]），不得改报 `TC_CE_CONSTANT_EXPRESSION` |

### 6.2 赋值语句编译器验证

编译器必须按 [语言标准 §6.2] 对赋值语句执行以下静态检查：

| 赋值形式 | 左侧约束 | 右侧约束 | 类型检查 |
| -------- | -------- | -------- | -------- |
| `<标识符> = <rhs>` | 可写 `var` / `static var`；`let` → `TC_CE_CONSTANT_ASSIGNMENT`；形参 → `TC_CE_PARAMETER_ASSIGNMENT` | 普通 RHS 或非 `void` `funcall` | RHS 结果类型与左侧声明类型严格一致 → `TC_CE_TYPE_MISMATCH` |
| `<标识符>.<字段> = <rhs>` | 基址为结构体类型；字段存在且可写 | 类型与字段声明类型严格一致 | 双层可变性检查（[语言标准 §3.9.5]）：外层可写 + 字段为 `var` |

**确定初始化检查**：赋值目标必须在当前 CFG 点已确定初始化（见 §9.2）。`var` 声明时的 `=` 初始化器不受本节的确定初始化检查——该检查只针对独立赋值语句的目标变量。

### 6.3 算术运算编译器验证

除 §6.0.1 的模式验证矩阵外，编译器还须按 [语言标准 §6.3] 执行以下检查：

#### 6.3.1 操作数类型一致性

- **规则 1**：所有算术运算的两个（或单个）值操作数的类型必须与显式类型参数 `T` 严格一致 → `TC_CE_TYPE_MISMATCH`。
- **规则 2**：字面量按类型参数 `T` 为期望类型检查（§3.6）。
- **规则 3**：`ref<T>` 不得进入任何算术运算 → `TC_CE_TYPE_MISMATCH`。

#### 6.3.2 运算特定约束

| 运算 | 编译器特定检查 |
| ---- | ------------ |
| `add` / `sub` / `mul` | 有符号默认 strict；`wrap` 合法；无符号不接受模式关键字 |
| `div` / `mod` | 不接受模式关键字；整数除数不能为编译期常量 0 → `TC_CE_CONSTANT_DIV_ZERO`（编译期）或 `TC_RE_DIVISION_BY_ZERO`（运行时） |
| `abs` / `neg` | 不接受模式关键字；有符号 `abs(INT_MIN)` → `TC_RE_INTEGER_OVERFLOW`（运行时）或 `TC_CE_CONSTANT_OVERFLOW`（编译期） |
| `shl` / `shr` | 仅整数；有符号 `shl` 默认 strict（可选 `wrap`）；移位计数按类型 `T` 的数值语义解码 |

#### 6.3.3 浮点异常优先级

编译器在 strict 模式下必须按以下优先级报告首个异常（[语言标准 §6.3.2]）：

1. `TC_RE_FLOAT_INVALID`（最高）
2. `TC_RE_DIVISION_BY_ZERO`
3. `TC_RE_FLOAT_OVERFLOW`
4. `TC_RE_FLOAT_UNDERFLOW`（最低）

不得合并或重新排序这些异常。

### 6.4 位运算编译器验证

编译器必须按 [语言标准 §6.4] 执行以下位运算检查：

| 运算 | 类型约束 | 操作数约束 | 模式约束 |
| ---- | -------- | ---------- | -------- |
| `and` / `or` / `xor` | 仅整数类型（有/无符号均可）或 `bool` | 两个操作数与显式 `T` 一致 | 无模式关键字；按位与布尔逻辑共享同一关键字 |
| `not` | 仅整数类型或 `bool` | 单操作数与显式 `T` 一致 | 同上 |
| `shl` / `shr` | 仅整数类型 | 移位操作数与显式 `T` 一致；移位计数操作数须为整数类型 | `shl` 有符号默认 strict，可选 `wrap` |

- **规则 1**：浮点类型不得参与位运算 → `TC_CE_TYPE_MISMATCH`。
- **规则 2**：`ref<T>` / `addr<T>` 不得参与位运算 → `TC_CE_TYPE_MISMATCH`。
- **规则 3**：`shl`/`shr` 的移位计数按类型 `T` 的数值语义解码：数学值小于 0 → `TC_RE_NEGATIVE_SHIFT_COUNT`（运行时）或 `TC_CE_CONSTANT_EXPRESSION`（编译期，子条件 "negative shift count"）。

### 6.5 比较与逻辑运算编译器验证

编译器必须按 [语言标准 §6.5] 执行以下检查：

#### 6.5.1 比较运算

| 运算 | 类型约束 | 特殊规则 |
| ---- | -------- | -------- |
| `eq` / `ne` / `lt` / `le` / `gt` / `ge` | 显式类型 `T` 可为整数或浮点；不接受 `ref<T>` / `addr<T>` | 操作数类型须与 `T` 一致；标识符操作数声明类型 ≠ `T` → `TC_CE_COMPARISON_TYPE_MISMATCH` |
| `ref_eq` / `ref_ne` | 显式类型 `T` 为所指类型；两个操作数同为 `ref<T>` | 同型 `ref<T>` 或 `none`；跨 `ref<T>`/`ref<U>` → `TC_CE_TYPE_MISMATCH` |
| `addr_eq` / `addr_ne` | 显式类型 `T` 为所指类型（含 `void`）；两个操作数同为 `addr<T>` | `nil` = 地址 0，合法；跨类型 → `TC_CE_TYPE_MISMATCH` |

**比较结果类型**：所有比较运算的结果类型固定为 `bool`。

#### 6.5.2 逻辑运算

| 运算 | 类型 | 操作数约束 | 短路规则 |
| ---- | ---- | ---------- | -------- |
| `and(bool, ...)` | `bool` | 两个操作数类型为 `bool` | 短路：左操作数为 `false` 时不求值右操作数；`let` 中仍须检查右操作数合法性 |
| `or(bool, ...)` | `bool` | 两个操作数类型为 `bool` | 短路：左操作数为 `true` 时不求值右操作数 |
| `xor(bool, ...)` | `bool` | 两个操作数类型为 `bool` | 不短路：两侧均求值 |
| `not(bool, ...)` | `bool` | 单操作数类型为 `bool` | 不适用 |

短路裁剪只免除不可达右操作数的**确定初始化读取检查**（[语言标准 §6.5.2.2]），不免除其词法、语法、名称和类型检查。

### 6.6 memblock 操作编译器验证

本节补充 §3.1 / §3.4 之外的 memblock 操作级编译器检查，对应 [语言标准 §6.7]。

#### 6.6.1 `memblock_load` 验证

| 检查项 | 规则 |
| ------ | ---- |
| 显式类型 `T` | 元素类型，须为 `void` 以外的完整类型 |
| 操作数 | `mb` 须为 `memblock<T>` 类型绑定；`index` 须为整数类型操作数 |
| 结果类型 | `T` |
| 确定初始化 | `mb` 为运行时 `var` 时须已确定初始化 |
| 编译期越界 | 下标为编译期常量且 `i < 0` 或 `i ≥ N` → `TC_CE_MEMBLOCK_INDEX_OUT_OF_RANGE` |
| 运行时越界 | 下标不满足 `0 ≤ i < N` → `TC_RE_MEMBLOCK_INDEX_OUT_OF_RANGE` |

#### 6.6.2 `memblock_store` 验证

| 检查项 | 规则 |
| ------ | ---- |
| 显式类型 `T` | 元素类型，须为 `void` 以外的完整类型 |
| 操作数 | `mb` 须为可写 `memblock<T>` 绑定（`let` → `TC_CE_CONSTANT_ASSIGNMENT`）；函数形参 memblock 只可修改其**副本**元素（[语言标准 §8.1.1]），对形参绑定本身赋值 → `TC_CE_PARAMETER_ASSIGNMENT`；`index` 须为整数；`value` 须为 `T` 类型 |
| 边界检查 | 同 `memblock_load` |
| 确定初始化 | `mb` 须已确定初始化 |

#### 6.6.3 `memblock_copy` 验证

- **显式类型 `T`**：元素类型；与 `dst`、`src` 的元素类型同时严格一致
- **操作数**：`dst` 可写（`let` → `TC_CE_CONSTANT_ASSIGNMENT`）；`src` 可为只读/可写；`dst_index`、`src_index`、`length` 为整数类型操作数（彼此类型可不同，也不必等于 `T`）
- **区间检查**：半开区间均在声明 `N` 范围内：`length ≥ 0 ∧ 0 ≤ dst_index ∧ 0 ≤ src_index ∧ dst_index + length ≤ N_dst ∧ src_index + length ≤ N_src`；`length = 0` 合法（允许下标等于 `N`，不修改元素）。编译期可确定越界 → `TC_CE_MEMBLOCK_INDEX_OUT_OF_RANGE`；运行时 → `TC_RE_MEMBLOCK_INDEX_OUT_OF_RANGE`
- **执行语义**：先拷入临时缓冲再写入目标（等价于 memmove），避免重叠区间问题。抽象执行：先把源区间 `[src_index, src_index + length)` 的 `length` 个元素按抽象位串拷入临时缓冲，再按相同顺序写入目标区间。同一绑定上的重叠区间行为完全确定
- **不重新规范化**：源元素已是合法 TC 值（含 `bool` 的 `0x00`/`0x01`），拷贝保持位串不变。<br>`memblock_copy` 不是 `let` 常量表达式的一部分；出现在 `const_rhs` 中属**语法拒绝**（`TC_CE_SYNTAX`，[语言标准 §5.2.1]）

**拷贝区间检查的确定性实现**：

由于 `N_dst` 与 `N_src` 均为编译期常量，编译器应在静态检查中尽可能多地发现越界情况。具体策略：

1. 若 `dst_index`、`src_index`、`length` 均为编译期常量，执行完整的静态区间判定。
2. 若其中任一为运行时值，仅检查 `length` 是否为编译期负常量（→ `TC_CE_MEMBLOCK_INDEX_OUT_OF_RANGE`），其余边界推迟到运行时。
3. 运行时越界 → `TC_RE_MEMBLOCK_INDEX_OUT_OF_RANGE`，按 §11.2 的提交规则不修改 `dst` 的任何元素。

### 6.7 托管引用操作编译器验证

本节补充 §3.2 之外的引用指令级检查，对应 [语言标准 §6.8]。

| 指令 | 显式类型 | 操作数 | 关键约束 | 编译期常量？ |
| ---- | -------- | ------ | -------- | ------------ |
| `ref_load(T, r)` | `ref_pointee_type`（标量 / `memblock` / 已定义结构体 / `ref<U>`；**不含 `void` 与 `addr<U>`**，[语言标准 §3.10.1]） | `r`: `ref<T>` | `none` → `TC_RE_NULL_REFERENCE_DEREFERENCE`；`T = bool` 时结果规范化（§6.7.1） | 否 |
| `ref_store(T, r, value)` | `ref_pointee_type`（标量 / `memblock` / 已定义结构体 / `ref<U>`；**不含 `void` 与 `addr<U>`**，[语言标准 §3.10.1]） | `r`: `ref<T>`；`value`: `T` | 所指外层可写；`none` 同上 | 否（语句） |
| `ref_of(T, ident)` | `ref_pointee_type`（标量 / `memblock` / 已定义结构体 / `ref<U>`；**不含 `void` 与 `addr<U>`**，[语言标准 §3.10.1]） | `ident`: `var` / `static var` / 形参，且其声明类型不得为 `addr<T>`（`ref<addr<T>>` 不是合法类型） | `let` / `static let` → `TC_CE_CONSTANT_ASSIGNMENT`；`T` 须与 `ident` 声明类型严格一致 | 否 |
| `ref_eq(T, r1, r2)` / `ref_ne(T, r1, r2)` | `ref_pointee_type`（标量 / `memblock` / 已定义结构体 / `ref<U>`；**不含 `void` 与 `addr<U>`**，[语言标准 §3.10.1]） | 同为 `ref<T>` | `none` 合法；两个 `none` 比较 → `true` / `false`；跨类型 → `TC_CE_TYPE_MISMATCH` | 否（`none` 比较可折叠） |
| `bits_of(T)` | `T`（完整类型，不含 `void`；**含** `ref<U>` / `addr<U>`） | **无操作数** | 返回 `sizeof_bits(T)` 并在编译期内联；可整条充当 `const_rhs`，不属于 `const_operand` | 是 |

**禁止的形态**（[语言标准 §3.10.8]）：托管引用**没有**算术与序关系比较指令——`ref_add` / `ref_sub` / `ref_diff` / `ref_lt` 一类形态不在附录 A 中，出现即语法拒绝；`addr_add` / `addr_sub` 属线性地址空间（§6.8），**不得接受 `ref<T>` 操作数**。

**引用操作数的形式**：`ref<T>` 操作数可为任意 `operand`——裸标识符、`Self.<名>`、`<模块名>.<名>`、结构体字段读取、以及 `none`；**仅 `ref_of` 例外**，其标识符限于裸名或限定名（附录 A 已限定）。限定名与字段访问链（`a.b.c`）整条按**一个** `operand` 计，不属于嵌套表达式（[语言标准 §6.1.2]）。

**调用型 RHS**：`ref_load`、`ref_of`、`ref_eq` / `ref_ne`、`bits_of` 均**不属于 `operand`**，只能整条充当 RHS，被嵌套时语法拒绝（`TC_CE_SYNTAX`）；`ref_store` 为独立语句。

#### 6.7.1 `ref_load` / `ref_store` 的 `bool` 规范化

`T = bool` 时：`ref_load(T, r)` 读出的字节须按 [语言标准 §3.4] 规范化后提交（`0x00` → `false`，其它 → `true`）；`ref_store(T, r, v)` 写入前规范化为 `0x00` / `0x01`。各后端必须一致。

### 6.8 线性地址操作编译器验证

对应 [语言标准 §6.9]；类型级约束见 §3.8。

#### 6.8.1 指令表

| 指令 | 显式类型 | 操作数 | 关键约束 | 编译期常量？ |
| ---- | -------- | ------ | -------- | ------------ |
| `addr(T, u)` | `T` ∈ 标量 / `addr<U>` / `void` | `u`: `usize` | 不访问内存；`u` 为编译期常量时整条可充当 `const_rhs`（`const_addr_expr`） | 是（常量 `u`） |
| `addr_load(T, a)` | `T` 标量 / `addr<U>`（非 `void`） | `a`: `addr<T>` | `nil` → `TC_RE_NULL_ADDRESS_DEREFERENCE`；不可完成访问 → `TC_RE_ADDR_UNAVAILABLE`；非易失 | 否 |
| `addr_store(T, a, v)` | 同上 | `a`: `addr<T>`；`v`: `T` | 同上；写入不适用 `TC_CE_CONSTANT_ASSIGNMENT` | 否（语句） |
| `addr_io_load(T, a)` | 同上 | `a`: `addr<T>` | **不检查空地址**；易失：次数与顺序可观察 | 否 |
| `addr_io_store(T, a, v)` | 同上 | 同上 | 同上 | 否（语句） |
| `addr_add(T, a, n)` / `addr_sub(T, a, n)` | `T` 非 `void` | `a`: `addr<T>`；`n`: `usize` | `nil` → `TC_RE_NULL_ADDRESS_ARITHMETIC`；步长 `sizeof_bytes(T)`；不检查越界 | 否（常量可折叠） |
| `addr_eq(T, a, b)` / `addr_ne(T, a, b)` | `T` 任意（含 `void`） | 同为 `addr<T>` | `nil` 合法（即地址 0）；不触发运行时错误 | 否 |

#### 6.8.2 编译器必须执行的检查

1. **类型参数一致性**：`T` 与操作数声明类型严格一致；`addr<void>` 不得用于访问与算术（`addr_load` / `addr_store` / `addr_io_load` / `addr_io_store` / `addr_add` / `addr_sub`）；本版不存在地址差、序关系比较与区间拷贝指令，`addr_eq` / `addr_ne` 允许 `addr<void>`。
2. **非法所指类型**：`addr<ref<U>>` / `addr<struct>` / `addr<memblock>` → `TC_CE_TYPE_MISMATCH`。
3. **跨空间禁止**：`ref<T>` 不得作为任何 `addr_*` 操作数；`addr<T>` 不得作为任何 `ref_*` 操作数 → `TC_CE_TYPE_MISMATCH`。
4. **数学值判定**：所有下标 / 长度 / 偏移的负值与边界判定按**数学值**（有符号解码后）进行，不得先按无符号回绕再比较。
5. **常量折叠**：常量 `addr`、常量 `addr_add` / `addr_sub` 可折叠；结果须与同一指令在抽象机中的运行时结果一致，并与 [语言标准 §6.9.5] 的算术语义、[语言标准 §3.11.3] 的往返语义及 [语言标准 §1.3] 的 as-if 规则保持一致，且不得改变空值与错误分类；折叠不改变 `const_rhs` 接受集，也不得消除 `nil` 操作数的 `TC_RE_NULL_ADDRESS_ARITHMETIC`。
6. **易失保序**：优化不得删除、合并、转发或重排 `addr_io_load` / `addr_io_store`。
7. **调用型 RHS**：`addr`、`addr_load`、`addr_io_load`、`addr_add`、`addr_sub`、`addr_eq` / `addr_ne` 均**不属于 `operand`**（嵌套 → `TC_CE_SYNTAX`）；`addr_store`、`addr_io_store` 为独立语句。
8. **不可完成访问**：宿主映射类实现对不可用地址报 `TC_RE_ADDR_UNAVAILABLE`；不得降级为内部错误，也不得回退为槽访问。
9. **字节序与对齐**：`addr_load` / `addr_store` / `addr_io_load` / `addr_io_store` 的字节序按执行访存的目标地址空间确定，不依赖宿主（[语言标准 §3.11.4]）；后端不得把未对齐访问实现为宿主未对齐访存——按字节访问时未对齐不构成错误，不按字节访问时按 [语言标准 §1.3] 第 3 项报 `TC_RE_ADDR_UNAVAILABLE`。

## 7. 控制流分析

本章对应 [语言标准 §7]。控制流语句的源语言规则以语言标准为准；本节规定 CFG 构建、控制流域边界，以及 `goto`/`label` 与 CFG 类诊断优先级。

### 7.1 代码块与 CFG 基本块

TC 将源语言的**代码块**与控制流图中的 CFG 基本块严格区分（代码块定义见 [语言标准 §7.1.4]）：

- **代码块**：是由 `then` / `else` / `end` 词法结构界定的直接语句序列，用于名称作用域、局部变量生命周期、标签可见性、`goto` 的块关系和缩进检查。函数的 `then … end` 构成函数体代码块；`if` 的 `then` 分支和 `else` 分支分别构成两个互不包含、不可比的兄弟代码块，无 `else` 时只有 `then` 代码块；`while` 的 `then … end` 构成循环体代码块。嵌套 `if` / `while` 开启新的代码块。
- **CFG 基本块**：CFG 基本块是没有内部控制流分叉的最大连续 CFG 节点序列。函数入口、条件分支目标、循环入口/退出点与 `label` 均形成 CFG 基本块入口；`return`、`goto`、`break`、`continue` 及条件分支节点终结当前 CFG 基本块。
- **`label` 与基本块**：`label` 不开启代码块、不创建作用域、不改变缩进层级；但由于它是跳转目标，必须形成新的 CFG 基本块入口。

### 7.2 顶层 CFG

顶层 CFG：

1. 具有唯一入口和唯一程序正常结束节点，入口已初始化集合为空。
2. 顶层绑定只由顶层声明和顶层数据流产生。
3. 文件末尾连接程序正常结束节点，不执行缺少返回检查。
4. 顶层 `return` 在 CFG 构建前拒绝。
5. 顶层及其嵌套块中的 `goto` / `label` 在 CFG 构建前分别以 `TC_CE_GOTO_OUTSIDE_FUNCTION` / `TC_CE_LABEL_OUTSIDE_FUNCTION` 拒绝；顶层不建立标签表，也不生成 `goto` 边。
6. 顶层 `funcall` 是单个原子节点，不产生到被调函数 CFG 的边。

### 7.3 函数 CFG

每个函数 CFG 至少包含唯一入口、函数体语句与控制节点、每条 `return` 的正常返回终止节点，以及表示未经 `return` 到达 `end` 的唯一函数末尾节点。

1. `IN[entry]` 恰好包含当前函数全部形参，不包含顶层绑定、调用者局部绑定或其他函数状态。
2. `if`、`while`、`break`、`continue`、`goto` 和标签沿用本章规则，但所有边必须留在当前函数 CFG 内。
3. `return` 只连接当前函数的正常返回终止节点，没有函数内后继边。
4. `funcall` 在调用者 CFG 中保持单节点；成功的非 `void` 调用若用于 `var` 初始化则把新绑定加入 `OUT`，若用于已有变量赋值则仅更新该绑定的值（不改变 `IN`/`OUT` 的成员关系）；`void` 调用不改变已初始化集合。
5. 按§9.2.1 从函数唯一入口遍历 CFG（路径语义见 [语言标准 §9.2]）；任何不在可达集合中的语句节点报 `TC_CE_UNREACHABLE_STATEMENT`。只有入口可达节点参与确定初始化固定点和函数末尾检查；不可达代码的词法、语法、名称和类型检查仍执行。
6. 函数末尾节点可达时报缺少返回；无出口循环不产生到函数末尾的边。

顶层 CFG 与各函数 CFG 是完整、封闭、彼此独立的分析单元，不得拼接、内联或共享节点、边、可达性、已初始化集合、活动块路径或固定点状态。实现可复用算法，但不得合并各域的入口、出口和语义状态。

### 7.4 函数控制流边界

顶层与每个函数是彼此封闭的控制流域；只有函数建立标签表。`return` 只退出当前函数，`break`/`continue` 只解析到当前函数内最内层 `while`。`goto`/`label` 的查找、块关系和诊断严格按 [语言标准 §7.3] 执行并在函数边界停止：跨函数或跳向顶层的边不进入 CFG，不同函数中的同名标签互不相关。

### 7.5 `goto` / `label` 上下文错误优先级

`goto` 与 `label` 必须先检查是否具有 `func` 词法祖先。没有函数祖先时分别报告 `TC_CE_GOTO_OUTSIDE_FUNCTION` 或 `TC_CE_LABEL_OUTSIDE_FUNCTION`，定位到关键字；该语句不参与标签表、名称解析或 CFG 构建。

只有确认位于函数体内后，才检查是否具有 `while` 词法祖先；违反时分别报告 `TC_CE_GOTO_INSIDE_LOOP` 或 `TC_CE_LABEL_INSIDE_LOOP`。因此，位于顶层 `while` 内的 `goto` / `label` 固定报告"函数外使用"，而不是"循环内使用"。

**`while` 循环内优先级判定**（[语言标准 §7.2.3]）：

| 诊断 | 条件 | 错误码 |
|------|------|--------|
| 函数外 `goto` | `goto` 无 `func` 祖先 | `TC_CE_GOTO_OUTSIDE_FUNCTION` |
| 函数外 `label` | `label` 无 `func` 祖先 | `TC_CE_LABEL_OUTSIDE_FUNCTION` |
| 循环内 `goto` | `goto` 有 `while` 祖先 | `TC_CE_GOTO_INSIDE_LOOP` |
| 循环内 `label` | `label` 有 `while` 祖先 | `TC_CE_LABEL_INSIDE_LOOP` |

函数内合法上下文中的 `label` 才进入当前函数标签表，函数内合法上下文中的 `goto` 才继续执行标签查找、跨函数判定和块关系检查。

标签查找必须按 [语言标准 §7.3.2] 从 `goto` 所在块沿祖先链由内向外进行，最近同名标签胜出。

若可见链查找失败且当前函数存在多个不可见同名候选：

- 诊断类别固定按"后代块 `TC_CE_JUMP_INTO_BLOCK` 优先于不可比块 `TC_CE_JUMP_INCOMPATIBLE_BLOCK`"选择；
- 同类别内以源位置最早的标签作为关联位置。

不得使用标签表或哈希表的自然遍历顺序选择目标或诊断。

编译器必须先收集全部函数中通过上述上下文检查的标签，再解析任何函数内 `goto`；跨函数诊断不得依赖函数定义顺序、标签表遍历顺序或当前正在分析的函数。

本小节中的全部 `goto` / `label` 上下文、名称、控制流域和块关系错误均属于第 6 阶段（子阶段 6a 控制流上下文 + 6b 名称作用域预建 + 6c goto/label 名称解析）。只有完成标签绑定并通过全部上述检查的 `goto` 才能在第 11 阶段进入当前函数 CFG；CFG 阶段不产生 `goto` / `label` 合法性诊断。

### 7.6 CFG 错误优先级

顶层和全部函数 CFG 构建完成后，CFG 类错误按源位置统一选择，不依赖内部分析顺序。同一位置依次为：`break` / `continue` 位置 → 按§9.2.1 从控制流域入口不可达的语句 → 确定初始化 → 缺少返回。

存在多个不可达语句时，选择源位置最早者，不依赖 CFG 节点遍历顺序。所有 `goto` / `label` 合法性诊断已在第 6 阶段（子阶段 6a–6c）按 §7.5 完成；非法跳转不进入 CFG，也不参与本阶段的错误选择。

缺少返回定位到函数定义头的返回类型，但与其他 CFG 错误比较源位置时使用该函数体 `end` 的位置；函数内有明确位置的 CFG 错误因此优先。多个函数都缺少返回时选择定义最早者。

## 8. 函数与调用模型

本章对应 [语言标准 §8]。函数语法、调用模型与无环要求以 [语言标准 §8.4]–[语言标准 §8.6] 为准；本节规定签名/`funcall`/`return` 诊断优先级、本库成员名索引，以及调用图与递归环的确定性算法。

### 8.1 函数签名错误优先级

第 5 阶段的候选错误包括函数重名、签名内名称冲突，以及全局函数名与顶层值作用域直接值绑定的冲突。多个候选先按本节规定的主位置选择源序最早者；同一主位置再按以下顺序：函数重复定义 → 函数名与顶层值作用域直接值绑定冲突 → 参数重名 → 参数名与全局函数名冲突。顶层嵌套块和函数体 `var` / `let` 的同名冲突在第 6 阶段按 §1.3 处理。

- **规则 1**：重复函数定位到第二次及后续定义的函数名。
- **规则 2**：函数名冲突定位到冲突的值绑定名，并把全局函数定义名作为关联位置。
- **规则 3**：参数重名定位到第二次及后续出现的参数名。
- **规则 4**：参数名冲突定位到冲突参数名。

参数和返回类型的语法接受集已由附录 A 的 `value_type` / `return_type` 穷尽规定；不符合该产生式的类型 Token 在第 3 阶段报告 `TC_CE_SYNTAX`，不得进入第 5 阶段，也不存在"参数类型非法"或"返回类型非法"的第 5 阶段候选。

**形参类型检查实现要点**：

函数形参可声明为以下类型（[语言标准 §8.1.1]：标量 / `ref<T>` / `addr<T>` / `memblock<T, N>` / 已定义结构体），编译器必须在第 6 阶段验证实参与形参的类型兼容性：

| 形参类型 | 合法实参形态 | 按值语义 |
|---------|------------|---------|
| 标量（`scalar_type`，含 `isize`/`usize`） | `operand`（标识符/限定名/字段读取/字面量）；运算、转换、构造器、`funcall` 不可 | 复制标量值 |
| `memblock<T, N>` | 标识符（已声明带长度 memblock 绑定），或 `memblock_constructor`（填充/逐值） | 深拷贝全部存储区（含长度头部与元素数据） |
| `ref<T>` | 同型 `ref<T>` 的任意 `operand`——裸标识符、`Self.<名>`、`<模块名>.<名>`、结构体字段读取（字段类型为 `ref<T>`），或 `none`（[语言标准 §6.1.2]、[语言标准 §6.8.7]） | 复制引用值（地址），不复制所指对象；传参后源与形参指向同一对象 |
| `addr<T>` | 同型 `addr<T>` 的任意 `operand`（**含 `nil`**）；裸标识符 / 限定名 / 字段读取 / `nil`，运算与 `funcall` 不可 | 复制地址整数，不访问所指内存（[语言标准 §3.11.6]）；传参后源与形参持有同一地址值 |
| 结构体类型 | 同类型标识符（含限定名、字段读取），或同类型 `struct_constructor` | 整块深拷贝（含各带长度 memblock 字段的完整存储区） |

- 每个形参类型是实参的唯一期望类型，不执行隐式转换。字面量按 [语言标准 §3.6] 以形参类型为上下文检查。
- **形参只读绑定**：入口已初始化。对形参**绑定本身**赋值、字段赋值或作为 `read` 目标 → `TC_CE_PARAMETER_ASSIGNMENT`。对形参做 `ref_of` 本身合法（**`addr<T>` 类型的形参除外**——`ref<addr<T>>` 不是合法类型，[语言标准 §3.10.1]）；经该引用再 `ref_store` → `TC_CE_CONSTANT_ASSIGNMENT`（[语言标准 §6.8.3]、[语言标准 §8.1.2]），不得改报 `PARAMETER_ASSIGNMENT`。
- **非法形参类型**：`void` 不得用作形参类型（语法拒绝）；`ref<void>` 不合法（静态语义拒绝）；**`ref<addr<U>>` 亦不合法且属语法拒绝**（`ref_pointee_type` 不含 `addr_type`，[语言标准 §3.10.1]），故地址型绑定与形参不能被 `ref_of` 取引用。
- **memblock 形参 `N` 比较**：`memblock<T, N>` 形参在传参时须比较两侧声明的 `N` 数学值，不相等 → `TC_CE_MEMBLOCK_SIZE_MISMATCH`（见 §3.1）。
- **`ref<T>` 形参按值传递**：复制引用值（地址），调用者与函数体共享所指对象。函数体内对形参做 `ref_load` 合法。对该引用值做 `ref_store` 写入的是所指对象，合法性按所指外层绑定判定，不因引用本身是形参而改报 `PARAMETER_ASSIGNMENT`。多参数均为 `ref<T>` 值时可能互为别名。

**返回类型检查实现要点**：

- **规则 1**：返回值类型可为任意值类型（含 `ref<T>`、`addr<T>`）或 `void`（[语言标准 §8.1.1]）。`memblock<T, N>` 与结构体返回时整块复制；`addr<T>` 返回时复制地址整数。
- **规则 2**：非 `void` 函数的所有可达路径必须有 `return <operand>`；`void` 函数必须有裸 `return`。
- 返回操作数类型必须与声明返回类型严格相同 → `TC_CE_RETURN_TYPE`。字面量按返回类型检查。

收集全部函数名是本阶段的前提，但诊断不得取决于函数表遍历顺序。

### 8.2 `funcall` 错误优先级

多个调用有错时选择 `funcall` 位置最早的调用。选定调用后依次检查：

1. 目标函数是否存在或是否因作用域/可见性不可直接以当前书写形式调用：不存在时定位到函数名，报告 `TC_CE_UNDEFINED_FUNCTION`，不检查实参；裸名命中本库 `func` 时报告 `TC_CE_FUNCTION_SCOPE_ACCESS`；经导入限定解析到存在但为 `private` 的函数时报告 `TC_CE_PRIVATE_MEMBER_ACCESS`。后两者与"不存在"同级，均抑制实参检查。
2. 调用位置是否适合返回类型；非 `void` 独立调用 → `TC_CE_FUNCALL_POSITION`，`void` 用于 `var` 初始化或已有变量赋值 → `TC_CE_FUNCALL_RESULT_TYPE`（三者均定位到 `funcall`，不检查实参；[语言标准 §8.2.3]、[语言标准 附录 B.12]）。
3. 实参重复、未知、缺失、数量超限、顺序、类型，按此顺序检查；数量超限（`TC_CE_EXTRA_ARGUMENT`）**仅在全部实参名称已知时**判定（[语言标准 §8.2.2]），不得抢先于重复/未知/缺失。
4. 非 `void` 调用接收变量的声明类型：`var` 声明为声明类型 Token，已有变量赋值为赋值目标标识符。在实参全部合法后检查；返回类型与接收声明类型不一致时报 `TC_CE_TYPE_MISMATCH`（[语言标准 附录 B.4]），错误定位到声明类型 Token 或目标标识符。

实参重复定位到第二个重复名称；未知实参定位到最早未知名称；缺失实参定位到右括号并指出声明顺序最靠前的缺失形参；顺序错误定位到第一个名称已知、集合完整但与对应位置形参不同的名称；类型错误定位到最早不匹配操作数。

只有实参名称全部已知、唯一且集合完整时才检查顺序；只有顺序正确后才从左到右检查类型。单个实参先检查名称，再检查类型类别，最后按 [语言标准 §3.6] 检查字面量符号性、后缀和范围。合法字面量不能用于形参类型时沿用字面量专用诊断，不降级为笼统实参类型错误。

实参个数多于形参且名称全部已知 → `EXTRA_ARGUMENT`（[语言标准 §8.2.2]）；名称未知 → `UNKNOWN_ARGUMENT`；名称集合完整但文本顺序不符 → `ARGUMENT_ORDER`。

### 8.3 `return` 错误优先级

多个 `return` 有错时选择关键字位置最早者；同一条依次检查：是否在函数体内 → 有值/无值形式是否匹配 → 返回名称是否合法 → 返回类型是否匹配 → 返回字面量是否合法且可表示。

顶层返回和形式错误定位到 `return`；返回类型错误定位到操作数；未定义或越过函数边界的返回操作数分别使用名称类错误码，但统一在第 8 阶段按本小节顺序报告；字面量问题同样在第 8 阶段检查并沿用字面量专用诊断。

### 8.4 本库顶层成员名索引

| 项 | 说明 |
| ---- | ---- |
| 建立时机 | 在 `#lib` 模块中，名称作用域预建阶段（见 §1.2 6b）为当前模块建立**本库顶层成员名索引** |
| 目的 | 落实 [语言标准 §8.4.1] 对 `TC_CE_FUNCTION_SCOPE_ACCESS` 的分类要求 |
| 适用范围 | **函数体内的一切裸名访问位置**——RHS/操作数（运算、比较、逻辑、位运算、移位、`cast`/`bitcast`、构造器字段）、`return` 操作数、`if`/`while` 条件、输出操作数、赋值目标、`read` 目标，以及 `memblock` 声明类型中的 `N` 与构造器 `count:` 的操作数 |
| 分类效果 | 这些位置均由本索引统一分类，**不得**降级为 `TC_CE_UNDEFINED_VARIABLE` |
| 索引内容 | 全部 `func` / `static let` / `static var` 的声明名（不分 `public` / `private`） |
| 用途限制 | **仅用于错误分类**，绝不把这些名字注入函数体的普通裸词查找 |

函数内普通裸名查找失败后，按以下规则分类诊断：

1. 若该名存在于本库顶层成员名索引，报告 `TC_CE_FUNCTION_SCOPE_ACCESS`（须写作 `Self.<名>`）；
2. 否则报告 `TC_CE_UNDEFINED_VARIABLE`（值位置）或按 `funcall` 规则报告 `TC_CE_UNDEFINED_FUNCTION`（调用目标位置）。

此分类统一适用于普通 RHS、赋值目标、`read` 目标、`let` 依赖、`funcall` 第一项与实参、以及 `return` 操作数。

### 8.5 `funcall` 调用语法编译器验证

编译器必须按 [语言标准 §8.2.1] 的调用者位置规则验证 `funcall` 的第一项书写形式：

| 调用者位置 | 本库函数写法 | 导入库函数写法 | 裸 `identifier` |
| ---------- | ------------ | -------------- | --------------- |
| `#program` 顶层 | 禁止（`TC_CE_PROGRAM_MODE_MISUSE` 在第 4a 阶段拒绝） | `<模块>.<函数名>` | `TC_CE_UNDEFINED_FUNCTION` |
| `#lib` 函数体 | `Self.<函数名>` | `<模块>.<函数名>` | 命中本库→`TC_CE_FUNCTION_SCOPE_ACCESS`；否则→`TC_CE_UNDEFINED_FUNCTION` |

`funcall` 的每项实参必须使用 `<形参名>: <实参>` 形式，每个形参恰好匹配一个实参。不做隐式转换；字面量以形参类型为期望类型检查。

**返回值使用位置验证**（[语言标准 §8.2.3]）：

| 调用写入位置 | 非 `void` 函数 | `void` 函数 |
| ------------ | ------------- | ----------- |
| `var x: T = funcall(...)` | 合法 | `TC_CE_FUNCALL_RESULT_TYPE` |
| `x = funcall(...)` | 合法（`x` 须已确定初始化） | `TC_CE_FUNCALL_RESULT_TYPE` |
| 独立 `funcall(...)` | `TC_CE_FUNCALL_POSITION` | 合法 |
| `let` / `return` / 嵌套实参 | 语法拒绝（`TC_CE_SYNTAX`） | 语法拒绝 |

非 `void` 函数的返回类型与接收 `var` / 赋值目标的声明类型不一致时报 `TC_CE_TYPE_MISMATCH`（[语言标准 §8.2.3]、[语言标准 附录 B.4]），不使用 `TC_CE_FUNCALL_RESULT_TYPE`——后者只用于「`void` 调用出现在需要值的位置」。

### 8.6 调用帧

在实现 [语言标准 §8.5] 的抽象调用帧时，每次 `funcall` 至少创建以下逻辑状态：

- 被调函数标识；
- 返回地址或等价继续点；
- 按形参绑定的实参值；
- 函数局部 `var` 槽；
- 活动块路径和函数内控制流状态；
- 非 `void` 函数的返回值位置。

规范不强制各后端使用相同物理布局，但可观测语义必须一致。

### 8.7 调用步骤

实现必须按下列顺序落实 [语言标准 §8.5] 的调用步骤：

1. 按形参声明顺序，从左到右检查同一文本位置的实参名称和期望类型，并读取实参操作数。
2. 任一运行时错误立即终止整个程序。
3. 创建被调函数帧并写入参数值。
4. 从函数体第一条语句开始执行。
5. 执行 `return` 时销毁函数帧并恢复调用者。
6. 非 `void` 结果若用于 `var` 声明则初始化新变量，若用于已有变量赋值则覆盖目标变量的当前值。

### 8.8 无环调用图

编译器必须为全部函数体内的 `funcall` 建立有向调用图，以实现 [语言标准 §8.6]；顶层调用可以作为无入边的外部根记录，但不参与函数间环判定。调用图边不是 CFG 边，不参与确定初始化、可达性或控制流传播。

若函数调用图存在环，无论相关调用点运行时是否可达，均报递归错误。自调用是长度为 1 的环；间接递归同样非法。

### 8.9 递归错误的确定规则

调用图环检查只在更早阶段全部成功后执行。存在多个递归强连通分量时，选择包含源位置最早函数定义的分量，再选择该分量内源位置最早、且目标仍在该分量内的调用点；将其调用边固定为首边 `e0 = (u, v)`，并在该调用点的函数名处报告递归错误。

诊断必须给出一个有限、确定的简单环路径。若 `u == v`，环路径只含自递归首边 `e0`。否则，在所选强连通分量内，从 `v` 到 `u` 的全部不重复函数顶点的简单路径中，先选择调用边数量最少者；仍有并列时，将各路径上的调用点源位置序列按 `(行, 列)` 做字典序比较，选择最小者。

最终环路径为首边 `e0` 加该返回路径，除闭合起点外不得重复函数顶点。有限调用图中该算法必定终止，且不得由哈希表、图节点或邻接表的自然遍历顺序改变结果。

### 8.10 调用深度上界 `D`

调用图无环（§8.8）与"语言不存在函数指针或间接调用"（[语言标准 §8.1.4]）共同给出 [语言标准 §8.6] 的正面保证：**最坏抽象活动帧数有静态上界**。编译器必须：

1. **计算 `D`**：`D` = 调用图中最长有向路径的顶点数（无环，故每个函数至多计一次）。顶层调用点作为外部根记录，但不增加函数间路径长度。
2. **可静态规划**：实现可据 `D` 与各函数帧大小在编译期规划栈/帧容量；帧大小与栈布局属实现细节，不是可观察行为。
3. **不得以 `D` 改变语义**：`D` 只用于资源规划与完整性检查；不得据此拒绝规范接受的程序（超出实际可用资源属实现失败，见 §1.5 第 2 条）。
4. **不引入时间界**：`D` 是**栈界**，与循环次数无关。
5. **内联与帧复用属实现自由**：`D` 只界定**抽象**活动帧数；实现是否内联、展开或复用物理帧，均不改变接受集、诊断与可观察行为，也不得把「可内联」当作放宽或收紧接受集的依据（[语言标准 §8.6]）。

## 9. 作用域、生命周期与确定初始化

本章对应 [语言标准 §9]。作用域规则、生命周期表与确定初始化的路径语义以 [语言标准 §9] 为准；本节给出编译器必须实现的作用域预建细节、CFG 构建与数据流固定点求解，使分析结果与语言路径语义一致且与遍历顺序无关。

### 9.1 作用域

TC 采用全局函数签名表 + 顶层值作用域 + 函数作用域 + 块级作用域：

| 项 | 说明 |
| ---- | ---- |
| 全局函数签名表 | 编译器先于函数体分析前收集全部函数签名。函数名全局可见，只有 `funcall` 的首项在此解析（RHS 不解析函数名）。 |
| 顶层值作用域 | `#program` 中不在 `if`/`while` 块内的 `var`/`let` 属顶层，遵循源序可见性，生命周期贯穿程序始终。`#lib` 无非 `static` 顶层值作用域，模块状态只能是 `static let`/`static var`（函数内通过 `Self.` 访问，见 [语言标准 §4.3]）。 |

| 项 | 说明 |
| ---- | ---- |
| 函数作用域 | 每个函数体是独立作用域（含只读参数、局部 `var`/`let` 及嵌套块）。名称查找到函数边界即止。每次调用创建独立帧，不共享参数或局部变量。 |
| 块级作用域 | `if` 的 `then`/`else` 为互斥兄弟块；`while` 的 `then … end` 为循环体块。兄弟分支中标识符互不可见（允许同名）。嵌套块可屏蔽外层同名绑定，但禁止重新声明全局函数名与函数形参。块内 `var`/`let` 离开块后不可访问。 |
| 标签作用域 | 标签限于函数体内，受函数边界与 `while` 隔离约束（[语言标准 §7.2.3]）。`goto` 沿祖先链由内向外查找，首个同名标签胜出；同块禁止同名标签。每个函数有独立标签表，顶层无标签表。 |
| 源序可见性 | 绑定从声明结束后的词法位置开始可见；初始化器不可引用当前绑定或尚未声明的标识符。`var` 的执行状态由 §9.2 确定初始化分析判定；`let` 统一在编译期求值内联，不受运行时路径影响。函数签名先于函数体收集，可调用后定义的函数（调用图不得有环，见 §8.7）。 |
| 变量生命周期 | 顶层变量启动时建槽，执行 `var` 时初始化；参数在帧建立时写入、返回时销毁；局部变量进入作用域时建槽，执行 `var` 时初始化；离开块时销毁（`end`/`break`/`continue`/`return`/`goto`），物理槽可复用。反向跳转/下一迭代重新初始化同一槽。`let` 无运行时槽。 |

### 9.2 变量生命周期与确定初始化

| 阶段 | 行为 |
| ---- | ---- |
| 作用域进入 | 建立本作用域全部 `var` 的固定槽位，初始状态为"未初始化" |
| `var` 执行 | 先检查并计算普通 RHS 或执行非 `void` `funcall` 初始化器，再写入对应槽位；成功后状态变为"已初始化" |
| 赋值 / `read` / `memblock_store` / `memblock_copy` / `ref_store` | 目标变量（及 `copy`/`store` 的目标块、引用所指的可写外层绑定）必须已确定初始化；成功后更新同一槽位内容，不改变其生命周期；`memblock_copy` 另须读取源块（`let` 源不进入 `IN` 检查）；`ref_load` / `addr_add` / `addr_sub` 读取绑定本身（非所指对象）时同样要求绑定 ∈ `IN` |
| 运行时绑定读取 | `var` 或参数绑定必须在当前 CFG 点上确定初始化，否则静态错误 `TC_CE_UNINITIALIZED_VARIABLE`；`let` 已在编译期内联，不属于本行 |
| 反向跳转 / 下一迭代 | 再次执行 `var` 时重新初始化同一槽位，不创建新绑定或新槽位 |
| 作用域离开 | 因正常 `end` / 循环回边、`break`、`continue`、`return` 或向外 `goto` 离开当前块实例时，结束局部生命周期并清除其确定初始化状态；物理槽可复用 |
| `let` | 编译期求值并内联，不生成运行时槽；在 CFG 中保留无运行时效果的身份节点，仅参与源级可达性诊断，数据流传递函数为恒等 |
| 参数 | 函数入口时已初始化，只读；不得对绑定本身赋值或作为 `read` 目标（`TC_CE_PARAMETER_ASSIGNMENT`）。经 `ref_of` 后再 `ref_store` → `TC_CE_CONSTANT_ASSIGNMENT` |
| `return` | 终止当前函数 CFG 路径，销毁当前函数帧及活动块局部槽 |

### 9.2.1 CFG 可达性与确定初始化数据流

编译器必须分别为顶层语句区和每个函数建立封闭 CFG。顶层 CFG 处理结构化控制流，不含 `goto` / `label` / `return`；函数 CFG 在同一分析框架中额外处理函数内 `goto` / `label` 与 `return`。不同控制流域不得共享节点、边或数据流状态。

**CFG 边与可达性**：

1. 在 [语言标准 §5.2] 常量求值和静态布尔三态判定完成后构建 CFG；静态 `true` / `false` 条件删除不可能边，`unknown` 条件保留真、假两边。
2. 附录 A `statement` 产生式接受的每条源语句均建立对应的源级 CFG 节点；其中 `let` 是无运行时效果的身份节点。普通顺序语句连接源序后继；`if` / `while` 按其结构化语义建立分支、会合、回边和退出边。函数定义、空行、纯注释行以及结构标记 `else` / `end` 不是语句节点。
3. `return` 只连接当前函数的正常返回终止节点；`break` 只连接最内层 `while` 的退出点；`continue` 只连接最内层 `while` 的条件节点；`goto` 只连接其已合法绑定的目标 `label`。这四类语句均不连接源序后继。
4. `label` 是 CFG 基本块入口，可同时接收源序落入边和合法 `goto` 边；但 `label` 不因自身是跳转目标而天然可达，只有来自已可达节点的入边才能使其可达。来自不可达 `goto` 的边不能使目标变为可达。
5. 从当前控制流域的唯一入口沿上述边遍历，所得节点集合是该域的唯一可达集合。每个函数的入口均作为本函数分析的可达根，不因该函数没有被 `funcall` 而把其函数体判为不可达。
6. 任何不在可达集合中的语句节点（包括 `label`）报 `TC_CE_UNREACHABLE_STATEMENT`，并定位到源位置最早的不可达语句。不可达语句仍须通过词法、语法、名称和类型检查，但不参与确定初始化固定点、函数末尾可达性传播或其他运行时数据流。

**活动作用域与边规范化**：

| 项 | 说明 |
| ---- | ---- |
| 节点附带词法活动链 | 每个 CFG 节点都附带其词法活动代码块链。绑定用"声明身份"而非名称表示，因此被屏蔽的同名变量是不同数据流元素。 |
| 对每条边 `p → n` | 先从 `OUT[p]` 删除所有在 `n` 的活动块链中不存活的绑定，再作为 `n` 的前驱状态。该规则统一处理 `end`、`break`、`continue`、`return` 和向外 `goto` 的生命周期结束。 |

| 项 | 说明 |
| ---- | ---- |
| 进入一个新的块实例时 | 该块内全部 `var` 绑定均以未初始化状态开始，即使实现复用同一物理槽。`while` 条件真边进入新一轮循环体时同样重置循环体局部绑定；`continue` 回到条件节点之前先离开当前循环体实例。 |
| 块内反向 `goto` | 同一块内的反向 `goto` 不离开该块，因此不会仅因跳转而清除仍存活绑定；若再次执行某条 `var`，该语句按普通传递函数重新写入同一词法槽。初始化 RHS 仍不得引用正在定义的绑定，即使该槽在反向边上曾经初始化。 |

因此，静态条件边裁剪后不可能执行的非空分支或循环体，以及无可达 `break` 的恒真循环之后的语句，均按本规则报不可达语句错误。只含 `let` 的 suite 仍含源级语句节点；空 suite 不含语句节点，本身不产生不可达语句诊断。

完成可达性检查后，仅在可达子图上执行确定初始化分析。各集合的定义：

| 集合 | 定义 |
| ---- | ---- |
| `IN[n]` | 可达语句 `n` 执行前确定已初始化的绑定集合 |
| `OUT[n]` | 语句 `n` 执行后的集合 |
| `U[n]` | 节点 `n` 的活动作用域链中全部运行时绑定的全集：包含当前函数形参，以及当前块实例和全部活动祖先块实例中仍处于生命周期内的全部 `var` 绑定，无论相应 `var` 声明语句此时是否已经执行；**不**包含编译期 `let`、其他函数的绑定、尚未进入或已经退出的块实例绑定 |

各集合均以声明身份区分同名屏蔽绑定，并满足 `IN[n] ⊆ U[n]`、`OUT[n] ⊆ U[n]`：

```text
IN[top-level entry] = ∅
IN[function entry]  = 当前函数的全部参数
IN[n]     = ∩ EDGE_OUT[p → n]，其中 p 为 n 的全部可达前驱，
            EDGE_OUT 为按活动作用域规范化后的 OUT[p]
OUT[var x = rhs] = IN[n] ∪ {x}
OUT[var x = funcall(...)] = IN[n] ∪ {x}  ; 调用成功路径
OUT[x = funcall(...)] = IN[n]              ; x 须 ∈ IN[n]，结果覆盖同一槽位，不改变成员关系
OUT[let ...]       = IN[n]               ; 无运行时效果的身份节点
OUT[其他语句]    = IN[n]
```

- `var x = rhs` 的 RHS 在加入 `x` 之前检查，因此初始化自引用仍非法。
- 任何可达的运行时 `var` / 参数读取、赋值目标或 `read` 目标都要求对应运行时绑定属于当前 `IN`。`memblock_copy` 的目标、`ref_store` 的目标引用所指绑定同样要求 ∈ `IN`。`let` 只要求名称可见且已成功求值，不属于 `U` / `IN`；逻辑短路的右操作数是否可达按 [语言标准 §6.5.2.2] 判定。`let` 标识符操作数的读取永不触发 `TC_CE_UNINITIALIZED_VARIABLE`，即使该 `let` 对应的 CFG 身份节点在不可达路径上（[语言标准 §5.2]）。
- 只有所有可达路径均已初始化才成立。
- 上述方程在可达子图上采用最大固定点（greatest fixed point）语义，不得任选任一固定点。一个等价的强制求解策略是：保持两个入口边界值不变；对每个非入口可达节点，以 `U[n]` 初始化 `IN[n]` 与 `OUT[n]`，再按活动作用域边规范化和传递函数单调向下迭代，直至所有集合稳定。工作队列、节点遍历和回边发现顺序不得改变最终结果。
- 绑定属于 `IN[n]`，当且仅当从当前控制流域唯一入口到 `n` 的每一条有限可达路径，在逐边应用作用域规范化和上述传递函数后，都已初始化该绑定。该路径定义用于判定任何求解实现是否一致。
- 对没有可达前驱的非入口节点不定义 `IN`；它们已由可达性阶段排除。每个节点参与固定点迭代的数据流格上界恰为 `U[n]`，绝不把其他函数、未进入或已退出块、或编译期 `let` 混入数据流域。
- CFG 可达性与静态条件边裁剪完全依据本小节前述规则；CFG 不另行维护运算符白名单，也不将优化器的值推测用于改变可达语句集合。
- `funcall` 在调用者 CFG 中是单个原子节点，不展开被调函数 CFG；被调函数发生运行时错误时程序终止，不形成返回调用者的 CFG 边。
- `return` 节点只连接当前函数的正常返回终止节点；函数末尾节点若从入口可达，触发缺少返回错误。顶层文件末尾是合法程序正常结束，不执行缺少返回检查。
- 不允许实现通过更弱或更强的默认规则改变合法程序集合。

声明时强制 RHS 与确定初始化分析是两个独立保证：前者约束源代码形态，后者证明每次可达使用之前相应初始化语句确已执行。

### 9.3 初始化相关错误分层

初始化相关错误按下表严格分工：

| 层次 | 违规形态 | 错误码 | 检查性质 | 规范依据 |
| ---- | -------- | ------ | -------- | -------- |
| **语法层** | `var` 声明缺少 `= <rhs>` | `TC_CE_VAR_MISSING_INIT` | 纯形态；与控制流无关 | [语言标准 §5.1] |
| **名称层** | 标识符从未声明、尚未源序可见或已超出词法作用域 | `TC_CE_UNDEFINED_VARIABLE` | 名称解析 | [语言标准 §9.1] |
| **数据流层** | 声明存在，但在可达使用点不满足确定初始化 | `TC_CE_UNINITIALIZED_VARIABLE` | 完整 CFG 固定点分析 | [语言标准 §9.2] |

`TC_CE_VAR_MISSING_INIT` 不得降级为通用语法错误；`TC_CE_UNINITIALIZED_VARIABLE` 不得替代名称解析错误；确定初始化是跨全部控制流种类的通用性质，不由任何单一语句承担专用码。

## 10. 标准 I/O

本章对应 [语言标准 §10]。I/O 语句语义、格式转换符与格式说明符的确定性拆分以 [语言标准 §10.4]–[语言标准 §10.5] 为准。显式类型参数仅接受 `scalar_type`；`memblock`、结构体、托管引用（`ref<T>`）与线性地址（`addr<T>`）属语法拒绝（`TC_CE_SYNTAX`）。

### 10.1 格式说明符确定性解析

第 6e 子阶段必须按 [语言标准 §10.5] 的确定性拆分规则解析标志、字段宽度与精度。拆分算法如下：

1. 从 `%` 后开始依次读取标志字符（`-`、`+`、`#`、`0`）。每个标志至多出现一次，顺序不限；重复标志 → `TC_CE_FORMAT_SPECIFIER`（定位到第二个及后续重复字符中的最早者）。
2. 连续的 `0` 字符在尚未开始字段宽度时合并为一个 `0` 标志；首个 `1`～`9` 才开始 `width`，其后的所有十进制数字均属于宽度。因此 `%0008d` 等价于 `%08d`（同为标志 `0`、宽度 `8`），不产生重复标志错误。
3. `width` 取值 `1`～`65535`（本版本硬上限，见 [语言标准 §10.5]）；超范围 → `TC_CE_FORMAT_SPECIFIER`（定位到字段宽度数字字段首字符）。
4. `.` 开始精度；随后全部十进制数字属于精度。`.` 后无数字等价于精度 `0`；精度取值 `0`～`65535`（同上硬上限）；超范围 → `TC_CE_FORMAT_SPECIFIER`（定位到 `.`）。
5. 转换符字符结束说明符。
6. 转换符不适用的标志或精度 → `TC_CE_FORMAT_SPECIFIER`（定位到源序最早的不适用控制项：标志字符或 `.`）。各转换符允许的标志见下表：

| 转换符 | 允许的标志 |
| ------ | ---------- |
| `%d`、`%i` | `-`、`+`、`0` |
| `%u` | `-`、`0` |
| `%x`、`%X`、`%o`、`%b` | `-`、`#`、`0` |
| `%f`、`%e`、`%E`、`%g`、`%G` | `-`、`+`、`#`、`0` |
| `%t` | `-`（精度不适用于 `%t`） |

不得凭 EBNF 的其他可选分组选择不同拆分。已匹配 EBNF 但控制项非法 → `TC_CE_FORMAT_SPECIFIER`；不符合该 EBNF 的形式按语法规则报告 `TC_CE_SYNTAX`。

### 10.2 格式类型兼容性校验

第 6e 子阶段在格式说明符解析成功后，按以下顺序检查类型兼容性（[语言标准 §10.1]）：

1. 先检查操作数（标识符或字面量）与显式 `scalar_type` 的一致性：

- **规则 1**：标识符的声明类型与显式类型不一致 → `TC_CE_TYPE_MISMATCH`（定位到操作数标识符）；
- **规则 2**：字面量按显式类型为期望类型检查（[语言标准 §3.6]），不兼容时使用字面量专用错误。
2. 类型一致性通过后，再检查操作数的显式类型与格式转换符的兼容性：

- 不兼容 → `TC_CE_FORMAT_TYPE_MISMATCH`（定位到格式说明符中的转换符字符）。兼容性对应关系见下表：

| 转换符 | 适用类型 |
| ------ | -------- |
| `%d`、`%i` | `int8`～`int64`、`isize`（有符号整数） |
| `%u` | `uint8`～`uint64`、`usize`（无符号整数） |
| `%x`、`%X`、`%o`、`%b` | 任一整数类型 |
| `%t` | `bool` |
| `%f`、`%e`、`%E`、`%g`、`%G` | `float32`、`float64` |

两类检查按序进行：类型不一致时不产生格式兼容性错误。

### 10.3 `read` 输入实现要点

`read` 目标变量检查按以下顺序（第 6 阶段子阶段 6d–6e）：

1. **名称解析**：目标标识符的名称分类与 §6.2 赋值左侧相同（`TC_CE_FUNCTION_SCOPE_ACCESS` / `TC_CE_UNDEFINED_VARIABLE` / `TC_CE_CONSTANT_ASSIGNMENT` / `TC_CE_PARAMETER_ASSIGNMENT`）。仅可写 `var`/`static var` 继续检查。
2. **类型一致性**：目标声明类型与 `read` 的显式 `scalar_type` 不一致 → `TC_CE_TYPE_MISMATCH`（在确定初始化检查之前完成；类型不一致时不产生 `TC_CE_UNINITIALIZED_VARIABLE`）。
3. **确定初始化**：目标 `var` 必须在当前 CFG 点已确定初始化（见 §9.2）。`read` 不是初始化器，不能代替 `var … = …`。
4. **`static var` 作为目标**：可通过 `Self.<成员名>` 或 `<模块名>.<成员名>` 覆盖公开标量 `static var`。公开 `memblock` `static var` 不得作为 `read` 目标。

运行时 `read` 输入 Token 验证必须按 [语言标准 §10.3] 的权威 EBNF 完成：`signed_input_integer`、`unsigned_input_integer`、`bool_input_token`、`input_float_token`，分别对应有符号整数、无符号整数、布尔和浮点目标类型。

整数输入固定为十进制，不接受进制前缀或源代码字面量后缀。`read` 先完整扫描并验证一个输入 Token，再转换并提交目标值；只有全部步骤成功后才覆盖目标变量。

**浮点输入转换规则**（编译器必须保证）：

| 项 | 规则 |
| ---- | ---- |
| 解析与舍入 | 有限浮点输入（包括整数书写形式）先解析为精确十进制数学值，再按 roundTiesToEven 直接舍入到目标 binary32/binary64；不得先解析为 TC 整数类型，也不得通过另一浮点类型中转 |
| 整数书写形式 | 因此不受 `uint64` 字面量词法上限约束 |
| 范围失败 | 有限输入的非零值舍入为零或有限值舍入为无穷时报告 `TC_RE_IO`；可表示的非规格化数合法 |
| `nan` | `nan` 输入生成 canonical quiet NaN |
| 宿主无关性 | 解析过程不受当前 locale、宿主 `strto*` 扩展拼写或宿主浮点中间精度影响 |

**输入 Token 的权威 EBNF**（[语言标准 §10.3]）：编译器后端必须按此 EBNF 验证输入 Token：

```ebnf
signed_input_integer
           = [ "-" ] , input_digits ;

unsigned_input_integer
           = input_digits ;

bool_input_token
           = "true" | "false" ;

input_float_token
           = finite_input_float
           | "inf"
           | "-" , "inf"
           | "nan" ;

finite_input_float
           = [ "-" ] , input_digits , [
               "." , input_digits , [ input_exponent ]
             | input_exponent
             ] ;

input_exponent
           = ( "e" | "E" ) , [ "+" | "-" ] , input_digits ;

input_digits = input_digit , { input_digit } ;
input_digit  = "0" … "9" ;
```

ASCII 空白仅指 U+0009～U+000D 与 U+0020，不受 locale 影响。输入必须完整匹配目标格式；例如 `12abc` 整体非法，不得只接受前缀 `12`。

**读取失败**：标准输入读取失败（宿主 I/O 失败）与非法 Token、超范围、非预期 EOF 同属 I/O 错误，报告 `TC_RE_IO`（[语言标准 §10.3]、[语言标准 §11.1]）；失败时目标槽保持原值，随后程序终止。

### 10.4 格式转换符定义与输出规则

本节固定 [语言标准 §10.4] 的格式转换符定义与确定性输出规则，编译器后端必须据此生成输出字节序列。

| 转换符 | 含义 | 适用类型 | 默认精度 | 特殊值表示 |
| ------ | ---- | -------- | -------- | ---------- |
| `%d` | 有符号十进制 | `int8`～`int64`、`isize` | — | — |
| `%i` | 有符号十进制（同 `%d`） | `int8`～`int64`、`isize` | — | — |
| `%u` | 无符号十进制 | `uint8`～`uint64`、`usize` | — | — |
| `%x` | 十六进制（小写 a-f） | 任一整数类型 | — | — |
| `%X` | 十六进制（大写 A-F） | 任一整数类型 | — | — |
| `%o` | 八进制 | 任一整数类型 | — | — |
| `%b` | 二进制 | 任一整数类型 | — | — |
| `%t` | 布尔值文本 | `bool` | — | `true` / `false` |
| `%f` | 浮点十进制（固定小数） | `float32`、`float64` | 6 位小数 | `inf`、`-inf`、`nan` |
| `%e` | 科学计数法（小写 e） | `float32`、`float64` | 6 位小数 | `inf`、`-inf`、`nan` |
| `%E` | 科学计数法（大写 E） | `float32`、`float64` | 6 位小数 | `INF`、`-INF`、`NAN` |
| `%g` | 紧凑格式（较短，小写） | `float32`、`float64` | 6 位有效数字 | `inf`、`-inf`、`nan` |
| `%G` | 紧凑格式（较短，大写） | `float32`、`float64` | 6 位有效数字 | `INF`、`-INF`、`NAN` |

**确定性格式规则**（编译器后端必须确保）：

- 格式化不受 process locale 影响，小数点固定为 `.`。
- 十进制输出的输入为源 binary32/binary64 值的精确十进制数学值，按 roundTiesToEven 舍入到要求的位数。
- `%e`/`%E`：在小数点前保留恰好一位非零数字，指数始终含 `+` 或 `-`，且至少两位数字。
- `%g`/`%G`：当 `e < -4` 或 `e ≥ p`（`p` 为精度）时使用 `%e`/`%E` 形式，否则定点形式；不输出无意义的尾随零。
- `%x`/`%X`/`%o`/`%b` 对任意整数输出其固定宽度二进制补码位模式，无前导零（`#` 标志除外）。
- `%t` 输出 `true` 或 `false`，接受最小字段宽度与 `-` 标志（[语言标准 §10.1] 示例 `write(bool, %-8t, flag)`）；不接受精度或 `+` / `0` / `#` 标志。
- 精度为 0 且值为 0 时，`%f`/`%e`/`%E` 不输出小数点后的任何数字。

### 10.5 C99 风格格式控制实现要点

本节补充 §10.1 解析规则之外的格式控制语义（[语言标准 §10.5]），编译器后端在构建输出字节序列时必须遵循：

| 控制项 | 语义 | 编译器实现要求 |
| ------ | ---- | ------------ |
| `-` 左对齐 | 结果不足字段宽度时在右侧补 ASCII 空格 | 仅当字段宽度大于实际输出宽度时生效 |
| `+` 强制符号 | 非负数值插入 `+`；特殊值显示 `+inf`、`+nan` | 仅对 `%d`/`%i` 及浮点转换有效 |
| `#` 备用形式 | `%x`/`%X`/`%b` 非零结果添加 `0x`/`0X`/`0b` 前缀；`%o` 保证首位为 `0`；浮点强制输出小数点 | — |
| `0` 零填充 | 在符号或进制前缀之后、数字之前补 `0` | `-` 标志与 `0` 标志同时出现时，`-` 优先 |
| 最小字段宽度 | 取值 `1`～`65535`（本版本硬上限） | 不得截断输出；超出宽度的输出按实际长度完整输出；超范围 → `TC_CE_FORMAT_SPECIFIER` |
| 精度 | 取值 `0`～`65535`（同上硬上限） | 对浮点指定小数位数（`%f`/`%e`/`%E`）或有效位数（`%g`/`%G`）；对整数指定最少数字位数（不足补前导零）；超范围 → `TC_CE_FORMAT_SPECIFIER` |

`write`/`writeln` 每条 I/O 先构建完整输出字节串，再尝试原子逻辑提交。只有全部提交成功时字节串才追加到 TC 抽象标准输出；失败时贡献零字节，此前已成功提交的输出不回滚。

## 11. 诊断与错误处理

遇到**第一个**错误即终止程序（fail-fast）。错误按发生阶段分为**静态**（词法/语法/静态分析，`TC_CE_*`）与**运行时**（`TC_RE_*`）两类。运行时错误类型与提交规则以 [语言标准 §11.1] 为准；本节补充静态诊断细则、与语言条款对齐的错误码表，以及编译警告禁令（含 [语言标准 §1.3] 一致性要求、[语言标准 §4.4] 与 [语言标准 §11.2]）。

### 11.1 静态错误

静态错误覆盖词法/语法、模块结构与导入、名称与作用域、类型/字面量/模式、常量求值、缩进与控制流、函数调用与返回、CFG 确定初始化、调用图，以及引用/memblock 静态约束。具体触发条件、标准错误码、打印名和阶段以 §11.4 为准，多个错误的选择顺序以 §1.3 及各章专用优先级为准。

语言正文对 `funcall` 实参缺失/重复/乱序等已给出专用码（见 [语言标准 附录 B.12]）；本说明书 §8.2 / §11.4.2 必须采用这些码，不得合并为笼统 `TC_CE_SYNTAX` 或 `TC_CE_TYPE_MISMATCH`（除非附录 A 已在语法阶段拒绝）。

### 11.2 运行时错误

| 错误类型         | 错误码 | 触发条件                                                     |
| ---------------- | ------ | ------------------------------------------------------------ |
| 除零错误         | `TC_RE_DIVISION_BY_ZERO` | 整数 `div`/`mod` 除数为 0；严格浮点 `div` 的有限非零被除数除以零，或严格浮点 `mod` 的有限非零被除数对零取模 |
| 整数溢出错误     | `TC_RE_INTEGER_OVERFLOW` | 有符号 `add`/`sub`/`mul`/`neg` 结果超范围；有符号 `div` 的数学商不可表示（即 `INT_MIN / -1`）；有符号 `abs(INT_MIN)`；任一整数类型的 strict `shl` 结果超范围 |
| 负移位计数错误 | `TC_RE_NEGATIVE_SHIFT_COUNT` | `shl`/`shr` 的有符号移位计数按其类型解码后的数学值小于 0 |
| 浮点溢出错误     | `TC_RE_FLOAT_OVERFLOW` | 严格模式浮点运算上溢                                         |
| 浮点下溢错误     | `TC_RE_FLOAT_UNDERFLOW` | 严格模式浮点运算下溢                                         |
| 浮点无效操作错误 | `TC_RE_FLOAT_INVALID` | 严格 `add/sub/mul/div/mod` 的输入含 NaN 或产生无效结果（如 0/0、∞−∞、0×∞、∞ mod x）；`abs/neg` 除外 |
| 转换溢出错误     | `TC_RE_CAST_OVERFLOW` | 严格 `cast` 的数学结果无法在目标类型中表示，或浮点源为 NaN/无穷且目标为整数 |
| 空引用解引用错误 | `TC_RE_NULL_REFERENCE_DEREFERENCE` | `ref_load` / `ref_store` 的操作数为 `none`（[语言标准 §11.1]） |
| 空地址解引用错误 | `TC_RE_NULL_ADDRESS_DEREFERENCE` | `addr_load` / `addr_store` 的操作数为 `nil` |
| 空地址算术错误 | `TC_RE_NULL_ADDRESS_ARITHMETIC` | `addr_add` / `addr_sub` 的地址操作数为 `nil` |
| I/O 错误         | `TC_RE_IO` | `read` 输入非法/超范围/EOF，标准输入读取失败，或 `write`/`writeln` 写入失败 |
| memblock 越界    | `TC_RE_MEMBLOCK_INDEX_OUT_OF_RANGE` | `memblock_load` / `memblock_store` 的运行时下标不满足 `0 ≤ i < N`；或 `memblock_copy` 的运行时区间不满足 [语言标准 §6.7.2.3]（上界为声明规划个数 `N`，[语言标准 §3.8]） |
| 地址访问不可完成 | `TC_RE_ADDR_UNAVAILABLE` | `addr_load` / `addr_store` / `addr_io_load` / `addr_io_store` 的目标地址在本次执行中不可用（宿主映射类实现；[语言标准 §1.3] 第 3 项） |

对 `shl` / `shr` 运行时指令，必须先按类型 `T` 解码移位计数的数学值并检查是否为负；只有该检查通过后，才检查 `k >= n` 或 `shl` 结果溢出。因此同一条指令不得以 `TC_RE_INTEGER_OVERFLOW` 代替 `TC_RE_NEGATIVE_SHIFT_COUNT`。

指令须先完成操作数读取与空值分类，再提交结果：

- `ref_load`/`ref_store` 的 `none` 只报 `TC_RE_NULL_REFERENCE_DEREFERENCE`；
- `addr_load`/`addr_store` 的 `nil` 只报 `TC_RE_NULL_ADDRESS_DEREFERENCE`；
- `addr_add`/`addr_sub` 的 `nil` 只报 `TC_RE_NULL_ADDRESS_ARITHMETIC`。

四个空值/不可用码之间不得混用。

**运行时错误提交规则**：每条 TC 指令在抽象机器中先读取全部实际需要读取的操作数并完成检查，再提交目标值。

- 算术、移位、转换、引用运算或函数调用发生运行时错误时，不提交当前指令的目标槽、调用返回值或新 `var` 的已初始化状态；
- `memblock_store` / `memblock_copy` 在下标或区间检查失败时不修改目标的任何元素；
- `read` / 输出失败的外部 I/O 边界按 [语言标准 §10] 单独规定。

首个运行时错误立即终止整个程序，不执行清理代码、后续语句或调用者续点，也不回滚此前已成功完成的赋值与 I/O。

### 11.3 编译警告

TC 无编译警告，也不以警告方式放行初始化、溢出、类型或控制流违规（[语言标准 §11.2]）。尤其不得以警告代替对公开 `static var` 跨模块写入或私有成员外部访问的既有拒绝（[语言标准 §4.4]、[语言标准 §1.3]）。`and`/`or` 短路裁剪只免除不可达右操作数的确定初始化读取检查，不免除其词法、语法、名称和类型检查；`xor` 不短路。

### 11.4 标准错误码对照表

下列各表是 0.0.45 完整、权威的标准错误码对照。语言错误码使用 `TC_CE_*`（编译期/静态）与 `TC_RE_*`（运行时）前缀，另含实现资源失败码 `TC_ERR_OUT_OF_MEMORY`。

语言错误码与诊断类别一一对应，码不得合并、别名化或以其他错误码代替；布尔 `xor` 与浮点 `mod` 复用既有错误码。打印名在**同一条件的编译期码与运行时码**之间可共用（如 `TC_CE_MEMBLOCK_INDEX_OUT_OF_RANGE` 与对应的 `TC_RE_MEMBLOCK_INDEX_OUT_OF_RANGE`），由诊断类别与阶段区分；其余情形打印名必须唯一。

本表镜像语言标准附录 B（**86 码 = 73 `TC_CE_*` + 13 `TC_RE_*`**），另记实现资源失败码 `TC_ERR_OUT_OF_MEMORY`（实现枚举共 87）。

各表的「阶段」列使用实现步骤口径；与 [语言标准 §11] 四步规则的诊断类阶段对应如下：

| 阶段区间 | 诊断类阶段 |
| ---- | ---- |
| 第 1–2 阶段 | **LT** |
| 第 3 阶段 | **SYN**（含结构类语法阶段诊断） |
| 第 4–8、11、12 阶段 | **SEM** |
| 第 9–10 阶段（常量求值与三态判定） | **CT**（其中形态与来源类子条件属 SEM） |
| 第 13 阶段 | 不产生语言诊断 |

- **报告顺序**：须遵守 [语言标准 §11] 的「阶段优先（LT → SYN → SEM → CT）」——CT 类诊断必须在全部 SEM 类诊断无触发后才报告（§1.3）。
- **「静态」的含义**：各表「阶段」列中未另行标注具体阶段的**「静态」一律等同于 SEM**（静态语义拒绝）。

**实现专用错误码说明**

`TC_ERR_OUT_OF_MEMORY` 不由 TC 抽象程序直接触发，仅表示实现为完成当前阶段所需的内部分配实际失败。它不是静态语义或运行时语义的一部分，不能用作固定长度、嵌套深度、标识符长度或程序规模限制的替代诊断；实现若事先施加资源上限，必须公开该上限并与真实资源失败区分。

打印名与诊断消息固定为实现约定（`OutOfMemory` / `memory allocation failed`），前缀保留 `TC_ERR_` 以区别于语言规范码。

### 11.4.6 引用与地址诊断错误码

下表固定 [语言标准 §3.10]～[语言标准 §3.11] / [语言标准 §6.8]～[语言标准 §6.9] 所需的**专用**诊断码；空值类运行时码亦列于 §11.4.1，本表交叉列出以便检索，不另计。跨类型比较复用 `TC_CE_TYPE_MISMATCH`，不另设专用码。

| 错误码 | 打印名 | 诊断类别 | 阶段 | 触发条件 |
| --- | --- | --- | --- | --- |
| `TC_RE_ADDR_UNAVAILABLE` | `AddrUnavailable` | 地址不可用 | 运行时 | `addr_load` / `addr_store` / `addr_io_load` / `addr_io_store` 的目标地址在本次执行中不可用（宿主映射类实现未提供该地址空间、地址不在可用区间、未对齐且未按字节访问、或目标硬件拒绝；[语言标准 §1.3] 第 3 项） |
| `TC_RE_NULL_REFERENCE_DEREFERENCE` | `NullReferenceDereference` | 空引用解引用错误 | 运行时 | `ref_load` / `ref_store` 的操作数为 `none` |
| `TC_RE_NULL_ADDRESS_DEREFERENCE` | `NullAddressDereference` | 空地址解引用错误 | 运行时 | `addr_load` / `addr_store` 的操作数为 `nil` |
| `TC_RE_NULL_ADDRESS_ARITHMETIC` | `NullAddressArithmetic` | 空地址算术错误 | 运行时 | `addr_add`、`addr_sub` 的地址操作数为 `nil` |

注：

- 空值运行时错误按**字面量与操作**分类：`ref_load` / `ref_store` 的 `none` → `TC_RE_NULL_REFERENCE_DEREFERENCE`；`addr_load` / `addr_store` 的 `nil` → `TC_RE_NULL_ADDRESS_DEREFERENCE`；`addr_add` / `addr_sub` 的 `nil` → `TC_RE_NULL_ADDRESS_ARITHMETIC`；不得互相顶替。`ref_eq` / `ref_ne` 允许 `none`、`addr_eq` / `addr_ne` 允许 `nil` 作操作数，不触发运行时错误。
- **易失档案不检查空地址**：`addr_io_load` / `addr_io_store` **不检查空地址**（地址 `0` 合法）；它们只可能报 `TC_RE_ADDR_UNAVAILABLE`。
- 托管引用**没有**算术指令：因此不存在「空引用算术」码；地址空间的两个空值码互不代用。
- **码总数与镜像**：语言码总数 **86 = 73 `TC_CE_*` + 13 `TC_RE_*`**；本表含 `TC_RE_ADDR_UNAVAILABLE`，空值三码与 §11.4.1 交叉列出、不另计。
