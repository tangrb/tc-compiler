## 1. 概述与编译管线

### 1.1 文档定位

本说明书是 0.0.35 编译器行为的规范性条款：凡影响可观察诊断、错误码、静态接受集或与语言标准交叉引用的算法步骤，均必须按本文实现。VM 与 AOT 共享同一前端分析语义；代码生成见各自实现文档，但不得改变本文规定的静态结果。

### 1.2 确定性处理顺序

0.0.35 采用确定的静态处理顺序：

1. 源字节的 UTF-8 解码（文件打开失败属于实现/API 层）；
2. 词法与缩进扫描；词法分析采用最长匹配策略（详见 §2.1），缩进处理基于缩进级别栈生成 INDENT/DEDENT Token（详见 §2.2）。在形成字面量 Token 时执行 [语言标准 §2.3.5] 的整数绝对值上限，以及 [语言标准 §2.4.1] 中由浮点后缀唯一确定源类型后的舍入为零/无穷检查，这两类只依赖 Token 自身的失败均报告 `TC_ERR_LITERAL_OUT_OF_RANGE`；
3. 语法解析；附录 A 已分区的 `#program` 顶层若在可执行语句之后再出现声明，按受限恢复报告 `TC_ERR_MODULE_LAYER`（附录 A.3），不进入后续阶段；
4. **模块结构、导入解析与函数签名收集**。本阶段内部按以下子阶段顺序执行，前一子阶段有错时不进入后一子阶段；跨文件诊断的主位置与关联位置规则见 §4.1：

   4a. **单文件模块结构**：检查五层排序（`TC_ERR_MODULE_LAYER`）、`#lib` 成员是否带显式 `public` / `private`（`TC_ERR_MISSING_VISIBILITY`，覆盖 `struct` / `func` / `static let` / `static var`；缺可见性前缀亦可在第 3 阶段受限恢复中报告，见附录 A.3）、以及 `#program` 是否误用 `func` / `Self` / `static` / `public` / `private`（`TC_ERR_PROGRAM_MODE_MISUSE`，含带可见性前缀的 `struct`）。

   4b. **导入解析**：对每个 `import` 唯一定位目标模块；找不到 → `TC_ERR_IMPORT_NOT_FOUND`；目标非 `#lib` → `TC_ERR_IMPORT_NOT_LIB`；逻辑名歧义 → `TC_ERR_IMPORT_AMBIGUOUS`；同名重复导入 → `TC_ERR_DUPLICATE_IMPORT`；导入名与本模块成员/顶层值绑定冲突 → `TC_ERR_IMPORT_NAME_CONFLICT`。

   4c. **依赖图环检查**：在完整可达依赖图上检查自环与任意长度间接环 → `TC_ERR_CIRCULAR_IMPORT`（§4.1）。

   4d. **收集函数签名**：在 4a–4c 成功后，收集全部可达 `#lib` 模块的函数签名，供后续阶段使用。

5. 检查函数重名、签名和名称空间；本阶段完成全局函数名与顶层值作用域直接 `var` / `let`、以及全部形参的冲突检查；
6. 名称、作用域与类型语义阶段。本阶段内部按以下子阶段顺序执行，每个子阶段内按同一源文件的行列序选择首个诊断；前一子阶段有错时不进入后一子阶段：

   6a. **控制流上下文检查**：检查 `goto` / `label` 是否具有 `func` 词法祖先；再检查是否具有 `while` 词法祖先（函数内 `while` 中的 `goto`/`label` 分别报 `TC_ERR_GOTO_INSIDE_LOOP` / `TC_ERR_LABEL_INSIDE_LOOP`）。

   6b. **名称作用域预建**：分别解析函数体和顶层的名称与词法作用域；为当前 `#lib` 建立 [语言标准 §8.4.1] 的本库顶层成员名索引；对顶层嵌套块及函数体任意层级的 `var` / `let` 执行全局函数名冲突检查（报告 `TC_ERR_FUNCTION_NAME_CONFLICT`）；仅为各函数建立标签表。

   6c. **goto/label 名称解析**：完成 `goto` 的标签查找（沿祖先链找到最近同名标签）、跨控制流域判定与块关系检查（[语言标准 §7.3.3]）。本子阶段使用 6b 建立的标签表；固定元数内建调用外壳的操作数数量已在第 3 阶段完成，本阶段不得再次分类或改写。

   6d. **类型、模式与字面量语义检查**：检查普通 RHS 与 `const_rhs` 的类型、模式及上下文字面量约束。其中 `let` 按 [语言标准 §5.2.1] 先检查名称绑定类别（`var` 或参数引用立即报 `TC_ERR_CONSTANT_EXPRESSION`），再检查 RHS 结果类型与声明类型是否闭合。标识符操作数的声明类型与显式类型不一致时报告对应错误；字面量的类别、后缀或范围不符合上下文时使用字面量专用错误。解析 `<模块名>.<成员名>` 时若成员存在但为 `private`，报告 `TC_ERR_PRIVATE_MEMBER_ACCESS`，不得改报未定义。函数内裸名命中本库顶层成员名索引时报告 `TC_ERR_FUNCTION_SCOPE_ACCESS`。

   6e. **I/O 格式检查**：检查 `write` / `writeln` / `read` 的显式类型、格式说明符静态控制项及转换符兼容性。格式说明符按确定性拆分算法（§10.1）解析标志、字段宽度和精度。已匹配 EBNF 但格式控制非法时报告 `TC_ERR_FORMAT_SPECIFIER`；操作数类型与转换符不兼容时报告 `TC_ERR_FORMAT_TYPE_MISMATCH`。

   `funcall` 实参和 `return` 操作数的上下文字面量检查分别保留到第 7、8 阶段。

7. 检查符合 EBNF 的 `funcall` 之目标、使用位置、实参、实参上下文字面量约束和接收类型；调用目标若以裸名命中本库 `func`，报告 `TC_ERR_FUNCTION_SCOPE_ACCESS`；经导入限定解析到 `private` 函数时报告 `TC_ERR_PRIVATE_MEMBER_ACCESS`；
8. 检查符合 EBNF 的 `return [operand]` 之位置、形式、操作数名称、返回类型和返回上下文字面量约束；返回操作数的名称类诊断在本阶段产生，不回到第 6 阶段；
9. 求值 `let` 常量（名称类别、类型闭合和依赖合法性已在第 6 阶段完成检查，本阶段仅执行算术、位运算和转换的编译期计算）；亦按源序求值各可达库的 `static let`，并检查 `static var` 初始化器的编译期约束（[语言标准 §4.2]）；
10. 按 [语言标准 §5.2] 执行 `if`/`while` 静态布尔三态判定，并按 [语言标准 §6.5.2.2] 判定逻辑 RHS 读边；
11. 构建唯一顶层 CFG，再分别构建各函数 CFG；按 [语言标准 §9.2] 从每个域的唯一入口计算可达节点，报告不可达语句，然后仅在可达子图上执行确定初始化固定点；仅函数 CFG 执行函数末尾检查；
12. 检查函数调用图中的递归环；
13. 生成 VM / AOT 代码。

第 6 阶段（名称、作用域与类型语义）建立后续检查所需的作用域和名称环境。其内部子阶段 6a–6e 按序执行，前一子阶段有错时不进入后一子阶段。`funcall` 内部名称与 `return` 操作数必须按第 7、8 阶段的专用优先级协调解析：未定义调用目标会抑制该调用的实参名称错误；`TC_ERR_FUNCTION_SCOPE_ACCESS` / `TC_ERR_PRIVATE_MEMBER_ACCESS` 与未定义目标同级，均抑制实参错误；调用位置错误会抑制实参错误；返回形式错误会先于返回操作数名称错误。下列专用规则覆盖通用阶段内的源位置顺序。

权威 EBNF 不接受的形式必须按 [语言标准 §1.3] 作**语法拒绝**（第 3 阶段），不得为产生后续专用语义诊断而放宽语法。亦须遵守 [语言标准 §1.3] 第 10 条：不得以降低人手编码成本为由放宽附录 A 接受集、静默接受对 `private` 成员的外部访问，或以警告代替对公开 `static var` 跨模块写入的既有语义。阶段按顺序完整执行，前一阶段有错时不进入后一阶段。

### 1.3 首个诊断的通用规则

一个程序同时存在多个错误时，唯一首个诊断按以下顺序确定：

1. **阶段优先**：先报告编号较小阶段的错误。
2. **源位置优先**：一个 TC 编译单元恰好对应一个源文件；同一阶段按行、列选择起始位置最早者。批量编译多个文件属于驱动层行为，各文件分别产生语言诊断，文件间次序不属于 TC 语言语义。
3. **规则优先**：同一位置按本节专用优先级；未专门规定时依次为语法形态/数量、语句上下文、名称存在性、重复、名称空间/作用域/控制流域、使用位置、实参顺序、类型、模式/结构、字面量、CFG、调用图。
4. **关联位置**：重复定义、跨域跳转和递归环使用下文指定的主位置比较；其他位置只作附注。
5. **遍历无关**：函数表、哈希表、CFG、调用图和实参集合的内部遍历顺序不得改变结果。

`TC_ERR_LITERAL_OUT_OF_RANGE` 的阶段由失败所需的信息唯一决定：只依赖字面量 Token 自身的整数绝对值上限或浮点源类型舍入检查属于第 2 阶段；只有结合普通 RHS / `let` / I/O 的期望类型才能确定的范围错误属于第 6 阶段；结合 `funcall` 形参或函数返回类型才能确定的范围错误分别属于第 7、8 阶段。第 2 阶段已经失败的字面量不得延迟到上下文阶段，因此阶段优先规则对所有实现唯一。

源位置使用 1 基行号与 1 基列号。对有效 UTF-8，列号按解码后的 Unicode 标量值计数，每个 ASCII 空格计一个标量；换行序列不属于下一行的列。对非法 UTF-8，行列按首个非法字节之前的最长有效前缀计算，首个非法字节占据下一列，并以 0 基源字节偏移作为附加位置；主错误码仍为 `TC_ERR_SYNTAX`。语言诊断文本可以本地化，但错误码、主位置和本节规定的关联位置必须稳定；表中明确固定文本的实现资源错误除外。

虚拟 Token 位置：`NEWLINE` 位于逻辑行最后一个源标量值之后一列（空行在第 1 列）。空文件 `EOF` 位于第 1 行第 1 列；非空文件在下一逻辑行第 1 列或最后标量值之后。

除 §4.1、§7.5～§7.6、§8.1～§8.3、§8.8 或其他规范性条款已经给出更专用的定位规则外，普通静态语义诊断的**主位置**按下列规则固定：

- 运算本身不支持显式类型参数所指类别时，定位到该类型参数 Token；若显式类型参数类别合法，而某个标识符或操作数与其期望类型不一致，则定位到源位置最早的不匹配操作数。`TC_ERR_COMPARISON_TYPE_MISMATCH` 使用同一操作数定位规则。
- RHS 自身合法、但其结果类型与接收变量、常量或赋值目标的声明类型不一致，且没有更专用的调用/返回诊断时，定位到 RHS 的第一个 Token。
- `TC_ERR_MODE_MISMATCH` 定位到候选模式关键字；`TC_ERR_BITCAST_WIDTH` 定位到源操作数的第一个 Token。
- `TC_ERR_LITERAL_TYPE` 与 `TC_ERR_LITERAL_OUT_OF_RANGE` 定位到完整字面量的第一个 Token；前导 `-` 属于该字面量时，定位到 `-`。
- `TC_ERR_CONDITION_TYPE` 定位到 `if` / `while` 条件 RHS 的第一个 Token。
- `TC_ERR_FORMAT_TYPE_MISMATCH` 定位到格式说明符中的转换符字符。格式说明符是单个 Token，但主列号仍精确指向该 Token 内对应的 Unicode 标量位置。
- `write` / `writeln` 的标识符操作数与显式 `scalar_type` 不一致，或 `read` 目标 `var` 的声明类型与显式 `scalar_type` 不一致时，使用 `TC_ERR_TYPE_MISMATCH` 并定位到操作数或目标标识符。格式化输出只在该检查成功后才检查转换符兼容性（[语言标准 §10.1]）。以 `memblock<…>` 作为 I/O 显式类型参数属语法拒绝（`TC_ERR_SYNTAX`），不适用本条。

词法、缩进、语法及格式控制专用诊断的主位置按下表固定：

| 错误码 | 主位置 |
| -------- | ---------- |
| `TC_ERR_SYNTAX` | 非法源字符或非法 Token 定位到其首字节/首标量或首 Token；对无专用错误码的语法失配，定位到使当前 Token 前缀无法继续匹配任一可行产生式的首个 Token；缺少必需 Token 时定位到应插入位置的当前 `NEWLINE` / `EOF` 或后继 Token。`TC_ERR_MISSING_END` 优先使用下表的专用规则。 |
| `TC_ERR_KEYWORD` | 误占标识符位置的保留关键字 Token。 |
| `TC_ERR_VAR_MISSING_INIT` | 该 `var` 声明的标识符。 |
| `TC_ERR_OPERAND_COUNT` | 平衡固定元数调用外壳的内建关键字。 |
| `TC_ERR_INDENT_MIXED` | 行首缩进中首个 U+0020 空格。 |
| `TC_ERR_INDENT_INSUFFICIENT` | 缩进层级或缩进栈转移首次非法的逻辑行第一个 Token。 |
| `TC_ERR_INDENT_ELSE_END` | 未与对应块头对齐的 `else` 或 `end` 关键字。 |
| `TC_ERR_MISSING_END` | 先按 EBNF 的嵌套结构以现有 `end` 从内向外完成唯一配对，再把每个仍未配对块的 `func` / `if` / `while` 开启关键字作为候选主位置；有多个候选时按源位置最早者。 |
| `TC_ERR_ELSE_POSITION` | 无对应 `if` 的 `else` 关键字。 |
| `TC_ERR_FORMAT_SPECIFIER` | 重复标志定位到第二个及后续重复字符中的最早者；宽度/精度超范围定位到对应数字字段首字符；标志或精度不适用于转换符时，定位到源序最早的不适用控制项（标志字符或 `.`）。 |

兜底规则：标识符/操作数错误 → 首 Token；重复定义 → 第二个及后续最早名称（关联首个）；构造级错误 → 构造首 Token；常量求值错误 → 触发运算关键字；运行时错误 → 当前指令首 Token；I/O 失败 → 对应 I/O 关键字。

函数参数名受保护：任意层级 `var`/`let` 与形参同名 → `TC_ERR_DUPLICATE_DEFINITION`（第 6 阶段，主位置为内层标识符，关联形参位置）。全局函数名受保护：与任何值绑定同名 → `TC_ERR_FUNCTION_NAME_CONFLICT`（顶层直接绑定在第 5 阶段，嵌套/函数体内在第 6 阶段；主位置为值绑定名，关联函数定义名）。

附录 A 首先决定 Token 序列能否进入静态语义（[语言标准 §1.3]）。不符合产生式属**语法拒绝**（第 3 阶段）：缺初始化器 → `TC_ERR_VAR_MISSING_INIT`，操作数数量错 → `TC_ERR_OPERAND_COUNT`，关键字占标识符位 → `TC_ERR_KEYWORD`，缩进/块形态 → 对应专用码，声明/语句分区破坏 → `TC_ERR_MODULE_LAYER`；其余用 `TC_ERR_SYNTAX`。格式说明符：无法匹配 EBNF → 第 3 阶段 `TC_ERR_SYNTAX`；已匹配但控制项非法 → 第 6 阶段 `TC_ERR_FORMAT_SPECIFIER`。

`TC_ERR_OPERAND_COUNT` 的适用范围是完整且权威的：仅当逻辑行中已识别出"内建关键字 `(` 顶层逗号分隔项 `)`"的平衡调用外壳，但其值操作数数量不符合下表时使用该错误码。类型参数、位于类型参数之后候选模式位置的 `wrap` / `ieee` / `truncate` 关键字，以及 `write` / `writeln` 的格式说明符均不计入值操作数。语法形态/数量的诊断优先级高于类型和模式组合：因此只要外壳平衡且顶层字段可分隔，先按上述方式计数值操作数；数量正确后，才由 EBNF 和 [语言标准 §6.3.1] 判定类型参数或候选模式在当前操作中是否合法。

本识别是第 3 阶段在正常 EBNF 匹配失败后的受限语法诊断恢复：固定元数产生式本身已经规定合法数量；本规则只把其中"平衡外壳且仅值操作数数量不符"的非法 Token 序列映射为专用错误码。该序列仍未通过附录 A，不得进入第 6 阶段的名称、类型或模式分析，也不得在第 6 阶段重新分类为其他错误。

| 固定元数外壳 | 期望的值操作数 | 说明 |
| ---------------- | ------------------ | ---- |
| `add` / `sub` / `mul` / `div` / `mod` | 2 | 普通 RHS 与 `let` 常量 RHS 均适用 |
| `and` / `or` / `xor` | 2 | 整数按位与 `bool` 逻辑重载均适用 |
| `shl` / `shr` | 2 | 模式位置的合法性仍由 EBNF 与 [语言标准 §6.3.1] 判定 |
| `eq` / `ne` / `lt` / `le` / `gt` / `ge` | 2 | 整数与浮点比较均适用 |
| `abs` / `neg` / `not` | 1 | `not` 的整数按位与 `bool` 逻辑重载均适用 |
| 严格 `cast` / `cast(..., truncate, ...)` / `bitcast` | 1 | 目标类型与 `truncate` 不计为值操作数 |
| `write` / `writeln` | 1 | 有格式和无格式形式均恰好输出一个值 |
| `read` | 1 | 唯一的目标标识符按一个操作数计 |

缺少右括号、顶层逗号结构破损或无法识别内建调用外壳时，使用 `TC_ERR_SYNTAX` 而非 `TC_ERR_OPERAND_COUNT`。嵌套调用也不属于操作数数量错误：`let` RHS 中的嵌套调用按本节后文报 `TC_ERR_CONSTANT_EXPRESSION`，其他不允许嵌套的位置报 `TC_ERR_SYNTAX`。`funcall` 的项是命名实参，不纳入本错误码；其缺失、重复、未知与顺序错误分别使用 §8.2 的专用诊断。`return`、`if` / `while`、变量/常量定义与其他语句形态也不属于内建固定元数调用外壳，沿用各自的语法或专用诊断。

只有完整 Token 序列符合附录 A 某一产生式时，才进入普通类型/模式诊断。语法已接受的同一位置同时违反多项静态语义时，固定按"运算支持的类型类别 → 模式合法性 → `bitcast` 位宽 → 字面量范围/类型 → 格式符与其他操作数类型"选择。`wrap` / `ieee` / `truncate` 仅在对应产生式明确提供的位置才是候选模式；若相关操作或上下文的产生式没有该参数位置，或类型参数已被专用非终结符排除，且没有上述语法专用诊断，统一在第 3 阶段报告 `TC_ERR_SYNTAX`。例如普通 RHS 的 `shr(int32, wrap, x, k)` 是语法错误，而 `const_shift_expr` 已接受的同形 `let` RHS 随后报告 `TC_ERR_MODE_MISMATCH`。

`let` 类型闭合检查在第 6 阶段完成：字面量按 [语言标准 §3.6] 报专用错误；标识符/单层调用的结果类型不同时报 `TC_ERR_TYPE_MISMATCH`（定位 RHS 首 Token）。调用的内部类型检查先于与外层类型的比较。

非法 UTF-8、文件起始 BOM、U+0000，以及注释外违反 [语言标准 §2.1] 的非法源字符均映射为 `TC_ERR_SYNTAX`；缩进和语法阶段有专用错误码时优先专用码。此处的专用语法码只改变错误分类，不改变附录 A 接受的程序集合。`let` RHS 嵌套调用在语法阶段映射为 `TC_ERR_CONSTANT_EXPRESSION`；自引用和前向引用在名称阶段映射为 `TC_ERR_UNDEFINED_VARIABLE`；`let` 中引用 `var` 或函数参数在第 6 阶段子阶段 6d 立即映射为 `TC_ERR_CONSTANT_EXPRESSION`，不再延迟到常量求值阶段。静态布尔判定仅在名称、类型及更早 `let` 求值成功后运行；合法常量形态的求值错误不得降级为 `unknown`。不可达代码仍完成词法、语法、名称和类型检查。

## 2. 词法结构

本章对应 [语言标准 §2]。下列条款规定词法扫描与缩进 Token 的确定性算法；字符集、字面量形态与关键字仍以语言标准为准。

### 2.1 词法分析器

词法分析器采用**最长匹配**策略，落实 [语言标准 §2.3.7]：

1. 扫描 `0` 时，检查后续字符是否为 `x`/`X`/`b`/`B`/`o`/`O`，转入对应进制（十六进制、二进制或八进制）。
2. 数字部分扫描完成后，检查后续字符是否为 `u`/`U`，归约为带后缀字面量。
3. 否则归约为无后缀字面量。

对于前导零判定，十进制字面量以 `0` 开头且后接数字字符（包括通过下划线 `_` 分隔符连接的数字）时，视为非法前导零（[语言标准 §2.3.4]）。忽略分隔符后仍按数字序列判定。

### 2.2 缩进处理

缩进由词法器维护的缩进级别栈处理：

1. 词法器维护由行首连续空格组数量构成的缩进级别栈，初始仅含顶层级别 `0`。
2. 每个非空、非纯注释逻辑行开始时，先检查第一个 Token 之前的字符：它们只能是 U+0020；行首出现 U+0009 均报 `TC_ERR_INDENT_MIXED`。统计行首连续空格数量，必须能被 4 整除，否则为缩进错误。然后将空格组数量（空格数 / 4）与栈顶比较：增加时必须恰好增加 `1`，压栈并生成一个 `INDENT`；一次增加多组为缩进错误。减少时逐项出栈并为每次出栈生成一个 `DEDENT`。减少后的空格组数量必须等于某个既有栈值，否则为缩进错误。
3. 一级缩进恒为 4 个连续 ASCII 空格 U+0020。
4. 空行和纯注释行只生成 `NEWLINE`，不改变缩进栈；它们的行首 ASCII 空格/制表符不参与缩进字符或层级检查。
5. LF（`\n`）、CRLF（`\r\n`）或 CR（`\r`）均表示一个逻辑行结束，并生成一个 `NEWLINE`；文件结尾先补最后一个 `NEWLINE`（若缺少），再生成剩余 `DEDENT`，最后生成 `EOF`。
6. `INDENT`/`DEDENT` 只反映 `func`/`if`/`else`/`while`/`struct` 语句体的实际缩进；合法的函数内 `label` 是普通语句，不改变缩进栈。

## 3. 类型系统

本章对应 [语言标准 §3]。类型分类、转换与布局语义以语言标准为准；本节仅固定 memblock 相关的编译器实现禁令。

### 3.1 memblock 编译器约束

编译器不得在符号表、类型表、CFG 或任何绑定属性上记录、传播、比较 memblock 的存储容量。具体而言：

- **不维护长度**：构造时的 `count:` 参数仅是分配参数，不写入绑定的编译期元数据。
- **不比较容量**：memblock 赋值与函数传参仅检查元素类型 `T` 是否一致，不检查两侧当前存储容量。
- **不做静态上界折叠**：编译器不得因构造时 `count: 4` 而证明 `i < 4` 恒成立。仅整数字面量和已求值 `let` 可参与编译期下标判定；`var` 不参与。
- **不记录进符号表**：memblock 绑定在符号表中的类型信息仅包含元素类型 `T`，不包含元素个数。

实现可为运行时越界检查持有存储区容量（实现细节），但该容量不是语言层面的 memblock 长度，也不得要求编译器维护。

## 4. 程序结构与模块系统

本章对应 [语言标准 §4]。模块模式、可见性与 `import` 语义以语言标准为准——含 [语言标准 §4.1] 的 `#program` 双文件约束（不得在 `#program` 内定义函数）与 [语言标准 §4.4] 的公开 `static var` 跨模块可变语义。本节规定第 4 阶段诊断的选择与定位；亦不得违反 [语言标准 §1.3] 第 10 条。

### 4.1 模块结构与导入错误优先级

第 4 阶段的模块类错误按子阶段 4a → 4b → 4c 选择；同一子阶段内按主位置源序，主位置相同时按下表规则优先顺序。跨文件比较时，先按**导入方**源文件中触发该诊断的 `import` 或限定名主位置选择；环诊断的主位置规则见下。

**4a 单文件结构**（同一文件内）：`TC_ERR_MODULE_LAYER` → `TC_ERR_MISSING_VISIBILITY` → `TC_ERR_PROGRAM_MODE_MISUSE`。

- `TC_ERR_MODULE_LAYER` 定位到破坏层序的最早构造首 Token（例如插在导入区中的 `var`、`#program` 顶层可执行语句区之后的 `let` / `var` / `var_funcall_def`、`static` 区之前的 `func`）。其中「`#program` 声明出现在可执行语句之后」由附录 A 分区产生式拒绝，并在第 3 阶段按受限恢复映射为本错误码（见附录 A.3），主位置仍为该声明首 Token。
- `TC_ERR_MISSING_VISIBILITY` 定位到缺少修饰符的 `struct` / `static` / `func` 关键字（`#lib` 顶层成员未写 `public` / `private`；附录 A 产生式要求前缀，第 3 阶段受限恢复映射为本错误码，见附录 A.3）。
- `TC_ERR_PROGRAM_MODE_MISUSE` 定位到误用的 `func` / `Self` / `static` / `public` / `private` 关键字（含 `#program` 中带可见性前缀的 `struct`；[语言标准 §4.1]）。不得把「单文件顶层语句 + 辅助函数」接受为合法程序。

**4b 导入解析**：同一导入方文件内按 `import` 行源序；同一 `import` 上依次为：`TC_ERR_IMPORT_NOT_FOUND` → `TC_ERR_IMPORT_NOT_LIB` → `TC_ERR_IMPORT_AMBIGUOUS` → `TC_ERR_DUPLICATE_IMPORT` → `TC_ERR_IMPORT_NAME_CONFLICT`。

- 找不到/非库/歧义均定位到该 `import` 的模块名标识符；歧义时把实现枚举到的最早候选路径作为关联附注（附注不参与主位置比较）。
- 重复导入定位到第二次及后续 `import` 的模块名，关联位置为首次同名 `import`。
- 导入名冲突定位到 `import` 的模块名，关联位置为冲突的本模块成员或顶层值绑定名。

**4c 循环导入**：存在多个环时，选择包含源位置最早之 `import` 边的环；将该边固定为首边。环路径的确定算法与 §8.8 递归环相同（以模块为顶点、`import` 为边），主位置为该首边 `import` 的模块名标识符。不得由模块表或邻接表遍历顺序改变结果。

`TC_ERR_PRIVATE_MEMBER_ACCESS` 属于第 6/7 阶段的名称/调用解析，定位到限定名中的成员名标识符，关联位置为该私有成员的声明名；不得改报 `TC_ERR_UNDEFINED_VARIABLE` 或 `TC_ERR_UNDEFINED_FUNCTION`（[语言标准 §4.4]）。公开 `static var` 的跨模块读写（含作为 `read` 目标）按 [语言标准 §4.4] / [语言标准 §10.3] 保留完整语义，不得降级为警告。

## 7. 控制流分析

本章对应 [语言标准 §7]。控制流语句的源语言规则以语言标准为准；本节规定 CFG 构建、控制流域边界，以及 `goto`/`label` 与 CFG 类诊断优先级。

### 7.1 代码块与 CFG 基本块

TC 将源语言的**代码块**与控制流图中的 CFG 基本块严格区分：

- **代码块**是由 `then` / `else` / `end` 词法结构界定的直接语句序列，用于名称作用域、局部变量生命周期、标签可见性、`goto` 的块关系和缩进检查。函数的 `then … end` 构成函数体代码块；`if` 的 `then` 分支和 `else` 分支分别构成两个互不包含、不可比的兄弟代码块，无 `else` 时只有 `then` 代码块；`while` 的 `then … end` 构成循环体代码块。嵌套 `if` / `while` 开启新的代码块。
- CFG 基本块是没有内部控制流分叉的最大连续 CFG 节点序列。函数入口、条件分支目标、循环入口/退出点与 `label` 均形成 CFG 基本块入口；`return`、`goto`、`break`、`continue` 及条件分支节点终结当前 CFG 基本块。
- `label` 不开启代码块、不创建作用域、不改变缩进层级；但由于它是跳转目标，必须形成新的 CFG 基本块入口。

### 7.2 顶层 CFG

顶层 CFG：

1. 具有唯一入口和唯一程序正常结束节点，入口已初始化集合为空。
2. 顶层绑定只由顶层声明和顶层数据流产生。
3. 文件末尾连接程序正常结束节点，不执行缺少返回检查。
4. 顶层 `return` 在 CFG 构建前拒绝。
5. 顶层及其嵌套块中的 `goto` / `label` 在 CFG 构建前分别以 `TC_ERR_GOTO_OUTSIDE_FUNCTION` / `TC_ERR_LABEL_OUTSIDE_FUNCTION` 拒绝；顶层不建立标签表，也不生成 `goto` 边。
6. 顶层 `funcall` 是单个原子节点，不产生到被调函数 CFG 的边。

### 7.3 函数 CFG

每个函数 CFG 至少包含唯一入口、函数体语句与控制节点、每条 `return` 的正常返回终止节点，以及表示未经 `return` 到达 `end` 的唯一函数末尾节点。

1. `IN[entry]` 恰好包含当前函数全部形参，不包含顶层绑定、调用者局部绑定或其他函数状态。
2. `if`、`while`、`break`、`continue`、`goto` 和标签沿用本章规则，但所有边必须留在当前函数 CFG 内。
3. `return` 只连接当前函数的正常返回终止节点，没有函数内后继边。
4. `funcall` 在调用者 CFG 中保持单节点；成功的非 `void` 调用若用于 `var` 初始化则把新绑定加入 `OUT`，若用于已有变量赋值则仅更新该绑定的值（不改变 `IN`/`OUT` 的成员关系）；`void` 调用不改变已初始化集合。
5. 按 §9.2.1 从函数唯一入口遍历 CFG；任何不在可达集合中的语句节点报 `TC_ERR_UNREACHABLE_STATEMENT`。只有入口可达节点参与确定初始化固定点和函数末尾检查；不可达代码的词法、语法、名称和类型检查仍执行。
6. 函数末尾节点可达时报缺少返回；无出口循环不产生到函数末尾的边。

顶层 CFG 与各函数 CFG 是完整、封闭、彼此独立的分析单元，不得拼接、内联或共享节点、边、可达性、已初始化集合、活动块路径或固定点状态。实现可复用算法，但不得合并各域的入口、出口和语义状态。

### 7.4 函数控制流边界

顶层与每个函数是彼此封闭的控制流域；只有函数建立标签表。`return` 只退出当前函数，`break`/`continue` 只解析到当前函数内最内层 `while`。`goto`/`label` 的查找、块关系和诊断严格按 [语言标准 §7.3] 执行并在函数边界停止：跨函数或跳向顶层的边不进入 CFG，不同函数中的同名标签互不相关。

---

### 7.5 `goto` / `label` 上下文错误优先级

`goto` 与 `label` 必须先检查是否具有 `func` 词法祖先。没有函数祖先时分别报告 `TC_ERR_GOTO_OUTSIDE_FUNCTION` 或 `TC_ERR_LABEL_OUTSIDE_FUNCTION`，定位到关键字；该语句不参与标签表、名称解析或 CFG 构建。

只有确认位于函数体内后，才检查是否具有 `while` 词法祖先；违反时分别报告 `TC_ERR_GOTO_INSIDE_LOOP` 或 `TC_ERR_LABEL_INSIDE_LOOP`。因此，位于顶层 `while` 内的 `goto` / `label` 固定报告"函数外使用"，而不是"循环内使用"。函数内合法上下文中的 `label` 才进入当前函数标签表，函数内合法上下文中的 `goto` 才继续执行标签查找、跨函数判定和块关系检查。

标签查找必须按 [语言标准 §7.3.3] 从 `goto` 所在块沿祖先链由内向外进行，最近同名标签胜出。若可见链查找失败且当前函数存在多个不可见同名候选，诊断类别固定按"后代块 `TC_ERR_JUMP_INTO_BLOCK` 优先于不可比块 `TC_ERR_JUMP_INCOMPATIBLE_BLOCK`"选择；同类别内以源位置最早的标签作为关联位置。不得使用标签表或哈希表的自然遍历顺序选择目标或诊断。

编译器必须先收集全部函数中通过上述上下文检查的标签，再解析任何函数内 `goto`；跨函数诊断不得依赖函数定义顺序、标签表遍历顺序或当前正在分析的函数。

本小节中的全部 `goto` / `label` 上下文、名称、控制流域和块关系错误均属于第 6 阶段（子阶段 6a 控制流上下文 + 6b 名称作用域预建 + 6c goto/label 名称解析）。只有完成标签绑定并通过全部上述检查的 `goto` 才能在第 11 阶段进入当前函数 CFG；CFG 阶段不再产生 `goto` / `label` 合法性诊断。

### 7.6 CFG 错误优先级

顶层和全部函数 CFG 构建完成后，CFG 类错误按源位置统一选择，不依赖内部分析顺序。同一位置依次为：`break` / `continue` 位置 → 按 §9.2.1 从控制流域入口不可达的语句 → 确定初始化 → 缺少返回。存在多个不可达语句时，选择源位置最早者，不依赖 CFG 节点遍历顺序。所有 `goto` / `label` 合法性诊断已在第 6 阶段（子阶段 6a–6c）按 §7.5 完成；非法跳转不进入 CFG，也不参与本阶段的错误选择。

缺少返回定位到函数定义头的返回类型，但与其他 CFG 错误比较源位置时使用该函数体 `end` 的位置；函数内有明确位置的 CFG 错误因此优先。多个函数都缺少返回时选择定义最早者。

## 8. 函数与调用模型

本章对应 [语言标准 §8]。函数语法、调用模型与无环要求以 [语言标准 §8.4]–[语言标准 §8.6] 为准；本节规定签名/`funcall`/`return` 诊断优先级、本库成员名索引，以及调用图与递归环的确定性算法。

### 8.1 函数签名错误优先级

第 5 阶段的候选错误包括函数重名、签名内名称冲突，以及全局函数名与顶层值作用域直接值绑定的冲突。多个候选先按本节规定的主位置选择源序最早者；同一主位置再按以下顺序：函数重复定义 → 函数名与顶层值作用域直接值绑定冲突 → 参数重名 → 参数名与全局函数名冲突。顶层嵌套块和函数体 `var` / `let` 的同名冲突在第 6 阶段按 §1.3 处理。

- 重复函数定位到第二次及后续定义的函数名。
- 函数名冲突定位到冲突的值绑定名，并把全局函数定义名作为关联位置。
- 参数重名定位到第二次及后续出现的参数名。
- 参数名冲突定位到冲突参数名。

参数和返回类型的语法接受集已由附录 A 的 `value_type` / `return_type` 穷尽规定；不符合该产生式的类型 Token 在第 3 阶段报告 `TC_ERR_SYNTAX`，不得进入第 5 阶段，也不存在"参数类型非法"或"返回类型非法"的第 5 阶段候选。

收集全部函数名是本阶段的前提，但诊断不得取决于函数表遍历顺序。

### 8.2 `funcall` 错误优先级

多个调用有错时选择 `funcall` 位置最早的调用。选定调用后依次检查：

1. 目标函数是否存在或是否因作用域/可见性不可直接以当前书写形式调用：不存在时定位到函数名，报告 `TC_ERR_UNDEFINED_FUNCTION`，不再检查实参；裸名命中本库 `func` 时报告 `TC_ERR_FUNCTION_SCOPE_ACCESS`；经导入限定解析到存在但为 `private` 的函数时报告 `TC_ERR_PRIVATE_MEMBER_ACCESS`。后两者与"不存在"同级，均抑制实参检查。
2. 调用位置是否适合返回类型；非 `void` 独立调用、`void` 用于 `var` 初始化、`void` 用于已有变量赋值均定位到 `funcall`，不再检查实参。
3. 实参重复、未知、缺失、顺序、类型，按此顺序检查。
4. 非 `void` 调用接收变量的声明类型：`var` 声明为声明类型 Token，已有变量赋值为赋值目标标识符。在实参全部合法后检查，错误定位到声明类型 Token 或目标标识符。

实参重复定位到第二个重复名称；未知实参定位到最早未知名称；缺失实参定位到右括号并指出声明顺序最靠前的缺失形参；顺序错误定位到第一个名称已知、集合完整但与对应位置形参不同的名称；类型错误定位到最早不匹配操作数。

只有实参名称全部已知、唯一且集合完整时才检查顺序；只有顺序正确后才从左到右检查类型。单个实参先检查名称，再检查类型类别，最后按 [语言标准 §3.6] 检查字面量符号性、后缀和范围。合法字面量不能用于形参类型时沿用字面量专用诊断，不降级为笼统实参类型错误。

### 8.3 `return` 错误优先级

多个 `return` 有错时选择关键字位置最早者；同一条依次检查：是否在函数体内 → 有值/无值形式是否匹配 → 返回名称是否合法 → 返回类型是否匹配 → 返回字面量是否合法且可表示。

顶层返回和形式错误定位到 `return`；返回类型错误定位到操作数；未定义或越过函数边界的返回操作数分别使用名称类错误码，但统一在第 8 阶段按本小节顺序报告；字面量问题同样在第 8 阶段检查并沿用字面量专用诊断。

### 8.4 本库顶层成员名索引

在 `#lib` 模块中，编译器的名称作用域预建阶段（见 §1.2 6b）为当前模块建立**本库顶层成员名索引**，用以落实 [语言标准 §8.4.1] 对 `TC_ERR_FUNCTION_SCOPE_ACCESS` 的分类要求。该索引收集全部 `func` / `static let` / `static var` 的声明名（不分 `public` / `private`），**仅用于错误分类**，绝不把这些名字注入函数体的普通裸名查找。

函数内普通裸名查找失败后，按以下规则分类诊断：

1. 若该名存在于本库顶层成员名索引，报告 `TC_ERR_FUNCTION_SCOPE_ACCESS`（须改为 `Self.<名>`）；
2. 否则报告 `TC_ERR_UNDEFINED_VARIABLE`（值位置）或按 `funcall` 规则报告 `TC_ERR_UNDEFINED_FUNCTION`（调用目标位置）。

此分类统一适用于普通 RHS、赋值目标、`read` 目标、`let` 依赖、`funcall` 第一项与实参、以及 `return` 操作数。

### 8.5 调用帧

在实现 [语言标准 §8.5] 的抽象调用帧时，每次 `funcall` 至少创建以下逻辑状态：

- 被调函数标识；
- 返回地址或等价继续点；
- 按形参绑定的实参值；
- 函数局部 `var` 槽；
- 活动块路径和函数内控制流状态；
- 非 `void` 函数的返回值位置。

规范不强制 VM 与 AOT 使用相同物理布局，但可观测语义必须一致。

### 8.6 调用步骤

实现必须按下列顺序落实 [语言标准 §8.5] 的调用步骤：

1. 按形参声明顺序，从左到右检查同一文本位置的实参名称和期望类型，并读取实参操作数。
2. 任一运行时错误立即终止整个程序。
3. 创建被调函数帧并写入参数值。
4. 从函数体第一条语句开始执行。
5. 执行 `return` 时销毁函数帧并恢复调用者。
6. 非 `void` 结果若用于 `var` 声明则初始化新变量，若用于已有变量赋值则覆盖目标变量的当前值。

### 8.7 无环调用图

编译器必须为全部函数体内的 `funcall` 建立有向调用图，以实现 [语言标准 §8.6]；顶层调用可以作为无入边的外部根记录，但不参与函数间环判定。调用图边不是 CFG 边，不参与确定初始化、可达性或控制流传播。

若函数调用图存在环，无论相关调用点运行时是否可达，均报递归错误。自调用是长度为 1 的环；间接递归同样非法。

---

### 8.8 递归错误的确定规则

调用图环检查只在更早阶段全部成功后执行。存在多个递归强连通分量时，选择包含源位置最早函数定义的分量，再选择该分量内源位置最早、且目标仍在该分量内的调用点；将其调用边固定为首边 `e0 = (u, v)`，并在该调用点的函数名处报告递归错误。

诊断必须给出一个有限、确定的简单环路径。若 `u == v`，环路径只含自递归首边 `e0`。否则，在所选强连通分量内，从 `v` 到 `u` 的全部不重复函数顶点的简单路径中，先选择调用边数量最少者；仍有并列时，将各路径上的调用点源位置序列按 `(行, 列)` 做字典序比较，选择最小者。最终环路径为首边 `e0` 加该返回路径，除闭合起点外不得重复函数顶点。有限调用图中该算法必定终止，且不得由哈希表、图节点或邻接表的自然遍历顺序改变结果。

## 9. 作用域、生命周期与确定初始化

本章对应 [语言标准 §9]。作用域规则、生命周期表与确定初始化的路径语义以 [语言标准 §9] 为准；本节给出编译器必须实现的作用域预建细节、CFG 构建与数据流固定点求解，使分析结果与语言路径语义一致且与遍历顺序无关。

### 9.1 作用域

TC 采用全局函数签名表 + 顶层值作用域 + 函数作用域 + 块级作用域：

- **全局函数签名表**：编译器先于函数体分析前收集全部函数签名。函数名全局可见，只有 `funcall` 的首项在此解析（RHS 不解析函数名）。
- **顶层值作用域**：`#program` 中不在 `if`/`while` 块内的 `var`/`let` 属顶层，遵循源序可见性，生命周期贯穿程序始终。`#lib` 无非 `static` 顶层值作用域，模块状态只能是 `static let`/`static var`（函数内通过 `Self.` 访问，见 [语言标准 §4.3]）。
- **函数作用域**：每个函数体是独立作用域（含只读参数、局部 `var`/`let` 及嵌套块）。名称查找到函数边界即止。每次调用创建独立帧，不共享参数或局部变量。
- **块级作用域**：`if` 的 `then`/`else` 为互斥兄弟块；`while` 的 `then … end` 为循环体块。兄弟分支中标识符互不可见（允许同名）。嵌套块可屏蔽外层同名绑定，但禁止重新声明全局函数名与函数形参。块内 `var`/`let` 离开块后不可访问。
- **标签作用域**：标签限于函数体内，受函数边界与 `while` 隔离约束（[语言标准 §7.2.4]）。`goto` 沿祖先链由内向外查找，首个同名标签胜出；同块禁止同名标签。每个函数有独立标签表，顶层无标签表。
- **源序可见性**：绑定从声明结束后的词法位置开始可见；初始化器不可引用当前绑定或尚未声明的标识符。`var` 的执行状态由 §9.2 确定初始化分析判定；`let` 统一在编译期求值内联，不受运行时路径影响。函数签名先于函数体收集，可调用后定义的函数（调用图不得有环，见 §8.7）。
- **变量生命周期**：顶层变量启动时建槽，执行 `var` 时初始化；参数在帧建立时写入、返回时销毁；局部变量进入作用域时建槽，执行 `var` 时初始化；离开块时销毁（`end`/`break`/`continue`/`return`/`goto`），物理槽可复用。反向跳转/下一迭代重新初始化同一槽。`let` 无运行时槽。

### 9.2 变量生命周期与确定初始化

| 阶段 | 行为 |
| ---- | ---- |
| 作用域进入 | 建立本作用域全部 `var` 的固定槽位，初始状态为"未初始化" |
| `var` 执行 | 先检查并计算普通 RHS 或执行非 `void` `funcall` 初始化器，再写入对应槽位；成功后状态变为"已初始化" |
| 赋值 / `read` / `memblock_store` / `memblock_copy` | 目标变量（及 `copy`/`store` 的目标块）必须已确定初始化；成功后更新同一槽位内容，不改变其生命周期；`memblock_copy` 另须读取源块（`let` 源不进入 `IN` 检查） |
| 运行时绑定读取 | `var` 或参数绑定必须在当前 CFG 点上确定初始化，否则静态错误 `TC_ERR_UNINITIALIZED_VARIABLE`；`let` 已在编译期内联，不属于本行 |
| 反向跳转 / 下一迭代 | 再次执行 `var` 时重新初始化同一槽位，不创建新绑定或新槽位 |
| 作用域离开 | 因正常 `end` / 循环回边、`break`、`continue`、`return` 或向外 `goto` 离开当前块实例时，结束局部生命周期并清除其确定初始化状态；物理槽可复用 |
| `let` | 编译期求值并内联，不生成运行时槽；在 CFG 中保留无运行时效果的身份节点，仅参与源级可达性诊断，数据流传递函数为恒等 |
| 参数 | 函数入口时已初始化，只读；不得赋值或作为 `read` 目标 |
| `return` | 终止当前函数 CFG 路径，销毁当前函数帧及活动块局部槽 |

### 9.2.1 CFG 可达性与确定初始化数据流

编译器必须分别为顶层语句区和每个函数建立封闭 CFG。顶层 CFG 处理结构化控制流，不含 `goto` / `label` / `return`；函数 CFG 在同一分析框架中额外处理函数内 `goto` / `label` 与 `return`。不同控制流域不得共享节点、边或数据流状态。

**CFG 边与可达性**：

1. 在 [语言标准 §5.2] 常量求值和静态布尔三态判定完成后构建 CFG；静态 `true` / `false` 条件删除不可能边，`unknown` 条件保留真、假两边。
2. 附录 A `statement` 产生式接受的每条源语句均建立对应的源级 CFG 节点；其中 `let` 是无运行时效果的身份节点。普通顺序语句连接源序后继；`if` / `while` 按其结构化语义建立分支、会合、回边和退出边。函数定义、空行、纯注释行以及结构标记 `else` / `end` 不是语句节点。
3. `return` 只连接当前函数的正常返回终止节点；`break` 只连接最内层 `while` 的退出点；`continue` 只连接最内层 `while` 的条件节点；`goto` 只连接其已合法绑定的目标 `label`。这四类语句均不连接源序后继。
4. `label` 是 CFG 基本块入口，可同时接收源序落入边和合法 `goto` 边；但 `label` 不因自身是跳转目标而天然可达，只有来自已可达节点的入边才能使其可达。来自不可达 `goto` 的边不能使目标变为可达。
5. 从当前控制流域的唯一入口沿上述边遍历，所得节点集合是该域的唯一可达集合。每个函数的入口均作为本函数分析的可达根，不因该函数没有被 `funcall` 而把其函数体判为不可达。
6. 任何不在可达集合中的语句节点（包括 `label`）报 `TC_ERR_UNREACHABLE_STATEMENT`，并定位到源位置最早的不可达语句。不可达语句仍须通过词法、语法、名称和类型检查，但不参与确定初始化固定点、函数末尾可达性传播或其他运行时数据流。

**活动作用域与边规范化**：

- 每个 CFG 节点都附带其词法活动代码块链。绑定用"声明身份"而非名称表示，因此被屏蔽的同名变量是不同数据流元素。
- 对每条边 `p → n`，先从 `OUT[p]` 删除所有在 `n` 的活动块链中不存活的绑定，再作为 `n` 的前驱状态。该规则统一处理 `end`、`break`、`continue`、`return` 和向外 `goto` 的生命周期结束。
- 进入一个新的块实例时，该块内全部 `var` 绑定均以未初始化状态开始，即使实现复用同一物理槽。`while` 条件真边进入新一轮循环体时同样重置循环体局部绑定；`continue` 回到条件节点之前先离开当前循环体实例。
- 同一块内的反向 `goto` 不离开该块，因此不会仅因跳转而清除仍存活绑定；若再次执行某条 `var`，该语句按普通传递函数重新写入同一词法槽。初始化 RHS 仍不得引用正在定义的绑定，即使该槽在反向边上曾经初始化。

因此，静态条件边裁剪后不可能执行的非空分支或循环体，以及无可达 `break` 的恒真循环之后的语句，均按本规则报不可达语句错误。只含 `let` 的 suite 仍含源级语句节点；空 suite 不含语句节点，本身不产生不可达语句诊断。

完成可达性检查后，仅在可达子图上执行确定初始化分析。设 `IN[n]` 为可达语句 `n` 执行前确定已初始化的绑定集合，`OUT[n]` 为执行后的集合。再令 `U[n]` 为节点 `n` 的活动作用域链中全部运行时绑定的全集：它包含当前函数形参，以及当前块实例和全部活动祖先块实例中仍处于生命周期内的全部 `var` 绑定，无论相应 `var` 声明语句此时是否已经执行；不包含编译期 `let`、其他函数的绑定、尚未进入或已经退出的块实例绑定。各集合均以声明身份区分同名屏蔽绑定，并满足 `IN[n] ⊆ U[n]`、`OUT[n] ⊆ U[n]`：

```text
IN[top-level entry] = ∅
IN[function entry]  = 当前函数的全部参数
IN[n]     = ∩ EDGE_OUT[p → n]，其中 p 为 n 的全部可达前驱，
            EDGE_OUT 为按活动作用域规范化后的 OUT[p]
OUT[var x = rhs] = IN[n] ∪ {x}
OUT[var x = funcall(...)] = IN[n] ∪ {x}  ; 调用成功路径
OUT[x = funcall(...)] = IN[n]              ; x 须 ∈ IN[n]，结果覆盖同一槽位，不改变成员关系
OUT[let ...]       = IN[n]               ; 无运行时效果的身份节点
OUT[其他语句]    = IN[n]
```

- `var x = rhs` 的 RHS 在加入 `x` 之前检查，因此初始化自引用仍非法。
- 任何可达的运行时 `var` / 参数读取、赋值目标或 `read` 目标都要求对应运行时绑定属于当前 `IN`。`let` 只要求名称可见且已成功求值，不属于 `U` / `IN`；逻辑短路的右操作数是否可达按 [语言标准 §6.5.2.2] 判定。
- 会合点取可达前驱集合的交集；只有所有可达路径均已初始化才成立。
- 上述方程在可达子图上采用最大固定点（greatest fixed point）语义，不得任选任一固定点。一个等价的强制求解策略是：保持两个入口边界值不变；对每个非入口可达节点，以 `U[n]` 初始化 `IN[n]` 与 `OUT[n]`，再按活动作用域边规范化和传递函数单调向下迭代，直至所有集合不再变化。工作队列、节点遍历和回边发现顺序不得改变最终结果。
- 最大固定点还等价于以下路径语义：绑定属于 `IN[n]`，当且仅当从当前控制流域唯一入口到 `n` 的每一条有限可达路径，在逐边应用作用域规范化和上述传递函数后，都已初始化该绑定。该路径定义用于判定任何求解实现是否一致。
- 对没有可达前驱的非入口节点不定义 `IN`；它们已由可达性阶段排除。每个节点参与固定点迭代的数据流格上界恰为 `U[n]`，绝不把其他函数、未进入或已退出块、或编译期 `let` 混入数据流域。
- CFG 可达性与静态条件边裁剪完全依据本小节前述规则；CFG 不另行维护运算符白名单，也不将优化器的值推测用于改变可达语句集合。
- `funcall` 在调用者 CFG 中是单个原子节点，不展开被调函数 CFG；被调函数发生运行时错误时程序终止，不形成返回调用者的 CFG 边。
- `return` 节点只连接当前函数的正常返回终止节点；函数末尾节点若从入口可达，触发缺少返回错误。顶层文件末尾是合法程序正常结束，不执行缺少返回检查。
- 分析结果是 0.0.35 的强制语义，不允许实现通过更弱或更强的默认规则改变合法程序集合。

声明时强制 RHS 与确定初始化分析是两个独立保证：前者约束源代码形态，后者证明每次可达使用之前相应初始化语句确已执行。

初始化相关错误按下表严格分工：

| 层次 | 违规形态 | 错误码 | 检查性质 | 规范依据 |
| ---- | -------- | ------ | -------- | -------- |

## 11. 诊断与错误处理

遇到**第一个**错误即终止程序（fail-fast）。错误按发生阶段分为**静态**（词法/语法/静态分析）与**运行时**两类。运行时错误类型与提交规则以 [语言标准 §11.1] 为准；本节补充静态诊断细则、与语言条款对齐的错误码表，以及编译警告禁令（含 [语言标准 §1.3] 第 10 条与 [语言标准 §11.2]）。

### 11.1 静态错误

静态错误覆盖词法/语法、模块结构与导入、名称与作用域、类型/字面量/模式、常量求值、缩进与控制流、函数调用与返回、CFG 确定初始化及调用图。具体触发条件、标准错误码、打印名和阶段以 §11.4 为准，多个错误的选择顺序以 §1.3 及各章专用优先级为准。

0.0.35 不定义 `TC_ERR_GOTO_SKIPS_VAR_INIT`、常量循环依赖专用错误、跨块引用专用错误或重复的 overflow-mode 错误：它们分别由确定初始化、源序可见性/名称解析，以及"EBNF 先行、模式语义随后"的统一规则处理。

### 11.2 运行时错误

| 错误类型         | 触发条件                                                     |
| ---------------- | ------------------------------------------------------------ |
| 除零错误         | 整数 `div`/`mod` 除数为 0；严格浮点 `div` 的有限非零被除数除以零，或严格浮点 `mod` 的有限非零被除数对零取模 |
| 整数溢出错误     | 有符号 `add`/`sub`/`mul`/`neg` 结果超范围；有符号 `div` 的数学商不可表示（即 `INT_MIN / -1`）；有符号 `abs(INT_MIN)`；任一整数类型的 strict `shl` 结果超范围 |
| 负移位计数错误 | `shl`/`shr` 的有符号移位计数按其类型解码后的数学值小于 0 |
| 浮点溢出错误     | 严格模式浮点运算上溢                                         |
| 浮点下溢错误     | 严格模式浮点运算下溢                                         |
| 浮点无效操作错误 | 严格 `add/sub/mul/div/mod` 的输入含 NaN 或产生无效结果（如 0/0、∞−∞、0×∞、∞ mod x）；`abs/neg` 除外 |
| 转换溢出错误     | 严格 `cast` 的数学结果无法在目标类型中表示，或浮点源为 NaN/无穷且目标为整数 |
| I/O 错误         | `read` 输入非法/超范围/EOF，标准输入读取失败，或 `write`/`writeln` 写入失败 |
| memblock 越界    | `memblock_load` / `memblock_store` 的运行时下标不满足 `0 ≤ i < extent`；或 `memblock_copy` 的运行时区间不满足 [语言标准 §6.7.2.3]（`extent` 为实现所持存储区容量，[语言标准 §3.8.0]） |

对 `shl` / `shr` 运行时指令，必须先按类型 `T` 解码移位计数的数学值并检查是否为负；只有该检查通过后，才检查 `k >= n` 或 `shl` 结果溢出。因此同一条指令不得以 `TC_ERR_INTEGER_OVERFLOW` 代替 `TC_ERR_NEGATIVE_SHIFT_COUNT`。

**运行时错误提交规则**：每条 TC 指令在抽象机器中先读取全部实际需要读取的操作数并完成检查，再提交目标值。算术、移位、转换或函数调用发生运行时错误时，不提交当前指令的目标槽、调用返回值或新 `var` 的已初始化状态；`memblock_store` / `memblock_copy` 在下标或区间检查失败时不修改目标块的任何元素；`read` / 输出失败的外部 I/O 边界按 [语言标准 §10] 单独规定。首个运行时错误立即终止整个程序，不执行清理代码、后续语句或调用者续点，也不回滚此前已成功完成的赋值与 I/O。

### 11.3 编译警告

TC 无编译警告，也不以警告方式放行初始化、溢出、类型或控制流违规（[语言标准 §11.2]）。尤其不得以警告代替对公开 `static var` 跨模块写入或私有成员外部访问的既有拒绝（[语言标准 §1.3] 第 10 条、[语言标准 §4.4]）。`and`/`or` 短路裁剪只免除不可达右操作数的确定初始化读取检查，不免除其词法、语法、名称和类型检查；`xor` 不短路。

### 11.4 标准错误码对照表

下列各表是 0.0.35 完整、权威的标准错误码对照，共 85 项：84 个语言错误码和实现资源失败码 `TC_ERR_OUT_OF_MEMORY`。语言错误码、打印名与诊断类别一一对应，不得合并、别名化或以其他错误码代替；布尔 `xor` 与浮点 `mod` 复用既有错误码。

**实现专用错误码说明**

`TC_ERR_OUT_OF_MEMORY` 不由 TC 抽象程序直接触发，仅表示实现为完成当前阶段所需的内部分配实际失败。它不是静态语义或运行时语义的一部分，不能用作固定长度、嵌套深度、标识符长度或程序规模限制的替代诊断；实现若事先施加资源上限，必须在实现文档中公开，并与真实资源失败区分。
