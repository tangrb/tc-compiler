## 1. 审查口径

本报告为 0.0.31 重新建立独立编号 `L/C/N/B/A/R-01..08`，不把 v0.0.26 的 375 项机械追加为新分母。每项必须同时有实现位置和自动化证据；正常回归、消毒器、无 fenv 后备、结构检查和平台内存检查共同组成发布证据。

历史 v0.0.26 的 375/375、384 VM、857 unit、210 AOT 是 2026-07-14 冻结的迁移起点，仅用于证明旧基线可追溯，不计入 0.0.31 的 48 项。

本次审查同时覆盖设计与实现。设计层检查规范内部一致性、规则的可判定性、错误模型闭环，以及控制流、类型系统、数值语义、I/O 和 `let` 常量求值之间的契约；实现层检查规范关键点到 parser、analyzer、CFG/DFA、runtime semantics、executor、AOT 与 libtc 的映射，并以 fixture、单元测试、VM/AOT 差分和安全门禁验证接受集与行为一致性。

### 1.1 综合设计评价

TC 0.0.31 是一次规范收敛版本。它以 `var` 强制初始化和完整 CFG 确定初始化构成双层安全模型，将受限 `goto` 与结构化 `while` 纳入统一控制流分析，明确拆分 `cast`、`truncate`、`bitcast`，并固定浮点、诊断阶段与首错优先级规则。整体设计偏向可判定、可验证和跨后端一致性，已经形成可直接实现和自动验证的闭环。

该取舍也有明确边界：表达式与 `let` 常量调用保持单层，条件剪枝和短路分析只接受规范规定的静态布尔形式，结构化循环与非结构化跳转不得混用。这些限制是 0.0.31 为确定性和实现一致性作出的设计选择；若未来提高语言可写性，应在后续规范版本中重新评估，而不应由实现自行放宽。

### 1.2 风险判断

原评审发现的完整单层静态布尔条件剪枝、源序更早且词法可见的 `let bool` 短路读集裁剪，以及诊断阶段冲突证明缺口均已关闭。当前未发现 VM 与 AOT 接受集分裂、共享数值或 I/O 语义漂移、旧初始化近似残留、`bitcast` 链路不完整或发布门禁失败等阻断风险。

### 1.3 范围

本报告覆盖：

- 标准定义的词法、语法、类型、语句、RHS、控制流、确定初始化、数值、转换、I/O 与诊断行为；
- libtc 编译事务、typed program 所有权及诊断生命周期；
- TC-VM 批处理、`--check`、执行和 REPL 的 0.0.31 行为；
- TC-AOT 生成 C99、runtime shim 和 VM/AOT 差分一致性；
- 构建警告、错误枚举完整性、结构同步、内存安全和平台后备路径；
- 正式标准、设计文档、CLI/API 参考和本报告之间的发布口径一致性。

以下内容不在 0.0.31 合规声明内：函数、数组、结构体、指针、字符串、模块系统、JIT、字节码文件格式，以及跨进程或跨线程并发编译保证。REPL 是实现提供的交互接口，不扩展标准允许的程序语法；其控制流限制按 API 行为审查。

## 9. 兼容性与迁移边界

0.0.31 是破坏性语言升级：无初始化器 `var`、浮点 wrap、浮点 truncate 位重解释和五个旧错误分类不再受支持。公共 compile/run/free 函数签名保持源兼容，但公开结构和错误枚举变化，嵌入应用升级后必须重新编译。

### 9.1 源码兼容性

- 每个 `var` 定义必须提供初始化器；旧的“声明后首次赋值或 `read` 初始化”写法必须改写。
- 浮点运算不再接受 `wrap`；调用方必须使用标准允许的严格或 `ieee` 形式。
- 浮点位模式重解释必须改用等宽 `bitcast`；`truncate` 只承担整数缩窄。
- 依赖旧 `goto` 局部近似检查的程序必须通过完整 CFG 确定初始化规则。
- 诊断采用固定阶段和首错顺序，旧测试若只匹配历史错误分类，需要更新期望值。

### 9.2 二进制与 API 兼容性

公共 compile/run/free 函数签名保持源级兼容，但 `TcTypedProgram`、相关公开结构和 `TcErrorKind` 已变化，不承诺与旧版本构建产物保持 ABI 兼容。嵌入应用升级头文件和静态库后必须清理旧对象并完整重新编译；不得混用不同版本的头文件、库和 typed program。

### 9.3 VM/AOT 产物边界

TC-VM 与 TC-AOT 对同一合法程序应具有一致的接受集、标准输出、运行时错误种类和关键数值位模式。AOT 的产物是严格 C99 源码，仍需目标平台 C99 编译器完成最终编译；报告不声明不同 C 标准库、不同浮点环境或非受测架构上的二进制逐字节一致。

## 10. 已知限制与非阻断风险

### 10.1 语言设计限制

- TC 0.0.31 有意保持单层 RHS 和非嵌套 `let` 调用，不把通用表达式树纳入本版。
- 结构化 `while` 与 `goto`/`label` 范式隔离；这属于规范限制，不是实现缺口。
- 静态布尔求值只处理规范定义的合法单层形式；无法静态确定时必须保守保留 CFG 边和 RHS 读集。
- 0.0.31 没有语言 warning；兼容的 warning 容器不代表存在规范警告行为。

### 10.2 平台风险
