## 1. 执行结论

### 1.1 v0.0.26

**v0.0.26 已实现合规基线：375/375 历史检查项合规。**

该结论来自 2026-07-14 的 v0.0.26 设计—实现复验，覆盖整数、bool、浮点、if/块作用域、受限 goto/label、路径敏感未初始化检查、内存安全和构建基础设施。2026-07-15 再次运行当前全量回归：

```text
384 VM passed
857 unit passed
210 AOT passed
```

`check_rhs_coverage.py` 与 `check_source_naming.py` 同日通过。

### 1.2 0.0.31

**0.0.31 当前不符合，不能给出通过率，也不能声明部分合规版本。**

理由不是当前 v0.0.26 质量失败，而是 0.0.31 是明确的破坏性规范升级，且标准首页声明实现仍停留在 v0.0.26。当前代码缺少或尚未收敛：

- 强制 `var` 初始化器；
- `while`、`break`、`continue` 与范式隔离；
- 全部控制流统一的完整 CFG 固定点；
- 等宽 `bitcast`；
- 严格 cast、整数 truncate 与浮点模式收敛；
- `let` 逐操作精度/模式一致性；
- 0.0.31 的 41 个语言错误码 + `OutOfMemory`；
- 文件/API 错误与语言错误分域；
- 相应 VM、AOT、unit 和迁移回归。

### 1.3 禁止的推断

- 375/375 不代表 0.0.31 的 375 项已通过；这些检查项属于 v0.0.26。
- 384/857/210 全绿不包含尚不存在的 0.0.31 用例。
- 三份 0.0.31 目标设计完成不等于代码实现完成。
- 现有 DFA 名称或 goto 分析不能自动证明完整 CFG 符合。

## 6. 关键语义差距

### 6.1 强制变量初始化

**当前**：`TcVarDef.has_rhs` 表达可选初始化；`tests/valid/var_no_init.tc` 证明无 RHS 声明当前合法。

**目标**：唯一合法形态为 `var <name>: <type> = <rhs>`。缺失初始化器在 Parser/形态阶段报告 `VarMissingInitializer`，不能降级为 SyntaxError，也不能由后续赋值或 read 补救。

**状态**：未实现。

### 6.2 结构化循环与范式隔离

**当前**：只有 if 和受限 goto，可用 if + goto 模拟循环。

**目标**：增加 while/break/continue；控制最内层 loop。while 词法祖先内的 goto 和 label 分别报告 `GotoInsideLoop`、`LabelInsideLoop`。

**状态**：未实现；if 块 Parser、scope 和 Executor 结构可部分复用。

### 6.3 完整 CFG 确定初始化

**当前**：`tc_analyzer_dfa.c` 对 if/goto 和短路执行路径敏感分析，但没有 0.0.31 所需的统一循环 CFG 与固定点契约。

**目标**：顺序、if、while 条件、正常回边、break、continue、goto、短路全部成为显式边；会合取全部可达前驱 OUT 的交集；循环迭代到固定点；合法常量条件可剪枝。

**状态**：部分基础可复用。现有 DFA 名称不能作为完整性证明。

### 6.4 转换与 bitcast

**当前**：strict cast、truncate 和 float cast 分支分散；浮点 truncate 承担位重解释；无 bitcast。

**目标**：

- strict cast 对所有数值转换检查数学值可表示性；
- truncate 只允许整数到更窄整数；
- bitcast 只做等位宽、非 bool 位复制；
- 运行时转换失败统一 `CastOverflow`；
- 常量转换失败统一 `ConstantCastOverflow`。

**状态**：bitcast 未实现，其余部分基础可复用但需破坏性迁移。

### 6.5 浮点

**当前**：三模式路径包含 float wrap；比较和 cast 仍有旧分类；常量求值以旧精度/模式规则实现。

**目标**：只保留 strict/ieee；固定逐操作 float32/float64 舍入、异常优先级和 NaN 行为；VM/AOT/let 一致。

**状态**：部分基础可复用。现有 0.0.25 浮点测试证明旧语义，不证明新语义。

### 6.6 `let`

**当前**：已有常量表达式、短路、浮点和 cast 求值，但保留常量循环依赖错误、旧模式限制和宿主精度行为。

**目标**：operand 仅为字面量或更早 let；最多一个非嵌套调用；每步按声明类型和 runtime 同模式求值；bitcast 可参与；自引用/前向引用归 UndefinedVariable。

**状态**：部分基础可复用。

### 6.7 REPL 与文件/API 错误

**当前**：REPL 把不支持的 if/goto/label 设置为 SyntaxError；`tc_compile_file` 的文件打开/读取失败也使用 SyntaxError。

**目标**：0.0.31 只规范批量源文件；REPL 限制、文件错误和 host 工具错误属于实现/API 域，不改变语言合法性。

**状态**：未实现诊断分域；CLI/API 目标边界已记录。

### 8.1 当前 RHS 分发

- Pass1 slot/scope；

- CFG/dataflow；
- REPL 拒绝边界；
- Executor；
- AOT codegen；
- stmt_index；
- unit/VM/AOT tests。

### 8.3 新 CFG 模块

实现可扩展 `tc_analyzer_dfa.c`，也可新增配对模块。无论文件布局，必须有单一 CFG 语义来源，并通过 source naming/CMake/架构索引检查。

- `var_no_init.tc`：从 valid 迁为 `VarMissingInitializer` static；
- `fp_*wrap*.tc`：改写为 ieee/bitcast 正例或 ModeMismatch 反例；
- `fp_cast_truncate.tc`：迁为 bitcast；
- constant circular 专用预期：改为 UndefinedVariable；
- cross-block 专用预期：改为 UndefinedVariable；
- float cast overflow 名称：改为 CastOverflow。

### 9.3 差分

VM 与 AOT 必须对同一合法源比较 stdout/退出状态/运行时错误；对 bitcast/浮点增加位模式输出。静态错误由共享 libtc 保证，`tc-vm --check` 与 `tc-aot --check` 都要覆盖。

### 9.4 非功能验证

- ASan 全量；
- UBSan；
- no-fenv 浮点回退；
- macOS leaks/Valgrind（平台可用时）；
- C99 `-Wall -Wextra -pedantic`；
- RHS coverage 与 source naming；
- 文档相对链接和版本陈述检查。
